# 日誌等級設定

決定系統的日誌**要記錄到多細**：排查問題時暫時**調低等級**讓日誌多寫一些細節，查完再**還原為系統預設等級**。

> 這一頁只有管理員可以使用。

### 一分鐘看懂這一頁

- **解決什麼問題**：在日誌檢視頁找不到足夠線索時，把日誌暫時調細，讓系統多記下查詢條件、換頁等排錯資訊，重現問題後就能看出原因。
- **誰會用到**：負責排查問題的系統管理員。平常不需要動它，只有在日誌不夠細、看不出原因的時候才會來。
- **它在系統的哪個位置**：側邊選單「系統管理 › 統計與分析」。它是日誌檢視的上游：這裡決定寫下多少，日誌檢視只能查到已經寫下的內容。
- **開始前要準備**：先想好要重現的操作步驟，並預留排查結束後把等級調回來的時間；調得越細，日誌量增加得越快。
- **做完會得到**：新的等級立即對整個系統生效，之後發生的事件會依新等級寫進日誌檔，稽核紀錄也會留下一筆調整紀錄。
- **它不做什麼**：不會修改任何設定檔，重新啟動後就回到系統預設；不會補回調整之前沒寫下的日誌；也不影響框架本身的日誌。

## 一、功能摘要

這一頁沒有表格，只有兩張資訊卡、一段黃色注意事項、一組等級選項和兩個按鈕。上方兩張卡分別顯示「目前生效等級」與「系統預設等級」；中間選擇要輸出的最低等級；按「套用」後立即生效，按「還原為系統預設等級」則回到系統設定檔裡的值。每一次套用與還原都會寫進稽核紀錄，事後查得到是誰、在什麼時候、從哪個等級調到哪個等級。

## 二、這個頁面在做什麼

統計與分析群組裡的幾個頁面構成一條排查工具鏈，本頁負責「細節不夠時調低等級再重現」：

| 頁面 | 回答的問題 |
|---|---|
| 系統健康監控 | 基礎元件現在有沒有壞？ |
| 系統例外紀錄 | 出過哪幾種錯、各發生幾次？ |
| 日誌檢視 | 某段時間內系統逐筆做了什麼？ |
| 日誌等級設定（本頁） | 日誌不夠細時，暫時調細等級再重現問題。 |
| 資料庫用量、Token 用量 | 容量還夠不夠、AI 花了多少錢。 |

日誌等級是一道「門檻」：只有等級**大於或等於**目前生效等級的事件才會寫進檔案。例如生效等級是 INFO 時，DEBUG 與 TRACE 的訊息會被直接丟棄，日後在日誌檢視頁再怎麼查都查不到。所以正確的順序是：**先調低等級 → 重現問題 → 到日誌檢視查詢 → 回來還原**。

這個設定對**整個系統**生效，不是只針對你自己；調整期間所有使用者的操作都會用新等級記錄。

## 三、畫面上有哪些按鈕、各自做什麼

### 資訊卡

| 畫面上的名稱 | 意思 |
|---|---|
| 目前生效等級 | 系統此刻實際使用的等級，卡片下方註明「此等級以上的日誌才會寫入檔案」。 |
| 系統預設等級 | 系統設定檔裡設定的等級，也就是重新啟動後會回到的等級。 |

### 注意事項（黃色區塊）

畫面上的黃色區塊說明了四件事，請務必讀完：

- **這個設定只在執行期有效**。系統重新啟動之後會回到「系統預設等級」，不會寫進任何設定檔。
- 套用之後，即使系統重新載入設定檔，這裡的設定仍會保留；要回到設定檔裡的值，請按「還原為系統預設等級」。
- 本設定**只影響應用程式日誌**；框架日誌（Microsoft、EntityFrameworkCore）另有專屬規則，不受這裡影響。
- **調到 Debug 或 Trace 會大幅增加日誌量**，排查完問題請記得調回來。

> **提醒**：等級只存在記憶體裡。系統重新啟動（包括部署新版本、伺服器重開機）後就會還原為系統預設等級，不需要手動調回，但也代表調低的效果不會一直保留。

### 等級選項

標題為「選擇要輸出的最低等級」，由細到粗共六個選項：

| 選項 | 畫面上的說明 |
|---|---|
| TRACE | 最詳細，含框架層級細節 |
| DEBUG | 含查詢條件、換頁等排錯資訊 |
| INFO | 含使用者操作軌跡，日常建議值 |
| WARN | 僅警告以上 |
| ERROR | 僅錯誤以上 |
| FATAL | 僅嚴重錯誤 |

### 按鈕

| 按鈕（滑鼠提示） | 做什麼 |
|---|---|
| 套用 | 把選取的等級立即設為生效等級。選取的等級與目前生效等級相同時停用。成功時顯示「已套用日誌等級：…」。 |
| 還原為系統預設等級 | 取消先前的調整，回到系統預設等級。目前沒有做過調整時停用。成功時顯示「已還原為系統預設等級：…」。 |

- 選擇 TRACE 或 DEBUG 再按「套用」時，會先跳出「確認調整日誌等級」對話窗，提醒會大幅增加日誌量，按「套用」才會生效，按「取消」則不變。
- 套用與還原都會在稽核紀錄留下一筆，動作分別為 `LogLevel.Apply` 與 `LogLevel.Restore`，內容記錄從哪個等級調整為哪個等級。
- 系統讀不到日誌設定時，整頁只會顯示紅色警示「無法讀取 NLog 設定，日誌等級無法在執行期調整。」，此時無法調整，請聯絡系統管理員檢查伺服器上的日誌設定檔。

## 四、建議這樣操作，會得到什麼

### 情境一：某個查詢結果不對，想看系統實際用了什麼條件

1. 確認「目前生效等級」是 INFO。
2. 選擇「DEBUG」，按「套用」，在確認對話窗再按一次「套用」。
3. 請使用者（或你自己）重做一次那個查詢，並記下操作時間。
4. 到日誌檢視頁，查詢那個時間前後、最低等級選「DEBUG」的日誌。
5. 查到需要的資訊後，回到本頁按「還原為系統預設等級」。

會得到：那次操作的查詢條件等排錯細節，以及稽核紀錄裡兩筆紀錄（調低與還原），日誌量也回到平常水準。

### 情境二：日誌檔長得太快，想暫時只記重要的事

1. 選擇「WARN」，按「套用」（調高等級不需要確認）。
2. 觀察一段時間，確認日誌量下降。
3. 問題處理完後，按「還原為系統預設等級」。

會得到：這段期間只記錄警告以上的事件；但要知道，這段期間的一般操作軌跡不會被記下，事後無法補查。

### 情境三：接手時不確定之前有沒有人調過

1. 打開本頁，比對「目前生效等級」與「系統預設等級」是否相同。
2. 若不同，且「還原為系統預設等級」按鈕可以按，代表有人調整過且尚未還原。
3. 到稽核紀錄查詢 `LogLevel.Apply`，確認是誰、何時調整的，再決定是否還原。

會得到：確認系統目前的日誌等級是否處於臨時調整狀態，避免細節日誌在沒人注意的情況下持續累積。

## 五、名詞解釋

| 名詞 | 白話解釋 |
|---|---|
| 日誌等級 | 每筆日誌的重要程度，由細到粗為 TRACE、DEBUG、INFO、WARN、ERROR、FATAL。 |
| 最低等級 | 門檻值；只有等於或高於這個等級的事件才會寫進日誌檔。 |
| 目前生效等級 | 系統此刻實際使用的門檻值。 |
| 系統預設等級 | 系統設定檔裡的門檻值，重新啟動後會回到這裡。 |
| 執行期 | 系統這一次啟動到下一次重新啟動之間；本頁的調整只在這段期間有效。 |
| 應用程式日誌 | 本系統自己的程式寫出的日誌；框架日誌則是底層套件寫出的，不受本頁影響。 |

## 七、常見問題

**我調成 DEBUG 了，為什麼日誌檢視還是查不到昨天的 DEBUG 訊息？**
等級只影響「之後」寫下的日誌。調整之前的事件當初就沒有寫進檔案，無法補回。調低等級後必須重現一次問題，才查得到那次的細節。

**調低之後忘了調回來，會怎樣？**
日誌量會大幅增加，佔用更多磁碟空間。系統重新啟動時會自動回到系統預設等級，但在那之前會一直維持調低的狀態，所以排查完請記得按「還原為系統預設等級」。

**選了 TRACE，為什麼還是看不到框架的細節？**
本頁只影響應用程式日誌。框架日誌另有專屬規則，由伺服器上的日誌設定檔控制，不受這裡影響；需要時請聯絡負責部署的人員。

**這個調整會影響其他管理員嗎？**
會影響同一個系統上的所有使用者，因為日誌等級是整個系統共用的設定。它只存在這一次執行的記憶體中，不會寫進任何設定檔。
