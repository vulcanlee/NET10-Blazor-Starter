# 稽核紀錄

這一頁讓你**查詢「誰、何時、對什麼、做了什麼、結果如何」**，並可**匯出查詢結果**或**清除過舊的紀錄**。

> 這一頁只有管理員可以使用。

### 一分鐘看懂這一頁

- **解決什麼問題**：發生帳號被改、權限被動、有人一直登入失敗這類事情時，用來追查是誰在什麼時候做的。
- **誰會用到**：系統管理員與需要做稽核、資安調查的人；一般使用者打開這一頁只會看到「你沒有權限存取此頁面」。
- **它在系統的哪個位置**：側邊選單「系統管理 › 權限管理」底下；紀錄由登入、使用者管理、角色管理等流程自動寫入，這一頁只負責看。
- **開始前要準備**：大概知道要查的時間範圍、操作者帳號或事件種類，查起來會快很多。
- **做完會得到**：符合條件的事件清單、每一筆的完整明細，以及可以帶出系統比對的 CSV 檔。
- **它不做什麼**：不能新增或修改紀錄，也不能刪除單一筆；程式錯誤請看系統例外紀錄，逐行的系統運作日誌請看日誌檢視。

## 一、功能摘要

- 依發生時間區間、動作、結果、操作者帳號與關鍵字查詢稽核事件。
- 按「查看」打開單筆明細，看完整摘要與原始的 UTC 時間。
- 把目前查詢條件下的結果匯出成 CSV，最多 10,000 筆。
- 清除發生在 365 天之前的紀錄，或清空全部紀錄；這兩個動作本身也會留下紀錄。

## 二、這個頁面在做什麼

系統在這些時候會自動寫一筆稽核紀錄：

| 類別 | 什麼時候寫入 |
|---|---|
| 登入 | 登入成功、登入失敗、帳號停用中仍嘗試登入、帳號被鎖定 |
| 使用者 | 在使用者管理新增、修改、刪除帳號 |
| 角色 | 在角色管理新增、修改、刪除角色 |
| 權限 | 有人透過系統的 Web API 做了沒有權限的動作而被拒絕 |
| 密碼 | 忘記密碼的申請、完成重設、重設失敗 |
| 郵件 | 在系統健康監控寄送測試信 |
| 稽核 | 在這一頁清除或清空稽核紀錄 |

最重要的是時間：**資料庫存的是國際標準時間（UTC），畫面上顯示的是伺服器所在地的本地時間**。查詢條件的時間也是以本地時間輸入，系統會自動換算。明細窗會同時列出本地時間與 UTC，方便和其他系統的紀錄對照。

頁面上方的說明框也寫著這一點：「時間以伺服器本地時區顯示（資料庫存的是 UTC）。清除與清空動作本身也會留下一筆紀錄。」

## 三、畫面上有哪些按鈕、各自做什麼

### 查詢條件

| 條件 | 說明 |
|---|---|
| 「發生時間（起）」～「發生時間（迄）」 | 可選到秒，只填一邊也可以 |
| 動作下拉（預設「動作：不限」） | 選項只列出資料庫裡**實際出現過**的動作代碼，沒發生過的事件不會出現在選單裡 |
| 結果下拉（預設「結果：不限」） | 可選「成功」或「失敗」 |
| 「操作者帳號」 | 輸入帳號的一部分即可 |
| 「關鍵字（動作／目標／摘要）」 | 會比對動作、目標與摘要，也會比對操作者帳號與目標識別 |

### 工具列按鈕

| 按鈕 | 做什麼 |
|---|---|
| 「查詢」 | 依上面的條件重新查詢，並回到第一頁 |
| 「重新整理」 | 重新查詢，並同時更新動作下拉的選項 |
| 「匯出目前查詢結果（CSV）」 | 把目前條件下的**全部**結果（不只當頁）下載成 CSV，最多 10,000 筆。查詢結果是 0 筆時按鈕會變灰 |
| 「清除 365 天前的紀錄」 | 確認後刪除發生時間早於 365 天前的所有紀錄，完成後顯示「已清除 N 筆紀錄。」或「沒有符合條件的紀錄。」 |
| 「清空全部紀錄」 | 確認後刪除所有稽核紀錄，完成後顯示「已清空全部稽核紀錄」 |

清除與清空都會先跳出確認窗，說明「此動作無法復原」，要按「清除」或「清空」才會執行。

CSV 的欄位依序是：發生時間（本地）、結果、動作、操作者帳號、操作者Id、目標類型、目標識別、摘要。標題特別寫明「本地」，提醒讀檔的人這不是 UTC。

### 清單欄位

| 欄位 | 意思 |
|---|---|
| 發生時間 | 本地時間，預設最新的在最上面，可點標題改變排序 |
| 結果 | 綠色「成功」或紅色「失敗」 |
| 動作 | 動作代碼，例如 `Login.Success`、`User.Update`，依類別上不同顏色 |
| 操作者 | 顯示為「帳號（Id=編號）」；沒有帳號的系統事件顯示「（系統／匿名）」 |
| 目標 | 顯示為「類型#識別」，例如被修改的是哪一位使用者；沒有目標時顯示「—」 |
| 摘要 | 補充說明，太長會被截斷，完整內容請按「查看」 |
| 操作 | 「查看」按鈕，打開「稽核明細」 |

### 「稽核明細」視窗

列出發生時間（本地）、發生時間（UTC）、結果、動作代碼、操作者、目標類型、目標識別與完整摘要；摘要是空的會顯示「（無）」。這個視窗只能看，按關閉鈕或 Esc 關閉。

> **提醒**：「失敗」不代表系統壞了。登入密碼打錯、帳號被停用或鎖定、權限不足被拒絕，都會記成「失敗」。

> **提醒**：摘要只記錄部分內容。使用者異動只記帳號、角色編號與團隊，**「管理員」與「啟用」勾選的變更不會寫進摘要**；角色異動只記名稱與權限數量，不記勾了哪些權限。團隊清單與分類清單的異動則完全不會寫入稽核紀錄。

## 四、建議這樣操作，會得到什麼

### 情境一：查某個帳號最近是不是一直登入失敗

1. 「操作者帳號」輸入該帳號，「結果」選「失敗」。
2. 按「查詢」，看動作欄是 `Login.Failed` 還是 `Login.LockedOut`。

會得到：這個帳號每一次失敗的時間與原因，可判斷是忘記密碼還是有人在嘗試猜密碼。

### 情境二：查某位使用者的權限是誰改的

1. 動作下拉選 `User.Update`，關鍵字輸入那位使用者的帳號。
2. 按「查詢」，再按可疑那一列的「查看」看完整摘要。

會得到：是哪一位管理員、在什麼時間修改了這個人的角色或團隊。

### 情境三：年度保存期滿，要清理並留存舊紀錄

1. 「發生時間（迄）」選到一年前，按「查詢」，再按「匯出目前查詢結果（CSV）」下載備份。
2. 按「清除 365 天前的紀錄」，在確認窗按「清除」。

會得到：一份舊紀錄的 CSV 備份，資料表只留最近一年；同時會多出一筆 `Audit.Purge`，記下是誰在何時做了清除。

## 五、名詞解釋

| 名詞 | 白話解釋 |
|---|---|
| 稽核紀錄 | 系統自動留下的「誰做了什麼」的事件紀錄，用來事後追查責任 |
| 動作代碼 | 事件的種類，前半段是類別（例如 `Login`、`User`），後半段是發生了什麼 |
| 操作者 | 做這件事的人。系統自己發生的事件沒有操作者 |
| 目標 | 被操作的對象，例如某一位使用者或某一個角色 |
| UTC | 國際標準時間。伺服器若設在台灣，本地時間會比它快 8 小時 |
| 本地時間 | 伺服器所在地的時間，也就是畫面上顯示的時間 |
| 清除與清空 | 清除只刪 365 天前的紀錄，清空是全部刪除；兩者都無法復原 |

## 七、常見問題

**為什麼畫面上的時間和資料庫裡看到的差了好幾個小時？**
資料庫存的是 UTC，畫面顯示的是伺服器本地時間。兩者都正確，只是時區不同；明細窗會把兩個時間並列。

**清空全部紀錄之後，為什麼清單上還剩一筆？**
這是刻意的設計。清除與清空完成後，系統會再寫一筆 `Audit.Purge` 或 `Audit.ClearAll`，記下是誰抹除了稽核紀錄，否則這會是整個系統唯一查不到的事。

**動作下拉裡找不到我要查的事件？**
下拉選項只列出資料庫裡實際出現過的動作代碼。那種事件如果從沒發生過，或已經被清除，就不會出現在選單裡；可以按「重新整理」更新選項。

**有人帳號打錯而登入失敗，操作者欄為什麼沒有「Id=」？**
輸入的帳號在系統裡不存在，所以只記下對方輸入的帳號文字，沒有對應的使用者編號。
