# 稽核紀錄

查詢系統自動留下的「**誰、何時、從哪個 IP、對什麼、做了什麼、結果如何**」事件紀錄，例如登入成功或失敗、帳號與角色異動、權限被拒絕；在「系統參數」開啟後，也會記每個人開了哪些頁、查了什麼、看了哪一筆，以及修改時改了哪些欄位（0.9.174 起這兩類預設不記）；並可**匯出查詢結果**或**清除過舊的紀錄**。

> 這一頁只有管理員可以使用。

### 一分鐘看懂這一頁

- **解決什麼問題**：發生帳號被改、角色被動、有人一直登入失敗這類事情時，用來追查是誰在什麼時候、從哪個 IP 做的，結果成功還是失敗。
- **誰會用到**：系統管理員，以及需要做稽核、資安調查的人；一般使用者看不到這一頁。
- **它在系統的哪個位置**：左側選單「系統管理 › 帳號與權限 › 稽核紀錄」；紀錄由登入、使用者管理、角色管理等流程自動寫入，這一頁只負責查看與清理。
- **開始前要準備**：大概知道要查的時間範圍、操作者帳號或事件種類，查起來會快很多；查詢的時間以伺服器所在地的本地時間輸入。
- **做完會得到**：符合條件的事件清單、每一筆的完整明細（含本地時間與國際標準時間），以及可以帶出系統比對的 CSV 檔。
- **它不做什麼**：不能新增、修改或刪除單一筆紀錄；程式錯誤請看「系統例外紀錄」，逐行的系統運作過程請看「日誌檢視」。

## 一、功能摘要

在這裡可以做什麼：

- 依發生時間區間、動作、結果、操作者帳號與關鍵字（含來源 IP）查詢稽核事件；要查「某一筆資料」的紀錄時，用「目標類型」＋「目標識別（精確）」完全相同比對，查 12 不會混到 112（0.9.173 起）。
- 分類、專案、團隊、使用者、角色五個資料頁，管理員在每一列按「異動歷程」，就能直接看到那一筆的新增、修改、刪除等紀錄與修改前後差異，不用到這一頁輸入條件（0.9.173 起）。
- 按每列的「查看」打開單筆明細，看完整摘要與國際標準時間（UTC）；修改與查詢的紀錄還能看到「詳細內容」（改了哪些欄位、舊值和新值，或完整的查詢條件；0.9.131 起）。修改前後差異要在「系統參數」開啟「稽核：記錄修改前後差異」才會記（0.9.174 起預設關閉）。
- 把目前查詢條件下的結果匯出成 CSV，最多 10,000 筆。
- 清除超過保留天數的紀錄（0.9.174 起分兩類：異動與安全紀錄預設 365 天、瀏覽紀錄〔換頁、搜尋、查看〕預設 90 天，由「系統參數」決定），或清空全部紀錄；這兩個動作本身也會再留下紀錄。系統每天也會自動清除一次，每一類刪到資料各留下一筆 `Audit.AutoPurge`。
- 按「驗證完整性」檢查稽核紀錄有沒有被人直接改資料庫、偷刪或偷塞（0.9.175 起）。每一筆新紀錄寫入時都會加上「簽章」，並和前一筆串在一起，像一條鏈子；有一筆被改、被刪，鏈子就接不起來。系統每天 03:30 也會自動檢查一次，發現問題時通知全體管理員並寄信。

頁面上方有一段固定說明：「本頁記錄『誰、何時、對什麼、做了什麼、結果如何』，涵蓋登入、使用者與角色異動、權限拒絕等事件。時間以伺服器本地時區顯示（資料庫存的是 UTC）。清除與清空動作本身也會留下一筆紀錄。」

0.9.174 起，「系統參數」裡的兩個稽核開關有關閉時，說明框會多一行，例如：「目前沒有記錄修改前後差異與瀏覽類事件（換頁、搜尋、查看），可在「系統參數」頁開啟。」只關一個時只列那一個；兩個都開時不顯示。

**修改的前後差異**（0.9.131 起；0.9.174 起要在「系統參數」開啟「稽核：記錄修改前後差異」才記，預設關閉）：分類、專案、團隊、使用者、角色的「修改」（畫面或 Web API），以及使用者在「個人資料」改自己的姓名，會把「欄位：舊值 → 新值」記在明細窗的「詳細內容」。關閉時修改照樣記一筆「誰、何時、改了哪一筆」，只是沒有差異。密碼只記「已變更」、不記內容；額外角色、團隊、角色權限列出新增與移除了哪些。

### 來源 IP

0.9.117 起每筆紀錄都會記下操作者的來源 IP：登入、登出與 Web API 取該次連線的 IP；個人資料、分類、團隊、專案、使用者管理、角色管理、稽核紀錄、寄信紀錄這幾頁的操作也是經 Web API 送出（0.10.1 起陸續改成這樣，使用者管理等四頁是 0.10.4 起），同樣取該次連線的 IP；其他頁面的操作（例如在「系統參數」存檔）取的是瀏覽器連上系統時的 IP，網路斷線重連後會更新。系統排程作業自動做的事，以及 0.9.117 之前的舊紀錄，沒有來源 IP，顯示「—」。

### 時間的顯示方式

**資料庫存的是國際標準時間（UTC），畫面上顯示的是伺服器所在地的本地時間**。查詢條件的時間也以本地時間輸入，系統會自動換算。伺服器設在台灣時，本地時間比 UTC 快 8 小時。明細視窗與 CSV 都標明是哪一種時間。

### 摘要記了什麼、沒記什麼

- 使用者異動只記帳號、角色編號與團隊；**在修改窗改「管理員」與「啟用」勾選的變更不會寫進摘要**，但按「查看」打開明細，「詳細內容」會列出 IsAdmin／Status 的舊值與新值（0.9.131 起）。在清單點狀態標籤啟用或停用（0.9.120 起）則各自記成 `User.Enable`／`User.Disable`。
- 角色異動只記角色名稱與權限數量，不記勾了哪些權限。
- 登入失敗會記下累計失敗次數；帳號不存在時記「帳號不存在」。
- 寄測試信只記寄送方式與成敗，不記收件者。
- 使用者在右上角鈴鐺刪除自己的通知、按「清除已讀」，不會留下稽核紀錄（只動到自己的通知）。

## 四、建議這樣操作，會得到什麼

### 查某個帳號最近是不是一直登入失敗

1. 「操作者帳號」輸入該帳號，「結果」選「失敗」。
2. 按「查詢」，看動作欄是 `Login.Failed`、`Login.LockedOut` 還是 `Login.Disabled`。
3. 按可疑那一列的「查看」，看摘要裡累計失敗了幾次；再看「來源 IP」是不是本人平常用的網路。

**會得到什麼**：這個帳號每一次失敗的時間、原因與來源 IP，可以判斷是本人忘記密碼、帳號被停用，還是有人從陌生的地方在嘗試猜密碼。

### 查某位使用者的角色是誰改的

1. 「動作」選 `User.Update`，「關鍵字」輸入那位使用者的帳號。
2. 按「查詢」，再按可疑那一列的「查看」看完整摘要。

**會得到什麼**：是哪一位管理員、在什麼時間修改了這個人的角色或團隊。

> 業務一組反映 `user01` 突然看不到專案。王小明在「動作」選 `User.Update`、關鍵字輸入 `user01` 後查詢，看到前一天下午有一筆由 `admin` 做的修改，摘要裡的團隊已經不含「業務一組」。他到「使用者管理」把團隊加回去，問題就解決了。

### 查某一筆資料是誰改的、改了什麼

1. 先在那一筆資料所在的頁面找到它的編號（例如分類清單的「編號」欄是 12）。
2. 「目標類型」選 `Category`，「目標識別（精確）」輸入 `12`，按「查詢」。
3. 按 `Category.Update` 那一列的「查看」，在「詳細內容」看「欄位: 舊值 → 新值」。

**會得到什麼**：只有編號 12 這一筆分類的紀錄（不會混進 112、120），包括誰在什麼時候新增、修改、停用或刪除它，以及每次修改前後的差異。只想看異動、不看誰開過或查過，也可以直接在分類清單那一列按「異動歷程」。

### 年度保存期滿，要清理並留存舊紀錄

1. 「發生時間（迄）」選到一年前，按「查詢」，再按「匯出目前查詢結果（CSV）」下載備份。
2. 按「清除超過保留天數的紀錄（異動 N 天、瀏覽 M 天）」（預設 365 天與 90 天），在確認窗按「清除」。

**會得到什麼**：一份舊紀錄的 CSV 備份，異動與安全紀錄只留最近一年、瀏覽紀錄只留最近 90 天；同時會多出兩筆 `Audit.Purge`，記下是誰在何時做了清除。

## 五、名詞解釋

| 名詞 | 白話解釋 |
|---|---|
| **稽核紀錄** | 系統自動留下的「誰做了什麼」的事件紀錄，用來事後追查責任。 |
| **動作代碼** | 事件的種類，前半段是類別（例如 `Login`、`User`），後半段是發生了什麼。 |
| **操作者** | 做這件事的人；沒有登入身分的事件顯示「（系統／匿名）」。 |
| **來源 IP** | 做這件事的電腦連上系統時的網路位址，用來判斷是不是從平常的地方操作。 |
| **目標** | 被操作的對象，例如某一位使用者或某一個角色。 |
| **摘要** | 補充說明，例如異動後的角色編號與團隊；只記部分內容。 |
| **UTC** | 國際標準時間。伺服器設在台灣時，本地時間會比它快 8 小時。 |
| **本地時間** | 伺服器所在地的時間，也就是畫面上顯示的時間。 |
| **瀏覽紀錄** | 換頁（`Page.View`）、按搜尋或查詢（`*.Search`）、打開某一筆來看（`*.View`）這類只看不改的紀錄；筆數最多，0.9.174 起預設不記、保留天數也比較短。 |
| **清除與清空** | 清除只刪超過保留天數的紀錄（異動與安全預設 365 天、瀏覽預設 90 天，依系統參數），清空是全部刪除；兩者都無法復原，而且都會再留下紀錄。 |
| **簽章** | 0.9.175 起每一筆新紀錄寫入時算出的一串檢查碼，用伺服器上一把只有系統知道的「金鑰」算出來；內容被改一個字，檢查碼就對不上。 |
| **鏈（異動鏈、瀏覽鏈）** | 每一筆的簽章都包含前一筆的簽章，一筆接一筆串起來，所以刪掉中間或最新的幾筆會被發現。系統依保留天數分成異動鏈與瀏覽鏈；正常的自動清除只從最舊的那一端刪，不會被當成問題。 |
| **升級前的紀錄** | 0.9.175 之前留下的紀錄，當時還沒有簽章，驗證時不檢查。 |
| **金鑰不同** | 金鑰檔遺失或換主機沒帶過去時，系統會自動產生新金鑰繼續記錄；舊金鑰簽的紀錄只能確認編號連續，無法確認內容有沒有被改，所以另外計數、不算問題。 |

## 七、常見問題

**問：為什麼畫面上的時間和資料庫裡看到的差了好幾個小時？**
答：資料庫存的是 UTC，畫面顯示的是伺服器本地時間。兩者都正確，只是時區不同；明細視窗會把兩個時間並列。

**問：清空全部紀錄之後，為什麼清單上還剩一筆？**
答：這是刻意的設計。清除與清空完成後，系統會再寫一筆 `Audit.Purge` 或 `Audit.ClearAll`，記下是誰抹除了稽核紀錄，否則這會是整個系統唯一查不到的事。

**問：「動作」下拉裡找不到我要查的事件？**
答：下拉選項只列出資料庫裡實際出現過的動作代碼。那種事件如果從沒發生過，或已經被清除，就不會出現在選單裡；可以按「重新整理」更新選項。

**問：有人帳號打錯而登入失敗，操作者欄為什麼沒有「Id=」？**
答：輸入的帳號在系統裡不存在，所以只記下對方輸入的帳號文字，沒有對應的使用者編號，摘要會寫「帳號不存在」。

**問：我改了某人的「管理員」或「啟用」勾選，為什麼摘要裡看不到？**
答：使用者異動的摘要只記帳號、角色編號與團隊，在修改窗改這兩個勾選不會寫進摘要。你仍然可以從 `User.Update` 看出是誰、在什麼時間改過這個帳號；摘要不記，但按「查看」打開明細，「詳細內容」會列出 IsAdmin／Status 的舊值與新值（0.9.131 起）。想讓停用與啟用留下明確的紀錄，請直接點清單上的狀態標籤（0.9.120 起），會記成 `User.Disable`／`User.Enable`。

**問：用關鍵字查編號 12，為什麼連 112、120 都跑出來？**
答：關鍵字是部分比對，只要欄位裡含有 `12` 就符合。要找某一筆資料，請改用「目標類型」加「目標識別（精確）」，兩格都是完全相同才符合（0.9.173 起）。

**問：「異動歷程」和這一頁查到的為什麼不一樣多？**
答：資料頁的「異動歷程」只列改了資料的紀錄（新增、修改、啟用／停用、刪除、還原、永久刪除等），不列換頁、按搜尋、開來看這類瀏覽紀錄；這一頁用目標類型與目標識別查，有人按「修改」打開那一筆的紀錄（例如 `Category.View`）也會一起出現，可以用來查誰開過這一筆。

**問：為什麼看不到換頁或查詢紀錄？**
答：0.9.174 起預設不記錄瀏覽類事件（換頁、按搜尋或查詢、打開某一筆來看），頁首說明框會提示目前沒有記錄。需要時請到「系統參數」的「資料保留」分類，把「稽核：記錄瀏覽類事件」打開，下一次換頁或搜尋起就會記；打開前的瀏覽沒有補記。已經記下的瀏覽紀錄預設保留 90 天（「稽核紀錄（瀏覽類）保留天數」）。

**問：為什麼 `User.Update` 這類修改紀錄的明細沒有「詳細內容」？**
答：0.9.174 起預設不記錄修改前後差異，修改仍會記下誰、何時、改了哪一筆。需要看「欄位：舊值 → 新值」時，請到「系統參數」把「稽核：記錄修改前後差異」打開，下一次修改起才會記；差異可能含個人資料，請依內部規定決定。

**問：明細裡的「簽章」寫「升級前的紀錄，未納入完整性驗證」是什麼意思？**
答：系統從 0.9.175 才開始幫每一筆紀錄加簽章，之前留下的紀錄沒有簽章，驗證完整性時不檢查，也不會被當成問題，只會在結果說明裡寫「N 筆升級前的紀錄未納入」。等這些舊紀錄超過保留天數被清掉，就只剩有簽章的紀錄。不過，如果有人在升級之後繞過系統塞進一筆沒有簽章的紀錄，驗證時還是會被抓出來。

**問：驗證結果寫「N 筆是別的金鑰簽的、無法驗證內容」，要緊嗎？**
答：這代表伺服器上的金鑰檔曾經遺失、被換，或換主機時沒有把金鑰帶過去，系統自動產生了新金鑰。舊金鑰簽的紀錄仍會檢查編號有沒有連續，但沒辦法確認內容有沒有被改。這本身不算問題；不過金鑰變更的那一次，每天的排程會發一次警示。請技術人員確認金鑰為什麼不見，並把離線保存的金鑰檔放回原位。

**問：驗證完整性「發現問題」，該怎麼辦？**
答：先把問題清單截圖或抄下來，交給負責資安或系統的人追查是誰、在什麼時候直接動了資料庫或伺服器上的檔案；**不要急著按「清空全部紀錄」**，清空後證據就沒了。被改、被刪的紀錄在清空前每天都會被報出來；金鑰變更、鏈頭重建、資料庫倒回這類一次性的事件，只有第一次看到的那天會報。

**問：從備份還原資料庫之後，隔天收到「稽核紀錄完整性檢查」失敗的通知？**
答：這是預期的。還原會讓資料庫回到備份當時的狀態，比上一次檢查時記下的還舊，系統分不出是「正常還原」還是「有人把資料庫倒回舊版」，所以會報一次「比上次檢查時還舊」。確認是自己還原造成的就可以不理，下一次檢查就會恢復正常。

**問：為什麼有些紀錄的來源 IP 是「—」？**
答：系統排程作業自動做的事（例如每天自動清除舊紀錄）沒有人從瀏覽器操作，所以沒有 IP；0.9.117 之前留下的紀錄當時還沒有記 IP，也會顯示「—」。

**問：還是解決不了怎麼辦？**
答：請記下發生時間、操作的頁面與按鈕、畫面或右下角的訊息（最好截圖；右下角的錯誤訊息可按「複製」，內容、時間與錯誤追蹤碼會一起放進剪貼簿），以及右上角使用者選單「關於」裡的系統版本，回報給系統管理員。
