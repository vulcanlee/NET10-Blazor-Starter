# 寄信紀錄

看系統**寄出的每一封信**：寄給誰、主旨、什麼時候寄出，**失敗了是什麼原因、還會不會再試**。使用者說「沒收到信」時，先來這裡查。

> 這一頁只有管理員可以使用。

### 一分鐘看懂這一頁

- **解決什麼問題**：以前信寄不出去只會記在日誌裡，使用者說「沒收到重設密碼信」時很難查。現在每一封信都有一列紀錄，看得到寄出了沒、失敗的原因。
- **誰會用到**：系統管理員；接到「沒收到信」的回報，或懷疑郵件伺服器設定有問題時使用。
- **它在系統的哪個位置**：左側選單「系統管理 › 監控與診斷 › 寄信紀錄」；寄信方式與郵件伺服器設定在設定檔的 EmailSettings，測試寄信在「系統健康監控」。
- **開始前要準備**：大概知道收信人的 Email 或寄信的時間。
- **做完會得到**：那封信的狀態（待寄、已寄出、失敗、未寄出）、嘗試了幾次、下次什麼時候再試，以及失敗的原因。
- **它不做什麼**：看不到信件內容（內容加密存放，寄出或放棄後就清除），也不能重新寄送；「系統健康監控」寄的測試信是直接寄出，不會出現在這裡。

## 一、功能摘要

在這裡可以做什麼：

- 依建立時間、狀態、種類與關鍵字（收件者或主旨）查詢寄信紀錄，最新的排在最前面；用下方頁碼換頁（每頁 8 筆）。
- 看每封信的狀態、嘗試次數、下次嘗試時間、寄出時間與錯誤摘要；錯誤摘要太長時，滑鼠停在上面可以看完整內容。
- 紀錄超過保留天數（預設 90 天）會由排程作業「寄信紀錄清理」自動刪除；還在等待寄出或重試的信不會被刪。

## 二、這個頁面在做什麼

### 誰會使用、為什麼要用

| 角色 | 為什麼要用 |
|---|---|
| 系統管理員 | 使用者說沒收到信時，確認信有沒有寄出、寄到哪個地址、失敗原因是什麼。 |
| 維運人員 | 更換郵件伺服器或密碼之後，確認信件恢復正常寄出。 |

### 信是怎麼寄出去的

1. 系統要寄信時（例如忘記密碼、帳號被鎖定通知管理員），先把信交給背景寄信器，畫面馬上回應，不必等郵件伺服器。
2. 背景寄信器把信存成一列「待寄」，信件內容加密存放。
3. 接著寄出。成功就記「已寄出」並清除內容。
4. 失敗時看原因：
   - **暫時性失敗**（連不上郵件伺服器、逾時、郵件伺服器回「稍後再試」）：過 1 分鐘、5 分鐘、15 分鐘再試，最多重試 3 次（次數可在「系統參數」調整）。都失敗就記「失敗」。
   - **永久性失敗**（帳號密碼錯、收件者被拒、收件者格式錯）：再試也不會好，直接記「失敗」。
5. 網站重新啟動時，「待寄」的信會接著寄，不會遺失。

### 需要的權限

| 權限 | 可以做的事 |
|---|---|
| 管理員 | 進入本頁、查詢寄信紀錄。 |
| 非管理員 | 無法使用。左側選單不會出現這一項；直接輸入網址會看到「你沒有權限存取此頁面」。 |

> 「管理員」是在「使用者管理」裡對使用者勾選的「管理員」，角色管理無法把這一頁開放給一般使用者。收件者是個資，所以只開放給管理員。

### 它跟其他頁面的分工

| 你想做的事 | 該去哪 |

| 查某封信有沒有寄出、為什麼失敗 | 這一頁 |
| 測試郵件伺服器設定能不能寄信 | 「系統健康監控」的寄信測試 |
| 調整重試次數或紀錄保留天數 | 「系統參數」 |

## 四、建議這樣操作，會得到什麼

### 使用者說沒收到重設密碼信

1. 在「關鍵字」輸入他的 Email，按「查詢」。
2. 找種類「重設密碼」、時間相符的那一列，看狀態：
   - **已寄出**：信已交給郵件伺服器，請他看垃圾郵件匣，或確認收件者地址正確。
   - **待寄**：正在重試，看「下次嘗試」的時間，稍後按「重新整理」。
   - **失敗**：看「錯誤摘要」。帳密錯誤或連不上伺服器時請洽負責郵件設定的人員；修好後請使用者重新申請。
   - **未寄出（寄信停用）**：系統的寄信方式是 None，請洽負責部署的人員設定 EmailSettings。
   - **找不到**：可能是帳號不存在或 Email 不對，系統不會寄信（畫面上刻意顯示相同的訊息，避免洩漏帳號是否存在）。

**會得到什麼**：知道問題出在系統、郵件伺服器還是收件端。

### 更換郵件伺服器設定之後

1. 先在「系統健康監控」寄一封測試信。
2. 之後等下一封正常寄出的信（例如請一位同事用「忘記密碼」申請重設），到這裡確認狀態是「已寄出」。

**會得到什麼**：確認新設定在正式寄信流程裡也正常。

## 五、名詞解釋

| 名詞 | 白話解釋 |
|---|---|
| **待寄** | 還沒寄，或暫時性失敗後等待重試。 |
| **已寄出** | 已經交給郵件伺服器。之後對方有沒有收到、有沒有被當成垃圾郵件，這裡看不到。 |
| **失敗** | 永久性失敗，或重試次數用完；系統不會再寄這封信。 |
| **未寄出（寄信停用）** | 當時系統的寄信方式是 None，所以這封信沒有寄。 |
| **暫時性失敗** | 等一下可能就會好的失敗：連不上郵件伺服器、逾時、伺服器回「稍後再試」。 |
| **永久性失敗** | 再試也不會好的失敗：帳號密碼錯誤、收件者被拒、Email 格式錯。 |

## 七、常見問題

**問：為什麼看不到信件內容？**
答：信件內容（例如重設密碼連結）加密存放，寄出或放棄後就清除，避免資料庫裡留下可以使用的重設連結。這裡只保留收件者、主旨與結果。

**問：失敗的信可以重新寄嗎？**
答：不行，內容已經清除了。請使用者重新操作一次（例如重新申請重設密碼），系統會寄一封新的信。

**問：為什麼「系統健康監控」的測試信不在這裡？**
答：測試信是直接寄出、當場告訴你結果，不經過寄信佇列，所以不會記在這裡。

**問：網站重新啟動時，正在等待重試的信會不見嗎？**
答：不會。「待寄」的信存在資料庫裡，網站重新啟動後會接著寄。

**問：還是解決不了怎麼辦？**
答：請記下那封信的建立時間、收件者與錯誤摘要，以及右上角使用者選單「關於」裡的系統版本，回報給系統管理員。
