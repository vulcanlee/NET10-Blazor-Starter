# 日誌檢視

依時間區間、最低等級與關鍵字**查詢系統日誌**，逐筆看某段時間內系統做了什麼；可以**匯出原始日誌**，也可以**請 AI 把查到的結果整理成報告**。

> 這一頁只有管理員可以使用。

### 一分鐘看懂這一頁

- **解決什麼問題**：知道「某個時間點出了事」之後，要看那段時間前後系統逐筆的經過，找出錯誤發生前做了哪些事、影響了誰。
- **誰會用到**：負責維運與排查問題的系統管理員；需要把一段日誌交給開發人員或廠商時，也從這裡匯出。
- **它在系統的哪個位置**：側邊選單「系統管理 › 統計與分析」。排查順序通常是：健康監控看有沒有壞 → 系統例外紀錄看是哪種錯 → 本頁看當時的逐筆脈絡。
- **開始前要準備**：大概的發生時間（前後最多 3 天）；最好再準備一個關鍵字，例如使用者帳號、錯誤訊息片段或一段 TraceId。
- **做完會得到**：一份依時間倒序排列的日誌清單、可下載的原始日誌檔，以及（有啟用 AI 時）一份可複製或匯出 PDF 的 AI 分析報告。
- **它不做什麼**：不會調整日誌要記錄多細（那是日誌等級設定頁），也不會把同一種錯誤合併計次（那是系統例外紀錄頁）；沒寫進檔案的內容這裡也查不到。

## 一、功能摘要

這一頁直接讀取系統的日誌檔，依你設定的時間區間、最低等級、筆數與關鍵字篩選，把結果列成表格，最新的在最上面，每頁 20 筆。展開任一列可以看到那一筆的完整原始內容。查到的結果可以原封不動匯出成日誌檔，也可以一鍵送給 AI，請它整理出重點、可能原因與建議，並把 AI 的報告複製或匯出成 PDF。打開頁面時會自動查詢最近 1 小時的日誌。

## 二、這個頁面在做什麼

統計與分析群組裡的幾個頁面構成一條排查工具鏈，本頁負責「看某段時間的逐筆脈絡」：

| 頁面 | 回答的問題 |
|---|---|
| 系統健康監控 | 基礎元件現在有沒有壞？ |
| 系統例外紀錄 | 出過哪幾種錯、各發生幾次？（同一種錯誤合併成一列） |
| 日誌檢視（本頁） | 某段時間內系統逐筆做了什麼？可請 AI 整理。 |
| 日誌等級設定 | 日誌不夠細時，暫時調細等級再重現問題。 |
| 資料庫用量、Token 用量 | 容量還夠不夠、AI 花了多少錢。 |

本頁看到的是**逐筆**事件，系統例外紀錄看到的是**聚合後**的次數，所以兩邊的筆數對不起來是正常的。

本頁只能查到**已經寫進日誌檔**的內容。日誌等級設定為「INFO」時，DEBUG 與 TRACE 的訊息根本沒有被寫下來，這裡把最低等級選成 TRACE 也查不到。需要更細的資訊時，請先到日誌等級設定頁調低等級，重現問題後再回來查。

## 三、畫面上有哪些按鈕、各自做什麼

### 查詢條件

| 條件 | 說明 |
|---|---|
| 起始時間／結束時間 | 查詢區間，精確到秒。預設是最近 1 小時。 |
| 最低等級 | 只看這個等級以上的日誌：不限、TRACE、DEBUG、INFO、WARN、ERROR、FATAL。 |
| 筆數 | 最多取幾筆，預設 100，可填 1～10,000。符合條件的超過這個數字時，保留**最新**的那幾筆。 |
| 關鍵字（比對整筆原始內容） | 不只比對訊息欄，而是比對整筆原始內容，所以帳號、記錄器名稱、TraceId 都能搜到。 |

> **提醒**：查詢區間**最長 3 天**。超過時系統會把起始時間往後調，並顯示黃色提示「查詢區間上限為 3 天，起始時間已調整為 …。」；起始時間晚於結束時間時會自動對調。調整後的實際區間會寫回兩個時間欄位，畫面與結果一致。

### 工具列按鈕

| 按鈕（滑鼠提示） | 做什麼 |
|---|---|
| 查詢 | 依目前條件重新讀取日誌。 |
| 匯出本次查詢結果（原始 nlog 格式） | 把目前查到的結果依時間先後，原封不動下載成一個 `.log` 檔。沒有結果時停用。 |
| AI 分析（將本次查詢結果送給 AI 整理） | 把目前查到的結果送給 AI 整理成報告。沒有結果或分析進行中時停用；AI 未設定時也停用，滑鼠移上去會顯示原因。 |

查詢後的狀態會顯示在表格上方：藍色是一般訊息（例如「指定條件下查無日誌紀錄。」「指定區間內沒有日誌檔案。」），黃色是條件被調整或某個檔案讀取失敗的提醒。

### 結果表格

| 欄位 | 意思 |
|---|---|
| 時間 | 這一筆日誌寫下的時間，精確到毫秒。 |
| 等級 | 以不同顏色的標籤顯示 TRACE～FATAL。 |
| 記錄器 | 寫出這筆日誌的程式模組名稱。 |
| 訊息 | 日誌訊息，過長時會截斷；展開整列可看完整原始內容。 |
| TraceId | 同一次請求的所有日誌共用同一個 TraceId，拿它當關鍵字查詢就能把一次請求的經過串起來。 |

### AI 分析對話窗

按下 AI 分析後，對話窗會立刻打開，標題隨狀態變化：

| 狀態 | 對話窗標題 | 畫面內容 |
|---|---|---|
| 進行中 | AI 日誌分析（進行中） | 「AI 正在分析 N 筆日誌…」與「已等待 N 秒」。推論可能需要數十秒到數分鐘。 |
| 失敗 | AI 日誌分析失敗 | 「AI 分析未完成」與失敗原因。 |
| 完成 | AI 日誌分析結果 | 分析報告，以及下表的按鈕與資訊。 |

| 按鈕或欄位 | 做什麼 |
|---|---|
| 一般／中／大 | 切換報告的字級。每次打開對話窗都會回到「一般」。 |
| 複製結果（Markdown 原文） | 把報告原文複製到剪貼簿，方便貼到工單或通訊軟體。 |
| 匯出 PDF 報告並下載 | 把報告連同查詢條件做成 PDF 下載。 |
| 查詢區間、最低等級、關鍵字 | 這次分析所用的查詢條件；沒填關鍵字時不顯示。 |
| 分析範圍 | 例如「分析 100 筆／查詢 300 筆」，表示實際送給 AI 的筆數與查到的總筆數。 |
| 使用模型、用量、耗時 | 這次分析用了哪個模型、多少 token、花了幾秒。 |

> **提醒**：AI 分析會**計費**，並以作業名稱「AI 日誌分析」記進 Token 用量頁。每次最多送出系統設定的筆數（預設 100 筆），查到的比這個多時只送**最新**的那些，並跳出提示「查詢共 N 筆，因筆數上限僅分析最新 M 筆。」。

> **提醒**：分析進行中，點對話窗外面**不會**關閉；按右上角關閉等於放棄這次分析，畫面會提示「已取消本次 AI 分析。」。請求可能已經送出，放棄不代表不計費。

- AI 分析送出的是**畫面上已經查出的結果**，不會重新查詢。改了條件之後，請先按「查詢」再按 AI 分析。
- 每次分析與每次匯出 PDF 都會在稽核紀錄留下一筆，動作分別為 `LogViewer.AiAnalyze` 與 `LogViewer.AiAnalyzeExportPdf`。
- AI 的報告會先經過安全處理再顯示（移除圖片、限制連結種類），因為日誌內容有一部分來自使用者輸入，不能完全信任。

## 四、建議這樣操作，會得到什麼

### 情境一：使用者說「剛剛下午三點存檔失敗」

1. 把起始時間設為 14:50、結束時間設為 15:10。
2. 最低等級選「WARN」，關鍵字填入該使用者的帳號，按「查詢」。
3. 找到錯誤那一列，展開看完整原始內容，記下它的 TraceId。
4. 把關鍵字換成那段 TraceId、最低等級改回「不限」，再查一次。

會得到：同一次請求從進來到出錯的完整經過，可以看出錯誤前系統做了哪些事。

### 情境二：一天內錯誤很多，想快速知道重點

1. 設定要看的時間區間（最長 3 天），最低等級選「ERROR」，按「查詢」。
2. 確認查到的筆數合理後，按「AI 分析（將本次查詢結果送給 AI 整理）」。
3. 等待對話窗出現結果，必要時用「大」字級閱讀。
4. 按「匯出 PDF 報告並下載」，把報告交給開發人員。

會得到：一份整理過的錯誤摘要報告，以及稽核紀錄裡一筆分析紀錄；費用會出現在 Token 用量頁。

### 情境三：需要把原始日誌交給廠商

1. 設定時間區間與條件，把「筆數」調高到足夠涵蓋整段期間，按「查詢」。
2. 確認表格上方沒有黃色提示說條件被調整過。
3. 按「匯出本次查詢結果（原始 nlog 格式）」下載 `.log` 檔。

會得到：一個依時間先後排列、與原始日誌檔格式相同的檔案，對方可以直接用慣用的工具閱讀。

## 五、名詞解釋

| 名詞 | 白話解釋 |
|---|---|
| 日誌 | 系統運作時逐筆寫下的紀錄，存在伺服器的檔案裡，一天一個檔案。 |
| 等級 | 每筆日誌的重要程度，由細到粗為 TRACE、DEBUG、INFO、WARN、ERROR、FATAL。 |
| 最低等級 | 只顯示這個等級以上的日誌；選 WARN 時會顯示 WARN、ERROR、FATAL。 |
| 記錄器 | 寫出這筆日誌的程式模組名稱，可用來判斷是哪個功能發出的。 |
| TraceId | 同一次請求共用的追蹤編號，用來把分散的多筆日誌串成一次完整的經過。 |
| 原始內容 | 日誌檔裡那一整行（或多行）的原文，關鍵字就是比對這個。 |
| AI 日誌分析 | 把查到的日誌送給 AI 整理成報告；在 Token 用量頁也用這個名稱記帳。 |

## 六、相關頁面

以下列出與這一頁搭配使用的頁面；你沒有權限進入的頁面不會顯示。

- [系統例外紀錄](/system-exceptions)：先在那裡找出是哪種錯誤、最後發生時間，再回本頁看當時的逐筆經過。
- [日誌等級設定](/log-level-setting)：本頁查不到需要的細節時，到那裡暫時調低等級再重現問題。
- [系統健康監控](/system-health)：懷疑是資料庫或磁碟等基礎元件故障時，先到那裡確認。
- [Token 用量](/token-usage)：每次 AI 分析的 token 數與費用都記在那裡，作業名稱為「AI 日誌分析」。
- [稽核紀錄](/audit-logs)：查誰在什麼時候做過 AI 分析或匯出分析報告。

## 七、常見問題

**我明明把最低等級選成 TRACE，為什麼還是看不到 DEBUG 的訊息？**
本頁只能查到已經寫進檔案的內容。若日誌等級設定頁目前生效的等級是 INFO，比 INFO 細的訊息當初就沒有寫下來。請先到日誌等級設定頁調低等級、重現問題，再回來查。

**為什麼我設了一週的區間，查出來只有三天？**
查詢區間最長 3 天，超過時系統會自動把起始時間往後調，並在表格上方顯示黃色提示。需要更長的期間，請分成幾段查詢。

**查詢結果只有 100 筆，是不是漏了？**
「筆數」預設是 100，符合條件的超過這個數字時只保留最新的 100 筆。可以把筆數調高（最多 10,000），或縮小時間區間、加上關鍵字。

**AI 分析的結果可以完全相信嗎？**
不行。AI 報告是協助閱讀的摘要，可能遺漏或誤判；做出決定前，請回到表格核對原始日誌。若出現「回應已達長度上限，結尾可能不完整」的提示，代表報告後段可能被截掉，請縮小查詢範圍後再分析一次。
