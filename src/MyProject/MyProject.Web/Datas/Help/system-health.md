# 系統健康監控

一頁看完系統是否正常：**開頁當下**逐項檢查資料庫、日誌、身分驗證、磁碟、AI、快取、寄信等 12 個項目，給出健康百分比與紅黃綠燈，並可**寄出測試信**確認寄信設定。

> 這一頁只有管理員可以使用。

### 一分鐘看懂這一頁

- **解決什麼問題**：使用者反映「系統怪怪的」時，先用一頁確認是不是有哪個基礎元件壞了，例如資料庫連不上、磁碟快滿、AI 端點不通、寄信主機登入失敗。
- **誰會用到**：負責維運的系統管理員；部署新版本、改完設定檔、或接到異常回報時，第一個打開的就是這一頁。
- **它在系統的哪個位置**：側邊選單「系統管理 › 統計與分析」的第一項，是排查工具鏈的起點：先在這裡看「有沒有壞」，再到系統例外紀錄看「是哪種錯」，到日誌檢視看「當時的逐筆經過」。
- **開始前要準備**：不需要準備任何條件；打開頁面就會自動檢查。若要測試寄信，準備一個你收得到信的 Email 信箱。
- **做完會得到**：一個總分與燈號、12 張檢查卡片（每張有狀態、權重、判斷依據與失敗原因）、今天日誌檔的最後 100 筆，以及一次寄信測試的成敗結果。
- **它不做什麼**：不會修復任何問題，也沒有背景排程、不會自動通知；它只在你打開頁面的那一刻檢查一次，離開頁面後不會再更新。

## 一、功能摘要

這一頁把系統的基礎狀態集中成一份「體檢報告」。打開頁面時，系統會依序檢查 12 個項目，每一項給出「正常」「警示」或「異常」，再依各項權重算出一個健康百分比，用紅黃綠燈表示整體狀況。頁面下方另有兩個輔助區塊：「寄信測試」可以當場寄一封測試信確認寄信設定是否正確；「最後 100 筆日誌紀錄」直接顯示今天日誌檔的最後幾行，讓你不必切換頁面就能瞄一眼系統剛剛在做什麼。

## 二、這個頁面在做什麼

這一頁是排查問題時的**第一站**，只回答一件事：「系統的基礎元件現在有沒有壞」。它和統計與分析群組裡的其他頁面分工如下：

| 頁面 | 回答的問題 |
|---|---|
| 系統健康監控（本頁） | 基礎元件現在有沒有壞？ |
| 系統例外紀錄 | 程式出過哪幾種錯、各發生幾次？ |
| 日誌檢視 | 某一段時間內系統逐筆做了什麼？可請 AI 幫忙整理。 |
| 日誌等級設定 | 日誌不夠細、看不出原因時，暫時調細再重現一次。 |
| 資料庫用量、Token 用量 | 容量還夠不夠、AI 花了多少錢。 |

本頁的檢查**只在打開頁面時執行一次**，沒有背景排程。想重新檢查，請重新整理瀏覽器或重新進入本頁。檢查過程中畫面會顯示「正在讀取系統健康狀態...」，其中 AI 的檢查最長可能等候 30 秒。

> **提醒**：「LLM API」這一項每次開頁都會**真的呼叫一次 AI**，會產生費用，並以作業名稱「系統健康檢測」記進 Token 用量頁。請不要把這一頁當成常駐儀表板一直開著或反覆重新整理，需要時再開即可。

## 三、畫面上有哪些按鈕、各自做什麼

### 頂端總覽

| 畫面上的名稱 | 意思 |
|---|---|
| 燈號與健康百分比 | 各項得分加總後除以總權重。每項「正常」給滿分、「警示」給一半、「異常」給 0 分。 |
| 整體狀態文字 | 百分比 90 以上顯示「正常」（綠燈），70 以上顯示「警示」（黃燈），低於 70 顯示「異常」（紅燈）。 |
| 最後檢查時間 | 這份報告產生的時間。因為只在開頁時檢查，這個時間就是你打開頁面的時間。 |

> **提醒**：12 項的權重加起來是 **135，不是 100**。所以「權重 10」的項目在總分裡佔的比例不到一成；權重高只代表它比較影響分數，不代表它比較嚴重。

### 檢查項目卡片

每張卡片上依序是：燈號、項目名稱、「類別 · 權重 N」、右上角的狀態（正常／警示／異常）、一段判斷依據的實際數值，以及只有出問題時才會出現的紅框失敗原因。排錯時真正有用的是那段**判斷依據**，例如資料庫卡片會寫出是否可連線、還有幾個資料庫更新尚未套用。

| 檢查項目 | 類別 | 權重 | 檢查什麼 |
|---|---|---|---|
| 網站 / 應用程式 | Application | 10 | 執行環境、系統版本、啟動時間與已運作時間。 |
| API | API | 10 | 對外 API 是否有註冊成功。 |
| 資料庫 | Database | 25 | 能否連線；仍有未套用的資料庫更新時為警示。 |
| 日誌 | Logging | 15 | 日誌目錄能否寫入、今天的日誌檔是否存在。 |
| 身分驗證 | Authentication | 15 | 登入與 API 驗證設定是否完整；正式環境若仍用開發用金鑰則為異常。 |
| 檔案系統 | FileSystem | 10 | 資料庫、下載、上傳、專案檔案等目錄是否存在且可寫入。 |
| 主機資源 | Host | 5 | 程式占用的記憶體與磁碟剩餘空間；剩不到 1 GB 為警示。 |
| 安全設定 | Security | 10 | 正式環境是否開啟了不該開的診斷功能。 |
| LLM API | Ai | 10 | 實際送一句話給 AI，確認有回應。AI 未設定時為警示，不會發出請求。 |
| 快取服務 | Cache | 10 | 寫入一筆測試值再讀回比對，確認快取真的能用。 |
| AI 計費表 | AiPricing | 5 | 目前使用的 AI 模型查不查得到價格；查不到時 Token 用量頁會記成「未定價」。 |
| 寄信服務 | Email | 10 | 寄信設定。只有正式寄信模式會實際連線並登入寄信主機（不寄信、最長 5 秒）；未啟用或開發模式固定為警示。 |

### 寄信測試

| 畫面上的名稱 | 做什麼 |
|---|---|
| 目前的寄送方式 | 顯示 `None（未啟用）`、`Pickup` 或 `Smtp`。`Pickup` 是開發用，信件只會寫成檔案，不會真的寄出。 |
| 「收件者 Email」輸入框 | 測試信要寄給誰，預先填好你自己的 Email。 |
| 寄出測試信 | **當場**寄一封測試信並等待結果，綠色訊息表示成功、紅色表示失敗。 |

- 寄送方式為 `None（未啟用）` 時，輸入框與按鈕都會停用，下方提示寄信功能未啟用。
- Email 格式不對時顯示「請輸入有效的收件者 Email。」，不會寄出。
- 成功時顯示「測試信已寄出，請到收件匣確認。」；`Pickup` 模式則顯示「測試信已寫入 Pickup 資料夾（不會真正寄出）。」。
- 失敗時顯示「寄送失敗：…。詳細原因請查看日誌。」。
- 每次測試（不論成敗）都會在稽核紀錄留下一筆動作 `Email.Test`，但**不記收件者**。

### 最後 100 筆日誌紀錄

顯示今天日誌檔的最後 100 行，右側是日誌檔所在路徑。讀不到時會改顯示原因，例如「今日日誌檔案尚未建立。」；沒有內容時顯示「沒有可顯示的日誌紀錄。」。這一區只能看，不能搜尋或篩選；要查詢請到日誌檢視頁。

## 四、建議這樣操作，會得到什麼

### 情境一：部署新版本之後做健康確認

1. 部署完成、網站啟動後，登入並打開本頁。
2. 看頂端燈號是否為綠燈、百分比是否為 90 以上。
3. 逐張看是否有黃燈或紅燈的卡片，特別是「資料庫」與「檔案系統」。
4. 看「網站 / 應用程式」卡片上的版本是否為剛部署的版本。

會得到：一份部署後的體檢結果。若「資料庫」卡片寫著仍有未套用的資料庫更新，代表更新沒有跑完，要回頭處理。

### 情境二：使用者反映收不到重設密碼信

1. 打開本頁，看「寄信服務」卡片的狀態與紅框失敗原因。
2. 到「寄信測試」區，在「收件者 Email」填入你自己的信箱，按「寄出測試信」。
3. 看回傳的綠色或紅色訊息；失敗時記下時間。
4. 到日誌檢視頁查詢那個時間點前後的日誌，找出完整原因。

會得到：確認問題出在寄信設定、寄信主機，還是使用者的信箱本身。

### 情境三：接到「系統變慢、偶爾出錯」的回報

1. 打開本頁，先確認沒有紅燈的項目。
2. 看「主機資源」卡片的記憶體與磁碟剩餘空間。
3. 拉到最下方看最後 100 筆日誌裡是否有連續的錯誤訊息。
4. 若基礎元件都正常，改到系統例外紀錄頁看最近出現了哪些錯誤。

會得到：快速排除「基礎元件故障」這個可能，把排查範圍縮小到程式邏輯或特定操作。

## 五、名詞解釋

| 名詞 | 白話解釋 |
|---|---|
| 健康百分比 | 各項得分除以總權重再乘以 100。總權重是 135，不是 100。 |
| 權重 | 這一項在總分裡的份量。權重越高越影響分數，但不代表問題越嚴重。 |
| 正常／警示／異常 | 各項的三種狀態，分別對應綠、黃、紅燈，得分為滿分、一半、0 分。 |
| 判斷依據 | 卡片中間那段實際數值，是系統判斷狀態的根據，排錯時最有用。 |
| 選配功能 | AI 與寄信都是可以不啟用的功能；未設定時給黃燈而不是紅燈，避免沒用這些功能的系統永遠亮紅燈。 |
| Pickup | 開發用的寄信模式，信件只寫成檔案存放在資料夾，不會真的寄出。 |
| 系統健康檢測 | LLM API 檢查在 Token 用量頁上的作業名稱；每開一次本頁就多一筆。 |

## 七、常見問題

**為什麼沒有「重新檢查」按鈕？數字會自己更新嗎？**
不會自己更新。本頁只在打開時檢查一次，沒有背景排程；想重新檢查請重新整理瀏覽器或重新進入本頁。刻意不做自動更新，是因為 LLM API 那一項每檢查一次就會計費一次。

**為什麼每一項都是綠燈，總分卻不到 100？**
不會發生這種情況；若看到低於 100，一定有卡片是黃燈或紅燈。最常見的是沒有啟用 AI 或寄信功能，這兩項會固定顯示警示並各扣掉一半分數。這是正常的，不代表系統壞了。

**Token 用量頁為什麼出現很多「系統健康檢測」的紀錄？**
每打開一次本頁，LLM API 檢查就會真的呼叫 AI 一次並記一筆。每筆的量很小，但次數多了還是會累積費用。那些紀錄的使用者欄是打開本頁的那位管理員。

**寄信服務是綠燈，是不是代表信一定寄得到？**
不一定。綠燈只代表能連上寄信主機並登入成功，並沒有真的寄信。要確認收得到，請用「寄出測試信」寄一封給自己。
