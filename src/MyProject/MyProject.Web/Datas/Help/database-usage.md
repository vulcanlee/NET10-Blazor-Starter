# 資料庫用量

查看資料庫**實際佔了多少磁碟空間**、有多少空間可以回收，以及**每一張資料表**的紀錄筆數與資料量估算。

> 這一頁只有管理員可以使用。

### 一分鐘看懂這一頁

- **解決什麼問題**：磁碟空間吃緊、備份檔越來越大，或刪了很多資料檔案卻沒變小時，用這一頁確認資料庫到底佔了多少、哪張表最大。
- **誰會用到**：負責主機容量與備份規劃的系統管理員；定期巡檢時也可以順手看一下各表的成長。
- **它在系統的哪個位置**：側邊選單「系統管理 › 統計與分析」。它和 Token 用量頁一起負責「容量與費用」，是排查工具鏈裡看長期趨勢的一環，不負責找錯誤。
- **開始前要準備**：不需要準備任何條件，打開頁面就會讀取；只要記得同一頁上有四種不同意思的「大小」，閱讀前先分清楚。
- **做完會得到**：六張容量卡片（磁碟占用、三個檔案各自的大小、已配置、可回收）與一張各資料表的筆數、資料量估算、索引數清單。
- **它不做什麼**：這一頁只能看，不能刪資料、不能壓縮或整理資料庫，也沒有任何按鈕；它也不會自動更新，要看最新數字請重新整理頁面。

## 一、功能摘要

打開頁面時，系統會讀取資料庫檔案的實際大小與內部的頁數資訊，整理成六張卡片，再逐一統計每張資料表的紀錄筆數、欄位內容的位元組總量與索引數，列成一張可以排序的表格。卡片下方有兩段固定的說明，解釋為什麼預寫日誌可能比主檔大、為什麼資料量估算不是磁碟占用量，這是最容易誤會的兩件事。本系統的資料庫是單一檔案型的資料庫，所以這裡看到的「檔案大小」就是它在硬碟上實際吃掉的空間。

## 二、這個頁面在做什麼

統計與分析群組裡的幾個頁面構成一條排查工具鏈，本頁和 Token 用量頁負責「容量與費用」：

| 頁面 | 回答的問題 |
|---|---|
| 系統健康監控 | 基礎元件現在有沒有壞？ |
| 系統例外紀錄 | 出過哪幾種錯、各發生幾次？ |
| 日誌檢視、日誌等級設定 | 某段時間內系統逐筆做了什麼？細節不夠時如何調細？ |
| 資料庫用量（本頁） | 資料庫佔了多少空間、哪張表最大？ |
| Token 用量 | AI 用了多少 token、花了多少錢？ |

這一頁最重要的觀念是：**同一頁上有四種不同的「大小」，不可混用，也不能互相加減**。

| 哪一種大小 | 對應畫面 | 回答的問題 |
|---|---|---|
| 檔案大小 | 磁碟占用總計、主資料庫檔、預寫日誌、共享記憶體索引 | 硬碟實際被吃掉多少？ |
| 已配置 | 已配置 | 資料庫內部總共開了多少頁的空間？ |
| 可回收 | 可回收 | 其中有多少是閒置、可以還給作業系統的？ |
| 資料量估算 | 表格的「資料量估算」欄 | 每張表的欄位內容大約有多少位元組？ |

要回答「硬碟被吃掉多少」，只看「磁碟占用總計」。表格的資料量估算加總起來，**不會等於**上面任何一張卡片的數字。

## 三、畫面上有哪些按鈕、各自做什麼

這一頁**沒有任何按鈕**，所有內容在打開頁面時讀取一次。讀取中顯示「正在讀取資料庫用量...」；讀取失敗時整頁改顯示紅色的「讀取資料庫用量失敗：…。」。

### 容量卡片

| 卡片 | 卡片下方的說明 | 意思 |
|---|---|---|
| 磁碟占用總計 | 主檔 + WAL + SHM 三個檔案 | 下面三個檔案的大小加總，這才是「硬碟被吃掉多少」。 |
| 主資料庫檔 | 資料庫檔案名稱 | 資料庫主檔本身的大小。 |
| 預寫日誌 | 檔案名稱，或「目前無此檔案（已 checkpoint）」 | 尚未併回主檔的交易紀錄檔，會週期性縮回去。 |
| 共享記憶體索引 | 檔案名稱，或「目前無此檔案」 | 資料庫運作時用的輔助小檔案。 |
| 已配置 | N 頁 × N B，含尚未併回主檔的頁 | 資料庫內部的頁數乘以每頁大小。因為包含還在預寫日誌裡的頁，可能比主資料庫檔大。 |
| 可回收 | N 個閒置頁，VACUUM 可釋放 | 刪除資料後留下的閒置頁，整理資料庫（VACUUM）後可以還給作業系統。 |

卡片下方有一段固定的說明：「**預寫日誌（WAL）比主檔大是正常的**。它是尚未 checkpoint 的交易紀錄，SQLite 會在適當時機把內容併回主檔並回收，不代表資料量暴漲。」

### 資料量估算的註記

表格上方另有一段註記，內容是：「資料量估算」不是磁碟占用量。它是各欄位內容的位元組加總，**不含索引、頁面碎片與已配置的閒置頁**，與實際磁碟占用會有差距。原因是系統使用的資料庫版本沒有提供逐表統計實際頁數的功能，因此只能用欄位內容的長度來估算。

> **提醒**：刪了很多資料但檔案沒有變小，是資料庫的正常行為：刪除只會把空間標成閒置，留著給之後的新資料用。這時請看「可回收」卡片。本頁沒有提供整理資料庫的按鈕，需要釋放空間時，請聯絡負責伺服器維護的人員安排。

### 資料表清單

| 欄位 | 意思 |
|---|---|
| 資料表 | 資料表名稱，預設依名稱排序。 |
| 紀錄筆數 | 這張表目前有幾筆資料；讀不到時顯示「—」。 |
| 資料量估算 | 欄位內容的位元組加總，不是磁碟用量。估算失敗時顯示「—」，滑鼠移上去可看原因。 |
| 索引數 | 這張表建了幾個索引。索引也佔空間，但沒有算進資料量估算。 |

- 四個欄位都可以點欄位標題排序，依實際數值排序，不會把 1.5 MB 排在 900 KB 後面。
- 清單一次列出全部資料表，不分頁。
- 有狀況時表格上方會出現黃色提示，例如「資料庫中沒有任何資料表。」、「找不到資料庫檔案：…」或「資料量估算失敗，已略過：…」。

## 四、建議這樣操作，會得到什麼

### 情境一：主機磁碟快滿了，想知道資料庫佔多少

1. 打開本頁，看「磁碟占用總計」。
2. 再看「預寫日誌」是否特別大；暫時偏大是正常的，過一段時間通常會縮回去。
3. 看「可回收」，估計整理資料庫後能釋放多少空間。

會得到：資料庫在硬碟上的實際用量，以及其中有多少是可以回收的閒置空間，作為是否安排整理或擴充磁碟的依據。

### 情境二：想找出成長最快的資料表

1. 打開本頁，點「紀錄筆數」欄位標題，改成由大到小排序。
2. 再點「資料量估算」欄位標題，看哪張表的內容最大。
3. 記下前幾名的數字，下個月再來比對一次。

會得到：各表的相對大小與成長趨勢。記得資料量估算只適合拿來互相比較，不能當成磁碟用量。

### 情境三：清除大量舊紀錄後，確認空間是否釋放

1. 在 Token 用量頁或其他頁面清除舊資料後，重新整理本頁。
2. 看對應資料表的「紀錄筆數」是否下降。
3. 看「可回收」是否增加；「磁碟占用總計」通常不會立刻變小。

會得到：確認資料確實已刪除，並了解要真正縮小檔案，還需要另外整理資料庫。

## 五、名詞解釋

| 名詞 | 白話解釋 |
|---|---|
| 磁碟占用總計 | 資料庫三個檔案在硬碟上的實際大小加總，是唯一能回答「硬碟被吃掉多少」的數字。 |
| 預寫日誌（WAL） | 新寫入的資料先記在這個檔案，之後再併回主檔（稱為 checkpoint）；暫時比主檔大是正常的。 |
| 共享記憶體索引（SHM） | 資料庫運作時使用的輔助小檔案。 |
| 頁 | 資料庫內部配置空間的單位，每頁大小固定。 |
| 已配置 | 資料庫內部總頁數乘以每頁大小，包含還在預寫日誌裡的頁。 |
| 可回收 | 刪除資料後留下的閒置頁，整理資料庫後可以還給作業系統。 |
| VACUUM | 整理資料庫、把閒置頁還給作業系統的維護作業；本頁不提供這個動作。 |
| 資料量估算 | 各欄位內容的位元組加總，不含索引、碎片與閒置頁，只適合各表之間互相比較。 |

## 七、常見問題

**我刪了很多資料，為什麼磁碟占用總計沒有變小？**
刪除只會把空間標成閒置，留給之後的新資料使用，檔案本身不會自動縮小。這些閒置空間會顯示在「可回收」卡片。要真正縮小檔案，需要由負責伺服器維護的人員整理資料庫。

**為什麼表格的資料量估算加起來，和磁碟占用總計差很多？**
兩者本來就是不同的東西。資料量估算只算欄位內容本身，不含索引、頁面碎片與閒置頁；磁碟占用總計是檔案的實際大小。四種大小不能互相加減比對。

**預寫日誌比主資料庫檔還大，是不是出問題了？**
通常不是。預寫日誌是還沒併回主檔的交易紀錄，資料庫會在適當時機併回並縮小它。若它長時間持續變大、完全不縮回，才需要請負責伺服器的人員檢查。

**數字會自動更新嗎？**
不會。這一頁只在打開時讀取一次，要看最新數字請重新整理頁面。
