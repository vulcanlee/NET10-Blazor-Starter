# 使用者管理

這一頁讓你**建立與維護系統帳號**，並在同一張表單裡**指派角色、額外角色與團隊**，決定每個人能做什麼、看得到哪些資料。

> 這一頁只有管理員可以使用。

### 一分鐘看懂這一頁

- **解決什麼問題**：新人要開帳號、有人離職要停用、有人換部門要調整角色或團隊時，都在這裡處理。
- **誰會用到**：負責帳號與權限的系統管理員；一般使用者打開這一頁只會看到「你沒有權限存取此頁面」。
- **它在系統的哪個位置**：側邊選單「系統管理 › 權限管理」底下；角色要先在「角色管理」建好，團隊要先在「團隊清單」建好，這裡才選得到。
- **開始前要準備**：確認要指派的角色已經存在、角色的權限勾對了，並想清楚這個人要看哪些團隊的資料。
- **做完會得到**：一個可以登入的帳號，權限是所有角色權限的合計，看得到的資料範圍是直接綁定的團隊加上所有角色的預設團隊。
- **它不做什麼**：不能在這裡設定「某個角色能做哪些動作」（那是角色管理的事），也看不到這個人做過什麼（請到稽核紀錄查）。

## 一、功能摘要

- 新增、修改、刪除使用者帳號，並可重新整理清單。
- 以關鍵字搜尋帳號、名稱、Email 或角色名稱，清單預設依帳號由小到大排列，各欄都可以點標題排序。
- 在同一張表單裡指派一個主要角色、任意多個額外角色，以及直接綁定的團隊。
- 以「啟用」勾選控制能不能登入，以「管理員」勾選授予最高權限。
- 每一次新增、修改、刪除都會自動寫進稽核紀錄。

## 二、這個頁面在做什麼

本系統的權限分成三層，這一頁同時管到其中兩層半，是最需要想清楚再動手的頁面：

| 層 | 在哪裡設定 | 決定什麼 |
|---|---|---|
| 管理員 | 這一頁的「管理員」勾選 | 勾了就略過所有權限檢查，也不受團隊限制，可以進入所有管理頁面。它不是一種角色 |
| 角色 | 這一頁的「角色」＋「額外角色」 | 能進哪些頁面、能做哪些動作（檢視、新增、編輯、刪除）。多個角色的權限是**加總**，不是互相覆蓋 |
| 團隊 | 這一頁的「團隊」＋每個角色在角色管理設定的「預設團隊」 | 看得到哪些**資料列**。這和「能做哪些動作」是兩回事 |

一個人實際看得到的團隊，一律是「這一頁直接綁定的團隊」加上「他所有角色（主要與額外）的預設團隊」。兩邊都沒有任何團隊時，他在專案項目只看得到沒有標記團隊的公開紀錄。

權限的變更不必等對方重新登入：對方下一次切換頁面或重新整理瀏覽器時，就會套用新的角色、團隊與啟用狀態；被停用的人會在那時被登出。

## 三、畫面上有哪些按鈕、各自做什麼

### 工具列

| 按鈕或欄位 | 做什麼 |
|---|---|
| 「新增」 | 開啟「新增使用者」表單。角色會預先帶入名稱為「預設角色」的那一個（找不到就帶入清單第一個），「啟用」預設勾選、「管理員」預設不勾 |
| 「重新整理」 | 重新讀取清單，右上角會出現「已更新最新資料」 |
| 搜尋框（提示字「請輸入搜尋關鍵字」） | 輸入關鍵字後按「搜尋」，會比對帳號、名稱、Email 與角色名稱 |
| 「清空搜尋」 | 搜尋框有文字時才會出現，按下後清掉關鍵字並回到第一頁 |
| 「搜尋」 | 依搜尋框的關鍵字篩選清單，並回到第一頁 |

> **提醒**：用角色名稱搜尋時，只會比對每個人的**主要角色**，只以「額外角色」擁有該角色的人不會被搜出來。

### 清單欄位

| 欄位 | 意思 |
|---|---|
| 帳號 | 登入用的帳號 |
| 名稱 | 顯示用的姓名 |
| Email | 聯絡信箱，也是忘記密碼時重設信的收件地址 |
| 角色 | **只顯示主要角色**。額外角色不會出現在這一欄，但它們的權限仍然有算進去 |
| 狀態 | 「啟用」或「停用」 |
| 管理員 | 是管理員時顯示「是」的徽章，不是時顯示「—」 |
| 建立時間／更新時間 | 系統自動寫入，不能修改 |
| 操作 | 每一列的「修改」與「刪除」按鈕 |

### 每一列的操作

| 按鈕 | 做什麼 |
|---|---|
| 「修改」 | 開啟「修改使用者」表單，會帶出這個人目前的額外角色與直接綁定的團隊 |
| 「刪除」 | 跳出「確認刪除」視窗，內容是「確定要刪除這筆紀錄嗎？此操作無法復原。」，按「刪除」才會執行，成功後顯示「刪除成功」 |

### 表單裡的欄位

| 區塊 | 欄位 | 說明 |
|---|---|---|
| 帳號與登入 | 帳號 | 必填。與別人重複時會出現「帳號已存在，無法新增。」或「帳號已存在，無法修改。」 |
| 帳號與登入 | 密碼 | 新增時必填；**修改時留白代表沿用原本的密碼**，不是把密碼清空（欄位下方會提示「編輯模式留白表示沿用既有密碼」） |
| 基本資料 | 名稱 | 必填 |
| 基本資料 | Email | 選填，系統不檢查格式 |
| 角色與團隊 | 角色 | 必填，單選，也就是清單上顯示的主要角色 |
| 角色與團隊 | 額外角色（多角色，權限取聯集） | 可多選，權限與主要角色**加總** |
| 角色與團隊 | 團隊（直接綁定此使用者） | 可多選，只列出啟用中的團隊。實際可見範圍是這裡再**加上**所有角色的預設團隊，不是取代 |
| 狀態 | 啟用 | 取消勾選後這個人就無法登入，但帳號與歷史紀錄都保留 |
| 狀態 | 管理員 | 勾選後略過所有權限檢查，也不受團隊限制 |

### 按下「儲存」之後會依序經過這些關卡

1. 必填欄位沒填會出現「帳號 不可為空白」「名稱 不可為空白」或「角色 不可為空白」；新增時沒填密碼會出現「新增使用者時必須輸入密碼。」。
2. 修改時一個字都沒改，會顯示「沒有任何變更，未進行儲存。」並直接關窗。
3. 跳出「確認儲存」視窗（「確定要儲存這筆記錄嗎？」），按「再檢查」可以回到表單。
4. 若「團隊」留空且沒有勾「管理員」，會再跳出「確認團隊設定」：角色有預設團隊時，會列出這個人將沿用的團隊；角色也沒有預設團隊時，會警告「此使用者將只能看到無團隊標記的公開紀錄」。按「仍要儲存」繼續，按「回去編輯」回到表單。
5. 成功後顯示「新增成功」或「修改成功」。

按「取消」、右上角的關閉鈕或 Esc 時，如果表單有改過，會先問「尚有未儲存的變更」，可選「放棄變更」或「繼續編輯」。

> **提醒**：帳號重複的檢查目前比較寬鬆，大小寫不同或前後多了空白都會被當成不同的帳號。建立前請先搜尋一次，避免同一個人有兩個帳號。

## 四、建議這樣操作，會得到什麼

### 情境一：幫新進同仁開帳號

1. 先到角色管理確認有適合的角色，例如只能檢視專案的角色。
2. 回到這一頁按「新增」，填帳號、密碼、名稱，Email 請填正確的信箱。
3. 「角色」選主要角色；需要跨職務時，再用「額外角色」補上其他角色。
4. 「團隊」選他所屬的團隊，按「儲存」並在確認窗按「儲存」。

會得到：一個可以立即登入的帳號，選單只會出現他有權限的頁面，專案清單只會出現他團隊的資料與公開資料。

### 情境二：同仁離職或長期請假

1. 搜尋他的帳號，按「修改」。
2. 取消勾選「啟用」，按「儲存」。

會得到：他在下一次切換頁面時就會被登出，之後也無法再登入，但他留下的資料與稽核紀錄都還在。日後復職只要重新勾回「啟用」即可。

### 情境三：用 Google 第一次登入的人要開通

1. 系統有開 Google 登入時，第一次用 Google 登入的人會自動建立一個「停用」狀態的帳號。
2. 在清單中找到狀態為「停用」的那一列，按「修改」，確認角色與團隊後勾選「啟用」並儲存。

會得到：對方下一次登入就能進入系統。

## 五、名詞解釋

| 名詞 | 白話解釋 |
|---|---|
| 主要角色 | 表單裡的「角色」欄位，清單的「角色」欄只顯示這一個 |
| 額外角色 | 主要角色以外另外指派的角色，權限與主要角色合在一起計算 |
| 權限取聯集 | 多個角色只要其中一個允許某個動作，這個人就能做。角色之間不會互相取消權限 |
| 直接綁定的團隊 | 在這一頁「團隊」欄位選的團隊，只屬於這個人 |
| 角色的預設團隊 | 在角色管理替角色設定的團隊，擁有該角色的每一個人都會自動多出這些團隊 |
| 可見範圍 | 直接綁定的團隊加上所有角色的預設團隊，決定這個人看得到哪些資料列 |
| 管理員 | 略過所有權限與團隊限制的特殊身分，只有它能進入系統管理底下的各頁 |
| 停用 | 保留帳號但禁止登入。和刪除不同，刪除後帳號本身就不存在了 |

## 七、常見問題

**「團隊」欄位留空，是不是代表這個人什麼都看不到？**
不一定。可見範圍一律是「直接綁定的團隊」加上「所有角色的預設團隊」，留空只是少了直接綁定那一份。只有當他的角色也都沒有預設團隊時，才會只看得到沒有標記團隊的公開紀錄；儲存前的「確認團隊設定」視窗會告訴你是哪一種情況。

**我修改時沒填密碼，對方的密碼會不會被清掉？**
不會。修改時密碼欄留白代表沿用原本的密碼，只有填了新密碼才會變更。

**清單上他的角色明明只能檢視，為什麼他能刪除資料？**
清單的「角色」欄只顯示主要角色。請按「修改」看「額外角色」，權限是所有角色合計；也請確認他是不是被勾了「管理員」。

**我在這裡改了系統內建管理帳號的密碼，為什麼過一陣子又變回去了？**
系統內建的預設管理帳號，每次系統重新啟動時密碼都會被重設回系統管理員在設定檔裡指定的值，所以在這裡改它的密碼不會長久生效。日常管理請另外建立自己的管理員帳號。
