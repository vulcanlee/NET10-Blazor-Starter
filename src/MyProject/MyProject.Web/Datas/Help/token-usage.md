# Token 用量

查看系統**每一次呼叫 AI**（大語言模型）用了多少 token、**花了多少錢**，可依使用者、作業、模型、型別與日期統計，並**匯出 CSV 或 PDF 報表**、清除舊紀錄。

> 這一頁只有管理員可以使用。

### 一分鐘看懂這一頁

- **解決什麼問題**：回答「AI 這個月花了多少錢、是誰或哪個功能在用、哪個模型最貴」，並在帳單金額對不上時，逐筆找出是哪幾次呼叫造成的。
- **誰會用到**：負責控管 AI 費用的系統管理員；月底對帳、評估要不要換模型，或發現費用異常增加時都會來看。
- **它在系統的哪個位置**：側邊選單「系統管理 › 統計與分析」。它和資料庫用量頁一起負責「容量與費用」；日誌檢視的 AI 分析與健康監控的 AI 檢查，都會在這裡留下紀錄。
- **開始前要準備**：想好要看的期間與對象（某個帳號、某個作業或某個模型）；要對帳時，先確認畫面上有沒有「未定價」的提示。
- **做完會得到**：篩選範圍的 token 合計與新台幣、美金花費，最近 1／7／30 天的費用卡、趨勢圖、四種分組統計、逐筆明細，以及可下載的 CSV 與 PDF 報表。
- **它不做什麼**：不會限制或阻擋 AI 的使用，也不會修改費率；費率與匯率由系統管理員在設定檔裡維護，而且改了之後不會回頭重算已經記錄的費用。

## 一、功能摘要

頁面最上方有一段固定的介紹文字，重點如下：

- 本頁記錄每次呼叫大語言模型的 token 用量：是哪個**作業**、哪個 **API 型別**、哪個**模型**、哪個**使用者**，以及供應商回傳的各類 token 數。
- 輸入（送出／prompt）與輸出（接收／completion）計價不同。**快取**是輸入的折扣子集，**推理**計入輸出，兩者都只是「其中多少」，不另外加進合計。按每列「詳細」可以看到完整分組與原始明細。
- 失敗的呼叫也會記錄。其中**回應成功但內容為空**特別值得注意：上游照常計費，使用者卻什麼都沒拿到。依音訊時長計費、不回傳 token 數的模型，不計入 token 合計。
- **費用**是呼叫當下依系統的 AI 計費設定（單價與匯率）算好，連同單價快照一起存下來的；**事後調整設定不會改變已經記錄的帳**。找不到該模型費率設定的呼叫會標示為「未定價」，不計入合計；0.9.17 之前的紀錄沒有單價快照，一律是未定價。合計的美金與台幣**各自為逐列加總**，區間橫跨匯率調整時，兩者彼此推算不出來。

## 二、這個頁面在做什麼

統計與分析群組裡的幾個頁面構成一條排查工具鏈，本頁負責「費用」：

| 頁面 | 回答的問題 |
|---|---|
| 系統健康監控 | 基礎元件現在有沒有壞？ |
| 系統例外紀錄 | 出過哪幾種錯、各發生幾次？ |
| 日誌檢視、日誌等級設定 | 某段時間內系統逐筆做了什麼？細節不夠時如何調細？ |
| 資料庫用量 | 資料庫佔了多少空間？ |
| Token 用量（本頁） | AI 用了多少 token、花了多少錢？ |

目前系統中會呼叫 AI 的地方主要有兩個，在「作業」欄會以不同名稱出現：

| 作業名稱 | 從哪裡來 |
|---|---|
| AI 日誌分析 | 日誌檢視頁按下 AI 分析時產生，使用者欄是按下按鈕的人。 |
| 系統健康檢測 | 每打開一次系統健康監控頁就產生一筆，使用者欄是打開該頁的管理員。 |

打開本頁時預設**不限日期**，所以最上方的合計是全部紀錄的總和；要看特定期間，請設定起始日與結束日，或直接點「最近 N 天」的卡片。

## 三、畫面上有哪些按鈕、各自做什麼

### 查詢條件

| 條件 | 說明 |
|---|---|
| 帳號 | 部分比對，輸入帳號的一部分即可。 |
| 起始日／結束日 | 以日期為單位，兩端都包含當天。留空代表不限。 |
| 作業 | 預設「全部作業」，選項來自已經有的紀錄。 |
| 型別 | 預設「全部型別」，也就是 API 呼叫的種類。 |
| 模型 | 預設「全部模型」。 |

### 工具列按鈕

| 按鈕（滑鼠提示） | 做什麼 |
|---|---|
| 查詢 | 依條件重新查詢，並回到明細的第一頁。 |
| 重新整理 | 重新載入資料，並更新作業、型別、模型下拉選單的選項（有新模型出現時用它）。 |
| 匯出目前查詢結果（CSV） | 把目前條件下的**全部**紀錄（不是只有當頁）下載成 CSV，共 24 欄。 |
| 下載全部頁籤的 PDF 報表 | 把條件、合計與所有頁籤的內容做成一份 PDF。 |
| 只匯出目前頁籤（…）的 PDF | 只輸出目前所在頁籤，括號內是頁籤名稱；條件與合計仍會保留在報表上。 |
| 清空全部紀錄 | 刪除所有用量紀錄與全部原始明細，會先跳出「清空全部用量紀錄」確認窗，此動作無法復原。 |

- 符合條件的紀錄為 0 筆時，CSV 與兩個 PDF 按鈕都會停用。
- CSV 欄位為：時間、使用者、作業、型別、供應商、模型、輸入、輸出、推理、快取、圖片輸入、圖片快取、圖片輸出、合計、費用USD、費用TWD、匯率、計價依據、長脈絡、字元數、音訊時長秒、耗時ms、結果、失敗原因。

### 批次清除舊資料

在「清除此日之前」選一個日期，再按紅色的「批次清除」。確認窗會寫明「將刪除 … 之前的所有用量紀錄與原始明細檔。此動作無法復原。」，按「清除」才會執行。**所選的那一天本身不會被刪除**。完成後會顯示「已清除 N 筆紀錄。」，沒有符合的資料時顯示「沒有符合條件的紀錄。」。

### 篩選範圍合計（上排四張卡）

標題為「篩選範圍合計　—　套用條件：…」，套用條件**包含日期**；沒有設定任何條件時顯示「全部條件」。這一排**不能點**。

| 卡片 | 內容 |
|---|---|
| 輸入（送出／prompt） | 送出的 token 數，副行是「其中快取」。 |
| 輸出（接收／completion） | 模型回傳的 token 數，副行是「其中推理」。 |
| 合計 | 輸入 ＋ 輸出，子集不重複計入。 |
| 花費 | 新台幣金額，副行是美金。有未定價時以橘字標出「其中 N 筆未定價未計入」，沒有時註明「美金與台幣各自逐列加總」。 |

> **提醒**：「其中快取」「其中推理」**已經包含**在輸入與輸出裡，**不要再另外加進合計**。這也是為什麼只有四張卡、快取與推理不各自成卡：拆成六張對等的卡，很容易讓人把它們全部相加。

> **提醒**：「未定價」**不等於 0 元**。它代表系統找不到這個模型的費率，所以沒有估算費用、也沒有算進花費；實際上供應商照樣收費。看到「其中 N 筆未定價未計入」時，畫面上的花費一定**少算**了。

### 最近用量與費用（下排三張卡）

標題為「最近用量與費用（點卡片可套用該區間）　—　套用條件：…」。三張卡是「近 1 天（今天）」「近 7 天」「近 30 天」，各自顯示新台幣、美金、「呼叫 N 次・合計 N」，有未定價時同樣標出。

- **點卡片**會把該區間填進起始日與結束日並重新查詢；目前套用中的那張卡會標亮。
- 這排卡片**沿用帳號、作業、型別、模型的篩選**，只把日期換成自己的區間，所以它標題的套用條件**不含日期**。選了某個模型後，卡片回答的就是「這個模型近 7 天花了多少」；看到數字偏小時，先確認這一行的條件。

> **提醒**：「近 N 天」**包含今天**往前數 N 天。例如「近 7 天」是六天前到今天，共 7 天，不是 8 天；「近 1 天」就是今天。

### 頁籤

| 頁籤 | 內容 |
|---|---|
| 趨勢圖（預設） | 上下兩張折線圖：「費用（NT$）」與「合計 token」，共用日期軸。區間不超過 92 天時「每點 = 1 天」，更長時改為「每點 = 1 週（週一起算）」。滑鼠移到點上可看期間、費用、合計 token、呼叫次數與未定價筆數。 |
| 每日趨勢（N） | 一天一列，每列有費用與合計 token 兩根長條，以及金額、token 數與「N 次」。沒有呼叫的日子也會列出空白列。 |
| 依使用者（N）、依作業（N）、依模型（N）、依型別（N） | 分組統計表，欄位為：分組名稱、輸入、輸出、快取、推理、合計、費用、次數。費用滑鼠移上去顯示美金；有未定價時加註「（N 未計）」。括號內是分組數。 |
| 明細（N） | 逐筆紀錄，括號內是符合條件的總筆數。 |

- 趨勢圖與每日趨勢在起訖日都沒填時顯示近 30 天；區間**最多 180 天**，超過時只顯示最後 180 天並註明「篩選區間超過 180 天，以下只顯示最後 180 天。」。
- 趨勢圖的兩張圖**各自有自己的縱軸**；每日趨勢的兩根長條**各自以區間內最大值為滿格**。費用與 token 單位不同，兩條線或兩根長條的高低**不可互相比較**。
- 區間內沒有資料時顯示「這段期間沒有任何呼叫紀錄。」；有未定價的呼叫時，圖下方會提示那些點的費用低於實際用量。

### 明細頁籤的欄位與操作

| 欄位 | 意思 |
|---|---|
| 時間 | 呼叫發生的時間，預設由新到舊，可點標題排序。 |
| 使用者 | 誰觸發的；沒有登入者身分的呼叫顯示「（系統自動）」。 |
| 作業 | 系統裡的功能名稱，例如「AI 日誌分析」「系統健康檢測」。 |
| 型別、模型 | API 呼叫種類與使用的模型；供應商要到明細窗或 CSV 才看得到。 |
| 輸入、輸出、推理、快取 | 各類 token 數；推理與快取是子集，不另外加總。 |
| 合計 | 輸入 ＋ 輸出。失敗的呼叫顯示紅色「失敗」標籤（滑鼠移上去看原因）；依時長計費的顯示「時長 N 秒」。 |
| 費用 | 新台幣金額，可排序；滑鼠移上去顯示美金、匯率與套用的費率。找不到費率時顯示橘字「未定價」。 |
| 操作 | 「詳細」開啟明細窗；「刪除」刪除這一筆，確認窗會提醒「確定要刪除這一筆嗎？原始明細檔也會一併移除。」。 |

> **提醒**：每一筆的費用是**呼叫當下的快照**。之後調整費率或匯率，已經記錄的費用**不會**跟著改；台幣與美金總額是各自逐列加總，不能用單一匯率互相換算。

### 明細窗「Token 用量明細」

依序分成幾段：基本資料（時間、使用者、作業、型別、供應商、模型、耗時、結果、紀錄 Id）、輸入、輸出、其他（音訊時長、字元數、合計）、費用、原始明細（供應商回傳）。

- 費用段列出費用 (TWD)、費用 (USD)、當時匯率、計價依據、長脈絡費率，以及套用的各項費率。
- 「計價依據」若寫著「以前綴比對自 …」，代表這個模型沒有自己的費率，是套用名稱開頭相同的另一組費率，例如帶日期版本號的模型會套用不帶日期的費率。
- 原始明細找不到時顯示「原始明細不存在（可能已被清除，或當初這次呼叫沒有回傳用量）。」。

## 四、建議這樣操作，會得到什麼

### 情境一：月底對帳

1. 起始日選該月 1 日、結束日選該月最後一天，按「查詢」。
2. 看上排「花費」卡，並確認有沒有「其中 N 筆未定價未計入」的橘字。
3. 若有未定價，切到「依模型」頁籤，找出帶有「（N 未計）」的模型。
4. 按「下載全部頁籤的 PDF 報表」留存。

會得到：該月的新台幣與美金花費、各模型的費用分布，以及一份可歸檔的 PDF。若有未定價的模型，要請系統管理員補上費率；補上之後只有**之後的**呼叫會計價，已記錄的不會重算。

### 情境二：費用突然變高，想找出原因

1. 點「近 7 天」卡片，看趨勢圖哪一天突然升高。
2. 切到「依使用者」與「依作業」頁籤，看是誰或哪個功能用得最多。
3. 切到「明細」頁籤，點「費用」標題排序，找出最貴的幾筆，按「詳細」看輸入與輸出的 token 數。

會得到：費用升高的日期、來源與具體是哪幾次呼叫，作為是否需要限制使用或更換模型的依據。

### 情境三：定期清理舊紀錄

1. 先按「匯出目前查詢結果（CSV）」把要清除的期間備份下來。
2. 在「清除此日之前」選擇要保留的最早日期。
3. 按「批次清除」，在確認窗按「清除」。

會得到：該日期之前的紀錄與原始明細都被刪除（所選那天本身保留），畫面顯示清除了幾筆，資料庫用量頁的筆數也會跟著下降。

## 五、名詞解釋

| 名詞 | 白話解釋 |
|---|---|
| Token | AI 計算用量與計費的單位，大約是一小段文字；送出與收回的文字都要算。 |
| 輸入（prompt） | 送給 AI 的內容所用的 token，單價較低。 |
| 輸出（completion） | AI 回覆的內容所用的 token，單價較高。 |
| 快取 | 輸入中重複送出、可以打折計價的部分；是輸入的「其中」，不另外加總。 |
| 推理 | 推論型模型在回答前「思考」所用的 token；算在輸出裡，不另外加總。 |
| 未定價 | 找不到這個模型的費率，所以沒有估算費用；不等於 0 元，花費會因此少算。 |
| 作業 | 系統裡是哪個功能呼叫了 AI，例如「AI 日誌分析」「系統健康檢測」。 |
| 計價依據 | 這一筆實際套用的是哪一組費率；可能是以名稱前綴比對到的另一個模型的費率。 |

## 七、常見問題

**輸入、輸出、快取、推理四個數字加起來，為什麼比合計大？**
因為快取是輸入的一部分、推理是輸出的一部分，畫面上寫「其中快取」「其中推理」就是這個意思。合計只算輸入 ＋ 輸出，把四個數字全部相加會重複計算。

**花費顯示「其中 3 筆未定價未計入」，那 3 筆是不是免費？**
不是。未定價代表系統找不到那個模型的費率，所以沒辦法估算，並不是 0 元；供應商照樣會收費。請到「明細」頁籤找出顯示「未定價」的紀錄，請系統管理員補上費率。已經記錄的那幾筆不會事後重算。

**「近 7 天」是從哪一天算起？**
包含今天，往前共 7 天。例如今天是 9 月 26 日，近 7 天就是 9 月 20 日到 9 月 26 日。

**我選了某個模型，為什麼「近 30 天」的費用比上面的花費小？**
上排的花費依你設定的起訖日計算（沒設就是全部期間）；下排卡片沿用模型等篩選，但日期換成自己的 30 天。兩排的期間不同，數字自然不同，請看各自標題上的「套用條件」。
