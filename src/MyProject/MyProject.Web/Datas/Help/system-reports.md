# 系統巡檢報告

每天自動檢查一次系統（健康、錯誤、排程、備份、磁碟容量、寄信、AI 與帳號安全），把結果整理成一份**有燈號的報告**：最前面是全面摘要，告訴你系統現在是否正常、哪些問題已經發生要馬上處理、哪些即將發生要在期限前處理、哪些只要注意，以及哪顆磁碟要開始準備擴充。每一項問題都寫出「不處理會怎樣、要怎麼處理、處理完會怎樣」。

> 這一頁只有管理員可以使用。

### 一分鐘看懂這一頁

- **解決什麼問題**：系統狀況分散在健康監控、日誌、例外、排程、備份、資料保留等十幾頁，每天逐頁看太花時間；這一頁每天自動幫你看一遍，只把需要你介入的事列出來。
- **誰會用到**：負責維運的系統管理員；主管要了解系統狀況時也可以看報告的摘要。
- **它在系統的哪個位置**：左側選單「系統管理 › 系統設定與維運 › 系統巡檢報告」；通知鈴鐺與 Email 裡的連結也會直接打開那一份報告。
- **開始前要準備**：不用準備。要改產生時間或磁碟門檻，到「系統參數」的「系統巡檢報告」分類；要停用日報，到「排程作業」停用「系統巡檢日報」。
- **做完會得到**：每天一份日報；有紅燈或橙燈時，所有管理員會收到站內通知與 Email。「立即產生」的報告在背景完成後，右上角鈴鐺會通知你。
- **它不做什麼**：不會自動修正問題（只列出建議與處理頁面）；燈號由程式依固定規則判定，AI 只負責寫說明，不能改燈號；目前只有日報，週報與月報在之後的版本。

## 一、功能摘要

在這裡可以做什麼：

- 看每一份報告的燈號、涵蓋區間、紅橙黃各幾項、有沒有通知管理員。
- 打開報告看全面摘要、AI 說明、每一項發現、磁碟容量與預估用完的日期、資料目錄大小與統計數字。
- 依種類、燈號、產生日期篩選報告。
- 按「立即產生」重新產生某一天的日報，並可選擇寄給所有管理員。
- 按「舊版巡檢報告」看 0.10.39 以前由 AI 判讀的每日巡檢報告。

## 二、這個頁面在做什麼

### 誰會使用、為什麼要用

| 角色 | 為什麼要用 |
|---|---|
| 系統管理員（每天上班） | 打開最新一份日報，看有沒有紅燈或橙燈；沒有就不用再逐頁檢查。 |
| 系統管理員（收到通知） | 點通知或 Email 裡的連結，直接看是哪一項出問題、要到哪一頁處理。 |
| 系統管理員（規劃擴充） | 看「需要準備擴充容量」與磁碟容量表，知道哪顆磁碟大約哪一天會用完、要準備多少空間。 |
| 主管 | 看報告最前面的一句話結論與摘要，掌握系統狀況。 |

### 燈號的意思

| 燈號 | 意思 | 例子 |
|---|---|---|
| 紅燈 | 已發生問題，要馬上處理。 | 排程作業最後一次失敗、最新的備份太舊、磁碟只剩不到 5%、信件卡在佇列寄不出去。 |
| 橙燈 | 即將發生，有期限要處理（報告會寫出期限日期）。 | 依成長速度預估 30 天內磁碟用完、備份排程被停用、AI 用量照目前速度會在月底前達到上限。 |
| 黃燈 | 注意即可，不急。 | 有新的例外種類、有管理員沒開兩步驟驗證、預估 90 天內磁碟用完。 |
| 綠燈 | 正常，沒有需要處理的事項。 | — |

整份報告的燈號是所有發現裡最嚴重的那一個。

### 報告怎麼產生

| 項目 | 說明 |
|---|---|
| 產生時間 | 每天在「系統參數」設定的時間（預設 07:30）產生前一天 00:00～24:00 的日報。網站在那個時間沒有執行時，下次啟動會補產生一次。 |
| 開關 | 「排程作業」頁的「系統巡檢日報」；停用後不再自動產生，仍可在這一頁「立即產生」。 |
| 誰會收到通知 | 日報有紅燈或橙燈時，所有啟用中的管理員都會收到站內通知與 Email（內容是程式產生的摘要與報告連結）。黃燈與綠燈只存報告，不打擾。 |
| AI 說明 | 程式把燈號與數字（不含帳號、路徑、錯誤內容）交給 AI，寫整體狀況、建議處理順序與下期預測。日報全部綠燈、系統參數「AI 寫報告說明」關閉或沒有設定 AI 時不呼叫 AI，報告照常產生。 |
| 容量預估 | 「容量快照」排程每天記一次各磁碟的用量，報告依成長速度推算幾天後用完。剛上線、快照少於 7 天時只看剩餘百分比，不預估日期。 |

### 需要的權限

| 權限 | 可以做的事 |
|---|---|
| 管理員 | 進入這一頁並使用所有功能。只有帳號勾選了「管理員」的人能進來，這個權限**不在**角色管理的權限表裡，無法透過角色開放。 |

### 它跟其他頁面的分工

| 想做的事 | 去哪裡 |
|---|---|
| 看每天的系統狀況與要處理的事 | 這一頁 |
| 改產生時間、磁碟門檻、AI 說明開關、報告保留天數 | 「系統參數」的「系統巡檢報告」與「資料保留」分類 |
| 停用或立即執行日報、容量快照 | 「排程作業」 |
| 依報告的建議處理問題 | 每一項發現的「前往處理」連結（例如「排程作業」「系統備份」「資料保留與清理」） |
| 隨時問系統狀況、指定其他區間 | 「系統管理助理」 |

### 報告內容視窗

| 區塊 | 內容 |
|---|---|
| 全面摘要 | 整體燈號與一句話結論；依序列出已發生問題（附處理方式）、即將發生（附期限）、注意事項（最多 10 項）、需要準備擴充的磁碟（附預估用完日期與建議擴充量）、下期預測。 |
| AI 說明 | 整體狀況、建議處理順序、下期預測。燈號與數字以摘要為準。 |
| 每一項發現 | 每一項的燈號、區塊、標題，以及現況、不處理會怎樣、怎麼處理（附「前往處理」連結）、處理完會怎樣、期限。 |
| 磁碟容量 | 每顆磁碟的用途、總容量、可用空間、每天成長與預估用完日期；快照不足 7 天時顯示「資料累積中」。 |
| 資料目錄 | 資料庫與各資料目錄的大小與檔案數；量測逾時的顯示「至少 …」。 |
| 統計 | 錯誤日誌、例外、排程失敗、寄信、AI 呼叫與費用、登入失敗等數字。 |
| 量測限制 | 這份報告數字的限制，例如日誌管線的計數在網站重新啟動後歸零。 |

右上角 × 或 Esc 關閉視窗。

## 四、建議這樣操作，會得到什麼

### 每天上班第一件事

1. 打開這一頁，看最上面一份日報的燈號。
2. 綠燈或黃燈：沒有急事，有空再看黃燈的項目。
3. 紅燈或橙燈：按「查看報告」，依「已發生問題」「即將發生」逐項按「前往處理」。

**會得到什麼**：不用逐頁檢查，就知道系統有沒有需要你介入的事。

### 收到「系統巡檢日報：紅燈」的通知或 Email

1. 點通知或 Email 裡的連結，直接打開那一份報告。
2. 看摘要的「已發生問題」與每一項的「怎麼處理」，到對應頁面處理。
3. 處理完後按「立即產生」重新產生同一天的日報，確認那一項不見了（或等明天的日報）。

**會得到什麼**：問題在第一時間被處理，下一份日報回到綠燈或黃燈。

### 規劃磁碟擴充

1. 打開最新一份報告，看「需要準備擴充容量」與「磁碟容量」表。
2. 依預估用完的日期與建議擴充量，提早申請擴充或縮短資料保留天數（到「資料保留與清理」看哪類資料最佔空間）。

**會得到什麼**：在磁碟滿之前完成擴充，避免資料庫、備份與日誌寫入失敗。

### 調整什麼時候算紅燈

1. 到「系統參數」的「系統巡檢報告」分類，調整容量的紅燈、橙燈、黃燈門檻或日報產生時間。
2. 回到這一頁按「立即產生」，確認新的門檻符合你的期待。

**會得到什麼**：燈號符合你們單位的擴充流程（例如採購要兩個月，就把橙燈的天數調長）。

## 五、名詞解釋

| 名詞 | 白話解釋 |
|---|---|
| **日報** | 涵蓋前一天 00:00～24:00 的報告；容量與健康檢查以產生當下為準。 |
| **發現** | 規則找到的一件需要注意的事，每一項都有燈號與處理建議。 |
| **容量快照** | 每天記一次的各磁碟與資料目錄用量，用來算每天成長多少、幾天後用完。 |
| **預估用完** | 依最近的成長速度推算，磁碟大約哪一天會滿；不會成長或資料不足時不預估。 |
| **AI 說明** | AI 依程式判定的燈號與數字寫的文字說明；燈號與數字以程式的結果為準。 |
| **舊版巡檢報告** | 0.9.161～0.10.38 由 AI 判讀的每日巡檢報告，已由這一頁的日報取代。 |

## 七、常見問題

**問：為什麼日報是黃燈卻沒有收到通知？**
答：日報只有紅燈或橙燈才通知管理員，黃燈與綠燈只存報告，避免每天被打擾。需要時可以在這一頁打開來看。

**問：燈號是 AI 判斷的嗎？**
答：不是。燈號與數字由程式依固定規則判定，同樣的狀況每次結果都一樣；AI 只依這些結果寫說明，沒有設定 AI 時報告照常產生。

**問：為什麼磁碟容量顯示「資料累積中」？**
答：預估幾天後用完需要至少 7 天的容量快照。剛升級的前幾天只看剩餘百分比，一週後就會出現每天成長與預估日期。

**問：報告的期限日期準嗎？**
答：期限依最近的成長速度直線推算，成長速度改變（例如大量上傳附件、縮短保留天數）時會跟著變，每天的日報都會重新推算。

**問：可以改成每週一份嗎？**
答：目前只有日報；週報與月報會在之後的版本加入，屆時可以在「系統參數」設定星期幾與時間。

**問：舊的「系統管理助理巡檢」到哪裡去了？**
答：0.10.39 起由這一頁的日報取代，排程作業頁不再有「系統管理助理巡檢」。舊報告按「舊版巡檢報告」可以看到它們過期為止。

**問：還是解決不了怎麼辦？**
答：請記下發生時間、哪一份報告、畫面上的訊息（最好截圖），以及右上角使用者選單「關於」裡的系統版本，回報給系統管理員。
