## 文件目的

說明本專案的整體分層、各專案職責、依賴方向、啟動流程，以及 DI 容器中註冊的主要服務，協助新進開發者快速建立心智模型。

---

## 1. 解決方案組成

方案檔：`src/MyProject/MyProject.slnx`（採新版 `.slnx` 格式）。共 7 個專案，採典型的分層架構：

| 專案 | 主要職責 | 依賴方向 |
|------|----------|----------|
| `MyProject.Web` | Blazor Server 宿主、Razor 元件、Web API、登入、本地化、靜態資源 | 依賴所有其他專案 |
| `MyProject.Business` | 商業邏輯：Service、Repository、AutoMapper Profile、Helper | → AccessDatas、Models、Dtos、Share |
| `MyProject.AccessDatas` | EF Core `DbContext`、Entity、Migration | → 無外部專案相依 |
| `MyProject.Models` | AdapterModel、System 設定模型、共用領域模型 | → 無外部專案相依 |
| `MyProject.Dtos` | API 對外 DTO：`ApiResult<T>`、`PagedResult<T>`、模組 DTO | → 無外部專案相依 |
| `MyProject.Share` | 跨層共用 Helper、Extension（純工具） | → 無外部專案相依 |
| `MyProject.Tests` | xUnit 測試（含慣例守門測試） | → Web 與其下所有專案 |

> 依賴方向永遠由「上層」指向「下層」，不可反向引用。Web 不應跳過 Business 直接操作 `BackendDBContext`，但 Web 內的 API Controller 為了輕量化，使用 `Repository`（仍位於 Business 專案）。

## 2. 啟動流程（`MyProject.Web/Program.cs`）

啟動主檔位於 [`src/MyProject/MyProject.Web/Program.cs`](../../src/MyProject/MyProject.Web/Program.cs)。整體流程：

> 以下一律引用 `Program.cs` 的 **`#region` 名稱**而非行號 —— 行號會隨每次改動失效，區塊名稱不會。

1. **建立 `WebApplicationBuilder`**。
2. **NLog 設定**（`#region NLog 相關設定`）：
   - 從 `NLog:BasePath` 讀取根目錄，於其下建立 `MyProject.Web` 子目錄。
   - 清除預設 logger provider，改由 `UseNLog()` 接管。
   - 立即建構服務取得 `ILogger<Program>` 寫入啟動日誌。
3. **核心服務註冊**（`#region 系統使用服務`）：
   - `AddRazorComponents().AddInteractiveServerComponents()`：Blazor Server 互動式渲染。
   - `AddControllers()`、`AddSwaggerGen()`：傳統 Web API + Swagger。
   - `AddLocalization()`、`AddAntDesign()`：在地化與 AntDesign。
   - `RequestLocalizationOptions`：支援 `zh-TW` / `en-US`，採 `AcceptLanguageHeaderRequestCultureProvider`。
   - `LocaleProvider.SetLocale("zh-TW", AntDesignLocaleFactory.Create("zh-TW"))`：套用本地化字串。
4. **認證**（`#region 加入使用 Cookie & JWT 認證需要的宣告`）：
   - `AddAuthentication(MagicObjectHelper.CookieScheme).AddCookie(...)`：`LoginPath` / `LogoutPath` /
     `AccessDeniedPath` 均指向 `/Auths/*`，Cookie 標記 `IsEssential = true`。
   - `AddJwtBearer(...)`：Web API 用，並自訂 `OnChallenge` / `OnForbidden` 讓 401／403 也回 `ApiResult`。
   - Google OAuth2（`#region Google OAuth2 第三方登入`）：僅在 `GoogleOAuthSettings.IsConfigured` 時才註冊。
   - `AddAuthorization()`。
   > 沿革：0.4.34 移除了原本的 `CookiePolicyOptions`（`MinimumSameSitePolicy = None`）——
   > pipeline 從未呼叫 `UseCookiePolicy()`，等於死碼，且 `SameSite=None` 會削弱 CSRF 姿態。
5. **AutoMapper**（`#region AutoMapper 使用的宣告`）：載入 `AutoMapping` Profile，可選擇套用 LicenseKey。
6. **強型別設定**（`ServiceCollectionExtensions.AddConfiguredOptions`）：將 `SystemSettings` 等 section 綁定為 `IOptions<T>`。
7. **外部目錄準備**（`#region 系統使用的目錄準備`）：依 `SystemSettings.ExternalFileSystem` 各路徑呼叫 `EnsureDirectoryExists`，缺少時自動建立。
8. **EF Core**（`ServiceCollectionExtensions.AddConfiguredDatabase`）：固定以 `UseSqlite` 註冊，
   連線字串由 `MagicObjectHelper.GetSQLiteConnectionString` 結合
   `SystemSettings.ExternalFileSystem.DatabasePath` 動態產生。
   ⚠️ 0.4.36 起是**雙註冊**：`AddDbContextFactory<BackendDBContext>()` 給 Blazor 路徑的資料服務
   （每個方法用完即棄），另加一個 scoped shim 從工廠取 context 給 Web API 路徑的 Repository 使用。
   不要改回單純的 `AddDbContext`，`DataAccessServiceLifetimeTests` 會擋。
9. **客製服務**（`#region 客製服務註冊` → `ServiceCollectionExtensions.AddApplicationServices`）：見第 3 節完整清單。
10. **資料庫初始化**（`#region 資料庫的 Migration`）：
    - 若有 Migration 則 `Database.Migrate()`，否則 `EnsureCreated()`。
    - Seed 預設 `RoleView`（`MagicObjectHelper.預設角色`）並寫入完整權限 JSON。
    - Seed 預設 `MyUser`（`BootstrapSettings.SupportAccount`），密碼以
      `SecurePasswordHasher.HashPassword`（**PBKDF2**）雜湊，標記為 `IsAdmin`。
    - **RBAC 回填**（`#region RBAC 回填`）：`IRbacBackfillService.RunAsync()`，冪等；失敗僅記錄、不中止啟動。
11. **中介軟體管線**（`#region 註冊中介軟體`）：
    - `UseSecurityHeaders()`：安全回應標頭（0.4.35）。
    - `UseConfiguredSwagger(logger)`、`UseHttpRequestLogging<Program>()`（每筆請求耗時與例外）。
    - `UseConfiguredForwardedHeaders`、`UseStatusCodePagesWithReExecute("/not-found")`、
      `UseHttpsRedirection`、`UseConfiguredLocalization`、`UseConfiguredCors`、`UseRateLimiter`、`UseAntiforgery`。
    - `UseAuthentication` → `UseAuthorization`。
    - `UseConfiguredDownloadStaticFiles`（`#region 綁定靜態資源`）將 `DownloadPath` 對應為 `/UploadFiles`。
      ⚠️ **必須排在 `UseAuthentication`／`UseAuthorization` 之後** —— 0.4.34 之前掛在前面，等於匿名可讀。
    - `MapControllers().RequireRateLimiting("api").RequireAuthorization()`
      —— 全站 API 一律套 `api` 限流分區，且**未明確標註授權的 Controller 一律拒絕**。
    - `MapHealthChecks("/health/live")`、`MapHealthChecks("/health/ready")`、
      `MapRazorComponents<App>().AddInteractiveServerRenderMode()`。
    - `/system-health` 由 Razor 元件提供人工巡檢頁，需 Cookie 登入且管理員限定。

## 3. 已註冊的客製服務

註冊處為 [`MyProject.Web/Extensions/ServiceCollectionExtensions.cs`](../../src/MyProject/MyProject.Web/Extensions/ServiceCollectionExtensions.cs)
的 `AddApplicationServices`（`Program.cs` 只呼叫一行 `builder.Services.AddApplicationServices();`）。

⚠️ **不是全部都是 Scoped**，有三個 Singleton：

```
// Singleton —— 跨請求共享的執行期狀態
SystemStartupState             // 啟動時間、啟動狀態（供「關於」對話窗與健康監控）
LogLevelRuntimeState           // 執行期日誌等級覆寫狀態
ICacheService → DistributedCacheService   // 於 AddConfiguredCache 註冊

// Scoped —— 跨切關注
AuthenticationStateHelper      // 驗證登入狀態、載入 CurrentUser、回傳認證檢查結果
CurrentUserService             // 保存目前登入使用者（含權限鍵與有效團隊）
IPermissionChecker             // ★ RBAC 判定的單一權威來源，UI 與 API 共用
IRbacWriteService              // 角色/使用者指派的關聯表雙寫
IRbacBackfillService           // 啟動時的 RBAC 冪等回填
IEffectiveTeamResolver         // 有效團隊＝UserTeam ∪ 角色 DefaultTeamsJson
IRecordAccessScopeProvider     // 取得 (IsAdmin, Teams) 存取範圍，Blazor 與 API 雙情境
IAuditLogService               // 稽核事件寫入
ITotpService                   // TOTP（預設關閉）
IJwtTokenService               // Web API 的 JWT 簽發與驗證
CircuitHandler → ApplicationCircuitHandler   // Blazor circuit 生命週期日誌

// Scoped —— 認證與選單
MyUserServiceLogin             // 登入流程（密碼比對、帳號鎖定、驗證碼）
ExternalLoginService           // Google OAuth2 帳號對應
SidebarMenuService             // 載入 Menu.json 並依權限過濾
RolePermissionService          // 角色權限矩陣

// Scoped —— 統計與分析
INLogFilePathResolver / ILogQueryService    // 日誌檢視
IDatabaseUsageService                        // 資料庫用量
IHealthLogReader / ISystemHealthService      // 健康監控與日誌 tail

// Scoped —— 領域資料
RoleViewService / MyUserService
ProjectService  / ProjectRepository
CategoryService / CategoryRepository
TeamService     / TeamRepository
```

> Repository 用於 Web API（`Controllers/`），Service 用於 Razor 元件 / Page；兩者目前並存。

## 4. 請求生命週期

### 4.1 Razor 元件請求（Blazor Server）

```
Browser ─► UseAuthentication ─► UseAuthorization ─► MapRazorComponents
                                                         │
                                                         ▼
                                         Layout.razor + Page.razor
                                                         │
                                                         ▼
                                       View 元件 ──► Service ──► DbContext
```

`AuthenticationStateHelper.Check(...)` 會在進入受保護頁面時讀取 `ClaimsPrincipal`、由 `Sid` 對應到 `MyUser`，檢查使用者狀態、強制改密碼需求與角色權限資料。檢查結果會以 `AuthenticationCheckResult` 回傳；Layout、NavMenu 或 Page 會依 `Succeeded`、`Unauthenticated`、`InvalidUser`、`RequiresPasswordChange` 決定是否繼續載入、停止載入或交由 Helper 導向登出與 `/ChangePassword`。

### 4.2 Web API 請求

```
Browser ─► UseRateLimiter ─► UseAuthentication ─► UseAuthorization ─► MapControllers
                                                         │
                                                         ▼
                                       Controller ──► Repository ──► DbContext
                                                         │
                                                         ▼
                                       回傳 ApiResult<T> 或 PagedResult<T>
```

詳見 [Web API 設計慣例](Web%20API%20設計慣例.md)。

API Controller 目前同時支援 `/api/{controller}` 與 `/api/v1/{controller}`；新用戶端應優先使用 `/api/v1/...`。

## 5. 程式碼分層慣例

| 慣例 | 說明 |
|------|------|
| 命名對齊 | `XxxPage` / `XxxView` / `XxxService` / `XxxRepository` / `XxxAdapterModel` / `XxxDto` |
| UI 不直接觸 DbContext | Razor 只呼叫 Service / Repository，不直接 `using` `BackendDBContext`。 |
| Edit 前先 Clone | 表格列被編輯前要 `Clone()` 隔離，避免雙向綁定污染來源。 |
| EF 生命週期 | Blazor 路徑的 `Services/DataAccess/*` 注入 `IDbContextFactory<BackendDBContext>`，每個方法 `await using var context = await contextFactory.CreateDbContextAsync();` 用完即棄。**不要改回注入 scoped `BackendDBContext`**（0.4.36 起，由 `DataAccessServiceLifetimeTests` 守門）。 |
| 通知統一走 AntDesign | 成功 / 失敗一律經 `NotificationService` / `MessageService`。 |
| API 回應統一 | 任何 Controller 一律回傳 `ApiResult<T>`，分頁則包 `PagedResult<T>`。 |

詳細模板請見 [建立一個新 CRUD 操作網頁說明](../guides/建立一個新%20CRUD%20操作網頁說明.md)。
