## 0. 名詞小辭典

第一次看到不懂的詞，回來這裡查。

| 名詞 | 白話解釋 |
|---|---|
| **腳手架（Scaffold／Starter）** | 蓋房子前先搭好的鷹架。在軟體裡指「一套已經能跑、把共通功能先做好的專案骨架」，你在上面蓋自己的業務功能 |
| **複刻／衍生專案** | 用腳手架複製出來、改成自己名字的新專案。本文的例子叫 `Acme.Erp` |
| **代號（ProjectName）** | 新專案的英文名字，會出現在資料夾、命名空間、組件名稱裡，例如 `Acme.Erp` |
| **.NET 10** | 微軟的程式開發平台，本專案用 C# 語言撰寫 |
| **Blazor Server** | 用 C# 寫網頁畫面的技術。畫面邏輯跑在伺服器上，瀏覽器和伺服器之間保持一條即時連線（SignalR） |
| **SQLite** | 一種「單一檔案」的資料庫，不用另外安裝資料庫伺服器。本系統只支援 SQLite |
| **EF Core／Migration** | EF Core 是用 C# 類別操作資料庫的工具；Migration（遷移）是「資料表結構的變更紀錄」，系統啟動時會自動套用 |
| **角色權限（RBAC）** | Role-Based Access Control。先定義「角色」能做哪些事，再把角色指派給使用者，而不是一個一個人設定 |
| **User Secrets** | 開發機上專門放密碼、金鑰的地方，存在你的使用者資料夾裡，**不會**被 commit 進 Git |
| **守門測試（慣例測試）** | 不是測功能對不對，而是掃描程式碼，擋下「照著做會出錯、但不會報錯」的寫法。違反時測試會紅，並告訴你原因 |
| **Vibe coding** | 用自然語言描述需求，讓 AI 助手（例如 Claude Code）幫你寫程式，你負責說清楚要什麼、檢查結果 |
| **CI** | Continuous Integration，每次推送程式碼時自動建置與測試的機制 |

## 1. 這份腳手架是什麼

**What**：一套已經可以直接上線的 **.NET 10 + Blazor Server 企業後台系統底座**。

一句話說明：

> 它不是「範例專案」，而是「**把每個內部系統都會重寫一次的東西，先寫好**」。

你拿到的是一個能跑、能登入、有權限、有日誌、有稽核、有健康監控的完整系統。
你要做的，是在上面加入**你自己的業務功能**（例如設備管理、請假單、報價單）。

**定位**：

| 特性 | 意思 |
|---|---|
| 開箱即用 | 下載、建置、執行，就能用預設帳號登入一個完整的後台 |
| 預先設定 | 日誌、快取、寄信、安全檢查、AI 計費等設定都已經接好，只要改設定值 |
| 易於擴充 | 有腳本產生新功能模組的骨架，有文件說明每一條慣例 |

## 2. 為什麼需要這份腳手架

### 2.1 Why：企業內部系統一直在重寫同一批東西

想像公司要做三個系統：設備管理、採購流程、客戶服務。每個系統開工的前一兩個月，都在做這些事：

- 登入、登出、忘記密碼、帳號鎖定
- 使用者管理、角色、權限、「這個部門只能看自己的資料」
- 操作紀錄（誰在什麼時候改了什麼）
- 系統出錯時要記下來、要通知人
- 日誌要能查、要能匯出
- 正式上線前的安全檢查

這些東西**跟業務無關，但每個系統都少不了**。問題是：

| 問題 | 後果 |
|---|---|
| 每次都從零寫 | 前一兩個月都在做「看不出成果」的基礎建設 |
| 每次寫法都不一樣 | 系統 A 的權限做法跟系統 B 不同，維護的人要學好幾套 |
| 每次都踩同樣的坑 | 例如預設密碼沒擋、匯出的 CSV 用 Excel 打開是亂碼、對話窗點旁邊就把整份輸入弄丟 |
| 品質靠個人經驗 | 資深的人做得好，新人做的就漏東漏西 |

### 2.2 How：腳手架怎麼解決

1. **先寫好**：上面那些共通功能全部做完、測過、寫好文件。
2. **一鍵複刻**：`New-StarterProject.ps1` 把整套複製並改成你的專案名字，幾分鐘完成。
3. **慣例固定品質**：每一條踩過的坑都寫成「守門測試」，違反就測試失敗，不用靠記憶。
4. **文件給人也給 AI 看**：讓新人和 AI 助手都能照著既有做法擴充，而不是各自發明。

### 2.3 When：什麼時候該用它

- 公司要開一個**新的內部系統**，而且需要帳號、權限、日誌這些基本功。
- 你想讓多個系統**長得一樣、做法一樣**，降低維護成本。
- 你打算用 **AI 助手**幫忙開發，希望 AI 寫出來的程式碼符合規範。

## 3. 適不適合用這份腳手架

**Why 要先判斷**：腳手架的技術選擇（Blazor Server、SQLite）有明確的適用範圍。選錯起點，後面會很痛苦。

### 3.1 適合

- 企業內部管理後台、營運系統、專案追蹤平台。
- 使用者**數十到數百人**。
- 需要依**部門／團隊**切分「誰能看到哪些資料」。
- 一開始就需要帳號權限、日誌、稽核、健康監控。

### 3.2 不適合

| 情境 | 為什麼不適合 |
|---|---|
| 公開網站、高流量的一般消費者服務 | Blazor Server 每個使用者佔一條即時連線，畫面狀態放在伺服器上，人數一多伺服器負擔很重 |
| 需要離線或網路很不穩的環境 | 連線斷了畫面就不能操作 |
| 多租戶 SaaS（一套系統賣給很多家公司、資料要完全隔離） | 只有「團隊」層級的分權，沒有「租戶」隔離 |
| 大量同時寫入（例如每秒上千筆交易） | 只支援 SQLite，同一時間只能有一個寫入者 |
| 介面要支援多國語言切換 | 多語系目前只是空殼：沒有語系資源檔，介面文字都是繁體中文 |

### 3.3 簡單判斷流程

```
是公司內部用的系統嗎？
├─ 否 → 不建議（考慮其他架構）
└─ 是 → 使用者會超過上千人同時在線嗎？
        ├─ 是 → 不建議
        └─ 否 → 需要多國語言介面或多租戶隔離嗎？
                ├─ 是 → 可以用，但要自己補一大塊（先評估成本）
                └─ 否 → ✅ 適合
```

## 4. 已經預先設計好的企業共通功能

下面每一項都是**已經做好、拿到就有**的功能。每項說明它是什麼、企業為什麼需要、在哪裡看到，以及出貨時是開還是關。

> 💡 「管理員」指的是有管理員身分的帳號。預設帳號 `support` 就是管理員。

### 4.1 帳號與登入

| 功能 | 是什麼 | 企業為什麼需要 | 出貨狀態 |
|---|---|---|---|
| 登入／登出 | 帳號密碼登入，用 Cookie 記住登入狀態；登出前會跳確認窗 | 最基本的門禁 | ✅ 開 |
| 記住我 | 勾選後 30 天內不用重新登入；沒勾則 8 小時（可在設定檔調整） | 在「方便」和「安全」之間給使用者選擇 | ✅ 開 |
| 登入驗證碼 | 4 位數驗證碼 | 減緩程式自動亂試密碼 | ✅ 開 |
| 帳號鎖定 | 連續失敗 5 次鎖 15 分鐘 | 擋暴力猜密碼 | ✅ 開 |
| 密碼安全儲存 | 密碼用 PBKDF2 雜湊後才存，資料庫裡看不到原始密碼 | 資料庫外洩時密碼不會直接曝光 | ✅ 開 |
| 忘記密碼 | 用帳號或 Email 申請，信中連結 30 分鐘內有效、只能用一次 | 減少「請管理員幫我重設密碼」的工作量 | ⚪ 需先啟用寄信 |
| Google 登入 | 用公司的 Google 帳號登入，第一次登入時自動建立帳號（預設停用，要管理員啟用） | 員工少記一組密碼 | ⚪ 預設關閉 |
| 預設管理員 | 第一次啟動自動建立 `support` 帳號 | 剛裝好就能登入，不用手動塞資料 | ✅ 開（上線前要換密碼） |

畫面路由：`/Auths/Login`、`/Auths/ForgotPassword`、`/Auths/ResetPassword`、`/ChangePassword`。

### 4.2 權限控管

| 功能 | 是什麼 | 企業為什麼需要 | 畫面 |
|---|---|---|---|
| 使用者管理 | 新增、修改、停用使用者 | 人員進出要能管 | `/myusers` |
| 角色管理 | 定義角色，用權限樹勾選每個角色能做什麼（看、新增、修改、刪除） | 不同職務能做的事不同，用角色管比一個一個人設快 | `/roleviews` |
| 多角色聯集 | 一個人可以有多個角色，權限取聯集 | 兼任多職的人很常見 | — |
| 選單依權限顯示 | 沒有權限的頁面，側邊選單直接不顯示 | 使用者不會看到一堆點了會被擋的功能 | 側邊欄 |
| 動作級權限 | 不只擋頁面，連「新增／修改／刪除」按鈕和 API 都會檢查，沒權限回 403 | 防止有人繞過畫面直接呼叫 API | — |

| 功能 | 是什麼 | 為什麼存在 | 畫面 |
|---|---|---|---|
| 專案項目 | 一個完整的範例業務模組：新增、查詢、修改、刪除（CRUD）、標籤、附件 | 讓你看「一個標準模組長什麼樣」，新模組照抄它的結構 | `/projects` |
| 分類清單 | 主資料管理，可指定適用的團隊 | 示範「下拉選單資料來源」怎麼做 | `/categories` |

### 4.4 稽核紀錄：事後查得到「誰做了什麼」

**What**：登入、登出、使用者／角色／權限的變更、清除紀錄等事件，都會寫一筆稽核紀錄。管理員可以在 `/audit-logs` 查詢、匯出、清除。

**Why**：出事時要能回答「誰、什麼時候、做了什麼」。很多產業的內控或法規也要求保存操作軌跡。
「清除稽核紀錄」這個動作本身也會留下一筆紀錄，避免有人刪紀錄滅證。

**出貨狀態**：✅ 開。預設保存 365 天，每天自動清除超過的部分（天數可在 `appsettings.json` 的 `LogRetentionSettings:AuditLogDays` 調整，設 `0` 代表不清）。

### 4.5 可觀測性：系統出問題時看得到、查得到

「可觀測性」的意思是：**系統在想什麼、哪裡壞了，你看得到**。這是上線後最常用到、卻最常被忽略的一塊。

| 功能 | 是什麼 | 企業為什麼需要 | 畫面 |
|---|---|---|---|
| 日誌檢視 | 依等級、關鍵字、時間查詢系統日誌，可匯出 | 不用登入主機翻檔案 | `/logs` |
| 日誌等級設定 | 執行中直接調整日誌要記多詳細（重啟後回到預設） | 出問題時臨時打開詳細日誌，不用重新部署 | `/log-level-setting` |
| 系統例外紀錄 | 程式出錯時自動收集，同一種錯誤合併計次，保存完整堆疊 | 錯誤不會被淹沒在日誌裡，一眼看出哪種錯誤最多 | `/system-exceptions` |
| 錯誤追蹤碼 | 使用者看到錯誤時，畫面會顯示一組追蹤碼 | 使用者回報「追蹤碼 XXX」，你就能在日誌找到同一次操作的所有紀錄 | — |
| 例外告警信 | 新種類的錯誤、或同一錯誤短時間暴增時寄信通知 | 系統壞了不用等使用者打電話來才知道 | ⚪ 預設關閉（填收件人＋啟用寄信） |
| 慢操作記錄 | HTTP 請求、資料庫指令、寄信、AI 呼叫超過門檻就記一筆警告 | 使用者說「系統很慢」時，知道是哪一步慢 | — |
| 瀏覽器錯誤回報 | 使用者瀏覽器裡的 JavaScript 錯誤也會送回伺服器記錄 | 伺服器原本完全看不到前端錯誤 | — |
| 系統健康監控 | 健康百分比、紅黃綠燈號，檢查資料庫、磁碟、寄信、AI、日誌管線等 13 項 | 一頁看完系統是否正常 | `/system-health` |
| 資料庫用量 | 各資料表筆數與估算大小 | 提早發現資料暴增 | `/database-usage` |
| 健康檢查端點 | `/health/live`、`/health/ready` | 給負載平衡器或監控工具自動偵測 | API |
| 自動清除 | 每天自動刪除過期的例外紀錄（90 天）、稽核紀錄（365 天）、AI 對話紀錄（90 天）；日誌檔保留 30 天 | 磁碟不會被塞爆 | 背景作業 |

### 4.6 AI 功能

| 功能 | 是什麼 | 企業為什麼需要 | 畫面 |
|---|---|---|---|
| 日誌 AI 分析 | 把查到的日誌送給 AI（Azure OpenAI 或 OpenAI），整理成看得懂的報告，可匯出 PDF | 幾千行日誌人工看不完 | `/logs` |
| 例外 AI 分析 | 對某一筆例外請 AI 分析原因與修法，可以多輪追問 | 加快除錯 | `/system-exceptions` |
| Token 用量與費用 | 每次呼叫 AI 都記錄用了多少 token、花多少錢（美金／台幣），有趨勢圖，可匯出 CSV／PDF | 用了 AI 卻不知道每個月會被扣多少錢，是很常見的問題 | `/token-usage` |
| AI 對話紀錄 | 保存每次送給 AI 的完整內容與回應（管理員專屬，90 天自動過期） | AI 回答怪怪的時候，能回頭看它到底收到什麼 | `/ai-call-logs` |

**出貨狀態**：⚪ 預設關閉。在 `appsettings.json` 的 `AiSettings` 填入 `ApiKey`（以及 `Endpoint`、`Model`）才會啟用。**沒填金鑰就是關閉**，沒有另外的開關。

### 4.7 Web API：給其他系統串接

| 功能 | 是什麼 | 為什麼需要 |
|---|---|---|
| 統一回應格式 `ApiResult<T>` | 每支 API 回傳的外層格式都一樣，分頁另有 `PagedResult<T>` | 串接的人只要學一種格式 |
| JWT 驗證 | 程式呼叫 API 用 Bearer token，跟網頁的 Cookie 登入分開 | 其他系統、排程、手機 App 也能安全呼叫 |
| Swagger | 自動產生 API 說明頁（`/swagger`），可直接在網頁上試呼叫 | 串接的人不用另外要文件（正式環境預設關閉） |
| 版本化路由 `/api/v1/...` | API 網址帶版本號 | 日後改版時，舊的呼叫端不會壞掉 |
| 速率限制 | 每個呼叫端每分鐘最多 120 次，登入每分鐘 10 次 | 防止被灌爆或被暴力嘗試 |

### 4.8 基礎設施

| 功能 | 是什麼 | 為什麼需要 | 出貨狀態 |
|---|---|---|---|
| 快取 | 統一的快取介面，單機用記憶體，多台主機可切換成 Redis，只改設定不改程式 | 常用資料（例如選單）不用每次查資料庫 | ✅ 記憶體 |
| 寄信 | 三種模式：不寄（None）、寫成檔案（Pickup，開發用）、真的寄出（Smtp）；有背景佇列 | 忘記密碼、告警都需要寄信 | ⚪ 不寄 |
| 登入金鑰保存（Data Protection） | 登入 Cookie 的加密金鑰存在固定資料夾 | 金鑰不見，全站使用者會被登出 | ✅ 開 |
| 元件本地化 | Ant Design 元件（日期選擇器等）依瀏覽器語言顯示 | 基本的在地化 | ✅ 開（⚠️ 只到元件層級，介面文字仍是繁中） |

### 4.9 介面

| 功能 | 是什麼 | 為什麼需要 |
|---|---|---|
| 單一色票來源 | 全站顏色只定義在 `wwwroot/theme.css` 一個地方 | 換品牌色只改一個檔，不用翻遍所有頁面 |
| 統一的對話窗、確認窗、通知、狀態徽章 | 共用元件，外觀與行為一致 | 每個頁面長得一樣、操作習慣一樣 |
| 每頁的「操作說明」 | 每個登入後的頁面都有一份白話使用說明 | 使用者不用另外找教育訓練文件 |
| 「關於」對話窗 | 顯示系統名稱、版本、執行環境、已運作時間 | 使用者回報問題時能說出版本 |
| 響應式登入頁 | 手機、平板、電腦都能正常顯示 | 行動裝置登入 |

### 4.10 安全防線

| 功能 | 是什麼 | 為什麼需要 |
|---|---|---|
| 正式環境啟動安全檢查 | 正式環境啟動時，發現 JWT 金鑰還是預設值、管理員密碼還是 `support`、Swagger 沒表態、寄信設定不完整……就**拒絕啟動** | 最常見的上線事故就是「忘了改預設值」，這道檢查直接擋住 |
| 安全回應標頭 | 自動加上防止被嵌入、防止內容型別被猜測等標頭 | 基本的網頁安全 |
| 上傳副檔名白名單 | 只允許文件、圖片等安全格式，擋下 `.exe`、`.html`、`.js` 等 | 防止有人上傳惡意檔案 |
| 機密不進版控 | 金鑰、密碼放 User Secrets 或環境變數 | 原始碼外流時不會連密碼一起外流 |

### 4.11 工程品質

## 6. 為什麼這些準備能讓 vibe coding 更順利

### 6.1 Why：AI 寫程式的四個常見問題，以及腳手架怎麼對付

| AI 常見問題 | 會發生什麼事 | 腳手架的對策 |
|---|---|---|
| **不知道上下文** | AI 不知道你的專案有哪些規則，只能猜 | 文件寫好規則；`CLAUDE.md`／`AGENTS.md` 是 AI 的入口，指引它先讀哪些文件 |
| **自己發明做法** | 同一件事每次用不同寫法，專案越來越亂 | 「這些事情不要自己發明」對照表（例如確認窗一律用 `ConfirmDialog`、顏色一律用 `var(--app-*)`），寫在指引 §14.2 和速查表 |
| **說完成了，其實沒做對** | 程式能編譯、測試也過，但畫面跑版、少了權限、匯出亂碼 | **守門測試**：把踩過的坑寫成測試，違反就紅燈，失敗訊息會說明原因 |
| **忘了收尾** | 改了程式，沒更新文件、沒改版本號 | `CLAUDE.md` 明定：每次異動版本號 +1、要寫 changelog、要同步相關文件、不可自動 commit |

**白話總結**：文件告訴 AI「該怎麼做」，守門測試在 AI 做錯時「自動抓出來」。兩者加起來，你不需要是資深工程師，也能讓 AI 產出符合規範的程式碼。

### 6.2 What：AI 會讀到哪些東西

AI 助手（例如 Claude Code）開啟專案時，會先讀根目錄的 `CLAUDE.md`（其他工具讀 `AGENTS.md`），裡面寫了最關鍵的規則，並指向下面這些文件。建議 AI 照這個順序讀：

| 順序 | 文件 | 管什麼 |
|---|---|---|
| 1 | `CLAUDE.md`／`AGENTS.md` | 行為準則與最關鍵的不變量 |
| 2 | `docs/architecture/開發慣例與限制速查.md` | 所有慣例與踩雷點（⚠️ 標記是硬紅線） |
| 3 | `docs/architecture/對話窗 UI 設計規範.md` | 對話窗、確認窗、通知 |
| 4 | `docs/architecture/介面視覺設計規範.md` | 色票、側邊欄、表格 |
| 5 | `docs/guides/畫面與欄位字典.md` | 既有欄位的意思 |
| 6 | `docs/prd/` 對應的 PRD | 該模組的既有行為 |

幾個代表性的守門測試：

| 測試 | 擋什麼 |
|---|---|
| `ThemeConventionTests` | 顏色寫死在頁面裡，而不是用 `theme.css` 的色票 |
| `PageHelpCatalogTests` | 新增了頁面卻沒有寫「操作說明」 |
| `MenuPermissionConsistencyTests` | 選單和權限設定對不上 |
| `DocumentationConventionTests` | `appsettings.json` 新增了區段卻沒寫進設定文件 |
| `StartupSafetyConventionTests` | 正式環境的安全檢查被改壞 |

### 6.3 How：一次對話的工作循環

```
1. 說清楚要什麼（一次只做一件事）
2. 請 AI 先讀相關文件，說明它打算怎麼做
3. 確認做法後，讓 AI 動手
4. 請 AI 跑四道檢查指令（見 6.5）
5. 你自己打開畫面看一次（視覺問題測試抓不到）
6. 看過變更內容（diff），確認沒有改到不相干的地方
7. 你自己決定何時 commit
```

### 6.4 可以直接照抄的提示詞

把 `Acme.Erp` 換成你的專案代號。

**① 新增一個業務模組**

```text
請用 scripts/New-CrudModule.ps1 新增一個「設備清單」模組（英文名 Equipment）。
欄位：設備編號（必填、唯一）、設備名稱（必填）、購入日期、保管人（使用者下拉）、備註。
```

**② 在既有模組加欄位**

```text
在「專案項目」加一個欄位「預計完成日」（日期，可空白）。
```

**③ 新增一個頁面並設定權限**

```text
新增一個「月報表」頁面，只有被授權的角色看得到。

MagicObjectHelper 權限鍵常數），並在 HelpTopics.json 登記、撰寫 Datas/Help 的操作說明。
完成後確認 MenuPermissionConsistencyTests 與 PageHelpCatalogTests 都通過。
```

### 6.5 AI 寫完後一定要跑的四道檢查

在 repo 根目錄執行（`Acme.Erp` 換成你的代號）：

```powershell
dotnet build  src/Acme.Erp/Acme.Erp.slnx -v:minimal    # 必須 0 warning
dotnet test   src/Acme.Erp/Acme.Erp.slnx               # 必須全綠
dotnet format src/Acme.Erp/Acme.Erp.slnx --verify-no-changes
pwsh ./scripts/Test-DocsEncoding.ps1                   # 文件編碼
```

⚠️ **這四道對「畫面好不好看」幾乎完全無感**。畫面跑版不會讓任何測試失敗，所以改了畫面一定要自己打開來看。

### 6.6 使用技巧

- **一次只做一件事**。一次要求太多，AI 容易漏掉其中幾項。
- **先叫 AI 讀文件、說明做法**，再讓它動手。方向錯了，早點發現成本最低。
- **看到守門測試失敗，先讀失敗訊息**。那裡寫著當初為什麼要有這條規則，通常照著改就對了。不要叫 AI 把測試改掉或跳過。
- **檢查 diff**。AI 有時會順手「改善」不相干的程式碼，`CLAUDE.md` 雖然有要求它不要，還是要看一下。
- **不要讓 AI 自動 commit**。commit 是你確認過、願意負責的時間點。

## 7. 用 `New-StarterProject.ps1` 複刻新專案

### 7.1 What／Why

**What**：一支 PowerShell 腳本，把整個腳手架複製到新資料夾，並把所有 `MyProject` 換成你的專案代號。

**Why**：手動複製再改名，要改的地方有上百處，其中有十幾個漏改**不會報錯**，例如：

- 樣式檔名稱沒改 → 全站畫面沒有樣式，卻沒有任何錯誤訊息。
- User Secrets 的 ID 沒改 → 兩個專案的密碼互相污染。
- 登入 Cookie 名稱沒改 → 同一台主機上的兩個系統互相把對方登出。

腳本把這些一次做完，並在最後掃描有沒有漏網之魚。

**When**：每要開一個新系統，就跑一次。**整個方案只要跑一次**，不是每個子專案跑一次。

### 7.2 事前準備

| 工具 | 為什麼需要 | 怎麼確認 | 怎麼安裝 |
|---|---|---|---|
| .NET SDK 10.0.400 以上 | 建置與執行。`global.json` 鎖定了版本 | `dotnet --info` | [.NET 下載頁](https://dotnet.microsoft.com/download) |
| PowerShell 7（`pwsh`） | 執行腳本。Windows 內建的 PowerShell 5.1 也能跑，但文件以 7 為準 | `pwsh --version` | Microsoft Store 或官網 |
| dotnet-ef | 腳本要用它重建資料庫 migration，**沒裝會直接中止** | `dotnet ef --version` | `dotnet tool install --global dotnet-ef` |
| Git | 版本控制 | `git --version` | 官網 |
| 開發用 HTTPS 憑證 | 第一次用 https 執行前要信任 | — | `dotnet dev-certs https --trust` |
| 網路 | 腳本會執行 `dotnet restore` 下載套件 | — | — |

### 7.3 參數

| 參數 | 必填 | 預設 | 說明 |
|---|---|---|---|
| `-ProjectName` | ✔ | — | 新專案代號。必須英文字母開頭，只能有英文、數字、底線、點。例：`Acme.Erp`、`HrPortal` |
| `-DestinationPath` | ✔ | — | 新專案要放的資料夾。已存在時會中止，不會覆蓋 |
| `-Force` | | 關 | 目標資料夾已存在時，**先整個刪除**再複製。⚠️ 無法復原 |
| `-SourceProjectName` | | `MyProject` | 要被取代的舊代號。從衍生專案再往下衍生時也不用填 |
| `-UserSecretsId` | | 自動產生新的 GUID | 想指定 User Secrets ID 時才填 |
| `-KeepStarterHistory` | | 關 | 保留腳手架的開發史文件（`planning/`、`superpowers/`、`changelog/`） |

**代號怎麼取**：

- 代號會變成**程式的命名空間**，例如 `Acme.Erp.Web`。取一個短、穩定、日後不會改的名字。
- 用點分隔公司與系統是常見做法：`公司.系統`，例如 `Acme.Erp`。
- **不能有連字號（`-`）、空白或中文**，腳本會拒絕。
- 目標資料夾**不要放在腳手架資料夾裡面**，否則會把自己複製進去。

### 7.4 使用範例

在**腳手架的根目錄**開啟 PowerShell 7 執行。

**範例一：最常用的寫法**

```powershell
pwsh ./scripts/New-StarterProject.ps1 -ProjectName Acme.Erp -DestinationPath D:\Work\Acme.Erp
```

**範例二：目標資料夾已存在，要覆蓋**（⚠️ 原資料夾內容會全部刪除）

```powershell
pwsh ./scripts/New-StarterProject.ps1 -ProjectName Acme.Erp -DestinationPath D:\Work\Acme.Erp -Force
```

**範例三：保留腳手架的開發史文件**（想研究腳手架為什麼這樣設計時）

```powershell
pwsh ./scripts/New-StarterProject.ps1 -ProjectName Acme.Erp -DestinationPath D:\Work\Acme.Erp -KeepStarterHistory
```

### 7.5 腳本做了什麼（白話版）

| 步驟 | 做什麼 | 為什麼 |
|---|---|---|
| 1 | 檢查有沒有安裝 dotnet-ef | 沒有就直接停，不留下做一半的資料夾 |
| 2 | 隨機挑一組本機沒被占用的開發連接埠（http 5000–5300、https 7000–7300） | 同一台電腦開多個衍生專案時不會搶埠 |
| 3 | 檢查目標資料夾 | 已存在又沒加 `-Force` 就停 |
| 4 | 複製整個資料夾，跳過 `.git`、`bin`、`obj`、`.vs`、`output` 等 | 只帶走原始碼和文件，不帶編譯產物和腳手架的版本歷史 |
| 5 | 把文字檔裡的 `MyProject` 全部換成新代號；舊的 User Secrets ID、舊連接埠也換掉 | 命名空間、設定、文件一次改完 |
| 6 | `appsettings.json`：JWT 金鑰換成「新代號-佔位符」、版本號重設為 `1.0.0 (今天)` | 新專案從 1.0.0 開始算版本 |
| 7 | 文件開頭的「現行系統版本」改成 `1.0.0` | 文件和系統版本一致 |
| 8 | 由深到淺改資料夾名稱，再改檔名 | 資料夾和檔名也要換成新代號 |
| 9 | 把新的 User Secrets ID 寫進 Web 專案的 csproj | 機密和其他專案分開 |
| 10 | 清空舊 migration，重新產生一個叫 `Init` 的 migration | 腳手架的資料庫變更歷史對新專案沒意義，從乾淨的第一版開始 |
| 11 | 清理文件：刪掉 `planning/`、`superpowers/`，清空 `changelog/`，修正指向它們的連結 | 新專案不帶腳手架的開發史 |
| 12 | 掃描殘留字串並印出警告，最後印出新網址、Google 登入要註冊的網址 | 讓你知道下一步 |

**腳本「不會」做的事**：

- 不會 `git init`（新資料夾沒有版本控制，要自己建）。
- 不會換 Logo 和網站圖示（圖片是二進位檔）。
- 不會改預設管理員密碼 `support`（換成另一個固定值也不會比較安全；正式環境由啟動檢查擋下）。
- 不會改 `DataProtectionApplicationName`（改了會讓既有登入全部失效，對新專案沒必要）。

### 7.6 跑完的畫面怎麼看

**成功時**會看到：

```text
UserSecretsId set to <新的 GUID>
SystemVersion reset to 1.0.0 (2026/10/02)
...
警告: ...（五條）
...
Next: see docs/guides/VS Code 開發環境與新專案上手指南.md - section 7 ...
```

**那五條「警告」全部都不用處理**。它們是掃描規則的必然命中，不是待辦：

| # | 位置 | 為什麼不用處理 |
|---|---|---|
| 1–2 | 上手指南的範例 | 文件正在教你「這個值要換掉」，本來就要把它印出來 |
| 3–4 | 腳本本身 | 腳本自己的取代規則，日後從這個專案再往下衍生時還用得到 |
| 5 | 整合測試 | 測試專用的金鑰，不進產品；改了測試會失敗 |

**反而不會警告、但你一定要處理的兩件事**：

1. **JWT 金鑰還是佔位符**（`Acme.Erp-ChangeThisJwtSigningKey-AtLeast32Chars`）。開發可以用，上線前必換。
2. **管理員密碼還是 `support`**。開發可以用，上線前必換。

這兩件事在正式環境啟動時會被擋下，不會靜悄悄地帶著弱密碼上線。

## 10. 複刻後的版本控制與腳手架更新

### 10.1 Why：腳手架會繼續更新，但你的專案不會自己知道

腳手架會持續修安全漏洞、補守門測試、改善慣例。
但**已經複刻出去的專案和腳手架之間沒有任何自動連結**，目前也沒有自動升級的機制。
不主動追，你的專案就會停在複刻當天的版本。

### 10.2 How：建議的做法

**① 記下你從哪一版複刻**

在第一個 commit 訊息、`docs/changelog/` 第一篇、或 `readme.md` 寫明：「從 NET10-Blazor-Starter 0.9.82 複刻」。
這是日後比對的起點。

**② 把腳手架加成第二個遠端**

```powershell
git remote add scaffold <腳手架的 Git 網址>
git fetch scaffold
```

- `origin` 是你自己的專案，`scaffold` 是腳手架。
- ⚠️ **不要直接 merge 腳手架**：兩邊的代號不同（`MyProject` vs `Acme.Erp`），直接合併會產生大量衝突。

**③ 定期挑選需要的修正**

1. 看腳手架的 `docs/changelog/`，找出你複刻之後的新紀錄。
2. 挑出跟你有關的（特別是安全性修正、守門測試）。
3. 照 changelog 說明手動套用到你的專案，或請 AI 幫忙：

```text
腳手架有一筆更新：<貼上那篇 changelog 的內容或連結>。
請評估這個修正是否適用於本專案，若適用，列出要改的檔案並說明差異。
注意本專案的代號是 Acme.Erp，不是 MyProject。
```

**When**：建議每個月或每季看一次；有安全性修正時立即看。

## 11. 常見卡關問題

| 症狀 | 原因 | 解法 |
|---|---|---|
| 腳本一開始就停：`dotnet-ef is required` | 沒安裝 dotnet-ef | `dotnet tool install --global dotnet-ef`，重開 PowerShell 再跑 |
| 腳本停在：`Destination already exists` | 目標資料夾已存在 | 換一個路徑，或加 `-Force`（⚠️ 會刪掉原資料夾全部內容） |
| 腳本說代號不符合格式 | 代號有連字號、空白、中文，或數字開頭 | 改成像 `Acme.Erp`、`HrPortal` 這樣的名字 |
| 腳本卡在 `dotnet restore` 或 `migrations add` | 網路下載套件失敗，或 SDK 版本不對 | 檢查網路與 `dotnet --info`；腳本會印出可以手動重跑的指令 |
| 腳本最後一行出現亂碼 | 很舊的腳手架副本用 Windows PowerShell 5.1 執行 | 改用 `pwsh`；純顯示問題，不影響結果 |
| 腳本印出五條警告 | 正常現象 | 不用處理，見 7.6 |
| 瀏覽器連不上或一直重導 | 用了 `http` profile | 改用 `--launch-profile https` |
| 瀏覽器說憑證不受信任 | 沒信任開發憑證 | `dotnet dev-certs https --trust` |
| 連接埠被占用 | 其他程式用了同一個埠 | 改 `Properties/launchSettings.json` 的 `applicationUrl` |
| 畫面完全沒有樣式 | 手動改名時漏改 `App.razor` 的 `*.Web.styles.css` | 改成 `<新代號>.Web.styles.css`（用腳本不會發生） |
| 一個小警告就建置失敗 | 刻意開啟「警告視為錯誤」 | 修掉警告，不要關掉這個設定 |
| 在畫面上改了 `support` 的密碼，重啟又變回去 | 系統每次啟動會用設定檔的值覆寫（刻意的救援設計） | 改 `BootstrapSettings:SupportPassword` 設定值 |
| 正式環境啟動失敗 | 啟動安全檢查擋下：JWT 金鑰、管理員密碼、Swagger 設定、寄信設定 | 錯誤訊息會說是哪一項，照 8.3 用環境變數設定 |
| User Secrets 設了沒效 | 環境不是 Development，或在錯的資料夾執行 | 確認 `ASPNETCORE_ENVIRONMENT=Development`；用 `dotnet user-secrets list --project <Web csproj>` 檢查 |
| 文件編碼檢查失敗 | 某份 `docs/` 的 Markdown 不是 UTF-8 含 BOM | 用編輯器以「UTF-8 with BOM」重存；PowerShell 寫檔用 `-Encoding utf8BOM` |
| 想把資料庫清空重來 | — | 先停止程式，刪除 `C:\temp\Acme.Erp\DB\BackendDB.db`，再重新執行 |
