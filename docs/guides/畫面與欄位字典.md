# 畫面與欄位字典

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：0.9.33
- 首次實作版本：0.9.33
- 最後核對日期：2026/09/19

## 目的

把系統的**每一個畫面、每一個欄位**講清楚：這一頁在做什麼、這個欄位是什麼意思、什麼時候要用它。

### 與 PRD 的分工

| 文件 | 回答的問題 |
|------|-----------|
| [`docs/prd/`](../prd/README.md) 各份 PRD | 「這一頁**怎麼運作**」—— 能力範圍、流程、權限、驗收條件 |
| **本文件** | 「這個**欄位是什麼**」—— 意思、用途、限制、容易誤解的地方 |

兩者都列欄位名，但角度不同。要改功能看 PRD，要搞懂某一欄看這裡。

### 怎麼讀

每個畫面固定三段：

1. **一段白話** —— 這頁做什麼、誰會用。不出現程式屬性名，給操作者看。
2. **這一頁可以做什麼** —— 工具列與動作。
3. **欄位對照** —— 給開發者的表：畫面上的名稱 ↔ 程式屬性 ↔ 限制 ↔ 意義 ↔ 陷阱。

⚠️ 標記代表「這一欄的字面意思會誤導你」，通常是本文件最值得讀的部分。

## 〇、先讀這段：全站共通的概念

這四組概念跨越多個畫面，先在這裡講一次，各畫面不再重複。

### 0.1 「團隊」在不同畫面語意不同 ⚠️

同樣叫「團隊」，**留空的意思完全不一樣**，這是本系統最容易搞錯的地方：

| 畫面 | 欄位 | 留空的意思 |
|------|------|-----------|
| 專案項目 | 團隊 | **公開給所有人看得到**（不是「沒人能看」）|
| 分類清單 | 適用團隊 | **所有團隊都能使用這個分類** |
| 角色管理 | 預設團隊 | 這個角色**只看得到沒有團隊的公開紀錄** |
| 使用者管理 | 團隊 | 沿用**該使用者角色的預設團隊** |

前兩個是「留空＝最寬鬆」，第三個是「留空＝最嚴格」。畫面上的 placeholder 都寫了，但很少人會讀。

> 為什麼分類與紀錄的規則相反：分類的可見性只是下拉選單的便利性過濾，
> 真正的安全邊界由 RBAC 負責，所以刻意放寬。見[速查表 §4.1](../architecture/開發慣例與限制速查.md)。

### 0.2 團隊用「名稱」比對，不是「代號」⚠️

`Project.Teams`、`Category.Teams` 裡存的是**團隊名稱字串**，不是 `Team.Code`。
代號欄位目前只是給人看的備註。改團隊名稱會影響既有紀錄的比對，改代號不會。

### 0.3 權限有三層，不是一層

| 層 | 欄位 | 行為 |
|----|------|------|
| 管理員 | 使用者的「管理員」勾選 | **短路所有動作級檢查**，也不受團隊過濾。不是一種角色 |
| 角色 | 主要角色 ＋ 額外角色 | 權限取**聯集**；但清單的「角色」欄只顯示主要角色 |
| 團隊 | 使用者團隊 ∪ 角色預設團隊 | 決定看得到哪些**資料列**，與能做哪些**動作**是兩回事 |

### 0.4 時間欄位

所有清單的「建立時間／更新時間」都是系統自動寫入，**沒有任何畫面可以修改它們**。
顯示為當地時間。

## 一、登入與帳號

### 1.1 登入　`/Auths/Login`

沒登入的人會被導到這裡。輸入帳號密碼與驗證碼即可進入系統；若系統有開 Google 登入，
也可以直接用 Google 帳號進來。

**這一頁可以做什麼**：登入、勾選記住我、用 Google 登入（需設定才會出現）。

| 畫面上的名稱 | 對應屬性 | 限制 | 意思與用途 | ⚠️ |
|---|---|---|---|---|
| 帳號 | `Input.Account` | 必填 | 系統帳號，不是 Email | 預設管理者帳號是 `support`，密碼由 `BootstrapSettings` 決定 |
| 密碼 | `Input.Password` | 必填 | 登入密碼，PBKDF2 雜湊後比對 | 與「API 密碼」是**兩組不同的密碼**，見 1.5 |
| 驗證碼 | `Input.CaptchaInput` | 必填，4 位數 | 防自動化嘗試 | 登入失敗會**重新產生**，不能沿用上一組 |
| 記住我 | `Input.RememberMe` | — | 勾選後關掉瀏覽器仍維持登入 | 原理見[記住我登入原理說明](../security/記住我登入原理說明.md) |
| 使用 Google 登入 | — | 條件顯示 | 只有在 `GoogleOAuthSettings` 設定完成時才出現 | 第一次用 Google 登入會建立**停用中**的帳號並導向 1.2 |

### 1.2 帳號待審核　`/Auths/Pending`

用 Google 第一次登入時，系統會幫你建一個帳號，但**預設是停用的**，要等管理員啟用。
這一頁就是告訴你「已經建好了，請等通知」。純說明頁，沒有欄位。

### 1.3 登出　`/Auths/Logout`

沒有畫面。點登出會先跳確認窗（0.9.29 起），確認後才真的登出。

> 系統自己發動的強制登出（session 失效、帳號被停用、角色被移除）**刻意不跳確認** ——
> 那是系統行為不是你的意圖，對已經失效的 session 問「確定要登出嗎」只會讓人卡住。

### 1.4 變更密碼　`/ChangePassword`（也可從右上角使用者選單開對話窗）

改自己的登入密碼。要先輸入目前密碼才能改。

| 畫面上的名稱 | 對應屬性 | 限制 | 意思與用途 | ⚠️ |
|---|---|---|---|---|
| 目前密碼 | `CurrentPassword` | 必填 | 驗證是本人 | 忘記密碼**沒有自助管道**，系統沒有寄信能力，只能請管理員改 |
| 新密碼 | `NewPassword` | 必填 | 新的登入密碼 | |
| 確認新密碼 | `ConfirmPassword` | 必填、需與新密碼相同 | 防打錯 | |

> `support` 開發帳號被擋住不能從這裡改 —— 它的密碼由 `BootstrapSettings` 控制，
> 每次重啟會被設定檔覆寫回去。

### 1.5 設定 API 密碼　`/Profile`

**這不是登入密碼。** 這裡設的是「程式呼叫 Web API 時要用的密碼」：
用你的 Email ＋ 這組密碼去打 `/api/v1/auth/login` 換取 JWT token。

| 畫面上的名稱 | 對應屬性 | 限制 | 意思與用途 | ⚠️ |
|---|---|---|---|---|
| 目前密碼 | `CurrentPassword` | 只在已設定過時才出現 | 第一次設定不需要 | |
| 新密碼 | `NewPassword` | 必填 | API 登入用 | **與 1.4 的登入密碼各自獨立**，改一邊不影響另一邊 |
| 確認新密碼 | `ConfirmPassword` | 需相同 | | |

## 三、業務資料

### 3.1 專案項目　`/projects`

系統內建的示範業務模組，也是你之後新增自己模組時的樣板。
每個專案可以掛分類標籤、團隊標籤，還可以上傳附件。

**這一頁可以做什麼**：新增、修改、刪除、重新整理、關鍵字搜尋、依分類過濾、依團隊過濾。
新增／修改／刪除按鈕會依你的權限個別顯示或隱藏。

**清單欄位**

| 畫面上的名稱 | 對應屬性 | 型別／限制 | 意思與用途 | ⚠️ |
|---|---|---|---|---|
| 標題 | `Title` | 必填 | 專案名稱，預設遞增排序 | |
| 描述 | `Description` | 選填 | 補充說明 | |
| 開始日期 | `StartDate` | 選填 | 預計或實際開始日 | |
| 結束日期 | `EndDate` | 選填 | 預計或實際結束日 | **不可早於開始日期**，儲存時會擋 |
| 狀態 | `Status` | 五選一 | 未開始／進行中／已完成／暫緩／等待 | 0.9.30 起顯示為徽章；合法值由 `StatusOptions` 界定、服務層把關 |
| 優先級 | `Priority` | 三選一 | 低／中／高，預設「中」 | |
| 完成百分比 | `CompletionPercentage` | 0–100 整數 | 進度 | 超出範圍儲存時會擋 |
| 負責人 | `Owner` | 必填 | **純文字姓名，不是系統帳號** | 不會與使用者管理連動，打錯不會有人提醒 |
| 分類 | `CategoriesText` | 顯示用 | 多個分類以「、」串起來 | 這是投影欄位；實際值在 `Categories` 清單 |
| 團隊 | `TeamsText` | 顯示用 | 同上 | **留空＝公開給所有人**（見 §0.1）|
| 建立時間 | `CreatedAt` | 自動 | | |
| 更新時間 | `UpdatedAt` | 自動 | | |
| 操作 | — | — | 修改／刪除 | 這一欄固定在右側，捲動時不會跑掉 |

**編輯表單**（分四個區塊）

| 區塊 | 畫面上的名稱 | 對應屬性 | 意思與用途 | ⚠️ |
|---|---|---|---|---|
| 基本資料 | 標題 / 負責人 / 描述 | `Title` / `Owner` / `Description` | 同上 | 描述獨占整行 |
| 排程與進度 | 開始日期 / 結束日期 / 狀態 / 優先級 / 完成百分比 | 同上 | 同上 | |
| 分類與團隊 | 分類 | `Categories` | 可複選；下拉**只列出你所屬團隊可用的分類** | 若紀錄原本掛了你看不到的分類，系統會額外插入一個「（已限定其他團隊）」選項，避免存檔時被無聲移除 |
| | 團隊 | `Teams` | 可複選，決定誰看得到這筆 | 留空時儲存前會跳提醒「將對所有使用者公開」 |
| 專案附件 | 新增附件 | — | 可一次選多檔，**每檔上限 1GB** | 副檔名有白名單，`.html`／`.svg`／`.exe` 等預設擋掉 |
| | 待上傳檔案 | — | 這次選了、但還沒按儲存的檔 | **取消編輯會一起丟掉**；未儲存提示有把它算進去 |
| | 已上傳檔案 | `Files` | 先前存好的檔，可下載或標記刪除 | 刪除紀錄時實體檔也會被刪 |

### 3.2 分類清單　`/categories`

維護「分類」這個主檔。分類會出現在專案項目的分類下拉選單裡。

**這一頁可以做什麼**：新增、修改、刪除、重新整理、搜尋。

| 畫面上的名稱 | 對應屬性 | 型別／限制 | 意思與用途 | ⚠️ |
|---|---|---|---|---|
| 名稱 | `Name` | 必填，最長 100，**全系統唯一** | 分類名稱 | 比對前會去除前後空白且不分大小寫；資料庫有唯一索引兜底 |
| 描述 | `Description` | 最長 2000 | 說明這個分類用在哪 | |
| 適用團隊 | `TeamsText`／`Teams` | 多值 | 哪些團隊可以使用這個分類 | **留空＝所有團隊都能用**（與專案的團隊語意相反，見 §0.1）|
| 啟用狀態 | `IsEnabled` | 預設啟用 | 停用後不再出現在專案的下拉選單 | 停用**不會**影響已經掛了這個分類的既有專案 |
| 更新時間 | `UpdatedAt` | 自動 | | 預設遞減排序 |

### 3.3 團隊清單　`/teams`

維護「團隊」主檔。團隊是本系統做資料分權的單位 —— 決定誰看得到哪些紀錄。

**這一頁可以做什麼**：新增、修改、刪除、重新整理、搜尋。

| 畫面上的名稱 | 對應屬性 | 型別／限制 | 意思與用途 | ⚠️ |
|---|---|---|---|---|
| 名稱 | `Name` | 必填，最長 100，**全系統唯一** | 團隊名稱 | **這個字串就是分權比對的鍵**（見 §0.2）。改名會影響既有紀錄的比對 |
| 代號 | `Code` | 選填，最長 50，有填則需唯一 | 對外系統整合或報表用的短代號 | **目前不參與任何分權比對**，純備註 |
| 描述 | `Description` | 最長 2000 | | |
| 啟用狀態 | `IsEnabled` | 預設啟用 | | |
| 更新時間 | `UpdatedAt` | 自動 | | |

## 四、系統管理（僅管理員）

### 4.1 使用者管理　`/myusers`

維護系統帳號，並在同一張表單指派角色與團隊。

**這一頁可以做什麼**：新增、修改、刪除、重新整理、搜尋（比對帳號／名稱／Email／角色名稱）。

**清單欄位**

| 畫面上的名稱 | 對應屬性 | 意思與用途 | ⚠️ |
|---|---|---|---|
| 帳號 | `Account` | 登入用帳號 | 唯一性檢查目前**偏弱**（未去空白、區分大小寫、無資料庫索引），已知待改善 |
| 名稱 | `Name` | 顯示用姓名 | 屬個資，**不會寫進日誌** |
| Email | `Email` | 聯絡信箱，也是 API 登入的帳號 | 系統目前**沒有寄信能力**，這裡不會收到任何通知 |
| 角色 | `RoleViewName` | **只顯示主要角色** | 額外角色不會出現在這一欄，但權限有算進去（見 §0.3）|
| 狀態 | `StatusText` | 啟用／停用 | 0.9.30 起顯示為徽章 |
| 管理員 | `IsAdminText` | 是／否 | 0.9.30 起「是」顯示徽章，「否」顯示「—」 |
| 建立時間 / 更新時間 | `CreateAt` / `UpdateAt` | 自動 | |

**編輯表單**

| 區塊 | 畫面上的名稱 | 對應屬性 | 意思與用途 | ⚠️ |
|---|---|---|---|---|
| 帳號與登入 | 帳號 | `Account` | 必填 | |
| | 密碼 | `Password` | 新增時必填 | **編輯時留白＝不變更**，不是「清空密碼」 |
| 基本資料 | 名稱 / Email | `Name` / `Email` | 名稱必填 | |
| 角色與團隊 | 角色 | `RoleViewId` | 必填，單選，主要角色 | |
| | 額外角色（多角色，權限取聯集）| `AdditionalRoleIds` | 可另外指派多個角色 | 權限是**聯集**不是覆蓋；清單的「角色」欄看不到這些 |
| | 團隊（直接綁定此使用者）| `TeamNames` | 這個人可以存取哪些團隊的資料 | **留空＝沿用其角色的預設團隊**（見 §0.1）|
| 狀態 | 啟用 | `Status` | 停用後無法登入，但保留歷史紀錄 | 與刪除不同：刪除會連紀錄一起消失 |
| | 管理員 | `IsAdmin` | **會短路所有動作級授權檢查** | 勾了之後團隊過濾也不生效；勾選時「團隊留空」的提醒會自動略過 |

### 4.2 角色管理　`/roleviews`

定義角色，以及每個角色能做哪些事。

**這一頁可以做什麼**：新增、修改、刪除、重新整理、搜尋。

| 畫面上的名稱 | 對應屬性 | 意思與用途 | ⚠️ |
|---|---|---|---|
| 名稱 | `Name` | 角色名稱 | 唯一性檢查偏弱，同 4.1 的帳號 |
| 預設團隊 | `DefaultTeams` | 這個角色預設可以看哪些團隊的紀錄 | **留空＝只看得到沒有團隊的公開紀錄**（最嚴格的那一種留空，見 §0.1）|
| 權限設定 | `RolePermission` | 逐資源、逐動作勾選 | 勾「全部」等於該資源的 view／create／edit／delete 全給 |
| 建立時間 / 更新時間 | `CreateAt` / `UpdateAt` | 自動 | |

> **`TabViewJson` 不是畫面上的欄位。** 它是舊的權限彙總字串，由系統從權限矩陣自動產生，
> 現在只剩「角色編輯畫面回填」的用途，**不參與權限判定**（判定讀 RBAC 關聯表）。不要手動編輯它。

> **管理員專屬頁面的權限鍵刻意不出現在矩陣裡。** 使用者管理、角色管理與統計分析各頁
> 都只靠「管理員」旗標放行，勾不到也授不了 —— 這是刻意設計，由守門測試固定。

## 五、統計與分析（僅管理員）

### 5.1 系統健康監控　`/system-health`

一頁看完系統是否正常：資料庫連得上嗎、磁碟還有空間嗎、AI 端點通不通。

| 畫面上的名稱 | 對應屬性 | 意思與用途 | ⚠️ |
|---|---|---|---|
| 健康百分比 | `report.Score` | 得分 ÷ 總權重 × 100 | **總權重是 125 不是 100**。新增一個檢查項會稀釋掉所有既有項目的佔比 |
| 燈號 | `report.Light` | 綠 ≥ 90、黃 ≥ 70、紅 < 70 | 每項正常給滿分、警示給一半、異常給 0 |
| 最後檢查時間 | `report.CheckedAt` | 這份報告產生的時間 | **開頁才檢查**，沒有背景排程，離開頁面就不會再更新 |
| 檢查項名稱／類別 | `item.Name` / `item.Category` | 例如「資料庫」`Database` | |
| 權重 | `item.Weight` | 這一項在總分裡的份量 | 權重高不代表比較嚴重，只代表比較影響分數 |
| 狀態 | `item.Status` | 正常／警示／異常 | |
| 佐證 | `item.Evidence` | 判斷依據的實際數值 | 排錯時真正有用的是這一欄 |
| 最後 100 筆日誌 | `report.LogTail` | 目前日誌檔的尾巴 | |

> ⚠️ **「LLM API」這一項每次開頁都會真的呼叫一次 API** —— 會計費，而且會以作業名稱
> 「系統健康檢測」出現在 Token 用量頁。常開這一頁會累積費用。

### 5.2 日誌檢視　`/logs`

查系統日誌，並可以請 AI 幫你整理成報告。

**這一頁可以做什麼**：依時間區間／最低等級／關鍵字查詢、匯出原始日誌、送 AI 分析、匯出 PDF。

| 畫面上的名稱 | 對應屬性 | 意思與用途 | ⚠️ |
|---|---|---|---|
| 起始／結束時間 | — | 查詢區間 | |
| 最低等級 | `minimumLevel` | 只看這個等級以上 | 只能查**已經寫進檔案**的；等級門檻低於目前設定的內容根本沒被寫下來（見 5.3）|
| 筆數 | `takeCount` | 最多取幾筆 | 有上限 |
| 關鍵字 | — | **比對整筆原始內容**，不只訊息 | |
| 時間 / 等級 / 記錄器 / 訊息 / TraceId | `Timestamp` / `Level` / `Logger` / `Message` / `TraceId` | 展開列可看原始內容 | TraceId 用來把同一次請求的多筆日誌串起來 |

> AI 分析的結果會經過安全管線再渲染（移除圖片、限制連結協定）—— 日誌內容有一部分來自
> 使用者輸入，模型輸出屬於不可信內容。

### 5.3 日誌等級設定　`/log-level-setting`

調整「要記錄到多細」。沒有表格，只有兩張卡片與一組選項。

| 畫面上的名稱 | 對應屬性 | 意思與用途 | ⚠️ |
|---|---|---|---|
| 目前生效等級 | `effectiveLevel` | 此等級以上才會寫入檔案 | |
| 系統預設等級 | `systemDefaultLevel` | `nlog.config` 裡設定的值 | |
| 選擇要輸出的最低等級 | `LevelOptions` | 套用後立即生效 | **只存在記憶體，重新啟動就回到系統預設**；也只影響應用程式自己的日誌 |

### 5.4 系統例外紀錄　`/system-exceptions`

程式出錯時自動收集的清單。**不是逐筆事件**，而是「同一種錯誤聚合成一列並累計次數」。

**這一頁可以做什麼**：依時間／來源／使用者／關鍵字查詢、查看明細、刪除單列、匯出 CSV、
清除 N 天未再發生的紀錄、清空全部。

| 畫面上的名稱 | 對應屬性 | 意思與用途 | ⚠️ |
|---|---|---|---|
| 最後發生 | `LastOccurredAt` | 這種錯誤最近一次發生的時間 | 預設排序欄 |
| 次數 | `OccurrenceCount` | **累計**發生幾次 | 與日誌檢視的筆數對不起來是正常的 —— 那邊是逐筆，這邊是聚合 |
| 類型 | `ShortExceptionType` | 例外型別（只顯示最後一節）| 滑過去可看完整型別名稱 |
| 訊息 | `Message` | 例外訊息 | |
| 頁面 | `Page` | 在哪一頁發生 | |
| 使用者 | `Account` | 誰遇到的 | |
| **操作（日誌訊息樣板）** | `Operation` | **是日誌的訊息樣板，不是使用者的操作** | 例如存的是 `Name={CategoryName}` 而不是 `Name=技術文件` —— 若存成算好的訊息，每個參數值都會變成一種新錯誤，列數會爆炸 |
| 首次發生 | `FirstOccurredAt` | 第一次出現的時間 | 判斷「這是新問題還是老問題」用 |
| 完整堆疊 | `StackTraceFile` | 存在資料庫外的檔案 | 開明細窗時才讀 |

### 5.5 資料庫用量　`/database-usage`

看資料庫佔了多少空間、哪張表最大。

**同一頁上有四種不同的「大小」，不要混用：**

| 畫面上的名稱 | 對應屬性 | 意思 | ⚠️ |
|---|---|---|---|
| 磁碟占用總計 | `TotalOnDiskBytes` | 主檔＋WAL＋SHM 的實際檔案大小 | 這才是「硬碟被吃掉多少」 |
| 主資料庫檔 | `MainDbBytes` | `.db` 檔本身 | |
| 預寫日誌 | `WalBytes` | SQLite 的 WAL 檔 | 會週期性縮回去，暫時偏大是正常的 |
| 共享記憶體索引 | `ShmBytes` | SQLite 的 SHM 檔 | |
| 已配置 | `AllocatedBytes` | 頁數 × 頁大小 | |
| 可回收 | `ReclaimableBytes` | 閒置頁，執行 VACUUM 可以還給作業系統 | 刪了很多資料但檔案沒變小，看這一欄 |
| 資料表 / 紀錄筆數 / 索引數 | `TableName` / `RowCount` / `IndexCount` | | |
| 資料量估算 | `EstimatedBytes` | **欄位位元組長度的加總** | ⚠️ **不是磁碟用量**：不含索引、不含碎片、不含閒置頁。加總起來也不會等於上面任何一個數字 |

### 5.6 Token 用量　`/token-usage`

每一次呼叫 LLM 的 token 數與花費。有四個彙總頁籤與一個明細頁籤。

**這一頁可以做什麼**：依帳號／日期／作業／型別／模型查詢、匯出 CSV、下載 PDF、
刪除單筆、清除某日之前、清空全部。

**加總語意（本頁最容易誤解的地方）** ⚠️

```
輸入（prompt）
 ├─ 其中快取命中   ← 是輸入的「折扣子集」，不另外加
 ├─ 其中圖片輸入   ← 同樣是子集
輸出（completion）
 ├─ 其中推理       ← 計入輸出，不另外加
 └─ 其中圖片輸出   ← 同樣是子集
合計 ＝ 輸入 ＋ 輸出        ← 子集一律不重複計入
```

畫面上寫「**其中**快取／**其中**推理」就是為了防止你把它們再加一次。

| 畫面上的名稱 | 對應屬性 | 意思與用途 | ⚠️ |
|---|---|---|---|
| 時間 | `OccurredAt` | 呼叫發生時間 | |
| 使用者 | `Account` | 誰觸發的 | 空的顯示「（系統自動）」—— 例如健康監控的探測 |
| 作業 | `Operation` | **應用層的業務名稱**，例如「系統健康檢測」 | 不是 API 概念 |
| 型別 | `CallKind` | 呼叫種類 | |
| 供應商 / 模型 | `Provider` / `Model` | | |
| 輸入 / 輸出 / 推理 / 快取 / 合計 | `InputCount` / `OutputCount` / `ReasoningCount` / `CachedInputCount` / `TotalCount` | 見上面的加總語意 | 失敗的呼叫合計欄顯示紅色「失敗」；依時長計費的顯示「時長 N 秒」 |
| 費用 | `CostTwd`（提示顯示 USD）| 這次呼叫花了多少 | **是呼叫當下的快照**。之後改費率表**不會**回頭修正 |
| （摘要列）⚠ N 筆未定價未計入 | `IsUnpriced` | 找不到費率的筆數 | **「未定價」不等於 0** —— 記成 0 會讓漏帳看起來像免費 |
| 當時匯率 | `CostExchangeRate` | 換算 TWD 用的匯率快照 | 台幣與美金總額各自逐列加總，**不能用單一匯率互換** |
| 計價依據 | `CostPriceKey` | 實際套用到哪一組費率 | 費率是**前綴比對**的：`gpt-4o-2024-08-06` 會套用 `gpt-4o` 的費率。對不上兄弟模型時看這一欄 |
| 音訊時長／字元數 | `DurationSeconds` / `CharacterCount` | 另外兩種計費單位 | 同一張表裡混著三種計費單位，「合計」欄的意義會逐列改變 |

## 六、沒有網址、但也是畫面

### 6.1 右上角使用者選單

顯示目前登入者的名稱，管理員會多一個「管理員」標記。展開後有：變更密碼、設定 API 密碼、關於、登出。

### 6.2 「關於」對話窗

顯示六項：系統名稱、系統描述、系統版本、執行環境、啟動時間、已運作時間。
回報問題時附上這六項最有幫助。（0.4.45 起不再顯示 .NET 版本。）

### 6.3 斷線重連提示

跟伺服器的連線斷掉時會蓋住整個畫面。這是 Blazor Server 的特性 ——
畫面狀態存在伺服器端，連線斷了就無法操作，**不是離線模式**。
