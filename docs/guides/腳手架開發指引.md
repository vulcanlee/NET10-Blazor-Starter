## 1. 這個腳手架是什麼

一套已經可以直接上線的 **.NET 10 + Blazor Server 後台系統底座**。
它不是「範例專案」，是「把每個內部系統都會重寫一次的東西先寫好」。

### 適合

- 企業內部管理後台、營運系統、專案追蹤平台。
- 使用者數十到數百人、以**部門／團隊**切分資料可見範圍。
- 需要「一開始就有」帳號權限、日誌、稽核、健康監控的專案。

### 不適合

| 情境 | 為什麼 |
|------|-------|
| 公開網站、高流量 C 端 | Blazor Server 每個使用者一條 SignalR 連線，狀態在伺服器 |
| 需要離線／弱網路 | 連線斷了畫面就不能操作，不是漸進式降級 |
| 多租戶 SaaS | 沒有租戶隔離，只有團隊分權（§6）|
| 高併發寫入 | 只支援 SQLite，單寫入者（§3.3）|
| 需要多國語言介面 | 多語系是空殼，零個 `.resx`（§6）|

### 核心設計取向

**用慣例與守門測試把品質固定住。** 這個 repo 有約 16 個「慣例測試」——
它們不測功能，專門擋「照著做會出錯但不會報錯」的寫法。
你會覺得某些規矩很囉唆，那些規矩幾乎都是踩過坑之後加的，`docs/changelog/` 有紀錄。

## 2. 從複製到跑起來

完整逐步操作在 [VS Code 開發環境與新專案上手指南](VS%20Code%20開發環境與新專案上手指南.md)（732 行）。
這裡只講**順序與最容易出事的點**。

### 2.1 建議順序

```
1. 跑 scripts/New-StarterProject.ps1 複製並改名
2. 檢查高風險字串（上手指南 §8.3 的 12 項）
3. 換掉 appsettings.json 的預設值
4. 設定 User Secrets
5. dotnet build → dotnet test → 跑起來登入
6. 換品牌（名稱、Logo、favicon）→ 見上手指南 §7
7. 換顏色 → 見本文 §4
```

```powershell
./scripts/New-StarterProject.ps1 -ProjectName YourApp -DestinationPath D:\Work\YourApp
```

腳本會：遞迴複製（排除 `.git`／`bin`／`obj`）、全檔文字取代 `MyProject` → `YourApp`、
深層優先改資料夾與檔名、**產生新的 `<UserSecretsId>`**、
把 `appsettings.json` 的開發用 JWT 金鑰與 `SupportPassword` 換掉，最後掃描殘留字串。

### 2.2 `<UserSecretsId>` ⚠️

`src/YourApp/YourApp.Web/YourApp.Web.csproj` 第 6 行：

```xml
<UserSecretsId>83f6d54f-9f33-4cd9-a626-d4c05c996e5d</UserSecretsId>
```

**這個值一定要換掉。** 它是「這個專案的機密存在硬碟哪個資料夾」的鍵：

```
%APPDATA%\Microsoft\UserSecrets\<UserSecretsId>\secrets.json
```

兩個專案共用同一個 Id，機密就會互相污染，而且 `dotnet user-secrets clear`
會一次清掉所有共用專案的機密。

- 用腳本複製：**已經自動換好**（除非你用 `-UserSecretsId` 指定）。
- 手動複製：自己產一個 `[guid]::NewGuid()` 貼上去。

> ⚠️ 只有 `*.Web.csproj` 有這個設定，其他專案沒有，也不需要加。
> ⚠️ User Secrets **只在 Development 環境載入**。正式環境用環境變數或密鑰保管庫。

### 2.3 一定要換掉的值

| 位置 | 值 | 不換的後果 |
|------|----|-----------|
| `JwtSettings:SigningKey` | 開發預設字串 | **Production 啟動會被 `StartupSafetyValidator` 擋下** |
| `BootstrapSettings:SupportPassword` | 預設密碼 | 同上 |
| `Swagger:EnabledInProduction` | 必須**明確**寫 true 或 false | 沒寫也會被擋下（不是預設 false，是強迫你表態）|
| `SystemSettings:ExternalFileSystem:*` | `C:\temp\MyProject\…` | 資料庫與附件會存在暫存目錄 |
| `SystemSettings:SystemInformation:SystemName` / `SystemDescription` | 樣板文字 | 登入頁、側邊欄、首頁都會顯示它 |

應該移到 User Secrets 的：`JwtSettings:SigningKey`、`GoogleOAuthSettings` 兩個、
`CacheSettings:RedisConnection`、`AutoMapper:LicenseKey`。

> ⚠️ `BootstrapSettings:SupportPassword` **不要**放 User Secrets ——
> 它每次啟動會反向覆寫資料庫裡的密碼，行為與一般機密不同。

### 2.4 新增一個 CRUD 模組

```powershell
./scripts/New-CrudModule.ps1 -Name Invoice -DisplayName 發票
```

產生 13 個檔到 `output/crud-modules/Invoice/`，**你自己搬進 `src/`**。
搬完要做的四處權限同步與其他細節，看產生出來的 `README.md` 與
[建立一個新 CRUD 操作網頁說明](建立一個新%20CRUD%20操作網頁說明.md)。

⚠️ **不要用「複製既有檢視」的方式建新模組。** 0.4.27 的 emoji 回歸就是這樣來的。

## 3. 技術棧與為什麼需要它

每一項都用同一個格式：**解決什麼問題 → 不用會怎樣 → 用在哪 → 何時該動它**。

### 3.1 Blazor Server（Interactive Server ＋ 全域 SSR）

- **解決什麼**：用 C# 寫互動式網頁，不用另外做一套 JavaScript 前端與 API。
- **不用會怎樣**：後台系統通常要再養一個前端專案、一套前端建置流程、一組重複的驗證邏輯。
- **用在哪**：全部畫面。
- **何時該動它**：使用者上千人、或需要離線時。它每個使用者佔一條 SignalR 連線，
  狀態在伺服器記憶體裡。

> ⚠️ `Program.cs` 把 SignalR 的 `MaximumReceiveMessageSize` 從預設 32KB 調到 **10MB**。
> 不調的症狀是：在 AntDesign 的多行文字框輸入長文之後，**連線無聲斷掉**。

### 3.2 AntDesign Blazor

- **解決什麼**：現成的表格、對話窗、表單、下拉、日期選擇器。
- **不用會怎樣**：光是「可排序可分頁的遠端資料表格」就要自己寫很久。
- **用在哪**：10 張資料表、所有對話窗。
- **何時該動它**：幾乎不要。它的樣式覆寫有既定規矩（§9），自己另外引一套 UI 庫會打架。

### 3.3 EF Core ＋ SQLite

- **解決什麼**：用 C# 物件操作資料庫，schema 變更用 Migration 版本控管。
- **不用會怎樣**：手寫 SQL、手動管理 schema 演進。
- **用在哪**：全部資料存取。
- **何時該動它**：**這是最可能需要換掉的一項。**

> ⚠️ **SQLite 是單寫入者的檔案資料庫。** 併發寫入會排隊甚至逾時。
> 同時要注意一個矛盾：本專案的快取支援 Redis（多節點情境），
> 但 SQLite 是本機檔案 —— **兩台機器不能共用同一個 SQLite 檔**。
> 真的要橫向擴充，資料庫必須先換掉（SQL Server 軌道已於 0.4.24 移除，要自己接回來）。

### 3.4 Cookie 驗證 ＋ JWT Bearer（雙軌）

- **解決什麼**：網頁畫面用 Cookie（瀏覽器自動帶）、程式呼叫 API 用 JWT（跨網域、可帶在標頭）。
- **不用會怎樣**：只用其中一種，另一種情境會很彆扭。
- **用在哪**：Blazor 畫面走 Cookie；`/api/v1/...` 走 JWT。
- **何時該動它**：要接單一登入（SSO）或 OIDC 時。

> ⚠️ 兩套的 claim 對應是**相反的**：Cookie 的 `NameIdentifier` 放帳號，
> JWT 的 `NameIdentifier` 放 UserId。寫「從 claim 取身分」的程式時不要假設只有一套。

### 3.5 RBAC 動作級授權

- **解決什麼**：不只「能不能進這一頁」，而是「能看不能改」。
- **不用會怎樣**：只能做到頁面層級的開關，實務上一定不夠。
- **用在哪**：`[HasPermission("resource:action")]` ＋ `IPermissionChecker`，UI 與 API 共用。
- **何時該動它**：需要「資料列層級」的細緻權限時（目前只有團隊層級）。

### 3.6 AutoMapper

- **解決什麼**：Entity ↔ DTO ↔ 畫面模型之間的欄位搬運。
- **不用會怎樣**：大量手寫賦值，加欄位時容易漏。
- **用在哪**：`AutoMapping` Profile。
- **⚠️ 注意授權**：16.x 起是商業授權版本，`AutoMapper:LicenseKey` 可留空（開發／測試可用），
  **正式商用請確認授權**。這是複製腳手架時最容易忽略的法務風險。

### 3.7 NLog

- **解決什麼**：把日誌寫成檔案、分級、輪替，並支援執行期調整等級。
- **不用會怎樣**：出事時沒有現場。
- **用在哪**：全站請求耗時、例外、使用者操作。
- **紅線**：**絕不記錄密碼／token／金鑰／驗證碼／Email／姓名**，可記錄的身分只有帳號與 UserId。
  由 `LoggingConventionTests` 擋。

### 3.8 分散式快取（Memory／Redis）

- **解決什麼**：把算過的東西暫存起來；換 Redis 就能多台機器共用。
- **用在哪**：側邊選單。
- **何時該動它**：加入新的高頻查詢時。注意 §3.3 的矛盾。

### 3.9 速率限制

- **解決什麼**：擋住暴力破解與濫用。
- **用在哪**：全部 API，**依使用者或 IP 分割**；登入端點另有更嚴格的配額。
- ⚠️ 兩組配額寫在**同一個政策**裡 —— 用 `[EnableRateLimiting]` 另掛一個政策會被端點慣例蓋掉。

### 3.10 健康檢查

- **解決什麼**：讓負載平衡器／容器編排知道這台機器能不能收流量。
- **用在哪**：`/health/live`（活著嗎）、`/health/ready`（可以收流量嗎），以及 `/system-health` 人工巡檢頁。

### 3.11 AI 整合與 Token 計費

- **解決什麼**：把一大堆日誌丟給 LLM 整理成人看得懂的報告；並記錄每次呼叫花了多少錢。
- **用在哪**：日誌檢視頁的「AI 分析」、健康監控的 LLM 探測。
- **何時該動它**：要加自己的 LLM 功能時 —— **每個呼叫點都必須記一筆用量**，
  作法見[速查表 §6.7](../architecture/開發慣例與限制速查.md)。漏記的那一筆通常正是最貴的。
- **沒填 API 金鑰就等於關閉**，不影響其他功能。

### 3.12 品質關卡

| 機制 | 作用 |
|------|------|
| `Directory.Packages.props`（CPM）| 套件版本單一來源，`.csproj` 不寫版本 |
| `TreatWarningsAsErrors` | 任何新警告直接讓建置失敗，長期維持 0 warning |
| `.editorconfig` ＋ `dotnet format` | 格式一致，CI 有關卡 |
| `global.json` | 鎖定 SDK 版本 |
| 約 16 個慣例測試 | 擋「不會報錯但是錯」的寫法 |

## 4. 換色與換登入頁主題

### 4.1 換成綠色系

**只需要改一個檔**：`src/YourApp/YourApp.Web/wwwroot/theme.css` 的 `:root`。

色相三元組（`--app-accent-rgb` 等）會讓所有濃淡自動跟著走，
所以不用去找散落各處的 `rgba(...)`。以下是一組**實測可用**的綠色系，可以直接覆蓋：

```css
:root {
    --app-accent-rgb: 22, 101, 62;
    --app-edge-rgb: 255, 255, 255;
    --app-glow-rgb: 214, 245, 227;
    --app-inner-rgb: 124, 196, 158;
    --app-tint-rgb: 235, 250, 241;
    --app-tint-glass-rgb: 232, 249, 239;
    --app-shadow-rgb: 16, 61, 40;

    --app-text: #12351f;
    --app-muted: #3d5a49;
    --app-on-accent: #f7fffa;

    --app-accent: #16653e;
    --app-accent-dim: #5fa483;
    --app-accent-light: #a7ddc2;
    --app-accent-soft: rgba(122, 190, 156, 0.25);
    --app-error: #a3161f;

    --app-primary-grad: linear-gradient(165deg, #6fc79b 0%, #1f8a55 58%, #16653e 100%);
    --app-page: linear-gradient(180deg, #f7fffa 0%, #eefaf3 52%, #fafffc 100%);

    --app-rail: linear-gradient(180deg, #0d2c1c 0%, #114023 52%, #16512c 100%);
    --app-rail-text: rgba(240, 255, 246, 0.90);
    --app-rail-text-strong: #f7fffa;
    --app-rail-icon: rgba(240, 255, 246, 0.80);
    --app-rail-faint: rgba(240, 255, 246, 0.62);
    --app-rail-active: linear-gradient(90deg, #16653e 0%, #0f4c2e 100%);
    --app-rail-cta: linear-gradient(135deg, #1f8a55 0%, #0f4c2e 100%);
    --app-dark-grad: linear-gradient(135deg, #0a2416, #16512c, #16653e, #6fc79b);

    --app-thead: #eff9f3;
    --app-row-alt: #f7fdf9;
    --app-row-hover: #e4f6ec;
}
```

沒有列出來的 token（`--app-ok`、`--app-warn`、`--app-off`、圓角、easing、`--app-row`）
**維持原樣不要動** —— 它們是語意色與形狀，不是品牌色。

#### 換色時一定要一起做的兩件事 ⚠️

**（一）同步 `ThemeConventionTests` 的色碼清單。**

`src/YourApp/YourApp.Tests/ThemeConventionTests.cs` 裡的 `PaletteHexes` 陣列
列的是舊的粉梅色碼。換色後跑測試會看到：

```
下列色碼已經不在 wwwroot/theme.css 裡，但仍列在 PaletteHexes 清單中：#51132f、#704054、…
```

把清單換成你的新色碼即可。

> 這一條是 0.9.34 補上的。在那之前換色會讓守門測試**靜默通過** ——
> 它還是綠燈，但守的是一組已經不存在的顏色，實際上不再保護任何東西。
> 本文件的作法就是實際換一次綠色系驗證出來的。

**（二）檢查深色側邊欄上的文字對比。**

`--app-rail-active` 上面是白字。粉梅版的亮端封頂在 `#a52b59`（白字對它約 5.6:1，通過 AA）；
上面的綠色版用 `#16653e`（更暗，更安全）。

⚠️ **不要把 `--app-rail-active` 改成 `--app-primary-grad`** ——
主按鈕漸層的亮端是給深色文字用的，白字放上去會低到約 2:1。

#### 驗收

```
dotnet build   src/YourApp/YourApp.slnx
dotnet test    src/YourApp/YourApp.slnx     # ThemeConventionTests 三條都要綠
```

然後開 `/myusers`、`/projects`、側邊欄收合與展開、任一個「修改」對話窗看一遍。

### 4.2 換登入頁主題（例如冬景 → 秋景）

登入頁的視覺**不吃 `theme.css` 的版面規則**，它有自己的 `Login.razor.css`（415 行）與三張素材。

#### 要換的素材

| 檔案 | 用途 | 要求 |
|------|------|------|
| `wwwroot/images/login-winter-desktop.png` | 桌面背景 | 約 1774×887，**不要有文字、Logo、表單** —— 中段要留白給真的 UI |
| `wwwroot/images/login-winter-mobile.png` | 手機背景 | 約 853×1844，中央低對比留白 |
| `wwwroot/images/login-snow.png` | 飄落粒子，會重複鋪排 | **必須有真正的透明背景**（alpha），不是白底 |

換成秋景時：背景改成楓紅／琥珀色調的落葉場景，`login-snow.png` 換成稀疏的落葉顆粒。
檔名可以沿用（改名要一併改 `Login.razor` 的 `Assets` 參照與 `New-StarterProject.ps1` 的掃描）。

#### `Login.razor.css` 哪些是主題、哪些不要動

| 區段 | 行為 | 換主題時 |
|------|------|---------|
| `.login-container` 的 `--login-*` | 色票別名層 | **不要改**，它們指向 `theme.css`。改 §4.1 就好 |
| `.winter-scene` / `.winter-scene img` | 背景圖容器 | 只有換圖，CSS 不用動 |
| `.snow-layer` / `.snow-layer-far` | 兩層飄落動畫，18 秒與 28 秒 | **要調**：落葉比雪重，速度放慢、幅度加大會更自然 |
| `--snow-image` | 粒子圖來源（寫在 `Login.razor` 的行內樣式）| 換檔名時改這裡 |
| `.login-card` 與 `@supports` 毛玻璃 | 面板材質 | 不用動，顏色來自 token |
| `@media` 各斷點 | RWD（1024／768／359px）| **不要動**，已通過五種寬度驗收 |
| `@media (prefers-reduced-motion: reduce)` | 無障礙降級 | **不要動** |

> ⚠️ 飄落動畫只用 `transform`，不要改成動 `filter` 或 `box-shadow` —— 那會讓整頁持續重繪。
> ⚠️ 改完一定要測 `prefers-reduced-motion`：開啟後動畫必須停止，但顏色回饋要保留。

歷史脈絡見 [登入頁改版紀錄](../changelog/login-redesign.md) 與根目錄的 `design-qa.md`。

## 5. 已經有什麼

完整能力矩陣見 [prd/README.md](../prd/README.md)。摘要：

| 類別 | 內容 |
|------|------|
| 帳號與權限 | 使用者 CRUD、角色與動作級權限矩陣、多角色聯集、團隊資料分權、帳號鎖定、PBKDF2、Google OAuth2（選用）|

## 6. 還缺什麼

**這一節很重要 —— 它決定你要自己補多少東西。** 依「第一天就會撞到」排序。

| # | 缺口 | 現況 | 影響 |
|---|------|------|------|
| 1 | **元件測試與 E2E 是零** | 600 個測試，**沒有一個渲染 Blazor 元件**；UI 保證全靠 regex 掃原始碼 | 改壞畫面時 CI 全綠。對「用腳手架約束品質」這個目標，**這是最大的缺口** |
| 2 | **稽核紀錄有寫沒有看** | `AuditLog` 有資料表、有服務、有測試，**沒有畫面也沒有選單項** | 寫進去就再也拿不出來。做一頁成本極低 |
| 3 | **TOTP 寫好卻沒接上** | 欄位、`ITotpService`、6 個測試都在，但 `ITotpService` **沒有任何地方注入** | 以為有兩階段驗證，其實沒有 |
| 4 | **沒有寄信能力** | 零個 SMTP／郵件套件，`appsettings.json` 也沒有對應區段 | 連帶**沒有忘記密碼**：使用者被鎖在外面只能找管理員 |
| 5 | **沒有使用者自助註冊** | 只能管理員建立，或 Google 首次登入自動建立（預設停用）| 對外服務要自己做 |
| 6 | **沒有任何背景排程** | 唯一的 `IHostedService` 是例外寫入器 | 日誌檔不輪替清理、孤兒附件不回收、Token 用量不彙總 |
| 7 | **檔案儲存沒有抽象層** | 三個類別各自 `Path.Combine` ＋ `FileStream`，路徑是絕對路徑 | 要換 S3／Azure Blob 得改三處 |
| 8 | **沒有 Dockerfile** | 部署綁 Windows ＋ `C:\temp\` 絕對路徑，CI 也跑 windows-latest | 容器化要自己來 |
| 9 | **多語系是空殼** | 有 `AddLocalization` 與 zh-TW／en-US，但**零個 `.resx`、零個 `IStringLocalizer`**，也沒有語言切換器 | 介面文字全部硬編繁體中文。國際化是一項大工程 |
| 10 | **業務頁面沒有匯出，也沒有匯入** | 只有三個診斷頁有匯出 | 使用者一定會要 |
| 11 | **沒有軟刪除** | 全部是硬刪除，沒有還原 | 誤刪就沒了 |
| 12 | **沒有多租戶** | 只有團隊分權，不是租戶隔離 | 做 SaaS 要重新設計 |
| 13 | **帳號／角色名稱唯一性偏弱** | 未去空白、區分大小寫、無資料庫索引（分類與團隊有做，這兩個沒有）| 影響登入與權限。已知待改善 |
| 14 | **沒有 CSP** | 其他安全標頭都有 | 建議先以 `Content-Security-Policy-Report-Only` 上線觀察 |
| 15 | **Refresh token 無法個別撤銷** | 是無狀態簽章 token | 只能靠縮短效期或換金鑰 |

### 刻意不做的三項（不是遺漏）

依 [`changelog/2026-07-09-三項待辦決定不實作.md`](../changelog/2026-07-09-三項待辦決定不實作.md)：
**Refresh Token 落庫撤銷、強制 MFA、SQL Server 軌道**。有真實需求時再重新評估。

### 16. 腳手架升級路徑 ⚠️（目前完全沒有）

**這是最容易被忽略、但長期影響最大的一項。**

腳手架會持續更新：修安全漏洞、補守門測試、改善慣例。
但**已經複製出去的專案不會自己知道**。目前沒有任何機制連結兩者。

建議至少做到：

1. 在 `appsettings.json` 記一個 `ScaffoldVersion`，標明「這個專案是從腳手架哪一版複製出來的」，
   與專案自己的 `SystemVersion` 分開。
2. 複製時保留腳手架的 git remote（`git remote add scaffold <url>`），
   日後可以 `git fetch scaffold` 後比對 `docs/changelog/` 決定挑揀哪些變更。
3. 腳手架這一側，在 changelog 標註哪些是**建議所有衍生專案都跟進**的（安全修補、守門測試）。

## 7. 部署

完整檢查清單在 [正式部署與安全檢查清單](../operations/正式部署與安全檢查清單.md)。這裡講重點。

### 7.1 上線前一定要確認

`StartupSafetyValidator` 會在 Production 擋下這些（沒過就**啟動失敗**，這是刻意的）：

- `JwtSettings:SigningKey` 不是開發預設值
- `BootstrapSettings:SupportPassword` 不是預設值
- `Swagger:EnabledInProduction` 有被**明確設定**
- 用 Redis 時連線字串不為空
- 填了 AI 金鑰時 `Endpoint` 與 `Model` 不為空

它擋不到、但你也要檢查的：CORS 白名單、`ForwardedHeaders` 的信任代理、
外部目錄路徑、附件副檔名白名單。

### 7.2 環境

- Windows ＋ IIS 或 Kestrel。**沒有 Dockerfile**（§6）。
- 走反向代理時**必須**設 `ForwardedHeaders:KnownProxies`／`KnownNetworks`，
  否則來源 IP 會全部變成代理伺服器，而且 `X-Forwarded-For` 可被偽造 —— 速率限制會失效。
- 健康檢查端點：`/health/live`（存活）、`/health/ready`（可收流量）。

### 7.3 已知限制要告知客戶

- **Web API 不做團隊列級過濾**（只有 Blazor 畫面有）。開放 API 給外部系統前務必說明。
- `DownloadPath` 底下的檔案，**任何已登入使用者**都讀得到（沒有逐筆權限檢查）。

## 8. 維運、監控與備份

### 8.1 每天看什麼

| 畫面 | 看什麼 |
|------|-------|
| `/system-health` | 健康百分比與紅黃綠燈。⚠️ 開這一頁會呼叫一次 LLM API（會計費）|
| `/system-exceptions` | 有沒有新的例外簽章、次數是否在爬 |
| `/database-usage` | 磁碟占用；「可回收」偏大時考慮 VACUUM |
| `/token-usage` | AI 花費 |

### 8.2 日誌

檔案在 `NLog:BasePath` 底下。`/logs` 可以查詢與匯出，`/log-level-setting` 可以在**執行期**調整等級。

⚠️ 執行期調整**只存在記憶體，重啟就回到 `nlog.config` 的預設**。要永久改請改設定檔。
⚠️ **沒有自動輪替清理**（§6），日誌檔會一直長大，請自行安排排程。

### 8.3 備份

至少要備份三樣，**它們不在同一個地方**：

1. SQLite 資料庫檔（`ExternalFileSystem:DatabasePath`）—— 連同 `-wal`／`-shm` 一起
2. 專案附件（`ProjectFilePath`）
3. 例外堆疊檔與 Token 原始 JSON（`ExceptionPath`／`TokenUsagePath`）

只備份資料庫的話，附件與堆疊檔會遺失，而資料庫裡只剩指向它們的路徑。

### 8.4 改了東西要同步哪些文件

看 [維護規範 §2](../operations/維護規範.md) 的對照表。**每一次異動都要**：
`SystemVersion` Patch +1、新增一篇 changelog、同步索引。

## 9. 用 AI 開發時的約束

目標：讓 AI 產出的程式碼**忠於這個腳手架既有的做法**，而不是每次都發明一套新的。

### 9.1 給 AI 的閱讀順序

專案根目錄的 `AGENTS.md` 與 `CLAUDE.md` 是入口（兩份內容相同，服務不同工具）。
請 AI 依序讀：

| 順序 | 文件 | 管什麼 |
|------|------|-------|
| 1 | `AGENTS.md` / `CLAUDE.md` | 行為準則與**最關鍵的不變量** |
| 2 | [`開發慣例與限制速查`](../architecture/開發慣例與限制速查.md) | 全部慣例與踩雷點（597 行，⚠️ 標記是硬紅線）|
| 3 | [`對話窗 UI 設計規範`](../architecture/對話窗%20UI%20設計規範.md) | 浮層：對話窗、確認窗、通知 |
| 4 | [`介面視覺設計規範`](../architecture/介面視覺設計規範.md) | 常駐介面：色票、側邊欄、表格 |
| 5 | [`畫面與欄位字典`](畫面與欄位字典.md) | 既有欄位的意思（避免誤解語意）|
| 6 | 對應的 PRD | 該模組的既有行為 |

### 9.2 這些事情不要自己發明

| 主題 | 一律用 | 不要 |
|------|-------|------|
| 新 CRUD 模組 | `scripts/New-CrudModule.ps1` | 複製既有檢視 |
| 對話窗尺寸與版型 | `Class="form-modal"`，尺寸寫在 `OverlayStyles.razor` | 用 `<Modal Width>` |
| 確認窗 | `Components/Commons/ConfirmDialog.cs` | 自己寫 `ConfirmAsync`（必定漏 `Danger`）|
| 通知 | `Components/Commons/ViewNotification.cs` | 直接用 `NotificationService` |
| 狀態徽章 | `<StatusPill Text Tone />` | 自己寫 span 與樣式 |
| 顏色 | `var(--app-*)` | 寫死色碼 |
| 表格樣式 | `wwwroot/theme.css` 一份全域 | 寫在檢視的 `.razor.css` |
| 圖示 | `ToolbarIconButton` / `CrudActionButton` ＋ classic Material Icons | emoji、AntDesign `<Icon>`、Material **Symbols** 名稱 |
| 表格排序解析 | `Components/Commons/TableSortHelper.cs` | 自己讀 AntDesign 內部屬性 |
| 資料存取 | `IDbContextFactory`，用完即棄 | 注入 scoped `DbContext` |
| 匯出檔位元組 | `TextDownloadPayload.Utf8WithBom` | `new UTF8Encoding(true).GetBytes()`（**不會**輸出 BOM）|

### 9.3 完工驗收清單

**四道指令**（全部要綠）：

```
dotnet build   src/YourApp/YourApp.slnx        # 必須 0 warning（TreatWarningsAsErrors）
dotnet test    src/YourApp/YourApp.slnx
dotnet format  src/YourApp/YourApp.slnx --verify-no-changes
pwsh scripts/Test-DocsEncoding.ps1
```

⚠️ **這四道對「視覺是否正確」幾乎完全無感。** CSS 的失敗模式全是靜默的，
所以下面的人工檢查不是選配：

- [ ] 新增／修改的對話窗：接近滿版、欄位 2 欄、標題列與按鈕列固定、中間捲動
- [ ] 有改動的表格：滑過整列時，**固定的「操作」欄不可留下一塊白**
- [ ] 排序中的那一欄，底色要跟著整列走，不可還是灰的
- [ ] 側邊欄收合後，**兩層飛出**滑鼠平移不斷開；點完子項後飛出要收起來
- [ ] 捲動讓固定欄位於頂欄下方，再開右上角使用者選單 —— 不可被蓋住
- [ ] 開啟 `prefers-reduced-motion` 後無彈跳，顏色回饋仍在
- [ ] 四個寬度：640 / 768 / 1024 / 1800px

**文件同步**（`CLAUDE.md` 的硬性要求）：

- [ ] `SystemVersion` Patch +1
- [ ] 新增一篇 `docs/changelog/`，UTF-8 **含 BOM**
- [ ] 依 [維護規範 §2](../operations/維護規範.md) 對照表更新受影響的文件
- [ ] 新增／移除文件時，**三處索引**缺一不可
- [ ] **不要自動 commit**

### 9.4 為什麼慣例這麼多

幾乎每一條都對應一次實際踩過的坑，而且那些坑的共同特徵是
**不會壞、不會紅、CI 全綠，只有實際點開那一頁才看得出來**：

- 對話窗少寫 `MaskClosable="false"` → 誤點遮罩，整份輸入無聲蒸發
- 用 `EditContext.IsModified()` → **恆為 false**，未儲存提示永遠不跳
- 匯出用 `new UTF8Encoding(true)` → 沒有 BOM，Excel 開啟整片亂碼
- 列底色寫在 `tr` 而非 `> td` → 固定欄留白塊
- 色票寫死在檢視裡 → 半年後換品牌色翻五個檔都翻不完

守門測試就是把這些坑變成「會紅」。**看到守門測試擋你，先讀它的失敗訊息** ——
那裡通常寫著當初為什麼要加這一條。
