## 一、目標與範圍

管理員處理系統管理工作時，要在系統管理底下的 16 個頁面之間來回切換：查問題時要比對健康監控、日誌、例外、排程紀錄；例行巡檢要逐頁看健康、備份、排程、用量；整理帳號與權限要翻使用者、角色和稽核紀錄。

「系統管理助理」在系統管理底下提供**單一入口**的 AI 代理人：管理員用一般說話的方式提問或下指令，它在背後**自動分派**給各領域的專家。專家能查詢、分析，也能**實際執行異動，但每一次異動都必須由管理員核准**。

這個功能建立在既有的 MAF Agent 骨架上，見 [AI Agent PRD](AI-Agent-prd.md) 與 [MAF AI 呼叫架構](../architecture/MAF-AI呼叫架構.md)。
使用說明、操作手冊、實機截圖與測試報告見 [系統管理助理：功能說明、使用手冊與測試報告](../features/系統管理助理.md)。

| 包含 | 不包含 |
|---|---|
| 系統管理底下四大類、16 頁的查詢與異動：帳號與權限、監控與診斷、AI 管理、系統設定與維運 | 定時巡檢自動修正問題（巡檢只查詢、只建議） |
| 對話中按需巡檢，產出固定格式的巡檢報告 | 在所有頁面都能叫出的浮動對話窗 |
| 所有異動都需要核准；不可復原的動作在核准窗以紅字警告 | 開放給非管理員角色 |
| 批次異動：一次核准整批，單次最多 50 筆 | 透過對話新增帳號、修改帳號基本資料（密碼會經過模型與紀錄，改為指引到「使用者管理」頁） |
| 對話保存與接續、逐段顯示、停止產生、Token 記帳與用量上限 | 還原備份、下載備份檔；RAG／知識庫；修改設定目錄以外的設定 |
| 第二版（0.9.161）：每天定時巡檢、存報告、需要注意時主動通知全體管理員 | 在頁面上修改巡檢時間（只能改設定檔的 cron）；單次巡檢費用上限 |

### 成功標準

1. 一句「幫我巡一下系統」就得到涵蓋健康、例外、排程、備份、用量、帳號異常的巡檢報告。
2. 問「昨晚備份為什麼失敗」時，它會自己串起排程紀錄、例外與日誌找出原因，不用開五個頁面。
3. 動手做事安全可靠：核准窗清楚說明要做什麼，做完留有稽核紀錄，結果和手動操作完全一致。

| 頁面 | 路由 | 選單 | 權限 |
|---|---|---|---|

## 三、架構

### 3.1 分派

- 每則使用者訊息先做一次「分派」判斷：用便宜的模型回覆要用的領域代碼（可以複選），代碼有 `accounts`、`monitoring`、`ai`、`ops`、`patrol`（巡檢）。判斷時會參考最近幾輪的對話，所以「那就停用他」這種接續句也能分對。
- 依判斷結果組出這一輪的 Agent，內容包括：共同說明、**四個領域的全部唯讀工具**（每輪都有，避免分派漏選導致查不到資料）、被選中領域的說明與異動工具。`patrol` 只載入唯讀工具，並套用巡檢報告格式。判斷結果無法解析或分派呼叫失敗時，退回「只有唯讀工具，套用全部領域的說明」。
- 整段對話共用一個 MAF session，前後文延續；每一輪重新建立 Agent，工具組可以不同。
- 模型要求核准之後，核准回覆那一輪沿用提出要求時的同一組定義，不重新分派。
- 不採用 MAF 的 handoff，也不把專家包成另一個 Agent 的工具。原因：這兩種做法下，專家要求的核准不會回到外層、外層找不到專家的工具、執行編號不連貫、專家的對話不會保存，也無法逐段顯示。

### 3.2 模型、提示詞與記帳

| 項目 | 設定 |
|---|---|
| 模型 | `AiModelSettings:AdminAssistant`（空白時用 `AiSettings:Model`）、`AiModelSettings:AdminAssistantRouter`（空白時用 AdminAssistant） |
| 提示詞（「AI 提示詞」頁可改） | `AdminAssistant`（共同說明，含巡檢報告格式）、`AdminAssistantRouter`、`AdminAssistantAccounts`、`AdminAssistantMonitoring`、`AdminAssistantAi`、`AdminAssistantOps` |
| Token 用量作業名稱 | 「系統管理助理」、「系統管理助理（分派）」；0.9.161 起定時巡檢另記「系統管理助理（排程巡檢）」（沒有登入使用者，只受全系統上限） |
| 對話保存 | 沿用 `AiAgentConversation`，AgentName 為 `AdminAssistant`，只限本人 |

分派呼叫與主呼叫都照常記 Token 用量、寫 AI 對話紀錄、檢查用量上限，並共用同一個 ConversationId。

### 3.3 資料外送

為了回答問題，使用者清單、稽核紀錄、日誌、例外堆疊、AI 對話內容都可以送給模型（使用者已同意），但會截斷長度。設定一律透過系統參數目錄讀取，**沒有任何工具會讀原始設定、連線字串或金鑰**。

## 四、工具

原則：

- 每個工具的權限都設為該功能原頁面的管理員專屬鍵。
- 參數用人看得懂的識別，例如帳號、角色名、排程名稱、檔名、參數鍵。
- 唯讀工具嚴格截斷筆數與字數。
- 所有異動工具都需要核准；標 ⚠ 的是不可復原的動作，核准窗會加紅字警告。

| 領域 | 唯讀 | 異動 |
|---|---|---|
| 帳號與權限 | 搜尋使用者（含 N 天未登入）、使用者明細、角色清單與權限、查詢稽核紀錄與內容 | 停用／啟用、解鎖、強制登出、軟刪除／還原帳號、設定或取消管理員、調整使用者角色、調整角色權限、軟刪除／還原角色；⚠ 徹底刪除帳號、⚠ 重設 2FA、⚠ 徹底刪除角色、⚠ 清除或清空稽核紀錄 |
| 監控與診斷 | 系統健康報告（會實際做一次 AI 探測並登入 SMTP）、查詢日誌、目前日誌等級、查詢例外與堆疊、資料庫用量 | 調整或還原日誌等級、寄測試信、發測試通知；⚠ 刪除、清除或清空例外 |
| AI 管理 | 提示詞與版本歷史、Token 用量摘要、用量上限狀態、查詢 AI 對話紀錄與明細 | 儲存提示詞新版本、啟用指定版本或回到預設；⚠ 刪除、清除或清空 AI 對話紀錄與 Token 用量 |
| 系統設定與維運 | 系統參數總覽（只限目錄內的鍵）、排程總覽與執行紀錄、備份清單、公告清單、資料保留總覽與預覽 | 修改或重設系統參數、立即執行或啟停排程、立即備份、新增或修改公告；⚠ 刪除公告、⚠ 刪除備份、⚠ 自訂清除、⚠ 立即執行清理類排程、⚠ 縮短保留天數 |

- **工具層的保護**：不能對自己強制登出、重設 2FA、取消管理員身分；不能取消最後一位管理員；support 帳號與預設角色的保護沿用服務原有規則。
- **稽核一致性**：原本由頁面自己寫稽核的動作，工具也用同一個稽核代碼寫入，detail 加上 `via=admin-assistant`。唯讀工具同樣比照頁面寫入查詢與檢視的稽核；頁面本身沒有寫稽核的統計類讀取則不寫。服務本身就會寫稽核的動作（使用者、角色）不重複寫。
- **查某一筆資料的異動**（0.9.173 起）：`search_audit_logs` 多了 `targetType`、`targetId` 兩個參數，完全相同才符合（關鍵字是部分比對，編號 12 會混到 112）；有給目標、沒給起始時間時預設往前查 366 天（沒給目標仍是 24 小時）。
  給了目標、**沒指定 `action`** 時自動排除換頁、搜尋、查看這類瀏覽紀錄（`AuditLogQuery.ExcludeBrowsing`，與資料頁「異動歷程」同規則），避免常被打開來看的資料，真正的修改被擠出前 20 筆；要查誰看過這一筆，請指定 `action`（例如 `Category.View`）。
  `targetType` 不在資料庫實際出現過的清單裡（例如把 `MyUser` 猜成 `User`）時，回傳的 note 提醒「不在系統已知的清單裡，可能查不到資料；請確認名稱是否正確」。
  帳號專家的指示加一句：問「某一筆資料是誰改的、改了什麼」時用 targetType＋targetId 精確查，需要修改前後差異再用 `get_audit_log_content`（改的是內建提示詞，見 [AI 提示詞管理](AI提示詞管理-prd.md)：管理員存過自訂版本的不會自動套用）。
  稽核 `Audit.Search` 比照稽核紀錄頁：`targetType` 在清單裡時摘要直接記，不在清單裡只記有沒有填；`targetId` 摘要只記 `hasTargetId=True/False`，原文只在詳細內容檔。見 [稽核紀錄 PRD](稽核紀錄-prd.md) §3.1。
  0.9.174 起稽核的「記錄修改前後差異」「記錄瀏覽類事件」兩個開關預設關閉：查瀏覽類動作（例如 `Category.View`＝誰看過）而瀏覽開關關閉時，回傳的 note 說明「目前沒有記錄瀏覽類事件…，查不到不代表沒有人看過」；`get_audit_log_content` 讀到沒有差異的修改時說明是開關關閉（開啟中則註明可能是開啟前寫的）。工具說明也提到兩個開關，避免模型把「沒有記錄」當成「沒有發生」。
- **批次**：可以作用在多個對象的異動工具，參數一律用清單，上限 50 筆。結果逐筆列出成功或失敗，每筆各寫一筆稽核。
- 排程與備份都是「排入佇列」：工具回覆「已排入」，並提示可以再查執行紀錄看結果。

## 五、畫面

- 版面與 Agent 測試台相同：左側「我的對話」（可重新命名、刪除，有待核准標籤）；右側是對話區、輸入框、停止產生、新對話，並顯示目前使用的模型。
- 每則 AI 回答上方標示「由 某某 回答」；跨領域時列出多個，巡檢時標「巡檢」。
- 空白對話時顯示範例問句：「幫我巡一下系統」「最近排程的執行狀況」「昨晚備份為什麼失敗」「哪些帳號超過 180 天沒登入」「把日誌等級調成 Debug」。
- 核准窗不能按 × 或遮罩關閉。窗中顯示工具名稱、參數與完整的批次對象清單，不可復原的動作加紅字警告。

**WebAssembly（0.10.7 起，WASM 遷移 M8）**：頁面與巡檢報告窗改在瀏覽器執行（`MyProject.Web.Client/Pages/AdminAssistantPage.razor`、`Views/Admins/AdminAssistantView.*`、`AdminPatrolReportsModal.*`；Server 版已刪除），畫面與訊息和之前相同。資料經只限管理員的 `api/v1/admin-assistant`（頁面資訊、我的對話、打開、改名、刪除、送出訊息與回覆核准〔NDJSON 串流〕、巡檢報告清單與單份），流程與 Agent 測試台共用 `AgentConversationEndpoint`：
- 每則訊息與每次核准都在伺服器「讀存檔 → 接續 → 執行 → 存檔」；停在核准的對話接續時**沿用提出核准的那一輪**（分派結果代碼存進對話檔的 `TurnKey`，由 `AdminAssistantTurnPlanner.RestoreTurnAsync` 重建，不呼叫分派模型）。「由誰回答」的標籤每個請求至少送一次。
- 網址帶 `?conversation={id}`，重新整理回到同一段對話（停在核准的再跳出核准窗）；`?patrolReport={id}` 深連結照舊。
- 同一段對話一把鎖：兩個分頁同時操作時後到的排隊；核准以條件式更新搶占，同一個核准送兩次只執行一次。核准不可復原的動作沒輸入「確認」伺服器也擋（400，`AdminAssistantApproval` 搬到 Client 與伺服器共用）。

## 七、第二版：定時巡檢與主動通知（0.9.161）

使用者 2026/11/06～07 決定的需求：

| 項目 | 決定 |
|---|---|
| 頻率 | 每天一次，預設 07:30（`ScheduledJobSettings:Jobs:AdminPatrol:Cron`，時間只能改設定檔）；可在「排程作業」頁停用或立即執行 |
| 何時通知 | 報告中有「注意」或「異常」才通知；全部正常只存報告、不打擾。判讀不出來（例如提示詞被改掉）也通知 |
| 通知管道 | 站內通知（右上角鈴鐺）＋ Email，給所有啟用中的管理員；內容是摘要（只列需要注意的段落與重點）＋報告連結 |
| 報告存放 | 系統管理助理頁的「巡檢報告」視窗，全體管理員都看得到；不放進「我的對話」 |
| 保留 | 90 天，系統參數「巡檢報告保留天數」可調（1～3650），由「巡檢報告清理」排程刪除，列在資料保留總覽 |
| 費用 | 每次約 NT$ 3（2026/11/07 實測 `gpt-5.6-sol` 三次都是 2 次模型呼叫、NT$ 2.65～2.73；決定時估 NT$ 1～2），不另設單次上限，沿用現有配額與記帳（作業名稱「系統管理助理（排程巡檢）」） |
| 執行身分 | 系統排程身分＋窄門：只在這次巡檢放行巡檢用的唯讀工具，其他一律拒絕；稽核的操作者留空並註明「排程巡檢」，不冒用任何人 |

技術決定：

- 巡檢**不經過** `AiAgentRunner`（它會存對話、權限檢查依賴登入的使用者、每輪多一次分派呼叫），改用 `AdminPatrolRunner` 直接以 `IAiAgentFactory` 執行；提示詞由 `AdminAssistantTurnPlanner.PatrolTurnAsync` 組出（跳過分派，仍讀「AI 提示詞」頁的作用中版本）。
- 窄門 `ScheduledPatrolToolGuard` 不註冊進 DI、不改動共用的 `AiToolPermissionGuard`；放行條件是「不會異動資料」且「名稱在 `AdminAssistantAgent.PatrolToolNames`」（巡檢指示列的 9 個；獨立審查後收窄，不給讀 AI 對話內文這類用不到的唯讀工具）。`AdminPatrolRunner` 在有登入使用者的 scope 被呼叫時直接丟例外，避免頁面誤用而越權。
- 報告內文是模型回應，只存內容檔（`{AiAgentConversationPath}\AdminPatrol\{yyyyMM}\{報告編號}.md`），資料表 `AdminPatrolReport` 只存狀態與固定的段落名稱（速查表 §6.7）。沿用 Agent 對話目錄，所以備份跟著 `IncludeAiAgentConversations`。
- 通知內文含模型產生的摘錄、而且 Email 會寄出系統外，這是 §6.7「模型內文只進 AI 對話紀錄」的**明文例外**：只寄純文字、移除網址、每段最多 3 點、全文 1000 字內。
