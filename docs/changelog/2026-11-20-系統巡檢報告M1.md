# 系統巡檢報告 M1：每天一份有燈號的日報，取代系統管理助理的定時巡檢（0.10.39）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：0.10.39
- 首次實作版本：0.10.39
- 最後核對日期：2026/11/20

## 目的

使用者 2026/11/20 要求：定時（每天、每週、每月）產生系統巡檢報告，以 PDF 分析報告寄給管理員；報告最前面是**全面摘要**——哪些問題已經發生、哪些即將發生、哪些只要注意、哪顆磁碟需要擴充——每一項都寫出「不處理會怎樣、怎麼處理、處理完會怎樣」。

0.9.161 起的「系統管理助理巡檢」由 AI 判讀狀態：同樣的狀況每次結果可能不同、沒設定 AI 就沒有報告、改了提示詞格式就「無法判讀」。這次改成**程式依固定規則判定燈號、AI 只寫說明**，並分四個里程碑交付；M1 是日報、新頁面、容量快照與 AI 說明，PDF 與寄附件在 M2。

需求、決定與規則目錄見 [系統巡檢報告 PRD](../prd/系統巡檢報告-prd.md)。

## 決定（使用者 2026/11/20 選定）

- 報告只有一種，分日報、週報、月報，各自在「排程作業」頁開關；時間與門檻在「系統參數」；週期採日曆區間（日報是前一天 00:00～24:00）。
- **燈號由程式規則判定**（紅燈＝已發生要馬上處理、橙燈＝即將發生有期限、黃燈＝注意、綠燈＝正常），AI 只寫整體狀況、處理順序與下期預測，不能改燈號。
- 每天記一次容量快照，依成長速度預估磁碟用完日期，提出擴充建議。
- 通知所有啟用中的管理員；日報只有紅燈或橙燈才通知，週報與月報一律寄送。Email 內文是程式產生的摘要加連結（M2 起附 PDF），**AI 說明不進通知與 Email 內文**。
- 新頁面 `/system-reports` 取代舊的定時巡檢；系統管理助理「幫我巡一下系統」在 M4 改用同一套規則並可指定區間。

## 變更內容

### 新頁面「系統巡檢報告」（`/system-reports`）

- 選單「系統管理 › 系統設定與維運 › 系統巡檢報告」（選單 id 70、圖示 assessment），只限管理員，權限鍵不在角色矩陣。
- 工具列：種類、燈號、產生日期（起迄）篩選，查詢、重新整理、立即產生、舊版巡檢報告。
- 清單：產生時間、種類、涵蓋區間、燈號、紅／橙／黃、產生方式、通知、AI 說明、查看報告。
- 報告內容視窗：全面摘要（一句話結論、已發生問題與處理、即將發生與期限、注意即可最多 10 項、需要準備擴充容量、下期預測）、AI 說明、每一項發現（現況／不處理會怎樣／怎麼處理＋前往處理／處理完會怎樣／期限）、磁碟容量、資料目錄、統計、量測限制。燈號以文字加 AntDesign 標籤顏色呈現。
- 立即產生：種類（目前只有日報）、日期（今天以前、保留天數以內）、「產生後寄給所有管理員（不論燈號）」；交給排程佇列在背景產生，完成時以鈴鐺通知產生者；稽核 `Job.Trigger`（`job=SystemReportDaily; date=…; send=…; via=system-reports`）。
- 操作說明 `Datas/Help/system-reports.md`，`HelpTopics.json` 已登記。

### 規則引擎（`MyProject.Web/SystemReports`）

- `SystemReportRules`（純函式）判定每一項發現：健康（被動模式，不呼叫付費的 LLM 檢查、不登入 SMTP）、錯誤、排程、備份、容量、寄信、AI（有設定時才檢查）、安全；讀不到的來源列黃燈「無法查詢：…」。整份報告的燈號是最嚴重的發現。完整規則見 PRD。
- `SystemReportCollector` 蒐集事實（只取數字與狀態，不帶路徑、設定值、例外內文與帳號）；`SystemReportSummarizer` 組全面摘要；`SystemReportGenerator` 產生並存檔；`SystemReportDelivery` 通知管理員或產生者。
- `CapacityProbe`／`VolumeResolver` 量測各磁碟與資料目錄；`CapacityForecast` 以已用空間做線性迴歸，至少 7 天快照才預估，否則顯示「累積資料中」；預估 365 天內用完的磁碟建議擴充「一年成長量＋15%」。
- `SystemReportNarrator`：AI 提示詞新增第 9 份「系統巡檢報告」（`SystemReport`）；輸入只有去識別的發現；輸出「## 整體狀況／## 建議處理順序／## 下期預測」；日報全綠、系統參數關閉或沒設定 AI 時不呼叫；失敗記為 Fallback，報告照常產生。Token 用量作業名稱「系統巡檢報告（AI 說明）」（ConversationId＝報告編號），模型用 `AiSettings` 的預設模型。

### 排程作業

- 新增「系統巡檢日報」`SystemReportDaily`：時間來自系統參數「日報產生時間」（預設 07:30），經新的 `IScheduledJobCronOverride` 提供（排程器每分鐘重讀），**不能**再用 `ScheduledJobSettings:Jobs` 覆寫（驗證器擋下）；排程或補跑時若那一天已有報告就略過；紅燈或橙燈才通知所有管理員（鈴鐺＋Email，連結 `/system-reports?report={id}`），在「排程作業」按「立即執行」也一樣。
- 新增「容量快照」`CapacitySnapshot`：每天 05:00（appsettings）。
- 「巡檢報告清理」改名「巡檢報告與容量快照清理」（作業名稱仍是 `AdminPatrolReportRetention`，03:00）：清新報告、舊版報告與容量快照；稽核 `SystemReport.AutoPurge` 與舊的 `AdminPatrol.AutoPurge`。
- 移除「系統管理助理巡檢」`AdminPatrol`（含 `AdminPatrolRunner`、`AdminPatrolReportParser`、`ScheduledPatrolToolGuard`）；`ScheduledJobSettingsValidator.RetiredJobNames = ["AdminPatrol"]`，舊 appsettings 的覆寫改為忽略、不讓啟動失敗。
- 手動觸發可帶 `Arguments`（JSON），經 `ScheduledJobOverviewService.TryTrigger` 排入佇列。

### 系統參數與設定檔

- 新分類「系統巡檢報告」：日報產生時間（`DailyTime`，HH:mm，07:30）、AI 寫報告說明（`AiNarrativeEnabled`，預設開）、容量紅燈：可用空間低於（%，5）、容量紅燈：可用空間低於（GB）（2，0＝不檢查）、容量紅燈：預估幾天內用完（7）、容量橙燈：可用空間低於（%，15）、容量橙燈：預估幾天內用完（30）、容量黃燈：預估幾天內用完（90）；驗證「紅 < 橙」與「紅 < 橙 < 黃」天數。
- 「資料保留」分類：「巡檢報告保留天數（日報）」（`SystemReportSettings:DailyRetentionDays`，1～3650，90；舊版報告也用它，取代 `AdminPatrolSettings:RetentionDays`）、「容量快照保留天數」（`CapacitySnapshotRetentionDays`，30～3650，730）。
- 設定檔區段 `SystemReportSettings` 取代 `AdminPatrolSettings`。系統管理助理推論等級參數的說明不再提定時巡檢。

### 資料與 API

- 新資料表 `SystemReport`、`CapacitySnapshot`（migration `20261120054158_AddSystemReportAndCapacitySnapshot`）。報告內容是 JSON 內容檔 `{AiAgentConversationPath}/AdminPatrol/{yyyyMM}/{id}.json`（與舊版 .md 同一個資料夾；開啟「備份 Agent 對話」才會進備份）。
- `api/v1/system-reports`（`[AdminOnly]`）：`POST search`、`GET {id}`、`POST generate`（已在佇列 409；今天以後或超過保留天數 400）、`GET legacy`、`GET legacy/{id}`。移除 `api/v1/admin-assistant/patrol-reports[/{id}]`。
- 站內通知分類 `SystemReport`（舊的 `AdminPatrol` 通知照常顯示）。

### 其他畫面

- 資料保留與清理：「巡檢報告」一列改為系統巡檢報告＋舊版報告，「前往」到 `/system-reports`；新增「容量快照」一列（沒有檔案、沒有自訂清除，「前往」到 `/system-reports`，由「巡檢報告與容量快照清理」清除）。
- 系統管理助理：工具列「巡檢報告」改為前往 `/system-reports`；舊連結 `/admin-assistant?patrolReport={id}` 轉到 `/system-reports?legacyReport={id}`（打開「舊版巡檢報告」）。對話裡「幫我巡一下系統」在 M1 不變（M4 改用規則引擎並可指定區間）。

## 已知限制

- M1 只有日報；PDF 與 Email 附件（M2）、週報與月報、備份可還原驗證、AI 費用分析、每季帳號與權限清查（M3）、系統管理助理依指定區間產生報告（M4）尚未實作。
- 容量預估要累積 7 天快照；升級後第一週只看剩餘百分比。
- 日誌管線的計數在網站重新啟動後歸零，報告的「量測限制」會註明。
- 舊版巡檢報告不再產生，依保留天數自然過期。
