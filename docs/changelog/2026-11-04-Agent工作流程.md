## 目的

MAF 四階段計畫的**第四階段：多 Agent 工作流程**。前三階段做出單一 Agent（工具權限、核准、RunId、對話保存）；
交接知識助理這類功能還需要「多個 agent 依流程協作、途中停下來問人」。這一版以 MAF Workflows（`Microsoft.Agents.AI.Workflows` 1.27.0）
做出工作流程骨架，並以新頁面「AI 助理 › Agent 工作流程」的兩條範例驗收：循序＋審閱關卡（專案狀態報告）、並行＋收齊（多觀點審查）。
設計見 [MAF AI 呼叫架構 §6.8](../architecture/MAF-AI呼叫架構.md)。四個階段至此全部完成。

## 一、兩條範例工作流程

| 工作流程 | 步驟 | 示範 |
|---|---|---|
| 專案狀態報告（`ProjectStatusReport`）| **蒐集**（`search_projects`、`get_project_detail`、`ask_user`）→ **撰寫**（Markdown 報告草稿）→ **審閱關卡**（通過／退回／結束（不定稿））→ **收尾**（`search_projects`、`append_project_status_summary`）| 循序流程與三種人工介入 |
| 多觀點審查（`MultiPerspectiveReview`）| 使用者貼上文件 → **需求完整性**、**技術可行性與風險**、**使用者體驗**三位審查者同時審查 → **彙整**收齊三份意見後合併成「彙整意見」| 並行分支（fan-out）與收齊 |

- 蒐集找不到專案、或符合的專案不只一個時，以 `ask_user` 請使用者指定。
- 審閱關卡：退回必須寫意見，撰寫者依意見重寫；最多退回 3 次，之後只剩「通過」與「結束（不定稿）」。通過時草稿成為產出「定稿報告」。
- 新的範例工具（`ProjectAgentTools`，都經 `ProjectService`，團隊範圍與 `Project.Update` 稽核照常生效；建構子可選 `TimeProvider`）：
  - `get_project_detail`「讀取專案明細」（專案項目：檢視，唯讀）：日期、狀態、優先等級、完成度、負責人、分類、團隊、描述（截斷到 1000 字）、附件檔名（`ProjectDetail`）。
  - `append_project_status_summary`「附加專案狀態摘要」（專案項目：編輯，**異動**）：在原描述最後面空一行接上「【狀態摘要 yyyy/MM/dd】…」（摘要收成一行、最多 200 字），原本的描述保留。
- 收尾的工具核准規則同 Agent 測試台：先檢查權限，沒有「專案項目」編輯權限直接拒絕（`Ai.ToolDenied`）、不出現核准卡片；使用者拒絕寫 `Ai.ToolRejected`，報告照樣完成、描述不變。
- 兩條流程的每個 agent 都有自己的提示詞，「AI 提示詞」頁多 7 個分頁（共 10 個）：狀態報告／蒐集、狀態報告／撰寫、狀態報告／收尾、審查／需求完整性、審查／技術可行性、審查／使用者體驗、審查／彙整
  （`PromptTemplateKeys.ProjectReportGatherer`、`ProjectReportWriter`、`ProjectReportFinalizer`、`ReviewRequirements`、`ReviewTechnical`、`ReviewUsability`、`ReviewAggregator`），固定的安全規則照樣自動附加。

## 二、為什麼自己寫 agent 步驟

實作前以探針驗證 MAF Workflows 的行為：

| 驗證項目 | 結果 | 決定 |
|---|---|---|
| 內建 agent executor（`AIAgent.BindAsExecutor`）| 把前一個 agent 的整段對話（含工具呼叫）轉給下一個；並行分支收齊時下游 agent 跑好幾次 | **不用**，改寫自訂 executor `AiAgentStep`，步驟之間只傳文字 |
| 自訂 executor 的事件 | 即時串流出來 | 文字片段與工具活動以 `AiWorkflowStepEvent` 送出 |
| `RequestPort` | 來回可用 | 三種人工介入都經它 |
| `WatchStreamAsync(blockOnPendingRequest: false)` | 停下來等請求時結束串流（狀態 `PendingRequests`）| 畫面讀到請求就停，使用者回覆後再讀下一輪 |
| 同一個 superstep 的 executor | 並行執行 | 多觀點審查的三位審查者同時跑 |
| `InProcessExecution.Concurrent` | 要求 executor 可跨執行共用 | 步驟有狀態，改用 `InProcessExecution.OffThread`、每次執行重新建立 |

## 三、執行器與人工介入

- `IAiWorkflowRunner.StartAsync(定義)` 為每個步驟取提示詞、經 `IAiAgentFactory` 建 agent、經 `AiAgentToolFactory` 建工具，呼叫定義的 `Wire` 接邊，
  並自動替每個會等使用者的步驟接一個 `RequestPort`、登記產出；回傳 `AiWorkflowRun`（`RunAsync(輸入)`、`RespondAsync(RequestId, 回覆)`、`DisposeAsync`＝中斷）。
- 三種人工介入（`AiWorkflowHumanRequest`／`AiWorkflowHumanResponse`），畫面上以卡片當下回覆（不是彈出視窗）：
  工具核准（拒絕／核准）、Agent 提問（`ask_user` 只有宣告、沒有實作，模型呼叫它時由步驟轉成提問；回答不可空白）、審閱（結束（不定稿）／退回／通過）。
- 工具核准的共用規則由 `AiAgentChat` 抽出成 `AiToolApprovals`（權限分流、拒絕原因、參數說明），Agent 測試台與工作流程共用；Agent 測試台行為不變。
- 「停止」取消整個工作流程。結果 `AiWorkflowOutcome`：`Completed`、`Ended`（審閱時選結束）、`Failed`、`Canceled`、`Interrupted`。

## 四、記帳

- 每個 agent 仍經 `IAiAgentFactory` 建立，每一次模型呼叫照常記 Token 用量與 AI 對話紀錄、照常檢查用量上限。
- 一次執行＝一個 `ConversationId`＋一個 `RunId`，整個流程的所有 agent 共用，人工介入的停頓前後也不換。
- 作業名稱是流程名稱：`TokenUsageOperations.ProjectStatusReport`「專案狀態報告」、`MultiPerspectiveReview`「多觀點審查」；
  AI 對話紀錄的「關聯說明」是「流程／agent」，例如「專案狀態報告／撰寫」。
- 模型：`AiModelSettings` 新增 `ProjectStatusReport`、`MultiPerspectiveReview`（空白＝`AiSettings:Model`），系統參數「AI 模型」多兩個
  「「專案狀態報告」工作流程使用的模型」「「多觀點審查」工作流程使用的模型」（生效：下一次執行起，執行中的流程沿用開始時的模型；系統參數共 49 個）。

## 五、執行紀錄

- 每次執行都存到左側「我的執行紀錄」（依目前選的工作流程分開，只有本人看得到），可唯讀回顧、重新命名（不寫稽核）、刪除（稽核 `AiAgentConversation.Delete`）。
- 與 Agent 對話（0.9.143）**共用儲存**：資料表 `AiAgentConversation`（`AgentName` 是流程名稱）、內容檔目錄 `AiAgentConversationPath`、保留天數 `AiAgentConversationSettings:RetentionDays`
  （預設 90，依最後一次執行時間）、排程作業 `AiAgentConversationRetention`、系統參數「備份 Agent 對話」、資料保留頁「Agent 對話」列（附註改為「全體使用者，連同內容檔；含 Agent 工作流程的執行紀錄；依最後一次對話時間」）。
  沒有新資料表、沒有 migration。
- 內容檔：`Session` 為 JSON null、沒有待核准；`AiAgentTranscriptEntry` 多可為 null 的 `Agent`（agent、審閱關卡或產出標題的顯示名稱），紀錄種類多 `Output`（產出）。只加不改，`SchemaVersion` 仍是 1。
- **不能從中途接續**：沒有跨重開機的檢查點。執行中或等使用者時離開、重新整理頁面 → 存成「執行中斷（離開頁面），工作流程無法從中途接續。」；
  等使用者時切換工作流程、按「新的執行」或點開另一筆紀錄，先確認「放棄目前的執行」。Agent 測試台也接不起工作流程紀錄。
