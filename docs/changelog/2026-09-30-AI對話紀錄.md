# 新增「AI 對話紀錄」：保存每次 AI 呼叫的完整 Prompt 與 Response，並與 Token 用量互相連結（0.9.72）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：0.9.72
- 首次實作版本：0.9.72
- 最後核對日期：2026/09/30

## 為什麼

AI 日誌分析、AI 例外分析的結果不如預期、失敗或花費異常時，管理員只看得到 Token 用量頁的數字，
看不到當時到底送了什麼、AI 回了什麼，只能再分析一次、再付一次錢。
這一版複刻 ReviewSkills.AI 1.0.34 的「AI 對話紀錄」頁，UI 改用本專案的設計規範。

⚠️ 這是對既有紅線的**正式修訂**：0.9.71 之前系統承諾「絕不保存提示詞與模型回應內文」。
0.9.72 起 Token 用量仍然絕不存內文；完整內文**只准**存進本功能的專屬儲存區（管理員專屬、依保留天數自動過期、可整個停用）。
其他資料表、NLog 日誌與稽核紀錄仍不得寫入內文。

## 做了什麼

- **新頁面** `/ai-call-logs`（系統管理 › 統計與分析 › AI 對話紀錄，id 66、圖示 `forum`，管理員專屬）：
  - 篩選：起訖日、作業、結果、模型、帳號、關聯說明關鍵字。
  - 清單：送出時間、結果（`StatusPill`）、作業、發起者、模型、耗時、送出字元、關聯說明；可查看對話與刪除。
  - 工具列：查詢、重新整理、匯出 CSV（不含內文）、清空全部；另有清除此日之前。刪除、清除、清空、匯出都寫自我稽核（`AiCallLog.*`）。
- **明細窗**（`.ai-call-log-modal` 90vw×90vh）：
  - 中繼資料、用量與費用（以 `CallId` 帶出 Token 用量）、同一段對話（`ConversationId`）。
  - 五種檢視：完整對話、送出 Prompt、取得 Response、原始 Request、原始 Response；純文字／Markdown 切換、每段複製。
  - 本專案的設計規範：訊息是淺色卡片＋左側角色色條；原始 JSON 用深梅黑原文區塊（`--app-code-*`）；字級「一般／中／大」（納入 `AiModalStyleConventionTests`）。
  - 下載完整紀錄（JSON）、匯出 PDF（沿用 `AiMarkdownPdfRenderer`，不含原始 JSON）。
- **記錄點**：`AiChatCompletionClient`（AI 日誌分析、AI 例外分析含追問）與 `AiHealthProbe`（系統健康檢測）。
  - 新增 `AiCallCapture`：`MarkSent()` 緊貼 `SendAsync`，單一 `finally` 以 `RecordSafelyAsync` 記錄；取消與非預期錯誤也記，沒送出的不記。
  - `AiChatCompletionRequest` 新增 `RelatedInfo`、`ConversationId`；`AiExceptionAnalysisService.AskAsync` 新增選用參數 `AiExceptionCallContext`，由 `ExceptionAiAnalysisModal` 開窗時產生對話識別碼。
  - Token 用量的記錄規則**不變**（仍不記取消與非預期錯誤），所以兩頁筆數可能不同。
- **資料**：新資料表 `AiCallLog`（索引 `OccurredAt`、`CallId` 唯一、`ConversationId`）；`TokenUsageLog` 新增 `CallId`（索引）。migration `AddAiCallLog`。
  內容檔在新設定 `ExternalFileSystem:AiCallLogPath`（`{yyyyMM}/{CallId}.json`），生命週期唯一入口 `AiCallLogFileStore`。
- **設定**：`AiCallLogSettings { Enabled: true, RetentionDays: 90 }`（1～3650，`ValidateOnStart`）。
- **自動過期**：`AiCallLogRetentionWorker`（本專案第一個定時型 `BackgroundService`，比照 `EmailDispatchWorker`），啟動時與每日一次。
- **Token 用量頁**：明細窗新增「AI 對話紀錄」列，有對話時按鈕導向 `/ai-call-logs?callId=…`；`MainLayout`／`NavMenu` 比對選單前去掉查詢字串，深連結的頁名與選單高亮才正確。
- **操作說明**：新增 `Datas/Help/ai-call-logs.md`；`token-usage.md`、`logs.md`、`system-exceptions.md`、`system-health.md`、`database-usage.md` 補上交叉說明（含「AI 呼叫內容會被記錄」的揭露）。
- **測試**：新增 `AiCallLogServiceTests`、`AiCallCaptureTests`、`AiCallLogPdfBuilderTests`、`AiCallLogSettingsTests`；
  各呼叫點測試補上 CallId 一致、取消／非預期錯誤只進對話紀錄、金鑰不外洩、recorder 丟例外不影響結果、追問共用 ConversationId；
  守門清單（管理員專屬、選單、圖示、服務生命週期、字級縮放、整合測試路徑）同步登記。

## 刻意不做的事

- 不移植 SSE 串流相關的欄位、檢視與上限：本專案目前沒有串流呼叫點。日後要加時，以可空欄位擴充、不必遞增 `SchemaVersion`。
- 不提供 Web API、不做內文全文搜尋、不做一般使用者只看自己的分權（與 ReviewSkills 相同）。
- Token 用量 CSV 不加呼叫識別碼欄（格式維持不變）。
- 不改 Token 用量「不記取消」的規則。
