# 修正勾選欄造成清單頁空白（0.9.150）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：0.9.150
- 首次實作版本：0.9.150
- 最後核對日期：2026/11/04

## 問題

「專案項目」頁（`/projects`）整頁空白，日誌每次開頁都有多筆：

```
ERROR|MyProject.Web.Components.LoggingErrorBoundary|Unhandled component exception captured by error boundary. Path=/projects
System.ArgumentNullException: Value cannot be null. (Parameter 'value')
   at AntDesign.CssSizeLength..ctor(String value)
   at AntDesign.ColumnBase.CalcFixedStyle()
   at AntDesign.ColumnBase.OnInitialized()
   at AntDesign.ActionColumn.OnInitialized()
```

## 原因

0.9.132（列表頁多筆刪除）起，專案、分類、團隊三頁的勾選欄寫成：

```razor
@if (!showDeleted)
{
    <RequirePermission Page="..." Action="@PermissionActions.Delete">
        <Selection />
    </RequirePermission>
}
```

AntDesign 1.6.0 的資料列以循環計數器替每一格編欄位序號（`ColumnContext.AddRowColumn`）。勾選格包在元件裡時，
它登記的順序跟同一列的其他欄對不上，**從第 3 列起序號錯位**。右側固定的操作欄（`Fixed="ColumnFixPlacement.Right"`）
在 `CalcFixedStyle()` 計算 sticky 位置時，會把「序號在它之後、有設 Fixed 的欄」寬度加總 —— 錯位後讀到的是真正的操作欄，
而它沒有設 `Width`，`(CssSizeLength)null` 就丟出例外，整頁被 error boundary 換掉。

資料 2 列以內不會錯位，所以一直沒被發現：分類、團隊在開發環境只有 0～1 筆，專案頁直到 0.9.145 產生 10 筆測試專案才爆出來。
以 bUnit 實驗確認：勾選欄包在元件裡＋3 列以上必定重現，與欄數、排序、遠端資料來源、操作欄內容都無關；勾選欄直接放在表格裡則 10 列也正常。

其他有勾選欄的頁（使用者、角色、公告、備份、例外紀錄、AI 對話紀錄、Token 用量）是管理員頁，勾選欄沒有包在元件裡，不受影響。

## 修正

- 專案、分類、團隊頁：code-behind 在判斷「顯示已刪除」權限時一併算出 `canDelete = AuthenticationStateHelper.CheckAccessAction(頁面, PermissionActions.Delete)`，
  表格裡改為 `@if (!showDeleted && canDelete) { <Selection /> }`。`CheckAccessAction` 與 `RequirePermission` 都是 `PermissionRules.CanAccessAction`，權限規則沒有變。
- CRUD 產生器樣板（`scripts/crud-templates/.../__Name__ViewView.razor(.cs).tmpl`）同樣修正，之後產生的模組不會帶著這個問題。
- 開發慣例與限制速查：§3（依權限顯示一律用 `RequirePermission`）註明勾選欄是唯一例外；§6.28 新增第 7 點。

## 測試

- `BatchDeleteConventionTests.Selection_ShouldNotBeWrappedInRequirePermission`：掃描所有檢視與 CRUD 樣板，`<Selection` 不可包在 `<RequirePermission>` 裡（Razor 註解不算）。修正前抓到上述 4 個檔案。
- `TableSelectionContractTests`：
  - `SelectionDirectlyInTable_WithRightFixedColumn_ShouldRenderManyRows`：本專案的寫法，10 列正常。
  - `SelectionWrappedInComponent_WithRightFixedColumn_ShouldThrowFromThirdRow`：鎖住 AntDesign 1.6.0 的行為（2 列正常、3 列丟例外）；AntDesign 修好時會紅，屆時可放寬慣例測試。
- 本機實測：專案頁 10 列、每列有勾選框；勾兩筆顯示「刪除選取（2）」；切到「顯示已刪除」勾選欄消失；分類、團隊頁正常；日誌沒有新的錯誤。
- 測試總數 1910。
