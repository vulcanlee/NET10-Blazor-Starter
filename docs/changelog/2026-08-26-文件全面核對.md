## 目的

`docs/` 累積到 86 份，但版本推進到 0.4.41 的過程中沒有跟上程式碼 ——
不少文件的「現行系統版本」還停在 0.4.23／0.4.24。

本次以三組稽核逐份回到程式碼查證，發現的**不只是版本號沒改**：
有 **7 處文件在教已經被移除、甚至被守門測試明文禁止的做法**。

## 四、索引缺漏與制度性根因

`docs/README.md` 漏列 3 份 PRD；根 `readme.md` 寫死「9 份能力 PRD」（實際 12）、
security 漏 1 份、changelog **漏 12 篇**且排序前半遞增後半遞減、結構樹漏 `prd/` 與 `superpowers/`。

**根因**：`operations/維護規範.md` 的對照表只寫「兩處索引」，實際是**三處**（子目錄 README 也要改）。
已修正對照表，並把根 `readme.md` 的 changelog 清單改為**單行指向 `docs/changelog/README.md`**，
根治三處長期不同步。

## 五、行號引用全面改造

`features/多語系與本地化.md` 與 `檔案上傳機制.md` 的引用是**整段搬家**
（程式碼已從 `Program.cs` 移到 `Extensions/`），一併更正。

> ⚠️ 一個方法論教訓：規劃階段我先跑的程式化檢查只驗「行號是否超出檔案長度」，
> 得到「162 條只有 1 條失效」的樂觀結論（且那 1 條還是 regex 把 `.razor.css` 誤判成 `.razor.cs` 的假陽性）。
> 逐條比對**該行的實際內容**之後，才發現 PRD 就有 42 條指錯。
> **驗「存在」不等於驗「正確」。**
>
> 另一個教訓：稽核代理曾回報「`ApplyPermissionStructure` 全 repo 已不存在」，
> 我據此在規格文件寫下「該方法已不存在」。實際 `grep` 後發現**方法仍在**，
> 只是內部從陣列索引改成了 id 對應。已於同次核對中更正。
> **代理的結論同樣要複驗。**
