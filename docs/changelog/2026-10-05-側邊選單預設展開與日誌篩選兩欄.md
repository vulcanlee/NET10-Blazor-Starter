## 目的

- **側邊選單**：狀態原本只是 `MainLayout` 的一個欄位（`isSidebarCollapsed = true`），每次開頁、F5、開新分頁都從收合（圖示列）開始。使用者希望第一次開啟就是展開。
- **日誌檢視**：「關鍵字」與「錯誤追蹤碼」各佔一整列。原因是 scoped CSS 的 `width: 240px／130px` 對 AntDesign 渲染的 `<input>` 無效（那個元素不帶本元件的 scope 屬性），只剩 AntDesign 自帶的 `.ant-input { width: 100% }` 生效。

使用者決定：

- 預設展開，並記住使用者的選擇。
- 窄螢幕仍預設收合。
- 兩個輸入框同列各佔一半。
- 只改日誌檢視。其他頁搜尋框的同類寬度失效問題這次不處理。

## 二、設計決定

| 決定 | 理由 |
|---|---|
| 在 `OnInitializedAsync`、`isAuthenticated = true` 之前讀取狀態 | 版面在登入檢查完成前完全不渲染，加上 `prerender: false`，這時已可呼叫 JS，而且不會先閃出另一種狀態 |
| 窄螢幕的切換不寫入 | 手機上漢堡鈕是抽屜開關；寫入會蓋掉同一個瀏覽器在桌面寬度時的偏好 |
| 斷點用 `640.98px` | 與 `MainLayout.razor.css`／`NavMenu.razor.css` 一致，JS 判斷與 CSS 版面同時切換 |
| 腳本命名 `nav-state.js`，不叫 `sidebar-state.js` | 腳本出現在未登入的空殼 HTML 裡；`PageAuthorizationTests.UnknownUrl_WithoutLogin_ShouldKeep404AndRenderNoPageContent` 以「沒有 sidebar 字樣」確認版面沒有渲染。最初命名就被這個測試擋下，選擇改名而不是放寬測試 |
| 兩欄寬度由本元件的格子決定 | 對 AntDesign `<input>` 直接下 width 不會生效；格子是本元件的 div，scope 屬性有效 |
