## 起因

`/system-health` 原本的 8 項檢查全是「本機自己的事」—— 應用程式、API、資料庫、日誌、
身分驗證、檔案系統、主機資源、安全設定。**外部相依完全沒有被檢查**：LLM API 通不通、
快取服務真的能不能讀寫，管理員都得等到功能壞掉才知道。

本次新增三項，權重合計由 100 增為 **125**：

| 項目 | 權重 | 做什麼 |
|------|------|--------|
| LLM API | 10 | 實際送一句 `hello` 給設定的 LLM，確認真的有回應 |
| 快取服務 | 10 | 用 `ICacheService` 寫一筆 sentinel 再讀回比對 |
| AI 計費表 | 5 | 確認目前模型在 `AiPricingSettings.Models` 查得到價格 |

## ⚠️ LLM 檢測每次開頁面都會花錢

這是本次最需要知道的行為改變：**每開一次 `/system-health` 就會對外發出一次付費 API 呼叫**。

實測數據（Azure OpenAI、`gpt-5.6-sol`）：

- 每次 **27 個 token**（輸入 23、輸出 4），費用 **NT$0.005418（US$0.000172）**。
- 頁面載入多等 **約 2.4 秒**。

依專案慣例（[開發慣例與限制速查](../architecture/開發慣例與限制速查.md) §6.6）
「每一個發出 LLM API 呼叫的地方都必須記一筆用量」，這次呼叫會記入「Token 用量」，
作業名稱為「**系統健康檢測**」。該頁的「依作業」頁籤因此從 1 列變成 2 列，
可用作業篩選器單獨檢視；未套用篩選時「篩選範圍合計」會把它一併計入。

沒有做結果快取、也沒有改成按鈕觸發 —— 這是刻意選擇的行為，讓燈號永遠反映當下狀態。

## 逾時：為什麼不能沿用設定值

`AiSettings.TimeoutSeconds` 預設是 **600 秒（10 分鐘）**，而具名 client `"AiChatCompletions"`
的 `client.Timeout` 就是從它來的。那個值是為「使用者主動按下 AI 分析、願意等」設計的。

健康監控頁是**自動載入**的，沿用它會讓 LLM 端點一失聯就把整個管理頁卡住十分鐘。

因此 `AiHealthProbe` 用 `CancellationTokenSource.CreateLinkedTokenSource(ct)` + `CancelAfter(30 秒)`
自己控制逾時，不去動共用的具名 client。

## 為什麼不重用 `IAiLogAnalysisService`

那支的簽章是 `AnalyzeAsync(IReadOnlyList<LogEntry> ...)`，空清單會直接回 `NoData`。
要拿它做探測就得餵假日誌，而且帳會被記成「AI 日誌分析」，汙染 Token 用量頁的作業分類。

改為新增 `AiHealthProbe`，直接重用既有的純靜態工具組裝請求：
`AiChatEndpoint.Validate` / `.Create`、`AiChatRequestFactory.CreateRequestJson`、
`AiChatResponseParser.Parse` / `.TryGetError` / `.ExtractUsageJson`。

## 實作細節

- **AI 未設定時回黃燈，不是紅燈。** 這個腳手架預設沒有 AI 金鑰，若判為紅燈，
  每個沒接 AI 的部署都會永遠看到紅燈。未設定時 `AiChatEndpoint.Validate` 會擋在前面，
  **完全不發 HTTP、也不記帳**（與既有的 `NotConfigured` 豁免一致）。
- **一律走 `AiChatEndpoint.Validate`**，不直接呼叫 `settings.GetProvider()` ——
  後者在 provider 打錯字時會拋例外，會炸掉整份健康報告。`CacheSettings.GetProvider()`
  有同樣的問題，快取檢查也一併擋住了。
- **三項新檢查都各自 try/catch 並自帶逾時。** 既有 8 項裡只有資料庫那項有防護，
  其餘 7 項拋例外就會讓整個頁面打不開；新增的都是外部相依，不能沿用那個壞習慣。
- **計費表比對重用 `AiUsageCostCalculator.Resolve`**，不自己實作。它是「完全比對優先、
  再取後綴合法的最長前綴」，自己寫一份必然會與實際計費行為不一致。
- **錯誤訊息只放 `error.code` 與例外型別名**，絕不回吐上游 body ——
  body 可能夾帶提示詞片段。已有測試 `ProbeAsync_ErrorMessage_ShouldNotLeakUpstreamBody` 守住。

## 刻意不動的東西

- **現有 8 項檢查的權重與邏輯完全未動。** 總權重由項目自行加總（不是寫死 100），
  所以只要追加即可，不需要重新平衡。⚠️ 資料庫的權重 `25` 在原始碼裡出現**三次**
  （三個 return 分支），日後若要調整極易漏改 —— 這正是本次補上權重測試的原因。
- **不把 LLM 檢測掛到 `/health/live`／`/health/ready`** —— 那會讓部署平台的輪詢變成付費呼叫。
- **不加 SMTP／備份檢查** —— 這個專案根本沒有這兩個子系統（已搜尋確認）。
- 不重構 `SystemHealthPage.razor` 為 Page＋View 三件式，不在本次範圍。
