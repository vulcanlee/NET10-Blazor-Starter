# 系統例外紀錄新增「AI 例外分析」：分析報告、多輪追問與 PDF（0.9.68）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：0.9.68
- 首次實作版本：0.9.68
- 最後核對日期：2026/09/27

## 為什麼

管理員打開「例外明細」後，常常看不懂堆疊，只能整包轉給開發人員；開發人員也要先花時間判斷嚴重度與根因。
這一版在明細窗加上「AI 分析」按鈕，讓 AI 同時寫出給管理者的白話摘要與給開發者的技術細節，
看不懂的地方可以在同一個視窗內繼續追問，最後下載 PDF 附進工單。

## 做了什麼

- **明細窗**：上方新增「AI 分析」按鈕（`insights`）。堆疊讀取中、AI 未設定時停用；未設定時 Tooltip 顯示缺少哪個設定。
- **AI 例外分析對話窗**（`ExceptionAiAnalysisModal`，`.exception-ai-modal` 96vw×96vh，疊在明細窗之上）：
  - 第一份回覆固定五章：管理者摘要、根本原因、修正建議、排查步驟、需要確認的問題。
  - 報告下方可多輪追問，每輪帶整段前文；上限 `AiSettings:MaxFollowUpRounds`（預設 10），畫面與服務層兩處擋，超過不發請求。
  - 追問失敗時提問放回輸入框、錯誤以紅框留在對話中，前文不受影響。
  - 字級三段、複製整段對話（Markdown）、產生 PDF 並下載（明細＋報告＋每輪追問＋附錄完整堆疊）。
  - **不保存**：關窗即丟棄；等待中關窗同時取消在途請求，遮罩等待中不可點關。
- **個資**：送出的內容不含帳號與 UserId，只給「有／無登入使用者」；PDF 的例外明細同樣不含。
- **共用核心**：HTTP、錯誤對應與 Token 用量記錄從 `AiLogAnalysisService` 抽成 `AiChatCompletionClient`，
  AI 日誌分析改為呼叫它（行為不變，`AiLogAnalysisServiceTests` 全數照舊通過）。named client 常數改為
  `AiChatCompletionClient.HttpClientName`；日誌的記錄器名稱改為 `MyProject.Web.Ai.AiChatCompletionClient`，訊息帶 `Operation=`。
- **PDF 共用**：樣式、頁首頁尾與 Markdown 渲染抽成 `AiMarkdownPdfRenderer`，日誌與例外兩份 PDF 共用。
- **用量**：新作業名稱「AI 例外分析」（`TokenUsageOperations.AiExceptionAnalysis`），初始分析與每輪追問各記一筆。
- **稽核**：`ExceptionLog.AiAnalyze`／`ExceptionLog.AiFollowUp`／`ExceptionLog.AiExportPdf`，只記數量、模型、用量與耗時。
- **設定**：`AiSettings.MaxFollowUpRounds`（預設 10，不寫進 appsettings 範本）。
- **操作說明**：`Datas/Help/system-exceptions.md` 補上按鈕、AI 視窗、訊息、情境與常見問題。

## 刻意不做的事

- 不保存報告與對話（不新增資料表或檔案）：使用者選擇以複製與 PDF 自行留存。
- 不送使用者帳號：對判斷根因幾乎沒有幫助，送出去卻是個資外洩。
- 不送前後時間的日誌、不送原始碼：只送明細窗上看得到的內容，費用與行為都可預期。
- 系統提示詞不開放設定（`AiSettings:SystemPrompt` 仍只給日誌分析用）。
- 不做串流輸出與自動重試，沿用日誌分析的取捨。
