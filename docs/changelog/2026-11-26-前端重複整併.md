## 樣式

- **AI 報告內文 `.ai-markdown`**（`OverlayStyles.razor`）：日誌檢視、AI 例外分析、AI 對話紀錄明細三份相同的 Markdown 規則合併成一份，各頁只留不同的部分（文字顏色、第一個標題的上邊距、明細窗捲動高度）。
  ⚠️ 唯一刻意的外觀改變：日誌檢視的 AI 報告程式碼區塊原本寫死 `#fffafc`／`#b4222a`，現在和另外兩個視窗一樣用 `var(--app-tint)`／`var(--app-error)`。
  `AiModalStyleConventionTests` 多檢查 `.ai-markdown` 的字級，並新增「三個報告容器都掛著 `ai-markdown`」的守門；`ai-markdown` 一律寫在 class 最前面（`ai-markdown exception-ai-report`），因為 e2e 以 `[class$="-report"]` 找報告。
- 稽核明細與例外明細的明細清單（清單、清單列、dt／dd、區塊標題）規則合併成一份（`OverlayStyles.razor`）。
- `ClientEmptyLayout.razor.css`、`ClientNoFooterLayout.razor.css`：拿掉 Server 範本殘留的 `.sidebar`／`.top-row`／`article` 規則（版面標記沒有這些元素，scoped CSS 從未生效），以及被 `column !important` 蓋過的寬螢幕 `flex-direction: row`。

## 評估後刻意不整併

理由詳見測試報告 C.8：其餘 9 處下載（各頁對 400／404／500 的處理不同、有的沒有 try/catch）、AI 串流流程本身（停止與關窗、追問、對話各頁不同）、CRUD 頁的還原／永久刪除／存檔流程（每一步都寫各模組自己的日誌，日誌樣板要寫在呼叫處）、`RoleApi`（伺服器沒有檢查、啟用、匯出端點，繼承會多出呼叫不存在端點的方法）、`PeriodicRefresh` 取代備份頁輪詢（它會一直輪詢、切回分頁也更新）、對話窗尺寸改成群組選擇器（移動規則會越過窄螢幕的 `@media` 規則）、`#blazor-error-ui` 三份（主版面那份多兩條規則）、鈴鐺與首頁通知小工具、毫秒格式（三種格式不同）、下載連結 JS（一個是全域腳本、一個是模組）、驗證碼區塊（搬進元件會改變 scoped CSS 的範圍）。
