## 二、設計決定

| 決定 | 理由 |
|---|---|
| 權限過濾在登記資料上做，只建立看得到的元件 | 「全部建立、元件裡自己判斷」會讓沒權限的小工具也查資料 |
| 每個小工具各自的錯誤邊界 | 一個小工具壞掉不能拖垮首頁；沿用會寫日誌、附追蹤碼的 `LoggingErrorBoundary` |
| 小工具只用以 `IDbContextFactory` 為基礎的服務或 singleton | 同一個連線的共用 DbContext 會與頁面的登入檢查並行衝突 |
| 「上一次登入」取倒數第二筆成功登入 | 最近一筆通常就是這次登入，顯示它沒有意義；要的是發現不是自己做的登入 |
| 不做使用者自訂排版 | YAGNI（路線圖決定） |
| 權限鍵在登記時給，不在首頁另寫檢查 | `MenuPermissionConsistencyTests` 以檔案裡第一個頁面權限常數呼叫比對選單，連註解也算 |
