# Token 用量頁新增「趨勢圖」頁籤：token 與費用的折線趨勢（0.9.55）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：0.9.55
- 首次實作版本：0.9.55
- 最後核對日期：2026/09/23

## 為什麼

「每日趨勢」頁籤是一天一列的長條清單，看得到每天的數字，卻看不出**走勢**。
使用者要一張折線圖，看指定區間內 token 與費用怎麼變化。

## 做了什麼

- `/token-usage` 新增「**趨勢圖**」頁籤，排第一個並設為預設頁籤；「每日趨勢」維持原樣，排第二。
- 上下兩張折線圖，共用日期軸：上面是費用 NT$，下面是合計 token，各自一個從 0 起算的 Y 軸。
- 滑鼠移到點上顯示期間、NT$（US$）、合計 token、呼叫次數，有未定價時另外註明。
- PDF 報表同步加入折線圖：「下載全部頁籤」與在趨勢圖頁籤「只匯出目前頁籤」都會輸出。

## 關鍵決定

| 決定 | 理由 |
|---|---|
| **兩張圖，不做雙 Y 軸** | 錢與 token 單位不同；雙軸圖上兩條線的交叉、誰高誰低都沒有意義，只會誤導 |
| **token 只畫合計** | 逐日資料 `TokenUsageDailyRow` 本來就只有合計；拆輸入／輸出要改 service 與 DTO，線多了也亂 |
| **區間跟著工具列的起訖日與篩選** | 直接用畫面上的 `dailyRows`（已補零、180 天上限），不多查一次資料庫，與每日趨勢頁籤必然一致 |
| **≤92 天按日、93～180 天按週（週一起算）** | 180 個點擠在一張圖上難讀；頭尾不滿一週的桶子也畫一點，提示寫出實際起訖日 |
| **行內 SVG，不加圖表函式庫、不加 JS** | 守住 PRD §3.3 的原則；提示用 SVG 原生 `<title>`，不必在 Blazor Server 上處理滑鼠移動事件 |

## 實作重點

- 新增 `MyProject.Web/Ai/TokenUsageTrendChart.cs`：分桶（`Bucket`）、Y 軸（`Axis`，1／2／5×10ⁿ 間距）、
  X 軸標籤間隔（`LabelStep`）、座標換算與 `polyline` 字串。**畫面 SVG 與 PDF 共用這一份**。
- ⚠️ 座標字串一律 `InvariantCulture`：以逗號為小數點的地區，`points="12,5 30,7"` 會解析失敗，
  整條線靜默消失 —— 與 `BarWidth` 是同一個雷，有測試守住。
- ⚠️ SVG 的 `<text>` 直接寫在 Razor 的 `@foreach` 裡會被當成 Razor `<text>` 指令標籤（RZ1023），
  必須外包一層 `<g>`。
- ⚠️ PDF：MigraDoc 沒有圖表。先用 PDFsharp `XGraphics` 把圖畫進一份單頁 PDF，再以 `base64:` 圖片來源嵌回，
  內容是向量、不落地暫存檔。圖放不下時整張換頁，標題與說明以 `KeepWithNext` 跟著圖走。
- `TokenUsageReportScope` 新增 `Trend`（位於 `All` 與 `Daily` 之間，順序與頁籤一致）。
  單頁籤匯出的檔名頁籤代碼為 `trend`。
- 色彩只用 `var(--app-accent)`／`var(--app-accent-dim)`／`var(--app-line)`／`var(--app-muted)`，
  沒有任何 hex，`ThemeConventionTests` 通過。
- `Directory.Packages.props` 與 `App.razor` 都沒動；service、DTO、資料庫都沒動。
