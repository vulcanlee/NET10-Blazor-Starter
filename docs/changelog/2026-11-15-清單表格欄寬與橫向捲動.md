# 清單表格欄寬與橫向捲動（0.10.25）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：0.10.25
- 首次實作版本：0.10.25
- 最後核對日期：2026/11/15

## 目的

0.10.24 用複刻出來的 `Acme.Erp` 做看得到的 Chrome 巡檢時，在 1440 寬、側邊欄展開的畫面看到兩個版面問題，使用者 2026/11/15 決定修正：

- **專案清單**：欄位被擠成一個字一行，描述、負責人、分類都變成直排；「完成百分比」這類標題也折成好幾行。整頁出現橫向捲軸，「更新時間」被右側固定的「操作」欄蓋住。
- **資料保留與清理**：「下次會清掉」只露出一個字元，「自動清理」整欄被固定的「操作」欄蓋住，畫面上看不出右邊還有內容。

逐頁檢查時，另外發現四頁有同類問題：

- **使用者管理**：同樣被擠窄，整頁也有橫向捲軸。
- **AI 對話紀錄**：操作欄的按鈕被切掉一半，看不出右邊還有內容。
- **系統健康監控**：檢查卡片裡的長路徑撐出整頁橫向捲軸。
- **系統參數**：AI 模型那一組的「參數」欄被擠到 50px，一兩個字一行；同一組的設定鍵還把整張表撐得比畫面寬。

使用者選的是「三頁一起修（專案清單、資料保留、使用者管理），並在 1440 寬下逐頁檢查所有清單頁」，所以逐頁檢查找到的另外三頁也一起修。放不下時採**表格內橫向捲動**；放不下時採**表格內橫向捲動**。具體做法：

- 短欄不折行；
- 長文字用「…」截斷，滑過看全文；
- 操作欄固定在右側，並有陰影提示右邊還有內容；
- 整頁不出現橫向捲軸。

## 原因

1. **外層容器沒有 `overflow-x: auto`**：`project-view-`、`my-user-`、`category-view-`、`team-view-`、`role-view-table-wrap` 這五個類別沒有任何 CSS。其他 14 個清單頁都有這條規則，少了它，表格會把卡片和整頁一起撐寬。
2. **欄位沒設 `Width`**：AntDesign 以自動版面把所有欄壓進容器寬度，而中文可以在任何字之間斷行，於是變成一字一行。
3. **全站沒有任何 `Table` 設 `ScrollX`**：捲動發生在外層 div，AntDesign 不知道表格在捲，固定的操作欄就不會出現 `ant-table-ping-right` 陰影。
4. **系統健康監控**：路徑中間沒有空白可以斷行，而格線裡的格子預設不會比內容窄（`min-width: auto`）。
5. **系統參數**：「參數」與「說明」欄都沒有寬度。AI 那組的說明很長，「參數」欄就被擠窄，裡面的設定鍵又設了 `word-break: break-all`，所以會被壓到很窄；`AiSettings:AgentReasoningEffort` 這類沒有空白的字串則把「目前值」「設定檔的值」撐寬。

## 變更內容

- 五個沒有 CSS 的 wrap 改用共用的 `.view-table-wrap`（theme.css，CRUD 產生器樣板本來就用它）。分類、團隊、角色欄位少，只換 class，欄位不動。
- **專案清單**（`ProjectViewView.razor`）：
  - 每欄設 `Width`，日期時間欄 210，勾選欄 50；
  - 標題、描述、負責人、分類、團隊、刪除者加 `Ellipsis`；
  - 操作欄 200；
  - `ScrollX="2240"`。
- **使用者管理**（`MyUserView.razor`）：
  - 每欄設 `Width`，帳號、名稱、Email、角色、刪除者加 `Ellipsis`；
  - 操作欄 360，並用 `<Space Wrap>`：被鎖定的使用者有 6 顆按鈕，會折成兩列；
  - `ScrollX="1730"`。
- **資料保留與清理**（`DataRetentionView.razor`）：
  - 原本就有欄寬，加上 `ScrollX="1280"`；
  - 操作欄由 130 改 180，實際的 3 顆按鈕放得下。
- **AI 對話紀錄**（`AiCallLogView.razor`）：
  - 補上勾選欄 50、關聯說明 200、操作欄 150 的寬度；
  - `ScrollX="1290"`。
- **系統參數**（`SystemParameterView.razor`／`.razor.css`）：這頁的說明要整段讀，所以不捲動。
  - 「參數」設 220、「操作」設 150，加上原本的「目前值」200、「設定檔的值」160，「說明」吃剩下的寬度；
  - 儲存格設 `overflow-wrap: anywhere`；
  - 各組是各自的表格，設寬後 8 組欄位都對齊（1440 寬時都是 220／200／160／296／150）。
- **系統健康監控**（`SystemHealthView.razor.css`）：
  - `.health-item { min-width: 0 }`；
  - 內文與 `.health-failure` 設 `overflow-wrap: anywhere`。

實測得到的三個注意事項，已寫進註解、規範與速查表：

- ⚠️ **`ScrollX` 不要用 `max-content`**：設了 `Ellipsis` 的欄會被撐成整段文字那麼寬，標題和描述就不會截斷。
- ⚠️ **勾選欄一定要設寬度**：`ScrollX` 等於欄寬加總時，沒寬度的勾選欄會被擠到 0，整欄消失。
- 已刪除模式多出「刪除時間」「刪除者」兩欄時，欄寬加總會超過 `ScrollX`，表格自動變寬（實測專案 2,520px、使用者 2,010px），不用另外處理。

## 測試

- 新增 `TableLayoutConventionTests`，共 5 個測試：
  - `EveryTableWrap_ShouldScrollHorizontally_InsteadOfWideningThePage`：每個 `*-table-wrap` 都必須是 `.view-table-wrap`，或在同一個元件的 `.razor.css` 有 `overflow-x: auto`。
  - `WideTables_ShouldGiveEveryColumnAWidth_AndScrollXShouldBeTheirSum`：上述四張表每一欄（含勾選欄）都有 `Width`，而且 `ScrollX` 等於平常會出現的欄寬加總（不含已刪除模式的欄）。故意改回錯的值 1190 時，測試會指出加總應為 1290。
  - 修正前先跑一次，4 個失敗，列出 5 個 wrap 和每一欄沒寬度的欄位名稱。
- 測試數 3,230 → 3,235。
- `scripts/e2e/explore-edge.mjs` 新增 **E6**：在 1440×900、側邊欄展開的條件下開所有登入後路由，檢查以下幾點：
  - 整頁沒有橫向捲軸；
  - 有表格的頁面表頭每格一行；
  - 4 個字以上的儲存格沒有被擠窄（排成 3 行以上、平均每行不到 4 個字）；
  - 表格放不下而右側有固定欄時，有 `ant-table-ping-right` 陰影；
  - 專案與使用者的資料列不超過 80px。
  - 用還是舊版面的 `Acme.Erp` 跑一次，結果是 FAIL：
    - 專案清單：整頁多出 59px，7 個表頭折行，描述與分類被擠窄，列高 319px；
    - 使用者管理：「管理員」表頭折行；
    - 資料保留：操作欄沒有陰影；
    - 系統健康監控：整頁多出 86px；
    - 系統參數：AI 模型那組的參數欄被擠窄。
  - 修正後跑同一段，PASS。
  - CSP 訊息「Executing inline event handler」只在 `/token-usage` 排除（同 E4），其他頁面照常算問題。

## 獨立審查

審查發現以下問題，都已修正：

- **錯誤**：AI 對話紀錄的 `ScrollX` 寫成 1190，實際的欄寬加總是 1290。畫面不會壞，但不符合「ScrollX＝欄寬加總」的規則。已改為 1290，守門測試也改成比對數值。
- 守門測試的正規式會被屬性裡的 `=>` 提早截斷，也抓不到一個 class 裡有多個類別的寫法。已改成跳過引號內的屬性值，`class` 屬性裡任何一個 `*-table-wrap` 都算，也接受 `overflow: auto`。
- E6 原本在所有頁面都排除 CSP 訊息，現在改成只在 `/token-usage` 排除。
- 「被擠窄」原本只抓得到每行 1～2 個字，現在每行 3 個字也算；判斷是否同一行改成依序比對上緣，相差超過 4px 才算新的一行。
- 門檻改嚴之後，E6 抓到系統參數頁的問題，已一併修正。

## 未處理的觀察

- **手機寬度的工具列**：`.project-view-toolbar` 與使用者管理的工具列不會折行。390 寬、沒有模擬手機時，專案清單整頁多出 343px，使用者管理多出 7px。E4 以 `isMobile` 模擬手機時沒有報出來。這是工具列的問題，不是表格，本次沒有改。
- **看得到的 Chrome 有 1px 細縫**：版面落在小數像素（例如右緣 1383.33px）時，固定欄與表格捲動區邊緣之間有千分之一像素的差距。Chrome 會在剛好有文字經過的列畫出一條 1px 的細縫，無頭模式看不到。這是 Chrome 的合成細節，欄寬本身正確，沒有用 CSS 硬補。
