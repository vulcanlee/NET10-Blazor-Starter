- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：0.9.158
- 首次實作版本：0.9.158
- 最後核對日期：2026/11/06

## 目的

里程碑 1～2（0.9.155～0.9.157）只能查詢。這一版讓助理**經管理員核准後實際修改系統**，達成成功標準 ③（動手做事安全可靠）：每一次修改都先跳核准窗，核准窗寫清楚要做什麼、影響與對象；做完的結果與稽核和手動操作相同。
這一版只做**可以復原**的動作；不可復原的（徹底刪除、清空紀錄、重設 2FA、刪除公告或備份、縮短保留天數、立即執行清理類排程）留到里程碑 4。需求見 [系統管理助理 PRD](../prd/系統管理助理-prd.md)，使用說明、截圖與測試報告見[使用手冊](../features/系統管理助理.md)。

## 一、開工前的實測

修改工具打算只在分派到該領域時載入，同一段對話的工具組會逐輪不同。先用 User Secrets 的金鑰實打 Azure（`gpt-6.1-sol`，Responses API、`store=false`）：第 1 輪給工具 A、B 並讓模型呼叫 B，第 2 輪同一個 session 只給 A。**上游接受**，所以維持「唯讀工具每輪都給、修改工具按領域給」；巡檢與沒分出領域時不給任何修改工具。

## 二、22 個異動工具（每一個都要核准）

| 領域 | 工具 | 保護 | 稽核 |

- `list_announcements` 加輸出公告編號（修改公告時用）。
- 共用規則 `AdminAssistantMutation`：`ValidateBatch`（去空白、去重、最多 50）、`CheckAdminsRemain`（整批做完後至少一位 `IsAdmin && Status`）、`BatchResult`（逐筆成敗）。
- 改使用者一律走頁面「修改」的流程：讀最新資料（含版本戳記）→ 帶回額外角色與團隊 → 密碼留空 → `BeforeUpdateCheckAsync` → `UpdateAsync`。
- 修改用的時間參數改用嚴格的 `AdminAssistantToolText.ParseTime`：看不懂就拒絕，不像查詢那樣改用預設。

## 三、核准窗與執行器

- `AiToolDefinition.ApprovalNote`：核准窗上給人看的影響與限制，例如「只在執行期有效…排查完請記得調回來」。
- `AiToolApprovalRequest` 加 `Note` 與 `Label`（提出的專家），核准窗顯示「由 某某 提出」。
- 陣列參數列成「共 N 筆」加逐行（最多 50 行），單一值上限從 2000 字放寬到 8000 字（容得下整份提示詞）；參數區超過 240px 可捲動。
- 需要核准的工具不會留下工具活動紀錄，所以把 `Label` 存進 `AiAgentPendingApprovalRecord`（只加不改，`SchemaVersion` 不變），接續時優先用它還原「由誰回答」——順便修掉里程碑 2 留下的「接續時還原成上一輪標籤」。

## 四、提示詞與說明

- 共同說明加修改規則：只在使用者明確要求修改時才呼叫修改工具（巡檢或查詢發現問題只建議）、先確認對象、一次最多 50 筆、被拒絕不換方式再試、照逐筆結果回報、不可復原的動作指向頁面。
- 四個專家說明各加上可以代為修改的項目。
- 頁面操作說明（`admin-assistant.md`）：核准窗現在會出現（欄位說明）、可代為修改的清單、「它不做什麼」、新的訊息、兩個操作範例與常見問題。

## 六、獨立審查

合併前由未參與實作的審查者讀過整份變更，沒有嚴重問題，有 4 項需要修；另外有幾項小問題依實際影響調高處理。以下都已修正，並附有先失敗、修正後通過的測試：

| 問題 | 修正 |
|---|---|
| 核准窗把參數截在 6000 字，但提示詞最多 8000 字：模型可以把內容藏在截斷處之後，管理員看不到完整內容就核准了 | 上限改為 8000；`save_prompt_version` 自己拒絕超過 8000 字（含前後空白）的內容，核准的就是會存的內容 |
| 可以啟用清理類排程，下一個時段就會永久刪除資料（違反「只做可復原」） | `set_scheduled_job_enabled` 對 `PurgeJobNames` 只允許停用；加測試確認除了系統備份與密碼到期提醒，其他排程都在清單內，新增排程時必須決定歸屬 |
| `set_user_roles` 改自己的角色會換掉工作階段版本，等於把自己強制登出（頁面存檔後會換發 Cookie，工具沒有） | 對自己直接拒絕，請到使用者管理頁自己改 |
| 角色只有頁面鍵（＝全部動作）時，移除單一動作被當成「本來就沒有」，模型可能回報錯誤的安全結論；已有頁面鍵時加入單一動作卻寫了一次沒有變更的稽核 | 移除時把頁面鍵展開成其餘動作；加入時算「已涵蓋」，不修改、不寫稽核 |
| 帳號區分大小寫（Bob 與 bob 可以並存），忽略大小寫比對可能改到別人，核准窗看不出來 | 忽略大小寫只在剛好一筆時採用，多筆時當成找不到並請模型給完全正確的帳號 |
| 公告結束時間只給日期時當成 00:00，會提早一天結束 | 結束時間只給日期時視為當天 23:59:59 |
| 兩個工具檔被腳本加上了 BOM，和同資料夾其他檔案不一致 | 移除 |

另補上「停用最後一位啟用中的管理員被擋」的測試。

**留到里程碑 4 的小問題**：
- 儲存提示詞以存檔當下的作用中版本做衝突檢查，別人在中間另存的一版會被取代（舊版仍在歷史，可以切回）；可改成讓模型傳入讀到的版本號。
- 縮短保留天數的判斷在目前值無法解析時放行（與頁面共用；目前的保留類參數都有值）。
- 還原帳號與角色用關鍵字搜尋已刪除清單的前 50 筆，名稱很短時正確的那筆可能不在其中。
- 刪除角色沒有像帳號那樣處理大小寫不同的重複名稱（第二筆回報失敗，只影響顯示）。
- 尚未用測試涵蓋：改角色或管理員身分時保留 Email、必須改密碼、鎖定狀態。
- 里程碑 2 留下、這一版沒處理的：健康報告證據含伺服器路徑、`Audit.View` 的 detail 沒有 `action=`、沒有內容檔的稽核回「編號不存在」、帳號工具每次重算最後登入、備份清單讀全部 manifest、「未開 2FA 的管理員」含停用與 Google 帳號。
