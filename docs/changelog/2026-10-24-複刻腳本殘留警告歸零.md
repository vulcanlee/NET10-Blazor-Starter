# 複刻腳本殘留警告歸零（0.9.138）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：0.9.138
- 首次實作版本：0.9.138
- 最後核對日期：2026/10/24

## 目的

使用者跑 `scripts/New-StarterProject.ps1` 後，看到結尾的 `Scaffold completed, but safety checks found values that still need review:` 和五條 `警告:`，問這是不是正常現象。
這五條在《[腳手架開發指引](../guides/腳手架開發指引.md)》§2.4 已經寫成「全部都不用處理」，所以確實是正常的。
但是每次複刻都會跳出一份「不用處理」的警告清單，使用者沒辦法分辨它和真正沒換到的東西，所以改成正常複刻時一條警告都不印。

## 一、五條命中的來源

五條都是開發用 JWT 佔位金鑰 `DevelopmentOnly-ChangeThisJwtSigningKey-AtLeast32Chars`。舊代號、UserSecretsId、連接埠都沒有命中。

| # | 位置 | 為什麼會命中 |
|---|---|---|
| 1–2 | 上手指南 §5.1 的 JSON 範例、§5.5 的欄位表 | 金鑰只在 `appsettings.json` 取代，文件仍然寫舊值，跟新專案實際出貨的 `<新代號>-ChangeThis…` 對不上 |
| 3–4 | `scripts/New-StarterProject.ps1` 的取代規則與掃描樣式 | 腳本掃到自己 |
| 5 | `ApiIntegrationTests.cs` 的 `ProductionSafetyValidation_WithDevelopmentDefaults_ShouldFailFast` | 金鑰只在 `appsettings.json` 取代 |

§2.4 原本說第 5 條「改了測試會紅」，這在 0.9.48 之後就不成立了。`JwtSettings.IsPlaceholderSigningKey` 比對的是 `ChangeThisJwtSigningKey` 這段標記，同一支測試檔第 650 行本來就在用 `Acme-ChangeThis…`。

## 二、腳本修正

| 項目 | 修正前 | 修正後 |
|---|---|---|
| 金鑰取代範圍 | 只取代 `appsettings.json` | 所有文字檔都取代，只跳過腳本自己。文件範例、整合測試資料跟 `appsettings.json` 一致 |
| 殘留掃描範圍 | 包含腳本自己 | 跳過腳本自己（`$scriptCopyPath`）。腳本的取代規則必須保留字面值，衍生專案日後才能再往下衍生 |

跑完的結果：正常複刻不會印出殘留警告。出現警告就代表真的有東西沒換到，例如新加了一種副檔名，卻沒有列進 `$textExtensions`。

## 四、驗證

- 從修改後的腳手架複刻 `CustomerHelpAgent` 到暫存目錄：沒有殘留警告；衍生專案的 `appsettings.json`、上手指南 §5.1／§5.5、`ApiIntegrationTests.cs` 第 623 行都是 `CustomerHelpAgent-ChangeThisJwtSigningKey-AtLeast32Chars`，複製過去的腳本仍保留 `DevelopmentOnly-…` 字面值。
- 衍生專案與腳手架本身都跑 `pwsh ./scripts/Invoke-QualityGate.ps1`。
