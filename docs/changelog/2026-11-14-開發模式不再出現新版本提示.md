# 開發模式不再出現新版本提示（0.10.20）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：0.10.20
- 首次實作版本：0.10.20
- 最後核對日期：2026/11/14

## 目的

使用者在 Visual Studio 以偵錯模式（Development）執行，登入後首頁底部出現「有新版本，按這裡重新整理」，以為是自動更新沒做完，容易混淆。

## 原因

- 0.10.11（WASM 遷移 M12）時假設開發用的 `wwwroot/service-worker.js` 內容固定，所以開發模式不會出現新版本提示列。
- 實際上 Debug 建置時，SDK 會改送 `obj/Debug/net11.0/service-worker/service-worker.js.build`，並在第一行加上 `/* Manifest version: … */`。這個版本碼由所有前端檔案算出，**程式一改、重新建置就變**。
- 瀏覽器發現 Service Worker 內容變了，就裝上新的一份並停在等待，`js/pwa.js` 於是顯示提示列。結果開發時每次改程式重新執行都會出現。
- 實機腳本 `m12-pwa.mjs` 用發佈版、每次都是全新的瀏覽器，所以沒測到這個情況。

提示列在正式環境的設計不變：部署新版後新版下載好就停住，**等使用者按了才換**，因為使用者可能正在編輯，自動重新載入會讓沒存的資料不見。

## 使用者決定（2026/11/14）

- 開發模式完全不出現提示列。
- 正式環境維持手動按，文字改清楚。

## 變更內容

### 1. 開發模式不顯示提示列

- 開發用的 `service-worker.js` 收到 `{ type: 'GET_KIND' }` 時回答 `'development'`，表明身分。
- `js/pwa.js` 顯示提示列之前先問 worker 的身分（`handleNewWorker` → `isDevelopmentWorker`，以 `MessageChannel` 詢問，1 秒沒回應當成發佈版）：
  - 開發版：等待中的直接送 `SKIP_WAITING` 讓它接手，不顯示提示列。開發版不快取、不攔截任何請求，換上它不會改變畫面。
  - 發佈版：照舊顯示提示列。
- 三個入口都經 `handleNewWorker`：開頁時已有等待中的新版、新版剛裝好、別的分頁換上新版（`controllerchange`）。
- 發佈版 `service-worker.published.js` 的程式不變（只改註解），不回答 `GET_KIND`。

### 2. 正式環境的提示文字

| 以前 | 0.10.20 起 |
|---|---|
| 整列是一個按鈕「有新版本，按這裡重新整理」＋「稍後」 | 說明文字「系統已更新到新版本。請先儲存編輯中的資料，再按「立即更新」。」＋實心按鈕「立即更新」＋「稍後」 |

窄螢幕時按鈕換到下一行。行為不變：按「立即更新」才換成新版並重新載入一次，「稍後」先收起（下次開頁還會出現）。

## 測試

- `PwaStatusBarTests`：驗證新的說明文字、「立即更新」與「稍後」。
- `PwaConventionTests` 新增兩項：
  - `DevelopmentServiceWorker_ShouldIdentifyItself`：開發版回答 `development`，發佈版不回答。
  - `Pwa_ShouldOnlyShowTheUpdateBarForThePublishedServiceWorker`：三個入口都先問身分。
- 實機：以開發模式啟動、開首頁，加一個暫時的前端檔案、重新建置並重啟主機後重新整理。
  - 修正前：出現提示列，且有等待中的 worker。
  - 修正後：不出現提示列，新的開發版已經接手。
- `m12-pwa.mjs`（發佈版、雙站台）重跑，W5 部署新版照樣出現提示列，「稍後」與「立即更新」都正常。
