- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：0.9.152
- 首次實作版本：0.9.152

## 問題

`pwsh ./scripts/Test-CrudGenerator.ps1` 跑不過，`New-CrudModule.ps1` 在產生第一個模組時就停下：

```
找不到登記位置：已刪除資料清理（服務）（MyProject.Business/Services/DataAccess/SoftDeletePurgeService.cs）。樣板或錨點需要更新。
```

## 原因

0.9.133～0.9.134（資料保留與清理、自訂清除）改寫了 `SoftDeletePurgeService`。原本的逐行 `await PurgeTypeAsync<Category>(…);` 拆成三處：

1. 清除順序清單 `EntityTypes`：`PurgeExpiredAsync` 依它逐一清除。
2. `PurgeOneTypeAsync` 的 switch：只清一種，給資料保留頁的「自訂清除」用。
3. `GetRetentionStatsAsync` 的統計表：給資料保留頁用。

`New-CrudModule.ps1` 還在找舊的寫法，所以找不到登記位置。`Test-CrudGenerator.ps1` 不在品質關卡裡（太慢），這個問題就一直沒被發現。

同一批改動也新增了「資料保留與清理」頁（`DataRetentionOverviewService`），每種軟刪除資料各一列，產生器也沒有登記這一頁。
只補服務的話，新模組會被排程清除，但不會出現在資料保留頁。而且 `SoftDeletePurgeAuditAction` 的預設分支是 `AuditActions.Role.Purge`，手動補登時很容易把稽核記錯。

## 修正（只改 `scripts/New-CrudModule.ps1`）

- **已刪除資料清理（服務）**：三處都登記，接在 Category 後面。三處仍在同一個 `Update-Source` 裡完成，marker 照舊是 `PurgeTypeAsync<Name>(`。
- **資料保留與清理（已刪除資料）**：新增登記。`DataRetentionOverviewService` 的三處都要補：
  - 列的清單加一列：key 為 `deleted-<路由>`，名稱為「已刪除的<項目>」，「前往」連到一般清單。產生的頁面不接 `?deleted=1`。
  - 列 key 對應實體的 `SoftDeleteEntityOf`。
  - 自訂清除的稽核 `SoftDeletePurgeAuditAction`，對應到 `<Name>.Purge`。
- **資料保留與清理測試**：新增登記。在 `DataRetentionOverviewServiceTests.Overview_ShouldListEveryKindOfData_WithItsJob` 的完整列 key 清單裡補上新的 key。
- **新 helper `Insert-AfterRequired`**：同一個檔案要登記好幾處時，任一處找不到錨點就停。原本的 `Insert-After` 找不到錨點時會原樣回傳，「只改了一部分」的情況 `Update-Source` 抓不到。

正式程式碼沒有變更。
