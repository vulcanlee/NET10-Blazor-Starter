# LLM API 呼叫費用計算（USD／TWD）（0.9.17）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：0.9.17
- 首次實作版本：0.9.17
- 最後核對日期：2026/09/17

## 起因

使用者的原話：

> 我想要看到每次呼叫 LLM API 的時候，除了 Token 用量之外，還可以看到這次 API 呼叫所造成的
> 花費是多少……除了美金之外，我想看到台幣的費用是多少，對於 API 呼叫的計算單價，可以設定在
> appsettings.json 內來指定或者修改，對於 Token 用量網頁上，我也想要看到過濾出來的 API 呼叫，
> 總共花費多少錢？

並附上 OpenAI 的模型／定價頁網址。

0.9.14 把用量記錄做完整時就預留了 `TokenUsageLog.EstimatedCost` 欄位，當時的註解也寫明了
正確作法：「真要實作時還需要把當下的單價一併存下來（單價會隨時間變動，否則金額無法重現）」。
這次就是把那個坑填起來。

## 五個關鍵決定

**一、費用在記錄當下算好並存進資料列，連同單價與匯率快照。**
不是查詢時即時換算。這樣日後調整 `appsettings.json` 的單價或匯率，**不會改變已經記錄的帳**；
也讓「篩選範圍的總花費」變成一次 SQL `SUM`，不必把資料撈進記憶體算。

**二、費用欄位用 `double`（SQLite `REAL`），不用 `decimal`。**
本功能的核心是在 SQL 端彙總，而 SQLite 把 `decimal` 存成 `TEXT`，無法可靠 `SUM`
（原本預留的 `EstimatedCost` 正是 `decimal?`，已一併移除）。單筆金額量級在 1e-6，
`double` 有 15–16 位有效數字，百萬列相對誤差仍在 1e-10 以下。
**帳目可重現性不靠儲存的金額，而靠單價快照加 token 數** —— 兩者都存了，隨時能重算驗證。

**三、圖片 token 定義為 `InputCount`／`OutputCount` 的子集，不是額外加項。**
供應商把圖片 token 算在 `prompt_tokens` 裡面。目前沒有寫入端，怎麼定都「對」；但第一個
從 `prompt_tokens_details.image_tokens` 填值的人一定會照抄供應商語意 —— 若當初定成加項，
那一刻起每筆圖片呼叫都會**重複計費**，而且費用已經是寫死的快照，回頭沒得修。
定成子集則沿用既有的 `CachedInputCount`／`ReasoningCount` 慣例，且在今天（全 null）
退化成與純文字計費完全相同。

**四、前綴比對限定日期／版本後綴。**
模型比對是「完全比對 → 前綴比對 → 未定價」。但純前綴比對會讓 `gpt-4o-mini` 命中 `gpt-4o`
（價差約 30 倍）、`gpt-4.1` 命中 `gpt-4`（價差約 15 倍），而且**完全靜默**，錯誤金額還會被
寫成永久快照。所以規則收緊為：剩餘後綴必須符合 `^-\d[\d-]*$`。

| 模型名稱 | 結果 |
|---|---|
| `gpt-4o-2024-08-06` | ✔ 套用 `gpt-4o` |
| `gpt-3.5-turbo-0125` | ✔ 套用 `gpt-3.5-turbo` |
| `gpt-4o-mini` | ✘ 未定價 |
| `gpt-4.1` | ✘ 未定價（不會套用 `gpt-4`） |

**寧可看得到「沒算到」，也不要默默算錯。** 要計價就補一筆設定，一行的事。

**五、算不出來回 `null`（未定價），不是回 0。**
「找不到費率」與「有費率但這次用量是 0」在畫面上意義完全不同；記成 0 會讓漏帳看起來像免費。
合計橫幅另外顯示「其中 N 筆未定價未計入」。

## 變更內容

### 新增（5 個檔案）

| 層 | 檔案 |
|---|---|
| Models | `Systems/AiPricingSettings.cs`（設定 POCO 與 `AiUsageCost`） |
| Business | `Services/Other/IAiUsageCostCalculator.cs`、`AiUsageCostCalculator.cs` |
| Tests | `AiUsageCostCalculatorTests.cs`、`AiPricingSettingsTests.cs`、`StaticOptionsMonitor.cs` |

設定 POCO 放在 `MyProject.Models` 而非 `MyProject.Web/Configuration`（`AiSettings` 所在處），
因為計算發生在 Business 層，而 Business 不相依 Web —— 理由與 `SystemSettings` 相同。

### 資料表

`TokenUsageLog` 移除 `EstimatedCost`（`decimal?`，預留但無寫入端、全為 NULL），新增十欄：

- 用量：`ImageInputCount`、`ImageCachedInputCount`、`ImageOutputCount`、`CharacterCount`
- 費用：`CostUsd`、`CostTwd`、`CostExchangeRate`、`CostPriceKey`、`CostLongContext`、`CostRateSnapshot`

Migration：`AddTokenUsageCost`。

⚠️ SQLite 的 `DropColumn` 在 EF Core 是整表重建，而 `Program.cs` 每次啟動自動 `Migrate()`。
套用時 EF 會警告 `PRAGMA foreign_keys = 0` **無法在交易內執行** —— 中途被中斷會停在部分套用
的狀態，需手動還原才能重跑。資料量小所以風險窗口極短，但**正式環境套用前務必先備份
`BackendDB.db`**。

EF 自動產生時把 `EstimatedCost` → `CostRateSnapshot` 配成「改名」（兩者都是 TEXT），那是誤判 ——
已手動改成明確的 `DropColumn` ＋ `AddColumn`，讓 migration 讀起來就是它實際做的事。

### 設定

`appsettings.json` 新增 `AiPricingSettings` 區段：`UsdToTwd` 固定匯率 ＋ 模型單價表。
範本帶入八個模型，支援四種計費單位（文字 token、圖片 token、每分鐘、每字元）
與長脈絡分級費率。完整鍵表見
[日誌與設定檔說明 §4.9](../operations/日誌與設定檔說明.md)。

### 接線

計算器接在 `TokenUsageLogService.RecordAsync` 內部，**呼叫端一行都沒改** ——
`AiLogAnalysisService` 的五個記錄分支自動跟著有費用，日後新增的呼叫點也是。

⚠️ 計算器的呼叫另包一層 `try/catch`。外層那個雖然也會吞例外，但它會在 `AddAsync` 之前就中止 ——
計算器有 bug 會讓每一列用量都靜默消失，那比丟掉費用嚴重得多。**用量比費用重要。**

### 頁面

- 合計橫幅：加總花費（台幣＋美金），有未定價時追加橘色提示。
- 明細表：加一欄「費用」顯示台幣、可排序；Tooltip 帶美金原價、當時匯率與費率來源，
  費率若來自前綴比對會標示「（前綴比對）」—— 那是唯一能發現「套錯兄弟模型費率」的地方。
- 四張分組統計表：各加一欄台幣費用（Tooltip 顯示美金）。
- 明細窗：新增「費用」一區，列出金額、匯率、計價依據與**費率快照**，可據以手算驗證。

### 匯出

- CSV：加費用 USD／TWD、匯率、計價依據、長脈絡，以及圖片三欄與字元數。
  ⚠️ 金額一律 `F6`／`F4` ＋ `InvariantCulture`，**不用 `N`** —— `N` 會插千分位逗號，
  Excel 會當成文字匯入，使用者做 SUM 得到 0。未定價輸出空字串而非 `0`。
- PDF：合計段落加總花費，分組表與明細表各加一欄費用（欄寬已重新核算，A4 橫式放得下）。

## 已知取捨

- **圖片 token 數與字元數目前沒有任何寫入端會填。** 系統唯一的 LLM 呼叫點只發 Chat 請求。
  欄位與費率先備齊，等日後接上圖片／TTS／轉錄 API 時就能直接填值。使用者明確要求一次做完。
- **長脈絡門檻 128000 是本系統自訂的估算值。** 供應商定價頁只列「Short context／Long context」
  兩組費率欄，並未公開切換門檻。請依實際帳單校正。
- **不支援 cache-write 費率。** 供應商回傳的 `usage` 沒有 cache-write token 數，硬猜只會算錯。
- **0.9.17 之前的紀錄一律維持「未定價」，不回補。** 當時沒有單價可快照，用今天的價補昨天的帳
  會違反快照的立意。頁面說明已註明。
- **Azure 部署名稱的坑**：`AiSettings.Model` 對 Azure 而言是部署名稱，而呼叫失敗的三個分支
  （HTTP 非 2xx／逾時／傳輸失敗）根本沒有回應 body，模型名稱必然退回部署名稱、一律變成
  「未定價」。這不是 bug，但未定價筆數會比預期高。解法不需改程式 —— 把部署名稱當成
  `Models` 的鍵再加一筆即可。
