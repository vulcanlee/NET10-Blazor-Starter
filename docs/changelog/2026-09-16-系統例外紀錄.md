# 新增「系統例外紀錄」頁面與例外自動記錄管線（0.9.11）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：0.9.11
- 首次實作版本：0.9.11
- 最後核對日期：2026/09/16

## 起因

使用者的原話：

> 記錄系統執行時拋出的例外：是哪個使用者、在哪一頁、按了哪顆按鈕、屬於哪個背景作業時出的錯。
> 使用者回報「系統怪怪的」時，可搭配日誌下載頁一起查。本頁僅管理員可見。
>
> 相同的例外會合併成一列並累加次數 —— 大語言模型主機不可用或逾時，往往在短時間內重複數百次，
> 不合併的話會把少見而更值得注意的例外淹沒。

在此之前，例外唯一的去處是 NLog 檔案（保留 30 天）。`AuditLog` 雖然存在，但刻意只承擔業務稽核軌跡，沒有例外欄位。

完整的設計脈絡與決策理由見
[系統例外紀錄設計規格](../superpowers/specs/2026-09-16-system-exception-log-design.md)。

## 三個關鍵決定

**一、捕捉掛在 `ILogger` 管線，而不是掛「未處理例外」。**
全專案 75 個 `catch (Exception ex)` 多數在服務層記完 `LogError` 後就回傳 `VerifyRecordResult`，
**例外不再往上拋**。只掛 error boundary 或 API filter 會完全收不到它們 —— 而那正是「系統怪怪的」的主要來源。
改用自訂 `ILoggerProvider` 之後，現有 75 處與日後新寫的 catch 全部自動涵蓋，**一行都不用改**。

**二、「按了哪顆按鈕」用既有的日誌訊息樣板。**
專案沒有任何按鈕追蹤機制，要做就得改 40 多個事件處理器。改用
`Failed to create category. Name={CategoryName}` 這種既有訊息當「操作」——
它實質上就是「他按了新增」，且零侵入。

**三、「背景作業」改成「來源」。**
專案當時沒有任何 `IHostedService`，那個欄位會永遠是空的。改成來源（畫面／WebAPI／系統啟動／背景作業），
現在能填前三種，日後真的有背景作業也不用改 schema。

**專案第一個 `IHostedService`**：`ExceptionLogWriter`。寫資料庫不能發生在 `logger.LogError()` 的呼叫執行緒上 ——
AI 主機逾時那種「短時間重複數百次」的情境，同步寫 DB 會直接拖垮正在等待的使用者。
改成有界 Channel（1000，滿載丟棄）＋ 單一消費者，logger 入列即返回，也順帶避開並發 upsert 競爭。

## 實作時踩到的三件事

### 1. 守門測試擋下了「管線內不得注入 ILogger」

`LoggingConventionTests.BehaviourClasses_ShouldHoldALogger` 要求 `Services`／`Diagnostics` 下的類別必須注入
`ILogger`。但本功能有四支類別**刻意不能注入** —— 它們位在記錄管線之內，用 `ILogger` 記自己的失敗會形成
「失敗 → 記錄 → 再失敗」的無限遞迴。已將四支加入該測試的豁免清單並註明理由：
`ExceptionContextAccessor`、`ExceptionLogProvider`、`ExceptionLogWriter`、`ExceptionStackFileStore`。
需要留話時一律走 `NLog.Common.InternalLogger`。**這不是漏加 logger，請勿「順手補上」。**

### 2. 整合測試把堆疊檔寫進了開發者的真實目錄

`ApiTestApplicationFactory` 已經把 `DatabasePath`／`DownloadPath`／`UploadPath`／`ProjectFilePath`
四個路徑導到暫存目錄，但新增的 `ExceptionPath` 漏了。整合測試會啟動**真實 host**，例外記錄管線是活的，
於是堆疊檔寫進 `C:\temp\MyProject\Exception`，資料列卻留在測試自己的資料庫裡 ——
跑完一次 `dotnet test` 就留下 3 個對不到紀錄的孤兒檔。已補上該設定。

> 教訓：日後在 `ExternalFileSystem` 新增任何路徑，都要同步加進 `ApiIntegrationTests.CreateSettings()`。

### 3. 資料列建立失敗時的孤兒檔

原本只在 `catch (DbUpdateException)` 時刪掉剛寫的堆疊檔；其他原因造成資料列沒建起來，
檔案就會留下來變孤兒。已改成攔所有例外一律刪檔。

## 刻意不做

- **不做 Web API controller**（內部管理員診斷頁，YAGNI）
- **不動那 75 個 `catch (Exception ex)` 區塊**（零侵入正是本設計的重點）
- **不對例外訊息遮罩**（本頁與「日誌檢視」同級，皆管理員專屬）
- **不做自動清除**：清除一律由管理員按下（刪單列／清空全部／清除 90 天未再發生）
