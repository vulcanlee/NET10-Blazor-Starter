# 修正使用者選單被表格固定欄遮蔽（0.4.44）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：0.4.44
- 首次實作版本：0.4.44
- 最後核對日期：2026/08/27

## 症狀

右上角使用者選單展開後，「關於」與「登出」看不見。

- 在 `/myusers`：只看得到「變更密碼」「設定 API 密碼」，下半截變成表格的「操作」欄
  與編輯／刪除按鈕。
- 在 `/logs`：四項都在，但中間被一個「TraceId」字樣穿透。

而且**時好時壞** —— 換一個頁面、捲動一下、改變視窗高度，看到的結果都不一樣。

## 根因

**兩個選單項一直都有渲染，是被蓋住的，不是沒畫出來。**

`.top-row` 是 `position: sticky` **加上 `z-index`** 的定位元素，因此它**自己建立了一個
stacking context**。`.user-menu-dropdown` 的 `z-index: 20` 只在這個 context 內部有效；
對整頁而言，整個頂部列（含選單）是以 `.top-row` 自己的值 —— 原本的 **1** —— 參與根層級堆疊。

而 `<ActionColumn Fixed="ColumnFixPlacement.Right" Title="操作">`（`MyUserView`、`RoleViewView`、
`CategoryViewView`、`ProjectViewView`、`TeamViewView` 五處）產生的固定欄儲存格在 `<article>` 裡、
**不在** top-row 的 context 內，AntDesign 給它們 `position: sticky !important; z-index: 2;
background: #fff`，於是以 **2 > 1** 蓋在選單上，還帶著自己的白底。

這正好解釋「上半截看得到、下半截變成表格」：選單上半部疊到工具列（沒有固定欄），
下半部才疊到表格的固定「操作」欄。`/logs` 的「TraceId」是同一回事，只是穿透的是別的欄。

> 一句話：**帶 `z-index` 的定位祖先會把子孫的 `z-index` 關在裡面。**

## 為什麼是「以前有、最近才不見」

兩個成分都不新：`Fixed` 自建立 `MyUserView`（`351f57c`）起就有，`.top-row` 的 `z-index: 1`
自 `da7eb4f Init` 起就有。這是**長期潛伏**的堆疊 bug，不是哪一次改動造成的回歸。

會忽然變明顯，是因為可見與否取決於「選單面板高度 vs 表格在畫面上的位置」：
0.4.24（`2903d25`）新增「關於」讓面板多一項、變高，把「登出」推進表格範圍；
再加上捲動位置與視窗高度不同，同一個畫面有時看得到、有時看不到。

## 修正

只動 `MainLayout.razor.css` 的 `@media (min-width: 641px)` 區塊內兩個數值：

| 選擇器 | 原值 | 新值 | 理由 |
|---|---|---|---|
| `.top-row` | 1 | **20** | 必須高於 AntDesign 表格用到的最大值 4（固定欄 2、sticky 標頭／選取欄 3、容器邊框 4） |
| `.page.sidebar-collapsed .sidebar` | 3 | **30** | 必須高於 `.top-row`，否則收合側邊欄的飛出選單會被剛拉高的頂部列蓋掉 |

修正後的根層級由低到高：表格固定欄／標頭 2–4 → `.top-row` 20 → 側邊欄／飛出選單 30 →
AntDesign Modal／Notification 1000+。

順帶也修好了同一個 bug 的另一個受害者：收合側邊欄的飛出選單先前是 `z-index: 3`，
與表格 sticky 標頭同層，同樣會被穿透。

兩處各加了註解說明數值由來，避免日後有人「順手改小」。

## 取捨與排除的作法

- **不移除 `.top-row` 的 `z-index`**：沒有 `z-index` 就不建立 stacking context，選單確實會浮上來，
  但 sticky 標頭反而會被表格固定欄穿透 —— 只是換一個 bug。
- **不改五個檢視的 `Fixed="ColumnFixPlacement.Right"`**：固定「操作」欄是刻意設計。
- **不改 `.user-menu-dropdown` 自己的 `z-index: 20`**：它在 top-row 的 context 內部本來就正確。
- `.ant-table-resizing` 是 99，本專案沒有任何表格開 `Resizable`（已確認零使用），不構成衝突；
  日後若啟用需重算層級表。

## 已知的既有樣式債（本次未處理）

`.user-menu-item` 的基底色是 `#b91c1c`（紅），讓所有選單項都是紅色；專用的
`.user-menu-item-danger` 定義了卻沒套到任何元素；`.top-row ::deep a` 又把兩個 `<a>`
蓋回深色 —— 於是「變更密碼／關於」是紅字、「設定 API 密碼／登出」是深色，看起來像沒有規則。
與本次遮蔽問題無關，另案處理。

## 驗收

CSS 沒有自動化測試基礎建設（無 bUnit、無視覺回歸工具），以「既有關卡不退步 ＋ 手動實跑」驗收。

- `dotnet build src/MyProject/MyProject.slnx` → 0 錯誤 0 警告
- `dotnet format src/MyProject/MyProject.slnx --verify-no-changes` → 無變更
- `dotnet test src/MyProject/MyProject.slnx` → 全數通過（純 CSS 改動）
- `pwsh scripts/Test-DocsEncoding.ps1` → 全數 BOM、無亂碼
- 手動實跑（**須 Ctrl+F5 強制重新整理**以避開 `MyProject.Web.styles.css` 快取）：
  五個有固定「操作」欄的頁面 ＋ `/logs` 展開選單四項完整；「關於」對話窗正常置頂；
  「登出」正常導向；收合側邊欄的飛出選單仍蓋在頂部列與表格之上；頂部列 sticky 行為不變。
