## 目的

0.9.163 盤點時，有 26 個套件不是最新版。品質關卡也一直允許一筆高風險弱點：GHSA-2m69-gcr7-jv3q／CVE-2025-6965，出在 `SQLitePCLRaw.lib.e_sqlite3` 2.1.11，由 EF Core 遞移帶入，當時上游還沒有修補版。

查證後，EF Core Sqlite 10.0.14 會帶入 `SQLitePCLRaw.*` 2.1.13，不在受影響範圍（`<= 2.1.11`）內。使用者決定把**全部套件升到最新**，包括測試工具的大版本。

## 刻意不升的兩個套件

兩者都是**編譯通過、跑測試才出錯**：

| 套件 | 停在 | 原因 |
|---|---|---|
| `PDFsharp-MigraDoc` | 6.2.4 | 6.5.0 起授權從 MIT 改為 **AGPL-3.0 或商業授權**，程式必須呼叫 `PdfSharpLicense.SetAgplLicense()` 或載入授權碼，否則產生 PDF 時丟 `PdfSharpLicenseException`（34 個 PDF 測試失敗）。AGPL 會要求公開衍生產品的原始碼，是商業決定，所以先不升 |
| `OpenAI` | 2.14.0 | 2.15.0 改了 `ResponsesClient.CreateResponseStreamingAsync` 的簽章。`Microsoft.Extensions.AI.OpenAI` 10.11.0（目前最新）是對著 2.14 編譯的，執行時丟 `MissingMethodException`，所有 Agent 測試都失敗。MAF 1.28 本身也相依 2.14.0 |

原因與升級條件寫在 `Directory.Packages.props` 的註解，以及 [CI-CD 與品質檢查 §4.4](../operations/CI-CD與品質檢查.md)。

## 弱點例外全部移除

- `Directory.Build.props` 拿掉 `NuGetAuditSuppress`（GHSA-2m69-gcr7-jv3q）。
- 品質關卡的 `$allowedAdvisories` 改成空陣列。從這一版起，掃描到任何諮詢都會讓關卡失敗。
- `MyProject.Web.csproj` 拿掉 `System.Security.Cryptography.Pkcs` 的直接參考，`Directory.Packages.props` 也拿掉它的版本。
- 結果：`dotnet list package --vulnerable --include-transitive` 七個專案都沒有任何弱點。
