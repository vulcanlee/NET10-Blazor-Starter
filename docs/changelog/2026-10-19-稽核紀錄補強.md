# 稽核紀錄補強：開頁、查詢、查看單筆與修改差異（0.9.131）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：0.9.131
- 首次實作版本：0.9.131
- 最後核對日期：2026/10/19

## 起因

使用者想在 `/audit-logs` 觀察每個人的行為：開了哪些頁、查了什麼、看了哪一筆、改了什麼，並希望這些資訊也同步記進日誌的 Debug 等級。
原本稽核只記改變狀態的動作與安全事件，修改也只記改後的摘要；換頁雖然有寫進日誌（Information），稽核頁卻看不到。

## 決定（2026/10/19，與使用者逐項確認）

| 項目 | 決定 |
|---|---|
| 觀察入口 | `/audit-logs`；保留天數維持 365 天，不分類型 |
| 開頁 | 已登入的使用者每換一頁記一筆 `Page.View`（目標是路徑、Detail `from=上一頁`）；只改 query string 不算 |
| 查詢 | 五個主要資料頁與管理診斷頁按「搜尋／查詢」才記（翻頁、排序、清除、頁面自動載入不記）；完整條件含搜尋原文寫進內容檔，Detail 只放短摘要 |
| 查看單筆 | 五個主要資料頁按「修改」開窗，管理診斷頁開明細窗；日誌檢視的展開只在瀏覽器端，沒有伺服器事件，不記 |
| 修改差異 | 分類、專案、團隊、使用者、角色（Blazor 與 Web API）以及個人資料改姓名，記「欄位：舊值 → 新值」 |
| 長內容寫檔 | 修改差異與查詢條件寫成檔案（`AuditContentPath`），稽核表只存相對路徑 `ContentFile`，Detail 只留原本的短摘要；明細窗開啟時才讀檔 |
| 同步到日誌 | 每筆稽核記一行 Debug `Audit recorded.`（只有短摘要與檔名）。Debug 預設不寫進檔案，要到「日誌等級設定」調低才看得到 |

採用的預設：開頁只記已登入的人；內容檔與稽核頁只有管理員看得到，所以 Email、姓名照實記舊值→新值；
密碼只記「已變更」，Salt、SecurityStamp、兩步驟密鑰、Google 綁定、鎖定與失敗次數不比對；內容檔不截斷。

## 異動

| 位置 | 改版後 |
|---|---|
| `AuditLogService` | 改注入 `IDbContextFactory`，每筆各用一個 context（換頁稽核射後不理，共用 circuit 的 scoped context 會和頁面初始化撞在一起，且被追蹤的實體只增不減）；`WriteAsync` 加 `content`，先寫檔再存列，存列失敗刪檔；寫入成功記 Debug |
| `AuditContentFileStore`（新增） | 內容檔的唯一入口，`{yyyyMM}/{Guid}.txt`（UTC 月份），拒絕根目錄以外的路徑 |
| `AuditLog.ContentFile` | migration `AddAuditLogContentFile`（加一個可為 null 的欄位） |
| `AuditLogQueryService` | `GetContentAsync`；清除 N 天前、自動清理、清空全部連同內容檔 |
| `AuditDiff`（新增） | 比對純量欄位、排除系統欄位與導覽屬性、`Masked`、`Set`（集合新增／移除），多行內容用區塊呈現 |
| 五個資料服務、`ProfileService`、三個 Repository 與 Controller、CRUD 範本 | 修改時產生差異；Repository 回傳 `UpdateOutcome`（Team 為 `TeamWriteResult.Diff`），Controller 經 `WriteAuditAsync(content:)` 寫入 |
| `AuditActions` | 新增 `Page.View`，以及十組 `*.Search`／九組 `*.View`（共 132 個常數）；CRUD 產生器同步加 `Search`、`View` |
| `ApplicationCircuitHandler` | 換頁寫 `Page.View`；第一頁等第一次連線建立（拿得到 IP）才寫 |
| `ViewAudit` | `WriteAsync` 加 `content`；新增 `WriteSearchAsync` 與 `AuditSearchCondition`（`Text` 為使用者輸入，摘要只記有沒有填） |
| 各頁 | 分類、專案、團隊、使用者、角色、日誌檢視、系統例外紀錄、AI 對話紀錄、Token 用量、稽核紀錄的查詢與查看；`RoleViewView` 補注入稽核服務 |
| `/audit-logs` 明細窗 | 「詳細內容」區塊（開窗後讀檔，框內捲動）；開頁類別為灰色 |
| 設定與備份 | `SystemSettings:ExternalFileSystem:AuditContentPath`（啟動驗證、啟動建目錄、不可與備份目錄重疊）；系統備份打包 `files/AuditContent`；`Restore-Backup.ps1` 加 `-AuditContentPath` |

## 注意

- 稽核筆數會明顯增加（每次換頁、搜尋、開窗各一筆），內容檔也會跟著增加；保留天數仍為 365 天。
- 搜尋原文不進資料庫，所以 `/audit-logs` 的關鍵字篩選找不到它，要打開明細窗看。
- 內容檔可能含 Email、姓名與搜尋原文：目錄權限只給應用程式集區與管理員，絕不可放在 `DownloadPath` 底下。
