## 目的

腳手架原本有三份描述畫面的文件：系統內各頁的操作說明、給開發者的《畫面與欄位字典》、給開發者的《腳手架總覽與複刻上手》。缺的是一份**給使用系統的人看的完整入門手冊**。

使用者要求參考「知識庫」專案（KnowledgeExtraction.AI）的《新手完整操作指南》，替腳手架寫一份使用手冊。複刻出的新系統沿用共通章節，再照同一套格式補上自己的業務章節。

## 使用者的決定（2026/11/07）

| 項目 | 決定 |
|---|---|
| 讀者 | 使用系統的人：一般使用者、管理員、維運人員；不談程式 |
| 給新系統 | 手冊＋獨立的《使用手冊寫作規範》 |
| 深度 | 完整版：每個畫面都有欄位表與按鈕表 |
| 截圖 | 不附，用表格與 Mermaid 流程圖（附純文字版） |
| 同步 | 寫進速查表 §6.14，並加守門測試 |
| 心智模型主軸 | 人 → 權限 → 資料 → AI → 維運 |
| 檔名 | `docs/guides/新手完整操作指南.md`（與知識庫專案同名）、`docs/guides/使用手冊寫作規範.md` |
| 走查章 | 不寫 |

## 內容

- **《新手完整操作指南》**：
  - 開頭依讀者分閱讀路線，接著「三分鐘摘要」：五個痛點，每個寫困擾、影響、設計、成效。
  - 心智模型：五站全貌與鐵律。
  - 全畫面總覽表：路由、選單、讀者、權限。
  - 登入與帳號安全：登入、忘記密碼、兩步驟驗證、變更密碼、個人資料、設定檔導讀。
  - 各畫面章節：基礎設定、業務資料範例、AI 功能、系統管理、監控與維運、首頁與通知。每個畫面都有開頭四行、欄位表、按鈕表、清單怎麼看、常見陷阱。
  - 收尾：資料生命週期與保留期總表、名詞速覽、FAQ、延伸閱讀。
- **《使用手冊寫作規範》**：
  - 章節結構，並標出哪些章共通、哪些要換成業務內容。
  - 每節開頭四行、畫面章節樣板、表格欄位定義、文風、流程圖規則。
  - 同步規則與守門測試。
  - 新系統的改寫步驟、給 AI 的三組提示詞、交付前檢查清單。
- **守門測試** `UserManualCoverageTests`：
  - `Datas/HelpTopics.json` 的每一個路由，手冊都要有標題含 `` `/路由` `` 的章節。
  - 手冊與寫作規範都要存在。
- **同步其他文件**：
  - 速查表 §6.14 規則 2：改頁面時也要同步手冊。
  - 維護規範 §2 的同步對照表。
  - 《腳手架總覽與複刻上手》§5.1、§5.2 文件地圖，以及 §8.2 複刻後待辦：改寫手冊的業務章節。
  - 文件索引：`docs/README.md`、`docs/guides/README.md`、根目錄 `readme.md` 第 9 節。
