# 稽核紀錄顯示來源 IP（0.9.117）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：0.9.117
- 首次實作版本：0.9.117
- 最後核對日期：2026/10/07

## 起因

「稽核紀錄」頁只回答「誰、何時、對什麼、做了什麼、結果」，沒有「從哪裡」。`AuditLog` 沒有 IP 欄位，追查帳號被盜、異常登入時看不出是不是從陌生的網路操作。

## 決定

- 顯示在清單欄位、明細窗與 CSV 匯出（CSV 加在**最後一欄**「來源IP」，不打亂既有依欄位位置讀檔的下游）。
- 併入既有關鍵字搜尋（部分比對，輸入 `192.168.1` 即可），不加獨立篩選框。
- 排程作業與 0.9.117 之前的舊紀錄沒有 IP，一律顯示「—」。
- 正式環境為 IIS in-process 或直接 Kestrel，不經反向代理，`ForwardedHeaders` 不需設定。

## 異動

### 寫入端：IP 集中在 `AuditLogService` 取得

稽核寫入分散在 51 個檔案、144 個呼叫點，因此**呼叫端與 `IAuditLogService` 簽章都不改**，改由 `AuditLogService` 寫入時自己取 IP：

| 檔案 | 異動 |
|---|---|
| `AccessDatas/Models/AuditLog.cs` | 新增 `ClientIp`（nullable） |
| `AccessDatas/Migrations/*_AddAuditLogClientIp.cs` | 只加一個 nullable TEXT 欄位、不加索引（重疊回收安全） |
| `Business/Services/Other/IClientIpProvider.cs`（新增） | `string? GetClientIp()`；Business 不相依 ASP.NET Core，實作放 Web |
| `Business/Services/Other/AuditLogService.cs` | 建構子加選用參數 `IClientIpProvider? clientIpProvider = null`，寫入時填 `ClientIp` |
| `Web/Auth/ClientIpProvider.cs`（新增，scoped） | circuit 寫入的值優先，否則 `HttpContext.Connection.RemoteIpAddress`；IPv4-mapped IPv6 轉回 IPv4 |
| `Web/Components/ApplicationCircuitHandler.cs` | `OnConnectionUpAsync`（第一次連線與斷線重連）把 SignalR 連線的 IP 寫進 `ClientIpProvider`，失敗只記 Warning |
| `Web/Extensions/ServiceCollectionExtensions.cs` | 註冊 `ClientIpProvider` 與 `IClientIpProvider`（同一個 scoped 實例） |

各情境的 IP 來源：

| 情境 | 例子 | IP 從哪來 |
|---|---|---|
| SSR 頁面 | 登入、登出、兩步驟驗證 | `HttpContext` |
| Web API | Controllers、`HasPermissionAttribute` | `HttpContext` |
| Blazor 互動 circuit | 各頁的存檔、匯出、清除 | 連線建立／重連時取得的 IP |
| 排程作業 | 自動清除、系統備份 | 無，存 null |

### 畫面與查詢

- `AuditLogAdapterModel` 加 `ClientIp`（AutoMapper 同名自動對應）。
- `AuditLogQueryService` 關鍵字條件加比對 `ClientIp`。
- `AuditLogView`：清單在「操作者」後加「來源 IP」欄、明細窗加「來源 IP」、關鍵字提示改為「關鍵字（動作／目標／摘要／IP）」、CSV 最後一欄「來源IP」。

### 測試

- `AuditLogServiceTests`：有 provider 時寫入 IP、沒有時為 null。
- `ClientIpProviderTests`（新增 6 項）：IPv4-mapped 轉換、IPv6 保留、null、讀 HttpContext、circuit 值優先、兩者皆無回 null。
- `AuditLogQueryServiceTests`：關鍵字輸入 IP 片段查得到。
- `ExportTests`：稽核 CSV 相容性測試補上「來源IP」欄。
- `LoggingConventionTests`：`ClientIpProvider.cs` 列入豁免（只持有狀態與格式化，無 I/O）。

### 實機驗證（暫時資料庫）

| 動作 | 情境 | 記到的來源 IP |
|---|---|---|
| 登入頁密碼錯誤、登入成功 | SSR | `::1` |
| 稽核紀錄頁「匯出 CSV」 | Blazor circuit | `::1` |
| `POST /api/Auth/login`（以 127.0.0.1 連線） | Web API | `127.0.0.1` |

關鍵字輸入 `127.0` 只查到 API 那一筆；明細窗顯示來源 IP。

## 注意

- 自己用 `IServiceScopeFactory` 開新 scope 再寫稽核，拿不到 circuit 的 IP（會退回 HttpContext，circuit 內通常也沒有）。
- 日後若改放在 Nginx、Cloudflare 等反向代理之後，必須設定 `ForwardedHeaders:KnownProxies`／`KnownNetworks`，否則所有紀錄的來源 IP 都是代理的 IP。
