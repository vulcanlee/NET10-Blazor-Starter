# 系統參數設定：在畫面上修改保留天數、監控門檻與系統名稱，存檔即生效（0.9.98）

- 文件版本：1.0

- 首次實作版本：0.9.98
- 最後核對日期：2026/10/04

## 目的

[路線圖](../planning/00-腳手架強化路線圖.md) B-6。保留天數、監控門檻、系統名稱這類值原本要改 `appsettings.json`（系統名稱還要重啟才生效），
排程頁與說明頁都寫「天數只能改設定檔」。目標：管理員在畫面上修改**非機密、執行期可改**的參數，存檔後不重啟即生效、寫稽核，參數只有一個定義來源。

使用者決定：

- 資料庫**只存覆寫值**，當成一層設定來源**疊在 appsettings 之上**；型別、範圍、說明沿用既有設定類別＋程式內目錄，不另存一份（路線圖原寫的「具型別、預設值、說明的 key/value 表」改為這個做法，避免同一個值兩邊各有一份）。
- 第一批：保留天數、系統名稱與簡介（不含版本號）、監控門檻與頻率，共 23 個鍵；一次做完。
- 登入鎖定次數／時間與密碼長度留給 C-9；頁面只限管理員。

設計經盤點、規劃代理對照程式碼審查，抓到幾個照直覺做會出錯的地方（第二節 ⚠️）。

## 二、設計決定

| 決定 | 理由 |
|---|---|
| 覆寫層是被動的 `ConfigurationProvider`，資料庫初始化之後才載入 | 建立設定時資料庫還沒 migrate；啟動時的 options 驗證只驗設定檔本身 |
| 覆寫層最後加入（優先權最高），**也蓋過環境變數** | 管理員在畫面上改的值要能生效；頁面同時顯示「設定檔的值」，部署文件寫明這個優先順序 |
| ⚠️ 存檔前用真的 options 管線驗證「設定檔的值＋候選覆寫」 | `IOptionsMonitor.CurrentValue` 遇到不合法的設定會丟例外，全站讀它的地方都會壞；DI 裡所有驗證器（含衍生專案加的）都會執行 |
| ⚠️ 不拿既有 provider 建新的 `ConfigurationRoot` 來驗證 | 建構子會呼叫每個 provider 的 `Load()`，JSON provider 會觸發全域 reload |
| ⚠️ 不在目錄的鍵一律不套用 | 安全邊界：資料表裡就算出現 `JwtSettings:SigningKey` 也進不了設定 |
| ⚠️ 已存的覆寫不合法時略過、標「未套用」，不讓啟動失敗 | 升級後範圍變窄不該讓網站起不來；設定檔本身有誤的區段拒絕存檔並明講，已套用的覆寫保留 |
| 內容沒變就不觸發 reload | 每次 reload 會讓所有 options 重新綁定 |
| 每分鐘刷新用 `PeriodicTimer` 背景服務，**不是**排程作業 | 每個行程都要刷新自己的設定，排程作業卻是跨行程只跑一次，也不該每分鐘寫執行紀錄 |
| ⚠️ 系統名稱改經 `ISystemIdentity`，設定被改壞時回傳上一次的值 | 原本的 `IOptions` 是啟動快照；直接改用 `IOptionsMonitor` 的話，執行中把 appsettings 改壞會讓側邊欄每次渲染都丟例外。它不注入 `ILogger`（例外告警在例外管線內使用它） |
| ⚠️ 限流分割鍵含配額 | limiter 依分割鍵快取、工廠只在第一次建立時呼叫：不含配額的話，持續呼叫的用戶端會一直沿用舊配額 |
| 版本號以條件式 UPDATE／DELETE 比對，不實作 `IConcurrencyStamped` | 那一套是給「整筆覆蓋的編輯畫面」用的（還要搭配 `ProtectFlags`），這裡一次只改一個值 |
| 修改窗用小型 `AntDesign.Form`，不用 `EditForm` | 含 `EditForm` 的窗依慣例是 95vw 的大窗 |
| 輸入的值等於設定檔的值時改為還原 | 不留一筆「剛好等於設定檔」的覆寫，之後設定檔改了才會跟著變 |
| 縮短保留天數（含 0 → 正數）先跳危險確認 | 下一次排程會永久刪除資料，無法復原 |

## 三、驗證（2026/10/04 實跑）

**故意改壞 17 處，全部被測試抓到**：套用不在目錄的鍵、載入時不驗證、存檔前不跑驗證器、不檢查設定檔本身、內容沒變也 reload、更新不比對版本號、
新增撞主鍵當成功、限流鍵不含配額、`SystemIdentity` 不回退、存檔後不重新套用、等於設定檔值不改走還原、忘記密碼設定改用 `IOptions` 注入、
縮短判斷漏掉 0 → 正數、允許控制字元、範圍不讀 `[Range]`、驗證器不換回設定檔值、設定檔有誤時丟掉現有覆寫。

第一輪有 3 處沒抓到，各補一個針對性的測試：
- 「載入時不驗證」：原測試用的不合法值會先被格式解析擋掉，沒走到驗證器 → 加一個自訂驗證器拒絕特定值的測試。
- 「驗證器不換回設定檔值」：需要「另一個行程移除一筆、同時修改另一筆」才碰得到 → 加跨欄位規則的測試。
- 「設定檔有誤時丟掉現有覆寫」：補「執行中把設定檔改壞」的測試。

**真實環境**（Playwright 驅動本機 Edge；所有外部路徑與日誌都指向暫存目錄，`C:\temp\MyProject` 與 `C:\temp\Logs` 在驗證期間無任何新檔）：

- 「系統管理 › 系統參數」列出四類、23 個參數。系統名稱留空 → 窗內顯示「不可留空。」且窗維持開啟；改成「驗證用系統」→ 換頁後側邊欄與「關於」都顯示新名稱。
- 稽核保留天數 365 → 30：跳出紅色「縮短保留天數」確認窗；儲存後來源顯示「系統參數」，「稽核紀錄」頁的按鈕變成「清除 30 天前的紀錄」，排程頁的說明改為「保留天數在『系統參數』頁設定」。
- 還原系統名稱 → 回到「企業管理平台」、來源「設定檔」；稽核頁出現 `SystemParameter.Update`／`Reset`，Detail `key=LogRetentionSettings:AuditLogDays; old=365(設定檔); new=30(系統參數)`。
- **兩個行程**（不同連接埠、同一個暫存資料庫）：B 啟動時就套用了 A 存的覆寫；A 改名後 B 在一分鐘內顯示新名稱。
- 非管理員帳號開這一頁 →「你沒有權限存取此頁面」，選單也沒有這一項。
- 兩個行程的日誌除了既有的 `JSDisconnectedException` 雜訊外沒有錯誤。

**品質關卡**：`Invoke-QualityGate.ps1` 完整通過（1346 個測試，含弱點掃描）。
