# 腳手架開發指引新增章節目錄與「權控機制白話導讀」，畫面與欄位字典同步程式現況（0.9.58）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：0.9.58
- 首次實作版本：0.9.58
- 最後核對日期：2026/09/24

## 為什麼

1. `腳手架開發指引.md` 已有三千多行，開頭只有一張「依情境跳章」的表，沒有辦法直接跳到某一節。
2. 原本的權限章節寫給開發者看，技術術語很多。系統管理員、主管、稽核這些不寫程式的讀者，
   需要一份白話版本：為什麼要權控、怎麼操作、遇到人事異動怎麼設定，以及現有設計有哪些問題。
3. `畫面與欄位字典.md` 停在 0.9.55，與程式現況有落差，其中有兩處說法是錯的。

## 做了什麼

### 腳手架開發指引（文件版本 3.4）

- 開頭新增「目錄」，列出所有章與節（兩層），並保留原本的「怎麼用這份文件」情境表。
- 新增 **§6 權控機制白話導讀**，共 12 節：
  - 為什麼需要權控，以及「角色＝能做什麼、團隊＝能看哪些」兩把鑰匙；
  - 權控的好處與可能的問題、什麼時候會用到、哪些人需要知道；
  - 機制坐落在哪裡（選單位置與程式位置對照表），以及設計新畫面時怎麼加入權控；
  - 用一家虛構公司模擬七種情境：新帳號比照 emily 再加上臨時專案小組、臨時小組解散或有人退出、
    調部門、離職、只看不改、請假代理、外部顧問只看特定專案；
  - 現有設計的 11 項問題與缺陷，每一項附建議作法與副作用。
- 原本的 §6 改名為 **§7 權限控管技術細節**，原 §7～§13 順延為 §8～§14。文件內的章節引用與錨點全部跟著修正，
  其他文件對本文件的章節引用也一併修正。
- 順手修正幾處早就錯位的章節引用（例如「§8 講缺什麼」實際上是 §9）。
- 對照程式現況，修正技術章節裡過時的內容：管理員專屬頁是 9 個（原寫 8 個）、
  不上架矩陣的權限鍵是 12 個（原寫 11 個）；「稽核紀錄沒有畫面」已過時（0.9.42 起就有畫面）；
  `AuthenticationStateHelper` 的行號也更新了。

### 畫面與欄位字典（文件版本 1.7）

- **更正兩處錯誤**：
  - 「API 密碼」和網頁登入密碼是**同一個欄位**，不是兩組各自獨立的密碼；
  - API 登入比對的是「帳號」，不是 Email。
- 共通概念補上幾件事：
  - 使用者的團隊是「直接綁定 ＋ 所有角色預設團隊」的聯集；
  - 分類對「沒有團隊的人」全部可見；
  - 團隊停用、改名、刪除分別會造成什麼後果；
  - 新增「側邊選單位置」對照表。
- 各畫面同步現況：
  - 專案項目新增時預帶團隊（0.9.57），以及新增時的預設值與儲存流程；
  - 分類清單的兩種儲存提醒；
  - 變更密碼的頁面與對話窗檢查差異；
  - 稽核紀錄的查詢條件、CSV 與明細；
  - 日誌檢視的 AI 分析；
  - 系統例外紀錄的清單與明細欄位分工；
  - Token 用量的 7 個頁籤、群組頁籤欄位、明細窗與 CSV 欄位；
  - 新增側邊選單一節；
  - `/not-found` 改為重新執行（網址不變）。

## 關鍵決定

| 決定 | 理由 |
|---|---|
| 白話章插在技術章前面，不另外開檔案 | 讀者先懂觀念再看技術；仍在同一份總指引裡，目錄可以直接跳過去 |
| 技術章改名為「權限控管技術細節」 | 與白話導讀明確區隔，避免兩章標題看起來像重複 |
| 問題與建議只寫在文件裡，不改程式 | 依需求先盤點；要實作哪幾項另外規劃 |
