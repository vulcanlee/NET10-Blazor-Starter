## 二、設計決定

| 決定 | 理由 |
|---|---|
| 樣板放獨立檔案（`.tmpl`），不再寫在腳本的字串裡 | C# 的 `$"..."` 與 PowerShell 的變數展開互相干擾；獨立檔案可以直接讀、直接改 |
| 登記以既有程式碼為錨點插入、以「新加的那一行」判斷是否已存在 | 重跑不會重複插入；錨點不見時停止並指出是哪一項，而不是默默漏登 |
| 預設要求工作目錄乾淨 | 產生器一次改 20 幾個檔，與手上的修改混在一起就很難檢查 |
| `-Force` 不覆蓋已產生的檔案 | 重跑是為了補登記，不該蓋掉已經開始修改的程式 |
| 一般頁面只能掛在群組 2 或 5 | 角色權限矩陣只有這兩組；掛在別處會「選單看得到、權限勾不到」 |
| 產生的檢視不帶 `.razor.css` | `theme.css` 早有給新模組用的 `.view-toolbar`／`.view-table-wrap` |
| migration 在隔離的暫存路徑產生、先建置再 `--no-build` | 設計階段會建立主機，不能寫進開發機的 `C:\temp`；先建置讓產出的編譯錯誤直接顯示 |
| 驗證工具用暫存 index 建立快照 | 包含尚未提交的變更，又不動使用者的 index |
| 依權限顯示按鈕抽成元件 | 規則只有一份、可以單元測試；檢視少了一層 `@if` |
