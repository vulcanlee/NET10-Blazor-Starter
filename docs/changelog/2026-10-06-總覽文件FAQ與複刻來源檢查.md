## 起因

要讓《腳手架總覽與複刻上手》成為真正好查的新手入口，並確認 `New-StarterProject.ps1` 複刻時用的是不是腳手架最新的檔案與文件。查核發現：

1. **腳本複製的是本機磁碟上的工作目錄，完全不看 git 狀態**。未提交的修改、未追蹤的檔案、落後 origin 的舊內容、開發中的功能分支，都會原樣進入新專案，而且沒有任何提示。
2. 被 `.gitignore` 忽略、又不在排除清單裡的本機檔案也會被複製（git status 看不到它們）。
3. 根目錄的 `design-qa.md`（0.9.23 登入頁視覺驗證紀錄，內含個人路徑）是腳手架自己的歷史，卻不在清理範圍，會跟著進入衍生專案。
4. **衍生專案一複刻就有 1 個測試失敗**：`TeamTreeTests.Migration_ShouldKeepExistingTeamsAndMemberships`（0.9.105 起）寫死腳手架的舊 migration `_AddTwoFactorBackupCodes`，腳本重建單一 `Init` 後必定找不到。文件卻寫「建置與測試全綠才代表複刻成功」。
5. 文件錯誤：總覽 §6.1 與開發指引 §14.3 說「`CLAUDE.md` 規定要寫 changelog」，實際出處是《維護規範》§2；開發指引 §10 第 17 項說升級路徑「已列入路線圖 G-22」，但 G-22 已於 2026/10/04 決定不實作。總覽 §7.5 的步驟表漏列 `.playwright-cli`、`*.user`、`*.suo` 與刪除舊 migration 測試。

## 異動

### `scripts/New-StarterProject.ps1`

| 項目 | 改版後 |
|---|---|
| 來源檢查（新增） | dotnet-ef 檢查之後、碰任何檔案之前：`git fetch origin`，再檢查工作目錄乾淨（`git status --porcelain`，含未追蹤檔）、在 origin 的預設分支（`origin/HEAD`，取不到時用 `main`）、不落後 origin。任一項不符合就以警告逐行列出問題並中止 |
| `-AllowUnsyncedSource`（新增） | 確定要照現狀複製時放行，問題改為警告 |
| 無法判斷時 | 不是 git repo（例如下載 zip）、沒有 origin、fetch 失敗、比對不到 origin 分支：只警告、不中止 |
| 被忽略的檔案 | `git ls-files --others --ignored --exclude-standard` 扣掉排除清單後，剩下的列出警告（不中止）；排除規則改由 `Test-ExcludedRelativePath` 與 `Copy-TreeExcluding` 共用同一組陣列 |
| 中文檔名 | 檢查期間把主控台輸出編碼設成 UTF-8、git 加 `core.quotepath=false`，清單裡的中文路徑不會變亂碼 |
| 刪除的舊 migration 測試 | 改為清單 `$starterMigrationTests`：`CategoryTeamUniqueIndexMigrationTests.cs`、`TeamTreeMigrationTests.cs` |
