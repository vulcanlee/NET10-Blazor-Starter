# 階段四 UI 實跑驗收（0.4.21，無版本變更）

## 目的

階段四 UI 三大功能（角色×動作矩陣、使用者多角色/多團隊指派、列表頁按鈕動作化）於 commits `3df3e69`/`1830a1d`/`1acd162` 完成並編譯通過，但交接文件（`docs/security/權限授權現況評估與改善路線.md` 第八節）標註「執行期待實跑驗證」。本次於可執行環境實際點擊 + API 呼叫完成驗收。**驗證通過、未發現產品缺陷，故不修碼、不改版本號。**

## 驗證環境與方法

- **環境**：`dotnet run`（Development / SQLite / `http://localhost:5189`），管理員 `support` / `support`。
- **UI**：headless Chromium 實際點擊（登入、後台角色/使用者/團隊頁、Modal 勾選與多選、列表按鈕）。
- **API**：以使用者 JWT（`POST /api/Auth/login`）直接呼叫 CRUD 端點，檢查狀態碼與 `ApiResult<T>` 回應格式。
- **測試資料**：新建唯讀角色「稽核員」（三模組僅勾檢視）、使用者 `auditor`（多角色/多團隊）與 `rouser`（純唯讀）、團隊「研發部/業務部」。皆屬可捨棄的 dev DB 資料。

## 驗證結果（全數通過）

### 1. 角色 × 動作權限矩陣（`RoleViewView` / `RolePermissionService`）
- ✅ **存回/回填**：「稽核員」專案項目只勾「檢視」→ 存檔後重開，精確回填為 `✓檢視 ✗全部 ✗新增 ✗編輯 ✗刪除 ✗匯出`。
- ✅ **互斥**：勾「全部」→ view/create/edit/delete/export 五動作 `Checkbox` 全變 `disabled`；取消「全部」→ 恢復可點且「檢視」保留。

### 2. 使用者多角色 + 多團隊（`MyUserView` / `MyUserService`）
- ✅ **多角色**：主要角色 + 額外角色（`AdditionalRoleIds`）指派後重開正確回填，且額外角色清單正確排除主要角色（`GetUserAssignmentsAsync`）。
- ✅ **多團隊**：多選團隊（`TeamNames`）寫入 `UserTeam` 後重開正確回填。

### 3. 列表頁按鈕顯隱 + API 動作粒度授權（可看不可改，關鍵驗收）
- ✅ **UI 顯隱**：純唯讀 `rouser` 登入，Project/MyTask/Meeting 三頁列表可見，但新增鈕與每列修改/刪除鈕皆隱藏；管理員登入則全顯示。
- ✅ **API 403**：`rouser` JWT 打 `POST /api/Project/search`（View）得 **200**；`POST`（Create）、`PUT`（Edit）、`DELETE`（Delete）皆得 **403**，回應維持 `ApiResult<T>` 格式並精確標示如「目前使用者沒有『專案項目:create』權限。」。MyTask/Meeting 同樣 create 403、search 200。
- ✅ **邊界對照**：無 JWT 得 **401**；管理員 create 得 **400**（驗證層，代表已通過授權而非被 403 擋下）。

> **重點佐證**：403 錯誤訊息精確標示動作鍵 `專案項目:create`，端到端證明矩陣產出的是 **view-only 動作鍵**而非裸頁面鍵（否則會全數 200）。此行為佐證取代了原本要查 DB 的宣稱——磁碟上未見 `BackendDB.db`（SQLite 落於暫存位置），故改以執行期行為驗證，結果一致。

## 注意事項

- 全新 dev DB 無團隊資料，須先建團隊才能測多團隊指派（非缺陷，屬環境條件）。
- 觀察（非產品 bug，供日後留意）：AntDesign Blazor `Input` 的 `@bind-Value` 於 change/blur 才提交；滑鼠點「確定」會先 blur 欄位故正常，但鍵盤 Enter 送出（焦點仍在欄位）理論上可能踩到延遲綁定的必填驗證。屬全站表單既有行為、非階段四改動。
