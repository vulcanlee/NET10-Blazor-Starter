# 頁面使用說明對話窗：每頁一份白話說明（0.9.66）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：0.9.66
- 首次實作版本：0.9.66
- 最後核對日期：2026/09/26

## 為什麼

系統原本沒有任何頁內說明。操作者遇到「團隊留空是公開還是不公開」「這個數字是不是磁碟用量」這類問題，只能問人或翻開發文件。
《畫面與欄位字典》寫得很完整，但它是給開發者看的欄位對照，操作者在畫面上看不到。

結構與機制參考 KnowledgeExtraction.AI 的頁面說明系統：固定七段章節、「一分鐘看懂這一頁」、左側章節導覽，並用守門測試確保每頁都有說明。
外觀與元件則全部沿用本專案的做法：粉梅色票 token、果凍對話窗基底、`ToolbarIconButton`、經典 Material Icons，以及 OverlayStyles 的放置規則。

## 做了什麼

- **頂欄按鈕**：`MainLayout` 頁名右側掛一顆 `PageHelpDialog`，外觀是 `ToolbarIconButton`（`help_outline`，滑鼠提示「使用說明」）。全站只掛這一處，依路由自動對應。
  窄視窗只隱藏頁名文字，按鈕保留。
- **說明窗**：`.page-help-modal`，尺寸 94vw × 96vh，≤640px 時滿版。左側是章節導覽，右側內容獨立捲動。
  - 點「全部」顯示前言與全部章節；點單一章節只顯示那一段（篩選，不用 JS）。
  - 每次開窗都回到「全部」；切換頁面時自動關窗。
- **相關頁面**：「六、相關頁面」解析成卡片，點擊時先關窗再導頁。
  卡片依權限過濾：受選單控管、但此人不在授權選單裡的頁面隱藏；`/ChangePassword` 這類不在選單裡的頁面照常顯示。授權選單與側邊欄同源。
- **內容**：`Datas/HelpTopics.json` 是路由、標題、檔名的索引；內容放在 `Datas/Help/*.md`，共 14 份，涵蓋 13 個選單頁與 `/ChangePassword`。
  - 內容以《畫面與欄位字典》與實際畫面原始碼為素材，寫成操作者看得懂的白話版。字典裡的 ⚠️ 陷阱都收錄進去了。
  - csproj 新增 `Datas\Help\**\*.md` 的 Content 規則，因為 Web SDK 預設只複製 json。
- **程式**：
  - `PageHelpService`：讀檔、快取、精確路由比對、相關頁權限過濾。
  - `PageHelpMarkdownParser`：切章節、解析相關頁。
  - `HelpMarkdownRenderer`：`DisableHtml` ＋ `UsePipeTables`。刻意與 `AiMarkdownRenderer` 分開，因為兩者的威脅模型不同。
  - `SidebarMenuService.LoadAllMenuUrlsAsync`／`CollectUrls`。
- **產生器**：`New-CrudModule.ps1` 會一併產生 `Web/Datas/Help/<路由>.md` 初稿（含 BOM，結構已符合守門測試），README 也補上在 `HelpTopics.json` 登記的步驟。
- **守門測試**：
  - `PageHelpCatalogTests`：每個 `@page` 都要登記說明，或明列排除理由；另檢查索引與檔案雙向一致、七段章節、「一分鐘看懂」、相關頁、BOM、表格與 csproj 規則。
  - `PageHelpParsingTests`、`HelpMarkdownRendererTests`。

## 刻意不做的事

- **不在說明內文寫 `docs/` 指引**：操作者看不到 repo。說明檔與字典章節的對應表寫在速查表 §6.14。
- **不動既有畫面上的說明文字**：Token 用量的介紹段、資料庫用量的註記都原樣保留，說明檔另外收錄一份。
- **不支援帶參數的路由**：目前沒有這類頁面。等到真的出現，再擴充 `MatchTopic` 與檔名規則。

## 影響

- 所有登入後頁面的頂欄多了一顆按鈕。匿名頁（登入、忘記／重設密碼、待審核）沒有頂欄，不受影響。
- **新增 `@page` 必須登記說明，或列入 `PageHelpCatalogTests.RoutesWithoutHelp`**，否則測試會紅。
- **改了頁面的按鈕或欄位，要同步改說明檔的第三段**。測試只檢查結構，擋不住內容過時。
- 速查表 §6.5 的「唯一 `MarkupString`」改成「唯一放**不可信內容**的 `MarkupString`」。
