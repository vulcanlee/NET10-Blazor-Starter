# WASM 遷移 M1：基礎建設（0.10.0）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：0.10.0
- 首次實作版本：0.10.0
- 最後核對日期：2026/11/10

## 目的

把系統從 Blazor Server 改寫為 WebAssembly＋獨立 Web API 的第一個里程碑（計畫見 [WASM 遷移計畫](../migration/WASM遷移計畫.md)）。
這次**不搬任何頁面、畫面行為完全不變**，只打好之後搬頁面要用的基礎：伺服器端刷新 Token、API 依 Token 判斷使用者、過渡期的 Cookie 換 Token，
以及一個空的 WASM 前端專案。另外一併修正一個既有問題：強制登出、停用、改密碼之後，對方的登入最多還能再用 5 分鐘。
測試報告見 [M01-基礎建設](../migration/測試報告/M01-基礎建設.md)。

## 變更內容

### 1. 刷新 Token 改存伺服器端（可輪替、可撤銷）

- 新資料表 `RefreshSession`（migration `AddRefreshSession`），只存 SHA-256；`IRefreshTokenStore` 負責發出、輪替、撤銷、清理。
- 每次刷新都換一個新的，舊的隨即失效；已被換掉的舊 Token 在 30 秒後又被拿來用就撤銷整串，稽核 `Token.ReuseDetected`。30 秒內重送（兩個分頁同時刷新、回應遺失）只回 401、不撤銷。
- 以 Cookie 換出的 Token 不會比 Cookie 活得久（整串上限取 Cookie 的到期時間）。
- 刷新時比對發出當時的工作階段版本：改密碼、停用、改角色、強制登出之後的刷新一律失敗（`Token.RefreshFailed reason=SessionRevoked`）。
- ⚠️ **契約變更**：`refreshToken` 不再是 JWT，而是不透明字串；回應的欄位不變，另外多了 `isPersistent`。曾經解析 refresh token 內容的用戶端要改成只保存字串。

### 2. Auth API

- 新增 `POST /api/v1/Auth/logout`：撤銷整串刷新 Token。
- 新增 `POST /api/v1/Auth/bridge`（過渡期）：已用網頁登入的人以 Cookie 換一組 Token。必須帶標頭 `X-MyProject-Client`（CSRF 防護）；`isPersistent` 沿用「記住我」。登入 Cookie 新增 `login_session` claim，從網頁登出時一併撤銷換出的 Token。
- `GET /api/v1/Auth/me` 改回傳 `SessionInfoDto`（從資料庫讀，多了有效權限、團隊、是否必須改密碼或設定兩步驟驗證）。

### 3. API 也知道「誰在操作」，並擋下強制設定期間的呼叫

- 從 `AuthenticationStateHelper.Check` 抽出 `ICurrentUserLoader`，網頁與 API 共用同一份載入規則（網頁版行為不變，21 個既有測試斷言未改）。
- `ApiActorMiddleware`：以 access token 呼叫時，每個請求載入目前使用者並填入 `CurrentUserService`。
- `ApiSessionGateFilter`：被要求先改密碼或先設定兩步驟驗證的人，業務 API 一律回 403，`ApiResult` 新增 `errorCode`（`PASSWORD_CHANGE_REQUIRED`／`TWO_FACTOR_SETUP_REQUIRED`）。以前拿到 Token 就能繞過網頁的強制導頁。
- 行為變更：已刪除帳號的 access token 改回 **401**（以前要到權限檢查才回 403）。

### 4. 強制登出、停用、改密碼立即生效（既有問題修正）

- 工作階段版本的查詢有快取，但以前改版本的地方都沒有清快取，被強制登出的人最多還能再用 5 分鐘（程式註解寫「立即生效」）。
- 新增 `SecurityStampInvalidationInterceptor`：任何改到 `MyUser.SecurityStamp` 的 UPDATE 或刪除使用者，都會清掉快取（交易中則提交後再清一次）；日後新增的改版本路徑也不必記得手動清。快取加上世代計數，查詢與清除同時發生時不會把舊版本寫回去。
- bridge 另以資料庫比對 Cookie 上的版本，避免剛被撤銷的 Cookie 在快取還沒更新時換出 Token（獨立審查發現）。

### 5. 其他

- 新排程「登入 Token 清理」（`RefreshSessionRetention`，每天 03:00）刪除已到期的刷新 Token 紀錄；資料保留頁新增「登入 Token」列。
- 新專案 `MyProject.Web.Client`（WASM 前端空殼，只能參考 Dtos／Models／Share），主機加上 WebAssembly 互動模式；目前沒有任何頁面使用。
- 測試：37 個測試檔的路徑尋找統一改用 `SourceTree`；新增 `RefreshTokenStoreTests`、`TokenApiIntegrationTests`、`SecurityStampInvalidationTests`、`RefreshSessionRetentionJobTests` 與兩個守門測試。
- 實機驗證工具：`scripts/Start-E2EHost.ps1`（隔離資料夾啟動網站）、`scripts/e2e/`（Playwright 情境與全部 37 個路由的煙霧測試）。

## 升級注意

- 部署後套用 migration `AddRefreshSession`（啟動時自動執行）。
- 已發出的 JWT 格式 refresh token 全部失效，API 用戶端要重新登入一次；網頁登入不受影響。
- 版本號 0.9.177 → 0.10.0（使用者決定：WASM 遷移從 Minor 升版開始）。
