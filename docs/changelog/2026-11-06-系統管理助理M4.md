# 系統管理助理：里程碑 4（0.9.159）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：0.9.159
- 首次實作版本：0.9.159
- 最後核對日期：2026/11/06

## 目的

里程碑 3（0.9.158）讓助理經核准後做**可復原**的修改。這一版補上 PRD 標 ⚠ 的**不可復原**動作，完成 PRD 的四個里程碑（定時巡檢在第二版）。依使用者 2026/11/06 的決定：
核准窗加紅字警告與紅色核准鈕，而且要**輸入「確認」**才能核准；刪除備份和頁面一樣不另外限制；里程碑 2～3 審查留下的小問題一起處理。
需求見 [系統管理助理 PRD](../prd/系統管理助理-prd.md)，使用說明、截圖與測試報告見[使用手冊](../features/系統管理助理.md)。

## 一、核准窗

- `AiToolDefinition.IsIrreversible` → `AiToolApprovalRequest.IsIrreversible`（`AiToolApprovals.Describe` 帶入；接續時從定義重新帶出，所以停在核准的對話回來時紅字還在）。
- 有不可復原的操作時：該筆上方紅字「⚠ 這個動作無法復原…」（只用 `--app-error`、`--app-tint`，不新增色票）、窗底「請輸入『確認』」欄位、紅色核准鈕。
- `AdminAssistantApproval.CanApprove`：輸入剛好「確認」（前後空白不計）才能核准；按鈕停用之外，`OnDecideAsync` 再擋一次。
- 實測發現 AntDesign `Input` 的 `@bind-Value`＋`BindOnInput` 要等失焦才回寫（打完字直接按核准會按到停用的按鈕），改用 `OnInput`。

## 二、15 個不可復原工具

| 領域 | 工具 | 保護 | 稽核 |
|---|---|---|---|
| 帳號與權限（4） | `purge_users`、`purge_roles`、`reset_two_factor`、`clear_audit_logs` | 徹底刪除只找已軟刪除的；重設 2FA 擋自己、對方要已啟用（原本只在頁面擋）；批次最多 50 | 徹底刪除與重設 2FA 由服務寫；清空稽核同頁面、刪完再寫 `Audit.ClearAll` |
| 監控與診斷（2） | `delete_exceptions`、`clear_exceptions` | 用 `search_exceptions` 的編號 | 同頁面加 `via`（刪除記 `type=…`） |
| AI 管理（3） | `delete_ai_call_logs`、`clear_ai_call_logs`、`clear_token_usage` | 清空 AI 對話紀錄不影響 Token 用量 | 同頁面加 `via` |
| 系統設定與維運（5） | `delete_announcements`、`delete_backups`、`run_purge_job`、`enable_purge_job`、`shorten_retention` | 備份只接受清單上的檔名；清理排程工具只接受清理類；縮短保留天數只接受真的會縮短的保留參數 | 同各頁加 `via`；公告刪除後刷新快取並廣播 |
| 共用（1） | `custom_purge` | 沿用資料保留頁的 `CustomPurgeCutoff`（1～3650 天、日期不晚於今天）；分派到任何專家領域都載入 | 同資料保留頁（`source=data-retention; …`），刪到資料才寫 |

- 依天數或日期的清除一律走 `custom_purge`：AI 對話紀錄與 Token 用量頁的「清除」接受任意日期（未來日期＝清空），助理刻意不走那條路。Token 用量沒有逐筆編號，所以不做逐筆刪除。
- 可復原的工具（`trigger_scheduled_job`、`set_scheduled_job_enabled`、`set_system_parameter`、`reset_system_parameter`）遇到會刪資料的變體仍拒絕，改指向不可復原的工具，兩種核准窗不混用。
- 新增 `ExceptionLogService.GetByIdAsync`、`AuditLogQueryService.GetByIdAsync`（工具寫稽核前取得例外類型與動作代碼）；`AdminAssistantMutation.ValidateIds`。
- 實測發現助理查不到已軟刪除的帳號而拒絕徹底刪除：`search_users` 加 `status=deleted`、`list_roles` 加 `includeDeleted`，比照頁面的「顯示已刪除」（稽核記 `showDeleted=true`）。

## 三、提示詞

- 共同說明：不可復原的動作也可以做，但要先列出對象或用 `preview_data_purge` 預覽筆數、提醒無法復原；依天數或日期清除一律用 `custom_purge`。
- 各專家說明補上新工具；帳號專家：還原或徹底刪除前用 `status=deleted`／`includeDeleted` 確認對象；AI 專家：儲存提示詞時填 `baseVersion`。
- 分派說明：以這則訊息本身提到的對象為準（提到帳號、角色或 2FA 一定含 accounts；提到備份、公告、排程、系統參數一定含 ops），前文只用來補足「他」「那些」。實測前文一直談維運時，「徹底刪除 temp-b」曾被分到 ops。

## 四、里程碑 2～3 審查留下的小問題

| 小問題 | 修正 |
|---|---|
| 提示詞存檔以存檔當下的作用中版本做衝突檢查，等於沒檢查 | `save_prompt_version` 加必填 `baseVersion`（讀到的作用中版本或 `default`），別人中間存過就不覆蓋 |
| 縮短保留天數的判斷在值無法解析時放行 | `OpsAssistantTools.WouldShortenRetention`：任一邊不是整數時保守地當作會縮短 |
| 還原只搜尋已刪除清單的前 50 筆 | 讀到 5000 筆再精確比對 |
| 刪除角色沒處理只差大小寫的重複名稱 | 依角色編號去重 |
| 改角色或管理員身分時保留其他欄位沒有測試 | 補測 Email、必須改密碼、鎖定狀態 |
| `Audit.View` 的 detail 和頁面不同；沒有內容檔時回「編號不存在」 | detail 改為 `action=…; via=…`（看明細就寫，同頁面）；不存在與沒有內容檔分開說明 |
| 「未開 2FA 的管理員」含停用與 Google 登入的帳號 | 只算啟用中、用密碼登入的管理員 |

不處理：健康報告的證據含伺服器路徑（使用者同意資料可送模型，只排除金鑰與連線字串）、每次重算最後登入與讀全部備份 manifest（效能，目前資料量小）。
