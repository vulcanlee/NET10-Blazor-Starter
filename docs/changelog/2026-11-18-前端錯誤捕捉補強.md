# 前端錯誤捕捉補強：登入前、離線、連線中斷、資源與安全政策都留紀錄（0.10.36）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：0.10.36
- 首次實作版本：0.10.36
- 最後核對日期：2026/11/18

## 目的

使用者 2026/11/18 詢問：前後端分離後，後端有完整的例外攔截與留存機制，前端出事時（包括網路問題、JS 問題、瀏覽器開發人員工具 Console 裡看到的錯誤）是否也能記錄到後端，方便日後調查。
盤點後發現 0.9.79 起已有瀏覽器錯誤回報（LOG-20），但只涵蓋**登入後**的 JS 錯誤與元件例外，缺口如下：

- 頁面自己 catch 到的未預期例外（`ViewNotification.UnexpectedError`，約 120 個 catch）只寫瀏覽器主控台；通知上的追蹤碼是「最近一次失敗的 API」的碼，前端程式自己的錯誤在伺服器查不到。
- 登入頁、重設密碼頁等匿名頁與 WASM 啟動失敗的錯誤一律不送（回報端點要登入，JS 只在記憶體暫存 20 筆，重新整理就沒了）。
- 連不上伺服器時請求根本到不了後端，後端日誌一片空白；使用者反映「常常斷線」時沒有任何證據。
- 回報沒有前端版本、瀏覽器、發生前的操作軌跡。
- 資源載入失敗（`<img>`、`<script>`、`<link>`）與內容安全政策（CSP）擋下的內容沒抓。
- 錯誤邊界以外的 .NET 未處理例外（例如根元件底下的狀態列）只顯示黃色的「系統發生未預期的錯誤」列。
- 頁面層的錯誤邊界包住整個版面：頁面出錯時側邊選單與頁首一起消失，換到別頁還是錯誤畫面（PRD 第五章原本誤標為「換頁自動復原」，只有浮層那一層會復原）。

## 決定（使用者選定）

- 四個缺口都補，並依嚴重程度寫到**適當的日誌等級**（不全部記 Information）：

  | 等級 | 事件 | 去向 |
  |---|---|---|
  | Error | JS 錯誤、Promise 未處理拒絕、錯誤邊界、錯誤邊界以外的 .NET 未處理例外、`UnexpectedError`、Service Worker 安裝失敗、WASM 啟動失敗 | 日誌檔＋系統例外紀錄＋告警 |
  | Warning | 瀏覽器有網路卻連不上伺服器（一段中斷一筆）、資源載入失敗、CSP 違規 | 只寫日誌檔 |
  | Information | 瀏覽器自己離線（一段中斷一筆） | 只寫日誌檔 |
  | 不記 | API 4xx／5xx（伺服器已有紀錄，只放進操作軌跡）、`LogWarning`、框架資訊、外掛雜訊 | — |

- **Console 不整個攔下來送**：大多是操作流水帳與雜訊，會灌爆日誌、帶出個資；只挑上表有調查價值的。需要細節時另做「前端診斷模式」（下一版 0.10.37）。
- 未登入時的錯誤**暫存在瀏覽器、登入後補送**，不開放匿名端點（任何人都能呼叫的話，可能被灌垃圾、擠掉真正的例外）。
- 沿用系統例外紀錄表（`ExceptionLog`，來源「瀏覽器」），背景資訊寫進堆疊檔、不加欄位。
- 操作軌跡記換頁與 API 呼叫最近 20 筆（只有路徑，不含查詢字串與輸入內容）。
- 前端版本用**前端主程式的指紋**，不把版本號寫進前端（否則每次升版，即使只改後端，使用者都會看到「有新版本」）。
- 每個 API 回應都加 `X-Trace-Code` 標頭，操作軌跡的每一筆都能到 `/logs` 對到伺服器那一次請求。
- 錯誤邊界一起修：只換掉內容區、換頁時復原。

## 變更內容

### 前端

- `wwwroot/js/client-error-reporter.js`（改寫）：前端唯一的回報管線，**排在所有腳本之前**載入。
  - 監聽 capture 階段的 `error`（目標是元素時是資源載入失敗，這種事件不會冒泡）、`unhandledrejection`、`securitypolicyviolation`。
  - 每筆先存進 localStorage 的 `app.clientReports.v1`（上限 30 筆、7 天、約 256KB，超過丟最舊的並計數）；localStorage 不能用時改存記憶體。
  - 登入後由 `ClientMainLayout` 註冊送件者（`register(ref, userId)`），一批最多 20 筆經 `Layout/ClientErrorReporter.SendAsync` 送出，伺服器回報處理完的才移除；被限流或送不出時 60 秒後再送；`online` 事件時立即再送。多個分頁以 Web Locks 只讓一個送。
  - 追蹤碼在這裡（或 .NET 端）產生並立即回傳，畫面馬上顯示，伺服器沿用。
  - 錯誤附最近 20 筆操作軌跡；同一個錯誤 10 秒內只記一次。
  - 連線中斷：`ApiClient` 每次呼叫都告訴這裡（狀態 0＝連不上）；第一次連不上開始一段（存在 `app.networkEpisode.v1`，中斷期間重新整理也接得上），第一次有回應時結束並記一筆。只要有一次失敗發生在瀏覽器認為有網路時就是 Warning，否則 Information。
  - 資源載入失敗：離線時不記；同一個網址每次載入頁面只記一次。CSP：同一個指令與網址每次載入頁面只記一次；AntDesign 頁籤的 `ondragover="event.preventDefault();"` 已知雜訊略過（速查表 §6.33）。
  - Blazor 啟動完成（`started()`）前收到的 JS 錯誤一律記成 `boot`。
- `wwwroot/js/app-start.js`（新）：`index.html` 的 blazor 腳本改 `autostart="false"`，由它呼叫 `Blazor.start()`，完成時通知回報管線、失敗時記 `boot`。
  ⚠️ 實機發現 .NET 11 擋下 `dotnet.native` 時 `Blazor.start()` 不會失敗，而是出現幾筆未處理的 Promise 拒絕（Failed to fetch、Failed to start platform…），所以靠「啟動完成前」來判斷。
- `wwwroot/js/pwa.js`：Service Worker 安裝失敗的種類改成 `sw-install`。
- `Commons/ClientErrorCapture.cs`（新，單例）：.NET 端交給 JS 的入口。`Capture(kind, ex)` 產生追蹤碼、記在例外的 `Data` 上（錯誤畫面顯示用），同一個例外只回報一次；`Api`、`Navigated`、`SetAppBuild`。全部同步呼叫，失敗一律吞掉（只記 Debug）。
- `Commons/ClientFrameworkErrorLoggerProvider.cs`（新）：只接 `Microsoft.AspNetCore.Components.*` 分類、Error 以上且帶例外的日誌，轉成 `unhandled` 回報。
- `Commons/ClientErrorBoundary.cs`：改經 `ClientErrorCapture.Capture("boundary", …)`，在第一個 await 之前取得追蹤碼。
- `Commons/ViewNotification.cs`：新增 `UseErrorCapture`；`UnexpectedError` 回報例外（`caught`），通知上附那筆回報的追蹤碼。73 個呼叫點不用改。
- `Commons/ClientPageErrorAlert.razor`（新）：頁面錯誤畫面，附追蹤碼。
- `Layout/ClientMainLayout.razor(.cs)`：以 `ClientErrorBoundary` 包住 `@Body`（只換掉內容區），換頁時 `Recover()`；註冊送件者時帶使用者 Id。
- `ClientRoutes.razor`：外層錯誤邊界保留為最後防線，也在換頁時復原；記換頁軌跡（含匿名頁）。
- `Views/Dashboard/DashboardGrid.razor`：小工具的錯誤畫面附追蹤碼。
- `Api/ApiClient.cs`：三個送出點包上 `TrackAsync`（計時、讀 `X-Trace-Code`、連不上時記狀態 0）；送出回報本身不記。
- `Program.cs`：註冊 `ClientErrorCapture`（單例）與 `ClientFrameworkErrorLoggerProvider`；`SetAppBuild` 用前端主程式的 `ModuleVersionId` 前 8 碼；`ViewNotification.UseErrorCapture`。

### 伺服器

- `POST api/v1/shell/client-reports`（`ShellController.ClientReports`）：批次回報，每批最多 20 筆，本體上限 256KB。錯誤沿用 `ClientErrorReporting:MaxPerCircuitPerMinute`（與舊端點同一個計數），事件另計每分鐘 30 筆；被限流的那筆與之後的不算完成（`DoneIds` 沒有），回 `RetryAfterSeconds = 60`。回報關閉時全部當成完成、不記錄。暫存區有捨棄（`Dropped`）時記一筆 Warning。
- `BrowserErrorReporter.Report(ClientReportDto, beforeSignIn, context)`：格式正確的瀏覽器追蹤碼以 `TraceCode.Begin` 沿用（日誌檔的 TraceId 與例外紀錄的最後追蹤碼都是它）；登入前發生的（發生時的使用者 Id 與送出時不同）用另一個樣板 `Browser script error before sign-in. Kind={Kind}`，在「操作」欄看得出來。
- `BrowserEventReporter`（新）：連線中斷、資源、CSP，不帶例外物件，訊息帶 Account、UserId。
- `BrowserReportContext`（新）：組背景資訊（追蹤碼、瀏覽器端發生時間、是否登入前、前端指紋、伺服器版本、UA、操作軌跡），去掉查詢字串與控制字元（避免偽造日誌行）、只留允許的 HTTP 方法與格式正確的追蹤碼。
- `BrowserScriptException`：背景資訊附在 `ToString()`，`Message` 不變，簽章不受影響。
- `TraceCode.IsValid`（新）。
- `UseHttpRequestLogging`：每個回應加 `X-Trace-Code`；CORS 公開這個標頭。
- 舊端點 `client-errors` 保留給瀏覽器裡還在快取的舊前端，之後移除。
- 系統參數頁「回報瀏覽器端錯誤」「瀏覽器錯誤每分鐘上限」說明更新。

## 已知限制

1. 背景資訊與操作軌跡只寫進**第一次**發生時的堆疊檔（同簽章合併時不重寫檔案）；之後每次發生的完整背景資訊在日誌檔那一行，可用追蹤碼在 `/logs` 查到。
2. 紀錄時間是伺服器收到的時間；瀏覽器端的發生時間在背景資訊裡。
3. 啟動失敗要等**同一個瀏覽器**之後成功啟動並登入才送得出去。
4. 追蹤碼在瀏覽器先產生並顯示；該筆回報被暫存區擠掉、被限流或回報被關閉時，管理員查不到。
5. 資源載入只抓得到 `<img>`、`<script>`、`<link>`；fetch、CSS `url()`、字型抓不到。
6. 登入前的錯誤記在之後登入的帳號下（共用電腦時不一定是同一人），紀錄上標「登入前」。
7. `ClientSession` 自己的請求（`/me`、刷新 Token）與帶附件的上傳（JS fetch）不在操作軌跡與連線中斷的計算內。
8. http（非 localhost）時沒有 Web Locks，多個分頁可能各送一次，伺服器收到重複的。

## 實機驗證

以 `Start-E2EHost.ps1` 的隔離網站執行新的 `scripts/e2e/browser-reports.mjs`（只比對這次執行之後寫的日誌），8 項全部通過：

- B1 登入頁的錯誤暫存在瀏覽器，登入後送出，例外紀錄的「操作」是登入前的樣板、帳號是登入的人。
- B2 瀏覽器產生的追蹤碼就是例外紀錄的最後追蹤碼；堆疊檔有背景資訊與操作軌跡。
- B3 回應帶 `X-Trace-Code`。
- B4 攔下所有 API：恢復後記一筆 Warning「Browser could not reach the server」（失敗次數、API 路徑）。
- B5 瀏覽器離線、恢復後重新整理：記一筆 Information「Browser was offline」。
- B6 壞掉的 `<img>`：Warning，網址不含查詢字串。
- B7 注入行內腳本被 CSP 擋下：Warning（`script-src-elem`、`inline`）。
- B8 擋下 `dotnet.native` 造成啟動失敗：錯誤存在瀏覽器（kind `boot`），正常啟動並登入後送出。

另外以暫存腳本確認：有頁籤的 `/token-usage` 主控台有 7 筆 AntDesign 的 CSP 違規，日誌 0 筆（已知雜訊有略過）；破壞 Blazor 管理的 DOM 造成錯誤邊界以外的框架例外，以 `Kind=unhandled` 回報，側邊選單仍在。
頁面錯誤邊界的實際畫面沒有實機觸發（正常功能沒有會丟例外的頁面），由慣例測試涵蓋。
