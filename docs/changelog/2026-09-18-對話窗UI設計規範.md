# 大量資料輸入對話窗：滿版 2 欄版型、未儲存保護與果凍視覺（0.9.25）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：0.9.25
- 首次實作版本：0.9.25
- 最後核對日期：2026/09/18

## 為什麼改

九個對話窗全部是單欄直排，90vw 的寬度有一半是空的，欄位一多就得一路往下捲。
同時有三個會實際咬人的缺口：

1. **零未儲存保護。** `OnModalCancelHandleAsync` 只做 `modalVisible = false;`，
   而 `MaskClosable` 在五個 CRUD 窗都沒設定（AntDesign 預設 `true`）——
   誤點一次遮罩，整窗輸入無聲蒸發。全專案 `EditContext.IsModified()` 零呼叫。
2. **版型規則不完整。** `category-view-modal` / `team-view-modal` 把 class 掛在 razor 上，
   但 `FormModalHelper.razor` 裡從來沒有對應規則，實際吃 AntDesign 預設的 520px 窄窗、body 不捲動。
3. **規範與程式碼不同步。** 速查表 §6.4 寫「三組版型」，實際有五組。

## 改了什麼

### 新的共用機制（`Components/Commons/`）

| 檔案 | 職責 |
|------|------|
| `FormDirtyTracker.cs` | 與原始快照做值比對的變更偵測（JSON 序列化），改了又改回原值視為無變更 |
| `FormEditConfirm.cs` | 「尚有未儲存的變更」與「確認儲存」兩段確認的文案樣板 |
| `FormModalFlow.cs` | 確定／取消的共用流程，收掉散在各失敗路徑的 `modalVisible = true;` |
| `FormSection.razor` | 區塊小標題 + 2 欄 grid 容器（刻意不附 scoped CSS） |

### 版型與視覺

`FormModalHelper.razor` 新增 `.form-modal`：95vw × 95vh（`max-width: 1400px`）、
標題列與按鈕列固定、中間捲動、2 欄 grid（`form-field-full` 獨占整行）、
粉梅暖雪果凍毛玻璃（色票沿用 `Login.razor.css`）、
`fm-arrive` 擠壓回彈開窗動畫、768px 塌單欄全螢幕、`prefers-reduced-motion` 降級。

### 行為變更（需告知使用者）

- **點遮罩不再關窗。** 大量輸入的窗，點遮罩從來不是「我要關窗」的刻意手勢。
- **有未儲存變更時按取消／✕／ESC 會先問一次**（「繼續編輯／放棄變更」）；沒有變更則直接關閉，不打擾。
- **按儲存且有變更時會再確認一次**（「再檢查／儲存」）。
- **一個字都沒改就按儲存**：提示「沒有任何變更，未進行儲存」後直接關窗，不寫入資料庫。

### 順手修掉的既有問題

- `CategoryViewView` / `TeamViewView` 補上尺寸規則（改用 `form-modal`）。
- `MainLayout.razor` 的「關於」窗移除 `<Modal Width="520">`，尺寸改寫在 `FormModalHelper`（速查表 §6.4）。
- `MainLayout.razor` 補上 `<FormModalHelper />`：先前只有各 View 自己渲染它，
  在不含那些 View 的頁面（例如首頁）開「變更密碼」或「關於」，尺寸規則整組不存在。
- `MyUserView.razor.css` 的 `.my-user-password-hint` 是 scoped CSS 卻寫在 Modal 裡，
  **從來沒有生效過**；改用全域的 `.form-field-hint`。
- `scripts/New-CrudModule.ps1` 改為直接產出符合規範的 Modal 骨架，不再只留 TODO。

## 為什麼不用 `EditContext.IsModified()`

只有繼承 `InputBase<T>` 的 Blazor 內建元件才會呼叫 `EditContext.NotifyFieldChanged`。
本專案的欄位全是 AntDesign 元件直接綁模型屬性，外層 `EditContext` 收不到欄位變更通知 ——
`IsModified()` 會恆為 `false`，未儲存提示**永遠不跳**，而且不會有任何徵兆。
改用 JSON 快照比對，順便繞開 `Clone()` 淺複製對 List 欄位的影響。
