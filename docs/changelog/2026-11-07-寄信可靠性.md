## 目的

《寄信服務 PRD》的已知限制有三項：
- 佇列只在記憶體（容量 100），程式重啟時尚未寄出的信會遺失。
- 寄送失敗不重試。
- 沒有寄送紀錄頁，失敗只出現在日誌與系統例外紀錄。

使用者說「沒收到重設密碼信」時，管理員很難查。

## 使用者的決定（2026/11/07）

| 項目 | 決定 |
|---|---|
| 範圍 | 資料庫佇列＋重試＋「寄信紀錄」頁 |
| 信件內容 | 重設密碼信含可用的重設連結，而資料庫本來只存權杖雜湊：內文用 Data Protection 加密存放，寄出成功或放棄後立刻清除 |
| 重試 | 只重試暫時性失敗，最多 3 次，間隔 1、5、15 分鐘 |
| 紀錄頁 | 管理員專屬，放在「系統管理 › 監控與診斷」；顯示完整收件者；保留 90 天 |

## 內容

### 先存再寄

- **呼叫端完全不改**：`IEmailQueue.TryEnqueue` 仍然只放進記憶體交接區就返回。
  - 例外告警信是在例外記錄管線的鎖定區段內入列的，那裡不能寫資料庫。
  - 重設密碼的回應時間也維持不變，不會因此洩漏帳號是否存在。
- **`EmailDispatchWorker` 改成兩段**：
  1. 從交接區取出信，交給 `EmailOutboxProcessor.PersistAsync` 寫進新資料表 `EmailOutbox`（狀態「待寄」，內文以 `EmailBodyProtector` 加密）。
  2. 再由 `SendDueAsync` 寄出到期的「待寄」，一次最多 20 封。沒有新信時最多等 15 秒，醒來看有沒有到期的重試。
- **重新啟動**：正常關機時，先把交接區剩下的信存進資料庫，下次啟動接著寄。只有程式崩潰時，交接區裡那幾毫秒的信會遺失。
- **寫入資料庫失敗**：退回直接寄一次（不留紀錄），資料庫出問題時告警信仍寄得出去。
- **寄信停用**（`Provider=None`）：記「未寄出（寄信停用）」，不存內文。
- **失敗分類**（`EmailFailureClassifier`）：
  - 暫時性：`SmtpCommandException` 的 4xx、`SocketException`、`IOException`、`SmtpProtocolException`、逾時，以及無法判斷的例外。
  - 永久性：5xx、`AuthenticationException`、`SslHandshakeException`、`ParseException`、`UnauthorizedAccessException`、解密失敗。
- **重試**：
  - 暫時性失敗依 `EmailDeliverySettings:MaxRetries`（預設 3，0～5）重試，間隔 1、5、15、30、60 分鐘取前幾段。
  - 重試用完或永久性失敗就記「失敗」，並清除內文。
  - 每次失敗記 Warning（會重試）或 Error（放棄），錯誤摘要存 500 字。

### 「寄信紀錄」頁 `/email-logs`

- 管理員專屬（選單 id 69，監控與診斷），唯讀。
- 欄位：建立時間、種類、收件者、主旨、狀態、嘗試次數、下次嘗試、寄出時間、錯誤摘要。
- 篩選：時間範圍、狀態、種類、關鍵字（收件者與主旨）；工具列有查詢、重新整理。
- 看不到內文（已清除），所以沒有重新寄送。

### 保留與清理

- 新增 `EmailDeliverySettings`：`MaxRetries`（3）、`RetentionDays`（90）。
- 兩個都可在「系統參數」頁調整：重試次數在「監控與告警」，保留天數在「資料保留」；系統參數 55 → 57 個。
- 排程作業「寄信紀錄清理」（`EmailLogRetention`，每天 03:00）刪除超過保留天數的紀錄，「待寄」不刪，稽核 `EmailLog.AutoPurge`。
- 「資料保留與清理」頁多一列「寄信紀錄」（可自訂清除，稽核 `EmailLog.Purge`）。
- 系統管理助理的清理作業清單也加上這個作業。

## 獨立審查

另派一個代理人只看程式差異，結果沒有高嚴重度問題。處理如下：

| 發現 | 處理 |
|---|---|
| 寄出後存檔失敗（資料庫被鎖），或 IIS 回收時新舊程序並存，同一封信可能重複寄送（中） | 寄送前用條件更新「佔住」這一列：下次嘗試推到現在＋15 分鐘租約，嘗試次數＋1；只有一個處理器會成功，佔住後重讀。結果存檔失敗時重試 3 次，仍失敗就等租約到期再寄（寧可重寄也不遺失）。新增測試：寄送途中另一個處理器拿不到這一列 |
| 郵件伺服器很慢時，整批寄送期間不讀交接區，交接區可能滿（中） | 每寄完一封就把交接區的新信存進資料庫；一批寄滿 20 封時不等待，直接寄下一批。新增測試 |
| 關機時寫入資料庫被取消，那封信就遺失（低） | 寫入資料庫改成不可取消。新增測試 |
| 存進資料庫後才改成寄信停用，`NullEmailSender` 回成功，結果被記成「已寄出」（低） | 寄之前先檢查，停用就記「未寄出」。新增測試 |
| 關機後交接區沒關閉，之後的入列回成功卻沒人處理（低） | 關機時先關閉交接區，之後的入列回 false 並記警告。新增測試 |
| 關機時資料庫被鎖，每封可能要等（低） | 不改：主機的關機時限會截斷，剩下的信會遺失；寫進程式註解 |

另外發現一件事：佔住之後把追蹤中的實體直接標成 `Unchanged`，EF 會把剛改的值還原，所以改成重讀這一列。
