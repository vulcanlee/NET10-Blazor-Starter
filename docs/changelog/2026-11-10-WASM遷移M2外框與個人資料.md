# WASM 遷移 M2：外框與個人資料頁（0.10.1）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：0.10.1
- 首次實作版本：0.10.1
- 最後核對日期：2026/11/10

## 目的

WASM 遷移的第二個里程碑（計畫見 [WASM 遷移計畫](../migration/WASM遷移計畫.md)）：第一個頁面「個人資料」（`/Profile`）改在使用者的瀏覽器以 WebAssembly 執行，
並建立 WASM 頁面用的外框（側邊選單、頂欄、通知鈴鐺、公告橫幅、操作說明）。其他 36 個頁面維持 Server 版、完全沒動。
測試報告見 [M02-外框與個人資料](../migration/測試報告/M02-外框與個人資料.md)。

## 變更內容

### 1. 個人資料頁改用 WebAssembly

- 頁面與檢視搬到 `MyProject.Web.Client`（`Pages/ProfilePage.razor`、`Views/Profiles/ProfileView`），畫面與操作和以前相同，資料來自新的 `GET/PUT /api/v1/profile`。Server 版的頁面已刪除。
- 從 Server 頁面進入個人資料、或從個人資料點側邊欄到其他頁面時，會**整頁重新載入**（遷移期間的正常現象）；第一次進入要下載 WebAssembly 程式，之後由瀏覽器快取。

### 2. WASM 版外框

- `MyProject.Web.Client/Layout/Client*` 與 `Commons/ClientPageHelpDialog`：標記與樣式照抄 Server 版，外觀相同（截圖比對見測試報告）。
- 選單、系統資訊、說明主題、通知、公告都改由新的 API 取得（`ShellController`、`NotificationsController`、`AnnouncementsController`），規則與 Server 版共用同一份程式。
- 通知鈴鐺與公告每 60 秒、以及切回分頁時更新（Server 版是即時推送；WASM 版到 M8 加上推播串流後恢復即時）。
- 開頁稽核與瀏覽器錯誤回報改由前端呼叫 API，規則與 Server 版相同。
  - 兩者都以「使用者」為單位限制每分鐘次數（錯誤回報沿用 `ClientErrorReporting:MaxPerCircuitPerMinute`，開頁稽核 60 次），由新的 `PerUserRateLimiter` 跨請求計數；超過的錯誤回報回 `accepted=false`。
  - 開頁稽核 API 只接受已搬到 WASM 的頁面路徑；Server 頁面由電路記。
  - Server 頁面與 WASM 頁面互相切換時只記一筆（即將整頁載入到另一邊時，離開的一邊不記）。

### 3. WASM 頁面的登入

- 打開 WASM 頁面時，以網頁登入的 Cookie 換一組 Token（M1 的 bridge），依「記住我」存在 localStorage 或 sessionStorage；多個分頁同時刷新時排隊（Web Locks），刷新不成功再以 Cookie 重換。
- 被要求改密碼或設定兩步驟驗證時，WASM 頁面一樣整頁導到那兩頁。
- 從 WASM 頁面登出：清掉瀏覽器存的 Token，交給網頁登出頁（撤銷 Token、寫一筆登出稽核）。
- **瀏覽器存的 Token 必須是這次網頁登入的人的**：主機把 Cookie 上的使用者 Id 傳給 WASM 頁面，不符就丟掉、重新以 Cookie 換；
  執行中發現另一個分頁換了人，整頁重新載入。登入頁載入時也會清掉瀏覽器存的 Token。
- 斷線或逾時時，刷新 Token 與 API 呼叫都回「目前無法連線到伺服器，請稍後再試。」，不會讓整頁出錯。
- 網址經過編碼（例如 `/%50rofile`）時，主機與 WASM 判斷一致，不會不停重新整理；整頁載入一律用目前網址，不從路徑重組。

### 4. 共用元件搬到 Client 專案

`StatusPill`、`StatusTone`、`OverlayStyles`、`ConfirmDialog`、`LogoutConfirm`、`UserInitials`、`MaterialIconOpticalSize`、`PageHelpFontSizes`、`AntDesignLocaleFactory` 搬到 `MyProject.Web.Client`，**命名空間不變**，Server 頁面照常使用。

### 5. 其他

- 主機依路由選渲染模式（`App.razor.cs`）：`ClientRouteTable` 列出的頁面以 WebAssembly 執行，其餘維持 Server。
- 測試：新增 `ShellApiIntegrationTests`、`Client/ClientSessionTests`；頁面授權、操作說明登記、色票規則等慣例測試改為同時掃描 Server 與 Client（`SourceTree.UiRoots`）。
- 實機驗證腳本 `scripts/e2e/m02-shell.mjs`；`scripts/Start-E2EHost.ps1` 另外開啟瀏覽類稽核，讓情境腳本檢查開頁稽核。
