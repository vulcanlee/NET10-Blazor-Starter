# 側邊欄選單階層重組：統計與分析／權限管理 收納進系統管理（0.9.21）

- 文件版本：1.1
- 文件狀態：已實作
- 現行系統版本：0.9.21
- 首次實作版本：0.9.21
- 最後核對日期：2026/09/18

## 起因

「統計與分析」與「系統管理」原本是兩個並列的根層群組，而「系統例外紀錄」被放在「系統管理」底下。
實際上那五個統計／診斷頁面（日誌檢視、日誌等級設定、系統例外紀錄、資料庫用量、Token 用量）
性質一致，都是管理員專屬的維運工具，散在兩個群組裡不易尋找；
「使用者管理／角色管理」則是帳號授權面向，與維運工具混在同一層也缺乏區隔。

本次把「統計與分析」整組搬進「系統管理」成為第三層群組並併入「系統例外紀錄」，
另新增「權限管理」群組收納「使用者管理／角色管理」。

## 結構前後對照

改前（兩層）：

```
統計與分析 (6)   ├ 日誌檢視 (61) ├ 日誌等級設定 (63) ├ 資料庫用量 (62) └ Token 用量 (64)
系統管理 (3)     ├ 使用者管理 (31) ├ 角色管理 (32) └ 系統例外紀錄 (33)
```

改後（三層）：

```
系統管理 (3)  [admin_panel_settings]
  ├ 統計與分析 (6)  [analytics]
  │   ├ 日誌檢視 (61)        /logs
  │   ├ 日誌等級設定 (63)    /log-level-setting
  │   ├ 系統例外紀錄 (33)    /system-exceptions
  │   ├ 資料庫用量 (62)      /database-usage
  │   └ Token 用量 (64)      /token-usage
  └ 權限管理 (34)  [manage_accounts]   ← 新增節點
      ├ 使用者管理 (31)      /myusers
      └ 角色管理 (32)        /roleviews
```

根層順序變為：首頁 (1) → 專案管理 (2) → 資料定義 (5) → 系統管理 (3) → 登出 (4)。

「統計與分析」下五項的順序依**功能性質分組**手動指定：先日誌類（檢視／等級設定／例外紀錄），
再用量類（資料庫／Token）。

## 為什麼非改收合模式不可

`NavMenu.razor` 的 `collapsed-menu-flyout` 區塊原本只有兩層迴圈，且**只在 `child.Url` 非空時才輸出 `<a>`**。

新結構下「系統管理」的兩個子項都是群組（無 `url`），若不動這段，
**收合側邊欄時「系統管理」的 flyout 會完全空白** —— 七個頁面全部進不去。

## 收合模式同樣維持三層

第一版曾把第三層**展平**（群組名稱當小標題，七個連結一次列完）。實際看過畫面後改掉：
收合時也要維持階層，因此群組子項改成**一列可懸停的觸發鈕**（圖示 ＋ 名稱 ＋ `chevron_right`），
滑過去才往右彈出屬於它自己的第二層 flyout。

```
┌──┐
│🛡│──▶ ┌────────────────┐
└──┘    │ 📊 統計與分析 ›│──hover──▶ ┌──────────────┐
        │ 👤 權限管理   ›│           │ 日誌檢視      │
        └────────────────┘           │ 日誌等級設定  │
                                     │ 系統例外紀錄  │
                                     │ 資料庫用量    │
                                     │ Token 用量    │
                                     └──────────────┘
```

實作重點：

- 純 CSS 懸停，**不引入 JS、不新增展開狀態** —— `.collapsed-flyout-group` 當定位基準，
  `.collapsed-flyout-submenu` 只覆寫 `left`／`top`，視覺樣式沿用共用的 `.collapsed-menu-flyout`。
- 第二層有自己的透明 `::before` 橋接，寬度（1rem）刻意大於水平間距（實測 5px），
  否則滑鼠從群組列平移到第二層的途中會脫離 hover 而關閉。
- 群組列用 `<button>` 而非 `<a>`（它沒有 `url`），且**不寫 `aria-expanded`** ——
  純 CSS 懸停無法同步其真假值，寫了就是錯的中繼資料；比照第一層只用 `aria-haspopup="menu"`。
- 群組列以 `GetCollapsedFlyoutGroupClass()` 前綴比對標示 active。展平版本七項同時可見，
  一眼就知道在哪一頁；改巢狀後第三層預設收著，沒有這個標示使用者會失去所屬群組的線索。

## `:has(:focus-visible)`：為什麼不是 `:focus-within`

`NavMenu.razor.css` 原本的區塊註解寫著「顯示條件不含 `:focus-within`（避免點擊子項後焦點黏住不收合）」——
那是前人刻意移除的。但不含任何焦點條件，鍵盤使用者就永遠進不了 flyout（Tab 到第一個連結時
觸發鈕失去焦點，flyout 當場消失）。

改用 **`:has(:focus-visible)`** 同時滿足兩邊：`:focus-visible` 本身就會區分鍵盤與滑鼠，
滑鼠點擊不成立（點完即收，不退化成原本的 bug），鍵盤 Tab 才成立（可一路進入第二、第三層）。
區塊註解已一併改寫說明此事，**請勿再改回 `:focus-within`**。

瀏覽器需求：`:has()` 需 Chrome 105+／Safari 15.4+／Firefox 121+。

## 刻意不動的東西

- **`id` 全部沿用既有值**（6／61／62／63／64／31／32／33 不變），只新增 34。
  `id` 與位置無關（0.4.x 起已移除位置索引耦合），沿用讓 `MenuPermissionMap` 與
  `AdminOnlyPermissionTests` 的既有條目零改動，也不影響任何既存權限資料。
- **`RolePermissionService.GetRoleListPermissionAllName()` 未動** ——
  `角色_權限管理` 與整支系統管理一樣維持管理員專屬（不種 `Permission` 資料列、角色矩陣不顯示），
  由 `AdminOnlyPermissionTests` 守住，**請勿補上**。
- **`SidebarMenuNode.razor`／`SidebarMenuItemModel.cs`／`SidebarMenuService` 的遞迴邏輯未動** ——
  資料模型、權限過濾與展開模式渲染本來就是深度無關的，三層直接可用。
- 所有頁面路由（`url`）與檢視本身皆未變動，未新增或刪除任何頁面。
- **不做「第二層超出視窗高度時自動翻轉」** —— 系統管理位在第 4 列、第二層最多 5 項，
  實測高度遠低於視窗；沒遇到的問題不先寫程式。
- 收合鐵軌在 <641px 由 `.nav-scrollable-collapsed { display: none }` 整個隱藏，
  因此本次只影響 ≥641px，未為手機版另做處理。
