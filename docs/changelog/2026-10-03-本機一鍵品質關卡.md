## 目的

[路線圖 v2.0](../planning/00-腳手架強化路線圖.md) 的 A-1。專案沒有 CI（2026-09-20 移除），提交前的檢查原本是四條要手動逐一輸入的指令，
散落在十多份文件裡；弱點掃描則完全沒有自動化 —— 而且 `dotnet list package --vulnerable` 找到弱點時**仍回傳 0**，
就算有人記得跑，也要自己讀輸出才知道有沒有問題。

這次把它們收斂成**一支腳本、一行指令**。之後路線圖每一項都以它驗收；日後若要建 CI，也只要讓 CI 執行同一行指令。

## 二、設計決定

| 決定 | 理由 |
|---|---|
| 遇到失敗就停（使用者決定） | 建置失敗時跑測試沒有意義；最快得到答案 |
| Build／Test 用 **Release** | 與原 CI、部署產物一致；開發中的網站鎖住的是 Debug 的 `bin`，網站開著也能跑關卡 |
| 弱點掃描沿用原 CI 的允許清單規則 | 清單外的諮詢失敗；清單內的諮詢**不再出現也失敗**，讓豁免無法變成永久。清單移到腳本的 `$allowedAdvisories`（目前只有 `GHSA-2m69-gcr7-jv3q`）|
| 擷取弱點掃描輸出時暫時把 `[Console]::OutputEncoding` 設為 UTF-8 | 實測發現：dotnet CLI 輸出 UTF-8，PowerShell 卻用主控台字碼頁（cp950）解碼，中文訊息變亂碼。判斷靠諮詢代號所以不影響結果，但失敗時會看不懂訊息 |
| 未設定時把 `NUGET_HTTP_TIMEOUT_SECONDS` 設為 180 | 沿用原 CI 的做法，降低 restore 偶發逾時造成的假失敗 |
| hook 用 `git rev-parse --git-path hooks` 找目錄、以 LF 寫入 | 相容 worktree 與 `core.hooksPath`；Git for Windows 用 sh 執行 hook，CRLF 會讓指令帶著 `\r` |
| hook 已存在時拒絕覆寫，`-Uninstall` 只刪自己裝的 | 不破壞使用者原有的 hook |
