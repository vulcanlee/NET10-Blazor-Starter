## 目的

[路線圖 v2.0](../planning/00-腳手架強化路線圖.md) 的 A-2。0.9.89 之前約 1100 個測試**沒有一個會渲染 Blazor 元件**：
UI 的保證全靠 regex 掃原始碼，加上兩個檢查伺服器端 HTML 的整合測試，結果是「把畫面改壞了，品質關卡仍然全綠」。

這次加入 bUnit，建立共用測試基底與 4 個樣板測試類別，並把寫法寫進[測試指南 §5.1](../guides/測試指南.md)。
元件測試本身沒有修改產品程式碼；唯一的產品程式異動是品質關卡順帶抓到的一個既有競態（`Program.cs`，見第四節）。

## 二、設計決定

| 決定 | 理由 |
|---|---|
| 範圍是「基礎 + 數個樣板」（使用者決定） | 先把寫法定下來，之後改到哪個元件就順手補哪個，不一次全面覆蓋 |
| 「權限按鈕顯示與隱藏」**不做**，移到 G-21（使用者決定） | 判斷直接寫在三個頁面的標記裡，沒有獨立元件；頁面又依賴 `AuthenticationStateHelper.Check()`（查資料庫、要登入身分）與 Table 遠端資料來源。為了測試而改產品程式，超出 A-2 範圍 |
| 測試寫成 `.cs`，不改成 Razor SDK | 測試專案是 `Microsoft.NET.Sdk`；C# API 已足夠，不為了 `.razor` 測試改專案類型 |
| JSInterop 用 Loose 模式 | AntDesign 的 Button、Tooltip、Modal 內部會呼叫 JS；Strict 模式下每一個沒設定的呼叫都會讓測試失敗 |
| 基底只放兩件事 | 需要登入身分等服務的測試出現時再擴充 |
| 斷言 class、文字、元素類型與回傳值，不比對整段 HTML | 避免 AntDesign 升版或無關的標記調整讓測試大量失敗 |
| `CrudActionButton` 的停用狀態改為斷言 `disabled` 屬性 | 計畫原本寫「停用時點擊不觸發」，但 bUnit 不模擬瀏覽器「停用元素不送出點擊」的行為；真正決定使用者能不能點的是 `disabled` 屬性，所以斷言它 |

建置時沒有出現版本衝突警告：bUnit 相依的 `Microsoft.AspNetCore.Components` 10.0.10 與本機 ASP.NET 執行階段 10.0.12 相容。

## 四、品質關卡抓到的既有競態（使用者決定併入本次修正）

第一次跑完整關卡時，`EmailDisabledPagesTests.LoginPage_ShouldNotLinkToForgotPassword` 在 `Program.cs` 第 74 行丟 `NullReferenceException`。

**根本原因**：整合測試在同一個行程內依序啟動多個 host。前一個 host 被釋放後，它的 `Main` 在背景執行緒繼續執行到
`finally { LogManager.Shutdown(); }`，把全行程的 NLog 設定清成 null，時間點不受控制。`Program.cs` 原本先檢查
`LogManager.Configuration is not null`，接著**再讀兩次**同一個屬性；`Shutdown()` 只要落在兩次讀取之間就會讀到 null。
正式環境一個行程只有一個 host，不會發生。

**為什麼加入 bUnit 後才冒出來**（實測）：

| 環境 | 結果 |
|---|---|
| HEAD（0.9.89，無 bUnit），以 worktree 隔離執行 | 10 次 0 失敗 |
| 加入 bUnit 套件、排除元件測試 | 8 次 2 失敗 |
| 加入 bUnit 套件、全部測試 | 6 次 2 失敗 |

元件測試沒有執行時也會失敗，代表觸發因素是 bUnit **套件本身**：它帶進 AngleSharp 與數個 WebAssembly 組件，改變了組件載入的時間，
讓原本就存在的時間窗變大。競態不是 bUnit 造成的，bUnit 只是讓它變得常見。

**修正**：把設定先存進區域變數、只讀一次（`Program.cs` 的 NLog 區段，附註解）。修正後完整測試連跑 12 次全數通過。
沒有選擇在測試工廠裡「等前一個 host 結束」：測試端拿不到 `Main` 的執行緒，只能輪詢或延遲，比較脆弱。
