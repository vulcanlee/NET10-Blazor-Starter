# 文件與原始碼全面同步（.NET 11，0.10.18）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：0.10.18
- 首次實作版本：0.10.18
- 最後核對日期：2026/11/14

## 目的

這一輪依序完成了 .NET 11 升級（0.10.14）、畫面選項資料一致性（0.10.15）、全面實機探索（0.10.16）與探索後的改善（0.10.17）。程式一路在變，說明類文件卻有不少地方還停在 WASM 改寫前後、甚至 .NET 10 的寫法。使用者要求：逐份核對文件與原始碼，過時的改寫，已不存在的刪除；部署文件全面改成 .NET 11 的做法。

## 核對方式

- 範圍：`docs/` 下的說明類文件（architecture、features、guides、operations、security、prd 與各 README）、根目錄 `readme.md`、`scripts/e2e/README.md`、操作說明 `MyProject.Web/Datas/Help/*.md`，以及文件提到的程式註解與畫面提示文字。
- 方法：分批由代理逐份比對文件中的類別、方法、路徑、設定鍵、API 路由、畫面路由、按鈕與欄位、指令與套件版本，確認都還存在、行為也一致；有疑問的地方再回頭讀原始碼確認。
- **歷史紀錄類不動**：changelog 各篇、`docs/migration/` 的遷移計畫與測試報告、可行性分析都是當時的紀錄，保留原貌。

## 變更內容

### 1. 操作說明（`Datas/Help`，會隨網站發佈）

18 份操作說明對照目前畫面改寫：

- **0.10.15～0.10.17 的新行為補進說明**：分類、團隊名稱與帳號的即時重複檢查；開窗後別人停用了你新選的分類或團隊時的錯誤訊息（「所選的團隊「X」已不存在或已停用…」）；帳號格式、專案標題 200 字上限；搜尋框按 Enter 就搜尋。
- **WASM 改寫後已經不一樣的地方**：系統例外紀錄的「頁面」欄位現在通常是 `/api/v1/...`（畫面都經 Web API），範例與來源說明跟著改；來源 IP 是取每個 API 請求的連線。
- **資料保護金鑰的用途說清楚**：0.10.8 起登入改用 Token，金鑰只保護兩步驟驗證密鑰、記住的裝置與兩步驟驗證票證；備份、系統參數、系統健康的說明把「登入金鑰」等舊說法改掉。
- 其他：AI 相關頁的「使用模型」欄位、排程作業清除的資料（含寄信紀錄、已到期的登入 Token）、系統參數 `ClientSettings:BaseUrl`、首頁讀取失敗的提示、系統管理助理縮短保留期限的訊息等。

### 2. 程式註解與畫面提示文字

- `BackupView.razor` 的提示改成「備份含全部資料與資料保護金鑰…」。
- `SystemSettings.cs` 的 `DataProtectionKeyPath` 註解與 `appsettings.json` 的對應註解改成目前的金鑰用途與遺失的影響。
- `MenuPermissionConsistencyTests` 的註解改用 `Permissions.CanAccessPage`／`Permissions.IsAdmin`（0.10.8 以前叫 `CheckAccessPage`／`CheckIsAdmin`）。

這些都不改變行為。

- **架構**：開發慣例與限制速查、架構總覽、Web API 設計慣例、Web API 端點目錄、對話窗 UI 設計規範、DTO 與模型邊界規範、介面視覺設計規範、資料模型與資料庫等，對照目前的類別名稱、端點與權限規則（例如首頁 `PermissionRules.OpenToEveryone`）。
