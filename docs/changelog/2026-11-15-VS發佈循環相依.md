# Visual Studio 發佈循環相依（0.10.30）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：0.10.30
- 首次實作版本：0.10.30
- 最後核對日期：2026/11/15

## 目的

使用者 2026/11/15 回報：在 Visual Studio 用 FolderProfile 發佈 `MyProject.Web`（Release）失敗：

```
Microsoft.NET.Sdk.Publish.CopyFiles.targets(81,5): 錯誤 MSB4006: 目標 "Publish" 相關的目標相依性關係圖中包含循環相依性。
循環為 "Publish<-_CopyAspNetCoreFilesToIntermediateOutputPath<-CorePublish<-DotNetPublish<-_PublishBuildAlternative<-Publish"
```

## 原因

- Visual Studio 發佈時把 `DeployOnBuild=true` 設成**全域屬性**。Web 專案的流程是 `Build` → `DotNetPublish`（`AfterTargets="Build"`，條件是 `DeployOnBuild == true`）→ `CorePublish` → `Publish`，這一層沒問題。
- 同站台發佈時，`MyProject.Web.csproj` 的 `UseProcessedFrontendIndexHtml` 會用 `<MSBuild Targets="Publish">` 再發佈一次前端（拿處理過的 `index.html`，見速查表第 95 點）。`<MSBuild>` 會繼承外層的全域屬性，`RemoveProperties` 卻沒有拿掉 `DeployOnBuild`。
- 前端的流程因此變成 `Publish` → `Build` → `DotNetPublish`（又被 `DeployOnBuild` 觸發）→ `CorePublish` → `Publish`，形成循環。
- 命令列 `dotnet publish` 不會設 `DeployOnBuild`，所以品質關卡與 e2e 的 `-Published` 都沒踩到。

## 變更內容

- `MyProject.Web.csproj`：`UseProcessedFrontendIndexHtml` 的 `RemoveProperties` 加上 `DeployOnBuild`、`WebPublishProfileFile`（後者 VS 發佈也會帶；SDK 對專案參考也拿掉它）。註解寫明原因。
- 新增 `FrontendPublishConventionTests`：讀 `MyProject.Web.csproj`，確認 `RemoveProperties` 含 `DeployOnBuild`、`WebPublishProfileFile`、`PublishProfile`、`RuntimeIdentifier`。

## 測試與驗證

- **先重現**：`dotnet build src/MyProject/MyProject.Web -c Release -p:DeployOnBuild=true -p:PublishProfile=FolderProfile -p:PublishUrl=<暫存資料夾>`（等同 VS 的發佈方式），得到一樣的 MSB4006，錯誤發生在 `MyProject.Web.Client.csproj`。
- **新測試先紅後綠**：修改前 `DeployOnBuild`、`WebPublishProfileFile` 兩筆失敗，修改後全部通過。
- **修好後**：
  - 同一個命令發佈成功；`VerifyFrontendIndexHtml` 通過；輸出的 `wwwroot/index.html` 有 import map、沒有 `{fingerprint}` 佔位。
  - 一般的 `dotnet publish -c Release -o <暫存資料夾>` 照樣成功，`index.html` 一樣是處理過的版本。
- **品質關卡**：7 步（建置、格式、測試、文件編碼、CRUD 錨點、弱點掃描）全部通過。
- **VS 本身**：請使用者在 VS 再按一次發佈確認。

## 已知、沒有處理的

- 發佈時有一個 NETSDK1198 警告（前端專案找不到名稱為 FolderProfile 的發行設定檔）。它來自一般的專案參考建置，修改前就有，不影響發佈結果。
- 用 `UseArtifactsOutput`（建置輸出放 `artifacts/`）時，`UseProcessedFrontendIndexHtml` 的 `_FrontendPublishDir` 會被拼成兩段絕對路徑而失敗（`$(MSBuildProjectDirectory)\$(IntermediateOutputPath)`，後者在那種模式是絕對路徑）。一般建置、VS、`dotnet publish` 都不會遇到，這次沒改。
