# Production 啟動安全檢查的錯誤訊息改善（0.9.86）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：0.9.86
- 首次實作版本：0.9.86
- 最後核對日期：2026/10/03

## 起因

一台 IIS 主機啟動即中止，事件檢視器顯示：

> Production 啟動安全檢查失敗：EmailSettings:PublicBaseUrl 在 Production 使用 Smtp 時必須是完整的 http(s) 網址……

同一份程式碼在開發機執行完全正常，重新部署最新程式碼後仍是同樣錯誤。

## 根因

- **環境不同**：開發機以 `launchSettings.json` 的 `ASPNETCORE_ENVIRONMENT=Development` 執行，`StartupSafetyValidator` 對非 Production 環境直接略過；IIS 不讀 `launchSettings.json`，未設定環境時預設即為 `Production`。
- **設定不完整**：主機上的設定把 `EmailSettings:Provider` 設為 `Smtp`，但 `PublicBaseUrl` 留空。
- **重新部署無效**：該設定位於部署不會覆蓋的位置，改程式碼無法修正。

原本的訊息只說「必須是完整的 http(s) 網址」，看不出是沒填、少了 `http(s)://`，還是為什麼開發機沒事。

## 異動

`StartupSafetyValidator`：

| 項目 | 改版後 |
|---|---|
| 總訊息開頭 | 補上「ASPNETCORE_ENVIRONMENT 未設定時預設即為 Production，例如 IIS；開發機以 Development 執行不會做此檢查」 |
| `PublicBaseUrl` 錯誤 | 帶出目前讀到的值（空白顯示「（空白）」，否則以「」括起原值）、範例 `https://erp.example.com`、只有 http 的環境可填 `http://...`，以及「暫不寄信可將 `Provider` 改回 `None`」 |

公開網址不是機密，可直接寫入事件記錄；其他檢查項目（金鑰、密碼）的訊息不帶出值。檢查規則本身不變。

`ApiIntegrationTests` 的 Production 安全檢查測試同步加上對應斷言。`SystemVersion` 由 `0.9.85` 遞增為 `0.9.86`。

## 為什麼不改成自動偵測網址

曾評估「`PublicBaseUrl` 留白時改從請求自動組網址」。目前 `AllowedHosts` 為 `*`，自動取 Host header 會重新打開 password reset poisoning：攻擊者以偽造 Host 觸發忘記密碼，受害者收到一封真的重設信，連結卻指向攻擊者網站，token 隨之外洩。因此維持 Production 使用 Smtp 時 `PublicBaseUrl` 必填。

## 部署端修正方式

在主機設定補上使用者實際開啟系統的網址，例如 `"PublicBaseUrl": "https://erp.example.com"`（結尾不加 `/`），重啟應用程式集區即可。見 [正式部署與安全檢查清單](../operations/正式部署與安全檢查清單.md) 的「寄信」段落。
