# 衍生專案版本號重設為 1.0.0，並補齊腳本參數說明（0.9.71）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：0.9.71
- 首次實作版本：0.9.71
- 最後核對日期：2026/09/29

## 為什麼

`New-StarterProject.ps1` 原本不碰版本號，衍生專案會原封不動沿用腳手架當下的版本（例如 `0.9.70`）。
於是新專案的「關於」視窗、首頁系統資訊列、健康監控頁，以及保留下來的約 57 份文件開頭，
都顯示別人的版本歷史；而文件只把它列為手動待辦，容易漏掉。

另外 `腳手架開發指引.md` §2 前後矛盾（「八條警告」對「五條警告」），`-Force` 與 `-SourceProjectName`
兩個參數沒有任何文件提到，版本的預設值範例也停在 `0.9.35`。

## 做了什麼

- **腳本**：
  - Web 的 `appsettings.json` 的 `SystemVersion` 重設為 `1.0.0 (執行當天 yyyy/MM/dd)`，日期用 `InvariantCulture`。
  - `.md` 檔內「`- 現行系統版本：…`」一律改為 `1.0.0`。regex 用 `[^\r\n]*`，保留 CRLF 行尾；「首次實作版本」保留原值。
  - 結尾印出 `SystemVersion reset to …`；找不到時改印警告。
- **實測**：產生 `Demo.Verify` 專案，`appsettings.json` 為 `1.0.0 (2026/09/29)`，57 份文件頭全為 `1.0.0`。
  BOM 與 CRLF 行尾不變，新專案 `dotnet build` 與 `Test-DocsEncoding.ps1` 通過，殘留字串警告仍為 5 條。
- **腳手架開發指引 §2**：
  - 新增完整參數表。
  - 「八條」更正為「五條」。
  - §2.3 表格補上 `SystemVersion`。
  - 設定檔章節的版本預設值不再寫死舊版本號。
- **VS Code 上手指南 §7.4／§8.1**、**腳手架新專案啟動流程**：同步版本重設的說明，§8.1 連到參數表。

## 刻意不做的事

- 不新增「自訂起始版本」參數：目前沒有需求，要別的起點就產生完專案之後改一行。
- 不改「首次實作版本」：那是功能從腳手架哪一版開始存在的歷史，不是新專案的版本線。
