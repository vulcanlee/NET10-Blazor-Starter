# Agent 測試台的測試專案（0.9.145）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：0.9.145
- 首次實作版本：0.9.145
- 最後核對日期：2026/11/04

## 目的

想試 AI Agent 卻沒有專案資料時，要自己一筆一筆建很麻煩。這一版在「Agent 測試台」加上一鍵產生 10 筆繁體中文測試專案的按鈕，
完成後跳出說明窗，告訴使用者在「Agent 測試台」與「Agent 工作流程」可以怎麼問；用完可以一鍵永久清除。

## 一、畫面

「Agent 測試台」（`/agent-playground`）右上角、「新對話」旁多了兩個按鈕：

| 按鈕 | 誰看得到 | 做什麼 |
|---|---|---|
| 產生 10 筆測試專案 | 有「專案項目」**新增**權限的人（管理員一律可以）| 建立固定 10 筆專案，成功後跳出說明窗 |
| 清除測試專案 | 有「專案項目」**刪除**權限的人 | 危險確認後，永久刪除所有標題以「【測試】」開頭的專案（含已刪除的）|

- 已經有測試專案（含已刪除的）時再按「產生」，提示「已經有 N 筆測試專案（含已刪除的），請先按『清除測試專案』。」，不再新增，避免同名專案讓 AI 搞混。
- 說明窗列出建立的專案名稱，以及範例問句：
  - Agent 測試台：「列出所有【測試】專案，依狀態分組」、「哪些測試專案的狀態是『進行中』？各自的風險是什麼？」、「找出描述提到『延遲』或『逾期』的測試專案」、「把【測試】客服機器人的描述改成『已結案，移交客服部維運』」（會跳核准窗）。
  - Agent 工作流程：專案狀態報告輸入「幫我寫【測試】ERP 系統導入的狀態報告」；輸入「幫我寫資料相關專案的報告」會對到兩筆，AI 會先問你；多觀點審查可貼上任一專案描述。
  - 範例只問 Agent 測試台搜尋工具回傳得到的欄位（名稱、狀態、描述）；優先等級與日期要用 Agent 工作流程的「讀取專案明細」。

## 二、測試專案的內容

固定 10 筆，標題開頭「【測試】」，**不指定團隊**（看得到專案的人與 AI Agent 都查得到），日期以「今天」推算（所以「已逾期」永遠成立），描述都寫了進度與風險：

官網改版、ERP 系統導入、行動 App 第二期、客服機器人、資安稽核改善（已逾期）、資料倉儲建置、員工教育訓練平台、電子發票串接、倉儲條碼系統、會員資料整合；
狀態涵蓋進行中、未開始、已完成、暫緩、等待，優先等級高／中／低都有。

## 三、實作

- 新服務 `MyProject.Business/Services/Other/ProjectSampleDataService.cs`（Scoped）：`Build(today)`、`GenerateAsync(today)`、`ClearAsync()`。
- 一律經 `ProjectService`：新增走 `AddAsync`（`Project.Create` 稽核）、清除先 `DeleteAsync` 再 `PurgeAsync`（`Project.Delete`／`Project.Purge` 稽核），團隊範圍與驗證照常生效，不直接碰資料庫。
- 以標題**開頭**辨認測試專案（`ProjectService` 的搜尋是「包含」，服務再篩一次），標題中間才出現「【測試】」的專案不受影響。
- 某一筆建立或刪除失敗就停下來，回報已處理的筆數與原因。
- 說明窗 `.agent-playground-samples-modal`（寬度在 `OverlayStyles.razor`）。

## 四、測試

新增 `ProjectSampleDataServiceTests`（5 個）：固定資料都通過專案驗證且至少一筆逾期、產生後再產生被拒（已刪除的也擋）、清除永久刪除含已刪除的測試專案且不動其他專案、清除後可再產生、沒有測試專案時清除回 0 筆。
