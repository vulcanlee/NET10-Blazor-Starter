## 目的

[路線圖](../planning/00-腳手架強化路線圖.md) A-4 再拆成三項（使用者決定）：A-4a 樂觀並行（0.9.93）、**本次 A-4b 軟刪除（專案、分類、團隊）**、A-4c 軟刪除（使用者、角色）。

改動前一律實體刪除，誤刪無法救；而且五個頁面中有四個**不檢查刪除結果**，失敗也顯示「刪除成功」。使用者決定：

- 還原介面：各頁工具列的「**顯示已刪除**」，權限沿用該頁的刪除權限與團隊範圍。
- 永久清除：先做手動「永久刪除」；依保留天數自動清除留給 B-5 排程。
- 角色的「預設團隊」是名稱字串、不比對團隊表 → 團隊被刪後成員仍可經由角色預設團隊取得（與改動前的實體刪除相同）：**維持現狀、寫進文件**。
- 一併修正三個 API 的 POST 採用客戶端傳來的 `Id`（0.9.93 發現）。

## 二、設計決定

| 決定 | 理由 |
|---|---|
| 再拆成 A-4b／A-4c（使用者決定） | 使用者、角色的軟刪除牽涉登入、權限判斷、Google 登入、種子資料，風險類型不同；審查列出的必修點已記入路線圖 A-4c |
| 具名全域過濾器 | 所有既有查詢自動排除已刪除資料，不必逐一修改；需要看到已刪除資料的地方明確寫 `IgnoreQueryFilters([ISoftDeletable.FilterName])`，以後加別的過濾器也不會被一併關掉 |
| 部分唯一索引 | 已刪除的名稱可以重新建立；還原時由服務層重新檢查，衝突就擋下並說明，不讓資料庫錯誤冒出來 |
| 忽略 EF 警告 10622，改以規則約束 | 警告指的是「從相依端經必要導覽查詢時，相依資料列會隨主體被過濾而消失」。現有程式碼全部用明確 Join，審查已確認不會發生；規則（關聯表一律明確 Join，不可 Include 有過濾器的主體）寫進速查表 |
| 不在關聯表（UserTeam、ProjectFile）上加過濾器 | 會撞 `(MyUserId, TeamId)` 唯一索引，且還原後關聯必須回來 |
| 整筆覆蓋時 `ProtectFlags` | Blazor 的 attach + Modified 與 API 的 `SetValues` 會把畫面模型的 `IsDeleted = false` 寫回去，等於把已刪除的資料救活 |
| 刪除與還原都換新版本號 | 正在編輯同一筆的人存檔時會收到既有的「已被其他人修改或刪除」訊息，而不是把修改寫進已刪除的資料 |
| 永久刪除專案：先提交資料庫、成功後才刪附件實體檔 | 改動前是先刪檔，資料庫失敗時檔案已經不見 |
| 已刪除清單用獨立的 `GetDeletedAsync` | 共用的 `DataRequest` 也被日誌類服務使用，不在上面加旗標 |
| API 不提供還原與永久刪除 | 只在畫面上做；API 刪除後對同一筆的 GET／PUT／DELETE 回 404（`FindAsync` 套用全域過濾器） |

## 三、驗證（2026/10/04 實跑）

**審查抓到、照原草案會出錯的三個洩漏**，各寫測試，再故意改壞確認測試會失敗：

| 改壞方式 | 會發生的事 | 結果 |
|---|---|---|
| `ProtectFlags` 改成什麼都不做 | 編輯一筆剛被別人刪掉的資料（舊版本號剛好對得上的情況）會把它救活 | 測試**失敗** |
| 拿掉附件下載的「父專案不存在」檢查 | 已刪除專案的附件變成任何人都能下載（`IsTeamAccessible(null)` 的語意是「公開」） | 測試**失敗** |
| 拿掉 `UserTeam` 的保留邏輯 | 編輯使用者會刪掉他和已刪除團隊的綁定，團隊還原後成員關係回不來 | 測試**失敗** |

**真實瀏覽器**（Playwright 驅動本機 Edge；所有外部路徑與日誌都指向暫存目錄，`C:\temp\MyProject` 無任何新檔）：

- 分類：新增 → 刪除（確認窗文字為新版）→ 從清單消失 → 「顯示已刪除」看到它（有刪除時間、刪除者 `support`，新增鈕隱藏）→ 還原 →「還原成功」、回到一般清單 → 再刪除 → 永久刪除 →「已永久刪除」→ 用同名再新增成功。
- 專案附件：上傳 1 個檔 → 下載 200 → 刪除專案後實體檔**仍在**、下載回 **404** → 已刪除模式下分類／團隊過濾隱藏 → 永久刪除（確認窗提醒附件一併刪除）→ 實體檔**消失**。

**品質關卡**：`Invoke-QualityGate.ps1` 完整通過（1203 個測試）。

## 四、驗證中觀察到的既有現象（未修）

  只用改動前就有的功能（分類頁按「重新整理」後整頁換頁 3 次）即可重現約 100 筆，與本次改動無關。這些是雜訊，但會進入系統例外紀錄，建議另行處理。
