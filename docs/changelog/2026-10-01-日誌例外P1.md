# 日誌與例外處理 P1：錯誤追蹤碼、例外告警、自動保存期限、稽核補齊（0.9.78）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：0.9.78
- 首次實作版本：0.9.78
- 最後核對日期：2026/10/01

## 為什麼

[日誌與例外處理 PRD](../prd/日誌與例外處理-prd.md) 的 P1 是「可追蹤性與主動通知」，對應下列問題：
- 使用者回報「剛剛出錯了」時，管理員對不上是哪一筆日誌。
- 嚴重例外沒人主動通知。
- 例外與稽核紀錄只能手動清除。
- 分類、團隊、專案的增刪改，以及登出、SSO 等事件都沒有稽核。
- 名稱重複這類使用者錯誤被記成系統例外。
- 幾個類別沒有日誌。
- 帶 Id 的 API 路徑讓同一個錯誤散成好幾列。

## 做了什麼

| 編號 | 內容 |
|---|---|
| LOG-10 錯誤追蹤碼 | 每個 HTTP 請求與每次 Blazor 互動產生一個 8 碼追蹤碼（`TraceCode`）：<br>• HTTP 請求直接取代 `TraceIdentifier`，API 回應、`/Error` 頁、日誌檔的碼一致。<br>• 例外紀錄新增 `LastTraceId`（migration `AddExceptionLogLastTraceId`），顯示在明細窗、點列複製與 CSV，關鍵字也能搜。<br>• 錯誤邊界、`/Error` 頁（改成中文）、表單儲存失敗與 18 處「…失敗：{型別}」通知會附上「錯誤追蹤碼：xxxx」。<br>• `ApiServerError` 帶 `TraceId`。<br>• `/logs` 新增「錯誤追蹤碼」篩選。 |
| LOG-11 | 分類、團隊撞到唯一索引時改記 Information，不進例外紀錄。專案刪除時的外鍵衝突改為先判斷再記錄，並補上 SQLite 的錯誤訊息。 |
| LOG-12 例外告警 | `ExceptionAlertService` 與 `ExceptionAlertSettings`：<br>• 觸發條件：新種類例外、Critical、暴增。<br>• 節流：同一種例外有冷卻時間，另有每小時上限，超過的筆數併入下一封。<br>• 信件只含摘要，出貨預設停用。 |
| LOG-13 自動保存期限 | `LogRetentionWorker` 搭配 `LogRetentionSettings`：例外紀錄保留 90 天、稽核保留 365 天，每日清理並寫 `*.AutoPurge` 稽核。兩頁的手動清除改讀同一組天數。 |
| LOG-14 稽核補齊 | 動作代碼集中到 `AuditActions`，由 `AuditConventionTests` 守門。新增以下事件：<br>• 分類、團隊、專案的增刪改（畫面與 API 都記）。<br>• 專案附件上傳與刪除。<br>• 登出。<br>• Google SSO 的成功、失敗、停用、帳號連結、自動建立。<br>• 自行變更密碼。<br>• JWT 刷新失敗。<br>• Blazor 頁面權限拒絕（14 頁）。<br>• 例外紀錄與 Token 用量的刪除、清除、清空。<br>• 五個頁面的匯出。<br>• 自動清理。 |
| LOG-15 | 為下列項目補上日誌：<br>• `JwtTokenService`<br>• `ApiValidationFilterAttribute`：只記欄位名稱。<br>• `DatabaseHealthCheck`<br>• `RecordAccessScopeProvider`<br>• 登出：記錄帳號。<br>「必有 ILogger」的慣例測試擴大到 `Web/Auth`、`Web/Filters`、`Web/Health`。 |
| LOG-16 | API 例外的「頁面」改記路由樣板，例如 `/api/Category/{id}`。 |

- 新增設定區段：`LogRetentionSettings`、`ExceptionAlertSettings`。兩份設定文件（操作文件 §4.11、§4.12 與開發指引）同步更新。
- **測試**：
  - 新增單元測試：`TraceCodeTests`、`ExceptionAlertServiceTests`、`LogRetentionWorkerTests`、`AuditConventionTests`（後兩者以假時鐘 `ManualTimeProvider` 驗證）。
  - 新增整合測試三項：追蹤碼與例外紀錄一致、`ApiServerError` 帶追蹤碼、路由樣板。
  - 擴充既有測試：服務稽核、追蹤碼篩選、`LastTraceId`。
- **驗證結果**：
  - 全部測試由 1,018 項增為 1,051 項，全數通過。
  - 移除 `ApiServerError` 的 TraceId 與路由樣板後，對應測試都會轉紅（已實測）。
  - 實機啟動確認 HTTP 請求的日誌行第 2 欄為 8 碼追蹤碼，`LogRetentionWorker` 於啟動時執行。
- `SystemVersion`：`0.9.77 → 0.9.78`。

## 刻意不做的事

- **不新增日誌欄位**：PRD 原規劃新增 TraceCode 欄，改為沿用原本的 TraceId 欄位，欄位數維持 7 個。這樣舊日誌檔、`/logs` 解析與 AI 日誌分析都不用改。
- **一般驗證訊息不附追蹤碼**：只有「未預期例外」才附，例如「名稱重複」就不附。
- **不修正 API 的紀錄存取範圍問題**：補日誌時發現 `RecordAccessScopeProvider` 用 `Sid` 找使用者，但 JWT 沒有 `Sid`，因此 API 使用者只看得到公開紀錄。這屬於權限行為，已列入 PRD §十 待另案處理。
- **Blazor 互動的追蹤碼與浮層錯誤提示，尚未在瀏覽器內人工觸發驗收。**
- **P2 不在本次範圍**：瀏覽器錯誤回報、慢操作、管線自我監控（LOG-20～22）。
