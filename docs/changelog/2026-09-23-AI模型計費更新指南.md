## 為什麼

OpenAI 經常推出新模型或調整價格，而 `AiPricingSettings` 是人工抄錄、不會自動更新的。
費用是呼叫當下的快照，**漏更新的那段期間永遠是「未定價」，不回補**。

過去的維護方式散在四處（日誌與設定檔說明 §4.9.5、LLM 呼叫費用估算 PRD §7、兩篇定價 changelog），
沒有一份從頭到尾的步驟；`models/all` 這個盤點用的網址只在一篇 changelog 出現過一次。

## 做了什麼

- 新增 [AI 模型計費更新指南](../operations/AI模型計費更新指南.md)：人與 AI 都能照做的逐步流程。
  - 查詢順序：`models/all`（盤點、看 Deprecated）→ 各模型頁（抄價格與門檻）→ pricing 頁（交叉核對）。
  - 先產出**盤點表**給人確認，才修改。
  - 四種情況：既有模型調價、新增模型、Deprecated（先看 `/token-usage` 近 30 天用量才刪）、
    計算方式改變（一律先討論）。匯率 `UsdToTwd` 列為選擇性步驟。
  - 收尾檢查表與給 AI 助手的執行守則。
- `CLAUDE.md`、速查表 §6.7、日誌與設定檔說明 §4.9.5、PRD §7 #7 加上指向指南的連結；
  三處索引（`docs/operations/README.md`、`docs/README.md`、根目錄 `readme.md`）登錄新文件。

### 已知的來源差異：`gpt-4o-transcribe-diarize`

- pricing 頁：`$0.006 / minute`，另加 input `$2.50`、output `$10.00`（每 1M token）—— 與現行設定一致。
- 模型頁：只寫「Audio Input $2.5 / 1M tokens」「Audio Output $10 / 1M tokens」，**沒有列每分鐘價格**。

數字本身沒有衝突，差在標示方式。經確認**以 pricing 頁為準、維持現狀**。
若日後要改成模型頁的「音訊 token」計價，那需要新的計費單位，屬於指南的情況 D，必須另行討論。

### 過程中發現並修正的指南漏洞

- 模型總數與清單實際寫在**五處**，不是原本以為的三處（漏了 PRD §4.2 逐一列舉模型名稱的段落，
  以及腳手架開發指引後段的第二處「11 個模型」）。指南改成**先 grep 再改**，不只依賴固定清單。
- `AppSettings_ShouldPinNonTextBillingUnits` 用的是逐行 `Assert`，不是 `InlineData`。指南已更正寫法。
