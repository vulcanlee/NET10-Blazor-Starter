# AI 分析的通知位置與失敗診斷修正（0.9.6）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：0.9.6
- 首次實作版本：0.9.6
- 最後核對日期：2026/09/11

## 問題

實際接上 Azure OpenAI 試跑之後回報兩件事。

**通知出現在畫面頂端。** 日誌檢視頁用的是 `MessageService`（AntDesign 頂部輕量 toast），
與專案其他頁面的右下角卡片不一致。AI 分析的階段提示與失敗原因都偏長，頂部那一條容易
被截斷，也容易被忽略。

**失敗了卻看不出原因。** 按下 AI 分析後得到「AI 服務拒絕本次請求（代碼
`unsupported_value`）」，而日誌裡只有：

```
ERROR|MyProject.Web.Ai.AiLogAnalysisService|AI log analysis upstream failure. StatusCode=400, ErrorCode=unsupported_value, Entries=30
```

代碼只說「有個值不受支援」，**完全看不出是哪一個參數**。

根因是 `temperature`：推論模型（o 系列、gpt-5 家族）只接受它的預設值，送 `0.2` 就會被
回 400。但這件事從當時的日誌與訊息都推不出來。

之所以會這樣，是 0.9.4 刻意訂的規則：錯誤訊息只能由固定字串加 `error.code` 組成，
絕不回吐上游回應 body —— 因為 body 可能夾帶整份提示詞，也就是日誌內容。這個顧慮本身
沒錯，但做得太絕，把唯一的線索也一起擋掉了。

## 改了什麼

### 一、通知改到右下角

日誌檢視頁的所有提示改走 `ViewNotification`（右下角卡片），不再用 `MessageService`。
不只 AI 分析，連既有的日誌匯出提示也一起改 —— 同一頁出現兩種位置的通知看起來像故障。

共用元件 `ViewNotification` 新增 `Info` 方法（藍色資訊圖示）。原本只有 `Warning`、
`Error`、`ValidationError` 三種；CRUD 的「新增成功」沿用 Warning 外觀是既有約定，但
「正在送出中」配上橘色警告圖示會讓人以為出了問題。其他頁面的既有外觀不受影響。

### 二、失敗原因變得可診斷

`AiChatResponseParser.TryGetErrorCode` 換成 `TryGetError`，改為回傳
`AiUpstreamError`，多讀三個欄位：

| 欄位 | 用途 | 安全性 |
|------|------|--------|
| `Code` | 例如 `unsupported_value` | 原本就有 |
| **`Param`** | **出問題的參數名稱**，例如 `temperature` | 純參數名稱，結構上不可能夾帶日誌內容 |
| `Type` | 例如 `invalid_request_error` | 固定列舉值 |
| **`Message`** | 上游的說明，**截斷至 300 字元** | 見下方說明 |

日誌現在記的是：

```
StatusCode=400, ErrorCode=unsupported_value, ErrorParam=temperature,
ErrorType=invalid_request_error, ErrorDetail=Unsupported value: 'temperature' does not
support 0.2 with this model. Only the default (1) value is supported., Entries=30
```

⚠️ `ErrorDetail` 的 300 字元截斷是必要的，不是保守：上游對某些錯誤（例如內容過濾）的
說明可能夾帶提示詞片段，而提示詞裡是上百筆日誌。不截斷會把日誌檔撐爆，也可能讓同一段
內容在日誌裡反覆堆疊。300 字元夠放一句完整的錯誤說明，又短到塞不進有意義的日誌內容。

至於「日誌內容寫回日誌檔算不算外洩」——不算，那本來就是同一份資料的來源。
原本的顧慮（`AuditLog` 的可視範圍比日誌檢視頁更廣）只適用於稽核明細，那一條維持不變：
**`AuditLog` 的 `Detail` 仍然只寫數量、模型、用量與耗時。**

使用者看到的訊息也跟著具體化：

| 情況 | 訊息 |
|------|------|
| 模型不接受 `temperature` | 此模型不接受 AiSettings:Temperature 的設定值，請將它設為 `null`（部分推論模型只接受預設值）。 |
| 其他參數被拒 | AI 服務不接受參數 `<參數名>` 的設定值（代碼 `<code>`），請調整 AiSettings 後再試。 |
| 上游沒給 `param` | 沿用原本的通用訊息 |

`temperature` 特別開一個分支，是因為它是切換模型時最常撞到的一個，直接講修法比讓人
自己去猜有用。

### 三、`Temperature` 預設改為 `null`

預設不送這個參數，由模型自己決定。推論模型只接受預設值，而一般模型不送也會用自己的
預設值 —— 不送就能相容所有模型，要調的人再自己填。這是上面那個故障的根治。

## 改動檔案

- `Components/Commons/ViewNotification.cs` — 新增 `Info`
- `Components/Views/Analytics/LogViewerView.razor.cs` — 注入改為 `NotificationService`，
  18 處提示全部改走 `ViewNotification`
- `Ai/AiModels.cs` — 新增 `AiUpstreamError`
- `Ai/AiChatResponseParser.cs` — `TryGetErrorCode` → `TryGetError`，含截斷
- `Ai/AiLogAnalysisService.cs` — 日誌多記三欄；新增 `DescribeBadRequest`
- `Configuration/AiSettings.cs` — `Temperature` 預設改 `null`
- `appsettings.json` — `"Temperature": null`；`SystemVersion` 0.9.5 → 0.9.6

- `dotnet test`：440 支全綠（AI 相關從 175 增為 181）。
- `dotnet build`：0 警告。`dotnet format --verify-no-changes`：無差異。
- 文件編碼檢查零失敗。
- 新增六支測試涵蓋：`param`／`type` 解析、長訊息截斷、只有 `message` 的錯誤、
  預設不送 `temperature`、明確設值才送、`temperature` 被拒時的訊息要指名修法、
  其他參數被拒時要指名參數。
