# 小型浮層果凍化：確認窗、通知與消息條（0.9.26）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：0.9.26
- 首次實作版本：0.9.26
- 最後核對日期：2026/09/18

## 為什麼改

0.9.25 把大量資料輸入對話窗做成粉梅暖雪果凍，但**只有那一種窗變了**。
刪除確認這類小窗仍是 AntDesign 的預設白盒子、直角、無毛玻璃，
跟旁邊的果凍表單窗擺在一起明顯是兩套視覺。

調查時另外找到三個實質問題：

1. **`OverlayStyles`（原 `FormModalHelper`）散在九個檢視與 `MainLayout` 裡。**
   AntDesign 把對話窗、確認窗、通知與消息條全部渲染在 `Routes.razor` 的 `AntContainer` 底下，
   與 layout 無關 —— 用別的 layout 的頁面（登入頁的 `NoFooterLayout`、首頁的 `EmptyLayout`）
   整組吃不到樣式，而那種缺失只有打開那一頁才看得出來。
2. **六處破壞性操作長得像一般提醒。** `ExceptionLogView` ×3 與 `TokenUsageView` ×3
   是刪除／清空，卻都沒有 `OkButtonProps.Danger`、也都沒有 `MaskClosable = false`
   —— **誤點遮罩就直接執行了不可復原的動作**。
3. **大表單窗同時跑著兩個進場動畫。** AntDesign 的 `antZoomIn` 掛在 `.ant-modal` 上，
   0.9.25 的 `fm-arrive` 掛在 `.ant-modal-content` 上，兩者疊加，
   實際彈跳幅度比設計時選定的更誇張。

## 改了什麼

### 樣式收成單一渲染點

`Components/Commons/FormModalHelper.razor` 更名為 **`OverlayStyles.razor`**
（它現在同時承載表單窗、確認窗、通知與消息條的樣式，原名已名不符實），
從九個檢視與 `MainLayout` 移除，改在 `Components/Routes.razor` 的 `AntContainer` 旁渲染**一次**。

### 確認窗（`.ant-modal-confirm`）

**不滿版**：440px、圓角 24px、`blur(20px)` 毛玻璃、`cfm-arrive` 380ms 短版擠壓回彈。
確認窗出現頻率高（每刪一筆就跳一次），動作太大或太久都會變成干擾。

破壞性動作（刪除／清空／放棄變更）轉**紅調**：邊框、光暈與圖示偏紅。

### 通知與消息條

- 右下角通知（`.ant-notification-notice`）：圓角 18px、`blur(14px)`、右側滑入＋回彈。
- 頂部消息條（`.ant-message-notice-content`）：膠囊形、`blur(14px)`、由上落下＋回彈。

⚠️ **圖示的語意色（成功綠／錯誤紅／警告橘／資訊藍）刻意不動。**
為了視覺統一把錯誤訊息染成粉紅，等於拿掉使用者最先讀到的那個訊號。

### 中和 AntDesign 的 `antZoomIn`

`.ant-modal.ant-zoom-enter { animation: none !important; transform: none !important; }`
—— 果凍動畫成為唯一的進場效果，大表單窗的實際彈跳幅度因此與設計時選定的一致。
離場動畫（`antZoomOut`）保留不動。

### 確認窗文案與參數收斂

新增 `Components/Commons/ConfirmDialog.cs`：

| 方法 | 用途 | 自動帶入 |
|------|------|----------|
| `AskDestructiveAsync` | 刪除、清空、放棄變更 | `Danger`、`MaskClosable = false`、`ZIndex = 1100` |
| `AskAsync` | 一般確認與提醒 | `MaskClosable = false`、`ZIndex = 1100` |
| `AskDeleteRecordAsync` | 五個 CRUD 檢視共用的「刪除這一筆」 | 同 `AskDestructiveAsync` |

15 處呼叫全部改走樣板；`FormEditConfirm` 與 `TeamBindingConfirm` 保留原有公開 API，
內部委派給 `ConfirmDialog`。具體文案仍由呼叫端提供 ——「清除 30 天未再發生的紀錄」
這種訊息有資訊價值，不該為了收斂被壓成罐頭句子。

## 行為變更（需告知使用者）

- **例外紀錄與 Token 用量的六處刪除／清空，現在點遮罩不會再直接執行**，
  且確認窗會是紅調，與一般提醒有明顯區別。
- 其餘確認窗的文案與按鈕不變，只有視覺改變。

## 為什麼紅調要靠 `Danger` 當 hook

`ConfirmOptions.ClassName` 會被 AntDesign 的 `Confirm::BuildDialogOptions` **無條件覆寫**成
`"ant-modal-confirm ant-modal-confirm-" + ConfirmType`，呼叫端給的 class 會被丟掉，
**個別確認窗無法掛自訂 class**。因此改用 `.ant-modal-confirm:has(.ant-btn-dangerous)`
—— 以「確定鈕是 Danger」當 CSS hook。`:has()` 不支援時只是退回粉梅（按鈕本身仍是紅的），
屬漸進增強。

這也是為什麼 `Danger` 必須由樣板統一設定：少設一次，那個窗就不會轉紅調。

## 守門

`MyProject.Tests/FormModalConventionTests.cs` 從四項增為六項，新增：

- `Components/Commons/` 之外不得出現 `ConfirmAsync(`。
- `<OverlayStyles />` 只能在 `Routes.razor` 出現，且恰好一次。
