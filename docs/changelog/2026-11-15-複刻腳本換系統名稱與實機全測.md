# 複刻腳本換系統名稱與實機全測（0.10.24）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：0.10.24
- 首次實作版本：0.10.24
- 最後核對日期：2026/11/15

## 目的

使用者 2026/11/15 要求實際用 `scripts/New-StarterProject.ps1` 產生一個新專案（`Acme.Erp`／「艾克米企業系統」），把腳本的每項功能、新專案的每個畫面都實際測過，並確認**啟動畫面、登入畫面與每一頁顯示的都是新專案的名稱**。先用 0.10.23 測現狀，修正後再重新產生、完整測試。

## 測現狀（0.10.23）找到的問題

1. **新專案的實機腳本不能用**：`scripts/e2e/*.mjs` 的副檔名不在腳本的 `$textExtensions`，沒有被改名。新專案的 `common.mjs` 仍預設連 `localhost:7144`（腳手架的埠）、讀 `myproject.auth`（新專案是 `acme.erp.auth`），`explore-perm.mjs` 讀 `src/MyProject/...`。實測：新專案的 `Test-CrudGenerator.ps1` 產生、建置、3,255 個測試都通過，最後的實跑一步 `ERR_CONNECTION_REFUSED at https://localhost:7144`；照 README 直接跑 `smoke-routes.mjs` 也一樣。
2. **畫面上的系統名稱留在腳手架的「企業管理平台」**：腳本只換程式代號，系統名稱與簡介要手動改四處（`appsettings.json`、`manifest.webmanifest`、`index.html` 首次載入卡片、`ClientLoadingScreen.razor`）。名稱檢查 50 項有 47 項不符。`manifest.webmanifest` 的副檔名也不在 `$textExtensions`。
3. **啟動頁的分頁標題是範本殘留的英文「Home」**。
4. **新代號含舊代號時殘留掃描印出大量假警告**：從 `Acme.Sn` 衍生 `Acme.Sn2` 時，每個 `Acme.Sn2` 都含 `Acme.Sn`，實測印出 5,920 條警告，真正沒換到的東西會被淹沒。

腳本的其他功能（名稱驗證、缺少或過舊的 dotnet-ef、來源有未提交檔／不在預設分支／落後 origin、目的地已存在、`-Force`、`-KeepStarterHistory`、`-UserSecretsId`、`-AllowUnsyncedSource`、從衍生專案再衍生一代）都照設計運作；產生 Init 時沒有寫進開發機的 `C:\temp`；新專案品質關卡 7 步通過（3,207 個測試）。

## 變更內容

### 複刻腳本 `scripts/New-StarterProject.ps1`

- 新增 **`-SystemName`（必填）** 與 **`-SystemDescription`（選填）**：來源的名稱與簡介從來源 `appsettings.json` 讀（比照連接埠從 `launchSettings.json` 讀，再往下衍生一代也換得到）。**只換固定位置**（`$systemNameTargets`）：`appsettings.json` 的 `SystemName`／`SystemDescription`、`manifest.webmanifest` 的 `name`／`short_name`、`index.html` 的 `app-loading-title`、`ClientLoadingScreen.razor` 的 `FixedSystemName`、操作說明的信件主旨範例 `[名稱]`；必換的位置沒換到時結尾列出檔案。長度上限與「系統參數」頁相同（50／200 字），擋掉 `"`、`\`、`<`、`>`、`&`、`|`、`\p{C}`（控制、格式、私用區字元）、`\p{Zl}\p{Zp}` 與頭尾空白（會弄壞 JSON、HTML、C# 字串與說明的表格）。
- 名稱與簡介先換成私用區字元的佔位字串、代號取代做完才放新值（新名稱含舊代號也不會被改到）。
- `$textExtensions` 加入 `.mjs`、`.webmanifest`。
- 殘留掃描判斷前先把新代號從該行拿掉，新代號含舊代號時不再誤報。
- 結尾印出 `SystemName set to '<新名稱>' (was '<舊名稱>')`。

### 啟動頁分頁標題

- `Pages/SplashPage.razor` 的 `<PageTitle>Home</PageTitle>` 移到 `Views/Commons/SplashView.razor`，改成系統名稱（`SplashView.ResolveTabTitle`：設定還沒讀到時顯示「系統啟動中」）。

### 測試（3,212 → 3,230）

- `ScaffoldScriptConventionTests`：
  - `EveryFileWithTheCodeName_ShouldHaveAnExtensionTheScriptRewrites`：整個 repo 裡含專案代號的文字檔，副檔名都要在腳本的 `$textExtensions`（先看到它抓出 7 支 `.mjs`；跳過 `TestResults`、`.trx`、`.log` 等本機產物）。
  - `SystemNameTargets_ShouldExist_AndContainTheShippedName`：`$systemNameTargets` 的每個必換位置存在、含出貨的系統名稱、副檔名在 `$textExtensions`。
  - `StarterScript_ShouldRequireASystemName_WithTheSameLimitsAsTheParameterPage`：必填、長度上限與 `SystemParameterCatalog` 相同、來源名稱與簡介從來源 appsettings 讀。
  - `StarterScript_SystemNamePattern_ShouldRejectCharactersThatBreakTheReplacedFiles`（13 組，含 `|`、U+2028、私用區字元）：以腳本裡實際的樣式驗證可接受與要擋的值。
  - `StarterScript_ResidualScan_ShouldIgnoreTheNewCodeNameThatContainsTheOldOne`。
  - `NoFile_ShouldContainTheBarePlaceholderPrefix` 改讀腳本的 `$textExtensions`，不再自己抄一份清單。
- `LoadingAndStatusPageTests.SplashTabTitle_ShouldBeTheSystemName_OrStartingUpBeforeTheSettingsArrive`。

## 驗證

- 本倉庫：新增的測試先失敗再通過；品質關卡 7 步通過（3,230 個測試）。
- 獨立審查指出兩個會在「從衍生專案再衍生」時出錯的問題，已修正並實測：系統名稱原本是全檔取代，名稱剛好是代號（`Acme`）或常見詞時下一代會把命名空間與文件一起改壞——改成只換固定位置；腳本測試原本斷言「腳本不含系統名稱」，名稱是腳本裡出現的字時衍生專案一出生就紅燈——改成檢查讀取方式。另採納：佔位字串改用私用區字元（原本含英文大寫，可能被大寫代號換壞）、名稱再擋 `|` 與行／段落分隔字元、副檔名檢查跳過本機產物。實測 `Acme`／「Acme」→ `Beta`／「Beta 平台」：「Beta 平台」只出現在 5 個固定位置，892 行 `namespace Beta.` 完好。
- 修正後的腳本實際執行：沒給 `-SystemName` 被擋（非互動）、`A"B`、`A<B>`、`A&B`、頭尾空白、51 字名稱、201 字簡介都在一開始被擋下且沒有建立目錄；產生的專案找不到「企業管理平台」與舊簡介；從衍生專案再衍生（`Acme.Sn` → `Acme.Sn2`、名稱 → 名稱二代）零警告，刻意放的殘留仍被抓到。
- 以修正後的腳本重新產生 `Acme.Erp`／「艾克米企業系統」並完整實機測試（詳細結果在本次的測試報告，不在 repo 內）：
  - 新專案品質關卡 7 步通過（3,225 個測試，少的 5 個是腳本刪掉的腳手架 migration 測試）；`Test-CrudGenerator.ps1` 通過，含修正前失敗的 WASM 實跑一步（3,273 個測試、三個產生的頁面新增修改刪除還原）。
  - 新專案自己的 `scripts/e2e` 全部情境：36 支腳本執行、833 項通過、0 失敗（每組一個全新的隔離主機；含真實模型的 AI 情境、雙站台、發佈版 PWA、效能量測、看得到的 Chrome 巡檢）。
  - 名稱檢查 50 項：修正前 3 項通過，修正後 50 項全過（首次載入卡片、啟動頁與分頁標題、登入／忘記密碼／重設密碼、首頁、側邊欄、「關於」、每個路由沒有舊名稱）；系統寄出的信件主旨與寄件者也是新名稱。
- 實機時另外發現並修正 `scripts/e2e/explore-ops.mjs` 的時區問題：O2 用 `toISOString()`（UTC）算「明天」，在台灣 00:00～08:00 會算成今天，伺服器照規則接受而誤判失敗；改用本機日期。
