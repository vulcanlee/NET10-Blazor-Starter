# 側邊欄「首頁」圖示由 `space_dashboard` 改為 `home`（0.9.10）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：0.9.10
- 首次實作版本：0.9.10
- 最後核對日期：2026/09/16

## 起因

使用者指著側邊欄「首頁」那一格的圖示反映：**不像「首頁」，語意不對**。

`Menu.json` id=1 原本用 `space_dashboard`，畫出來是一個被切成格子的矩形，
讀起來像「版面／儀表板」。而側邊欄**預設是收合狀態**
（`MainLayout.isSidebarCollapsed = true`），收合時只剩圖示、沒有文字 ——
圖示必須自己撐起語意，`space_dashboard` 撐不起來。

## 變更內容

| 檔案 | 異動 |
|------|------|
| `src/MyProject/MyProject.Web/Datas/Menu.json` | id=1 的 `icon` 由 `space_dashboard` 改為 `home` |
| `src/MyProject/MyProject.Tests/MenuIconTests.cs` | `AllowedIcons` 新增 `"home"` |
| `src/MyProject/MyProject.Web/appsettings.json` | `SystemVersion` 0.9.9 → 0.9.10 |

**白名單為什麼一定要同步加**：`MenuIconTests.AllowedIcons` 是一份人工維護的允許清單，
`Menu.json` 只要出現清單外的名稱，`MenuJson_AllIcons_ShouldBeNonEmptyAndAllowed` 就會失敗
並指名該圖示。這是刻意的設計 —— 強迫開發者先確認新名稱真的是有效的 classic Material Icons，
再放行。

**為什麼 `home` 是安全的選擇**：它是最早期的 classic Material Icons 之一，
確定存在於 `App.razor` 載入的字型中（不像 0.9.9 踩到的 `shield_person`，
那是 Material Symbols 專有名稱，會被拆成「盾」與「人」兩個圖示）。
且 `NavMenu.GetMaterialIconKind` 與 `SidebarMenuNode.GetMaterialIconKind`
都已有 `"home" => "home"` 這條對應，**不需要動任何 C# 映射邏輯**。

## 刻意不動的東西

- **`AllowedIcons` 的 `space_dashboard` 保留**。改完後 `Menu.json` 確實不再使用它，
  但它仍是一個「已確認有效」的 classic 名稱，且兩支 `GetMaterialIconKind` 還有
  `"dashboard" => "space_dashboard"` 把它當成映射目標。留著零成本。
- **`docs/changelog/2026-06-22-側邊欄群組圖示.md`**（0.4.4）內文仍寫「首頁 `space_dashboard`」——
  那是當時的歷史紀錄，不回頭改寫。
- 側邊欄左上的品牌圖示（`NavMenu.razor:14` 的 `dashboard_customize`）是另一個東西，未動。
- 權限、路由與選單順序皆未動（圖示與權限無關）。
