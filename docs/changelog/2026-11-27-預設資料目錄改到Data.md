# 預設資料目錄改到 C:\Data（0.10.47 → 0.10.48）

- 日期：2026/11/27
- 版本：0.10.47 → 0.10.48
- 起因：使用者擔心預設把資料存在 `C:\temp` 底下，暫存區常被系統或人工清理，資料庫、金鑰、備份會被誤刪。

## 變更

- `appsettings.json`：`SystemSettings:ExternalFileSystem` 的 12 個資料目錄與 `EmailSettings:PickupDirectory` 由 `C:\temp\MyProject\…` 改為 `C:\Data\MyProject\…`（子資料夾名稱不變）；日誌根目錄 `NLog:BasePath` 由 `C:\temp\Logs` 改為 `C:\Data\Logs`。
- `EmailSettings.PickupDirectory` 的程式預設值、系統設定驗證錯誤訊息裡的範例路徑同步。
- 正式環境照舊在 `appsettings.Production.json` 設自己的路徑（這些設定仍標「⚠️【正式必改】」：開發預設在系統碟）。
- 不受影響：e2e 主機、CRUD 產生器、新專案複刻腳本都把路徑導到暫存目錄；複刻腳本把 `MyProject` 整個換名，新專案的預設自然是 `C:\Data\<新名稱>`。

## 既有開發機要做的事

改了預設路徑，**舊資料不會自動搬**：網站下次啟動會在新位置建一個全新的空資料庫，舊資料與 Data Protection 金鑰（兩步驟驗證密鑰、記住裝置）都讀不到。請先停掉網站，再把舊資料夾整個複製過去：

```powershell
robocopy C:\temp\MyProject C:\Data\MyProject /E /COPY:DAT /DCOPY:T
```

確認網站正常後再自行刪除舊的 `C:\temp\MyProject`。日誌是歷史紀錄，不必搬，新的日誌寫到 `C:\Data\Logs`。User Secrets 若設了 `EmailSettings:PickupDirectory` 也要一起改。

## 驗證

- 開發機的 579 個檔案（30.8 MB）複製到新位置後逐檔比對（相對路徑＋大小）0 個差異；User Secrets 的寄信資料夾改到新位置。
- 以預設設定啟動網站：讀寫的是 `C:\Data\MyProject`（資料庫 `-wal` 更新、帳號 3 筆與稽核 440 筆與舊資料相同）、日誌寫到 `C:\Data\Logs`，`C:\temp\MyProject` 與 `C:\temp\Logs` 的檔案快照前後完全相同。
- 品質關卡 8 步全部通過。
