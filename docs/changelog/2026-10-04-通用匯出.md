## 二、設計決定

| 決定 | 理由 |
|---|---|
| 匯出呼叫畫面同一個服務方法（`GetAsync`／`GetDeletedAsync`），不另寫查詢 | 團隊範圍由服務內的 `RecordTeamScope` 套用，匯出與畫面不可能不一致 |
| 以第一頁、`PageSize = 10000` 查詢，看服務回的總筆數判斷超量 | 不必多查一次總數；超量就不產生檔案，避免匯出被悄悄截斷 |
| 不另設 export 權限 | 使用者決定；匯出的內容與畫面完全相同，看得到就能匯出 |
| 欄寬給固定值，不用 `AdjustToContents` | 自動欄寬要量字型，伺服器（IIS）上不可靠 |
| 字串一律寫成文字值 | 以「=」開頭的內容不會在 Excel 變成公式（公式注入） |
| 診斷頁維持 CSV | 使用者決定；先以舊程式碼當對照寫好逐字比對的測試，再重構 |
| 使用者匯出不含額外角色與直接綁定的團隊 | 清單查詢沒有載入這兩項；為匯出另外查詢會讓「與畫面相同」的原則破例 |
