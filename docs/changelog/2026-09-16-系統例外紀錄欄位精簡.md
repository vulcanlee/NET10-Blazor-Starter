# 系統例外紀錄：精簡清單欄位並改用「查看」明細窗（0.9.12）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：0.9.12
- 首次實作版本：0.9.12
- 最後核對日期：2026/09/16

## 起因

0.9.11 的「系統例外紀錄」頁面實跑後，使用者回報兩個問題（附截圖）：

1. **表頭出現兩個「操作」**。左邊那個是「日誌訊息樣板」（程式當時在做什麼），
   右邊是動作按鈕欄 —— 同名兩欄，看不出哪個是哪個。
2. **欄位太多要左右捲動**。9 個資料欄的固定寬度合計 **1530px**（還不含展開圖示欄），
   一般螢幕一定會出現水平捲軸。

使用者要求：精簡到一頁看得完的必要欄位，其餘欄位改用「查看」按鈕檢視。

## 變更內容

### 清單欄位 9 → 6

| 保留 | 移進明細窗 |
|---|---|
| 最後發生、次數、類型、訊息、頁面、使用者 | 來源、首次發生、**操作（日誌樣板）**、記錄器、UserId、完整類型／訊息、完整堆疊 |

保留的欄位剛好涵蓋原始需求的「誰、在哪一頁、何時、什麼錯、幾次」。
**日誌樣板那一欄移出清單後，「操作」的名稱衝突自動消失**，不需要為了改名而改名；
動作欄維持「操作」，與全站其他清單頁一致。

固定寬度由 1530px 降到約 655px＋訊息彈性。

### 新增「查看」明細窗，移除展開列

- 動作欄改為 **查看（`visibility`）＋ 刪除（`delete`）** 兩顆按鈕，
  比照 `MyUserView`／`CategoryViewView` 以 `<Space><SpaceItem>` 包裹使其並排
  （直接並列會讓按鈕上下堆疊、列高從 52px 變成 84px）。
- 明細窗以 `<dl>` 列出全部欄位，最後接完整堆疊；**堆疊在開窗當下才讀檔**，
  清單查詢不會一次把所有檔案讀進記憶體。
- **移除 `<ExpandTemplate>` 與 `stackTraceCache`**：明細窗已涵蓋同一份資料，
  兩個入口看同一件事是多餘的，順帶省掉展開圖示欄的寬度。

## 踩到的兩件事

### 1. Modal 的內容樣式不能寫在 scoped CSS

第一版把 `<dl>` 與堆疊的樣式寫在 `ExceptionLogView.razor.css`（含 `::deep`），結果**整組失效** ——
AntDesign 的 `Modal` 會把內容渲染到元件 DOM 範圍之外的容器，scoped CSS 打不到。
已移到 `Components/Commons/FormModalHelper.razor` 的全域 `<style>`，
與該檔既有的三組 Modal 版型放在一起（該檔的存在理由正是這個）。

### 2. `.razor` 檔的 `<style>` 裡 `@media` 要寫成 `@@media`

Razor 會把 `@media` 當成程式碼轉換，直接編譯失敗：
`error CS0103: 名稱 'media' 不存在於目前的內容中`。
`FormModalHelper.razor` 先前沒有任何 media query，所以這個坑到現在才踩到。
（`.razor.css` 沒有這個問題，只有 `.razor` 有。）
