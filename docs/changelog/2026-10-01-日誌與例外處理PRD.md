# 新增「日誌與例外處理 PRD」：全系統日誌等級、例外處理與稽核的共用規範及缺口清單（0.9.76）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：0.9.76
- 首次實作版本：0.9.76
- 最後核對日期：2026/10/01

## 為什麼

日誌、例外紀錄、稽核的規則原本分散在操作文件、速查表與各頁 PRD，沒有一份「往後每個功能都要依此驗收」的需求文件。
盤點後也發現幾類例外**完全不會留下紀錄**：射後不理的 Task、程序層級例外、瀏覽器端錯誤、建立服務容器前的啟動失敗、關機時佇列殘留；
另有例外紀錄帳號欄恆空、丟棄筆數永遠是 0、同一例外記兩筆等錯誤。

## 做了什麼

- 新增 [日誌與例外處理 PRD](../prd/日誌與例外處理-prd.md)：
  - §二 四種紀錄的分工與每類事件的去向。
  - §三 六個日誌等級的規則（以操作文件 §2.1–2.3 為基礎完整寫出），補上外部呼叫、背景作業、慢操作、設定缺漏、迴圈內的等級，
    明訂 Debug／Trace 預設不寫入檔案；Trace 定義用途但不強制補寫。
  - §四 例外處理三原則、例外分類表、必備情境欄位、敏感資料、守門方式。
  - §五 未捕捉例外的涵蓋矩陣（每個進入點的現況與需求）。
  - §六 需求清單：已實作基線，以及規劃中 LOG-01～LOG-08（P0）、LOG-10～LOG-16（P1）、LOG-20～LOG-22（P2）。
- 已確認的需求決策：
  - 例外告警：寄 Email，加節流；收件人寫在設定檔，只含摘要與連結。
  - 瀏覽器端錯誤：回報並寫進例外紀錄表。
  - 稽核：涵蓋所有寫入動作與安全事件。
  - 保存期限：統一自動清理，天數可設定。
  - 查詢關鍵字：不記原文。
- [PRD 主控台](../prd/README.md)「無選單入口的核心能力」、[文件總索引](../README.md) 加入此 PRD。
- [日誌與設定檔說明](../operations/日誌與設定檔說明.md) §2 註明等級規則以 PRD 為準，§2.6 註記 LOG-08 規劃中的守門測試。
- [開發慣例與限制速查](../architecture/開發慣例與限制速查.md) 日誌條目、[系統例外紀錄 PRD](../prd/系統例外紀錄-prd.md)、[稽核紀錄 PRD](../prd/稽核紀錄-prd.md) 補上指向新 PRD 的連結。
- `appsettings.json` 的 `SystemVersion`：`0.9.75 → 0.9.76`。

## 刻意不做的事

- **本次只立需求、不改程式**：LOG-xx 各項日後各自另開設計規格與實作，完成一項就從 PRD §6.2–6.4 移到 §6.1。
- 不導入集中式日誌平台或 JSON 日誌格式：`/logs` 檢視器與 AI 日誌分析依賴現有純文字格式。
- 不記稽核的修改前後值，只記變更的欄位名稱。
- 不改既有等級判定：驗證失敗、重複名稱維持 Information（0.4.30 為此重新分類過 50 處）。
