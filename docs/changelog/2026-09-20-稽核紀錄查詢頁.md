## 起因

盤點系統現況時挑出三個可以往下做的方向，使用者選了其中的「補上稽核紀錄查詢頁」。

`docs/guides/腳手架開發指引.md` §9 把這件事列為第 2 號缺口，§6.5 評為「投報率最高」：
`AuditLog` 從 0.4.8 起就有資料表、服務、migration 與測試，全系統共 **15 個寫入點**，
但查證確認 **零個 `.razor` 參考它，`Menu.json` 也沒有對應選單項**。
資料進得去、拿不出來 —— 客戶問「誰把這個角色的權限改掉了」，只能直接開 SQLite 檔查。

## 做了什麼

### 1. 讀寫分離的查詢服務

新增 `MyProject.Business/Services/DataAccess/AuditLogQueryService.cs`，**不動既有的 `AuditLogService`**。

兩者刻意分開：寫入端注入 scoped `BackendDBContext`，因為它被夾在 `MyUserService`／`RoleViewService`
的寫入流程裡、與業務共用同一個 context；讀取端只服務 Blazor 畫面，必須注入
`IDbContextFactory<BackendDBContext>` 用完即棄（Blazor 的 DI scope 等同整條 SignalR circuit）。
把查詢塞進寫入服務會同時違反這條不變量，並波及 5 個呼叫點與 2 個測試 fixture。

方法：`GetAsync`（過濾／排序／分頁）、`GetDistinctActionsAsync`（下拉選項）、`PurgeAsync`、`ClearAllAsync`。

### 2. 管理員專屬唯讀頁 `/audit-logs`

- `Components/Pages/Admins/AuditLogPage.razor`（薄殼）＋ `Components/Views/Admins/AuditLogView.*`。
- 比照「系統例外紀錄」：`CheckIsAdmin()` 守門、`RemoteDataSource` 伺服器端分頁、
  `ToolbarIconButton` 工具列、`ConfirmDialog.AskDestructiveAsync` 二次確認、明細 `Modal`。
- 篩選：時間區間、動作、結果（成功／失敗）、操作者帳號、關鍵字。
- 匯出 CSV 走 `TextDownloadPayload.Utf8WithBom`。

### 3. ⚠️ 時區：本次最大的坑

`AuditLog.OccurredAt` 是**全專案唯一以 UTC 寫入**的時間欄位（`AuditLogService` 用 `DateTime.UtcNow`，
與 `LockoutEndUtc` 一致）。而 `ExceptionLog` 與 `TokenUsageLog` 寫的都是 `DateTime.Now`（本地時間），
所以那兩頁全程不換算。

**照抄那兩頁，整條時間軸會偏掉一個時區（台灣 8 小時）**，症狀是「明明有資料卻查不到」。
換算集中在 `AuditLogQueryService` 的三個邊界：

| 邊界 | 作法 |
| --- | --- |
| DatePicker → 查詢條件 | `ToUtc`：`SpecifyKind(Local).ToUniversalTime()` |
| 資料庫 → 清單／明細／CSV | `ToLocal`：`SpecifyKind(Utc).ToLocalTime()` |
| 清除門檻 | `DateTime.UtcNow.AddDays(-days)`，**不是** `DateTime.Now` |

三條測試分別釘住這三個邊界。**已實測**：把換算拿掉後這三條全部轉紅（其餘 21 條仍綠），
確認它們不是形式上的測試。

### 4. 清除與清空會記錄它自己

`Audit.Purge` / `Audit.ClearAll` 兩個新動作代碼，在刪除**之後**寫入，因此會留在清空後的資料表裡。

稽核軌跡可被管理員一鍵抹除，若不記錄這件事本身，「誰抹除了稽核紀錄」會成為系統裡唯一查不到的事。
寫入失敗只記錯誤、不向使用者報錯 —— 不該推翻「已經刪除」這個事實。

清除門檻取 **365 天**而非例外紀錄的 90 天：例外紀錄清的是噪音，稽核軌跡清的是責任證據。

### 5. 權限登錄（六處，缺一就紅燈）

這次實際踩到的是：原本只認得「四方同步」，但受影響的登錄點其實有六個。

| # | 檔案 | 內容 |
| --- | --- | --- |
| 1 | `MagicObjectHelper.cs` | `角色_稽核紀錄 = "稽核紀錄"` |
| 2 | `SidebarMenuService.MenuPermissionMap` | `[35] = 角色_稽核紀錄` |
| 3 | `Datas/Menu.json` | 權限管理(34) 底下新增 id 35、icon `fact_check` |
| 4 | `AdminOnlyPermissionTests.AdminOnlyPermissionKeys` | 加入該鍵＝承諾不上架角色矩陣 |
| 5 | `MenuPermissionConsistencyTests.AdminOnlyViews` | 加入 `AuditLogView.razor.cs` |
| 6 | `MenuIconTests.AllowedIcons` | 加入 `fact_check` |

另加 `DataAccessServiceLifetimeTests.DataAccessServices` 一列（驗證注入的是工廠而非 scoped context）。

⚠️ `RolePermissionService.GetRoleListPermissionAllName()` **一個字都沒有改**。系統管理類頁面
刻意不上架角色矩陣，只靠管理員短路通過；`AdminOnlyPermissionTests` 存在的目的就是擋下「順手補齊」。
