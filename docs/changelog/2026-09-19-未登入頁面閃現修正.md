# 未登入也看得到頁面：改由 HTTP 層擋下，並補上權限閘門與 ReturnUrl 防護（0.9.41）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：0.9.41
- 首次實作版本：0.9.41
- 最後核對日期：2026/09/19

## 為什麼

使用者回報：還沒登入時直接輸入 `https://localhost:7144/app`，會**瞬間看到系統畫面**，然後才被導去登入頁。
使用者根本沒有登入，不應看到系統的任何內容，更可能因此看到不屬於他權限的東西。

## 根因

頁面一律**沒有** `[Authorize]`（`Program.cs` 的註解明寫是刻意的），全部改在 `OnInitializedAsync` 內呼叫
`AuthenticationStateHelper.Check()` 命令式檢查。問題在時序：

1. 未登入的請求照樣拿到 HTML 殼，circuit 建立後 `MainLayout`、`NavMenu`、頁面檢視同時開始初始化。
2. `Check()` 在未登入分支先 `await Task.Delay(200)` 才 `NavigateTo`。
3. Blazor 在 `OnInitializedAsync` 第一個 `await` 就先渲染一次 —— 側邊欄、頁首、`/App` 的系統介紹與版本、
   CRUD 頁的工具列與表格框架全都畫出來了，200ms 後才被導走。

同一個時序缺陷還造成第二個問題：**已登入但沒有該頁權限**的人，會先看到工具列與表格框架，
才換成「你沒有權限存取此頁面」（`RoleMessage` 初值為空，第一次渲染走的是 `else` 分支）。

## 做了什麼

### 1. HTTP 閘門（根治）

- 新增 `Components/Pages/_Imports.razor`：`@attribute [Authorize]`，`Pages/` 底下（含子資料夾）現在與未來的頁面**預設需要登入**。
  未登入的請求在授權中介軟體就被 Cookie challenge 302 到 `/Auths/Login?ReturnUrl=…`，**瀏覽器收不到任何頁面內容**。
- 匿名頁面各自標 `[AllowAnonymous]`：`Home`（`/` 啟動頁）、`Error`（並改用 `EmptyLayout`）、`NotFound`、`Login`、`Logout`、`Pending`。
- `Program.cs` 註冊 `AddCascadingAuthenticationState()`，並改寫 `MapControllers` 上方的註解。

### 2. circuit 內的第二道網

`Routes.razor` 改用 `AuthorizeRouteView`：驗證中不渲染，未授權時由新的 `Auths/RedirectToLogin.razor` 整頁導向登入頁並帶上原網址。

### 3. 檢查完成前不渲染

- `MainLayout`：`Check` 成功前整個版面（側邊欄、頁首、頁面本體、對話窗）都不渲染。擋的是「Cookie 還在但帳號停用／被刪／缺角色」。
- 11 個檢視與 `SystemHealthPage`：新增 `isAccessChecked`，權限判定完成前不渲染任何內容。
  `Profile`、`ChangePassword` 的 `isLoading` 初值即為 `true`，本身已是閘門，不另加。

### 4. ReturnUrl 防護（順手關掉既有的 open redirect）

登入後現在會回到原本要去的頁面。但原本的 `Login.razor.cs` 把查詢字串的 `ReturnUrl` 原封不動塞進
`AuthenticationProperties.RedirectUri`，而 Cookie handler 對**明寫的** `RedirectUri` 不做站內檢查 ——
`/Auths/Login?ReturnUrl=https://evil.com` 登入成功後會被導去外站。新增 `ReturnUrlGuard.Sanitize`：
只接受 `/` 開頭、不是 `//`、`/\` 開頭、不含控制字元的站內路徑，其餘回 `/App`；帳密登入與 Google 登入兩條路都經過它。

## 過程中踩到的坑：`NotFound` 必須匿名

原本打算讓 `NotFound` 也需要登入（未登入者輸入不存在的網址一樣導去登入頁）。實作後既有的三個整合測試立刻紅了：
`/api/project-files/1/download` 的 401、`/UploadFiles/…` 的 401、`/WeatherForecast` 的 404 全變成 **302**。

原因是 `UseStatusCodePagesWithReExecute` 會把「沒有 body 的錯誤狀態碼」改寫成 `/not-found` 再跑一次管線 ——
`/not-found` 一旦需要登入，所有這類回應都會被 Cookie challenge 換成 302，API 呼叫端拿不到真正的狀態碼。

改為：`NotFound` 維持匿名（狀態碼得以保留），但它用的 `MainLayout` 在登入檢查通過前不渲染，並把未登入者導去登入頁。
結果一樣是「未登入者看不到任何東西、被送去登入」，而 API 行為不變。

## 守門

`MyProject.Tests/PageAuthorizationTests.cs`：

| 測試 | 守什麼 |
|---|---|
| `EveryRoutablePage_ShouldDeclareItsAccessLevel` | 每個可路由元件都必須有 `[Authorize]` 或 `[AllowAnonymous]` |
| `AnonymousPages_ShouldMatchTheAllowList` | 匿名頁面必須**恰好**等於白名單，新增匿名頁面得有意識地改測試 |
| `ProtectedPage_WithoutLogin_…`（逐一列舉所有受保護路由） | 未登入 GET 一律 302 到 `/Auths/Login`、帶正確 `ReturnUrl`、回應 body 為空 |
| `UnknownUrl_WithoutLogin_ShouldKeep404AndRenderNoPageContent` | 不存在的網址維持 404 |
| `AnonymousPage_WithoutLogin_ShouldBeServed` | `/`、`/Auths/Login`、`/Auths/Pending` 仍可匿名開啟 |
| `ReturnUrlGuard_ShouldOnlyAllowLocalPaths` | 外站、協定相對、反斜線、控制字元一律回 `/App` |
| `ComponentsCallingAuthenticationCheck_ShouldRenderNothingUntilTheCheckCompletes` | 掃描原始碼：呼叫 `Check()` 的元件必須有 `isAccessChecked` 閘門 |
| `MainLayout_ShouldRenderNothingUntilAuthenticated` | `MainLayout` 的閘門不被拿掉 |
