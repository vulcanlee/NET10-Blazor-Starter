# http 也能啟動（0.10.31）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：0.10.31
- 首次實作版本：0.10.31
- 最後核對日期：2026/11/15

## 目的

使用者 2026/11/15 把發佈檔放到 IIS，用 http 加 IP（例如 `http://192.168.1.10:85/App`）開，畫面一直停在「正在載入，請稍候…」。使用者目前沒辦法提供 HTTPS，希望 http 也能用。

## 原因

用無頭 Chrome 實際開使用者的網址查過：

- 發佈檔本身沒問題：`index.html` 已處理過，`_framework` 的檔案都是 200，CSP 的 import map 雜湊也對得上。
- 主控台唯一的錯誤：`MONO_WASM: Assert failed: This engine doesn't support crypto.subtle` → `Failed to start platform`。
- .NET 11 的 `dotnet.js` 啟動時**無條件**檢查 `crypto.subtle`。瀏覽器只在安全連線（https、localhost、127.0.0.1）提供它，用 http 加 IP 或網域開就直接中止。
- 執行環境只有一處真正用到它：`dotnet.runtime.*.js` 用 `crypto.subtle.digest("SHA-256", …)` 算快取鍵。Blazor 與我們的 C#（`LoginStorage` 的 SHA256、亂數）都不靠它；`crypto.getRandomValues` 在 http 照常可用。
- 先在使用者的網址上做過可行性實驗：只在測試用的瀏覽器裡、頁面載入前補上純 JS 的 `crypto.subtle.digest`，就正常啟動、進到登入頁。

## 變更內容

- 新增 `MyProject.Web.Client/wwwroot/js/insecure-context-crypto.js`：
  - 只在 `!window.isSecureContext`、瀏覽器又沒有 `crypto.subtle` 時動作；https 與 localhost 完全不受影響。
  - 補一個只有 `digest` 的 `crypto.subtle`，只支援 SHA-256（純 JS 實作，FIPS 180-4）；其他演算法丟出清楚的錯誤，不假裝支援。
- `index.html`：在 `blazor.webassembly` 之前載入它。必須是外部檔案（CSP 只允許 import map 這段行內腳本）；import map 沒變，CSP 雜湊不用改。
- 順便修正：速查表第 147 點（0.10.29 加的）的反引號在編輯時被 PowerShell 吃掉，這次補回。

## 測試

- 新增 `InsecureContextConventionTests`：`index.html` 要在 `blazor.webassembly` 之前載入這支腳本，腳本要有 `isSecureContext` 判斷。先紅後綠。
- 第一版把說明註解放在載入卡片與 `<script>` 之間，`LoadingAndStatusPageTests` 失敗（它預期 `</div>` 後面直接是 `<script`），改把註解放到補丁那行之後。

## 驗證（實際發佈、從發佈檔執行）

- 用 `scripts/Start-E2EHost.ps1 -Published -LaunchProfile http` 以 Release 發佈到隔離資料夾，執行發佈出來的 `MyProject.Web.exe`（全新資料庫）。
- 模擬「非 localhost 的 http」：Chrome 加 `--host-resolver-rules="MAP iis-test.example 127.0.0.1"`，開 `http://iis-test.example:5109`（`isSecureContext` 為 false）。
  - **修改前**：沒有 `crypto.subtle`，停在載入卡片，跟 IIS 上一樣。
  - **修改後**：
    - 正常啟動；補上的 SHA-256 與 Node `crypto` 比對三組（空字串、`abc`、1 MB 隨機資料）都一致；
    - support 登入成功，首頁、使用者管理、專案清單都正常顯示（截圖看過）。
- **安全連線不受影響**：同一個發佈版用 `http://localhost:5109`（安全連線）開，`crypto.subtle` 是瀏覽器原生的，補丁沒有動作，登入與三個頁面都正常。
  - 計畫原本要另外以 https 設定檔再發佈一次，改用 localhost 確認：https 與 localhost 都是安全連線，腳本走同一個判斷。
- 兩種情況主控台都有幾筆 `.wasm` 下載中斷（`Failed to fetch`），是驗證腳本中途換頁打斷下載造成的；安全連線也一樣有，跟這次改動無關。
- **品質關卡**：7 步（建置、格式、測試、文件編碼、CRUD 錨點、弱點掃描）全部通過。

## 限制與提醒

- http 下沒有 PWA（離線、安裝、新版本提示），帳號密碼與登入 Token 以明文傳送；有網域或內部 CA 時建議盡早改走 https。
- 升級 .NET 時要在發佈後的 `_framework/dotnet*.js` 搜尋 `crypto.subtle`，用到 `digest` 以外的功能就要跟著補（速查表第 148 點）。
