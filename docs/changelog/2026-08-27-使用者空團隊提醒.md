# 使用者維護：團隊留空的儲存前提醒（0.4.43）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：0.4.43
- 首次實作版本：0.4.43
- 最後核對日期：2026/08/27

## 目的

需求是「新增或修改使用者時，團隊沒有輸入任何內容，儲存時應該要有提醒訊息」。

在 `/myusers` 的維護表單中，「團隊（直接綁定此使用者）」若一個都沒選，先前會直接儲存、
沒有任何提示。管理員很容易在沒察覺的情況下建立出一個看不到任何有團隊標記紀錄的帳號。

## 一、為什麼不是加 `[Required]`

**空團隊在本系統是刻意的合法值，不是漏填。**

使用者的「有效團隊」＝直接綁在使用者的 `UserTeam` ∪ 其**所有**角色（主要＋額外）的
`RoleView.DefaultTeamsJson`，聯集去重（`EffectiveTeamResolver.ResolveAsync`）。這個設計讓
「團隊綁使用者」與「團隊綁角色」並存，才做得到個別使用者的差異化授權 —— 欄位的
placeholder 本來就寫著「不設定則沿用其角色的預設團隊」。

因此若比照「角色」欄位加上 `[Required]` 與紅色星號：

- 角色已帶預設團隊的使用者會被迫重複指定一次，多餘且容易與角色設定產生分歧。
- 既有資料中大量團隊留空的帳號會在下次編輯時無法儲存。

結論是**軟性提醒**：儲存前跳確認、說明後果，使用者仍可按「仍要儲存」繼續。
資料模型、驗證屬性、服務層一律不動。

## 二、作法

沿用既有的共用確認樣板 `TeamBindingConfirm`（`Web/Components/Commons/`，標題「確認團隊設定」、
按鈕「仍要儲存」／「回去編輯」、`MaskClosable = false`）。分類（`CategoryViewView`）與
專案（`ProjectViewView`）早已在用，使用者維護是唯一有團隊欄位卻沒接上的檢視 ——
本次只是把它接上，**沒有新增任何共用元件**。

新增 `MyUserView.ConfirmTeamBindingAsync()`，於 `OnModalOKHandleCoreAsync` 中呼叫，位置在
密碼檢查之後、`if (isNewRecordMode)` 分支之前 —— 與同屬「內容層級守門」的密碼檢查排在一起，
維持本檔既有的「內容守門 → 持久化前置檢查 → 寫入」順序，新增與修改共用同一個呼叫點。

判斷邏輯：

1. 團隊已選至少一個，或勾選了「管理員」→ 直接放行。
   管理員不受團隊行級權控（`BuildTeamAccessPredicate` 只套非管理員），提醒對他只是雜訊。
2. 否則取主要角色 `RoleViewId` ＋ 額外角色 `AdditionalRoleIds` 在 `roleViewAdapterModels` 中的
   `DefaultTeams` 聯集（不分大小寫去重），依有無分兩種措辭：

   | 情境 | 訊息 |
   |---|---|
   | 角色有預設團隊 | 未直接指定團隊，此使用者將沿用其角色的預設團隊（○○、△△）。確定要這樣儲存嗎？ |
   | 角色也沒有預設團隊 | 未直接指定團隊，且其角色也沒有預設團隊，此使用者將只能看到無團隊標記的公開紀錄。確定要這樣儲存嗎？ |

3. 選「回去編輯」則保持 Modal 開啟、已填內容不遺失、不寫入資料庫，並記一筆 Debug 日誌。

角色的預設團隊在畫面上本來就拿得到（`RoleViewAdapterModel.DefaultTeams` 由 `AutoMapping`
從 `DefaultTeamsJson` 反序列化），**不需要新的服務呼叫或資料庫查詢**。

Modal 內按 Enter 送出走 `OnModalKeyDownAsync` → `OnModalOKHandleAsync`，自動涵蓋同一條路徑。

## 三、已知取捨

新增使用者時若帳號重複且團隊留空，會先看到團隊確認、按下「仍要儲存」後才看到
「帳號已存在，無法新增。」。這是把確認放在前置檢查之前的代價，屬罕見錯誤路徑，
換得的是單一呼叫點、不必改動 `BeforeAddCheckAsync`／`BeforeUpdateCheckAsync` 兩個分支。

## 五、驗收

專案沒有 bUnit／UI 測試專案，`ConfirmTeamBindingAsync` 是 Razor code-behind 的私有方法，
無法單元測試，因此以「既有測試不退步 ＋ 手動實跑」驗收。

- `dotnet build src/MyProject/MyProject.slnx` → 0 錯誤 0 警告（`TreatWarningsAsErrors` 已開啟）。
- `dotnet format src/MyProject/MyProject.slnx --verify-no-changes` → 無變更。
- `dotnet test src/MyProject/MyProject.slnx` → 286 項全數通過（本次不動服務層，應原封不動通過）。
- 手動實跑 `/myusers`：團隊留空（角色有／無預設團隊兩種）、團隊已選、勾選管理員、新增與修改、
  Enter 送出、按「回去編輯」不寫入 —— 均符合上表行為。
