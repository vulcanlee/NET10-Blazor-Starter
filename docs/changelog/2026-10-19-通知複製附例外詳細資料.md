# 錯誤通知「複製」附例外詳細資料（0.9.130）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：0.9.130
- 首次實作版本：0.9.130
- 最後核對日期：2026/10/19

## 起因

0.9.129 讓錯誤通知可以按「複製」，但只複製畫面上看得到的文字。管理員排查問題時，還要拿追蹤碼去「系統例外紀錄」查例外類型與呼叫堆疊，多一道手續。
這次讓「複製」直接把例外細節一起放進剪貼簿。

## 決定（2026/10/19，與使用者確認）

| 項目 | 決定 |
|---|---|
| 誰拿得到細節 | 管理員一律可以；其他人只有 `ExceptionDetailPolicy` 允許時可以（Development，或 `Security:ReturnExceptionDetails=true`）。正式環境的一般使用者複製到的和 0.9.129 相同 |
| 內容 | 完整 `ex.ToString()`（類型、訊息、所有內層例外、堆疊），不截斷，放在最後並以「----- 錯誤詳細資料開始／結束 -----」包住 |
| 涵蓋範圍 | 全部 `UnexpectedError`，再加上 catch 裡原本用 `Error` 的 37 處（改用 `UnexpectedError`，同時補上追蹤碼） |
| AI 上游失敗 | 沒有例外物件，改附 `HTTP 429; code=…; type=…; param=…`。**不含**上游 `error.message` 與回應本文（既有規範：可能回吐整份 prompt）。逾時、連線失敗、未預期例外則附 `ex.ToString()` |
| 按鈕 | 文字維持「複製」，不另外標示 |
| 日誌 | 細節不進通知那筆日誌，也不上畫面；例外已由呼叫端 `LogError(ex, …)` 記錄 |

這是《日誌與例外處理 PRD》「使用者看到的訊息不得含例外型別、堆疊」的例外，已在該條下方註明。

## 注意

- 正式環境若把 `Security:ReturnExceptionDetails` 設成 `true`，**所有使用者**複製錯誤通知時都會拿到堆疊。
- 例外內容不做遮罩（與系統例外紀錄頁同級），可能含使用者輸入。
- 既有問題、不在本次範圍：18 處 `$"…失敗：{ex.GetType().Name}。"` 會在畫面上顯示例外類型；服務層 `VerifyRecordResult.Exception` 仍沒有被 UI 讀取。
