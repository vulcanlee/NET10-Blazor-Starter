# 側邊欄展開後的黑字與藍字：AntDesign 蓋過了深梅配色（0.9.40）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：0.9.40
- 首次實作版本：0.9.40
- 最後核對日期：2026/09/19

## 為什麼

使用者從畫面截圖指出：側邊欄展開後，**子選單項目的文字是黑色**，壓在暗紅底上幾乎看不見；
而且選中的「首頁」是**藍色**，與整個深梅色系格格不入。

## 根因（只有一個）

AntDesign 的 `MenuItem` 只要有 `RouterLink`，就會在 `<li class="ant-menu-item">` 裡面
**再包一層 `<a>`**：

```html
<li class="ant-menu-item ant-menu-item-selected">
  <a href="/App" class="active">…文字…</a>   ← 多出來的這一層
</li>
```

而 `NavMenu.razor.css` 的顏色覆寫全部只打在 `<li>` 與 `.ant-menu-submenu-title` 上。
CSS 的 `color` 在子元素被**直接指定**時不會繼承，於是 AntDesign 出廠的規則直接生效：

| AntDesign 規則（v1.6.0）| 行號 | 造成 |
|---|---|---|
| `.ant-menu-item a { color: rgba(0,0,0,.85) }` | 15721 | 葉節點黑字 |
| `.ant-menu-item a:hover { color: #1890ff }` | 15724 | 葉節點 hover 藍字 |
| `.ant-menu-item-selected a { color: #1890ff }` | 15764 | 選中項藍字 |
| `.ant-menu-inline .ant-menu-item::after { border-right: 3px solid #1890ff }` | 16033 | 右緣藍色指示條 |

**這個缺陷難以察覺的地方在於「看起來大部分都對」**：群組標題是 `<div>`、「登出」走
`OnClick`，兩者都沒有那層 `<a>`，所以一直是白的；圖示用的是後代選擇器，本來就穿得過 `<a>`。
所以只有「有連結的葉節點」壞掉 —— 而那正好是最常點的那些。

⚠️ 只發生在**展開**狀態。收合時走的是另一套手寫 HTML，顏色規則完整。

## 做了什麼

- `wwwroot/theme.css` 新增 `--app-rail-text-sub: rgba(255, 240, 246, 0.80)` ——
  葉節點專用，比群組標題淡一階做出層次。
- `NavMenu.razor.css` 新增四組覆寫（一般／hover／選中的 `<a>`，以及 `::after` 指示條），
  全部 `var(--app-*)` ＋ `!important`（scoped 束排在 AntDesign 之前）。
- 選中項**維持莓紅膠囊改白字**。評估過「淡粉底＋深梅字」，但實算深梅字對莓紅只有
  **2.1:1**，比原本的藍字更糟，已排除。

## 對比度實算（底色取漸層最亮端 `#6b1c3d`，最不利情況）

| 元素 | 修正前 | 修正後 | 門檻 |
|---|---|---|---|
| 葉節點文字 | **1.78:1** ❌ | **7.09:1** ✅ | 4.5 |
| 選中項文字（對莓紅）| **2.09:1** ❌ | **6.45:1** ✅ | 4.5 |
| 群組標題 | 8.58:1 ✅ | 8.58:1 ✅ | 4.5 |
| hover | — | 10.73:1 ✅ | 4.5 |
| 副標「功能選單」| 4.86:1 ✅ | 4.86:1 ✅ | 4.5 |
| 右緣指示條 | 3.48:1 ✅ | 6.76:1 ✅ | 3.0 |

⚠️ **指示條那一列要誠實**：藍色 `#1890ff` 其實**通過**非文字元素的 3:1 門檻，
換成 `--app-accent-light` 是**配色一致性**的決定，不是無障礙修正。
真正不合格的只有兩列文字。

## 守門測試

新增 `SidebarLinkColorConventionTests`（2 條）：

1. `SidebarMenuAnchors_ShouldHaveExplicitColorOverrides` —— `.ant-menu-item a`、
   `.ant-menu-item-selected a`、`.ant-menu-item::after` 三者都必須有覆寫。
2. `SidebarMenuAnchorOverrides_ShouldUseImportant` —— 覆寫必須帶 `!important`。

⚠️ 既有的 `ThemeConventionTests` 三條**都擋不到這個問題** —— 它們只管色碼住在哪、
以及 `theme.css` 的載入順序，全專案**沒有任何測試檢查對比度**。這類缺陷會通過
建置、`dotnet format` 與 `TreatWarningsAsErrors`，只有實際展開選單才看得到。

## 驗證

- 用**真實的** CSS（`app.css` → scoped 束 → `ant-design-blazor.css` → `theme.css`，
  與 `App.razor` 同序）建拋棄式 HTML 測試頁，以 Edge headless 截圖修正前後對照。
  「修正前」的截圖完整重現了使用者回報的症狀（藍字首頁、藍色指示條、看不見的子項目、
  以及白色的「登出」），確認診斷正確。
- 對比度以 WCAG 相對亮度公式實算，不是目測。
- `dotnet test` 全綠。
