# 一致性修正（0.9.165）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：0.9.165
- 首次實作版本：0.9.165

## 目的

0.9.163 文件全面對版時，有 5 個程式問題只列、沒改。這一版逐一處理。

動手前先查過程式，有 3 項和對版報告的假設不一樣，做法都和使用者確認過。

## 使用者的決定（2026/11/07）

| 問題 | 查證結果 | 決定 |
|---|---|---|
| 系統健康監控只查 4／11 個目錄 | 啟動時會建立全部 11 個目錄，但「檔案系統」只檢查其中 4 個 | 11 個全部檢查 |
| 帳號管理、角色管理多欄預設排序 | 帳號管理 4 欄、角色管理 3 欄宣告 `DefaultSortOrder`。實際只依第一欄排序，畫面卻可能好幾欄亮著箭頭 | 只留一欄 |
| 「團隊／部門」混用 | 範圍比報告大：團隊清單頁的「上層部門」欄位、表單與提示、Excel 匯出欄名、錯誤訊息（Web API 的 400 也用同一組）、個人資料頁、資料保留頁都用「部門」 | 畫面、訊息、文件全部改成「團隊」；程式註解不動 |
| 密碼驗證訊息兩套寫法 | 全站表單欄位驗證 25 處都是「欄位 不可為空白」（有空格、沒句號），變更密碼頁是照慣例寫；服務層訊息本來就是另一種寫法 | 維持現狀；只把 Web API 登入的 2 處補上空格，讓全站 27 處一致 |
| 刪除成功訊息寫法不一 | 「新增成功／修改成功／刪除成功」是 CRUD 清單的慣例（CRUD 產生器範本也這樣寫），Token 用量是照慣例；真正不一致的是敘述句有沒有句號 | 保留 CRUD 慣例，敘述句補句號 |

## 內容

### 系統健康監控檢查全部 11 個目錄

- 「檔案系統」改成檢查 `ExternalFileSystem` 的 11 個目錄：
  - 原本的 Database、Download、Upload、ProjectFile。
  - 新增的 Exception、TokenUsage、AiCallLog、AiAgentConversation、AuditContent、DataProtectionKey、Backup。
- 清單抽成 `SystemHealthService.FileSystemPaths`。新測試用 reflection 確認 `ExternalFileSystem` 的每一個目錄屬性都在清單裡，之後新增目錄漏加會被擋下。
- 權重（10）與判斷方式（不存在或不可寫入 → 紅燈）不變。
- 定時巡檢與系統管理助理的「系統健康報告」讀同一份報告，自動跟著列出全部目錄。

### 預設排序只留一欄

- 帳號管理只保留「帳號」欄、角色管理只保留「名稱」欄的 `DefaultSortOrder`。
- 新增守門測試 `TableDefaultSortConventionTests`：每個 `.razor` 最多一個 `DefaultSortOrder`。

### 「部門」改成「團隊」

| 位置 | 修改 |
|---|---|
| 團隊清單頁 | 欄位與表單「上層部門」→「上層團隊」；提示文字；已刪除的上層顯示「（已刪除的團隊）」 |
| Excel 匯出 | 欄名「上層部門」→「上層團隊」 |
| 錯誤訊息（`TeamHierarchy`、`TeamService`，Blazor 與 Web API 共用） | 例如「上層部門不能是自己。」→「上層團隊不能是自己。」、「這個部門底下還有 N 個下屬部門…」→「這個團隊底下還有 N 個下屬團隊…」 |
| 個人資料頁 | 「下屬部門」→「下屬團隊」 |
| 資料保留頁 | 「還有下屬的部門」→「還有下屬的團隊」 |

- 程式註解沒有改（使用者決定）。
- 文件同步：
  - 操作說明（團隊清單、個人資料、資料保留、專案項目、分類清單）與 CRUD 產生器的說明範本。
  - 使用手冊、畫面與欄位字典、PRD、架構與安全文件。
- 文件中講真實世界組織的「部門」保留，例如「新部門成立」「部門裁撤」「部門主管」「其他部門的同事」。
- changelog 的歷史標題（例如《部門樹》那一篇）保留當時的寫法。

### 訊息標點

- 規則：
  - CRUD 清單的短狀態訊息不加句號：新增成功、修改成功、刪除成功、已更新最新資料、已永久刪除、已啟用／已停用、批次「已刪除 N 筆」。
  - 其他敘述句一律以句號結尾。
  - 規則寫進 `ViewNotification.Warning` 的註解與速查表。
- 補上句號的 7 處：
  - 已清空全部稽核紀錄。
  - 已清空全部例外紀錄。
  - 已清空全部對話紀錄。
  - 已刪除對話紀錄。
  - 已強制登出「X」。
  - 已解除「X」的鎖定。
  - 已重設「X」的兩步驟驗證。
- Web API 登入的必填訊息改為「帳號 不可為空白」「密碼 不可為空白」，與全站一致。
- 操作說明與手冊裡引用這些訊息的原文都同步了。

### CRUD 產生器補上使用手冊章節（修正 0.9.162 的漏洞）

- 驗證時跑 `Test-CrudGenerator.ps1`，發現產生出來的模組會讓 `UserManualCoverageTests` 失敗（2319 個測試中 1 個）。
- 原因：
  - 0.9.162 新增的守門測試要求 `HelpTopics.json` 的每個路由都要有手冊章節。
  - 但產生器只登記操作說明，不會在手冊加章節。
  - 0.9.162 當時沒有跑產生器驗證，所以沒發現。
  - 速查表 §6.27 第 2 點本來就規定：新增「每個模組都要登記」的地方時，要同步在產生器加一個 `Update-Source`。
- 修正（使用者決定讓產生器自動加章節）：
  - `New-CrudModule.ps1` 多登記一項「使用手冊章節」：在《新手完整操作指南》第六章最後加一節「6.N 顯示名稱 `/路由`」。
  - 節號接在第六章現有最大的節號後面，插在第七章前的分隔線之前。
  - 內容樣板是 `scripts/crud-manual-section.md.tmpl`，照《使用手冊寫作規範》的畫面章節樣板寫，有開頭四行、欄位表、按鈕表、常見陷阱。
  - 品質關卡的錨點檢查自動涵蓋這一項（24 項）。
- 文件同步：
  - 《建立一個新 CRUD 操作網頁說明》的登記表與產生後檢查清單。
  - 《使用手冊寫作規範》§9。
  - 速查表 §6.14。
