# 決定紀錄：腳手架路線圖 v2.0 —— 前提修訂、選題判準與翻案（0.9.88）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：0.9.88
- 首次實作版本：0.9.88
- 最後核對日期：2026/10/03

## 目的

使用者希望把**大部分系統都會用到**的功能先做進腳手架，日後開發個人或企業系統時不必重做，以縮短開發時間、提高品質。
本次先盤點 0.9.87 的現有功能與基礎設施，再與使用者逐項討論需求，最後把結論寫成
[腳手架強化路線圖 v2.0](../planning/00-腳手架強化路線圖.md)。

**純文件異動，沒有程式碼變更。** 版本號依 `CLAUDE.md` 規則 Patch +1（0.9.87 → 0.9.88）。

## 一、選題判準（新增）

> 只放「**大部分系統都會用到**」的功能。只有少數系統才需要的，等複製出新專案後，在那個專案裡再做。

討論時這條判準由使用者在「企業登入方式」一題提出：AD／LDAP 等需求留給有需要的衍生專案自行實作。之後的每一項取捨都以此為準。

## 二、前提修訂（取代 v1.2 的前提）

| 項目 | v1.2（2026/09/24） | v2.0（2026/10/03） |
|---|---|---|
| 交付情境 | 單一產品底座 + 未來多租戶 SaaS 底座 | **一客戶一套（單租戶）** |
| 部署目標 | Windows Server + IIS、Docker／Linux | **Windows Server + IIS（內網）** |
| 資料庫 | SQLite，SaaS 採一租戶一檔 | **只用 SQLite** |
| 系統類型 | （未定義） | **內部管理類、AI 應用類** |
| 語系 | （未定義） | **只做繁體中文** |
| 衍生專案同步 | （未定義） | **升級筆記 + patch 腳本**，維持複製改名模式 |
| 部門與團隊 | 團隊為平面清單 | **Team 加 ParentId 即部門**，列級權限含下屬部門 |
| 實作順序 | Top 10（含多租戶擴充點） | **地基優先 A → B → C → D／E → F → G** |

## 三、翻案（原決定不實作 → 改為要做）

| 項目 | 原決定 | 新決定 |
|---|---|---|
| MFA（TOTP） | [2026-07-09](2026-07-09-三項待辦決定不實作.md)：不做 QR 綁定 UI 與登入第二步 | **要做**（路線圖 C-12）：QR 綁定、登入第二步、備用碼、依角色強制 |
| Refresh Token 撤銷 | [2026-07-09](2026-07-09-三項待辦決定不實作.md)：stateless、不可撤銷 | **部分翻案**（路線圖 C-11）：以 `MyUser.SecurityStamp` 讓某位使用者的所有工作階段失效；**單顆 token 落庫撤銷與裝置管理仍不做** |

## 四、降級（原計畫要做 → 經決定不實作）

| 項目 | 理由 |
|---|---|
| 多租戶擴充點（v1.2 第 2 期全部，原標為「有時效性」） | 交付模式改為一客戶一套 |
| OpenTelemetry（v1.2 7-1） | 單機 IIS，NLog 檔案 + 既有健康監控已足夠 |
| Dockerfile／docker-compose／devcontainer（v1.2 7-2） | 部署環境只有 Windows + IIS |

v1.2 第 2 期中與租戶無關的 SQLite 連線參數（`WAL`、`busy_timeout`、`Foreign Keys`）移到 A-3 繼續做。
多租戶的關鍵分析結論保留在路線圖 v2.0 的附錄，供日後翻案參考。

## 五、明確不納入

Excel／CSV 匯入、代碼表、全域搜尋、AD／LDAP／Windows 整合驗證／Entra ID 登入、簽核流程引擎、多語系。
理由都是「不是大部分系統都需要」，或前提已排除（多語系）。

## 六、納入的 22 項

A 地基（品質關卡、bUnit、資料庫初始化重構、軟刪除與並行）、B 平台服務（排程、系統參數、備份、站內通知）、
C 帳號安全（密碼與鎖定原則、個人資料頁、工作階段管理、MFA）、D 組織呈現（部門樹、儀表板、暗色模式）、
E 資料處理（Excel 匯出）、F AI（Prompt 範本、用量配額、聊天元件、RAG）、G 開發效率（CRUD 產生器、衍生專案升級）。
每項的目的、範圍、注意點、相依與驗收見[路線圖 v2.0](../planning/00-腳手架強化路線圖.md)。
