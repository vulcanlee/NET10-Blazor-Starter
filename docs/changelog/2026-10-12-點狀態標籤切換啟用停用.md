# 點狀態標籤切換啟用／停用（0.9.120）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：0.9.120
- 首次實作版本：0.9.120
- 最後核對日期：2026/10/12

## 起因

清單上的「啟用／停用」標籤只能看，要停用一筆資料得按「修改」、在窗裡切開關、再儲存。使用者希望直接點標籤就能切換。

決定（2026/10/12）：

- 範圍：團隊 `/teams`、分類 `/categories`、使用者 `/myusers`，以及 CRUD 產生器範本。
- 停用先確認，啟用直接切換。
- 外觀維持原本的標籤，有權限時可點；沒有權限或在「顯示已刪除」時與原本相同。
- 使用者：不可停用自己與 support；「修改」窗存檔也補上同一條規則（之前可以，且 support 停用後重新啟動也不會恢復）。

## 設計

- **只改狀態的服務方法**：`TeamService.SetEnabledAsync`、`CategoryService.SetEnabledAsync`、`MyUserService.SetStatusAsync`。
  以 `ExecuteUpdateAsync` 只寫狀態、更新時間與版本號，不走整筆覆寫的 `UpdateAsync`。
  ⚠️ `MyUserService.UpdateAsync` 會依畫面模型重寫角色與團隊，而清單列沒有這兩項；直接拿清單列存檔會清掉那個人的額外角色與團隊。
- **參數是目標值**：重複點（兩個分頁各點一次）不會反轉；已經是目標值時回成功、不寫稽核。
- **換版本號**：別人開著同一筆的修改窗存檔時得到並行衝突，而不是把狀態蓋回去。
- **使用者另換工作階段版本**：被停用的人下一次換頁就被登出（速查表 §6.20）。
- **稽核**：新增 `Team.Enable`／`Team.Disable`、`Category.Enable`／`Category.Disable`、`User.Enable`／`User.Disable`。分類檢查團隊範圍（與修改相同）。

## 實機驗證（2026/10/12）

本機以環境變數把資料目錄指到暫存區、全新資料庫啟動，Playwright 驅動 Edge：

| 情境 | 結果 |
|---|---|
| 團隊「啟用」標籤 | 是 button，提示「點一下切換為停用」 |
| 點「啟用」→ 確認窗按「取消」 | 狀態不變 |
| 點「啟用」→ 確認窗按「停用」 | 提示「已停用「研發部」」，標籤變「停用」、提示變「點一下切換為啟用」 |
| 點「停用」 | 不跳確認窗，提示「已啟用「研發部」」 |
| 開著修改窗時另一個分頁停用，回來改代號並存檔 | 「這筆資料在你編輯期間已被其他人修改或刪除…」，狀態維持「停用」 |
| 分類停用 | 提示「已停用「技術文件」」 |
| 使用者：support 那一列 | 標籤是 span（不可點）；bob 那一列是 button |
| 停用 bob（他另一個瀏覽器已登入） | 確認窗文字正確；bob 下一次換頁回到登入頁 |
| 修改窗把 support 取消「啟用」後存檔 | 「「support」是系統預設的開發帳號，不可停用。」 |
| 稽核紀錄 | `Team.Disable`、`Team.Enable`、`Team.Disable`、`Category.Disable`、`User.Disable` |

沒有實機驗證的：沒有修改權限的角色看到不可點的標籤（由 `RequirePermissionTests` 的 `Fallback` 測試涵蓋）。

順帶觀察到、與本次無關的既有狀況（未修改）：

- 預設 support 的 Email（`BootstrapSettings:SupportEmail`）是 `support`，在修改窗存檔會先被「Email 格式不正確」擋下。
- 390px 寬的團隊清單有水平捲動，來源是工具列的搜尋區與表格寬度。
