## 二、設計決定

| 決定 | 理由 |
|---|---|
| 固定規則接在最後、而不是開頭 | 管理員的指示若與規則衝突，模型以最後、且明說優先的規則為準 |
| 原本的第 1 條「只依提供的內容作答」留在可改的部分 | 它是分析指示（兩個範本的寫法不同），不是安全或格式規則 |
| 每次分析都重新讀取，不快取 | 一次查詢的成本遠小於一次 AI 呼叫；切換後立即生效、多台主機也一致 |
| 讀不到資料庫時退回內建預設 | AI 分析的介面約定是不丟例外；提示詞讀不到不該讓分析整個失敗 |
| 存新版本時比對開窗時的作用中版本 | 兩位管理員同時編輯時，後存的人不會在不知情下蓋掉別人的版本 |
| 「內建預設」做成版本紀錄的一列 | 改回原始提示詞不必複製貼上，也不會產生一個看起來像自訂的版本 |
| 匯入放在 seeder、不在 migration | 需要讀設定檔；只在資料庫還沒有版本時做，之後設定檔的值不會蓋回畫面上的修改 |
| 不能刪除版本 | 使用者決定全部保留；版本只有文字，量很小 |

⚠️ 行為變更：0.9.107 以前用 `AiSettings:SystemPrompt` 自訂的提示詞是整段取代（含安全規則）；匯入後一律再接上固定規則。沒自訂過的系統送出的內容每一行都與之前相同，只是順序改為「角色與指示、章節、規則」，換行一律 LF（之前在 Windows 上建置時是 CRLF）。
