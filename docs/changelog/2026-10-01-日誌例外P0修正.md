# 日誌與例外處理 P0 修正：例外不再漏記、記錯與重複（0.9.77）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：0.9.77
- 首次實作版本：0.9.77
- 最後核對日期：2026/10/01

## 為什麼

0.9.76 立案的 [日誌與例外處理 PRD](../prd/日誌與例外處理-prd.md) 盤點出 8 項 P0 缺口：

- 例外紀錄的帳號欄恆為空。
- 佇列滿時丟棄筆數永遠是 0。
- 同一例外記成兩列。
- 射後不理的 Task、程序層級、啟動失敗、關機時的例外完全不留紀錄。
- 浮層出錯會讓 circuit 整個中斷。
- 日誌記了使用者輸入的查詢關鍵字原文。
- 多處 catch 靜默吞掉例外。

## 做了什麼

| 編號 | 修正 |
|---|---|
| LOG-01 | 新增 `UseExceptionContextUser()`，排在 `UseAuthorization` 之後補上帳號。`UseHttpRequestLogging` 的 catch 記錄前再取一次。帳號改由 `RequestActorResolver` 依 claim 解析，不再依路徑判斷：原本 `/api/project-files`（Cookie 驗證）會把**姓名**當成帳號。 |
| LOG-02 | 例外 Channel 從 `DropWrite` 改為 `Wait` ＋ `TryWrite`，丟棄筆數才算得出來。 |
| LOG-03 | `ExceptionLogProvider` 以例外實例去重（`ConditionalWeakTable`），同一個例外只收第一次。 |
| LOG-04 | 新增 `ProcessExceptionHooks`，處理 `UnobservedTaskException` 與 `AppDomain.UnhandledException`。新增例外來源「系統」（`ExceptionSources.Process`），清單標籤為火山橘。 |
| LOG-05 | `ExceptionLogWriter` 關機時清空佇列，上限 5 秒。 |
| LOG-06 | 啟動失敗分三個時間點處理：<br>• **設定驗證**：`StartupSafetyValidator` 移到 NLog 設定之後。<br>• **host 建立前**：失敗直接經 NLog 寫進日誌檔。<br>• **所有啟動失敗**：寫入補登檔（`CrashMarkerStore`，`{ExceptionPath}/pending/`），下次成功啟動時補進例外紀錄。<br>頂層 catch 排除 `HostAbortedException`。 |
| LOG-07 | `Routes.razor` 以第二個 `LoggingErrorBoundary` 包住 `AntContainer`：<br>• 觸發時在畫面底部顯示「畫面元件發生錯誤，已記錄」，並附「重新整理頁面」連結。<br>• 換頁時自動復原。<br>• 樣式 `.overlay-error-banner` 寫在 `theme.css`。 |
| LOG-08 | 17 處查詢關鍵字改記 `HasSearch`／`SearchLength`：<br>• Web API 為 `HasKeyword`／`KeywordLength`。<br>• 專案擁有者篩選為 `HasOwner`。<br>以下靜默的 catch 改為記錄 Warning：<br>• 團隊與權限 JSON 解析失敗：`TeamJsonHelper`、`RoleViewService`、`RbacBackfillService`。<br>• 健康檢查失敗：`SystemHealthService`、`HealthLogReader`，兩者都補注入 `ILogger`。<br>• 例外情境設定失敗：`ApplicationCircuitHandler`、`UseHttpRequestLogging`。 |

**新增的測試**：

| 類別 | 測試 |
|---|---|
| 單元測試 | `RequestActorResolverTests`、`CrashMarkerStoreTests`、`ProcessExceptionHooksTests`、`ExceptionLogWriterTests` |
| `ExceptionLogProviderTests` 補強 | 丟棄計數增量、同實例去重 |
| 整合測試（`ApiIntegrationTests`） | API 例外帶得出帳號、非 API 頁面例外只記一列 |
| 慣例測試 | `LoggingConventionTests.LogPlaceholders_ShouldNotRecordSearchText`、`LoggingConventionTests.CatchBlocks_ShouldNotBeEmpty`、`FormModalConventionTests.AntContainer_ShouldBeWrappedInErrorBoundary` |

**驗證**：
- 全部測試由 996 增為 1,018 項，全數通過。
- 拿掉 LOG-01、LOG-03、LOG-08 的修正後，對應測試都會轉紅（已實測）。
- 啟動失敗已實機驗證：以 Production 設定（佔位密碼）啟動失敗一次，日誌檔出現 FATAL 並產生補登檔。正常啟動後，例外紀錄多了來源為「系統啟動」的一列，補登檔已刪除。

`SystemVersion`：`0.9.76 → 0.9.77`。

## 刻意不做的事

- **Try 型 API 不補日誌**：例如 `SecurePasswordHasher` 格式錯誤回傳 false、AI 回應解析失敗回傳 null。回傳值本身就是結果，由呼叫端處理。
- **不以 GC 觸發 `UnobservedTaskException` 做測試**：觸發時機不定，測試會不穩，改為直接呼叫事件處理器。
- **錯誤提示暫不顯示追蹤碼**：屬 P1 的 LOG-10。
- **浮層例外未在瀏覽器內人工觸發驗收**：目前由慣例測試守住結構，並確認頁面照常渲染。
