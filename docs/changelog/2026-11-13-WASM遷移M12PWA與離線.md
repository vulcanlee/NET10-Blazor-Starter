# WASM 遷移 M12：PWA 與離線（0.10.11）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：0.10.11
- 首次實作版本：0.10.11
- 最後核對日期：2026/11/13

## 目的

WASM 遷移的最後一個里程碑（計畫見 [WASM 遷移計畫](../migration/WASM遷移計畫.md)）：前端成為**可安裝的 PWA**，程式本體由 Service Worker 快取在瀏覽器；**斷線時畫面不卡死、有提示，恢復連線後自動復原**；部署新版時提示使用者重新整理。另外修剪下載量，並做遷移的最終文件整理。
依計畫的決策「離線只要斷線不卡死」：**不做離線資料快取與同步**，資料畫面仍需要連線。
測試報告見 [M12-PWA與離線](../migration/測試報告/M12-PWA與離線.md)。

## 變更內容

### 1. Service Worker：只快取前端自己的檔案

- `MyProject.Web.Client/wwwroot/service-worker.js` 是**開發用**：什麼都不快取、不攔截請求（改了程式重新整理就看得到），啟用時清掉同一範圍發佈版留下的快取（同一個網址先前跑過發佈版時），並保留 `SKIP_WAITING`。發佈時 SDK 以 `service-worker.published.js` 取代它，並在檔頭加上資產清單的版本註解（`MyProject.Web.Client.csproj` 的 `ServiceWorker` 項目）。
- 建置與發佈時產生資產清單 `service-worker-assets.js`（每個檔案的網址與 SHA-256、整份清單的版本；`ServiceWorkerAssetsManifest`）。
- 發佈版**只在安裝時**把清單上的前端檔案（`.wasm`、`.dll`、`.dat`、`.blat`、`.js`、`.json`、`.css`、`.html`、`.png`、`.woff(2)`、`.webmanifest`；排除 Service Worker 自己、沒用到的 Bootstrap 檔案與 AntDesign 主題）帶 `integrity` 放進 `offline-cache-<encodeURIComponent(範圍路徑)>:<清單版本>`（例：`offline-cache-%2F:LfLkqW7Z`）；同站台時入口頁不在清單裡，另外放一份 `index.html`。**執行期間從不寫快取**，所以不可能存到 API 回應、資料或 Token。
- 攔截規則：
  - 不是 GET、跨來源（雙站台的 API、Google 字型）一律不攔截。
  - **伺服器端點一律只走網路**（`networkOnlyPaths`：`/api`、`/signin-google`、`/auths/google`、`/swagger`、`/health`、`/auths/resetpassword`；小寫，整段相符或其下的路徑）。同站台時 API 主機一併提供前端，這些端點都在 Service Worker 的範圍裡，導覽到這裡也不可回 index.html，否則 Google 登入、下載票證、Swagger 都會壞；重設密碼頁的網址帶 Token，一律向伺服器拿，讓伺服器加的 `no-referrer`、`no-store` 生效。
  - 前端的頁面網址（導覽）一律回快取的 `index.html`（快取優先），由前端路由決定顯示哪一頁；清單上的檔案從快取回；其他不攔截。
- 啟用（activate）時只刪**同一範圍**、版本不同的快取：同一來源不同路徑可各部署一套，彼此不互刪（獨立審查前會刪掉同來源所有其他 `offline-cache-*`）。
- ⚠️ **新增伺服器端點（不在 `/api/` 底下的 Controller 路由、OAuth 回呼、健康檢查等）時要加進 `networkOnlyPaths`**，`PwaConventionTests` 會啟動主機、從實際註冊的端點檢查。

### 2. 可安裝為 PWA

- `wwwroot/manifest.webmanifest`：`name`／`short_name`「企業管理平台」、`lang` zh-TW、`display: standalone`、`start_url`／`scope`／`id` 為 `./`、`theme_color` `#a52b59`（＝ `theme.css` 的 `--app-accent`）、`background_color` `#fff7fa`（＝ `--app-page` 的第一個顏色）、圖示 `images/icon-192.png`、`images/icon-512.png`（由 `brand-logo.png` 產生）。
- `index.html` 加 `<link rel="manifest">`、`<link rel="apple-touch-icon" href="images/icon-192.png">`，並以 `<script src="js/pwa.js">` 註冊 Service Worker（CSP 不允許行內腳本）。
- ⚠️ manifest 的名稱是**固定值**：系統參數頁改系統名稱不會跟著變（已安裝的 App 名稱也不變）；複刻新專案改 `SystemName` 時要一起改 manifest（`PwaConventionTests` 比對 `appsettings.json` 的 `SystemName` 與 theme.css 的色票）。

### 3. 新版本提示

- 部署新版後，瀏覽器在開頁時（以及分頁回到前景時，最多每 30 分鐘一次，`registration.update()`）發現 `service-worker.js` 變了，新版安裝完停在等待（**不自動 `skipWaiting`**，使用者可能正在編輯）。
- `js/pwa.js` 通知根元件的 `ClientUpdateBar` 顯示「有新版本，按這裡重新整理」（另有「稍後」收起，下次開頁還會出現）。按下時送 `SKIP_WAITING`，新版啟用、刪掉舊快取，頁面收到 `controllerchange` 後整頁重新載入一次。別的分頁先套用了新版時也顯示提示列，按下直接重新載入。
- 第一次安裝不算新版本；開發模式（開發用的 `service-worker.js` 內容固定）不會出現提示列。
- 註冊時 `updateViaCache: 'none'`：檢查新版時連資產清單也一律向伺服器確認。

### 4. 離線提示列與連線恢復

- `Commons/ClientConnectivity`（scoped）包住 `navigator.onLine` 與 `online`／`offline` 事件（`pwa.js` 的 `appPwa.watchConnectivity`）。`IsOnline` 為 false 表示瀏覽器確定離線；為 true 只代表有網路，伺服器仍可能連不上。
- `Layout/ClientOfflineBar`：瀏覽器離線時顯示「目前離線：畫面可以瀏覽，但需要連線的功能暫時無法使用；恢復連線後會自動重新連線。」（警示琥珀 `--app-warn-*`）。恢復連線時消失，並讓通知推播立即重連（`ClientPushConnection.ReconnectNow`，不等退避，最長 60 秒）、鈴鐺與公告立即重讀（不等 60 秒輪詢）。
- 兩條提示列掛在根元件 `ClientRoutes`（登入頁等匿名頁也看得到），容器 `.app-status-bars` 固定在畫面底部置中、`z-index: 1001`（高於 AntDesign 對話窗 1000、低於通知與訊息 1010），容器本身不接收點擊；樣式在各自的 `.razor.css`，顏色一律 `var(--app-*)`。
- `ApiClient` 連不上伺服器時：瀏覽器確定離線 → 「目前離線，請恢復連線後再試。」（`BrowserOfflineMessage`）；否則照舊「目前無法連線到伺服器，請稍後再試。」（`OfflineMessage`）。
- **離線開頁讀不到身分**：`ClientSession` 讀 `/me` 或刷新 Token 連不上伺服器時設 `IsUnreachable`，`InitializeAsync` 回 false 但**不清 Token、不導去登入頁**（連不上不代表登入失效）；外框顯示「目前無法連線到伺服器，恢復連線後會自動重新載入。」與「重新整理」按鈕。瀏覽器恢復連線時自動重新載入；另外每 15 秒試一次匿名的 `api/v1/shell/culture`（`ClientSession.WaitUntilReachableAsync`），拿到非 5xx 的回應就重新載入。後者是實機發現的：瀏覽器一直有網路、只是伺服器暫時連不上時，收不到恢復連線的事件。
- **伺服器回 502／503／504（IIS 停機、部署中）視同連不上**（獨立審查）：開頁時保留登入、顯示上面的訊息，伺服器恢復後自動重新載入；500 等其他狀態碼照舊回登入頁。
- **API 回 401 後刷新時連不上不再登出**（獨立審查；行為改變）：刷新 Token 時網路斷線或伺服器回 502／503／504，`ApiClient` 的一般請求、下載、串流、表單四條路都回「目前無法連線到伺服器，請稍後再試。」（瀏覽器離線時「目前離線，請恢復連線後再試。」）的失敗結果，不清 Token、不導頁，別的分頁也不會收到登出廣播。0.10.10 以前「刷新時網路斷線」會被當成登入失效而登出。

### 5. 修剪與延遲載入（量測後決定）

- **地區資料改只載中日韓**：`BlazorWebAssemblyLoadAllGlobalizationData`（完整 `icudt.dat`）改為 `BlazorIcuDataFileName=icudt_CJK.dat`（含 zh、zh_Hant、zh_Hant_TW、英文與根語系）。Brotli 後 329,770 → 248,840 bytes（少 81 KB），`_framework` 的 Brotli 總量 −1.8%；英文瀏覽器實測日期仍是 zh-TW 格式。⚠️ 要用到中日韓以外的語系格式時改回 `BlazorWebAssemblyLoadAllGlobalizationData`。
- **不做**：修剪 `System.Private.Xml`（AntDesign 用到）、延遲載入 Markdig（效益約 1.7%，風險大於效益）。

### 6. 發佈與部署

- 靜態站 `web.config` 加 `.webmanifest` 的 MIME（`application/manifest+json`；IIS 預設不認得、會回 404）。`service-worker.js`、`service-worker-assets.js`、`manifest.webmanifest` 檔名不帶指紋，沿用預設的 `no-cache`（瀏覽器才查得到新版）。
- **不產生壓縮副本的清單**移到 `MyProject.Web.Client/FrontendCompression.props`，前端與 API 主機兩個專案共用：`service-worker.js`、`service-worker-assets.js`、`appsettings*.json`、`*.webmanifest`。壓縮副本比版本註解、資產清單與 `ApiBaseUrl` 的改寫早產生，靜態站的 Brotli 規則與同站台的 `MapStaticAssets` 看到它就會送出過期的版本。獨立審查發現：0.10.10 的排除清單只寫在前端專案，同站台發佈（由 API 主機壓縮前端檔案）其實沒套用，`appsettings.json` 與 manifest 都有 `.br`；原本「靜態站發佈後刪掉 Service Worker 壓縮副本」的步驟一併移除。
- 雙站台發佈帶 `-p:StaticSiteApiOrigin` 改寫 `appsettings.json` 時，**同步更新資產清單上它的雜湊與清單版本、`service-worker.js` 的版本註解**（否則 Service Worker 以 integrity 驗證失敗、整個安裝失敗）。
- 同站台由 API 主機以 `MapStaticAssets` 提供這些檔案（`SameSiteHostTests` 確認類型正確、`no-cache`）。

### 7. 與 0.10.10 不同、使用者看得到的地方

- 瀏覽器可以「安裝」這個網站（桌面或手機主畫面，獨立視窗）。
- 斷網時畫面底部出現離線提示列；操作需要連線的功能時錯誤訊息是「目前離線，請恢復連線後再試。」；恢復連線後提示列消失、通知推播與鈴鐺立即更新。
- 離線時重新整理或重開網址，外框照樣開得起來、不會被登出，顯示「目前無法連線到伺服器，恢復連線後會自動重新載入。」，恢復後自動回到原本的頁面。
- 部署新版後畫面底部出現「有新版本，按這裡重新整理」。⚠️ 部署後使用者第一次開頁仍是舊版（從快取），要按提示列（或關掉這個網站的所有分頁再開）才換成新版。

### 8. 已知限制

- Service Worker 只在 **HTTPS 或 localhost** 生效；用 http 的內部網址部署時沒有離線與安裝功能（其他功能不受影響）。
- Material Icons 字型由 Google Fonts 跨來源載入、不快取：離線時圖示會顯示成文字（例如「menu」）。
- 離線時只能開外框與看到提示，資料畫面需要連線（計畫決策「離線只要斷線不卡死」）。
- 開發模式（`dotnet run`）不快取、不會出現新版本提示；要驗證 PWA 行為須用發佈版前端。
- **部署後不可手改任何前端檔案**（獨立審查）：Service Worker 以 integrity 驗證每個檔案，手改的檔案會讓新版安裝失敗、使用者停在舊版，修改本身也不生效；一律重新發佈。新版安裝失敗時 `pwa.js` 經 `client-error-reporter.js` 新增的 `report()` 回報：API 主機日誌與系統例外紀錄出現一筆來源「瀏覽器」的錯誤，訊息以 `Service worker installation failed…` 開頭（登入前最多暫存 20 筆，登入後送出）。
- **快取的入口頁連同回應標頭一起存**（獨立審查）：只改伺服器的安全標頭（CSP 等）而前端沒變時，使用者沿用舊標頭；要重新發佈前端讓版本變動。
- **退版到 0.10.10 以前、拿掉 PWA、同站台改雙站台而原網址改當 API 主機**（獨立審查）：已裝過的使用者會卡在快取的舊前端、沒有提示；要在原網址部署「自我註銷」的 `service-worker.js`，範例與步驟見 [正式部署與安全檢查清單](../operations/正式部署與安全檢查清單.md)「退版／移除 Service Worker」。

## 升版注意

- 版本號 0.10.10 → 0.10.11。
- 沒有資料庫異動、沒有新的伺服器設定鍵。
- 行為改變：API 回 401 後刷新 Token 時網路斷線或伺服器回 502／503／504，0.10.10 以前會被登出，0.10.11 起保留登入、顯示「目前無法連線到伺服器」，恢復後照常使用。
- 衍生專案若在自己的專案檔加過 `CompressionExcludePatterns`：前端的排除清單改在 `MyProject.Web.Client/FrontendCompression.props`，API 主機的專案檔也要匯入它。
- 部署：靜態站要更新 `web.config`（`.webmanifest` 的 MIME）；PWA 只在 HTTPS 生效。部署新版後使用者要按「有新版本」提示列（或關掉所有分頁再開）才換成新版，期間舊前端仍會呼叫新 API —— API 的改版要相容舊前端，或請使用者重新整理。⚠️ 0.10.11 起不可在部署後手改前端檔案；之後要退回 0.10.10 以前，先照部署清單「退版／移除 Service Worker」部署自我註銷的 `service-worker.js`。
