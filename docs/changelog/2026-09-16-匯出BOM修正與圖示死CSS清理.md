# 匯出檔補上 UTF-8 BOM，並清掉圖示的死 CSS（0.9.16）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：0.9.16
- 首次實作版本：0.9.16
- 最後核對日期：2026/09/16

## 起因

0.9.14 實作 Token 用量時，實跑抓下匯出檔的位元組，意外發現兩個**建置、測試、
程式碼審閱全都看不出來**的問題。當時只順手修了 Token 用量那一處，其餘掛在待辦上，
本次補齊。

---

## 一、匯出的 CSV／日誌其實沒有 BOM

### 問題

三個匯出點都寫成：

```csharp
// 加 BOM，否則 Excel 開啟繁體中文會亂碼。
var bytes = new UTF8Encoding(encoderShouldEmitUTF8Identifier: true).GetBytes(text);
```

⚠️ **`GetBytes` 不會輸出前導碼。** 那個旗標只影響 `GetPreamble()` 與 `StreamWriter`，
所以旗標設了也一樣沒有 BOM ——「加 BOM」那行註解從頭到尾都是假的。

實測檔頭是 `E6 99 82`（「時」）而不是 `EF BB BF`。

| 匯出點 | 檔案 | 0.9.16 前 |
|---|---|---|
| 日誌檢視 → 匯出 | `MyProject.Web-logs-*.log` | **無 BOM** |
| 系統例外紀錄 → 匯出 CSV | `MyProject.Web-exceptions-*.csv` | **無 BOM** |
| Token 用量 → 匯出 CSV | `MyProject.Web-llm-usage-*.csv` | 0.9.14 已修 |

> 前兩者的標頭與每一格都是繁體中文，Excel 開起來就是整片亂碼。
> 而 [日誌檢視 PRD](../prd/日誌檢視-prd.md) 早在 0.4.x 就寫著「編碼為 UTF-8 含 BOM」——
> **文件沒寫錯，是程式沒做到。**

### 作法

新增 `MyProject.Web/Components/Commons/TextDownloadPayload.cs`，把「接上 `GetPreamble()`」
這件事收斂成一個修改點（與同目錄 `TableSortHelper` 同一思路 ——
原本各檢視複製一份、改了要改好幾處）：

```csharp
var bytes = TextDownloadPayload.Utf8WithBom(text);
```

三個匯出點各縮成這一行。`TokenUsageView` 那份 0.9.14 的 8 行也一併收掉。

### 守門

新增 `MyProject.Tests/ExportEncodingConventionTests.cs`（4 筆）：

| 測試 | 驗什麼 |
|---|---|
| `Utf8WithBom_ShouldStartWithBomBytes` | 前三個位元組是 `EF BB BF` |
| `Utf8WithBom_ShouldRoundTripChinese` | 去掉前導碼後逐字還原，補 BOM 不動內容 |
| `Utf8WithBom_ShouldReturnOnlyBom_WhenTextIsEmpty` | 查無資料時仍下載得到編碼正確的空檔 |
| `WebSources_ShouldNotUseRawUtf8EncodingFlag` | **掃 Web 原始碼**，除 `TextDownloadPayload.cs` 外不得再出現 `encoderShouldEmitUTF8Identifier` |

最後一支是重點：這個 bug 不會讓任何東西變紅，唯一防線就是不讓那個旗標再被寫出來。
掃描前先 `Assert.NotEmpty` 檔案清單 —— 路徑一失效測試就會空跑綠燈，等於沒守門
（沿用 `AiModalStyleConventionTests` 的同一道保險）。

**已實測守門有效**：故意在 `Diagnostics/TokenUsageFormat.cs` 加一行帶該旗標的註解，
測試立刻失敗並指名該檔。

## 二、圖示的 font-size CSS 全是死的

### 問題

`MaterialIcon` 元件會輸出**行內**的 `style="font-size:24px;"`，CSS 的 `font-size`
規則一律被壓過（全專案沒有任何一條帶 `!important`）。

全專案 4 個 CSS 檔共 **9 條死的 `font-size`**，外加 1 條靠繼承、同樣打不到的
（`.sidebar-brand-icon` 的唯一子節點就是 `<MaterialIcon>`）。

### 變更

| 檔案 | 動作 |
|---|---|
| `Components/Commons/ToolbarIconButton.razor.css` | 刪 `font-size: 18px`，保留 `line-height: 1` |
| `Components/Commons/CrudActionButton.razor.css` | 同上 |
| `Components/Layout/MainLayout.razor.css` | 整條刪（使用者選單圖示與箭頭，只有 font-size）|
| `Components/Layout/NavMenu.razor.css` | 漢堡鈕、品牌圖示、窄螢幕漢堡鈕三條整條刪；`.sidebar-brand-icon` 的繼承 font-size 刪；展開選單項、收合觸發鈕、飛出子選單三條只刪 font-size，`color`／`line-height` 保留 |

四個檔案各留一行註解：圖示大小請改 `MaterialIcon` 的 `Size` 參數
（側邊欄走 `Components/Layout/MaterialIconOpticalSize.cs`）。

⚠️ 沒有動到**有效**的文字 `font-size`：`NavMenu.razor.css` 的 `.ant-menu-item`（0.92rem，
選單文字）、`.collapsed-flyout-item`（0.92rem，飛出項文字）、`.navbar-brand`（1.15rem，
品牌文字）都保留。

### ⚠️ 刪掉的是「從未生效的設計意圖」

這些規則不只是冗餘。14 個 `<MaterialIcon>` 裡有 **9 個沒傳 `Size`、停在預設 24px**，
而 CSS 原本想要的是：

| 位置 | CSS 想要 | 實際 |
|---|---|---|
| `ToolbarIconButton`（36×36 按鈕內） | 18px | 24px |
| `CrudActionButton`（28×28 按鈕內） | 18px | 24px |
| 右上角使用者選單圖示與箭頭 | 19.2px | 24px |
| 側邊欄漢堡鈕 | 17.6px（窄螢幕收合 15.2px） | 24px |
| 側邊欄品牌圖示 | 20.8px | 24px |
| 展開側邊欄的選單項 | 16px | 24px（`home` 27px）|

**刪掉等於正式承認「現在的 24px 就是定案」** —— 使用者一路看到的、
0.9.15 光學補正的基準，都是這個外觀。本次刻意不改任何圖示的實際大小。
日後若真想縮小，路徑是 `Size` 參數（`ToolbarIconButton`／`CrudActionButton`
目前沒有 `Size` 參數，要縮得先補一個），**不是把 CSS 改回去**。
