# 錯誤與警告通知加「複製」按鈕並寫入日誌（0.9.129）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：0.9.129
- 首次實作版本：0.9.129
- 最後核對日期：2026/10/19

## 起因

右下角「系統訊息」通知出錯時（例如 AI 服務回 HTTP 429 的長訊息），使用者只能截圖或手抄，回報時常漏掉時間與錯誤追蹤碼。
而且通知本身不寫日誌，要靠每個呼叫點自己先寫 `logger.Log*`，做法不一致：有些業務拒絕只跳通知，/logs 查不到使用者看到了什麼。

## 決定（2026/10/19，與使用者逐項確認）

| 項目 | 決定 |
|---|---|
| 哪些通知加「複製」 | `Error`、`UnexpectedError`、`ValidationError`，以及新增的 `Caution`（真正的警告）；成功訊息（沿用 `Warning`）與 `Info` 不加 |
| 複製內容 | 標題、內文、錯誤追蹤碼（只出現一次）、時間、頁面網址 |
| 顯示時間 | 有複製鈕的通知**不自動關閉**（`Duration = 0`），按 X 關閉 |
| 複製回饋 | 按鈕文字改成「已複製」或「複製失敗」，2 秒後恢復，不另外跳通知 |
| 日誌 | 在 `ViewNotification` 顯示當下集中寫一筆：`UnexpectedError` 記 Error，`Error`（多半是業務拒絕）、`ValidationError`、`Caution` 記 Warning；呼叫點原本的 log 保留，兩筆以同一個追蹤碼串起來 |
| `Warning` 怎麼分 | 盤點 85 處後，26 處真正的警告改成 `Caution`（操作失敗、衝突或找不到資料、AI 結果不完整、匯出筆數超過上限）；「瀏覽器拒絕存取剪貼簿」維持 `Warning`，因為這時複製也會失敗 |
| 變更密碼頁 | 原本自己建立通知（標題「變更密碼失敗」），改走 `ViewNotification`，標題改用標準的「系統訊息」或「驗證失敗」 |

## 注意

- `UnexpectedError` 原本停留 10 秒、`ValidationError` 5 秒，現在都改成不自動關閉。
- 通知日誌不帶例外物件，所以只寫到 /logs，不會進入「系統例外紀錄」；例外仍由呼叫點的 `LogError(ex, ...)` 記錄。
- 通知內文會原樣寫進日誌，所以內文不可夾帶密碼、token 或 Email（本次已掃描，現有呼叫點沒有）。
