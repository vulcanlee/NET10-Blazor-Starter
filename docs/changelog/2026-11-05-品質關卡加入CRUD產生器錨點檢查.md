## 目的

CRUD 產生器（`New-CrudModule.ps1`）以既有程式碼為錨點插入登記。0.9.133 改寫了 `SoftDeletePurgeService`，錨點因此失效，產生器一直壞到 0.9.152 才修好（見 [修正 CRUD 產生器登記錨點](2026-11-04-修正CRUD產生器登記錨點.md)）。
會發現這種問題的 `Test-CrudGenerator.ps1` 要跑數分鐘，所以不在品質關卡裡。這一版加了一個幾秒鐘的檢查放進品質關卡：被登記的檔案改了寫法、錨點對不上時，提交前就會擋下。

## 一、`New-CrudModule.ps1 -CheckAnchors`

- 照常執行每一項登記的插入邏輯（就是產生器真正用的那些 transform），但**不寫任何檔案**：不產生樣板、不改被登記的檔案、不產生 migration，也不檢查工作目錄是否乾淨。
- 找不到錨點時，沿用原本的錯誤「找不到登記位置：<項目>…樣板或錨點需要更新。」。同一個檔案有多處登記時，`Insert-AfterRequired` 會再附上找不到的錨點內容。
- 遇到「已存在」的登記時當作失敗：檢查用的名稱一定是新的，出現「已存在」代表那一項的錨點根本沒有檢查到。
- 通過時印出「CRUD 產生器錨點檢查通過（N 項）」。
- 不另外維護一份錨點清單（那份清單本身也會過期），檢查的就是產生器自己的登記邏輯。

## 二、品質關卡第 6 步「CRUD anchors」

- `Invoke-QualityGate.ps1` 在「Docs encoding」之後、「Vulnerability」之前執行 `Invoke-CrudAnchorCheck`。不需要連網，`-Quick` 也會跑。
- 以 `-Name CrudAnchorProbe -DisplayName 產生器錨點檢查 -Icon crud_anchor_probe` 跑三種組合：一般、`-WithTeams`、`-AdminOnly -MenuGroupId 8`。三種組合涵蓋的分支與 `Test-CrudGenerator.ps1` 相同。
- `-Icon` 用不存在的名稱，讓「選單圖示允許清單」這一項也真的檢查到錨點。
- repo 沒有 `scripts/New-CrudModule.ps1`（例如衍生專案刪掉了產生器）時略過。
- 它只確認插得進去。修改產生器或樣板後，仍要跑 `Test-CrudGenerator.ps1`，確認產出的模組能建置、能通過測試。
