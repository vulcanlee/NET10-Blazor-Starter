# 系統健康監控頁：外框對齊粉梅、修掉重複標題與字級（0.9.31）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：0.9.31
- 首次實作版本：0.9.31
- 最後核對日期：2026/09/19

## 為什麼

0.9.30 把全站收進粉梅色票時，**刻意排除了整個系統健康監控頁**，理由是
「紅綠燈是語意色，染粉會傷害可讀性」。

實際畫面出來後，那個理由仍然成立，但**範圍畫得太寬**：讓這一頁在新的 28px 圓角
粉色卡片裡看起來像外來物的，是**外框**不是**號誌** —— 方角、`#d9d9d9` 冷灰邊框、
`#666` 冷灰次要文字、純黑的號誌光環。這些是 chrome，與「號誌要一眼可辨」無關。

同時發現兩個與顏色無關的問題：

1. **標題重複**：頂部列已顯示「系統健康監控」，摘要卡裡又有一個同文字的 `<h1>`。
2. **字級全用瀏覽器預設**：整頁一個 `font-size` 都沒寫，`h1`/`h2`/`h3` 吃 32/24/19px，
   項目標題比它底下的內文大一大截，密度與其他頁對不上。

## 做了什麼

改動集中在 `Components/Pages/SystemHealthPage.razor.css` 一個檔（`.razor` 未改）。

**外框跟著色票走**

- `.system-health-summary`、`.health-item`、`.system-health-loading`、`.empty-log`：
  `#d9d9d9` → `var(--app-line)`，補上 `var(--app-radius-control)` 圓角。
- `.health-item-heading span`、`.log-path`：`#666` → `var(--app-muted)`。
- `.traffic-light` 的光環：`rgba(0,0,0,0.06)` → `rgba(var(--app-shadow-rgb), 0.1)`。
- `.health-failure`、`.log-tail`：補圓角，顏色一律不動。

**字級**

`h2` 1.05rem／`h3` 1rem／內文 0.875rem／後設資訊 0.8rem。
`.summary-score strong`（100%）維持 32px —— 那是這一頁唯一該大的數字。

**重複標題**

`<h1>系統健康監控</h1>` **視覺隱藏而非刪除**。它是整頁唯一的 `<h1>`，拿掉會讓文件
失去標題層級，而頂部列的標題是 `MainLayout` 的一個 `div`，補不了這個洞。手法沿用
`CrudActionButton` 的 `.crud-action-button-label`（`position:absolute` ＋ `clip`）。
因為是純 CSS，`.razor` 一行都沒改。

## 刻意維持原色

三顆號誌色 `#1f8f45`／`#c78100`／`#c7362f`、卡片左側 6px 狀態色條、
`.health-failure` 的紅色失敗區塊、`.log-tail` 的深色終端機底。
這些是使用者掃這一頁時唯一要讀的訊號。

⚠️ 它們也**刻意不收進 `theme.css`** —— 那是本頁的語意常數，不是品牌色票；
收進去會讓「換品牌色」連帶改掉紅綠燈。`ThemeConventionTests` 的色票清單不含它們，
不會誤報。

## 一個實作細節

狀態色條由 `border-left: 6px solid <色>` 改為 `box-shadow: inset 6px 0 0 0 <色>`。
加上圓角之後，6px 的左邊框與 1px 的上下邊框在轉角會接成一塊楔形；
inset 陰影則順著圓角裁切，邊框維持均勻 1px。兩個元素原本都沒有 `box-shadow`，不衝突。
對應的 `padding-left` 一併加大，避免文字貼到色條。
