# 忘記密碼與重設密碼：Email 連結自助重設、三頁共用登入外觀（0.9.60）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：0.9.60
- 首次實作版本：0.9.60
- 最後核對日期：2026/09/24

## 為什麼

0.9.59 補上寄信能力後，《腳手架開發指引》§10 缺口 #4 只剩下半段：**沒有忘記密碼**，使用者被鎖在外面只能找管理員。
這是兩階段中的第二階段，設計在第一輪問答就已定案，見
[設計文件](../superpowers/specs/2026-09-24-email-password-reset-design.md)。
原訂 0.9.60 的《寄信服務使用說明》順延為 0.9.61，一次涵蓋寄信與忘記密碼。

## 做了什麼

- **登入頁**：寄信啟用（`EmailSettings:Provider` 不是 `None`）時，「記住我」右側出現「忘記密碼？」；
  從重設頁成功導回時顯示綠色「密碼已重設，請以新密碼登入。」。
- **兩個匿名頁**：`/Auths/ForgotPassword`（帳號或 Email ＋ 驗證碼）、`/Auths/ResetPassword?token=…`（新密碼兩次）。
  寄信未啟用時兩頁只顯示「未啟用」。加入 `PageAuthorizationTests` 匿名白名單。
- **資料表** `PasswordResetToken`（migration `AddPasswordResetToken`）：只存 token 的 SHA-256；`TokenHash` 唯一索引；
  FK 對 `MyUser` 為 Cascade。
- **設定** `PasswordResetSettings`：`TokenLifetimeMinutes`（預設 30，5–1440）、`RequestCooldownSeconds`（預設 60，0–3600），`ValidateOnStart`。
- **服務** `PasswordResetService`（Business）：`RequestAsync`／`ValidateTokenAsync`／`ResetAsync`；
  稽核 `Password.ResetRequested`／`ResetCompleted`／`ResetFailed`（稽核紀錄頁以橘色標示）。
- **信件**：`EmailTemplates.BuildPasswordReset`、`BuildPasswordChanged`，信件種類 `PasswordReset`／`PasswordChanged`。
- **共用外觀**：新元件 `AuthShell`；`MyProject.Web.csproj` 以 `CssScope="b-auth-shell"` 讓登入、忘記、重設三頁與外框共用
  `Login.razor.css` 的 scope —— 樣式原封不動，只在檔尾追加三個類別。驗證碼產生抽到 `AuthCaptcha`。
- **連結網址**：`PublicBaseUrlResolver`，以 `EmailSettings:PublicBaseUrl` 為準；留白時只有非 Production 退回目前請求的網址。
- 健康監控「寄信服務」在 `None` 時的佐證補一句「登入頁也不提供忘記密碼」。

## 關鍵決定

| 決定 | 理由 |
|---|---|
| token 獨立成表，不在 `MyUser` 加欄位 | 管理員編輯使用者時 `MyUserService.UpdateAsync` 會把 AdapterModel 沒帶的 `MyUser` 欄位覆寫成預設值 |
| 只存 SHA-256、新申請與重設成功都作廢其餘 token | 資料庫外洩拿不到可用的連結；同一帳號永遠只有最新一封信有效 |
| 交易內 `ExecuteDelete` 搶占 token | 同一個連結並發送出兩次，只有一次會成功 |
| 密碼規則不過不消耗 token | 使用者打錯一次不必重新申請 |
| 畫面一律同一句話、信走背景佇列、原因只寫稽核 | 防止用這一頁試探帳號是否存在（包括用回應時間試探）|
| 一個 Email 對多帳號 → 各寄一封 | `Email` 沒有唯一索引；信中與重設頁都標明帳號 |
| 排除 support、停用、無本地密碼的 Google 帳號、Email 無效 | support 每次啟動被重設；停用者重設也登不進來；Google-only 本來就沒有密碼可忘 |
| 新密碼 ≥ 6 字元且 ≠ `123456` | `123456` 是強制改密碼的哨兵值；只套用在忘記密碼，不動既有兩個改密碼入口 |
| 重設成功解除鎖定、寄「密碼已變更」通知、不自動登入 | 被鎖的人可立即登入；非本人操作時帳號主人能察覺 |
| 樣式用 `CssScope` 共用，不改寫成 `::deep` 或複製 | 登入頁 415 行樣式零改動，回歸風險最低 |

## 順手修正（整合測試的 NLog 競態）

新增兩個會啟動 host 的測試類別後，整合測試開始大量失敗（`NLogConfigurationException: Unrecognized value 'BasePath'`）。
根因是既有問題：`Program.cs` 結束時 `LogManager.Shutdown()` 清掉全行程的 NLog 設定，而 `Main` 在背景執行緒結束、時間點不受控；
下一個 host 啟動時 NLog.Web 找不到設定，就把 appsettings 的 `NLog` 區段（其實只放 `BasePath`）當 NLog 設定解析。原本四個 host 類別
恰好同時啟動而沒觸發。處置：

- `Program.cs`：`UseNLog(new NLogAspNetCoreOptions { LoggingConfigurationSectionName = "" })`，不再從 appsettings 載入 NLog 設定。
  正式環境行為不變（設定一律來自 `nlog.config`，已實測日誌照常寫檔）。
- `ApiTestApplicationFactory`：建構時若 NLog 設定已被清掉，重新載入 `nlog.config`。
- 新增 `IntegrationHostCollection`：六個啟動 host 的測試類別循序執行，也一併消除 factory 寫入／清除行程環境變數的競態。

## 驗證

```
dotnet build src/MyProject/MyProject.slnx                     → 建置成功，0 warning
dotnet test  src/MyProject/MyProject.slnx                     → 847 通過（799 → 847，+48），連跑 5 次結果一致
dotnet format src/MyProject/MyProject.slnx --verify-no-changes → 無差異
scripts/Test-DocsEncoding.ps1                                 → 全部通過
```

端對端（Development、Provider=Pickup、暫存資料庫與目錄，headless 瀏覽器）：

1. 登入頁出現「忘記密碼？」→ 以大小寫不同的 Email 申請 → 畫面訊息正確，Pickup 資料夾出現重設信（寄件者、收件者、主旨、連結皆正確）。
2. 60 秒內以帳號再申請 → 畫面相同、沒有新信；以不存在的 Email 申請 → 畫面相同、沒有新信。
3. 重設頁：5 字元、不一致、`123456` 各自被擋並顯示原因 → 合規密碼送出 → 導回登入頁顯示成功訊息。
4. 以新密碼登入成功（該帳號原本處於鎖定狀態，已一併解除）；同一連結再開 → 「重設連結無效或已過期」＋「重新申請重設信」。
5. 資料庫 token 清空；稽核依序為 ResetRequested（成功）、ResetRequested（Cooldown）、ResetRequested（NotFound）、ResetCompleted、Login.Success；
   另有一封「您的密碼已變更」通知信。
6. Provider=None：登入頁沒有連結、兩頁顯示未啟用。登入頁 HTML 正規化後與改動前逐字相同，截圖一致。

## 影響

- 出貨預設 `EmailSettings:Provider=None`，**什麼都不會變**：登入頁沒有連結、兩頁顯示未啟用。
- 啟用寄信即開放忘記密碼。請確認使用者的 Email 登記正確；上線檢查見 [正式部署與安全檢查清單](../operations/正式部署與安全檢查清單.md)。
- 新增 migration，啟動時自動套用。
- 已知限制：重設後其他裝置的工作階段不會失效、沒有依 IP 限流、驗證碼只是減速帶、token 會出現在 IIS W3C 日誌。
