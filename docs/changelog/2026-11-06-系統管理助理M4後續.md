## 一、核准窗顯示「目前狀態」

原本修改系統參數的核准窗只顯示 key 與新值，看不到目前值；會不會縮短、縮短多少，只能靠模型在回覆裡寫。

- `AiToolDefinition.ApprovalPreview`（選填）：提出核准時，用模型給的參數算一段給人看的說明。
- `AiAgentToolFactory.PreviewAsync`：
  - 用它持有的服務呼叫預覽，最多等 5 秒。
  - 逾時或例外時回 null 並記警告，不擋核准。
- 預覽結果的傳遞與保存：
  - 經 `AiToolApprovals.TriageAsync` 帶到 `AiToolApprovalRequest.Preview`。
  - 存進 `AiAgentPendingApprovalRecord.Preview`（只加不改，`SchemaVersion` 不變）。
  - 接續時照樣顯示、不重算。真正執行時，工具仍會重讀最新資料與版本戳記。
- 工作流程不傳預覽，行為不變。
- 掛在 `set_system_parameter`、`reset_system_parameter`、`shorten_retention`（`OpsAssistantTools.PreviewParameterChangeAsync`）。
  - 例如：「稽核紀錄保留天數：目前 365 天（設定檔）；設定檔值 365 天；改為 30 天。⚠ 會縮短保留期限。」
  - 只有保留類參數才加「會不會縮短」那一句。
  - 找不到參數時不顯示。
- `AdminAssistantView` 在核准說明下方顯示「目前狀態」，沿用既有樣式、不新增色票。
- 順手更正三個修改系統參數工具的說明：原本寫「會縮短保留天數的修改不在這一版處理」，改成指向 `shorten_retention`。

## 二、刪除 AI 對話紀錄只讀資料列

`delete_ai_call_logs` 原本為了取作業名稱，呼叫 `GetDetailAsync`，會讀內容檔、反序列化並查 Token 用量，50 筆就讀 50 次檔。
改用新的 `AiCallLogService.GetByIdAsync`，只讀資料列。

## 三、已刪除帳號超過上限時說明

`search_users`（`status=deleted`）只讀前 5000 位，超過時原本沒有說明。
新增 `AccountsAssistantTools.ScanNote`，一般查詢與已刪除帳號共用，超過時在 `note` 寫「已刪除的帳號共 N 位，只檢查前 5000 位」。
