# 密碼原則與登入鎖定：規則、歷史、到期與鎖定都能在畫面上調整，旗標取代 123456，管理員可解鎖（0.9.101）

## 目的

[路線圖](../planning/00-腳手架強化路線圖.md) C-9（第 1 批第三項）。改動前：

- 密碼規則各處不一致：右上角對話窗至少 6 字、`/ChangePassword` 頁沒有下限、忘記密碼至少 6 字且不可為 123456、管理員設密碼沒有任何規則。
- 「必須變更密碼」以「密碼等於 123456」表達，每次換頁都算一次 PBKDF2。
- 鎖定是寫死的 5 次、15 分鐘；⚠️ 鎖定到期後失敗次數留在門檻上，**再錯一次就立刻又鎖**；Google 登入不看鎖定；管理員看不到誰被鎖、也沒有解鎖按鈕（只能改密碼）；鎖定時回「帳號已鎖定」，等於告訴別人這個帳號存在。

使用者決定：

- 預設「中等」：至少 8 字、要有英文與數字、不可重複最近 3 組、不過期；全部可在系統參數調整。
- 以「下次登入須變更密碼」旗標取代 123456；管理員新增使用者或替使用者設密碼時預設勾選。
- 修正鎖定到期後的再鎖、Google 登入也看鎖定、使用者清單顯示鎖定、鎖定訊息不透露帳號是否存在；鎖定次數最少 1（不能關閉）。
- 移除右上角的變更密碼對話窗，只留頁面。

## 二、設計決定

| 決定 | 理由 |
|---|---|
| `ApplyAsync` 是唯一的雜湊點，加守門測試 | 之後新增的設密碼路徑若繞過原則，測試會擋下；規則、歷史、旗標、解鎖不會漏做其中一樣 |
| 歷史含目前密碼，存與 `MyUser.Password` 相同的雜湊 | 不必重算；升級前沒有歷史的帳號也擋得住「改回同一組」 |
| 歷史在 `ApplyAsync` 裁切，比對只取最近 N 筆 | 調小次數後不必立刻清資料，下一次設定密碼時自然裁掉 |
| 旗標取代 123456；舊資料在登入時補旗標 | 旗標可以由管理員直接勾選；舊資料只有雜湊、無法用 SQL 轉換，登入那一刻才看得到明文 |
| support 與沒有本機密碼的帳號豁免 | support 每次啟動被重設回設定檔的密碼；Google 帳號無從變更 —— 不豁免會永遠卡在變更頁 |
| 三種登入失敗同一則訊息、登入頁固定顯示規則 | 不讓人從訊息判斷帳號存在；被鎖住的人仍知道可以等、重設或找管理員 |
| 解鎖用 `ExecuteUpdate`、不換版本號 | 解鎖不是編輯；別人正開著這位使用者的編輯窗時不該因此衝突 |
| Google 判斷抽成 `ExternalLoginResult.Evaluate` | 控制器沒有測試；抽出來才測得到「鎖定要擋」這條規則 |
| 移除變更密碼對話窗 | 兩個入口規則不同是錯誤的根源；只留一個入口 |
| 不採用路線圖說的「重用 `PasswordHelper.cs`」 | 它是舊 SHA256 格式，只留給登入時的舊雜湊相容判斷 |
