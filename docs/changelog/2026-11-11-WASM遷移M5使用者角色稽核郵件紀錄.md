- 文件版本：1.0
- 文件狀態：已實作

- 首次實作版本：0.10.4
- 最後核對日期：2026/11/11

## 目的

WASM 遷移的第五個里程碑（計畫見 [WASM 遷移計畫](../migration/WASM遷移計畫.md)）：「使用者管理」（`/myusers`）、「角色管理」（`/roleviews`）、「稽核紀錄」（`/audit-logs`）、「寄信紀錄」（`/email-logs`）改在使用者的瀏覽器以 WebAssembly 執行，背後是新的只限管理員的 Web API。
同時建立「每個 API action 都要標註授權意圖」的規則與守門測試，並把原本只在畫面擋的自我保護補到 API。其他頁面維持原狀。
測試報告見 [M05-使用者角色稽核郵件紀錄](../migration/測試報告/M05-使用者角色稽核郵件紀錄.md)。

## 變更內容

### 1. 四個管理頁改用 WebAssembly

- 頁面與檢視搬到 `MyProject.Web.Client`（`Pages/MyUserPage.razor`、`RoleViewPage.razor`、`AuditLogPage.razor`、`EmailLogPage.razor`，`Views/Admins/*`，含 `RolePermissionMatrix`），Server 版已刪除。
  畫面、按鈕、對話窗與訊息和以前相同：與 Server 版截圖比對 8 個畫面，4 個完全相同，其餘最多 17/255 的色差、肉眼看不出差異。
- 資料經 `Web.Client/Api/UserApi.cs`、`RoleApi.cs`、`AdminLogApi.cs` 呼叫 API；DTO 與畫面模型的對應在 `UserDtoMapper`、`RoleDtoMapper`，WASM 頁面與伺服器的 Controller 共用。DTO 在 `MyProject.Dtos/Admins`。
- 目前以 WebAssembly 執行的頁面：`/Profile`、`/categories`、`/teams`、`/projects`、`/myusers`、`/roleviews`、`/audit-logs`、`/email-logs`。

### 2. 只限管理員的 Web API

都只有 `api/v1` 路由、要 Bearer、標 `[AdminOnly]`（見第 3 節），走與畫面相同的服務（`MyUserService`、`TwoFactorService`、`RoleViewService`、`AuditLogQueryService`、`EmailOutboxQueryService`）。端點細節見 [Web API 端點目錄](../architecture/Web%20API%20端點目錄.md) 第二之一節。

- **`api/v1/users`**（`UsersController`）：`POST search`（每列帶 `CanDelete`／`CanCopy`／`CanToggleStatus`／`CanForceLogout`／`CanResetTwoFactor`，以及依伺服器時區算好的鎖定文字 `LockedText`）、`GET {id}`（含額外角色與團隊，寫 `User.View`）、`GET options`（角色含預設團隊、團隊、預設角色、密碼規則說明）、`GET password/generate` 的回應帶 `Cache-Control: no-store`（明碼密碼不可被快取）、`POST check`（新增前檢查帳號等規則：「複製」建立時與 Server 版同樣順序，先檢查帳號、再問「Email 已有人使用」）、`GET {id}/copy-draft`（support 或不存在回 404）、`POST accounts-using-email`、`POST`（新增；`CopiedFromAccount` 有值時稽核記 `copiedFrom`）、`PUT {id}`（回 `SessionRefreshUrl`，見第 4 節）、`PUT {id}/enabled`、`POST {id}/unlock`、`POST {id}/force-logout`、`POST {id}/two-factor/reset`、`DELETE {id}`、`POST {id}/restore`、`DELETE {id}/purge`、`POST export`（xlsx）。
- **`api/v1/roles`**（`RolesController`）：`POST search`（含權限矩陣）、`GET {id}`（寫 `Role.View`）、`GET options`（團隊與空白矩陣）、`POST`、`PUT {id}`、`DELETE {id}`、`POST {id}/restore`、`DELETE {id}/purge`。權限矩陣在 API 上是樹狀 DTO（群組 → 頁面 → 動作），伺服器轉成權限鍵，規則不變。**只採納權限目錄**：送來的矩陣套到 `InitializePermissionSetting()` 的範本上，目錄裡沒有的群組、頁面、動作一律忽略（呼叫端不能多塞「稽核紀錄」這類管理員專屬鍵）；修改不再覆寫建立時間（`CreateAt`）。
- **`api/v1/audit-logs`**（`AuditLogsController`）補上稽核紀錄頁的其他端點（0.10.2 起已有的 `history`、`{id}/content` 不變）：
  - `POST search`：`RecordSearch` 為 true 時寫 `Audit.Search`，自由輸入的欄位只記有沒有填。
  - `GET options`：出現過的動作、目標類型、清除用的保留天數、記錄範圍提示。
  - `GET {id}`：明細與詳細內容，本地與 UTC 時間由伺服器算，寫 `Audit.View`。
  - `POST export`：CSV、UTF-8 含 BOM、最多 10000 筆（與 Server 版相同），寫 `Audit.Export`，記實際匯出筆數；超過 10,000 筆被截掉時另記總筆數（`format=csv; rows=10000; total=N`）。
  - `POST purge`：兩段清除各寫一筆 `Audit.Purge`。
  - `POST clear-all`：寫 `Audit.ClearAll`。
  - `POST verify`：完整性驗證，寫 `Audit.Verify`；WASM 端這個請求最長等 30 分鐘（`ApiClient.PostLongRunningAsync`），不受一般 100 秒逾時限制。
- **`api/v1/email-logs`**（`EmailLogsController`）：`POST search`（唯讀，不寫稽核，與 Server 版相同）。
- 非管理員一律 403，並寫一筆 `Permission.Denied`（detail「需要管理員」）。
- 四個 controller 都套 `[ApiValidationFilter]`：每頁筆數 1～200、頁碼 ≥ 1，不合法回 400。使用者的帳號、名稱、角色與角色名稱的必填由伺服器再驗一次（400），API 呼叫端不經過畫面的表單驗證。
- 失敗依種類回狀態碼：找不到 404、重複或衝突 409、規則不符 400、未預期 500（`MyUserService`、`RoleViewService`、`TwoFactorService` 的失敗都標上 `Kind`）；錯誤訊息就是畫面那一句。
- 寫入的稽核由服務寫（與畫面相同、每個動作一筆）；查看、搜尋、匯出由 Controller 寫。

### 3. `[AdminOnly]`、`[SignedInUser]` 與守門測試

- **`[AdminOnly]`**（`MyProject.Web/Filters/AdminOnlyAttribute.cs`）：授權篩選器。沒登入回 401；不是管理員回 403 `ApiResult`（「只有管理員可以使用這個功能。」）並寫 `Permission.Denied`。管理員身分看 `ApiActorMiddleware` 依存取 Token 從資料庫載入的目前使用者，剛被取消管理員的人下一個請求就被擋。
- **`[SignedInUser]`**（同一個檔案）：本身沒有行為，標在「登入即可、刻意不檢查頁面權限」的端點：個人資料、WASM 外框、通知、公告（類別層級）與 `Auth/me`。
- **新守門測試 `ApiAuthorizationConventionTests`**：每個 Web API action 都必須標 `[HasPermission]`、`[AdminOnly]`、`[SignedInUser]` 或 `[AllowAnonymous]` 其中之一（標在類別上等於每個 action），漏標就失敗；除了 `[AllowAnonymous]`，有授權標註的 action 一定要有 `[Authorize]`；繼承自基底 controller 的 action 也檢查。只有 `[Authorize]` 的端點任何登入的人都能呼叫，新增端點時忘了加權限是最常見的越權漏洞。
- `BackupController.Download` 是 Cookie 驗證、不經 `ApiActorMiddleware`，`[AdminOnly]` 讀不到目前使用者，所以暫時標 `[SignedInUser]`、管理員檢查留在方法裡（註解寫明它是管理員專屬、不可拿掉方法裡的檢查）；M7 改成下載票證時改用 `[AdminOnly]`。
- 新增 API 時怎麼選，寫在 [Web API 設計慣例](../architecture/Web%20API%20設計慣例.md)「功能級／動作級授權」與 [腳手架開發指引](../guides/腳手架開發指引.md) §6.8。

### 4. 管理員改自己仍維持登入

- 改了自己的密碼、角色或管理員身分後，`PUT api/v1/users/{id}` 回傳 `SessionRefreshUrl`（`/Auths/RefreshSession?ticket=…&returnUrl=%2Fmyusers`，沿用 0.9.103 的一次性、2 分鐘 ticket），WASM 頁整頁導過去換發這台裝置的登入；其他裝置維持登出。與 Server 版的體驗相同。
- 改別人、停用、強制登出、重設兩步驟驗證會換對方的工作階段版本：對方下一個請求就被登出（API 401、刷新 Token 被拒）。

### 5. 自我保護補到 API

- Server 版「不可強制登出自己」「不可重設自己的兩步驟驗證」只在畫面擋（不顯示按鈕），0.10.4 起 API 也擋，回 400：
  - 「不可強制登出自己的帳號，請使用右上角的登出。」
  - 「不可重設自己的兩步驟驗證，請到「兩步驟驗證」頁停用或重新設定。」
- 停用、刪除自己與 support 的保護本來就在服務層，畫面與 API 一致。
- **support 不可改帳號**（服務層，畫面與 API 都適用）：「「support」是系統預設的開發帳號，不可修改帳號。」。「不可停用、不可刪除」都是比對帳號，以前先把 support 改名就能繞過；這是改寫前就有的問題，一併修正。

### 6. 時區由伺服器算

- 使用者清單的鎖定文字（「鎖定至 HH:mm」）與稽核明細的 UTC 時間，改由伺服器依伺服器時區算好送來，瀏覽器時區和伺服器不同也不會顯示錯。
- **本地時間一律以「不帶時差」送出**（`DateTimeKind.Unspecified`）：稽核紀錄（含 M3 起的「異動歷程」對話窗）與寄信紀錄的本地時間，之前 JSON 帶 `+08:00`，WASM 會換成瀏覽器的時區，伺服器與瀏覽器時區不同時整頁時間都錯（獨立審查發現）。UTC 欄位以 `Z` 結尾。
- WASM 端日期篩選的起訖時間送出前也去掉時區（`ClientCulture.Unzoned`），伺服器照自己的時區解讀。
- 實機發現並修正：稽核的單筆查詢回的是 UTC（清單才換成本地），曾被當成本地時間再換算一次，差了 8 小時。
- WASM 清單的日期欄位一律用 `ClientCulture.DateTimeFormat`（與分類、團隊、專案頁相同）。

### 7. 稽核紀錄頁的兩個小調整

- 稽核 CSV 的欄位定義從頁面搬到 `MyProject.Web/Export/AuditLogExport.cs`（內容與欄名不變）。
- 「發生時間」排序：Server 版的排序其實沒生效（AntDesign 給的方向字串與程式比對的字串對不上，點了順序也不變），WASM 版依點選的方向排序。

### 8. 權限不變

- 使用者、角色、稽核紀錄、寄信紀錄的權限鍵仍不放進角色矩陣，只有管理員能用。

### 9. 測試

- 測試 2,704 → 2,734，全部通過。新增 `UserApiTests`（8）、`RoleApiTests`（5）、`AuditEmailLogApiTests`（9）、`ApiAuthorizationConventionTests`（3），`Client/ClientCultureTests` 多 1 個（`Unzoned`），`Client/ClientSessionTests` 的路由表補上四個新的 WASM 頁；`ExportTests` 改引用 `AuditLogExport`。
- 實機驗證腳本：`scripts/e2e/m05-admin.mjs`（A1～A13）＋37 路由煙霧測試全數通過；`scripts/e2e/m05-views.mjs`（固定的使用者、角色、稽核、寄信資料，8 個畫面供截圖比對；隔離資料庫裡 support 的 Email 改成 `support@e2e.test`，避免截圖露出個資）。

## 升版注意

- 版本號 0.10.3 → 0.10.4。
- 沒有資料庫異動。
- support 帳號不能再改帳號名稱（「「support」是系統預設的開發帳號，不可修改帳號。」）。
- 有外部程式要管理使用者、角色或查稽核的，現在可以用 `api/v1/users`、`api/v1/roles`、`api/v1/audit-logs`、`api/v1/email-logs`，只限管理員的 Bearer Token。
- 衍生專案自己新增的 Web API：升級後 `ApiAuthorizationConventionTests` 會列出沒有標註授權意圖的 action，逐一補上 `[HasPermission]`、`[AdminOnly]`、`[SignedInUser]` 或 `[AllowAnonymous]`（不要為了過測試就一律標 `[SignedInUser]`）。
