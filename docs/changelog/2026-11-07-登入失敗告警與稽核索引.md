# 登入失敗告警與稽核索引（0.9.166）

- 文件版本：1.0
- 文件狀態：已實作

- 最後核對日期：2026/11/07

## 目的

《稽核紀錄 PRD》的規劃中需求有兩項：
- `AuditLog.OccurredAt` 補單欄索引。
- 稽核事件的告警，原文是「同一帳號短時間大量 Login.Failed」。

查證現況後，「同一帳號」這一塊其實已經有了：
- 連續輸錯 5 次就鎖 15 分鐘，並通知全體管理員、寄信。
- 登入端點每個來源每分鐘最多 10 次。
- 每天的巡檢會統計 24 小時內的失敗。

沒人能即時發現的是**橫向攻擊**：
- 猜不存在的帳號：沒有可以鎖的對象，只寫一筆稽核。
- 對很多帳號各試幾次，每個都沒到鎖定門檻。
- 從多個 IP 慢慢試。

## 使用者的決定（2026/11/07）

| 項目 | 決定 |
|---|---|
| 偵測什麼 | 全系統短時間大量登入失敗：不分帳號、不分 IP，含不存在的帳號 |
| 預設門檻 | 10 分鐘內 20 次；發出後 60 分鐘內不再重發；都可在「系統參數」頁調整 |
| 通知 | 全體管理員站內通知＋寄信（同帳號鎖定），連到稽核紀錄頁 |
| 索引 | 一起做 |

## 內容

### 登入失敗告警

- **新設定** `LoginFailureAlertSettings`：

  | 鍵 | 預設 | 說明 |
  |---|---|---|
  | `Threshold` | 20 | `0`＝不告警 |
  | `WindowMinutes` | 10 | 統計最近幾分鐘 |
  | `CooldownMinutes` | 60 | 發出後多久內不再重發 |

  三個都放在「系統參數」頁的「密碼與登入」，系統參數共 52 → 55 個。
- **計入的動作**：`Login.Failed`（含帳號不存在、鎖定中再試）、`Login.LockedOut`、`Login.TwoFactorFailed`、`Login.Sso.Failed`。停用帳號的登入不算。
- **評估時機**：
  - `AuditLogService` 寫完上述稽核後，呼叫 `LoginFailureAlertService`。
  - Blazor 登入、Web API 登入、Google 登入都寫稽核，所以一處就涵蓋全部。
- **通知內容**：
  - 分類 `LoginFailureBurst`，站內通知全體管理員並寄信，連到「稽核紀錄」。
  - 標題例如「登入失敗次數異常：10 分鐘內 23 次」。
  - 內文列出最常被試的帳號與來源 IP 各前 5 名。帳號是攻擊者輸入的任意文字，每個最多顯示 30 字；IP 最多 45 字，完整的 IPv6 不會被截斷。
- **冷卻與並行**：
  - 同時有多筆失敗進來時只有一個在評估，不會重發。
  - 冷卻狀態只在記憶體，重新啟動網站後，攻擊仍在進行就會再發一次。這是刻意的取捨。
- **不影響登入**：評估、讀設定或通知失敗都只記 Warning 日誌，不會丟例外。寄送失敗時不進入冷卻，下一次失敗會再試。

### 稽核發生時間索引

## 獨立審查

另派一個代理人只看程式差異，沒有高嚴重度問題。DI 沒有循環相依、生命週期正確，EF 查詢可以轉譯，信件內文有 HTML 編碼。處理結果：

| 發現 | 處理 |
|---|---|
| 先設冷卻才寄送：寄送失敗後 60 分鐘內都不會再告警（中） | 改成寄送成功才進入冷卻，新增測試 |
| IP 也截成 30 字，完整 IPv6 會被截斷，沒辦法照著封鎖（中） | IP 上限改為 45 字（IPv6 最長的寫法），新增測試 |
| 讀設定在 try 外面，設定不合法時例外會傳到登入請求（低） | 移進 try，新增測試 |
| 正在評估時進來的失敗會被略過（低） | 不改：下一次失敗就會補上，比排隊等待更不影響登入回應 |
| 對已鎖定帳號的嘗試也算進告警（低） | 不改，屬刻意：那仍然是攻擊行為，文件已寫明「含鎖定中再試」 |
