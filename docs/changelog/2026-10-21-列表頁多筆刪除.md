# 列表頁多筆刪除（0.9.132）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：0.9.132
- 首次實作版本：0.9.132
- 最後核對日期：2026/10/21

## 起因

十個列表頁都只能一筆一筆刪：清理一批過期的例外紀錄、AI 對話紀錄，或一次淘汰幾個分類時，要重複按「刪除 → 確認」很多次。

## 決定（2026/10/21，與使用者逐項確認）

| 項目 | 決定 |
|---|---|
| 範圍 | 有單筆刪除的十頁：專案、分類、團隊、使用者、角色（軟刪除）；例外紀錄、Token 用量明細、AI 對話紀錄、公告、備份（實體刪除）。稽核紀錄頁不做逐筆刪除 |
| 勾選範圍 | 只在目前這一頁；換頁、排序、搜尋／查詢、重新整理、切換「顯示已刪除」、刪除後都清掉 |
| 「顯示已刪除」 | 不能勾選，還原與永久刪除維持單筆 |
| 不能刪的列 | 已知的反灰：使用者頁的 support 與自己、角色頁的「預設角色」 |
| 確認窗 | 列出筆數與名稱（最多 10 筆，其餘「…等共 N 筆」）；實體刪除用紅色確認窗，軟刪除提示可到「顯示已刪除」還原 |
| 部分失敗 | 能刪的照刪；全部成功顯示「已刪除 N 筆」，有失敗用可複製、不自動關閉的錯誤通知列出名稱與原因 |
| 團隊樹 | 由下屬部門往上層刪；勾上層不連帶勾下屬（`CheckStrictly`）；只勾上層、下屬還在時照原規則失敗 |
| 稽核 | 沿用每筆一列 `*.Delete`，不另加批次摘要 |
| Web API | 不加批次端點 |
| CRUD 產生器 | 樣板一起更新，新模組預設就有 |

## 注意

- 確認與結果通知的名稱會寫進日誌（`ViewNotification` 記通知內文），所以使用者頁只列帳號。
- 備份進行中畫面每 5 秒自動重新整理，勾選會被清掉。
- 實體刪除頁若刪除成功後寫稽核失敗，這一筆會列為失敗（實際已刪除），與單筆刪除的行為相同。
