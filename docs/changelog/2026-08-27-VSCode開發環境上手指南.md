## 症狀

腳手架缺少「拿到 repo 之後怎麼開始」的說明，新進開發者三個常見卡點：

1. **沒有任何 VS Code 相關文件**，repo 也沒有 `.vscode/` 目錄。`readme.md` §5 只有 `dotnet run` 一行 CLI 指令，且沒說明必須用 `https` profile —— 照著跑 `http` profile 會因為 `Program.cs:389` 無條件的 `UseHttpsRedirection()` 而連不上。
2. **沒有獨立的機密設定文件**。`MyProject.Web.csproj:6` 早已宣告 `UserSecretsId`，但沒有任何機密真的搬進去，`dotnet user-secrets` 只在 [Google OAuth2 第三方登入](../security/Google%20OAuth2%20第三方登入.md) 裡順帶出現，開發者不知道 `secrets.json` 放哪、長什麼樣、該搬哪些鍵。
3. **改名流程只有一份 6 行待辦清單**，沒有實際操作步驟，也沒有列出「改資料夾名不會自動修好、漏改又不會報錯」的高風險字串。

另外，既有的 `scripts/New-StarterProject.ps1` 有三個缺陷，會讓照著用的人踩坑（見下方根因）。

## 根因

| 缺陷 | 位置 | 說明 |
|------|------|------|
| `docs/**/*.md` 的 BOM 被抹除 | `New-StarterProject.ps1` 原第 48、54 行 | 用 `Get-Content` / `Set-Content -Encoding UTF8` 讀寫。**PowerShell 7 的 `utf8` 是「不含 BOM」**，於是複製出來的專案所有文件都掉 BOM，第一次跑 CI 就卡在 `scripts/Test-DocsEncoding.ps1` |
| 不更換 `UserSecretsId` | `New-StarterProject.ps1` 全檔 | 衍生專案沿用 `83f6d54f-…`，多個專案共用同一份 `secrets.json` 互相污染，且 `dotnet user-secrets clear` 會一次清掉所有專案的機密 |
| `bin` / `obj` / `.vs` 排除無效 | `New-StarterProject.ps1` 原第 27、32-38 行 | `$excludedDirectories` 只過濾 repo 根目錄第一層，但這些目錄都在 `src/MyProject/**` 深處，`Copy-Item -Recurse` 照複製不誤；後續文字取代迴圈還會去改 `obj/project.assets.json` 等建置產物 |

## 修正

### 1. 新增主文件

`docs/guides/VS Code 開發環境與新專案上手指南.md` —— 單一入口，10 節：必備工具與擴充套件、第一次建置、VS Code 啟動與偵錯、**機密設定檔（User Secrets）**、資料庫與預設帳號、**複製腳手架並更名**、驗證清單、疑難排解。

文件中特別標示的陷阱：

- `App.razor:13` 的 `@Assets["MyProject.Web.styles.css"]` —— 更名漏改會讓**全站 scoped CSS 靜默失效**，沒有任何錯誤訊息。
- `NavMenu.razor:17` 側邊欄品牌文字是硬編的，**不走** `SystemSettings:SystemInformation:SystemName`。
- `appsettings.json:52-54` 的 `SystemSettings:ConnectionStrings:SQLiteDefaultConnection` 是**死設定，執行期不會被讀取**。
- `Program.cs:337-345` 會在啟動時把 `support` 密碼**覆寫回設定檔的值**，這是刻意的救援設計，不是 bug。

### 2. 新增 `.vscode/` 設定（4 檔）

| 檔案 | 內容 |
|------|------|
| `launch.json` | F5 偵錯，固定使用 `https` profile，`serverReadyAction` 自動開瀏覽器 |
| `tasks.json` | `restore` / `build` / `format-check` / `test` / `docs-encoding`，對齊 CI 的品質關卡 |
| `settings.json` | Markdown 預設 **UTF-8 含 BOM**、隱藏 `bin`/`obj`、指定 `dotnet.defaultSolution` |
| `extensions.json` | C# Dev Kit、PowerShell、EditorConfig 等建議擴充套件 |

`.gitignore:400-405` 原本就白名單了這四個檔名，可直接進版控。

### 3. 修正 `scripts/New-StarterProject.ps1`

- 改用 `[System.IO.File]::ReadAllText()` / `WriteAllText(..., [System.Text.UTF8Encoding]::new($hasBom))`，新增 `Test-Utf8Bom` 先偵測原檔前三個位元組，**逐檔保留原本的 BOM 狀態**（`.md` 保留、`.cs`/`.json` 維持無 BOM）。
- 新增 `-UserSecretsId` 參數（預設 `[guid]::NewGuid()`），取代完成後改寫 Web 專案 csproj 並印出新值。
- 新增 `Copy-TreeExcluding` 遞迴複製函式，**逐層**跳過 `.git` / `bin` / `obj` / `.vs` / `.playwright-cli` / `output`。
- 結尾的殘留掃描加驗舊的 `UserSecretsId`，並提示接續閱讀上手指南 §7.1 與 §7.3。

### 4. 文件索引同步

`docs/guides/README.md`、`docs/README.md`、`readme.md` §9 三處索引；`readme.md` §5 與 §6 結構樹補上新指南與 `.vscode/`；`docs/architecture/開發慣例與限制速查.md` §8 與 `docs/guides/腳手架新專案啟動流程.md` 加上互相指引。
