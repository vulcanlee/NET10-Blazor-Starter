# 修正 Agent 帶工具時 400 reasoning_effort（0.9.146～0.9.148）

- 文件版本：1.3
- 文件狀態：已實作
- 現行系統版本：0.9.149
- 首次實作版本：0.9.146
- 最後核對日期：2026/11/04

> ⚠️ **0.9.149 起本篇內容已被取代**：Agent 功能改走 Responses API，`ToolReasoningEffort` 改名為 `AgentReasoningEffort`、錯誤訊息改為單一句，見 [Agent 改走 Responses API](2026-11-04-Agent改走ResponsesAPI.md)。本篇保留 0.9.146～0.9.148 的嘗試過程與實測紀錄。

## 問題

「Agent 測試台」以 `gpt-6.1-sol` 執行時，第一次模型呼叫就失敗，畫面顯示
「AI 服務不接受參數 reasoning_effort 的設定值（代碼 ），請調整 AiSettings 後再試。」日誌：

```
AI chat completion upstream failure. Operation=Agent 測試台, StatusCode=400, ErrorCode=, ErrorParam=reasoning_effort,
ErrorType=invalid_request_error, ErrorDetail=Function tools with reasoning_effort are not supported for gpt-6.1-sol
in /v1/chat/completions. To use function tools, use /v1/responses or set reasoning_effort to 'none'.
```

系統**沒有**送 `reasoning_effort`。是 `gpt-6.1-sol` 的預設推論等級不是 none，而它在 Chat Completions 上不允許
function tools 搭配推論。所有帶工具的 agent（Agent 測試台、Agent 工作流程）都會中；AI 日誌分析、AI 例外分析不帶工具，不受影響。

另外訊息裡的「（代碼 ）」是空的：上游這個錯誤沒有 `code`。

## 修正

### 一、新設定 `AiSettings:ToolReasoningEffort`（0.9.146）

| 值 | 效果 |
|---|---|
| `null`（預設）| 不送 `reasoning_effort`，由模型決定 —— 與 0.9.145 以前完全相同 |
| `none`／`low`／`medium`／`high`／`xhigh`（不分大小寫）| **只有帶工具的 agent 呼叫**送出這個值；不帶工具的呼叫一律不送 |

- 給「不允許工具搭配推論、但接受 `none`」的模型用：設 `none` 即可使用 Agent 測試台與 Agent 工作流程。
- 只套用在帶工具的呼叫，是為了讓分析功能保有模型預設的推論。
- 填其他值時啟動就擋下（`AiSettingsValidator`）。⚠️ 不接受 `none` 的模型不要設，否則換成 400 `unsupported_value`。
- 實作：`AiAgentFactory.CreateChatOptions` 在 `tools` 非空時設 `ChatOptions.Reasoning`，由 `Microsoft.Extensions.AI.OpenAI` 送成 `reasoning_effort`。
- 不寫進 `appsettings.json` 範本（見「三」）。需要時在 `appsettings.Development.json`、User Secrets 或環境變數 `AiSettings__ToolReasoningEffort` 設定：

```json
"AiSettings": {
  "ToolReasoningEffort": "none"
}
```

### 二、錯誤訊息

| 情況 | 0.9.145 | 0.9.148 |
|---|---|---|
| 400 `param=reasoning_effort`、沒有 code（不允許工具搭配推論）| AI 服務不接受參數 reasoning_effort 的設定值（代碼 ），請調整 AiSettings 後再試。 | 此模型在帶工具的呼叫不接受推論（reasoning_effort）。請將 AiSettings:ToolReasoningEffort 設為 none；若此模型不接受 none，請在「系統參數」的「AI 模型」為 Agent 功能指定其他模型。 |
| 400 `param=reasoning_effort`、`code=unsupported_value`（送出的值不被接受）| AI 服務不接受參數 reasoning_effort 的設定值（代碼 unsupported_value），… | 此模型不接受 AiSettings:ToolReasoningEffort 的設定值，請改為 null 或此模型接受的值。若改為 null 後出現「不支援工具搭配推論」，表示此模型無法用於 Agent 功能，請在「系統參數」的「AI 模型」為 Agent 功能指定其他模型。 |
| 其他參數被拒、上游沒給 code | …的設定值（代碼 ），… | …的設定值，…（省略代碼）|

0.9.146～0.9.147 的訊息只有一種（叫人設 none、已設定則改 null），遇到下面「三」的模型會讓人在兩個錯誤之間來回，0.9.148 依 code 拆開。

### 三、Azure `gpt-6.1-sol` 在 Chat Completions 上無法使用工具（0.9.147 試、0.9.148 撤回）

0.9.147 在 `appsettings.json` 範本填 `"ToolReasoningEffort": "none"`，實測 Azure 部署 `gpt-6.1-sol` 回：

```
ErrorCode=unsupported_value, ErrorParam=reasoning_effort, ErrorDetail=Unsupported value: 'reasoning_effort' does not
support 'none' with this model. Supported values are: 'low', 'medium', 'high', and 'xhigh'.
```

也就是這個模型**不送**會因「工具搭配推論」被拒、**送 `none`** 不被接受、**送 low～xhigh** 又是工具搭配推論 ——
在 Chat Completions 上沒有任何值行得通（第一個錯誤訊息「set reasoning_effort to 'none'」對它不成立）。0.9.148 撤回範本的 `none`。

**處理方式**：`AiSettings:Model` 可以維持 `gpt-6.1-sol`（AI 日誌分析、AI 例外分析不帶工具，照常可用），
在「系統參數」的「AI 模型」把 `AgentPlayground`（Agent 測試台）、`ProjectStatusReport`、`MultiPerspectiveReview`（Agent 工作流程）
指定為同一個 Azure 資源裡、在 Chat Completions 上支援工具呼叫的部署。記得在 `AiPricingSettings` 確認該模型有費率。

## 沒有做的

改走 Responses API 可以讓推論與工具並存（也是讓 `gpt-6.1-sol` 用於 Agent 的唯一辦法），但 AI 對話紀錄頁、PDF、用量解析、
串流擷取都依 Chat Completions 格式，屬於另一輪的改動（見 [MAF AI 呼叫架構 §3](../architecture/MAF-AI呼叫架構.md)）。

## 測試

- `AiAgentPipelineTests.ToolReasoningEffort_ShouldOnlyBeSent_WhenSetAndAgentHasTools`：預設不送、設了且帶工具才送（`none`／`high`／`xhigh`，大小寫正規化）、設了但不帶工具不送。
- `AiLogAnalysisServiceTests`：沒有 code 的 400 `reasoning_effort` 叫人設 none 並提到「AI 模型」；`unsupported_value` 叫人改為 null 或換模型、不再叫人設 none（0.9.148）；上游沒給 code 時訊息不含「代碼」。
- `OptionsValidationTests`：未知值（`extreme`、`minimal`、空白）擋下，五個合法值與 `null` 通過。
- `AiSettingsTests.Defaults_ShouldMatchDocumentedValues`：預設 `null`。
