## 目的

WASM 遷移的第十一個里程碑（計畫見 [WASM 遷移計畫](../migration/WASM遷移計畫.md)）：把前端 `MyProject.Web.Client` 拆成**獨立的 Blazor WebAssembly 靜態站台**，`MyProject.Web` 只剩 Web API。
部署有兩種，由 API 主機的 `ClientSettings:BaseUrl` 決定：**同站台**（留空，API 主機直接提供前端，一個 IIS 站台）與**雙站台**（填前端網址，例如 `app.公司.com` 前端靜態站＋`api.公司.com` API 主機）。**畫面與 API 不變。**
測試報告見 [M11-獨立靜態站台](../migration/測試報告/M11-獨立靜態站台.md)。

## 變更內容

### 1. 前端成為獨立的靜態站台

- 入口頁 `MyProject.Web.Client/wwwroot/index.html` 取代已刪除的 `MyProject.Web/Components/App.razor`：建置與發佈時 SDK 填入 import map、preload 連結與帶指紋的 `blazor.webassembly` 檔名（`OverrideHtmlAssetPlaceholders`）；`ClientProgram` 把 `ClientRoutes` 掛在 `#app`、`HeadOutlet` 掛在 `head::after`。樣式順序不變（bootstrap → app.css → scoped CSS → AntDesign → theme.css）。
- API 主機的網址：`MyProject.Web.Client/wwwroot/appsettings.json` 的 `ApiBaseUrl`，**留空＝與網頁同一個網址**（同站台）。`Api/ApiAddress` 把它套到所有呼叫 API 的 `HttpClient`、Google 登入的整頁導向、附件上傳與下載網址（`BrowserFiles`）；雙站台時以發佈參數 `-p:StaticSiteApiOrigin` 填入（見第 3 節）；寫錯（不是完整 http(s) 網址、帶 `?` 或 `#`）前端啟動就失敗並在主控台說明。
- 靜態檔從 `MyProject.Web/wwwroot` 搬到 `MyProject.Web.Client/wwwroot`：`app.css`、`theme.css`、`favicon.png`、`images/`、`js/`、`lib/bootstrap`。**全站色票的唯一來源改成 `src/MyProject/MyProject.Web.Client/wwwroot/theme.css`**；`MyProject.Web` 沒有 `wwwroot`。
- 附件與備份下載：同一個來源照舊用暫時的 `<a download>` 原生下載；跨來源（雙站台）時瀏覽器會忽略 `download` 屬性而整頁導過去，改由 `browser-files.js` 以 `fetch` 取回、blob 網址存檔（檔案在瀏覽器記憶體、不經過 WASM；大檔會佔用同樣大小的記憶體、看不到下載進度）。失敗（票證失效、權限已失去）時回伺服器訊息，畫面顯示錯誤通知、頁面留在原地。`BrowserFiles.DownloadAsync` 改回傳 `string?`（`null`＝成功），`ProjectApi`、`BackupApi` 轉成失敗結果。
- `ClientRoutes` 遇到不是 WASM 頁面的網址（同站台時的 Swagger 等）照舊整頁載入；不是頁面的網址主機或靜態站都回 index.html，由前端顯示找不到頁面（0.10.9 以前是主機回 404 後重跑 `/not-found`）。

### 2. 兩種部署：`ClientSettings:BaseUrl`

- **留空＝同站台**（預設）：API 主機一併提供前端。`UseFrontend`（管線最後）以 `MapStaticAssets` 提供 Client 的靜態檔，沒有任何端點對應的 GET／HEAD（不是 `/api/`、不是 `/_framework/`）回 `index.html`（`no-cache`），`_framework` 找不到回 404。不需要反向代理（計畫原寫「同站台反向代理」，改成這個更簡單的做法）。SPA 回退刻意做成「沒有端點時」的中介軟體，不用 `MapFallback`（萬用回退端點會讓 `/api/` 的 POST 變 405、沒帶 Content-Type 的 API 請求變 404）。
- **有值＝雙站台**：API 主機只提供 API，非 API 路徑 404。
  - CORS 允許 `BaseUrl` 的來源加上既有的 `Cors:AllowedOrigins`；只收 `Authorization`、`Content-Type`，方法 GET／POST／PUT／DELETE，公開 `Content-Disposition`（下載檔名），不帶憑證，預檢快取 10 分鐘。`UseConfiguredCors` 移到驗證與限流之前：預檢不會被 401 或 429 擋下。兩者都沒有（同站台預設）＝不回任何 CORS 標頭。
  - Google 登入導回、所有信中連結、非 API 例外導頁一律經 `ClientSettings.FrontendUrl` 導到前端：信中連結由註冊 `EmailSettings` 時的 `PostConfigure` 以 `BaseUrl` 蓋過 `EmailSettings:PublicBaseUrl`（重設密碼、站內通知、巡檢報告、例外告警一起換）。只用設定值，不採用請求的 Host 或參數（不可成為開放式重新導向）。Google 的回呼（`/signin-google`）仍在 API 主機。
  - 必須是完整的 http(s) 網址、不帶 `?`／`#`（`ClientSettingsValidator`），正式環境必須 https（`StartupSafetyValidator`）；寫錯網站不啟動。雙站台時正式環境用 Smtp 可以不填 `PublicBaseUrl`。
- `/api/` 底下沒有本文的錯誤狀態碼（找不到路由、方法不符）補上 `ApiResult`（`UseApiStatusCodePages`，取代 `UseStatusCodePagesWithReExecute("/not-found")`）。

### 3. 靜態站的 IIS 設定 `web.config`

`MyProject.Web.Client/web.config`，只在發佈 Client 時放到輸出根目錄（刻意不當 Content，否則同站台發佈 Web 時會蓋掉 API 主機自己的 web.config）。發佈輸出是 `web.config`＋`wwwroot/`，IIS 站台的實體路徑指向輸出根目錄，**需要 IIS URL Rewrite 模組**：

- 規則依序：瀏覽器接受 br 且有 `.br` 副本時送預先壓縮的檔（outbound 規則補 `Content-Encoding`、原本的 `Content-Type` 與 `Vary`；IIS 自己的壓縮與核心模式快取關掉）→ `wwwroot` 底下的實體檔 → `_framework` 找不到回 404 → 其他網址回 `index.html`。
- MIME：`.wasm`、`.dll`、`.webcil`、`.dat`、`.blat`、`.pdb`、`.json`、`.woff`、`.woff2`。
- 快取：預設 `no-cache`（`index.html` 與 `appsettings.json` 改了立刻生效），檔名帶指紋的 `_framework` 檔 `public, max-age=31536000, immutable`（只套用在 200 回應：部署途中新的 index.html 先上線、檔案還沒複製完時，404 不會被快取一年）。
- 安全標頭與 API 主機相同（`X-Content-Type-Options`、`X-Frame-Options`、`Referrer-Policy`、`Strict-Transport-Security: max-age=2592000`〔與 `UseHsts` 相同〕、CSP）；`/Auths/ResetPassword` 加 `Referrer-Policy: no-referrer`、`Cache-Control: no-store`（網址帶 Token）。
- **雙站台的 API 網址用發佈參數**：`dotnet publish src/MyProject/MyProject.Web.Client -c Release -o <輸出> -p:StaticSiteApiOrigin=https://api.公司.com`（只要 scheme＋主機＋連接埠）在發佈時同時填 `wwwroot/appsettings.json` 的 `ApiBaseUrl` 與 web.config CSP 的 `connect-src`，兩處一致。兩個檔一律從專案裡的範本重寫：同一個輸出資料夾重新發佈也照樣填好，不帶參數就回到空白（同站台）；不要在部署後手改輸出。參數格式不對時發佈失敗。
- `wwwroot/appsettings.json` 不產生 `.br`／`.gz` 壓縮副本（`CompressionExcludePatterns`）。
- 這些 IIS 規則只能靠 `StaticSiteWebConfigTests` 解析 XML 守門，本機跑不出來；上線前要在真的 IIS 驗證一次（部署清單有這一條）。

### 4. CSP（前端頁面）

```
default-src 'self'; script-src 'self' 'wasm-unsafe-eval' 'sha256-<import map>'; style-src 'self' 'unsafe-inline' https://fonts.googleapis.com;
font-src 'self' https://fonts.gstatic.com; img-src 'self' data:; connect-src 'self'; frame-ancestors 'none'; base-uri 'self'; object-src 'none'
```

- 同站台由 API 主機加在前端的回應上（`UseSecurityHeaders`，Swagger 除外），靜態站由 web.config 加；兩份內容一致（`StaticSiteWebConfigTests` 守門）。
- import map 是 index.html 唯一的行內腳本、雜湊每次建置不同：同站台由主機執行時從 index.html 算（`FrontendIndexPage`），靜態站由 `MyProject.Web.Client.csproj` 在發佈時從專案裡的 web.config 範本填入佔位（一律讀範本，同一個輸出資料夾第二次發佈不會因佔位已被換掉而失敗）。算雜湊前先把換行正規化成 LF（瀏覽器的算法）。
- **雙站台時 web.config 的 `connect-src` 要有 API 主機的來源**，否則瀏覽器擋下所有 API 呼叫：發佈前端時帶 `-p:StaticSiteApiOrigin` 就會填入。
- 已知：AntDesign 頁籤的 `ondragover="event.preventDefault();"` 行內事件會被擋（本專案頁籤不開放拖曳，沒有功能影響），刻意不加 `'unsafe-hashes'`。

### 5. 同站台發佈

SDK 從參考的 Client 帶進 Web 發佈輸出的 index.html 是沒處理佔位的原始檔（瀏覽器載不到 WebAssembly）。`MyProject.Web.csproj` 在發佈後另外發佈一次 Client 到中繼資料夾，拿它的 index.html 覆蓋，並逐一確認引用的 `_framework` 檔都在 Web 的發佈輸出裡（對不上就讓發佈失敗）；所以 Web 的發佈多花一次 Client 發佈的時間。這一步以 `RemoveProperties` 拿掉外層的 `RuntimeIdentifier`、`SelfContained`、`PublishProfile`、`PublishReadyToRun`、`PublishSingleFile`、`PublishTrimmed`、`StaticSiteApiOrigin` 等，Web 帶 `-r win-x64` 發佈時前端照樣能發佈。同站台不可在部署後改 `wwwroot/appsettings.json`（`ApiBaseUrl` 維持空白）。
從原始碼執行時 `builder.WebHost.UseStaticWebAssets()` 讓 Development 以外的環境（測試主機）也讀得到 Client 的靜態資產。
