# 死碼清理：移除沒有任何程式使用的程式碼、退場功能殘留與沉睡的擴充點（0.10.43）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：0.10.43
- 首次實作版本：0.10.43
- 最後核對日期：2026/11/26

## 目的

使用者 2026/11/26 要求檢查整個專案（src 全部含測試＋scripts）的重複程式碼與沒有被使用的程式碼，分四批處理：①死碼移除（本批）②伺服器端重複整併 ③前端重複整併 ④e2e 腳本。每一項都由使用者逐項決定，並要求附測試報告證明改了什麼、如何證明沒有影響：見 [重複程式碼與死碼清理測試報告](../migration/測試報告/重複程式碼與死碼清理.md)。

## 決定（使用者 2026/11/26）

- 全專案沒人用的程式碼全部刪除；可能是刻意保留的通用 API（`ConfirmDialog.AskDeleteRecordAsync`、`PagedResult.HasPreviousPage`／`HasNextPage`）也刪。
- 退場功能的殘留連同測試一起刪：舊版巡檢報告的寫入路徑、舊端點 `client-errors`、`AgentPageInfoDto.ReasoningEffortValues`。
- **只有測試在用、但本身是在保護正式功能的檢查掛鉤或規格常數保留不動**（清單見速查表 §6.33 第 159 點）。
- 沉睡的擴充點全部拿掉：依對話選推論等級、給多個 Agent 頁共用的設定層（流程類別保留）、沒有版本號的路由別名（CRUD 產生器樣板一起拿掉）。

## 變更內容

### 全專案沒人用的程式碼

- 五個 CRUD 服務（分類、使用者、專案、角色、團隊）的 `BeforeDeleteCheckAsync`：從未被呼叫，只寫一筆 Debug 後回成功。
- `Models/Others/RecordVm.cs`（整檔）、`DatabaseUsageModels` 的 `SizeEstimateMethod` 與 `EstimateMethod`、`AiReportPdfBuilder.MaxHeadingLevel`、`AuditLogQueryService.OlderThan`（0.9.175 起清理改走 `AuditChainStore`，它就沒人用了；上面那段 `PurgeBeforeAsync` 的說明移回原位）、`DataRequest` 的 `Skip`／`RequiresCounts`、`SearchRequestBaseDto.IncludeRelatedData`、`ProjectController.GetById` 不作用的查詢參數 `includeRelatedData`（0.10.3 起保留相容；呼叫端多帶也會被忽略，使用者在第一批驗收時決定一併移除）、`PagedResult.HasPreviousPage`／`HasNextPage`、`ConfirmDialog.AskDeleteRecordAsync`。
- 巡檢退場的殘留：`AdminPatrolStatuses.Unreadable`／`NeedsAttention()`、`AdminPatrolSections`、Token 用量的 `AdminAssistantPatrol` 作業名稱常數（舊紀錄的作業名稱照舊顯示）、`CapacitySnapshotKinds.StatusUnavailable`、`AgentPageInfoDto.SystemDefaultReasoningLabel`／`ReasoningEffortValues`。舊報告的狀態若是「無法判讀」，畫面照舊以預設顏色顯示。
- 死設定：`appsettings.json` 的 `SystemSettings:ConnectionStrings`、`SystemSettings.ConnectionStrings` 類別、`MagicObjectHelper.DefaultSQLiteConnectionStringKey`。資料庫位置一直只看 `ExternalFileSystem:DatabasePath`；舊設定檔留著這個鍵也沒有影響。
- 沒用到的 CSS：`app.css` 的 Bootstrap 範本殘留（`.btn-link`、`.form-control`、`.form-check-input`、`.darker-border-checkbox`、`.form-floating`）、`ClientMainLayout` 的 `.user-menu-item-danger`、三個 Layout 的 `::deep .btn-link`、角色頁的 `.role-view-sort-field`／`-direction`。只拿掉選擇器裡對不到任何元素的部分（例如 `a, .btn-link` 改成 `a`），畫面不變。

### 退場功能

- **舊版巡檢報告的寫入路徑**：`AdminPatrolReportService.SaveAsync`、`AdminPatrolReportFileStore.WriteAsync`、`AdminPatrolReportDraft`（0.10.39 起不再產生舊版巡檢報告）。讀取、清理與「舊版巡檢報告」視窗不變。測試改用新的 `LegacyPatrolReports.SeedAsync` 照原本的寫法佈置舊報告；只測寫入行為的 3 個測試刪除。
- **舊端點 `POST api/v1/shell/client-errors`**（0.10.36 起前端改送 `client-reports`，註解寫明「之後移除」）：連同 `ClientErrorReportDto`、`BrowserErrorReporter` 的舊多載刪除。它也是「前端錯誤回報因限流丟棄」計數唯一的來源（`client-reports` 被限流時留在瀏覽器稍後再送，不丟棄），所以 `LoggingPipelineMonitor` 的這個計數與系統健康監控「日誌管線」佐證裡的「前端錯誤回報因限流丟棄 N」一起拿掉（這個數字在 0.10.36 以後的前端一直是 0；燈號規則本來就不看它）。`ShellController` 不再注入 `LoggingPipelineMonitor`。原本以舊端點驗證「上限跨請求、以使用者計算」的測試改寫成 `client-reports` 版，另加一個測試：送到舊端點的回應和一個從來不存在的網址相同（不會被處理）。

### 沉睡的擴充點

- **依對話選推論等級**（0.9.170 起，0.10.22 起沒有頁面使用）：拿掉 `AgentConversationProfile.SupportsReasoningEffort` 與端點的分支、`IAiAgentRunner.StartAsync` 的推論等級參數、`AiAgentChat.ReasoningEffort`／`SetReasoningEffort`、`AiCallContext.ReasoningEffortOverride` 與只為它存在的 `ModelOverride`、`AiReasoningEffortOrigin.Conversation`、`AgentMessageRequestDto`／`AgentConversationDto`／`AgentStreamFrameDto` 與內容檔 `AiAgentConversationContent` 的 `ReasoningEffort`。系統參數的功能推論等級與 `AiSettings:AgentReasoningEffort` 不變。舊內容檔帶的 `ReasoningEffort` 讀取時略過（新增測試證明讀得到）；系統管理助理一直沒有這個值，行為不變。
- **給多個 Agent 頁共用的設定層**：刪 `AgentConversationProfile`，`AgentConversationEndpoint` 直接注入 `AdminAssistantTurnPlanner`、使用系統管理助理的 Agent 名稱與未預期錯誤訊息（流程類別保留，Controller 仍只標授權）；前端 `AgentConversationApi` 併入 `AdminAssistantApi`（檔名改為 `AdminAssistantApi.cs`）。
- **沒有版本號的路由 `api/[controller]`**：`Auth`、`Category`、`Project`、`Team` 四個 Controller 與 CRUD 產生器的 Controller 樣板只留 `api/v1/[controller]`；登入配額清單拿掉 `/api/Auth/login`。整合測試改打 `/api/v1/...`。
