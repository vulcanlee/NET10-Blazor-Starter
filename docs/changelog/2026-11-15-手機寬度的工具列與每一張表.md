# 手機寬度的工具列與每一張表（0.10.26）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：0.10.26
- 首次實作版本：0.10.26
- 最後核對日期：2026/11/15

## 目的

0.10.25 修好 1440 寬的表格版面後，留下一項觀察：手機 390 寬時，專案清單上方的工具列不會折行，整頁多出約 343px。使用者 2026/11/15 決定修正。

實際逐頁量過手機寬度後，問題比原本看到的多。使用者決定**工具列加上所有表格一起修**，工具列放不下時**折到下一列**。

1. **工具列撐寬整頁**：專案清單多出 343px，分類、團隊、使用者管理各多出 7px。原因是工具列與左右兩半都不會折行。
2. **表格在手機上被擠窄**：0.10.25 只替欄位多的四張表設了欄寬，其他表在手機上照樣被 AntDesign 壓進約 290px。
   - 擠得比較嚴重：分類、團隊、角色的表頭一字一行；系統參數的說明欄很窄；AI 提示詞、公告、備份的內容被擠窄。
   - 輕微：稽核紀錄、系統例外、AI 對話紀錄的「操作」表頭折行；資料庫用量的表頭折行。
3. **E4 的手機檢查有漏洞**：它拿 `window.innerWidth` 比較整頁寬度，但模擬手機時 `innerWidth` 會跟著內容一起變大（專案清單實測 733），所以永遠量不出橫向捲軸。0.10.25 的報告裡，E4 在專案清單撐寬 343px 時仍是通過。

修的過程中還發現：

4. **手機上固定的操作欄把資料蓋住**：每欄設寬後，表格在手機上可以左右捲。但使用者管理的操作欄 360px、角色 280px，比手機上的表格（約 290px）還寬，固定在右側時資料整個被蓋掉，捲到哪裡都只看得到按鈕。

## 變更內容

- **工具列**：專案、分類、團隊、使用者、角色五頁，以及 CRUD 產生器用的共用 `.view-toolbar`（theme.css）：
  - 工具列與左右兩半都設 `flex-wrap: wrap`；
  - 手機寬度（≤ 640px）時右半邊占滿一整列，搜尋框與篩選下拉 `flex: 1 1 160px` 拉長；
  - 搜尋框與下拉是 AntDesign 渲染的元素，拿不到元件的 scope 屬性，從工具列用 `::deep` 往下套。
- **每一張表都設欄寬**：其餘 17 張表的每一欄（含勾選欄、操作欄）都設 `Width`，`Table` 設 `ScrollX`＝平常會出現的欄寬加總。
  - 涵蓋：分類、團隊、角色、稽核紀錄、系統例外、AI 提示詞、資料庫用量、備份、公告、寄信紀錄、日誌檢視、排程（兩張）、Token 用量（兩張）、系統健康的警告日誌、系統參數。
  - 原本在 1440 寬放得下的表，欄寬加總控制在 1,000 以內，桌機不會因此多出捲動。例如稽核紀錄的「動作」175→150、「目標」170→150，摘要 105。
    - 一開始以 1,020 為上限；巡檢時發現看得到的 Chrome 在長頁面會出現直向捲軸，表格可見寬度從 1,026 少到約 1,011，稽核紀錄因此多出一小段橫向捲動，所以統一降到 1,000。
  - 系統參數的說明欄也設寬（270），1440 寬時放得下，更窄時在表格內捲動。
  - 備份頁原本有寬度的欄稍微縮小：檔名 235（加 `Ellipsis`）、建立時間 145、大小 80、系統版本 155、觸發 65、內容 120，加總 1,000（巡檢時看到檔名 200 會被切掉，再調整一次）。
  - 日誌檢視、系統健康的警告日誌有展開列，AntDesign 會自動多一欄 48px 的展開圖示，它不在欄位定義裡。所以「訊息」設 292、`ScrollX` 952，加上展開欄實際 1,000。這一點是獨立審查指出的。
  - 「上層團隊」只在團隊清單非樹狀（搜尋或顯示已刪除）時出現，和刪除時間、刪除者一樣不算進 `ScrollX`。
- **手機寬度時操作欄不固定**（theme.css）：`.ant-table-cell-fix-right` 改成 `position: static !important`，蓋掉 AntDesign 的行內 sticky，固定欄的陰影 `::after` 一起關。手機上先看到資料，往右捲到底才是按鈕；桌機維持固定加陰影。
- **CRUD 產生器樣板**（`scripts/crud-templates/Web.Client/Views/__Plural__/__Name__ViewView.razor.tmpl`）：每欄設寬，有團隊欄時 `ScrollX="1000"`，沒有時 `930`。

## 測試

- `TableLayoutConventionTests` 的欄寬檢查改為 `EveryTable_ShouldGiveEveryColumnAWidth_AndScrollXShouldBeTheirSum`：
  - 從 0.10.25 的四張表（`[Theory]` 四筆）擴大到 UI 底下的**每一張表**（21 張）；
  - 每一欄都要有 `Width`，`ScrollX` 要等於平常會出現的欄寬加總。
  - 修正前的畫面跑一次：17 張表失敗，逐一列出沒有寬度的欄位。
  - 測試數 3,235 → 3,232（四筆 `[Theory]` 合成一個 `[Fact]`）。
- `scripts/e2e/explore-edge.mjs`：
  - E4、E6 改用共用的 `measureLayout`，整頁寬度改用 `document.documentElement.clientWidth` 比；
  - E4 另查表頭折行與欄位被擠窄；
  - 用還是 0.10.24 的 `Acme.Erp` 跑，E4 失敗並列出 12 頁的問題（專案清單整頁多出 816px、使用者管理 897px、分類 255px…）；修正後的版本 E4、E6 都通過。

## 獨立審查

審查沒有找到阻擋性的錯誤：21 張表與樣板兩種情況的 `ScrollX` 都逐張重算過，全部正確。審查指出的問題都已處理：

- 有展開列的兩張表（日誌檢視、系統健康的警告日誌）多一欄 AntDesign 自動加的 48px 展開圖示，備份頁加總 1,140，這三張在桌機會多出捲動。已調整欄寬，見上方「變更內容」。
- `measureLayout` 回傳沒用到的 `tableCount`，已刪除。
- 測試數與本篇的驗證一節還沒更新，已補上。

巡檢時另外發現兩件事，也一起修了：

- 備份頁檔名 200px 時會被切掉，改成 235 並加 `Ellipsis`。
- 看得到的 Chrome 在長頁面會多出直向捲軸，表格可見寬度約 1,011。稽核紀錄因此多出一小段捲動，所以欄寬加總上限從 1,020 降到 1,000。
