## 目的

[路線圖](../planning/00-腳手架強化路線圖.md) B-7（第 1 批第一項）。改動前沒有任何備份機制，只有開發指引 §13.3 的手動清單；
WAL 模式下直接複製資料庫檔會漏掉還在 `-wal` 的寫入，附件、堆疊檔與金鑰環又分散在不同目錄。

使用者決定：

- 備份資料庫、專案附件、例外堆疊檔、Token 原始檔與 Data Protection 金鑰環；AI 對話內容預設不備份（系統參數可開）。
- zip 不加密，靠存放位置與權限；新增 `BackupPath`，管理員可在畫面上下載。
- 每天 02:00 自動備份、保留 7 份（系統參數可調）。

同一批次另外決定：D-15 暗色模式、F-19 AI 聊天元件、F-20 RAG、G-22 衍生專案升級腳本改列「經決定不實作」（路線圖第四節寫明理由），剩下 12 項分三批執行。

## 二、設計決定

| 決定 | 理由 |
|---|---|
| ⚠️ `VACUUM INTO`，不直接複製檔案、不強制 checkpoint | WAL 模式下讀到一致快照、不擋寫入、產出單一檔；直接複製會漏掉 `-wal` 裡的寫入 |
| 獨立的 `SqliteConnection`（`Pooling=False`、`CommandTimeout=0`） | 池子裡的連線會鎖著快照檔（打包與刪除會失敗）；大資料庫超過預設 30 秒；不走 EF 的慢查詢攔截器 |
| 先資料庫、後檔案 | 之後才出現的檔案只是孤兒；反過來會有資料列指向不在備份裡的檔 |
| 打不開的來源檔只計數 | 清理作業同時刪檔、或堆疊檔正被寫入時，不該讓整份備份失敗；寫 zip 的失敗（磁碟滿）仍讓備份失敗 |
| `.work/`＋`*.partial`、完成才改名 | 中斷時不留下看似完整的半成品；下一次執行再清一次（被強制結束時 `finally` 不會跑） |
| ⚠️ 成功後才刪舊備份 | 失敗的那一次不可以把好的備份輪掉 |
| 排序以時間戳＋同秒序號比較 | 字串比較時 `-2.zip` 排在 `.zip` 前面，較新的反而被刪 |
| 備份清單只存在檔案系統 | 放資料庫的話，還原時清單會跟著倒回去 |
| 下載端點從資料庫確認管理員 | Cookie 沒有「是否為管理員」的宣告；管理員權限被取消後不該還能下載 |
| 還原只走停站＋腳本 | 網站執行中替換資料庫檔不安全；腳本把還原前的資料改名保留，可以回復 |
| ⚠️ 還原時移走 `-wal`／`-shm`、金鑰合併 | 殘留的 WAL 會被套用到還原的資料庫上把它弄壞；合併金鑰讓備份之後發的登入 Cookie 仍有效 |
| 02:00 執行 | 排在 03:00 的清理作業之前 |

## 三、驗證（2026/10/04 實跑）

**故意改壞 15 處，全部被測試抓到**：重疊只檢查一個方向、前綴比對不加分隔字元、路徑比對區分大小寫、不檢查網站目錄、AI 對話旗標反向、
不清 partial、直接複製資料庫檔、不清上次殘檔、打不開的檔案讓備份失敗、失敗也刪舊備份、排序用字串比較、不檢查檔名規則、下載不檢查管理員、
每個續傳區段都寫稽核、份數 0 也刪。第一輪「不清 partial」沒被抓到（原取消測試在快照階段就取消，partial 還沒產生），補上「打包途中取消」的測試後抓到。

**真實環境**（Playwright 驅動本機 Edge；所有外部路徑、備份目錄、信件與日誌都指向暫存目錄，`C:\temp\MyProject` 與 `C:\temp\Logs` 無任何新檔）：

- 「系統管理 › 系統備份」按「立即備份」→ 頁面自動更新出現 `backup-…zip`，摘要顯示下次自動備份 02:00、上次執行成功。
- 下載：200、`application/zip`；zip 內為 `db/BackendDB.db`、`files/Keys/…`、`manifest.json`（版本、最後 migration、資料夾檔案數），稽核 `Backup.Download` 一筆。
- 系統參數把保留份數改成 2（跳出危險確認）→ 再備份三次，只剩最新 2 份，稽核三筆 `Backup.AutoPurge`；開啟「備份 AI 對話內容」後的備份含 `files/AiCallLog/…`；刪除一份寫 `Backup.Delete`。
- **還原演練**：建立分類「Before Backup」→ 備份並下載 → 建立「After Backup」→ 停站 → 以 **Windows PowerShell 5.1** 執行 `Restore-Backup.ps1`（明確路徑、`-Yes`）→
  鎖檔被刪、原資料庫與 `-wal`、`-shm` 改名保留 → 啟動網站、照常登入，「Before Backup」在、「After Backup」不在。
- 把 `BackupPath` 設在 `DownloadPath` 底下啟動 → 啟動失敗，訊息「BackupPath 不可與 DownloadPath 重疊…」。
- 還原腳本不含專案名稱（`New-StarterProject.ps1` 改名不受影響）；日誌除既有的 `JSDisconnectedException` 雜訊外沒有錯誤。

**品質關卡**：`Invoke-QualityGate.ps1` 完整通過（1391 個測試，含弱點掃描）。
