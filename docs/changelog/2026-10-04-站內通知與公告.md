## 目的

[路線圖](../planning/00-腳手架強化路線圖.md) B-8（第 1 批第二項）。改動前系統只有 AntDesign 右下角的暫時提示：關掉就沒了、只有當下那個畫面的人看得到；
排程作業失敗、Google 新帳號待開通這類「要有人知道」的事，只能靠管理員自己去翻頁面。

使用者決定：

- 通知由程式發出（使用者／角色／團隊／全體管理員），不做手動發通知的畫面；公告由管理員在頁面上發布。
- 內建四個事件：Google 新帳號待開通 → 管理員；排程作業失敗 → 管理員＋手動觸發者並寄信；帳號鎖定 → 管理員並寄信、密碼即將到期 → 本人（後兩者在 C-9 實作）。
- 公告是每頁上方可關閉的橫幅，每人各自關閉；對象為全體或單一角色／團隊。
- 程式可指定通知同時寄信。

## 二、設計決定

| 決定 | 理由 |
|---|---|
| 一位收件人一列（不做「訊息＋收件人」兩張表） | 已讀、清除、查詢都只看自己那一列；腳手架的規模下寫入量不是問題 |
| ⚠️ `SendAsync` 絕不丟例外 | 通知是附帶的：通知失敗不可讓 Google 登入或排程作業跟著失敗 |
| 團隊反查放在 `IEffectiveTeamResolver` 並加對照測試 | 「誰在這個團隊」與「這個人在哪些團隊」必須同一個定義，否則通知與列級權控會不一致 |
| 訊號只送「有變動」，畫面自己重查 | 訊號不帶內容就不必處理權限與序列化；漏掉一次也只是晚一點更新 |
| 60 秒輪詢 | IIS 重疊回收或多台主機時，別的行程發的訊號收不到 |
| 作業失敗在 runner 結束後以新 scope 發送 | 作業自己的 scope 可能已經壞了（資料庫錯誤）；集中在 runner 一處，所有作業（含系統備份）自動涵蓋 |
| ⚠️ 例外記錄管線內不發通知 | 發送失敗會記錯誤，形成遞迴 |
| 公告純文字、連結只導向站內 | 不必處理 HTML 注入；外部連結不經檢查就導向是開放重新導向 |
| `Announcement` 以條件式 UPDATE 比對版本號，不實作 `IConcurrencyStamped` | 該介面要求軟刪除旗標保護，公告沒有軟刪除 |
| 公告修改後不重新顯示給已關閉的人 | 關閉紀錄以公告 Id 為準；要大家重看就發新的一則（說明頁寫明） |
