- 文件版本：1.0
- 文件狀態：已實作

- 首次實作版本：0.10.15
- 最後核對日期：2026/11/14

## 目的

前後端分離後，下拉選單的選項（分類、團隊、角色）是畫面向伺服器讀來暫存在瀏覽器裡的。使用者停在畫面上時，別人可能已經新增、停用或刪除了選項；以前專案與分類頁只在開頁時讀一次，要重新整理整頁才看得到新選項，選了剛被停用的分類也照樣存得進去。
使用者決定的規則（2026/11/14）：**開窗時重讀**、**查詢條件在「重新整理」時重讀**、**存檔時由伺服器檢查**（選項已不存在或已停用就擋下並說明，畫面自動換成最新選項）。
測試結果見 [測試報告](../migration/測試報告/畫面選項資料一致性.md)。

## 變更內容

### 1. 開窗時重讀選項

- 有表單選項的頁面（專案、分類、角色、使用者、公告）以 `LoadFormOptionsAsync()` 讀選項，「新增」「修改」「複製」開窗的第一步就重讀；存檔失敗後也再讀一次。別人剛新增的分類、團隊、角色，不必重新整理整頁就看得到。
- 專案頁按「重新整理」時，工具列的「分類過濾」「團隊過濾」也一起更新。只有查詢條件下拉的頁面（稽核紀錄、系統例外紀錄、AI 對話紀錄、Token 用量）原本就在「重新整理」時重讀，不變；團隊頁的「上層團隊」原本就在開窗時讀，不變。
- 公告管理的角色與團隊選項改成開窗時讀（以前開頁讀一次）。角色管理的「複製」也會重讀。

### 2. 存檔時由伺服器檢查

- 專案的分類與團隊、分類的適用團隊、角色的預設團隊、使用者的團隊、CRUD 產生器頁面（`-WithTeams`）的團隊：**這次新選的**值已不存在或已停用時，存檔擋下並顯示「所選的分類「X」已不存在或已停用，請重新選擇（選項已更新）。」，對話窗不關、選項換成最新的。
- 複製：角色複製開窗時不帶已停用的預設團隊；使用者複製窗的團隊是唯讀的，開窗後範本的團隊被停用而被擋時，把它從要建立的資料拿掉（窗內清單跟著更新，再按一次就能建立）。
- 紀錄原本就掛著、後來才被停用或限定其他團隊的值不檢查（畫面上照舊標示「（已限定其他團隊）」保留著），舊資料照樣能改其他欄位後存檔。
- 共用寫法 `MyProject.Business/Helpers/SelectedOptionGuard.cs`，放在各服務的 `BeforeAddCheckAsync`／`BeforeUpdateCheckAsync`，所以 Web API 也一樣：這種情況回 **400**（`ValidationError`，訊息在 `ErrorMessage`）。網址與欄位不變。以前使用者的團隊選了不存在的名稱會被默默略過，現在會擋下。

### 3. 欄位的即時檢查（.NET 11 非同步表單驗證）

- 新元件 `Commons/AsyncFieldCheck`：分類與團隊的名稱、使用者的帳號（新增與複製）輸入後不必按「儲存」，離開欄位約 0.4 秒就在欄位下方顯示「分類名稱已存在，無法新增。」這類訊息，改好後消失；按「儲存」時會等檢查完成。
- 檢查呼叫既有的存檔前檢查端點（`POST …/check`），只認「已存在」（409）；檢查本身失敗（連不上、伺服器錯誤）不顯示、不擋存檔，存檔時伺服器還會再檢查一次。
- 按「儲存」會等檢查完成：`AntDesign.Form` 另外建了自己的 `EditContext`，頁面驗證的是外層 `EditForm` 的，所以元件以 `SaveContext` 參數同時掛上外層（獨立審查發現；只掛內層時欄位下方有訊息、但打完立刻按儲存會跳出確認窗，交給伺服器的 409 擋）。
- 分類的修改：重名檢查改排在團隊檢查之前（與新增、CRUD 產生器樣板相同），欄位即時檢查才看得到「已存在」。團隊的名稱檢查不帶代號（代號重複也是 409，以前會顯示在名稱下面）。
- AntDesign 的非同步驗證支援（PR #4882）還不在 `1.6.3-dotnet11.rc3` 裡，所以用 .NET 11 `EditContext` 本身的 `RegisterAsyncFieldValidator`／`AddAsyncValidator`，訊息顯示在既有的 `ValidationMessage`。

### 4. 權限（既有機制，這一版不改）

- 角色權限被改掉時，畫面上的按鈕與選單是登入時讀的，要重新整理才會更新；伺服器每個請求都重新載入目前使用者並檢查權限，沒重新整理時按下的動作會被伺服器擋下。實機情境 F10 記錄了實際行為。

### 5. CRUD 產生器

- 樣板（`-WithTeams`）照同樣規則：`LoadFormOptionsAsync` 在開窗與存檔失敗後重讀、服務以 `SelectedOptionGuard` 擋下新選的已停用團隊、名稱欄位有 `AsyncFieldCheck`。`Test-CrudGenerator.ps1` 通過。

### 6. 測試與實機腳本

- 新增 `SelectedOptionValidationApiTests`（經 Web API）、`Client/FormOptionsConventionTests`（開窗與重新整理重讀的守門，含產生器產生的頁面與樣板）、`Components/AsyncFieldCheckTests`；`ProjectApiTests` 補上測試用的分類。
- 新增實機腳本 `scripts/e2e/ux-data-freshness.mjs`（兩個瀏覽器、兩個帳號，F1～F10 與 F8b）。
- 測試 3,188 → 3,209，品質關卡 7 步通過；`Test-CrudGenerator.ps1` 通過；獨立審查 1 項中、2 項低全部處理（見測試報告 A.5）。
