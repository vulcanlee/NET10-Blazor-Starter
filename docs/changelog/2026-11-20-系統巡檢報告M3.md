# 系統巡檢報告 M3：週報與月報、備份可還原驗證、AI 費用與每季帳號清查（0.10.41）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：0.10.41
- 首次實作版本：0.10.41
- 最後核對日期：2026/11/20

## 目的

使用者 2026/11/20 要求系統巡檢報告可以指定每天或每週執行，並選定月報、AI 費用、帳號與權限清查、備份可還原驗證併入同一種報告（見 [M1](2026-11-20-系統巡檢報告M1.md)、[M2](2026-11-20-系統巡檢報告M2.md)）。M1、M2 交付了日報與 PDF；M3 加上週報與月報：每週、每月一份總結，和上一期比較、看容量一年後夠不夠、驗證最新的備份真的還原得回來，月報再加 AI 費用，每季一次附上帳號與權限清查。

需求、決定與規則目錄見 [系統巡檢報告 PRD](../prd/系統巡檢報告-prd.md) 5.5、5.6。

## 決定

- 週報與月報一律寄給全體啟用中的管理員（附 PDF）；日報維持橙燈以上才寄。開關在「排程作業」頁，時間在「系統參數」頁（不可用 `ScheduledJobSettings:Jobs` 覆寫）。
- 帳號與權限清查附在 1／4／7／10 月產生的月報：實作上是區間月份為 3／6／9／12 的月報，涵蓋剛結束的那一季（例 10 月初的月報清查 7～9 月）。只列清單，不做確認或簽核流程，PDF 可留存作為清查紀錄。
- **報告裡的帳號（使用者 2026/11/20 決定的窄例外）**：報告頁與 PDF 只在月報的「AI 費用」（費用最高的 10 位使用者）與「帳號與權限清查」兩節的表格列出帳號與姓名，清查要列出帳號才有意義，PDF 是資安稽核的留存。各節的重點、站內通知、Email 內文與送給 AI 的資料仍只有數量。
- 備份可還原驗證只驗最新的一份，照還原腳本的步驟做但不真的還原；空間不夠或檔案剛好被清掉時算「沒驗完」（黃燈），不算「備份壞了」（紅燈）。
- 保留天數依種類各自設定：日報 90 天、週報 365 天、月報 1095 天（季度清查的留存）。
- 不加欄位、沒有 migration：週報、月報沿用同一張表與內容檔格式，只在內容 JSON 多了章節。

## 變更內容

### 排程作業與時間

- 新增「系統巡檢週報」`SystemReportWeekly`（預設星期一 08:00，涵蓋上週一～週日）與「系統巡檢月報」`SystemReportMonthly`（預設每月 1 日 08:30，涵蓋上個月）。三種報告共用抽象類別 `SystemReportJob`（`Scheduling/Jobs/SystemReportDailyJob.cs`），只差在頻率；排程與補跑遇到同一個區間已有排程產生的報告就略過。
- `SystemReportScheduleProvider` 接手三個作業的時間：週報 `WeeklyDayOfWeek`＋`WeeklyTime`（1＝星期一 … 7＝星期日，星期日轉成 cron 的 0）、月報 `MonthlyDay`＋`MonthlyTime`（只開放 1～28 號，每個月都有這一天）。
- 區間一律由 `SystemReportPeriod`（`SystemReports/SystemReportFacts.cs`）計算：`Containing`（某一天所在的區間）、`LastComplete`（排程時段往前最近一個完整的區間）、`Previous`（上一期）、`Quarter`（帳號清查的季度）、`IsPeriodic`、`IncludesAiCost`、`IncludesAccountReview`。
- 何時寄：`SystemReportJob.ShouldSendScheduled`——日報橙燈以上、週報與月報一律。

### 系統參數

- 「系統巡檢報告」群組新增 4 個：週報產生日（星期幾，1～7，預設 1）、週報產生時間（HH:mm，預設 08:00；說明提醒避開系統備份的時間）、月報產生日（每月幾號，1～28，預設 1）、月報產生時間（HH:mm，預設 08:30）。改了約一分鐘內生效。
- 「資料保留」群組新增 2 個：巡檢報告保留天數（週報，7～3650，預設 365）、巡檢報告保留天數（月報，31～3650，預設 1095）。

### 週報與月報的章節

- 報告內容新增 `Sections`（`SystemReportSectionDto`：`Key`、`Title`、`Highlights`、`Tables`、`Notes`；表格 `SystemReportTableDto`），代碼在 `SystemReportSectionKeys`，由 `SystemReports/SystemReportPeriodicSections`（純函式）組出；日報是空的。
  - 趨勢比較（週報、月報）：本期與上一期的新例外種類、還在發生的例外種類、排程失敗、寄出與寄送失敗的信、AI 呼叫與失敗、AI 費用、登入失敗、權限被拒，重點列出增加最多的 3 項。
  - 容量成長與規劃（週報、月報）：每顆磁碟的期初、目前、本期增加、總容量、一年後預估已用（夠不夠）；資料庫與資料目錄的期初、期末、本期增加（取自容量快照）。
  - 備份可還原驗證（週報、月報）：驗證的備份與每一項檢查的結果。
  - AI 費用（月報）：本月與前一個月、依功能、依模型、費用最高的 10 位使用者（帳號、姓名）。
  - 帳號與權限清查（季末月份的月報）：管理員、超過 90 天沒有登入、沒有兩步驟驗證（Google 登入不算）、本季帳號與角色異動；每張清單最多 200 筆；最後登入取自稽核 `Login.Success`／`Login.Sso.Success`。
- Business 層 `SystemReportMetricsService` 改為 partial，新增 `SystemReportMetricsService.Monthly.cs`（`GetAiCostAsync`、`GetAccountReviewAsync` 與對應的資料型別）；收集時不寫稽核。
- 報告視窗與 PDF 用同一套通用的「重點＋表格」呈現各節（放在「每一項發現」之後；PDF 欄寬平均分配），全面摘要多一段「本期重點」。

### 備份可還原驗證

- 新增 `MyProject.Web/Backup/BackupVerifier`（singleton）：打開最新一份備份的壓縮檔與 `manifest.json`（格式版本）、每個項目解壓縮比對 CRC32、各資料夾檔案數與 manifest 相同、把資料庫解到 `{BackupPath}/.work/verify-<guid>/` 比對 SHA-256、`PRAGMA integrity_check`、`__EFMigrationsHistory` 與 manifest 相同。
- 結果 `Passed`／`Failed`／`Unverifiable`（可用空間不到資料庫 1.1 倍、備份檔在驗證前不見、讀取錯誤）。不碰正在使用的資料庫、做完就刪暫存檔；結果只有數字與固定用語。
- 新規則 `BKP-VERIFY`：`Failed` → 紅燈「最新的備份無法還原」；`Unverifiable` → 黃燈「這次沒有完成備份可還原驗證」。

### 通知、信件與 AI 說明

- 週報、月報的通知與信件內文在原本的程式摘要後，每節加一行「【節標題】重點」（只有數字）。
- AI 說明的輸入另送各節的標題與重點，不送表格（帳號與姓名不送）；預設指示 `SystemReportNarrator.DefaultInstructions` 加一段，可以引用這些重點。只有日報全部綠燈時才略過 AI。

### 立即產生與 API

- `POST api/v1/system-reports/generate` 的 `Frequency` 可以是 `Daily`／`Weekly`／`Monthly`，`Date` 是區間內任一天；區間還沒過完 400（「這一週還沒過完，只能產生上週以前的週報。」「這個月還沒過完，只能產生上個月以前的月報。」）、區間起日早於那一種報告的保留天數 400；放進對應作業的佇列，同一個作業已在產生中 409「已經有一份週報正在產生，請等它完成。」。稽核 `Job.Trigger` 的 detail 是 `job=SystemReportWeekly; date=…; send=…; via=system-reports`（月報同理）。
- `SystemReportListDto` 新增 `WeeklyRetentionDays`、`MonthlyRetentionDays`。

### 頁面 `/system-reports`

- 種類篩選加入週報、月報；上方說明改為三種報告的產生與寄送規則，以及「報告保存：日報 N 天、週報 N 天、月報 N 天」。
- 「立即產生」視窗加入種類（日報／週報／月報）；日期標籤依種類顯示「日期（選那一週的任一天）」「日期（選那個月的任一天）」；提示週報、月報要驗證備份、約需數分鐘。
- 報告視窗顯示「本期重點」與各節的重點、表格與說明。

### 保留與清理

- 清理條件依種類：`SystemReportSettings.RetentionDays(frequency)`、`SystemReportService.RetentionDays(frequency)`、`ExpiryThreshold(frequency, now)`；清理與資料保留頁的統計共用同一個條件。
- 「巡檢報告與容量快照清理」的稽核 detail 改為 `reports=N; days=D; weeklyDays=W; monthlyDays=M; snapshots=S; snapshotDays=SD; trigger=T`，結果訊息列出三種保留天數；資料保留頁「巡檢報告」列的規則改為「產出後保留：日報 N 天、週報 N 天、月報 N 天」。

## 已知限制

- 備份可還原驗證只驗最新的一份，資料庫大時要花幾分鐘並暫時佔用約一份資料庫大小的空間；不驗證衍生專案自訂的資料夾內容是否正確，只比對檔案數與校驗碼。
- 帳號清查的最後登入取自稽核紀錄，超過稽核保留天數的登入查不到（顯示「沒有紀錄」）；系統不記錄清查的確認結果。
- 已在「AI 提示詞」頁改過「系統巡檢報告」指示的，新的預設段落不會自動套用，AI 說明不一定引用各節的重點。
- 系統管理助理依指定區間產生報告與 PDF（M4）尚未實作。
