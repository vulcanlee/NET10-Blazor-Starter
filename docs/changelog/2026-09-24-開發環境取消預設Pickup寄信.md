# 開發環境取消預設 Pickup 寄信，回到與出貨相同的 None（0.9.62）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：0.9.62
- 首次實作版本：0.9.62
- 最後核對日期：2026/09/24

## 為什麼

0.9.61 在 `appsettings.Development.json` 預設 `EmailSettings:Provider=Pickup`，讓本機一啟動就有「忘記密碼？」。
經決定開發環境維持與出貨相同的 `None`，不在進版控的設定檔裡預設開啟寄信；要測的人自己用 User Secrets 開。

## 做了什麼

- `appsettings.Development.json` 移除 `EmailSettings` 區塊，只剩 `Logging`（惰性）。
- 刪除守門測試 `EmailSettingsTests.ShippedDevelopmentSettings_ShouldUsePickupWithoutSecrets`（它要求開發設定必須是 `Pickup`）。
- 同步文件：凡寫「開發環境預設 Pickup、本機看得到忘記密碼」之處，改為「開發環境也是 `None`，本機要測用 User Secrets 設 `Provider=Pickup`」。
- 原訂 0.9.62 的《寄信服務使用說明》再順延為 0.9.63。

## 本機要測忘記密碼

```
dotnet user-secrets set "EmailSettings:Provider" "Pickup" --project src/MyProject/MyProject.Web
```

信會寫成 `.eml` 到 `C:\temp\MyProject\Mails`，不需要任何帳密。

## 影響

- **本機**：登入頁預設不再有「忘記密碼？」；直接開 `/Auths/ForgotPassword` 會顯示「系統目前未啟用寄信功能」。
- **系統健康監控**：開發機的「寄信服務」由 Pickup 黃燈變回 None 黃燈，分數不變。
- **Production／整合測試**：不受影響（本來就不載入 `appsettings.Development.json`）。
