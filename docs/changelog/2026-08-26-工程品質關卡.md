CI（`.github/workflows/dotnet-ci.yml`）於 Build 之後新增 **Format check** 步驟。

> 因此刻意**不強制** namespace 宣告形式、`this.` 前綴、`var` 用法、檔案 BOM 與 using 排序

### 三、修正高嚴重性套件弱點 GHSA-v5pm-xwqc-g5wc

導入 `TreatWarningsAsErrors` 時才浮現：`Microsoft.OpenApi` 2.4.1 具高嚴重性弱點
（循環 schema 參考可導致 OpenAPI 解析中止），由 `Swashbuckle.AspNetCore` 10.1.5 遞移引入。
它以 `NU1903` 警告形式存在，原本不會讓建置失敗，因此一直沒被注意到。

**處置：升級 `Swashbuckle.AspNetCore` 10.1.5 → 10.2.3。**
10.2.1 起其相依改為 `Microsoft.OpenApi >= 2.7.5`（修補版），弱點自然消失，
**不需要抑制、也不需要 pin 遞移套件**。詳見 [CI-CD 與品質檢查 §4.2](../operations/CI-CD與品質檢查.md)。

### 四、修正 LogQueryServiceTests 的日期時間炸彈

7 個測試在建立基準線時就是失敗的（與本次異動無關，在 commit `5ab240c` 上即可重現）。

**根因**：測試把日誌內容的日期**寫死成 `2026-08-25`**（撰寫當天），
但日誌檔名與查詢範圍都用 `DateTime.Today`。查詢範圍是今天、內容卻停在舊日期，
於是這些測試**在寫完的隔天就全部失效**。

**處置**：13 行的日期改為 `$"{today:yyyy-MM-dd} ..."` 內插產生，
與同檔其他本來就會過的測試寫法一致；對應的 `Assert.Equal(new DateTime(2026, 8, 25, ...))`
一併改為以 `today` 組成。並加註解說明日期不可寫死的理由。

## 影響與注意事項

- **升級套件請改 `Directory.Packages.props`**，不要在 `.csproj` 寫回 `Version`。
- **不要為了讓建置過關而整包關閉警告**。需要豁免時針對單一規則碼加 `NoWarn`
  並註明原因與解除條件，比照 `NuGetAuditSuppress` 的寫法。
- 本次未加嚴 analyzer（未設定 `AnalysisMode`），維持 SDK 預設。
  目的是鎖住現有成果，而非一次引入上百條新規則；analyzer 加嚴另案評估。
