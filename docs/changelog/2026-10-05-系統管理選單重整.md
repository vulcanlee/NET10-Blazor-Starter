# 系統管理選單重整（0.9.113）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：0.9.113
- 首次實作版本：0.9.113
- 最後核對日期：2026/10/05

## 目的

「系統管理」底下原本是兩個子群組加四個散落的頁面：

- 系統參數、系統備份、公告管理、AI 提示詞，是 0.9.98～0.9.108 陸續加入、直接掛在系統管理下的頁面。
- 「統計與分析」有 8 項，混了監控診斷、用量、AI 與排程。

CRUD 產生器的文件也建議管理員專屬頁面用 `-MenuGroupId 3`，會繼續產生散落項目。

使用者決定：

- 依功能分成四個子群組，系統管理底下不再有單一頁面。
- 群組可以改名，操作說明與文件一併更新。
- 產生器禁止掛在 3。

## 一、新結構

| 子群組（id） | 頁面 |
|---|---|
| 帳號與權限（34，原「權限管理」） | 使用者管理、角色管理、稽核紀錄 |
| 監控與診斷（6，原「統計與分析」） | 系統健康監控、日誌檢視、日誌等級設定、系統例外紀錄、資料庫用量 |
| AI 管理（7，新） | AI 提示詞、AI 對話紀錄、Token 用量 |
| 系統設定與維運（8，新） | 系統參數、公告管理、排程作業、系統備份 |

頁面的選單 id、路由與權限鍵都不變，只換所屬群組。

## 三、設計決定

| 決定 | 理由 |
|---|---|
| 群組改名時連權限鍵字串一起換 | 這些鍵是管理員專屬、從未種進資料庫，換字串不影響任何角色；沿用舊字串則常數名與畫面名稱對不上 |
| 群組沿用舊 id（34、6），新群組用 7、8 | id 只是對應鍵，沿用可減少異動；7、8 未被使用 |
| 稽核紀錄留在帳號與權限 | 內容以登入、帳號與角色異動為主 |
| 資料庫用量歸監控與診斷，Token 用量歸 AI 管理 | 前者是系統容量，後者是 AI 費用 |
| 排程作業歸系統設定與維運 | 它管的是清理與備份等維運作業，執行時間也在系統參數調整 |
| 產生器擋 3，而不是只改文件建議 | 文件建議擋不住；直接停止並列出子群組，之後就不會再出現散落項目 |
| 展開的群組在 `OnAfterRender` 才套用 | AntDesign `Menu` 只把 `OpenKeys` 套到已經註冊的 `SubMenu`；選單與 `SubMenu` 在同一次渲染才建立時，初始值會落空。0.9.112 以前預設收合，使用者展開時 `SubMenu` 早已存在，所以看不到這個問題 |
