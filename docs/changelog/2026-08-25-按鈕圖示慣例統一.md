# 統一按鈕圖示慣例：工具列 emoji 改用 MaterialIcon（0.4.27）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：0.4.27
- 首次實作版本：0.4.27
- 最後核對日期：2026/08/25

## 目的

日誌檢視頁的「查詢」「匯出」按鈕使用 emoji 當圖示，與專案慣例不符。追查後發現這**不是新頁面獨有的問題，而是全專案性的漂移**：

- `readme.md` 技術堆疊表明訂 **BlazorMaterialIcons 為本專案的圖示函式庫**，`Components/Commons/CrudActionButton.razor` 即依此建立。
- 2026-06-22 的「通用型改善移植」把**操作欄**的 emoji（✏️／🗑️）換成了 `CrudActionButton`，但該次範圍明確只涵蓋操作欄（見該篇 changelog），**工具列從未被處理**。
- 之後新頁面靠複製既有檢視建立，emoji 就一路擴散到六個檢視、共 22 個工具列按鈕。

異動前的分佈：

| 位置 | 寫法 | 數量 |
|---|---|---|
| 操作欄（修改／刪除）| `CrudActionButton` ＋ MaterialIcon | 10 |
| 工具列（新增／重整／清空／搜尋／匯出）| **emoji** | **22** |
| AntDesign `<Icon Type="...">` | 完全未使用 | 0 |

## 變更範圍

### 一、新增共用元件 ToolbarIconButton

新增 `Components/Commons/ToolbarIconButton.razor` ＋ `.razor.css`，**刻意比照 `CrudActionButton` 的結構**（同資料夾、同樣以 `<Tooltip>` 包覆、同樣渲染 `<MaterialIcon Theme="Outlined" Kind="@Icon" />` 加無障礙隱藏標籤），讀其中一個就懂另一個。

之所以不直接沿用 `CrudActionButton`：它是 28×28、透明無框的低調樣式，適合塞在表格操作欄；工具列按鈕是 36px 的一般 AntDesign Default 外觀（有框有底），視覺定位不同，硬套會讓工具列整排變成無框。

CSS 內容取自原本六份重複的 `*-icon-button` 規則，**另補上 `height: 36px`** —— 原本只設 `width`，高度靠 AntDesign 預設的 32px，所以按鈕不是正方形。

### 二、22 個工具列按鈕改用新元件

| 檢視 | 按鈕數 |
|---|---|
| `Views/Admins/RoleViewView.razor` | 4 |
| `Views/Admins/MyUserView.razor` | 4 |
| `Views/Teams/TeamViewView.razor` | 4 |
| `Views/Categories/CategoryViewView.razor` | 4 |
| `Views/Projects/ProjectViewView.razor` | 4 |
| `Views/Analytics/LogViewerView.razor` | 2 |

圖示對應：新增 `add`、重新整理 `refresh`、清空搜尋 `close`、搜尋／查詢 `search`、匯出 `file_download`。

> **匯出刻意採用 `file_download` 而非 `download`**：專案載入的是 **classic Material Icons**（非 Material Symbols），`download` 是較晚加入的名稱，有渲染成破圖方塊的風險。

`<Tooltip>` 改由元件內部提供，外層不再重複包。日誌頁「查詢」原本是 `ButtonType.Primary`（六個檢視中唯一的例外），改用元件後統一為 Default。`ProjectViewView` 的按鈕位於 `CheckAccessAction(...)` 權限判斷內，改寫時保留了外層 `@if`。

六個檢視的 `.razor.css` 各自刪除那份 `*-icon-button` 規則（六份內容逐字相同），改由元件統一提供。其餘 `*-toolbar`、`*-search-input` 等版面規則未動。

### 三、ProjectViewView 的 Bootstrap 按鈕

檔案上傳清單的兩個「移除」按鈕原本是 `<button class="btn btn-sm btn-outline-danger">`，是全專案唯一混用 Bootstrap 的按鈕。改用 `<CrudActionButton Title="移除" Icon="close" Danger />`。

### 四、刪除範本殘留

| 刪除 | 理由 |
|---|---|
| `Views/Admins/RoleViewViewSample.razor` ＋ `.razor.cs` ＋ `.razor.css` | 無 `@page`、無任何外部引用；**修改與刪除都用 ✏️**（複製錯誤），且引用 `.btn-edit`／`.icon-edit` 兩個全專案都不存在的 CSS class。取名 Sample 卻是錯誤範例，最容易被拿去照抄。 |
| `Pages/Counter.razor` | .NET 範本殘留，且 `@page "/counter"` **對外暴露路由** |
| `Pages/Weather.razor` | 同上，`@page "/weather"` |

2026-06-22 那篇 changelog 當年保留孤兒 CSS 與 Sample 檔的決定，在本次一併結清。

### 五、堵住漂移的根源

**`src/MyProject/.github/copilot-instructions.md`** —— 原本寫「在此 Blazor 專案的 UI 元件中，優先採用 Ant Design icons」，與下一行（sidebar 用 Material Icons）自相矛盾，也與 `readme.md` 矛盾，而且全專案 AntDesign `<Icon>` 使用次數為 **0**。這條規則會讓 AI 協作持續產生錯誤寫法，已改為明確指向兩個共用元件。

**`docs/architecture/開發慣例與限制速查.md`** —— 原本對圖示一字未提，新增 §6.1「按鈕與圖示慣例」，含元件對照表、常用圖示名稱、classic vs Symbols 的字型陷阱與沿革說明。

**`docs/guides/建立一個新 CRUD 操作網頁說明.md`** —— §3.1 原本只描述工具列該有哪些按鈕，**沒有任何 markup 範例**，這正是大家複製既有檢視、把 emoji 一路帶下去的原因。補上 `ToolbarIconButton` 與 `CrudActionButton` 的完整範例。

### 六、新增守門測試

新增 `MyProject.Tests/ButtonIconConventionTests.cs`，比照 `MenuIconTests` 的思路遞迴掃描 `Components/**/*.razor`，發現 emoji 圖示即失敗，錯誤訊息直接指出該用哪個元件與哪個 icon 名稱。

例外清單：`EmptyLayout.razor` 與 `NoFooterLayout.razor` 的 `🗙`（Blazor 錯誤 UI 的關閉連結，由框架樣板產生，是 `<a>` 非按鈕）。

**這是唯一能真正防止復發的機制** —— 文件與 copilot-instructions 只是建議，測試才會擋下 PR。已實測：暫時把某個按鈕改回 emoji，該測試確實失敗。
