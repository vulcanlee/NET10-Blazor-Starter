## 為什麼

現有文件很完整，但都是寫給「已經知道要找什麼」的人：
- 《腳手架開發指引》有 3600 多行，是技術百科。
- 《VS Code 開發環境與新專案上手指南》是逐步操作手冊。

剛入門的開發者缺一份入口文件，用白話一次回答下面這些問題：
- 為什麼要有這份腳手架？適不適合我的系統？
- 它已經做好哪些企業都需要的功能？為什麼需要？
- 準備了哪些文件，什麼時候該讀哪一份？
- 為什麼這些文件和守門測試能讓 vibe coding 更順？
- 怎麼用 `New-StarterProject.ps1` 複刻？複刻後要做什麼？

## 做了什麼

只新增文件，程式沒有異動。

**新增 [腳手架總覽與複刻上手](../features/腳手架總覽與複刻上手.md)**（約 800 行）。各節依 What／Why／When／How 說明理由：

- 名詞小辭典、腳手架的定位、為什麼需要它、適不適合用，以及判斷流程。
- 已內建的企業共通功能，分 11 組：
  - 帳號、權限、業務樣板、稽核、可觀測性、AI
  - Web API、基礎設施、介面、安全、工程品質
  - 每項寫明企業為什麼需要、畫面在哪裡、出貨時是開還是關。
- 文件分類，以及「什麼時候讀哪一份」。
- vibe coding 為什麼更順：AI 的四個常見問題與對策、給 AI 的閱讀順序、五則可照抄的提示詞、四道檢查指令。
- `New-StarterProject.ps1`：
  - 事前準備、參數、命名建議、四個範例
  - 腳本做了什麼的白話版、跑完的五條警告怎麼看、產出的資料夾長相
- 複刻後的待辦，分「第一天、第一週、上線前、長期」。
- 範例功能要不要刪。
- 複刻後的版控，以及怎麼跟上腳手架的更新。
- 常見卡關問題 16 題。
