# 登入 Cookie 名稱依專案區分：同主機多站不再互相登出（0.9.64）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：0.9.64
- 首次實作版本：0.9.64
- 最後核對日期：2026/09/24

## 為什麼

登入 Cookie 原本沒有設定名稱，框架依配置名稱自動命名為 `.AspNetCore.CookieAuthenticationScheme`。
這個名稱裡沒有專案名，`New-StarterProject.ps1` 的字串取代換不到，所以每個衍生專案的登入 Cookie 都同名。
瀏覽器的 Cookie 只看主機名稱、不看連接埠，兩個衍生專案若部署在同一台 IIS 的同一主機名稱、不同連接埠
（例：`http://server:8081`、`http://server:8082`），登入 B 會覆蓋 A 的 Cookie，A 解不開就把使用者登出 —— 兩站互相登出。
（不會越權：兩站的 Data Protection 應用程式名稱與金鑰目錄本來就不同。）

## 做了什麼

- `Program.cs` 的登入 Cookie 明寫 `options.Cookie.Name = ".MyProject.Auth"`，寫法比照既有的 `.MyProject.External`。
  名稱帶專案名，`New-StarterProject.ps1` 會自動換成新專案名，腳本本身不需修改。
- `ApiIntegrationTests` 新增 `AuthCookieName_ShouldBeProjectSpecific`：期望值由組件名稱推算（`.{專案名}.Auth`），衍生專案裡一樣有效。
- 盤點其他同主機共用資源：外部登入 Cookie、防偽 Cookie、Data Protection 應用程式名稱、`ExternalFileSystem` 各目錄、
  NLog 日誌子目錄與檔名前綴，都已依專案區分，未修改。
- 原訂 0.9.64 的《寄信服務使用說明》再順延為 0.9.65。

## 影響

- **既有部署**：Cookie 名稱改變，所有已登入的使用者（連同「記住我」）**會被登出一次**，重新登入即可。
- **0.9.64 之前產生的衍生專案**：不會自動修正；重新產生，或依[正式部署與安全檢查清單](../operations/正式部署與安全檢查清單.md)「同一主機名稱部署多個衍生系統」手動補一行。

## 驗證

```
dotnet test src/MyProject/MyProject.slnx                     → 847 通過（846 → 847：新增 AuthCookieName_ShouldBeProjectSpecific）
scripts/New-StarterProject.ps1 -ProjectName ProjA ...        → 產出的 Program.cs 為 ".ProjA.Auth"，衍生專案測試通過
scripts/Test-DocsEncoding.ps1                                → 全部通過
```
