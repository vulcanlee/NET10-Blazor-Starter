# 前端診斷記錄：對指定使用者限時收集前端的 Debug／Trace 日誌（0.10.37）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：0.10.37
- 首次實作版本：0.10.37
- 最後核對日期：2026/11/18

## 目的

延續 0.10.36 的前端錯誤捕捉（[前端錯誤捕捉補強](2026-11-18-前端錯誤捕捉補強.md)）。使用者 2026/11/18 也問到：瀏覽器 Console 裡的那些訊息、哪些該用 Debug 或 Trace 寫進日誌系統。
前端的一般日誌（約 360 處：查詢、開視窗、清單重新載入、推播重試…）平常只印在瀏覽器主控台。常態全部送到伺服器會灌爆日誌、帶出帳號等資訊，所以平常不送；
但遇到「某位使用者回報的怪問題、伺服器日誌看不出原因」時，需要看到**那個人瀏覽器裡當時的細節**。

## 決定（使用者選定）

- **針對指定使用者、限時開啟**（不是全體一起開）：管理員在「日誌等級設定」頁選帳號、等級（DEBUG 或 TRACE）、時間（15 分鐘～8 小時，預設 1 小時），到期自動關閉，也可以提前停止。
- **只存記憶體**：與同一頁的「執行期日誌等級」相同，伺服器重新啟動就全部關閉，不加資料表。
- **告知被診斷的使用者**：畫面底部出現「系統管理員已開啟診斷記錄（至 HH:mm）」，透明，也讓使用者知道可以開始重現問題。
- 開啟與關閉都寫稽核。
- 對象改用**輸入帳號**選擇，不做可搜尋的使用者下拉（不必把全部使用者的姓名載入畫面）。

## 變更內容

### 伺服器

- `Diagnostics/ClientDiagnosticsRegistry`（新，單例）：`Enable`（同一位使用者再開就取代）、`Disable`、`Find`（到期自動失效）、`List`；用 `TimeProvider`，只存記憶體。
- `LogLevelController`（只限管理員）：
  - `GET api/v1/log-level/client-diagnostics`：開著的清單（`ClientDiagnosticsSessionDto`，時間是伺服器本地時間）。
  - `POST api/v1/log-level/client-diagnostics`（`ClientDiagnosticsStartRequestDto{Account,Level,DurationMinutes}`）：等級只能 DEBUG／TRACE、時間只能 15、30、60、120、240、480 分鐘（400），帳號找不到 404；寫 `LogLevel.ClientDiagnosticsStart`（「對 X 開啟前端診斷記錄 TRACE，至 yyyy/MM/dd HH:mm（僅執行期有效）。」）。
  - `DELETE api/v1/log-level/client-diagnostics/{userId}`：沒開著（或已到期）409；寫 `LogLevel.ClientDiagnosticsStop`。
- `MyUserService.FindByAccountAsync`（新）：依帳號找未刪除的使用者（不分大小寫）。
- `UseClientDiagnosticsHeader`（排在 `ApiActorMiddleware` 之後）：被診斷的使用者，每個 `/api` 回應帶 `X-Client-Diagnostics: 等級;到期 HH:mm;剩幾秒`；CORS 公開。不另外輪詢、不經推播（推播關閉時一樣有效），鈴鐺每 60 秒呼叫一次 API，所以最慢約 1 分鐘生效。
- `POST api/v1/shell/diagnostic-logs`（`ClientLogBatchDto` → `{Active}`，本體 512KB）：沒開著一律不寫、回 `Active=false`；開著時 `BrowserLogForwarder`（新）以**原等級**寫到 `MyProject.Browser.<前端分類去掉 MyProject.>`，分類只接受英數字與點（其他歸到 `MyProject.Browser.Other`），低於這次診斷等級的捨棄，每批最多 200 筆、每位使用者每分鐘 30 批。**不帶例外物件**（只把「型別: 訊息」寫在訊息裡），不會進系統例外紀錄。
- `nlog.config`：`<logger name="MyProject.Browser.*" minlevel="Trace" final="true">` 排在所有規則之前 —— 不受「日誌等級設定」的 `*` 規則影響（`LogLevelRuntimeState` 只調整 `*`），也不會重複寫。

### 前端

- `Commons/ClientDiagnosticsState`（新，單例）：解析標頭；到期時間依「剩幾秒」換算（不依賴瀏覽器時鐘），到期自己停止。
- `ApiClient`：帶 Token、非 401 的回應交給 `ClientDiagnosticsState.Update`（匿名呼叫的回應不算）；每次呼叫另記 Trace `API call completed. Method=…, Path=…, Status=…, ElapsedMilliseconds=…, TraceId=…`（只有路徑）。送出診斷日誌本身不記。
- `ClientRoutes`：換頁記 Trace `Navigated. Path=…`。
- `Commons/ClientDiagnosticsLoggerProvider`（新，單例）：只在開啟時收本專案（`MyProject.*`）達門檻的日誌，錯誤回報管線自己的分類不收；緩衝 500 筆（滿了丟最舊的並計數），每 5 秒或滿 100 筆送一批；伺服器回 `Active=false` 就停止。送件者由 `ClientMainLayout` 在登入後設定。
- `Program.cs`：最低等級放到 Trace，篩選讓瀏覽器主控台照舊只顯示 Information 以上。
- `Layout/ClientDiagnosticsBar.razor`（新）：放在根元件的狀態列區。
- `Views/Analytics/LogLevelSettingView`：新增「前端診斷記錄」區塊（帳號、等級、時間、開始；開著的清單與停止）。

## 測試

- `ClientDiagnosticsTests`（新）：對象的到期、取代、關閉；轉送依原等級、分類換成 `MyProject.Browser.*`、不信任分類與換行、低於門檻捨棄、每批上限；`nlog.config` 的規則順序與 `final`；前端狀態解析標頭；日誌接收器只收本專案、門檻以上、開啟時，伺服器說關閉就停止，緩衝上限與捨棄計數。
- `LogApiTests`：只套用到被選的使用者、標頭只出現在他的回應、他送的被接受、別人送的回 `Active=false`、停止後標頭消失、開啟與關閉的稽核；不合法的等級、時間、帳號不寫稽核；非管理員打三個新端點都是 403。
- `ClientSessionTests.ApiClient_ShouldFollowTheDiagnosticsHeader_OnSignedInResponsesOnly`、`PwaStatusBarTests.DiagnosticsBar_ShouldShowWhileDiagnosticsIsOn`、`DualSiteHostTests`（CORS 公開 `X-Client-Diagnostics`）、`ClientErrorReportingConventionTests`（`Program.cs` 的日誌設定）。

## 實機驗證

以 `Start-E2EHost.ps1` 的隔離網站執行新的 `scripts/e2e/client-diagnostics.mjs`，6 項全部通過：

- D1 管理員在頁面上輸入帳號、選 TRACE、15 分鐘，按開始：清單列出這一筆。
- D2 那位使用者登入後畫面底部出現「系統管理員已開啟診斷記錄（至 15:39）…」。
- D3 他換頁後，日誌檔出現 `MyProject.Browser.Web.Client.ClientRoutes` 的 `Navigated` 與 `MyProject.Browser.Web.Client.Api.ApiClient` 的 `API call completed`（TRACE，16 行）。
- D4 沒開啟的 support 換頁，沒有任何前端日誌送來。
- D5 管理員按「停止」：清單清空，使用者下一次呼叫 API 後提示列消失，之後換頁不再送來。
- D6 開啟與關閉各有一筆稽核。

## 已知限制

- 開啟後最慢約 1 分鐘才開始送（等使用者下一次呼叫 API；鈴鐺每 60 秒一次）；關閉也一樣，已經在路上的那一批照樣寫入。
- 開啟前的前端日誌不會補送。
- 只存記憶體、單機設計：重新啟動就關閉；多台主機時每台各一份。
- 前端日誌本身的等級還沒依 PRD §三 整理（例如「按了搜尋」記成 Information）；下一版 0.10.38 整理前後端的日誌等級。
