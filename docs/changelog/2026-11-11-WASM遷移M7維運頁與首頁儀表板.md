# WASM 遷移 M7：維運頁與首頁儀表板（0.10.6）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：0.10.6
- 首次實作版本：0.10.6
- 最後核對日期：2026/11/11

## 目的

WASM 遷移的第七個里程碑（計畫見 [WASM 遷移計畫](../migration/WASM遷移計畫.md)）：「排程作業」（`/scheduled-jobs`）、「系統健康監控」（`/system-health`）、「系統備份」（`/backups`）、「資料保留與清理」（`/data-retention`）、「資料庫用量」（`/database-usage`）、「系統參數」（`/system-parameters`）、「公告管理」（`/announcements`）與登入後首頁（`/App`）改在使用者的瀏覽器以 WebAssembly 執行，背後是新的 Web API。
同時把系統備份的下載改成一次性下載票證，退役最後一個只收 Cookie 的 API（`BackupController`），並修正 M2 留下的鈴鐺與個人資料頁時差問題。其他頁面維持原狀。
測試報告見 [M07-維運頁與首頁儀表板](../migration/測試報告/M07-維運頁與首頁儀表板.md)。

## 變更內容

### 1. 八個頁面改用 WebAssembly

- 頁面與檢視搬到 `MyProject.Web.Client`（`Pages/ScheduledJobPage.razor`、`SystemHealthPage.razor`、`BackupPage.razor`、`DataRetentionPage.razor`、`DatabaseUsagePage.razor`、`SystemParameterPage.razor`、`AnnouncementPage.razor`、`HomeAuthed.razor`；`Views/Admins/*`、`Views/Analytics/DatabaseUsageView`、`Views/Commons/HomeWelcomeView`、`Views/Dashboard/*`），Server 版已刪除。系統健康監控原本整頁寫在 `SystemHealthPage.razor`，改拆成頁面＋`Views/Admins/SystemHealthView`。畫面、按鈕、對話窗與訊息和以前相同。
- 資料經 `Web.Client/Api/OpsApi.cs`（`ScheduledJobApi`、`SystemHealthApi`、`DashboardApi`）、`MaintenanceApi.cs`（`BackupApi`、`DataRetentionApi`、`DatabaseUsageApi`）、`SystemParameterApi.cs`、`AnnouncementApi.cs`（DTO 對應 `AnnouncementDtoMapper`）呼叫 API。DTO 在 `MyProject.Dtos/Admins`（`ScheduledJobDtos`、`SystemHealthDtos`、`MaintenanceDtos`、`SystemParameterDtos`、`AnnouncementDtos`）與 `MyProject.Dtos/Shell/DashboardDtos.cs`。
- 搬到共用的位置：`SystemParameterValueCodec` 搬到 `MyProject.Web.Client/Configuration/`（命名空間仍是 `MyProject.Web.Configuration.Parameters`，定義以新的 `ISystemParameterFormat` 傳入；系統管理助理的「會不會縮短保留天數」也改用它）；`SystemParameterKind`／`SystemParameterSource` 搬到 `MyProject.Dtos/Admins`；公告對象種類 `AnnouncementTargetKinds` 搬到 `MyProject.Share/Helpers/`（命名空間仍是 `MyProject.AccessDatas.Models`）。
- 目前以 WebAssembly 執行的頁面共 22 個：`/Profile`、`/categories`、`/teams`、`/projects`、`/myusers`、`/roleviews`、`/audit-logs`、`/email-logs`、`/logs`、`/log-level-setting`、`/system-exceptions`、`/ai-call-logs`、`/token-usage`、`/prompt-templates`，加上這次的 8 個。仍是 Server 的：`/`（導到 `/App`）、`/ChangePassword`、`/TwoFactorSetup`、`/agent-playground`、`/agent-workflows`、`/admin-assistant`、`/Error`、`/not-found` 與登入相關頁。

### 2. 新的 Web API

除首頁外全部只有 `api/v1` 路由、要 Bearer、標 `[AdminOnly]`（非管理員 403 並寫 `Permission.Denied`）、回 `ApiResult`；本地時間以不帶時差送出，「現在」「今天」用伺服器時間；稽核動作與內容和 Server 版頁面相同、由伺服器寫。端點細節見 [Web API 端點目錄](../architecture/Web%20API%20端點目錄.md) 第二之三節。

- **`api/v1/scheduled-jobs`**（`ScheduledJobsController`）：`GET` 總覽、`POST {name}/trigger`（放進排程佇列；已在執行回 409；成功寫 `Job.Trigger`，`job=名稱`）、`PUT {name}/enabled`（`Job.Enable`／`Job.Disable`）、`GET {name}/runs`（最多 50 筆）。作業名稱不分大小寫。
- **`api/v1/system-health`**（`SystemHealthController`）：`GET` 報告（⚠️ 每次都跑全部檢查，AI 有設定時「LLM API」會真的呼叫模型並記 Token 用量，Server 版也是）、`GET warn-logs`（最近 24 小時 WARN 以上；讀取失敗只影響這一區）、`POST test-email`（`Email.Test`）、`POST test-notification`（`Notification.Test`）。
- **`api/v1/backups`**（`BackupsController`）：`GET` 清單與作業狀態、`POST run`（放進排程佇列；執行中 409；`Job.Trigger`）、`DELETE {檔名}`（`Backup.Delete`）、`POST {檔名}/ticket`（一次性下載票證，見第 3 節）。
- **`api/v1/data-retention`**（`DataRetentionController`）：`GET` 總覽（含伺服器的「今天」）、`POST {種類}/purge-now`（放進佇列；`Job.Trigger`，`job=…; source=data-retention; expected=N`，N 由伺服器重算）、`POST {種類}/preview`、`POST {種類}/custom-purge`（長時間請求，WASM 用 `PostLongRunningAsync`；稽核照 Server 版）。
- **`api/v1/database-usage`**（`DatabaseUsageController`）：`GET`（只送資料庫檔名，不送完整路徑；不寫稽核）。
- **`api/v1/system-parameters`**（`SystemParametersController`）：`GET`（全部參數、不認得的鍵、設定檔有誤的區段）、`POST save`（`Key`、`Value`、`ExpectedStamp`；`SystemParameter.Update`，值與設定檔相同改記 `Reset`）、`POST reset`。**驗證全在伺服器**（`SystemParameterManager`＋設定驗證器）：不在目錄的鍵（例如 `JwtSettings:SigningKey`）404、輸入不合法 400、版本衝突或設定檔有誤 409。設定鍵含冒號，放在本文。
- **`api/v1/announcements`**（`AnnouncementsController` 擴充）：`GET` 清單（含角色、團隊選項與伺服器的「現在」）、`POST`、`PUT {id}`、`DELETE {id}?concurrencyStamp=`（`Announcement.Create`／`Update`／`Delete`，刪除的標題取自資料庫）；原有的 `active`、`dismiss` 改為各自標 `[SignedInUser]`。存檔後伺服器照 Server 版清快取並廣播。
- **`api/v1/dashboard`**（`DashboardController`，首頁 view 權限）：`GET` 首頁（系統名稱、版本、環境、依權限過濾的快速入口、**這個人看得到的小工具**）、`GET account`、`GET notifications`（最新 5 則，只保留站內安全連結）、`GET scheduled-jobs`（`[AdminOnly]`）。不寫稽核。
- 「刪除選取」照 M5 由畫面逐筆呼叫 `DELETE`，沒有批次端點。排程、備份、資料保留共用的作業狀態轉換在 `Controllers/MaintenanceJobMapper.cs`。

### 3. 備份下載改用一次性票證，退役 `BackupController`

- 下載先以 Bearer 呼叫 `POST api/v1/backups/{檔名}/ticket`，再由暫時的 `<a download>` 讓瀏覽器原生下載 `GET api/v1/downloads/{票證}`（與 M4 的專案附件同一個端點，不經 WASM 記憶體）。
- `DownloadTicketService` 的票證目標改成字串（`DownloadTicket.Target`：附件 Id 或備份檔名），新增種類 `BackupKind`。兌換時重新檢查帳號、工作階段版本、強制改密碼／兩步驟驗證、**仍是管理員**，檔名經 `BackupStore.TryResolveFullPath` 防路徑穿越；任何一關不過都回同一個 404。稽核 `Backup.Download` 在**兌換時**寫一筆。
- **舊的 `BackupController`（`GET api/backups/{檔名}/download`，只收 Cookie）已刪除**，舊網址回 404。0.10.6 起已沒有以 Cookie 驗證的 API。
- ⚠️ 與 M4 附件相同的取捨：**票證只能用一次，下載中斷不能續傳**，要回頁面重新點（Server 版的 Cookie 下載可以續傳；遷移計畫與 M4 已拍板一次性票證）。

### 4. 首頁小工具由伺服器決定

- 伺服器的 `AddDashboard()` 只登記代號、標題、順序、權限與圖示（`AddDashboardWidget(…)`，描述子不再帶元件型別），`GET api/v1/dashboard` 依 `DashboardWidgetCatalog.VisibleTo` 只回這個人看得到的小工具；快速入口也由伺服器依權限過濾（`DashboardQuickLinks`）。
- Client 的 `DashboardWidgetComponents` 以代號對應元件（不認得的代號不顯示內容），兩邊的代號由 `DashboardTests` 檢查一致。每個小工具繼承 `DashboardWidgetBase`、**自己讀資料**，讀不到只影響自己那張卡片（顯示 API 回應的追蹤碼）。
- 新增小工具的步驟見 [首頁儀表板 PRD](../prd/首頁儀表板-prd.md)「新增一個小工具」。

### 5. 外框立即重讀：`ClientRefreshSignal`

WASM 收不到伺服器的 `INotificationSignal`，外框的鈴鐺與公告橫幅平常 60 秒輪詢。新增共用基底 `ClientRefreshSignal`（`MyProject.Web.Client/Layout/ClientNotificationSignal.cs`），頁面做了會讓外框內容改變的事就請它立即重讀：

- `ClientNotificationSignal`：系統健康監控「發送測試通知」、首頁「我的通知」點開通知後，鈴鐺（與「我的通知」）立即重讀；在鈴鐺標為已讀、刪除、全部已讀或清除已讀後，鈴鐺以 `RequestRefresh(except: 自己)` 請首頁「我的通知」立即重讀（跳過已經重讀過的鈴鐺）。
- `ClientAnnouncementSignal`：公告管理存檔或刪除後，同一個分頁的公告橫幅立即重讀。
- 只對同一個分頁有效；其他已開的分頁照舊 60 秒輪詢與切回分頁時重讀。

### 6. 修正：鈴鐺、個人資料頁與「關於」的時差（M2 留下的問題）

三處：`NotificationsController`（鈴鐺）、`ProfileController` 與 `ShellController`（「關於」的啟動時間 `StartedAtLocal`）。前兩者的本地時間以 `TimeZoneInfo.ConvertTimeFromUtc` 算出、後者用 `DateTimeOffset.LocalDateTime`，都是 `Kind=Local`，序列化時帶 `+08:00`，伺服器與瀏覽器時區不同時 WASM 會換成瀏覽器的時區、時間就錯。改為以不帶時差（`Unspecified`）送出，補測試 `NotificationsProfileAndShellInfo_ShouldSendLocalTimesWithoutAnOffset`（`ShellController` 是獨立審查發現的）。

### 7. 獨立審查（4 項修正，另記 2 項設計說明）

1. 低～中：排程作業、系統備份、資料保留頁執行中的自動輪詢失敗時（伺服器重啟、斷線），每 2／5 秒疊一則不會自動關閉的錯誤通知 → 輪詢失敗只記日誌，下一次輪詢再試；按「重新整理」失敗時照舊顯示錯誤。
2. 低：首頁「我的通知」第一次讀取還沒回來就換頁時，元件已移除仍訂閱 `ClientNotificationSignal`（之後每次訊號都多打一次 API）→ 訂閱前先確認元件還在。
3. 低：「關於」的啟動時間（`ShellController` 的 `StartedAtLocal`）仍帶 `+08:00` 送出 → 改不帶時差；時差測試涵蓋 `shell/info`（見第 6 節）。
4. 低：文件寫備份下載可以續傳、排程每 5 秒自動更新 → 已更正（操作說明、手冊、欄位字典、PRD、測試指南等）。
- 設計說明（不改）：備份票證是「持有連結即可下載」——只發給管理員、60 秒、只能用一次、兌換時再檢查身分與管理員；日後可在兌換時比對同源 Cookie 再加強。
- 設計說明（不改）：公告 API 的開始／結束時間是伺服器本地時間；非 WASM 的呼叫端若送帶 `Z` 的 UTC，會被當成本地時間。

### 8. 與 Server 版不同、使用者看得到的地方

1. 備份下載不能續傳（一次性票證，見第 3 節）。
2. 排程作業有作業排隊或執行中時每 **2 秒**自動更新（Server 版 5 秒），結束或離開頁面就停；備份與資料保留頁維持 5 秒。
3. 系統健康頁讀不到報告時停在「正在讀取系統健康狀態...」並跳錯誤通知（Server 版整頁進錯誤畫面）；資料庫用量頁讀不到時顯示「讀取資料庫用量失敗：…」（Server 版一直停在讀取中）。
4. 「發送測試通知」後這一頁的鈴鐺立即更新；其他已開的頁面與其他管理員最慢 60 秒（說明文字照抄 Server 版的「即時更新」，操作說明已補充）。公告存檔後同一分頁的橫幅立即更新，其他分頁與其他人最慢 60 秒。
5. 「立即清理」稽核的 `expected` 由伺服器在按下時重算，可能和確認窗的數字差幾筆；自訂清除的條件由伺服器驗證。

## 升版注意

- 版本號 0.10.5 → 0.10.6。
- 沒有資料庫異動。
- 有外部程式或腳本用 `GET /api/backups/{檔名}/download`（Cookie）下載備份的，這個網址已移除；改成以管理員的 Bearer Token 呼叫 `POST /api/v1/backups/{檔名}/ticket`，再下載回傳的網址（60 秒、只能用一次），或直接從 `BackupPath` 複製檔案。
- 大檔備份的異地保存建議直接從 `BackupPath` 複製：瀏覽器下載中斷時不能續傳。
- 有外部程式要讀排程、系統健康、資料保留或系統參數的，現在可以用 `api/v1/scheduled-jobs`、`api/v1/system-health`、`api/v1/data-retention`、`api/v1/system-parameters`，只限管理員的 Bearer Token（注意 `GET api/v1/system-health` 每次都會呼叫一次 AI 模型）。
- 衍生專案若新增過首頁小工具：伺服器的登記改成 `AddDashboardWidget("代號", …)`（不再帶元件型別），元件搬到 `MyProject.Web.Client/Views/Dashboard/` 並登記到 `DashboardWidgetComponents`，資料改經 `DashboardController` 的端點。
- 衍生專案若引用了 `SystemParameterView.ShortensRetention` 或 `SystemParameterValueCodec`：改用 `MyProject.Web.Client/Configuration/SystemParameterValueCodec`（命名空間不變，參數改為 `ISystemParameterFormat`）。
