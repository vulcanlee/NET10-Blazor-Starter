# 全站粉梅視覺收尾：色票單一化、深梅側邊欄、表格與 shell 統一（0.9.30）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：0.9.30
- 首次實作版本：0.9.30
- 最後核對日期：2026/09/19

## 為什麼

「粉梅暖雪」只做了一半：登入頁（0.9.23）與所有浮層（0.9.25–0.9.29）是粉梅果凍，
但側邊欄、頂欄與十個清單頁還停在藍紫／灰白。使用者的實際動線是**三段不同色系**
—— 粉色登入 → 藍紫後台 → 點「修改」又跳出粉色果凍窗。

同時，粉梅色票被複製了三份以上且沒有共同來源（`Login.razor.css` 的 `--login-*`、
`OverlayStyles.razor` 的 `--ov-*`、shell 與各檢視裡整片硬編）。對一個**腳手架**專案來說
這是主要缺陷：別人拿去換品牌色得翻五個檔。

## 設計決策

**分層強度**：浮層維持完整果凍；**資料工作區維持白／極淡暖白的高對比**。
粉梅用在側邊欄、頂欄、卡片亮邊、按鈕、focus、排序箭頭、列 hover、分頁目前頁與狀態徽章。

比稿來源那張「粉底表格」是**對話窗比稿頁的背景陪襯**（該頁自己的說明寫著
「用來讓毛玻璃有東西可以透」），只有 4 列 8 欄、沒有排序箭頭與固定操作欄。
本系統的日誌與 Token 用量頁有 8～10 欄，直接照搬會犧牲掉使用者停留最久的那個畫面的可讀性。

## 做了什麼

### 色票單一化

- 新增 `src/MyProject/MyProject.Web/wwwroot/theme.css`：`:root` 色票，含色相三元組
  （`--app-accent-rgb` 等），所有濃淡用 `rgba(var(--…-rgb), a)` 組出來，換色只改這一個檔。
- `<link>` 掛在 `App.razor` 的 **AntDesign CSS 之後**（排在前面會在同分特異性上輸掉）。
- `--ov-*`（OverlayStyles）與 `--login-*`（Login）降為別名層，一律指向 `var(--app-*)`；
  `OverlayStyles` 內通知／消息條區塊原本吃不到變數而硬編的色碼也一併收斂。

### 常駐介面

- `theme.css` 新增 AntDesign 頁內元件的全域覆寫：表格（表頭／斑馬／hover／**固定欄**／
  排序欄位與箭頭）、分頁、輸入框與下拉聚焦、`.ant-tag` 圓角、工具列按鈕、`.alert-danger`。
  **十張表一次到位，各檢視的 `.razor.css` 一行都不用改。**
- 刪除 `OverlayStyles.razor` 裡只服務角色管理頁的 `.role-view-table-wrap` 斑馬與藍色 hover
  —— 十張表裡只有一張有斑馬，現在改由全域規則一致提供。
- `MainLayout.razor.css`：頁面底、頂欄、使用者選單、`article` 卡片（圓角 28px ＋ 粉色外亮邊）。
- `NavMenu.razor.css`：側邊欄改**深梅漸層＋淺色字**，active 用莓粉亮塊；收合軌同步；
  飛出面板**維持淺粉**（它浮在白色內容區上，深色面板會像一塊斷裂的方塊）。
- 其餘畫面：操作欄按鈕（每一列都有）、首頁歡迎頁、啟動頁、**待審核頁**（原本是綠色的第三套色）、
  登出頁、變更密碼頁、資料庫用量、日誌等級設定、日誌檢視、Token 用量、`app.css` 的連結色與焦點環。

### 狀態徽章

新增 `Components/Commons/StatusPill.razor`（＋ `StatusTone.cs`）。這是**去重複**：
分類清單與團隊清單原本各帶一份**逐字相同**的 `.category-status` / `.team-status`
（連色碼都一樣），使用者管理與專案項目則是純文字 —— 同一個概念三種長相。
語氣對應留在呼叫端（見 `ProjectViewView.ResolveStatusTone`）。

### 守門測試

`MyProject.Tests/ThemeConventionTests.cs` 兩條，擋的都是 CI 看不到的靜默漂移：

1. `ThemeCss_ShouldLoadAfterAntDesignStylesheet` —— 有人整理 `<head>` 或 AntDesign 升版
   改了引入點，十個清單頁的表格樣式會**同時**失效而毫無徵兆。
2. `PaletteHexes_ShouldOnlyLiveInThemeCss` —— 沒有這條，「換色只改一個檔」在交付當天成立、
   三個功能之後就不成立了。（這條測試在導入當下就抓到 `Login.razor.css` 兩處漏網。）

### 產生器

`scripts/New-CrudModule.ps1` 原本輸出 `class="<前綴>-view-toolbar"`，
但整支腳本**從未產生對應的 `.razor.css`** —— 每個新模組一出生工具列就沒有版型。
改為使用 `theme.css` 的共用類別 `view-toolbar` / `view-table-wrap`，並補上樣式歸屬的註解。
既有十個檢視的前綴**不重新命名**（純 churn、零視覺收益）。

## 順手修正的既有問題

- `.user-menu-item` 的基礎色原本是 `#b91c1c`，讓「變更密碼」「關於」全都長得像危險動作；
  危險色改由 `.user-menu-item-danger` 單獨負責。
- `.sidebar` 頂端的 `radial-gradient` 白光原為 `0.85`（給淺色側邊欄用的），
  深梅底上會把上緣洗成近白、品牌文字直接看不見。已降到 `0.10`。
- 文件漂移三處：`fm-jelly-check` 實際叫 `ov-jelly-check`；§9 的 `cfm-arrive` 根本不存在
  （確認窗用共用的 `ov-arrive`）；速查表 §6.4 仍把 `.role-view-modal`／`.project-view-modal`
  列為「尚未遷移」，兩者早已遷移且 class 已不存在。

## 刻意沒做

| 項目 | 理由 |
|---|---|
| `SystemHealthPage` | 紅綠燈與黑底日誌區是語意色與工具感，染粉會傷害可讀性 |
| `ReconnectModal` | 原生 `<dialog>`，渲染在 `<Routes>` 之外，且有 `@starting-style` 進退場編排 |
| `#blazor-error-ui`、`.blazor-error-boundary` | 框架級 panic UI，刻意不品牌化 |
| 通知圖示與 `<Tag Color>` 的語意色 | 染成粉紅等於拿掉使用者最先讀到的訊號 |
| 十個檢視的 class 前綴重新命名 | 純 churn |
| 深色模式／主題切換 | 不在本次範圍 |

已回報未處理的既有死 CSS：`EmptyLayout.razor.css` 與 `NoFooterLayout.razor.css` 裡的
`.sidebar` / `.top-row` 規則 —— 兩個 layout 都沒有渲染那些元素。
