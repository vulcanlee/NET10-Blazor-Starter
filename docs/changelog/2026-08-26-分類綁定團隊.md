# 分類綁定團隊與儲存前團隊確認（0.4.40）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：0.4.40
- 首次實作版本：0.4.40
- 最後核對日期：2026/08/26

## 目的

「分類」原本是全系統共用的平面主檔，任何使用者在任何團隊下都會看到**全部**分類項目。
實務上某些分類只給特定團隊使用，造成下拉清單塞滿用不到的項目、使用者難以挑選。

本次讓分類可以指定**適用團隊**，並在「團隊欄位沒設定就要存檔」時主動提醒使用者影響。

## 一、分類新增「適用團隊」欄位

`Category` 新增 `Teams` 欄位（migration `AddCategoryTeams`），沿用既有的**換行分隔標籤字串**
格式（`TagStringHelper`，例 `"\n研發部\n業務部\n"`），與 `Project.Categories` / `Project.Teams` 一致。

> **為什麼不開中介表**：`TagStringHelper.BuildTeamAccessPredicate` 已經存在，且它的
> 「欄位為 null／空 ＝ 公開」語意正好就是本次要的規則，沿用等於零新增過濾邏輯。
> 開 `CategoryTeam` 中介表要多出 Entity / DbSet / OnModelCreating / Sync 服務 / 名稱↔Id 解析，
> 換來的參照完整性是 `Project.Teams` 目前也沒有的東西，會讓系統同時存在兩種團隊綁定風格。
> 已知取捨：團隊改名會斷掉綁定（既有問題，本次不擴大也不修正）。

分類維護頁（`/categories`）表格新增「適用團隊」欄，編輯 Modal 新增多選欄位。

## 二、可見性規則

| 情境 | 結果 |
|------|------|
| 分類未指定適用團隊 | 公用分類，所有人可見 |
| 使用者為系統管理員 | 看得到全部分類 |
| 使用者未綁定任何團隊 | 看得到全部分類 |
| 使用者有團隊 | 看得到「公用分類」＋「與自己所屬團隊有交集」的分類 |

「使用者的團隊」＝其**所有**所屬團隊的聯集（`IEffectiveTeamResolver`），系統沒有
「目前團隊／切換團隊」的概念。

規則集中在 `CategoryService.ApplyTeamVisibility`（清單／下拉）與 `IsVisible`（單筆），
套用於三個讀取入口：清單 `GetAsync(DataRequest)`、單筆 `GetAsync(int)`、
下拉來源 `GetAllEnabledNamesAsync()`。分類維護頁本身也套用同一過濾。

### ⚠️ 刻意偏離：空團隊使用者的規則與紀錄相反

紀錄（`Project`）的規則是「使用者沒有團隊 → **只**看得到公開紀錄」；
分類則是「使用者沒有團隊 → 視為不受限，看得到**全部**分類」。

分類可見性是下拉清單的**便利性過濾**，不是安全邊界（安全邊界為 RBAC），因此採寬鬆規則。
`CategoryServiceTeamVisibilityTests.GetAsync_NonAdminWithoutTeams_ShouldSeeAllCategories`
釘住這條規則，避免日後被「順手改成一致」。

名稱唯一性檢查**不**套團隊過濾（維持全域比對），否則會出現「看不到卻建得出同名分類」。

## 三、儲存前的團隊確認對話窗

新增共用樣板 `Components/Commons/TeamBindingConfirm.cs`：標題「確認團隊設定」、
確認鈕「仍要儲存」、取消鈕「回去編輯」、`MaskClosable = false`。
取消時 Modal 保持開啟，表單內容不消失。

三個觸發點：

| 畫面 | 條件 | 提醒內容 |
|------|------|----------|
| 分類編輯 | 未指定適用團隊 | 將出現在所有使用者的分類下拉清單中（視同公用分類） |
| 分類編輯 | 指定的團隊與自己所屬團隊沒有交集 | 儲存後你將無法在分類清單中看到這筆資料 |
| 專案編輯 | 未指定團隊 | 將對所有使用者公開可見 |

第二種情境是「維護頁也依團隊過濾」的直接後果：一個【研發部】使用者若把分類只綁給
【業務部】，存檔後這筆分類會立刻從他自己的清單消失。

## 四、順帶修正的資料遺失風險

`CategoryController.Update` 是 `mapper.Map<Category>(dto)` 之後整筆覆寫。
`CategoryCreateUpdateDto` 若沒有 `Teams` 欄位，**每一次經由 API 更新分類都會把團隊綁定清成 null**。
本次一併補上 `teams` 欄位（`CategoryDto` 繼承取得）。

Web API 路徑（`CategoryRepository` / `CategoryController`）維持既有分工，**不**做行級過濾。

## 五、專案編輯頁的舊值保留

分類下拉改用 `modalCategoryOptions` ＝「目前可見分類」∪「這筆專案已貼但看不到的分類」，
後者顯示為「分類名稱（已限定其他團隊）」。

若不這麼做，AntDesign 的多選 `Select` 會把已選但不在選項中的值視為未知，
使用者一存檔就被靜默清掉。`Value` 一律維持原始名稱，只有顯示文字加註。
