# 開發環境預設開啟 Pickup 寄信，本機一啟動就能測忘記密碼（0.9.61）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：0.9.61
- 首次實作版本：0.9.61
- 最後核對日期：2026/09/24

## 為什麼

0.9.60 完成忘記密碼後，本機登入頁仍看不到「忘記密碼？」—— 出貨的 `EmailSettings:Provider` 是 `None`，
依設計沒啟用寄信就沒有忘記密碼。每位開發者都得自己設 User Secrets 才能測，容易誤以為功能壞了。

## 做了什麼

- `appsettings.Development.json` 新增 `"EmailSettings": { "Provider": "Pickup" }`：
  開發環境一啟動，登入頁就有「忘記密碼？」，信寫成 `.eml` 到 `C:\temp\MyProject\Mails`，不需要任何帳密。
  只覆寫 `Provider`，其餘（`PickupDirectory`、`PublicBaseUrl` 留白 → 用目前請求網址）沿用 `appsettings.json`。
- 新增守門測試 `EmailSettingsTests.ShippedDevelopmentSettings_ShouldUsePickupWithoutSecrets`：
  開發設定必須是 `Pickup`，且不得出現 `Password`／`UserName`（這個檔會進版控）。
- 原訂 0.9.61 的《寄信服務使用說明》順延為 0.9.62。

## 不受影響

- **Production**：不載入 `appsettings.Development.json`，出貨仍是 `None`；就算有人在正式環境設成 `Pickup`，
  `StartupSafetyValidator` 也會拒絕啟動。
- **整合測試**：環境是 `Testing`，不載入這個檔，而且 `ApiTestApplicationFactory` 明寫 `Provider=None`。
- **系統健康監控**：開發機的「寄信服務」由 None 黃燈變成 Pickup 黃燈，分數不變。

## 順手修正

- 本機測試時，`appsettings.json` 的 `BootstrapSettings` 後面多了一段 `"EmailSettings": { "Provider": "" }`，
  與檔案後段原有的 `EmailSettings` 重複，設定會以「A duplicate key 'EmailSettings:Provider' was found」載入失敗、系統起不來。
  經確認後移除，改由本次的 `appsettings.Development.json` 達到同樣目的。
- `日誌與設定檔說明` §5 的 `appsettings.Development.json` 範例早已與實際內容不符（`Default` 其實是 `Debug`），已照實際內容更新。

⚠️ 驗證時開發者本機正在執行網站（鎖住 `MyProject.Web/bin`），因此以
`dotnet build MyProject.Tests -p:BuildProjectReferences=false` 只重建測試專案 —— 本次沒有任何 Web 程式碼變更，
沿用已建置的 Web 組件即可；兩個設定檔由整合測試與守門測試直接從原始碼位置讀取。
