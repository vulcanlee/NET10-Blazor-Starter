# 程式問題修正：交易、預設角色、JWT 工作階段、通知去重、語系（0.9.136）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：0.9.136
- 首次實作版本：0.9.136
- 最後核對日期：2026/10/23

## 目的

0.9.114 與 0.9.135 兩次文件全面核對時，列出了「文件對、程式錯」的疑似程式問題（見 [0.9.135](2026-10-23-文件與原始碼全面同步.md) 第四節）。使用者決定這次一起修。
有行為改變的項目都先寫會失敗的測試，確認失敗，再修到通過。

## 一、行為修正

| 項目 | 修正前 | 修正後 | 測試 |
|---|---|---|---|
| 使用者與角色存檔的交易 | `MyUserService`／`RoleViewService` 先用工廠 context 存主表，`RbacWriteService` 再用 DI 注入的另一個 context 寫 `UserRole`／`UserTeam`／`RolePermissionMap`。兩邊各自存檔，可能只成功一半 | `IRbacWriteService` 加上帶 `BackendDBContext` 的多載。兩個服務的新增與修改都開一個交易：存主表 → 用同一個 context 同步對應表 → 提交，失敗時整筆回復。原本不帶 context 的多載保留（測試與其他呼叫端不用改） | `MyUserServiceAssignmentTests`、`RoleViewServiceTests` 各 2 支 |
| 「預設角色」改名 | 可以改名。之後啟動時找不到這個名稱，會重建一個帶全部權限的新「預設角色」 | `BeforeUpdateCheckAsync` 與 `UpdateAsync` 都擋下，訊息「「預設角色」是系統內建的角色，不可改名。」，不換版本號；權限與其他欄位照常可改 | `RoleViewServiceTests` 2 支 |
| JWT access token 的工作階段 | `OnTokenValidated` 只檢查 token 類型。改密碼、強制登出或停用帳號後，已發出的 access token 還能用到過期，最多 60 分鐘 | 另以 `ISecurityStampService.IsValidAsync` 比對工作階段版本與帳號狀態，和登入 Cookie 共用同一套快取（`CookieSettings:ValidationIntervalMinutes`，預設 5 分鐘），不符時回 401 `ApiResult`。停用確認窗寫的「API 會被登出」從此成立 | `ApiIntegrationTests` 2 支（換版本、停用） |
| 通知去重 | `SourceKey` 只比對現存的通知。0.9.125 起通知可以刪除，已讀的 7 天後也會被清除，因此：AI 用量 80%／100% 的警告在同一期間會重發，全系統 100% 那則還會重寄信；密碼到期提醒也會重發 | 新表 `NotificationDispatch`（主鍵為鍵加收件人），和通知在同一次存檔寫入，去重改看這張表。它跟著通知的建立保留天數（`RetentionDays`，預設 90 天）清除，不受 `ReadRetentionDays` 影響。migration `AddNotificationDispatch` 會把升級前的帶鍵通知補成紀錄 | `NotificationTests` 2 支；回填 SQL 另以臨時測試驗證後刪除（寫死 migration 名稱的測試會讓衍生專案失敗） |
| 鈴鐺「清除已讀」按鈕 | 只看下拉顯示的最新 10 則；最新 10 則都未讀時按不了 | 改用 `NotificationQueryService.HasReadAsync`，只要有任何已讀通知就能按 | `NotificationComponentTests` 1 支 |
| 語系 | 支援 `zh-TW` 與 `en-US`，`Routes.razor` 每次渲染都依目前文化呼叫 AntDesign 的 `LocaleProvider.SetLocale`，會改到**行程層級**的預設 UI 文化。只要一位用英文瀏覽器的使用者連線，背景執行緒就變成 en-US | 只支援 `zh-TW`，拿掉每次渲染的呼叫，AntDesign 的語系只在啟動時設定一次 | `LocalizationTests` 2 支 |
| 專案「顯示已刪除」的搜尋 | 只比對標題、描述、負責人 | 和一般清單一樣，也比對狀態、優先級 | `SoftDeleteTests` 2 支 |
| 複刻腳本 | `New-StarterProject.ps1` 替換專案名稱時，副檔名清單不含 `.tmpl`，`crud-templates` 裡 46 處 `MyProject.` 不會被換掉 | 補上 `.tmpl` | 實際複刻到暫存目錄驗證：樣板剩下的 `MyProject` 為 0 處，46 處都換成新名稱 |

## 二、使用者看得到的文字

- 「密碼有效天數」參數說明：「到期前 7 天每天早上會收到站內通知」改為「到期前 7 天內會收到一次站內通知」，符合實際只提醒一次的行為。
- 排程作業「站內通知清理」的說明補上已讀保留天數。
- 使用者管理「管理員」欄位提示：「管理員會短路所有動作級授權檢查。」改為「管理員不受角色權限限制，可以使用所有功能。」
- AI 對話紀錄頁停用記錄時的提示：設定鍵 `AiCallLogSettings:Enabled = false` 改為系統參數名稱「記錄 AI 對話內容」。
- 系統例外紀錄：點列複製失敗時，統一顯示「請改按「查看」手動選取複製」。
- 專案結束日期驗證訊息統一為「結束日期不可早於開始日期。」

**刻意保留**：
- 健康監控頁的寄信提示、測試寄信的錯誤訊息會出現 `EmailSettings`／`Provider`。這兩頁只有管理員能進，而且那是只能改設定檔的設定，鍵名是管理員需要的資訊。
- 排程作業頁的 `ScheduledJobSettings:Enabled` 也是同樣理由。
