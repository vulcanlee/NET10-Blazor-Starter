# AI 呼叫改走 Microsoft Agent Framework（0.9.140）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：0.9.140
- 首次實作版本：0.9.140
- 最後核對日期：2026/11/02

## 目的

系統所有 LLM 呼叫（AI 日誌分析、AI 例外分析含追問、健康監控的 AI 連線探測）原本都是手刻 HTTP。
為了讓腳手架與複刻出的專案之後能直接用 MAF 的 Agent 能力（工具呼叫、多輪對話、多 Agent 工作流程），
改由 Microsoft Agent Framework 建立的 agent 送出。這是四階段計畫的第一階段：**只換底層，行為不變**。
設計與後續階段見 [MAF AI 呼叫架構](../architecture/MAF-AI呼叫架構.md)。

## 一、管線

- 新增 `IAiAgentFactory`／`AiAgentFactory`：建立 agent 的唯一入口。組 OpenAI 官方 SDK（Azure 也用它，指向 `/openai/v1`）、
  關掉 SDK 重試（預設 3 次）、關掉 SDK 與具名 HttpClient 的逾時，再以 `AsAIAgent(..., clientFactory:)` 掛上記帳中介層。
- 新增 `AiAccountingChatClient`：原本 `AiChatCompletionClient.CompleteAsync` 的用量上限、AI 對話紀錄、逾時、錯誤對應、Token 用量
  原樣搬過來，改成對「每一次模型呼叫」生效（位在 MAF 工具呼叫迴圈下方，之後的 Agent 不會漏帳）。失敗以 `AiCallException` 往外丟。
- 新增 `AiHttpCapturePolicy`（SDK 管線上擷取請求與回應原文）與 `AzureApiKeyPolicy`（Azure 改送 `api-key` 標頭，和以前一致）。
- 用量、實際模型、`finish_reason`、內容過濾類別仍由 `AiChatResponseParser` 從回應原文解析，Token 用量與對話紀錄內容與以前一致。
- `AiChatCompletionClient` 介面與 `AiChatCompletionRequest`／`AiAnalysisResult` 不變；`AiLogAnalysisService`、`AiExceptionAnalysisService`、
  兩個畫面都沒改。`AiHealthProbe` 改走同一條管線（30 秒逾時、不受用量上限影響）。
- 移除手寫 JSON 的 `AiChatRequestFactory`、`AiChatEndpoint.Create` 與 `AiChatEndpointDescriptor`；`AiChatEndpoint` 改提供 `GetBaseUri`。
- 串流暫時由記帳中介層明確拒絕，第二階段接上記帳後才開放。

## 二、看得到的差異

| 項目 | 修改前 | 修改後 |
|---|---|---|
| 請求 body | 自己寫，明寫 `"stream": false`，中文跳脫成 `\uXXXX` | SDK 產生，省略 `stream`（預設即不串流）；中文直接以 UTF-8 保存、欄位順序不同，AI 對話紀錄頁照樣解析 |
| 健康探測失敗原因 | 連線失敗 `TransportError`、HTTP 失敗一律 `UpstreamError` | 與分析共用分類（`UpstreamError`、`Unauthorized`、`RateLimited`、`NotConfigured`）；健康頁的訊息不變 |
| 失敗日誌的記錄器 | `MyProject.Web.Ai.AiChatCompletionClient` | `MyProject.Web.Ai.AiAccountingChatClient`（AI 例外分析失敗畫面的提示文字同步）|
