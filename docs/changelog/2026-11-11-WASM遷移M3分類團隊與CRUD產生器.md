- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：0.10.2
- 首次實作版本：0.10.2
- 最後核對日期：2026/11/11

## 目的

WASM 遷移的第三個里程碑（計畫見 [WASM 遷移計畫](../migration/WASM遷移計畫.md)）：「分類清單」（`/categories`）與「團隊清單」（`/teams`）改在使用者的瀏覽器以 WebAssembly 執行，
兩者的 Web API 改走與畫面相同的服務，CRUD 產生器改為產生 WASM 頁面。其他頁面維持 Server 版。
測試報告見 [M03-分類團隊與CRUD產生器](../migration/測試報告/M03-分類團隊與CRUD產生器.md)。

## 變更內容

### 1. 分類、團隊兩頁改用 WebAssembly

- 頁面與檢視搬到 `MyProject.Web.Client`（`Pages/CategoryPage.razor`、`Pages/TeamPage.razor`、`Views/Categories`、`Views/Teams`），Server 版已刪除。
  畫面與操作和以前相同：與 Server 版截圖比對 8 個畫面，4 個完全相同，其餘最多 8/255 的色差。
- 資料經 `Web.Client/Api` 的用戶端呼叫 API：`CrudApi`（共用的搜尋、單筆、存檔前檢查、新增、修改、啟用切換、刪除、還原、永久刪除、匯出）、`CategoryApi`（另有表單選項）、`TeamApi`（另有全部團隊、可選的上層團隊）。
  DTO 與畫面模型的對應放在 `CategoryDtoMapper`、`TeamDtoMapper`，WASM 頁面與伺服器的 Controller 共用。
- 批次刪除沿用共用的 `BatchDelete`，逐筆呼叫單筆刪除的 API（規則與每筆的稽核都和以前一樣）。
- 頁面權限改用 `PagePermissions`（`Permissions.CanAccessPage(...)`）；沒有權限開頁時的稽核（`Permission.Denied`，detail `via=WASM`）由伺服器在開頁紀錄 API（`POST /api/v1/shell/page-view`）依選單的權限鍵寫。

### 2. 分類、團隊的 API 改走服務

- `CategoryController`、`TeamController` 改呼叫 `CategoryService`、`TeamService`：團隊範圍、名稱規則、並行衝突、軟刪除與稽核和畫面只有一份。`CategoryRepository`、`TeamRepository` 已刪除（`ProjectRepository` 在 M4 刪除）。
- 新增端點（`/api/v1/Category`、`/api/v1/Team`，舊的 `/api/...` 一樣可用）：`PUT {id}/enabled`、`POST {id}/restore`、`DELETE {id}/purge`、`POST check`（存檔前檢查）、`POST export`（xlsx）；分類另有 `GET options`，團隊另有 `GET all`、`GET {id}/parent-candidates`。
- 搜尋多了 `Deleted`（顯示已刪除，要有刪除權限，否則 403）、`RecordSearch`（寫搜尋稽核）；`SortBy` 不分大小寫，也能用 `createdAt`。`GET {id}` 寫一筆查看稽核。
- `CategoryDto`、`TeamDto` 多了 `IsDeleted`、`DeletedAt`、`DeletedBy`。
- 修改時先確認資料在自己的團隊範圍內（範圍外 404），再比對名稱。
- 匯出超過 10000 筆回 400 並說明原因；匯出已刪除的資料要有刪除權限；寫匯出稽核。
- **錯誤訊息改成與畫面相同**（使用者確認沒有外部程式依賴舊訊息）；網址、HTTP 狀態碼與欄位沒變（團隊「還有下屬不可刪除」「改成已刪除團隊的名稱」仍回 400，非數字的 id 仍回 400）。
- 服務的結果多了失敗種類 `VerifyRecordResult.Kind`（`NotFound`、`Conflict`、`Invalid`、`Error`），Controller 以 `FromVerify` 轉成 404／409／400／500（500 依 `ExceptionDetailPolicy` 決定是否帶例外細節）；某個參數要更高權限時用 `ForbidUnless` 回 403。
  服務另外在新增後把 `Id` 與版本號寫回、清單可依啟用狀態篩選、可依建立時間排序。

### 3. 異動歷程與日期時間格式 API

- 新的 `AuditLogsController`（只限管理員）：`GET /api/v1/audit-logs/history`、`GET /api/v1/audit-logs/{id}/content`，給 WASM 頁每列的「異動歷程」對話窗用；稽核的寫法和 Server 版對話窗相同（打開時一筆搜尋、看內容時一筆查看）。不回傳伺服器上的檔案路徑。
- 瀏覽器內建的 zh-TW 時間格式和伺服器不同（「上午9:00:00」對「上午 09:00:00」），而且在 WASM 設定目前文化不影響畫面。
  新增不需登入的 `GET /api/v1/shell/culture`，WASM 啟動前讀一次（`ClientCulture`），清單的日期時間欄位一律指定 `Format="@ClientCulture.DateTimeFormat"`。
  Client 專案設 `BlazorWebAssemblyLoadAllGlobalizationData=true`：不論瀏覽器語言都是 zh-TW，下載量約多 1～2 MB（M12 實測）。

### 4. CRUD 頁共用元件搬到 Client 專案

- `ToolbarIconButton`、`CrudActionButton`、`BatchDeleteButton`、`FormSection`、`InputWatcher`、`FormDirtyTracker`、`FormModalFlow`、`FormEditConfirm`、`TeamBindingConfirm`、`TableSortHelper`、`BatchDelete`、`ViewNotification`、`ToastCopyButton`、`ToastCopyText`、`RequirePermission`、`AuditHistoryButton`、`AuditHistoryDialog` 搬到 `MyProject.Web.Client/Commons`，**命名空間不變**，Server 頁面照常使用；另新增 `AuditLogDisplay`、`FileDownload`、`TraceCodeText`、`IAuditHistorySource`。
- `PermissionRules` 搬到 `MyProject.Models`（命名空間不變，新增 `CanAccessPage`），`TagStringHelper` 搬到 `MyProject.Share`（命名空間不變）。
- 依賴伺服器的部分分開：`PagePermissions`（Server：`ServerPagePermissions`；WASM：`ClientPagePermissions`）、`IAuditHistorySource`（Server：`ServerAuditHistorySource`；WASM：`ApiAuditHistorySource`）。
- `ViewNotification` 不再綁 Server：以 `UseLoggerFactory`、`UseTraceCodeProvider` 設定。WASM 的追蹤碼是最近一次失敗的 API 回應的 TraceId（10 秒內有效、用一次就清掉）。
  M2 的 `ClientNotify` 拿掉，WASM 頁面的通知和 Server 版外觀相同（含「複製」按鈕）。

### 5. CRUD 產生器改產生 WASM 頁面

- `scripts/New-CrudModule.ps1` 只產生 WASM 頁面（使用者決定：沒有 Server 版選項，也不寫衍生專案舊 Server 版模組的轉換指南）：
  `Web.Client/Pages`、`Web.Client/Views`、`Web.Client/Api/<Name>Api.cs`（用戶端＋DTO 對應）、走服務的 Controller（上面全部端點，`-WithTeams` 另有 `GET options`）、API 測試 `<Name>ApiTests`（完整生命週期與稽核、409、匯出、403）。Repository 樣板已刪除。
- 登記：DI 錨點改為 `services.AddScoped<CategoryService>();` 之後（只登記服務）；不再改 `_Imports.razor`；新增在 `MyProject.Web.Client/Program.cs` 的 `builder.Services.AddScoped<TeamApi>();` 之後登記 `<Name>Api`。仍是 24 處登記，三種模組（一般、`-WithTeams`、`-AdminOnly`）的 `-CheckAnchors` 都通過。
- `scripts/Test-CrudGenerator.ps1` 加上瀏覽器實跑：在暫存 worktree 以 `Start-E2EHost.ps1` 啟動網站，用 `scripts/e2e/crud-generated.mjs` 對三個產生的頁面新增、修改、刪除、顯示已刪除、還原。需要 `PLAYWRIGHT_CORE_DIR`，`-SkipRealRun` 略過；暫時密碼經環境變數 `E2E_SUPPORT_PASSWORD` 傳遞（`Start-E2EHost.ps1` 讀不到參數時改讀它）。

### 6. 開發時要注意的兩件事

- WASM 清單的日期時間欄位一律指定 `Format="@ClientCulture.DateTimeFormat"`。
- AntDesign：WASM 頁面若先畫出表格、等權限或選項回來後才加上 `<Selection />`，之後釋放時 `Selection.Dispose` 會丟 `NullReferenceException`（畫面出現錯誤列）。決定勾選欄的權限與選項確定後才設 `isAccessChecked = true`。

### 7. 獨立審查

7 項發現全部修正並補測試：只有檢視權限的人能經 API 列出與匯出已刪除的資料、WASM 匯出被拒時顯示「驗證失敗」（以上 2 項中度）；存檔前檢查端點會透露資料是否存在且只要檢視權限、追蹤碼可能是舊的、讀不到表單選項時沒有提示、團隊部門樹匯出忽略啟用狀態條件、產生器實跑時暫時密碼出現在命令列（以上 5 項輕度）。
