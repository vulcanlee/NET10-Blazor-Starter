# 修好「登入存不住」：Data Protection 金鑰、強制登出放大器、Cookie 效期外部化（0.9.39）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：0.9.39
- 首次實作版本：0.9.39
- 最後核對日期：2026/09/19

## 為什麼

使用者回報：**有勾「記住我」，但隔一天沒用、關掉瀏覽器再開就被強制重新登入**，
本機與 IIS 兩邊都會。這與 0.9.38 剛寫進文件的「14 天滑動續期」直接矛盾。

矛盾本身就是線索：有勾記住我 ＝ 持久 Cookie ＋ 長票證，隔天被踢代表
**Cookie 根本沒被成功讀出來**，而不是過期。查下去找到兩個互相加乘的缺陷。

## 缺陷一：完全沒有設定 Data Protection 🔴

登入 Cookie 是用 ASP.NET Core Data Protection 的金鑰加密的。全 repo 對
`AddDataProtection`、`PersistKeysToFileSystem`、`SetApplicationName` **零命中** ——
金鑰走框架預設位置。後果：

- **IIS 的應用程式集區若未載入使用者設定檔，金鑰會退化成「只存在記憶體」**，
  每次回收就換一批（IIS 預設 20 分鐘閒置關閉、29 小時定期回收）→ **全站所有人被登出**。
  這就是「網站重啟後大家都要重新登入」的答案：**修正前，會。**
- `SetApplicationName` 沒設 → 判別子取自 content root 路徑，**換部署目錄也會失效**。

**修法**：新增 `AddConfiguredDataProtection`（比照既有的 `AddConfiguredCache` 寫法），
金鑰環固定寫到新設定鍵 `SystemSettings:ExternalFileSystem:DataProtectionKeyPath`
（預設 `C:\temp\MyProject\Keys`），並以 `MagicObjectHelper.DataProtectionApplicationName`
固定判別子。目錄比照既有六個路徑由 `EnsureDirectoryExists` 建立。

⚠️ Windows 上金鑰檔以 DPAPI 加密，**應用程式集區識別身分換掉一樣會解不開**；
多機部署必須共用金鑰目錄。這些已寫進部署檢查清單的新章節。

## 缺陷二：讀不到 Cookie 時，系統會把它「毀屍滅跡」🔴

`AuthenticationStateHelper.Check` 在「未認證」時導向 `/Auths/Logout`，
而那一頁會**無條件 `SignOutAsync` 刪掉 Cookie**。日誌裡每次都是同一個模式：

```
15:57:40  Application started
15:57:42  Authentication check failed ×3
15:57:42  User logout completed successfully   ← 持久 Cookie 被永久銷毀
```

於是 Cookie 只要有**任何一次**讀不到（重啟、金鑰不一致、換連接埠），
原本還有效的「記住我」就被永久毀掉，而且**症狀會自我延續** ——
下次回來一樣沒有 Cookie，一樣再演一遍。

**修法**：該分支改導向 `/Auths/Login`，不再主動清除。真正失效的 Cookie 由 Cookie
handler 自己清理，不需要我們動手。**其餘五個分支維持導向登出**
（`Sid` 無效／查無使用者／帳號停用／缺 `RoleView`／例外）—— 那些情況身分確實已失效。

✅ 不會產生重導迴圈：登入頁用 `NoFooterLayout`，而該版面不呼叫 `Check`。

## 缺陷三：Cookie 效期是隱形的（使用者原本問的）

`ExpireTimeSpan` 與 `SlidingExpiration` 都沒有設定，吃框架隱藏預設。

**修法**：新增 `CookieSettings` 區段（與 `JwtSettings` 平行，同樣
`ValidateDataAnnotations` ＋ `ValidateOnStart`）：

| 鍵 | 預設 | 說明 |
|---|---|---|
| `ExpireMinutes` | `480`（8 小時）| 沒勾記住我 |
| `RememberMeDays` | `30` | 勾了記住我 |
| `SlidingExpiration` | `true` | 滑動續期 |

⚠️ 兩種效期做不到只設一個鍵：`ExpireTimeSpan` 是整個 scheme 共用的，
所以 `RememberMeDays` 是在登入時以 `AuthenticationProperties.ExpiresUtc` 明寫覆蓋。

⚠️ **這是行為變更**：預設從隱形的 14 天改成明確的 8 小時／30 天。

⚠️ **單做這一項不會解決症狀** —— 問題從來不是「14 天太短」，是 Cookie 活不到 14 天。

## 其他

- `Login.razor.cs` 的硬編字串 `"CookieAuthenticationScheme"` 改用
  `MagicObjectHelper.CookieScheme` 常數（同檔其餘皆用常數，只有這裡是字面量）。
- `ApiIntegrationTests.CreateSettings()` 補上新路徑鍵 —— 否則整合測試會把金鑰環
  寫進開發者（或 CI）的真實目錄。這是 `日誌與設定檔說明 §4.6` 明文要求的。

## 測試

- 新增 `CookieSettingsTests`（5 條）：預設值有效、兩個 `[Range]` 邊界、
  以及「記住我的效期必須比一般登入長」。
- **改寫** `Check_WithUnauthenticatedPrincipal_...`：斷言導向登入頁而非登出頁，
  並在測試註解寫明**為什麼**，避免日後有人「修好」它而把缺陷改回去。
  其餘五個分支既有的「應導向登出」測試正好構成對照組。
- `dotnet test` **612 通過 / 0 失敗**。
- ⚠️ `DocumentationConventionTests` 如預期擋下「新增區段但兩份文件沒寫」，補完才轉綠。
