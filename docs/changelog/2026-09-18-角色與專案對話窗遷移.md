# 角色管理與專案項目對話窗遷移完成，並訂正 scoped CSS 的說法（0.9.27）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：0.9.27
- 首次實作版本：0.9.27
- 最後核對日期：2026/09/18

## 為什麼改

0.9.25 訂出表單對話窗規範時，範圍只涵蓋使用者管理（示範頁）、分類清單與團隊清單；
角色管理與專案項目留在 `FormModalConventionTests.PendingMigrationViews` 當作已知技術債。
這次把它們補齊，守門規則從此涵蓋全部五個 CRUD 檢視。

## 改了什麼

### `RoleViewView`（角色管理）

- `Class="form-modal"`、`MaskClosable="false"`、未儲存二次確認、儲存前確認。
- 欄位分兩個區塊：
  - **角色資料**：名稱（2 欄）、預設團隊（多選，獨占整行）
  - **權限設定**：`SingleColumn` —— 權限矩陣本身就是二維排列，再塞進半欄會變成三層巢狀。
- 移除原本多餘的巢狀 `<FormItem>` 包裝。

### `ProjectViewView`（專案項目）

- 同上，另加 `UploadStateFingerprint()`：待上傳與待刪除的檔案不在 `ProjectAdapterModel` 裡，
  不納入變更偵測的話，「只加了檔案、沒動欄位」會被判定為無變更而直接關窗。
- ⚠️ 取消流程調整：檔案清單只能在**確定要關窗之後**才清掉，
  否則使用者選「繼續編輯」會發現選好的檔案不見了。
- 欄位分四個區塊：
  - **基本資料**：標題、負責人（2 欄）、描述（獨占整行）
  - **排程與進度**：開始日期、結束日期、狀態、優先級、完成百分比
  - **分類與團隊**：兩個多選，各獨占整行
  - **專案附件**：`SingleColumn` —— 檔案清單是縱向的，橫向切一半只會兩邊都不好讀

### 清理

- `OverlayStyles.razor` 移除已無人使用的 `.role-view-modal` / `.project-view-modal`（約 1 KB 死 CSS）。
- `FormModalConventionTests.PendingMigrationViews` 清空。

## 訂正：scoped CSS 打不到 Modal 內容 —— 這個說法不精確 ⚠️

專案長期相信（0.9.25 的紀錄也這樣寫）：「AntDesign 會把 Modal 內容渲染到元件 DOM 範圍之外，
scoped CSS 都打不到。」

這次遷移權限矩陣時實際查證了產生的 Razor C#，結論是**這個說法只對一半**：

```csharp
// RoleViewView_razor.g.cs —— <Modal> 內容裡的 div 仍然拿到了 scope 屬性
__builder6.AddAttribute(163, "class", "role-permission-group");
__builder6.AddAttribute(164, "b-sf8x6goptk");
```

- **檢視自己在 `.razor` 裡寫的元素會拿到 scope 屬性**，即使位於 `<Modal>` 內容中。
  因此 `.role-permission-group` 這類純自有 markup 的規則留在該檢視的 `.razor.css` 是**正確且有效**的。
- **真正打不到的**是 AntDesign 自己渲染的元素（`.ant-modal-*`、`.ant-form-item`、`.ant-btn`…）——
  它們不帶檢視的 scope 屬性；`::deep` 同樣無效，因為它編成 `[b-hash] 後代`，
  而 modal 的外框是 AntDesign 渲染的，沒有那個屬性。

連帶訂正：0.9.25 的紀錄說 `MyUserView` 的 `.my-user-password-hint`
「從來沒有生效過」——**那是錯的**，它一直有效。改用全域 `.form-field-hint` 本身仍然合理
（讓各檢視的欄位提示長得一樣），但當時給的理由不成立。

[開發慣例與限制速查](../architecture/開發慣例與限制速查.md) §6.4、
`FormSection.razor` 與 `OverlayStyles.razor` 的註解、以及 0.9.25 的變更紀錄。
