## 目的

[路線圖](../planning/00-腳手架強化路線圖.md) C-12（第 2 批第二項）。改動前只有 `TotpService` 骨架與 `MyUser.TwoFactorEnabled`／`TwoFactorSecret` 欄位，沒有設定畫面、登入流程也不檢查。

使用者決定：

- 自選開啟＋依角色強制，另有系統參數「管理員必須使用」；support 不受強制。
- Google 建立、沒有本機密碼的帳號不問；但**帳號已開啟時 Google 登入也要第二步**。
- QRCoder 產生 QR；10 組備用碼、管理員重設、記住這台裝置 30 天、同一組驗證碼不能重複使用。
- 驗證碼輸錯計入與密碼相同的鎖定次數。

## 二、設計決定

| 決定 | 理由 |
|---|---|
| 密碼對了但還沒過第二步不歸零失敗次數 | 否則知道密碼的人每猜幾次驗證碼就重輸一次密碼，次數永遠到不了門檻 |
| 防重放用條件式 UPDATE（`TwoFactorLastStep < step`） | 「先查再寫」在並行請求下會讓同一組碼用兩次 |
| 已開啟的帳號 Google 登入也要第二步 | Google 會自動連結同 Email 的既有帳號；不問的話，管理員的兩步驟驗證可以改用 Google 繞過 |
| 待驗證狀態放在加密 Cookie，不放網址或表單 | 不讓人改使用者 Id；5 分鐘到期；送出時重查工作階段版本 |
| 「記住裝置」綁定工作階段版本 | 改密碼、強制登出、重設之後，原本記住的裝置要重新驗證 |
| 密鑰以 Data Protection 加密 | 資料庫單獨外流時拿不到密鑰；代價是金鑰環遺失要逐一重設（support 不受強制，是救援入口） |
| 重新產生與停用的錯誤不計入鎖定 | 那時已經登入，鎖定只防登入時的猜測 |
| 角色強制不換工作階段版本 | 不需要把人踢出去；下一次換頁就會被帶到設定頁 |
| QR 用 `PngByteQRCode` | 不依賴 System.Drawing（Windows 以外的平台與新版 .NET 都不支援） |
| API 對「必須使用卻還沒設定」直接拒絕 | API 沒有地方設定；放行等於可以用 API 繞過強制 |

## 四、實機驗證

Playwright＋Edge，所有外部路徑與日誌隔離到暫存目錄；沿用上一版的資料庫（啟動時套用 `AddTwoFactorBackupCodes`）。驗證碼由腳本依頁面顯示的金鑰計算：

- erin 從個人資料頁開啟：QR 為 PNG；錯碼提示「驗證碼不正確。請確認手機時間正確…」；正確後顯示 10 組備用碼，按「我已保存，繼續」回到個人資料頁仍是登入狀態並顯示「已啟用」；另一個瀏覽器下一次換頁回到登入頁。
- 重新登入：密碼後進入 `/Auths/TwoFactor`；錯碼留在原頁並顯示固定訊息；正確碼進入首頁；同一組碼在另一個瀏覽器再用被拒；去掉橫線、小寫的備用碼可用，同一組再用被拒；勾「記住這台裝置」後登出再登入直接進首頁。直接開 `/Auths/TwoFactor` 回到登入頁。
- API：不帶碼 401「需要兩步驟驗證碼。」、錯碼 401、正確碼取得 token。
- 管理員：erin 那一列有「兩步驟驗證」徽章與「重設兩步驟驗證」，support 那一列只有「修改」；對 erin 強制登出後，原本記住的裝置又要第二步；重設後徽章消失，erin 只用密碼登入。
- 角色「通知角色」勾「需要兩步驟驗證」：carol 登入後落在設定頁並看到說明框，換頁或重新整理任何頁面都回到設定頁；她的 API 登入被拒「請先在網頁完成兩步驟驗證設定。」。
- 已開啟畫面：剩餘備用碼數；以備用碼確認重新產生 10 組；以驗證碼停用後回到個人資料頁仍是登入狀態、顯示「未啟用」。
