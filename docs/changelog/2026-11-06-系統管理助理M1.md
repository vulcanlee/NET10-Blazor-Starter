## 目的

管理員查一個問題，常要在健康監控、日誌、例外、排程紀錄之間來回切換。「系統管理助理」在系統管理底下提供單一對話入口：每則訊息先自動判斷屬於哪個領域，再交給對應的專家，由專家用工具查資料後回答。
完整需求與後續里程碑見 [系統管理助理 PRD](../prd/系統管理助理-prd.md)；這一版是里程碑 1：骨架、分派，以及監控與診斷、排程的唯讀工具。

## 一、新頁面「系統管理助理」

- 路由 `/admin-assistant`，選單「系統管理 › 管理助理 › 系統管理助理」（新子分類 id 10、頁面 id 101，圖示 `support_agent`、`assistant`）。
- **只限管理員**：`CheckIsAdmin()`；權限鍵 `角色_管理助理`、`角色_系統管理助理` 不放進角色矩陣（`AdminOnlyPermissionTests` 守門）。
- 版面與互動沿用 Agent 測試台：「我的對話」（保存、接續、重新命名、刪除）、逐段顯示、停止產生、核准窗。另外有兩處不同：
  - 每則 AI 回覆上方標示「由 某某 回答」。
  - 空白對話時顯示 5 個範例問句，點一下就填進輸入框。剛送出時進度顯示「分派中」。
- 操作說明 `Datas/Help/admin-assistant.md`。

## 二、執行器支援「每輪規劃」

- 新增 `IAiAgentTurnPlanner` 與 `AiAgentTurn`（`Ai/Agents/AiAgentTurn.cs`）。`IAiAgentRunner` 多了 `StartAsync(planner)`、`ResumeAsync(planner, id)` 兩個方法。
- 每次 `SendAsync` 前，先由規劃器決定這一輪的定義、提示詞與標籤，再用同一個 `ConversationId` 重建 agent。**MAF session 不換**，所以前後文會延續。
- 核准回覆（`RespondAsync`）不重新規劃。每一輪的定義名稱必須等於 `Home.Name`，否則丟出例外。
- 規劃器的 `Home` 含全部工具，接續對話時用它還原，待核准的工具才找得到。
- 沒有規劃器時（Agent 測試台）行為完全不變，原有測試全部通過。

## 三、分派與組裝

- `AdminAssistantTurnPlanner` 每則訊息先呼叫一次模型，回覆英文代碼 `accounts, monitoring, ai, ops, patrol`。分派失敗或讀不出代碼時，退回「全部領域」。
- 唯讀工具**每一輪都全部載入**，所以分派漏選某個領域也查得到資料。分派只決定三件事：套用哪些領域的說明、載入哪些異動工具（這一版還沒有異動工具）、顯示哪個「由誰回答」標籤。
- 提示詞分成 6 段，都可以在「AI 提示詞」頁修改：管理助理／共同、分派、帳號與權限、監控與診斷、AI 管理、設定與維運。
  新增的 `IAiSystemPromptProvider.GetInstructionsAsync` 取出各段時不含固定規則，組好之後只接一次固定規則。
- 模型：`AiModelSettings:AdminAssistant`、`AiModelSettings:AdminAssistantRouter`（空白時沿用 AdminAssistant），可在系統參數的「AI 模型」設定。
- Token 用量作業名稱：「系統管理助理」、「系統管理助理（分派）」。

## 四、第一批唯讀工具（8 個）

| 工具 | 權限（原頁面的管理員專屬鍵） | 稽核 |
|---|---|---|
| `get_system_health` 系統健康報告 | 系統健康監控 | 不寫（頁面也不寫）；說明中註明會做一次 AI 探測並登入 SMTP |
| `query_logs` 查詢日誌 | 日誌檢視 | `LogViewer.Search`，`source=admin-assistant` |
| `get_log_level` 查看日誌等級 | 日誌等級設定 | 不寫 |
| `search_exceptions` 查詢系統例外 | 系統例外紀錄 | `ExceptionLog.Search`，`source=admin-assistant` |
| `get_exception_detail` 查看例外堆疊 | 系統例外紀錄 | `ExceptionLog.View`，`source=admin-assistant` |
| `get_database_usage` 資料庫用量 | 資料庫用量 | 不寫 |
| `get_scheduled_jobs_overview` 排程總覽 | 排程作業 | 不寫 |
| `get_job_recent_runs` 排程執行紀錄 | 排程作業 | 不寫 |

- 參數不合法時不丟例外：時間解析不了就用預設區間，筆數超出範圍就夾住，排程名稱不存在就列出可用的名稱，並在回覆中說明實際套用了什麼。
- 長文字一律截斷：日誌訊息 500 字、例外訊息 300 字、堆疊 4000 字。
