# 登入後首頁改為系統品牌介紹頁（0.9.9）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：0.9.9
- 首次實作版本：0.9.9
- 最後核對日期：2026/09/16

## 起因

使用者的原話：

> 我想要修正首頁的頁面內容，需要設計一個靜態內容，顯示出這個產品的名稱與相關說明，
> 也需要包含這個系統的商品圖片，也就是說，當使用者第一次進入這個系統的時候，
> 可以看到關於這個系統的品牌設計資訊與關於這個系統的介紹。

登入後首頁 `/App`（`HomeAuthed.razor`）原本直接渲染 `<ProjectViewView/>`，
與側邊選單「專案管理 → 專案項目」指向的 `/projects`（`ProjectPage.razor`）**渲染同一個檢視** ——
同一份專案清單掛在兩個路由上，使用者登入後第一眼看到的是一張資料表格，
完全沒有任何關於這個系統是什麼的訊息。

## 決策

討論後確定的範圍：

| 決策點 | 結論 |
|---|---|
| 改哪一頁 | **`/App`（登入後首頁）**；`/`（`Home.razor` → `SplashView`）的過場與自動跳轉維持不動 |
| 商品圖片 | 沿用現有 `wwwroot/images/brand-logo.png`，不新增圖檔 |
| 內容區塊 | Hero ＋ 能力卡片 ＋ 快速入口 ＋ 系統資訊，四塊全做 |
| 文案管理 | **寫死在 `.razor.cs`**，比照上手指南 §7.6「設計文案刻意不參數化」的既有慣例 |
| 權限 | 沿用選單 id=1 的權限鍵 `MagicObjectHelper.角色_首頁` |

刻意不做：不動 `Menu.json`、`MenuPermissionMap`、`MagicObjectHelper`（id=1 與 `角色_首頁` 都已存在），
不動 `/projects`，不新增任何 `appsettings.json` 設定鍵。

## 變更內容

### 1. 新增 `HomeWelcomeView`

`src/MyProject/MyProject.Web/Components/Views/Commons/` 下新增三個檔案
（與 `SplashView` 同目錄；**必須放在 `Components/Views/` 之下**，
否則 `MenuPermissionConsistencyTests.FindViewPath` 找不到檔案）：

- `HomeWelcomeView.razor` —— 四個區塊的靜態標記。
- `HomeWelcomeView.razor.cs` —— 權限檢查、能力卡片與快速入口資料。
- `HomeWelcomeView.razor.css` —— CSS isolation，配色沿用 `SplashView.razor.css`。

權限檢查比照 `ProjectViewView.OnInitializedAsync` 的樣板：先 `AuthenticationStateHelper.Check`，
再 `CheckAccessPage(MagicObjectHelper.角色_首頁)`，不通過就填 `RoleMessage` 並停止渲染內容。
品牌與版本一律由 `IOptions<SystemSettings>` 取得，未新增任何設定類別。

快速入口以同一支 `CheckAccessPage` 過濾：

```csharp
quickLinks = [.. AllQuickLinks.Where(x => AuthenticationStateHelper.CheckAccessPage(x.PermissionKey))];
```

### 2. `HomeAuthed.razor`

`<ProjectViewView/>` 改為 `<HomeWelcomeView />`；
順手把範本殘留的 `<PageTitle>Home</PageTitle>` 改成「首頁」（上手指南 §7.5 已列此為待修項）。
頂部列標題不需改 —— `MainLayout.UpdateCurrentPageTitle` 以路徑比對 `Menu.json`，
`/App` 自動取到 id=1 的「首頁」。

### 3. 守門測試

`MenuPermissionConsistencyTests.ViewToMenuId` 新增 `["HomeWelcomeView.razor.cs"] = 1`，
讓「四方一致」的第四方（檢視實際呼叫的權限鍵）也被納管。

## 踩到的坑：圖示名稱

⚠️ 能力卡片的圖示第一版用了 `shield_person`，實跑後發現它**被拆成「盾」與「人」兩個圖示**，
一起撐破了 2.75rem 的圓角容器 —— 因為 `App.razor` 載入的是 **classic Material Icons**，
而 `shield_person` 是 Material Symbols 專有名稱。

值得注意的是 `Menu.json` 也用 `shield_person`（角色管理），側邊欄之所以正常，
是因為 `NavMenu.GetMaterialIconKind` 與 `SidebarMenuNode.GetMaterialIconKind`
都有一條 `"shield_person" => "security"` 的映射把它換掉了。
`MenuIconTests.AllowedIcons` 只是一份人工維護的字串清單，**驗不出字型裡有沒有這個字**。

本頁不經過那層映射，因此直接寫 `security`。新增卡片時請實際開頁確認圖示有渲染出來。
