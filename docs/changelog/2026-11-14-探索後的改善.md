# 探索後的改善（0.10.17）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：0.10.17
- 首次實作版本：0.10.17
- 最後核對日期：2026/11/14

## 目的

[.NET 11 全面實機探索](2026-11-14-NET11全面實機探索.md)（0.10.16）找到 5 項既有行為（.NET 10 也一樣）會改變使用者看得到的操作，依約定先請使用者決定。使用者 2026/11/14 決定全部改善。

## 變更內容

### 1. 首頁不受權限限制

- 以前角色沒有勾「首頁」時，使用者一登入看到的第一個畫面就是「你沒有權限存取此頁面」，側邊欄也沒有「首頁」。
- 改成每個登入的人都能開首頁（`PermissionRules.OpenToEveryone`）：首頁畫面、側邊欄的「首頁」、首頁儀表板的 API（改 `[SignedInUser]`）。儀表板裡的小工具與快速入口照舊依各自權限（排程作業只限管理員）。
- 角色管理的權限表**拿掉「首頁」勾選框**（使用者決定）：勾不勾都一樣，留著會讓人以為能擋。既有角色存著的「首頁」權限鍵留著無妨。

### 2. 清單的搜尋框按 Enter 就搜尋

- 專案、分類、團隊、使用者、角色的搜尋框，以及 CRUD 產生器產生的頁面：按 Enter 等於按「搜尋」。以前按 Enter 沒有反應。

### 3. 專案標題上限 200 字

- 以前沒有上限（5,000 字也存得進去；分類、團隊名稱上限 100）。畫面的輸入框最多 200 字，伺服器在新增或改標題時也檢查，API 回 400「專案標題長度不可超過 200 字元。」。以前存下的長標題只改其他欄位時照常可存（獨立審查提醒）。

### 4. 帳號格式

- 帳號只能用英文字母、數字與 `- _ . @`。以前含空白與 HTML 字元也能建立。
- 只在新增或改帳號時檢查：既有帳號（例如 Google 登入以 Email 建立、含 `+` 的）不改帳號時照樣能存。新增使用者時帳號欄位會立刻提示格式；API 回 400「帳號只能使用英文字母、數字與 - _ . @。」。

### 5. 手機版收合的側邊欄變薄

- 手機寬度（≤ 640px）時，收合的側邊欄以前仍佔約 220px 高的深色區塊（品牌文字被擠成直排），使用者選單被擠到下一行。
- 改成收合時只留選單鈕、浮在頁首列左側，頁首只有一列（選單鈕＋通知＋使用者選單）；展開時照舊是整片選單。桌機不受影響。

## 測試

- 新增 `HomeOpenToEveryoneTests`、`Client/ListSearchEnterConventionTests`；`DashboardApiTests` 改成「沒有首頁權限也能開」、`ProjectApiTests` 補標題上限（含舊的長標題不改標題照常可存）、`UserApiTests` 補帳號格式（含既有帳號不受影響）；`RbacBackfillServiceTests` 改用矩陣裡還有的權限鍵當範例。
- 實機：`explore-perm`（低權限角色沒有「首頁」也開得起首頁）、`explore-lists`（按 Enter 搜尋）、`explore-input`（I10 標題上限、I12 帳號格式、I16 帳號欄位即時提示）、`explore-edge`（E4 手機版頁首只有一列）。

## 升版注意

- 版本號 0.10.16 → 0.10.17。沒有資料庫異動、沒有設定異動。
- 呼叫 Web API 的外部程式：新建或改名的帳號不合格式、專案標題超過 200 字時回 400；首頁儀表板 API 不再需要「首頁」權限。
- 衍生專案：自己加的清單搜尋框要有 `OnPressEnter`（`ListSearchEnterConventionTests` 會提醒）。
