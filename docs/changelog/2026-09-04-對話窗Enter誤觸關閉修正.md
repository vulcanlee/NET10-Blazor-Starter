# 修正對話窗內按 Enter／Shift+Enter 誤觸關閉（0.9.3）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：0.9.3
- 首次實作版本：0.9.3
- 最後核對日期：2026/09/04

## 症狀

五個 CRUD 維護對話窗（使用者、角色、分類、團隊、專案）中，只要焦點停在對話窗內的
任何元件上按下 **Enter 或 Shift+Enter**，就會立刻存檔並關閉對話窗 —— 使用者的資料
輸入通常還沒完成。

受影響的不只多行文字與下拉：

| UI | 位置 | 按 Enter 的實際結果 |
|---|---|---|
| `TextArea` 多行文字 | 分類／團隊／專案的「描述」 | 無法換行，直接存檔關窗；Shift+Enter 亦然 |
| `Select` 下拉（含多選、可搜尋）| 角色／團隊／分類／狀態／優先級 | 選取選項後順便存檔關窗 |
| `Input`／`Input Password` | 全部檢視 | 存檔關窗（原設計意圖，但常在填到一半誤觸）|
| `DatePicker` | 專案的開始／結束日期 | 確認日期後順便關窗 |
| `InputNumber` | 專案的完成百分比 | 提交數值後順便關窗 |
| `Checkbox`／`Switch` | 使用者的啟用／管理員、角色權限矩陣、分類／團隊的啟用 | 焦點在上面按 Enter 就關窗 |
| `InputFile` | 專案附件 | 開啟檔案對話框**同時**關窗 |
| `CrudActionButton`（移除待上傳檔案）| 專案 | 移除檔案後順便存檔關窗 |

Escape 也過度攔截：下拉展開時按 Esc 應只收合下拉，卻會關掉整個對話窗、丟棄已輸入的內容。

## 原因

`@onkeydown` 掛在 `<EditForm>`（渲染成 `<form>`）上，而 keydown 會從表單內**任何**
子元素冒泡上來：

```razor
<EditForm Model="@CurrentRecord" Context="editContext" @onkeydown="OnModalKeyDownAsync">
```

```csharp
if (args.Key == "Enter")            // 未檢查 ShiftKey，Shift+Enter 完全等同 Enter
{
    await Task.Delay(200);          // 等 @bind-Value 回寫模型的競態 hack
    await OnModalOKHandleAsync(new MouseEventArgs());
}
else if (args.Key == "Escape" || args.Key == "Esc")
{
    await OnModalCancelHandleAsync(new MouseEventArgs());
}
```

三個關鍵事實：

1. **AntDesign 的 overlay 攔截幫不上忙**：`ant-design-blazor.js` 的 `preventKeyOnCondition`
   只呼叫 `preventDefault()`，**沒有 `stopPropagation()`**，所以「`Select` 按 Enter 選取選項」
   之後事件照樣冒泡到 form。
2. **`KeyboardEventArgs.Key` 對 Enter 與 Shift+Enter 都回傳 `"Enter"`**，只比對 `Key`
   會讓「TextArea 換行」這個標準手勢變成存檔關窗。
3. **`Task.Delay(200)` 是競態 hack**：keydown 早於 change 事件，這 200 毫秒是在等
   `@bind-Value` 回寫模型。Blazor Server 走 SignalR，網路稍慢就會存到舊值。

`MainLayout` 的「變更密碼」「關於」對話窗未掛 `@onkeydown`，不受影響。

## 修正

- 五個檢視的 `<EditForm>` 移除 `@onkeydown`，並整段刪除 `OnModalKeyDownAsync`
  （`Task.Delay(200)` 競態一併消失）：
  `MyUserView`、`RoleViewView`、`CategoryViewView`、`TeamViewView`、`ProjectViewView`。
- `<Modal>` 的 `Keyboard="true"`、`OnOk`、`OnCancel` 維持不動 —— 存檔的唯一入口是
  「確定」按鈕，Escape 由 AntDesign Modal 統一處理（下拉／日期面板展開時會先被該元件消化）。
- 新增守門測試 `MyProject.Tests/ModalKeyboardConventionTests.cs`：掃描
  `Components/**/*.razor`，`<EditForm>`／`<form>` 帶 `@onkeydown`／`@onkeyup`／`@onkeypress`
  即失敗。

> 綁定安全性：`@bind-Value` 在 change／blur 才回寫，滑鼠點「確定」會先讓欄位 blur，
> 這是既有且正常運作的路徑（見 [2026-07-09-階段四UI實跑驗收](2026-07-09-階段四UI實跑驗收.md)）。
> 移除 Enter 路徑後不再有「焦點還在欄位就送出」的情況。

## 行為變更（需告知使用者）

**對話窗內按 Enter 不再送出。** 存檔一律按「確定」按鈕。這是刻意的取捨：先前的 Enter
捷徑在多行文字、下拉、日期、數字、勾選等元件上全都是誤觸來源，代價遠大於便利。

DatePicker／InputNumber 內 Enter 不關窗、下拉展開時 Esc 只收合下拉、點「確定」正常驗證與存檔。
