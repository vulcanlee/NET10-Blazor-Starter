- 文件版本：1.0
- 文件狀態：已實作

## 目的

WASM 遷移的第六個里程碑（計畫見 [WASM 遷移計畫](../migration/WASM遷移計畫.md)）：「日誌檢視」（`/logs`，含 AI 日誌分析）、「日誌等級設定」（`/log-level-setting`）、「系統例外紀錄」（`/system-exceptions`，含 AI 例外分析與追問）、「AI 對話紀錄」（`/ai-call-logs`）、「Token 用量」（`/token-usage`）、「AI 提示詞」（`/prompt-templates`）改在使用者的瀏覽器以 WebAssembly 執行，背後是新的只限管理員的 Web API。
同時建立 AI 逐字顯示的串流基礎（NDJSON，不用 SignalR），並修正 WASM 頁面被伺服器限流時把人丟回登入頁的問題。其他頁面維持原狀。
測試報告見 [M06-AI串流日誌與AI管理頁](../migration/測試報告/M06-AI串流日誌與AI管理頁.md)。

## 變更內容

### 1. 六個頁面改用 WebAssembly

- 頁面與檢視搬到 `MyProject.Web.Client`（`Pages/LogViewerPage.razor`、`LogLevelSettingPage.razor`、`ExceptionLogPage.razor`、`AiCallLogPage.razor`、`TokenUsagePage.razor`、`PromptTemplatePage.razor`，`Views/Analytics/*`、`Views/Admins/*`，含 AI 例外分析窗與 AI 對話紀錄明細窗），Server 版已刪除。畫面、按鈕、對話窗與訊息和以前相同。
- 資料經 `Web.Client/Api/ExceptionLogApi.cs`、`LogApi.cs`、`AiCallLogApi.cs`、`TokenUsageApi.cs`、`PromptTemplateApi.cs` 呼叫 API；DTO 與畫面模型的對應在 `ExceptionLogDtoMapper`、`AiCallLogDtoMapper`、`TokenUsageDtoMapper`。DTO 在 `MyProject.Dtos/Admins` 與 `MyProject.Dtos/Ai`。
- 搬到 Client 共用（命名空間 `MyProject.Web.Ai` 不變）：`AiMarkdownRenderer`（Client 參考 Markdig）、`AiInterruption`、`AiTokenUsage`（新增 `ToDisplayText`、`FromDto`／`ToDto`）、`TokenUsageTrendChart`、`TokenUsageReportScope(s)`、`AiCallLogText`；`TokenUsageFormat` 在 `MyProject.Web.Client/Diagnostics`，`LogLevelRank`／`LogLevelRankHelper`／`LogTimeRanges` 在 `MyProject.Web.Client/Diagnostics/LogLevels.cs`；`ExceptionLogClipboardText` 命名空間改為 `MyProject.Web.Client.Views.Admins`。
- 目前以 WebAssembly 執行的頁面共 14 個：`/Profile`、`/categories`、`/teams`、`/projects`、`/myusers`、`/roleviews`、`/audit-logs`、`/email-logs`、`/logs`、`/log-level-setting`、`/system-exceptions`、`/ai-call-logs`、`/token-usage`、`/prompt-templates`。

### 2. AI 逐字顯示改用 NDJSON 串流

- **格式**：`MyProject.Dtos/Ai/AiStreamDtos.cs` 的 `AiStreamFrameDto`，每行一筆，`Kind` 依序是 `start`（帶 `AiStreamScopeDto`）、`delta`（帶 `Text`）、最後一定是 `result`（帶 `AiResultDto`）；另有 `AiUsageDto`、`AiChatMessageDto`。伺服器端轉換在 `MyProject.Web/Ai/AiStreamFrames.cs`。
- **伺服器**：`MyProject.Web/Streaming/NdjsonResult.cs`，`application/x-ndjson; charset=utf-8`、關閉回應緩衝、每行 flush、`Cache-Control: no-cache, no-transform`、`X-Accel-Buffering: no`。使用者中斷後不再寫出，但**序列照樣讀完**，收尾的稽核與用量記帳一定執行。
- **`AiStreamGuard`**（`MyProject.Web/Ai/AiStreamGuard.cs`，獨立審查後新增）：保證最後一定有一筆結果。取消例外 → 「已取消」（稽核照寫）；其他例外 → 記錯誤日誌、「未預期的錯誤」、不寫稽核（同 Server 版）。
- **WASM**：`ApiClient.StreamAsync<T>(url, body, onItem, ct)`，帶 Token、401 時刷新後重送一次、強制改密碼／兩步驟的 403 整頁導走、伺服器拒絕時回一般 `ApiResult`、只有標頭受 100 秒逾時、取消時回失敗不丟例外。
- **停止產生／關窗＝中斷請求**：伺服器的 `RequestAborted` 取消上游 AI 呼叫（計費與「已取消」紀錄的行為不變）。畫面收不到伺服器最後那筆結果，用已收到的文字自己收尾（加「已中止」註記），所以**停止後對話窗資訊不顯示模型與用量**（伺服器的稽核與用量紀錄仍完整）。
- **IIS**：`application/x-ndjson` 不在 IIS 動態壓縮的預設類型內；`web.config` 加註解：主機若把它（或 `*/*`）加進 `dynamicTypes`、或前面有會緩衝的反向代理，AI 回覆會變成一次出現，請排除。部署檢查見 [正式部署與安全檢查清單](../operations/正式部署與安全檢查清單.md)。

### 3. 只限管理員的 Web API

全部只有 `api/v1` 路由、要 Bearer、標 `[AdminOnly]`（非管理員 403 並寫 `Permission.Denied`）、套 `[ApiValidationFilter]`、回 `ApiResult`；時間是伺服器本地時間、不帶時差。端點細節見 [Web API 端點目錄](../architecture/Web%20API%20端點目錄.md) 第二之二節。

- **`api/v1/exception-logs`**（`ExceptionLogsController`）：`POST search`（`RecordSearch` 才寫 `ExceptionLog.Search`）、`GET options`（清除天數、上限、AI 是否可用與原因、追問輪數上限）、`GET {id}`（明細與堆疊，寫 `ExceptionLog.View`）、`GET {id}/stack-trace`（點列複製）、`POST copy-text`（複製目前查詢結果）、`POST export`（CSV）、`DELETE {id}`、`POST purge`、`POST clear-all`、
  `POST {id}/ai`（NDJSON；畫面送 `ConversationId` 與之前的問答，伺服器以資料庫與堆疊檔重建第一則例外明細與 system 提示；檢查角色交替、追問 ≤ 2,000 字、回覆 ≤ 512K 字、輪數 ≤ 上限；稽核 `AiAnalyze`／`AiFollowUp`）、`POST {id}/ai/pdf`（伺服器補例外明細與堆疊，寫 `AiExportPdf`）。
- **`api/v1/logs`**（`LogsController`）：`POST search`（快速區間 `last5m`／`last15m`／`last1h`／`today` 或預設最近 1 小時，「現在」由伺服器算；回實際起訖寫回畫面、警告）、`POST export`（`.log`，UTF-8 含 BOM，伺服器依同條件重查）、`POST ai`（NDJSON；伺服器依同條件重查、取最新 `MaxEntries` 筆；`start` 帶範圍）、`POST ai/pdf`（伺服器重建 prompt 當附錄）、`GET options`。
- **`api/v1/log-level`**（`LogLevelController`）：`GET`、`POST apply`（稽核 `LogLevel.Apply`「由 X 調整為 Y（僅執行期有效）」）、`POST restore`。
- **`api/v1/ai-call-logs`**（`AiCallLogsController`）：`POST search`（內文關鍵字由伺服器逐檔掃描，可取消；搜尋稽核寫在掃描前）、`GET options`、`GET by-call/{callId}`（深連結）、`GET {id}`（明細，每段只送前 20 萬字元）、`GET {id}/text?part=`（複製被截斷的段落時取全文）、`POST {id}/raw`（完整 JSON）、`POST {id}/pdf`、`POST merged-pdf`（`selected`／`conversation`／`query`，最多 50 筆）、`POST export`（CSV 不含內文，上限 10000）、`DELETE {id}`、`POST purge`、`POST clear-all`。
- **`api/v1/token-usage`**（`TokenUsageController`）：`POST dashboard`（明細一頁、合計、4 種分組、每日（補零、最多 180 天）、近 1／7／30 天卡片、用量上限文字，「今天」用伺服器時間）、`GET options`、`GET {id}`（原始 usage 平攤、費率快照、對話紀錄是否存在）、`POST export`（CSV）、`POST export-pdf`（全部或單一頁籤）、`DELETE {id}`、`POST purge`、`POST clear-all`。
- **`api/v1/prompt-templates`**（`PromptTemplatesController`）：`GET`（16 個種類的標題、版本、內建預設、固定附加規則）、`POST {key}/versions`（樂觀鎖衝突 409；建立者由伺服器取目前帳號；寫 `Prompt.Update`）、`POST {key}/activate`（寫 `Prompt.Activate`）。分頁標題搬到伺服器的 `MyProject.Web/Ai/PromptTemplateTitles.cs`（與系統管理助理的提示詞工具共用）。
- 「刪除選取」照 M5 由畫面逐筆呼叫 `DELETE {id}`（每筆一列稽核），沒有批次刪除端點。
- CSV 欄位定義搬到 `MyProject.Web/Export/`：`ExceptionLogExport`、`AiCallLogExport`、`TokenUsageExport`。`AiCallLogService`、`TokenUsageLogService`、`PromptTemplateService` 的失敗標上種類（404／409／400／500）。

### 4. 例外 AI 對話：畫面送回問答，伺服器重建明細

遷移分析報告原本寫「對話存伺服器快取」，實作改為**畫面送回問答、伺服器重建例外明細與系統提示**：伺服器無狀態、不怕 IIS 回收，畫面也改不到例外內容與系統提示。例外 PDF 匯出不再受追問輪數上限限制（對話途中調低上限仍可匯出）。

### 5. 被伺服器限流時不再登出

被伺服器限流（429）時，WASM 不再把人丟回登入頁，改在外框顯示「請求過於頻繁，請稍後再試。」與「重新整理」按鈕（`ClientSession.IsThrottled`／`ThrottledMessage`；`ApiClient` 在刷新被限流時回 429 訊息）。這是 M2 就有的行為，M6 實機才發現（煙霧測試一分鐘內整頁載入二十幾個 WASM 頁）。

### 6. 與 Server 版不同、使用者看得到的地方

- **排序修正**：系統例外（最後發生、次數）、AI 對話紀錄（送出時間、耗時、送出字元）、Token 用量明細（時間、費用）的排序現在依點選方向生效，匯出、複製、PDF 與畫面同一個順序（Server 版比對 `ascend`／`descend`，AntDesign 給的是 `Ascending`／`Descending`，從未生效）。
- 停止產生後對話窗資訊不顯示模型與用量（見第 2 節）。直接離開頁面造成的取消，伺服器也會記 AI 分析稽核（Server 版因電路已收掉而不記）。
- Token 用量 PDF 由伺服器依同條件重查（查詢與匯出之間有新紀錄時數字可能多幾筆）。
- 提示詞頁的頁籤等資料到了才畫（實機發現：AntDesign `Tabs` 先以零個頁籤畫出、之後才補頁籤時 `ActiveKey` 不套用，畫面沒有頁籤被選中）。
- 例外「複製目前查詢結果」多一次查總筆數的請求；AI 是否可用改在開頁與重新整理時讀。

### 7. 獨立審查（7 項：修 6 項，1 項記為已知）

1. 高：AI 回覆的 Markdown 消毒漏掉角括號自動連結 `<javascript:…>`（main 就有；WASM 下 Token 在瀏覽器 storage，影響更大）→ `AutolinkInline` 套同一份白名單，不合格降級成純文字；補測試。
2. 低：日誌 AI PDF 的報告與模型名稱來自畫面、沒有上限 → 加長度上限（Markdown ≤ 512K、模型名稱 ≤ 200、原因 ≤ 50，超過回 400）。
3. 低：按「停止產生」剛好收到失敗結果時對話卡住（例外窗與日誌窗）→ 閘門改看「關窗」而非「已取消」；補元件測試。
4. 低：AI 對話紀錄內文掃描失敗後搜尋稽核記錯 → 稽核移到掃描前，退回重查不重記。
5. 低：讀取提示詞時取消被當成未預期錯誤、例外端點沒有防護 → `AiStreamGuard`。
6. 資源（與 Server 版相同，不是新問題，記為已知限制）：Token 用量 CSV／PDF 明細全表、例外複製最多 5000 筆含堆疊、AI 原文 JSON 一次讀進記憶體。
7. 流程：版本號、`web.config` 串流註解。

## 升版注意

- 版本號 0.10.4 → 0.10.5。
- 沒有資料庫異動。
- IIS 主機若自訂過動態壓縮（把 `*/*` 或 `application/x-ndjson` 加進 `dynamicTypes`），或前面有會緩衝回應的反向代理，請把 `application/x-ndjson` 排除，否則 AI 回覆會等全部產生完才一次出現（功能正常、只是不逐字）。
- 有外部程式要查例外、日誌、AI 對話紀錄或 Token 用量的，現在可以用 `api/v1/exception-logs`、`api/v1/logs`、`api/v1/ai-call-logs`、`api/v1/token-usage`，只限管理員的 Bearer Token。
- 衍生專案若新增過提示詞種類，分頁標題要改加在 `MyProject.Web/Ai/PromptTemplateTitles.cs`（原本的 Server 版 `PromptTemplateView.razor.cs` 已刪除）。
