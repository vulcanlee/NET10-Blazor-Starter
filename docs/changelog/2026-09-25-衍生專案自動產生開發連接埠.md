# 衍生專案自動產生開發連接埠：同機多專案不再搶埠（0.9.65）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：0.9.65
- 首次實作版本：0.9.65
- 最後核對日期：2026/09/25

## 為什麼

`New-StarterProject.ps1` 原本不動 `Properties/launchSettings.json`，每個衍生專案都沿用腳手架的
`http://localhost:5109`／`https://localhost:7144`。同一台機器同時開兩個衍生專案就會搶埠；
Google OAuth 的 redirect URI 也依埠註冊，全部衍生專案都擠在同一組網址上。
另外上手指南與 Google OAuth 文件寫的是更早的 `7044`／`5189`，與實際設定不符。

## 做了什麼

- `scripts/New-StarterProject.ps1`：
  - 新增 `Get-FreeDevPort`，從 VS／`dotnet new` 慣用範圍隨機取埠（http `5000–5300`、https `7000–7300`），
    排除腳手架自己的 `5109`／`7144`，並在 Loopback 試綁，綁不上（已被占用或屬於 Windows 保留埠範圍）就重抽。
    在複製之前產生，找不到可用埠會直接中止、不留半成品。
  - 文字取代迴圈把 `localhost:5109`／`localhost:7144` 換成新埠：`launchSettings.json` 兩個 profile
    （`https` profile 內的 http 埠與 `http` profile 相同）與文件裡的網址一次換掉。只換帶 `localhost:` 的形式，不動裸數字。
  - 殘留掃描加入舊埠網址；結尾印出新網址與要到 Google 註冊的 redirect URI。
- 文件：上手指南（§4.3、§4.4、§7.7、§9、§10）與 Google OAuth 文件的過期埠號改正為 `5109`／`7144`；
  上手指南 §8.1、腳手架開發指引 §2.1／§4.5、新專案啟動流程補上腳本的新行為。

## 影響

- 腳手架本身的埠號不變。
- 衍生專案每次產生都拿到不同的埠；要用 Google 登入時，依腳本最後印出的 redirect URI 到 Google Cloud Console 註冊。
- 腳本結尾的殘留字串警告仍是原本五條（腳本以變數組出舊埠網址，不會自我命中）。
- 0.9.65 之前產生的衍生專案不會自動修正；要換埠請手動改 `launchSettings.json` 的 `applicationUrl`。

## 驗證

```
New-StarterProject.ps1 -ProjectName Acme.Demo（pwsh 7）      → launchSettings 為 7227／5092；衍生文件無 localhost:5109／7144 殘留；警告五條
衍生專案 dotnet run --launch-profile https                  → Now listening on https://localhost:7227 與 http://localhost:5092，首頁 200
New-StarterProject.ps1 -ProjectName Acme.Demo2（PowerShell 5.1）→ 另一組埠 7094／5013
dotnet test src/MyProject/MyProject.slnx                     → 847 通過（未改 C#，數量不變）
scripts/Test-DocsEncoding.ps1                                → 全部通過
```
