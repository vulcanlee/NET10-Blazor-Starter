# 瀏覽器人工驗收：浮層例外與瀏覽器錯誤回報（0.9.172）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：0.9.172
- 首次實作版本：0.9.172
- 最後核對日期：2026/11/08

## 目的

《日誌與例外處理 PRD》§九有兩項只有自動測試、還沒在瀏覽器裡實際驗收：

- **LOG-07**（0.9.77）：浮層（確認窗、通知等 `AntContainer` 底下的元件）出錯時不能讓整個連線中斷，要顯示「畫面元件發生錯誤，已記錄」並記進系統例外。
- **LOG-20～22**（0.9.79）：瀏覽器 JS 錯誤回報、慢操作記錄，以及健康監控的「日誌管線」。

## 驗收方法

- 隔離環境（隔離路徑、暫時密碼、Playwright），不呼叫 AI。
- **LOG-07**：照使用者的決定（2026/11/08），本機**暫時**把危險確認窗的內容改成丟出 `InvalidOperationException("LOG-07 驗收")`，驗完立刻還原，不進 commit。
  - 這個確認窗渲染在 `AntContainer` 底下，正好是要驗的那一層。
  - 觸發方式：在「AI 對話紀錄」按「清空全部紀錄」。
- **LOG-20**：登入後在頁面上用 Playwright 觸發錯誤。
  - 一個同步錯誤、一個未處理的 Promise。
  - 同一分鐘內再觸發 12 個錯誤。
- **LOG-21**：用環境變數把慢請求與慢資料庫指令的門檻設成 1 ms，只在這次隔離啟動有效。

## 結果

| 項目 | 結果 |
|---|---|
| LOG-07 浮層例外 | 畫面底部出現「畫面元件發生錯誤，已記錄」與重新整理連結；頁面仍可操作（沒有出現重新連線視窗、可以換頁）。系統例外有這筆紀錄（來源「畫面」、`/ai-call-logs`、帳號 support），追蹤碼和畫面上的一致。換頁後提示消失，在新頁面按「重新整理」，右下角通知照常出現 |
| LOG-20 瀏覽器錯誤 | 同步錯誤與未處理的 Promise 各記一筆，來源「瀏覽器」，型別 `BrowserScriptException`，頁面 `/system-exceptions`。一分鐘內總共 14 個錯誤時，記 10 筆、丟棄 4 筆 |
| LOG-21 慢操作 | 日誌有慢請求（例如 `Path=/Auths/Login, ElapsedMilliseconds=125, ThresholdMilliseconds=1`）與慢資料庫指令（`CommandKind=PRAGMA`，只記類型、不記 SQL）的 Warning |
| LOG-22 日誌管線 | 健康監控「日誌管線」顯示「正常」，以及「前端錯誤回報因限流丟棄 4」、例外佇列 0/1,000 等數字 |

## 驗收時發現並修正

### 1. 錯誤提示的追蹤碼從沒顯示過（0.9.77 起）

- 浮層提示的實際畫面是：「若持續發生請聯絡系統管理員@TraceCode.Suffix(TraceCode.FromException(exception))。」——程式碼原樣顯示出來了。
- 原因：Razor 把「字母或數字後面緊接 @」當成 Email 位址，不會切換成程式碼；中文字也算字母。
- 受影響的有三個地方：頁面錯誤邊界、浮層錯誤邊界（都在 `Routes.razor`），以及首頁小工具的錯誤提示（`DashboardGrid.razor`）。
- 修正：改成明確運算式 `@(TraceCode.Suffix(...))`。修正後畫面顯示「（錯誤追蹤碼：SWXJ7RY4）」，和系統例外紀錄的追蹤碼一致。
- 新增守門測試 `RazorTransitionConventionTests`：所有 `.razor` 不得有「文字後面緊接 @識別字」。測試本身也驗了全形標點後面、`@(...)` 不會誤判。

### 2. 關掉分頁時，一批連線中斷例外灌進系統例外與暴增告警

- 每次 Playwright 關掉瀏覽器，系統例外就多出一批「Unobserved task exception」（來源「系統」），各次實機 13～48 筆不等。
  - 內容都是 `JSDisconnectedException`：連線已經斷了，還在路上的 JS 呼叫送不出去。
- 使用者關掉分頁也會這樣，而且這些都計入例外暴增告警（預設 10 分鐘 20 次）。設了告警收件人，就可能因為有人關分頁而寄出告警信。
- 使用者的決定（2026/11/08）：視為正常，不記進系統例外。
- 修正：
  - 新增 `CircuitDisconnect.IsOnlyDisconnect`：例外本身是 `JSDisconnectedException`，或 `AggregateException` 展開後全部都是時，才算連線中斷。
  - `ProcessExceptionHooks`：這種未觀察 Task 只記 Debug。
  - `ExceptionLogProvider`：不收錄這種例外，和「使用者取消」同類。
  - 同一批裡只要混了別的例外，就照常記 Error。
- 修正後重跑：關掉瀏覽器後，系統例外沒有新增任何連線中斷的紀錄。

## 獨立審查

另派一個代理人只看程式差異，結果沒有高、中嚴重度問題。
- 審查人另建一個 Razor 專案看編譯產生的程式碼，確認 `文字@(...)` 會正常執行、`文字@識別字` 會原樣輸出、`@@` 不會誤判。
- 審查人也確認：被略過的例外不會進暴增告警；程序崩潰的補登檔不受影響。

低嚴重度的處理如下：

| 發現 | 處理 |
|---|---|
| 守門測試逐行掃描，`@code` 裡的 C# 字串或 Razor 註解可能誤判；錯誤訊息建議的 `@@` 在 C# 字串裡是錯的 | 錯誤訊息改寫：`@@` 只用在畫面文字，命中 C# 字串或註解時換個寫法（目前專案沒有這種情況） |
| `IsOnlyDisconnect` 沒有測到「沒有內層例外」的情況 | 補測試：沒有內層例外、真正的 `JSException`、被包在別種例外裡的，都不算連線中斷 |
| 連線中斷只記 Debug，而日誌最低等級是 Info，所以完全不會寫出；元件洩漏造成的 JS 呼叫也會因此看不到 | 不改：改成 Info 等於每關一次分頁就多 13～48 行日誌；要查這類問題時，暫時把日誌等級調成 Debug 即可 |
| 同一批裡同時有連線中斷與取消例外時仍記 Error；`@` 後面接中文識別字時守門測試抓不到 | 不改：實務上很少見 |
