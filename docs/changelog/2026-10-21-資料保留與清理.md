# 資料保留與清理總覽頁（0.9.133）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：0.9.133
- 首次實作版本：0.9.133
- 最後核對日期：2026/10/21

## 起因

系統有 7 個自動清理排程（多數每天 03:00、備份 02:00），各頁也有手動刪除，但資訊分散：保留天數在「系統參數」，排程在「排程作業」（看不到實際保留天數），手動刪除在各頁，彼此沒有連結。要回答「資料留多久、空間被誰佔掉、自動清理有沒有在跑」得開好幾頁。

## 決定（2026/10/21，與使用者逐項確認）

| 項目 | 決定 |
|---|---|
| 頁面 | 新增「資料保留與清理」（`/data-retention`，管理員專屬，系統設定與維運）；排程作業頁不變 |
| 列 | 每種資料一列、全部列出：已刪除的專案／分類／團隊／使用者／角色（分 5 列）、例外紀錄、Token 用量、AI 對話紀錄、稽核紀錄、站內通知、系統備份、排程執行紀錄、日誌檔、公告 |
| 欄位 | 目前數量、檔案空間、最舊一筆、保留規則、下次會清掉、自動清理（頻率、上次、下次） |
| 手動操作 | 「立即清理」（照目前規則跑一次該排程）＋「前往」（到細部刪除的頁面；已刪除資料直接開「顯示已刪除」）；系統備份只有「前往」 |
| 保留天數 | 只顯示，「修改」連到系統參數頁並捲到對應分類 |

## 注意

- 已刪除資料的「下次會清掉」是最多值：support 帳號、預設角色、仍在使用的角色與還有下屬的部門會留到下次。
- 日誌檔由 NLog 自己刪，頁面顯示的 30 天抄自 nlog.config；改 `maxArchiveDays` 要一起改 `NLogRetention.MaxArchiveDays`（有測試守門）。
- 檔案很多時頁面要等幾秒；超過 10 秒的資料夾顯示「至少 …」。
