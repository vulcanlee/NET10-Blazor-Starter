# 伺服器端重複整併：檔案存放、資料保留、時間換算、稽核、PDF、AI 工具註冊與零碎小元件（0.10.44）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：0.10.44
- 首次實作版本：0.10.44
- 最後核對日期：2026/11/26

## 目的

使用者 2026/11/26 要求整併重複程式碼（分四批的第二批，第一批是[死碼清理](2026-11-26-死碼清理.md)）。本批只動伺服器端（`MyProject.Business`、`MyProject.Web`、`MyProject.Share`），原則是**行為不變**：只搬程式，不改 API 回應、使用者看得到的訊息、稽核內容與日誌寫法。唯一刻意的行為改變是補上三個檔案存放類別缺少的根目錄檢查。證據見[測試報告](../migration/測試報告/重複程式碼與死碼清理.md) B 章。

## 變更內容

### 1. 檔案存放：共用 `RootedFiles`

- 新增 `Business/Services/Other/RootedFiles`：相對路徑一律先經 `TryResolve`（解析後必須在根目錄底下；`../`、絕對路徑、根目錄沒設定都不行），以及讀寫刪、清空（根目錄本身留著）、收舊月份目錄與空月份目錄。它不接例外、不寫日誌，失敗丟給呼叫端。
- 七個存放類別改用它：AI 對話紀錄、Token 用量原始檔、例外堆疊、稽核內容檔、巡檢報告、Agent 對話（只用路徑解析、刪檔與收空月份目錄；讀寫要允許同時開檔並重試，仍自己寫）、專案附件（路徑解析）。各類別的公開方法、回傳值與日誌訊息逐字保留；例外堆疊照舊不寫日誌。
- ⚠️ **安全修正**：AI 對話紀錄、Token 用量原始檔、例外堆疊三個類別原本直接 `Path.Combine(根目錄, 資料庫裡的路徑)`，資料庫的值被改成 `../x` 或絕對路徑時能讀刪根目錄以外的檔案；現在一律拒絕。新增的 `FileStoreBehaviorTests` 在整併前就寫好，這組在整併前失敗、整併後通過。
- 稽核、巡檢報告、Agent 對話三個類別原本各自的內部方法 `TryResolveFullPath` 由 `RootedFiles.TryResolve` 取代；專案附件的同名公開方法保留（`ProjectService` 在用）。

### 2. 資料保留：`RetentionQueries`

- 新增 `Business/Helpers/RetentionQueries`：
  - `StatsAsync`：總筆數、最舊一筆、過期筆數。取代 11 個服務的同一段寫法：AI 對話紀錄、Agent 對話、巡檢報告、Token 用量、例外紀錄、寄信紀錄、容量快照、排程執行紀錄、已刪除資料、系統巡檢報告、刷新 Token。
  - `DeleteRowsThenFilesAsync`：先取出檔案路徑 → 刪資料列 → 刪檔。取代 AI 對話紀錄、巡檢報告、Token 用量三段清除。Token 用量的手動清除原本是把整筆資料載入再 `RemoveRange`，現在和其他兩段一樣直接 `ExecuteDelete`（刪除的資料與檔案相同，不必把整批資料讀進記憶體）。⚠️ 只適用於寫入後不再更新清理條件欄位的資料表：例外紀錄同一個例外再發生時會更新最後發生時間，「先取檔案、再依時間條件刪」之間剛好又發生的那一列會留下、檔卻被刪，所以維持原本依主鍵刪的寫法（獨立審查發現）。
- 各服務仍自己定義清理條件。通知（兩條規則取聯集）、稽核紀錄（走稽核鏈）、Agent 對話（刪檔前重新檢查還在用的檔）、例外紀錄的清除（依主鍵刪）是刻意保留的例外。

### 3. 時間換算：`LocalTime`

- 新增 `Business/Helpers/LocalTime`：`timeProvider.ToLocal`／`ToUtc`／`ToLocalUnzoned`（也接受 `DateTimeOffset` 與 null）與 `LocalTime.Unzoned`。
- 取代以下各處的寫法：
  - 公告、寄信紀錄、AI 提示詞三個服務的私有 `ToLocal`／`ToUtc`。
  - 首頁、通知、個人資料三個 Controller 的私有 `ToLocal`。
  - 日誌等級、系統健康監控兩處 `DateTimeOffset` 的換算。
  - 排程總覽服務的 `ToLocal`。
  - `MaintenanceJobMapper` 與 4 個 Controller 的私有 `Unzoned`。
- 系統參數 Controller 原本用機器時區的 `ToLocalTime()`，改為注入 `TimeProvider`。`AuditLogQueryService.ToLocal` 是其他類別直接呼叫的靜態方法，改經 `TimeProvider.System`；它的 `ToUtc` 維持原樣，因為日光節約時間跳過的那一小時，兩種寫法的處理不同。
- 正式環境的 `TimeProvider.System` 就是伺服器時區。`LocalTimeTests` 用三種時區（含日光節約時間）、整年每天兩個時刻，逐一比對整併前的每一種寫法，數值與 `Kind` 都相同。

### 4. Controller 的稽核包裝

- `ViewAudit.WriteAsync` 新增 `success` 參數（預設 true），說明改成「動作完成之後呼叫」。
- 以下 6 個私有包裝改成一行委派，拿掉多餘的 try/catch（`AuditLogService.WriteAsync` 本來就自己接住並記錄，這些 catch 從來不會執行）：
  - AI 對話紀錄、稽核紀錄兩個 Controller 的 `WriteSelfAuditAsync`。
  - 日誌檢視、系統例外紀錄兩個 Controller 的 `WriteAiAuditAsync`。
  - 日誌等級 Controller 的兩個包裝。
- `ControllerAuditExtensions` 的過時說明（「API 的 Controller 走 Repository」）改正，並寫清楚它和 `ViewAudit` 各自的用途。

### 5. PDF 產生器

- `AiMarkdownPdfRenderer` 新增 `EnsureFont`、`SystemNameOrDefault`、`AddSectionHeading`、`CreateTable(字級, 上下內距, 左右內距)`。
- 改用這些方法的地方：
  - Token 用量報表：字型檢查、輸出、表格、文件作者，以及與共用渲染器數值相同的四個顏色。
  - 系統巡檢報告：表格。
  - AI 對話紀錄、例外分析：區段標題。
  - 系統名稱預設值：共 5 處。
- 各產生器的版面設定（字級、行距、方向、邊界都不同）與表頭資訊行維持各自的寫法。
- 驗證：用各產生器測試的固定輸入，在整併前後各產生 20 份 PDF（含 Token 用量的 8 種範圍、系統巡檢報告 4 種燈號 × 有無 AI 說明）。去掉每次都會變的建立時間、文件 ID 與字型子集前綴後逐位元組比對，**完全相同**。

### 6. 系統管理助理的工具註冊

- `AiToolDefinition` 新增泛型工廠 `For`／`ForMutating`／`ForIrreversible`。
- 帳號、AI、監控、維運四個工具類別的 `Define`／`DefineMutating`／`DefineIrreversible` 改成一行委派，呼叫端不變。
- 驗證：64 個工具的名稱、顯示名稱、權限、是否異動、是否不可復原、核准說明與給模型的說明，在整併前後輸出比對完全相同。

### 7. 日誌類清單的排序

- 新增 `Business/Helpers/QueryableSorting.SortWithIdTieBreak`：同值依 Id，沒有指定方向回 null、沿用預設排序。
- AI 對話紀錄、Token 用量、例外紀錄、稽核紀錄的 10 處三段式三元運算改用它。
- CRUD 產生器產生的服務維持樣板的寫法。

### 8. 零碎小元件

- `Share/Helpers/TextTruncate`（`Cut`／`WithEllipsis`）：11 個 `Truncate` 改成呼叫它，方法名稱與各自對 null 的處理（空字串、「（無）」、照樣 null）不變。
- `BackupStore.FreeSpaceOf`／`Sha256Async`／`TryDeleteDirectory`：取代系統備份與備份驗證各自的一份，日誌訊息不變。
- `JsonFileOptions.IndentedRelaxed`：取代三份逐字相同的「縮排＋中文不跳脫」設定，原本的公開欄位名稱保留並指向它。
- `TabularExport.FileNamePrefix`（`MyProject.Web-`）、`PdfContentType`：取代 12 個下載檔名前綴與 6 個 `"application/pdf"`，產生的檔名與 Content-Type 不變。

### 評估後刻意不整併

理由詳見測試報告 B 章：

- **PDF 的「缺少內建中文字型」訊息**：有的帶「PDF 匯出失敗：」前綴，有的不帶，是配合各頁前端自己加不加前綴。統一的話某些頁面會重複或少了前綴。
- **三個日誌維護 Controller 的刪除／清除／清空**：每個動作約 8 行，稽核內容與訊息都不同。
- **分批依 Id 刪除的迴圈**（3 段）：取的欄位與刪檔與否不同，泛型化要動態組 Expression。
- **服務的刪除單筆／清空全部**：回傳型態與訊息不同。
- **AI 對話紀錄與 Token 用量的篩選**：兩張不同的資料表，要共用得加一個實體介面。
- **頁面路徑正規化**（4 處）：空值結果與裁切規則各不相同。
- **兩個內嵌 JSON 檔的讀取**：日誌訊息不同。
- **DataAnnotations 驗證**（3 處）：後續處理不同。
- **`MissingOrConflictAsync`**：不同資料表與主鍵型別。
- **`ApiResult` 的工廠方法**：回傳型別不同。
- **SHA-256 Token 雜湊**：大小寫不同，合併會讓已存的雜湊對不上。
- **重試迴圈**：等待規則不同。
