# 稽核紀錄記錄範圍開關與瀏覽保留天數（0.9.174）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：0.9.174
- 首次實作版本：0.9.174
- 最後核對日期：2026/11/08

## 目的

0.9.131 起稽核紀錄什麼都記：每換一頁一筆 `Page.View`、每按一次搜尋一筆 `*.Search`、每打開一筆來看一筆 `*.View`，每次修改還把「欄位: 舊值 → 新值」存成內容檔。結果：

- 稽核表裡大部分是瀏覽紀錄，是資料庫變大的主因，而且和異動一樣留 365 天。
- 修改前後差異可能含個人資料（姓名、Email 等），不是每個系統都需要、也不是每個系統都適合留。

這次把「要不要記」交給管理員決定：兩種紀錄改成可以在「系統參數」開關，**預設關閉**；瀏覽類另外給一個較短的保留天數。登入、權限拒絕、新增、修改、刪除這類安全與異動事件**永遠照記**。

## 變更內容

### 1. 兩個記錄範圍開關（新設定區段 `AuditLogSettings`）

| 設定鍵 | 預設 | 系統參數名稱 | 生效 | 關閉時 |
|---|---|---|---|---|
| `AuditLogSettings:RecordFieldChanges` | `false` | 稽核：記錄修改前後差異 | 下一次修改起 | 修改照樣記一筆「誰、何時、哪一筆」，只是沒有差異。只作用在 `*.Update` 與 `User.ProfileUpdate`；其他動作帶的內容（例如 `AiCallLog.Export` 匯出了哪些 Id）不受影響 |
| `AuditLogSettings:RecordBrowsing` | `false` | 稽核：記錄瀏覽類事件 | 下一次換頁或搜尋起 | 換頁 `Page.View`、按搜尋 `*.Search`、開單筆來看 `*.View`（**含 `Audit.Search`／`Audit.View`＝誰看過稽核紀錄**）整筆不寫：不寫資料列、不寫內容檔，也不記 NLog 的 Debug 行 |

- 兩個開關都在「系統參數」頁的「資料保留」分類，可即時修改（改了會留下 `SystemParameter.Update`）。「稽核：記錄修改前後差異」的說明提到差異可能含個人資料。
- 判斷只在 `AuditLogService.WriteAsync` 一處：每次寫入讀 `IOptionsMonitor.CurrentValue`，切換立即生效；讀設定失敗時當作全關，但異動事件照寫；已註冊 `ValidateOnStart`。
- 「會帶差異」的動作由新的 `AuditActions.CarriesFieldDiff` 判斷（`*.Update` 與 `User.ProfileUpdate`）；瀏覽類沿用 0.9.173 的 `AuditActions.IsBrowsing`。

### 2. 瀏覽類的保留天數

- 新增 `LogRetentionSettings:AuditBrowsingLogDays`（預設 90，0＝不自動清除，範圍 0～36500），系統參數名稱「稽核紀錄（瀏覽類）保留天數」，生效：下一次排程清理時（預設每天 03:00）；「稽核紀錄」頁的清除按鈕立即使用。
- 異動與安全事件仍用 `AuditLogDays`（預設 365）。
- 系統參數 61 → 64 個。

### 3. 排程作業「稽核紀錄清理」分兩段清

- 異動與安全事件用 `AuditLogDays`、瀏覽類用 `AuditBrowsingLogDays`，各自 0 就略過。
- 每段刪到資料各寫一筆 `Audit.AutoPurge`，摘要 `rows=N; days=D; kind=change` 或 `kind=browsing`，最後是 `trigger=T`。
- 結果訊息「刪除 N 筆超過 365 天的異動與安全紀錄；刪除 M 筆超過 90 天的瀏覽紀錄。」；某一類為 0 時那一段寫「異動與安全紀錄不自動清除（保留天數為 0）」或「瀏覽紀錄不自動清除（保留天數為 0）」；兩類都設 0 時「保留天數都設為 0，不自動清除。」
- 排程作業頁的說明改為「刪除超過保留天數的稽核紀錄：異動與安全事件預設 365 天、瀏覽類（換頁、搜尋、查看）預設 90 天，在「系統參數」頁設定，0 = 不清除。」
- 內容檔的月份目錄（空目錄與孤兒檔）：兩類天數都大於 0 時，最後用**較舊**的門檻收；只清單一類時不收 —— 用 90 天的門檻收，會誤刪 90～365 天前的修改差異檔。

### 4. 稽核紀錄頁 `/audit-logs`

- 清除按鈕（圖示 `history`）的提示文字改為「清除超過保留天數的紀錄（異動 N 天、瀏覽 M 天）」，N 讀 `AuditLogDays`（0 時退回 365）、M 讀 `AuditBrowsingLogDays`（0 時退回 90）。
- 確認窗標題「清除超過保留天數的紀錄」，內文「將刪除早於 N 天前的異動與安全紀錄，以及早於 M 天前的瀏覽紀錄（換頁、搜尋、查看）。此動作無法復原，且本次清除會另外留下稽核紀錄。」
- 按「清除」後兩類各清一次，各寫一筆 `Audit.Purge`；右下角提示合成一則，例如「異動與安全紀錄：已清除 3 筆紀錄。瀏覽紀錄：沒有符合條件的紀錄。」兩類都清完後，用較舊的天數收掉空的月份目錄與孤兒檔；只要第一段有刪到，清單就會重新整理。
- 頁首藍色說明框在開關有關閉時多一行：「目前沒有記錄修改前後差異與瀏覽類事件（換頁、搜尋、查看），可在「系統參數」頁開啟。」（只關一個時只列那一個）。

### 5. 資料頁「異動歷程」視窗

沒有內容檔時的文字改為「（這一筆沒有詳細內容。修改前後差異只在「修改」、而且系統參數「稽核：記錄修改前後差異」開啟時才會記錄）」。

### 6. 資料保留與清理頁 `/data-retention`

- 稽核紀錄列的保留規則改為「異動與安全事件保留 365 天；瀏覽類（換頁、搜尋、查看）保留 90 天」（某一類為 0 時那一段寫「不自動刪除（保留天數為 0）」）。
- 目前數量、最舊一筆與「下次會清掉幾筆」是兩類相加，與排程實際刪的一致；兩類都是 0 時才停用「立即清理」。
- 自訂清除仍清全部種類。

### 7. 系統管理助理

開關關閉時，模型不能把「沒有記錄」當成「沒有發生」：

- `search_audit_logs` 查瀏覽類動作（例如 `Category.View`＝誰看過）而瀏覽開關關閉時，回傳的 note 加上「目前沒有記錄瀏覽類事件（…），查不到不代表沒有人看過」。
- `get_audit_log_content` 讀到沒有差異的修改時，說明「修改前後差異只在系統參數『稽核：記錄修改前後差異』開啟時記錄，目前關閉」（開啟中則註明「這筆可能是開啟前寫的」）。
- 兩個工具的說明都補上開關的存在。

## ⚠️ 升級影響

1. ⚠️ **升級後立刻停止記錄修改前後差異與瀏覽類事件**（0.9.131～0.9.173 都會記）。需要的話到「系統參數」的「資料保留」打開；打開前的不會補記。
2. ⚠️ **升級後第一次排程（03:00）會刪掉超過 90 天的舊瀏覽類紀錄**。要保留更久，升級前先把「稽核紀錄（瀏覽類）保留天數」調大或設 0，或先匯出 CSV。
3. ⚠️ 瀏覽開關關閉時，「誰看過稽核紀錄」（`Audit.Search`／`Audit.View`）、資料頁「異動歷程」的打開與點選、系統管理助理的查詢稽核，**也都不會留下紀錄**。有內控要求「查看稽核也要留痕」的系統，請打開瀏覽開關。
4. NLog 同步沒變：沒寫進資料庫的事件不記 Debug 行。

## 新紅線

寫進[速查表 §6.30](../architecture/開發慣例與限制速查.md)：

1. **開關只能在 `AuditLogService` 判斷，呼叫端照常傳 `content`**。在頁面或服務自己讀開關，一定會漏、而且切換後行為不一致。
2. **只有 `*.Update` 與 `User.ProfileUpdate` 能帶修改前後差異**（`AuditActions.CarriesFieldDiff`）。由 `AuditConventionTests.CarriesFieldDiff_ShouldBeTrueExactlyForUpdateConstants` 守門。
3. **瀏覽類常數名稱必須是 `Search`／`View`**（0.9.173 的紅線，現在保留天數與開關也靠它）。
4. **只清單一類時不可收內容檔的月份目錄**（`RetentionJobTests.AuditLogJob_ShouldCollectMonthFoldersOnlyBeforeTheOlderThreshold`）。

## 已知限制

- 開關打開前的瀏覽與差異不會補記。
- 瀏覽類與異動類靠動作代碼區分，常數取錯名字會被歸錯類（有守門測試）。
- 自訂清除不分類，一次清全部種類。
