# 日誌檢視新增「全部展開／收合」與「複製到剪貼簿」：點列複製單筆、一鍵複製查詢結果（0.9.69）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：0.9.69
- 首次實作版本：0.9.69
- 最後核對日期：2026/09/29

## 為什麼

在 `/logs` 要看多筆原始內容只能一列一列點 `+` 展開；要把某一筆或一段日誌貼給開發人員，只能先匯出 `.log`
檔再開檔複製。這一版讓展開、收合與複製都能在頁面上一步完成，而且內網以 http 部署時也能用。

## 做了什麼

- **工具列**（順序：查詢｜全部展開｜全部收合｜複製本次查詢結果｜匯出｜AI 分析），三顆新按鈕在查無資料時停用：
  - **全部展開**（`unfold_more`）：`Table.ExpandAll()`，並把 `isExpandAll` 綁到 `DefaultExpandAllRows`，換頁後新的一頁也展開。
  - **全部收合**（`unfold_less`）：`Table.CollapseAll()`。
  - **複製本次查詢結果（原始 nlog 格式）**（`content_copy`）：複製全部 N 筆、時間正序，內容與匯出 `.log` 相同
    （兩者共用新抽出的 `BuildRawText()`）。超過 **1,000 筆**先以 `ConfirmDialog.AskAsync` 確認（「仍要複製」／「取消」）。
- **點列複製**：`Table.OnRowClick` → 複製該筆 `Raw`，只複製不展開；列游標為手指、展開後的原文區塊為文字游標。
  展開圖示與原文區塊不觸發複製（瀏覽器實測確認）。
- **重新查詢回到收合**：除了把 `isExpandAll` 設回 false，也呼叫 `CollapseAll()` ——
  AntDesign 依 `RowKey`（`Sequence`）記住每列展開狀態，新舊結果的鍵重疊時，只改旗標那些列仍會展開（實測踩到）。
- **剪貼簿**：沿用 `wwwroot/js/clipboard.js` 的 `appClipboard.copyText`（https／localhost 用 `navigator.clipboard`，
  http 退回 `textarea + execCommand`），以 `http://<區網 IP>` 的非安全內容實測單筆與整批複製皆成功。
- **提示**：一律右下角 `ViewNotification`：「已複製 N 筆日誌到剪貼簿。」「瀏覽器拒絕存取剪貼簿，請手動選取複製。」
  「複製失敗，請手動選取複製。」「目前沒有可複製的日誌。」。成功時寫一筆應用程式日誌（`Rows`、`Characters`）。
- **操作說明**：`Datas/Help/logs.md` 補上三顆按鈕、點列複製、訊息與兩則常見問題。

## 刻意不做的事

- 不排除「在列上拖曳選字」：放開滑鼠時也會整筆複製。只想複製一小段時，展開後在原文區塊裡選取即可。
- 確認門檻不進 appsettings（程式常數 `CopyAllConfirmThreshold`）。
- 複製不寫稽核紀錄，與匯出一致。
