# 操作按鈕改成無框線小方塊（0.10.27）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：0.10.27
- 首次實作版本：0.10.27
- 最後核對日期：2026/11/15

## 目的

使用者 2026/11/15 要求清單「操作」欄的圖示按鈕，大小與間距比照 KnowledgeExtraction.AI 的影音轉逐字稿頁：圖示排得緊密、沒有框線。本專案的操作欄（例如角色管理）每顆按鈕都被一個大框框住，按鈕之間的距離很大。

查明的原因：

- 參考專案的 `CrudActionButton` 是 28×28 的透明方塊、沒有框線，按鈕間隔 8px。樣式寫在全站的 `app.css`。
- 本專案的 `CrudActionButton.razor.css` 其實也寫了「28×28 透明無框」，`ToolbarIconButton.razor.css` 寫了 36×36，但兩者都是 **CSS 隔離（scoped CSS）**。
  - CSS 隔離的 scope 屬性只加在元件**自己輸出**的元素上。`<Button Class="crud-action-button">` 是把 class 傳給 AntDesign 的 `Button` 元件，它輸出的 `<button>` 沒有這個屬性，所以規則套不到。
  - 只有 `Href` 版的 `<a>` 吃到過這些規則。
  - 實測修正前，每顆操作按鈕與工具列按鈕都是 AntDesign 預設的 **56×32、有框線**。滑鼠移上時會出現框線，圖示變成 AntDesign 的藍色，不是主色。

使用者的決定：

1. 範圍：操作按鈕（`CrudActionButton`），加上表格上方工具列的按鈕（`ToolbarIconButton`）。兩者都改成同樣的無框小方塊，參考專案的工具列也是這樣。
2. 滑鼠移上：圖示變主色，出現淡色底，**不出現框線**。
3. 操作欄寬度：一起縮成剛好放得下。

## 變更內容

- **外觀搬到 `wwwroot/theme.css`**（全站）：`.crud-action-button.crud-action-button` 與 `.toolbar-icon-button.toolbar-icon-button`。class 重複兩次，是為了權重壓過 AntDesign 1.6.3 的 `.ant-btn:hover`／`:focus`／`:active`；選擇器也涵蓋 `<a>`。停用規則和 `.ant-btn[disabled]:hover` 權重相同，只靠排在最後贏，註解寫明不能挪前面。
  - 平常：28×28、框線透明、沒有底色，圖示 `--app-muted`，圓角 4px。
  - 滑鼠移上、鍵盤焦點：圖示 `--app-accent`，底色 `--app-accent-soft`，仍然沒有框線。
    - 一開始用 `--app-tint`，實機截圖發現它比整列 hover 的底色還淺，在列上幾乎看不出來，所以改掉。
  - 鍵盤焦點另加 2px `--app-accent` outline（`--app-accent-dim` 對白底約 3.1:1、對列 hover 約 2.6:1，不夠）。
  - 滑鼠點過、焦點還留在按鈕上時，回到平常的樣子（AntDesign 的 `:focus` 會套藍色）。
  - 危險按鈕（刪除、永久刪除）：紅色圖示，移上時是淡紅底。`:root` 新增 `--app-danger`、`--app-danger-strong`、`--app-danger-bg`。
    - 圖示色沿用原本 `.razor.css` 的值。
    - 底色原本的 `#fff1f0` 比列 hover 的底色還淺，獨立審查指出後改成半透明紅 `rgba(207, 19, 34, 0.12)`。
  - 停用：`--app-off`。
  - 工具列按鈕保留滑鼠移上時上移 1px、按下時縮小的動態，以及 reduced-motion 降級。
  - 範圍：全站所有用這兩個元件的地方都一起變。包含表格外的幾顆（管理助理的重新命名／刪除對話、系統參數的移除、專案附件的移除），以及對話窗裡的按鈕（AI 對話紀錄明細的複製、AI 例外分析的工具列）。
- **兩個元件的 `.razor.css`** 只留真正套得到的規則（視覺隱藏、只給螢幕閱讀器的 label，是元件自己輸出的 `<span>`），檔頭註解說明原因。元件 `.razor` 的註解同步更新（`ToolbarIconButton` 原本寫「36x36 的一般 AntDesign 外觀」）。
- **操作欄寬度＝`36 × 按鈕數 ＋ 24`，無條件進位到 10**（按鈕 28、間隔 8、儲存格左右 padding 各 16；設 `TableSize.Small` 的表 padding 是 8，多出 16px 餘裕）。按鈕數取這張表一列最多會同時出現的數量：以管理員計算，含「異動歷程」，正常與「顯示已刪除」兩種模式取多的。`ScrollX` 照 0.10.26 的規則同步重算。

  | 表 | 按鈕數 | 操作欄 | ScrollX |
  |---|---|---|---|
  | 角色 | 4 | 280 → 170 | 950 → 840 |
  | 使用者 | 最多 7 | 360 → 280 | 1730 → 1650 |
  | 專案 | 3 | 200 → 140 | 2240 → 2180 |
  | 分類、團隊 | 3 | 200 → 140 | 1000 → 940 |
  | 資料保留 | 3 | 180 → 140 | 1280 → 1240 |
  | 公告、備份、系統例外、排程、系統參數 | 2 | 150 → 100 | 1000 → 950 |
  | AI 對話紀錄 | 2 | 150 → 100 | 1290 → 1240 |
  | Token 用量 | 2 | 150 → 100 | 1400 → 1350 |
  | AI 提示詞 | 2 | 150 → 100 | 780 → 730 |
  | 稽核紀錄 | 1 | 90 → 60 | 1000 → 970 |

  - 使用者管理在「被鎖定、開了兩步驟驗證、又不是自己」的使用者時，7 顆按鈕會同時出現（修改、複製、解鎖、強制登出、重設兩步驟驗證、刪除、異動歷程），所以是 280。
    - 「強制登出」的條件是「不是自己」（`UsersController.ToDto`），跟有沒有登入中的工作階段無關。
    - 實測：複製 support 建一個這樣的使用者，1440 與 390 寬時 7 顆都排成一列，儲存格 280/280。
    - `Space Wrap` 保留，萬一放不下就折到第二列。
- **CRUD 產生器樣板**：操作欄 200 → 140（修改、刪除、異動歷程 3 顆），`ScrollX` 有團隊欄 1000 → 940、沒有 930 → 870。

## 測試

- 新增 `ActionButtonStyleConventionTests`（3 筆）：
  - `ScopedCss_ShouldNotStyleClassesPassedToOtherComponents`：傳 `Class` 給別的元件時，自己的 `.razor.css` 不可以直接寫那個 class 的規則，只能出現在 `::deep` 後面。
    - `Class="@CssClass"`、`Class="@(…)"` 這種運算式，會改看屬性值、`@code` 與 code-behind 裡字串常值中的 class 名稱；Razor 註解先去掉。
    - 修正前列出兩個元件共 13 條套不到的按鈕規則，並以此確認測試會失敗。
    - 屬性名稱不分大小寫（Blazor 比對元件參數不分大小寫，`class=` 一樣是傳給元件）。第一版只認大寫 `Class`，獨立審查指出後改掉，又抓出 13 個既有的無效 class：各清單頁的 `.<前綴>-search-input`，以及稽核紀錄、系統例外、Token 用量、寄信紀錄的帳號、IP、識別碼輸入框寬度。它們寫給 AntDesign 的 `Input`／`Select`／`RangePicker`，從來沒生效。
      - 讓它們生效會改變那些輸入框現在的寬度，不在這次範圍，所以列在 `KnownIneffective`，不要再新增。
      - 清單裡的規則不在了也會紅燈，提醒從清單拿掉。
  - `ThemeCss_ShouldGiveIconButtonsA28pxBorderlessSquare`（兩筆）：`theme.css` 要有兩種按鈕的規則（class 寫兩次的選擇器），28×28、框線透明；修正前失敗。
- `TableLayoutConventionTests` 不用改：它核對新的操作欄寬度與 `ScrollX` 加總，通過。
- `scripts/e2e/explore-edge.mjs`：E4、E6 共用的 `measureLayout` 新增兩項檢查。
  - 每顆可見的操作按鈕與工具列按鈕是 28×28、沒有框線（E6 沒有表格的頁面也查）。
  - 操作欄的按鈕排在同一列（上緣相差超過 4px 才算另一列，因為「前往」是 `<a>`，上緣比按鈕少 1px），而且沒有超出儲存格；放不下時報告寫出是哪一張表。
  - E6 另外在角色管理把滑鼠移上「修改」與「刪除」，確認底色看得出來（不是透明、不是白色、不同於列底），而且沒有框線；量不到時記成失敗，不會中斷整支腳本。
  - 修正前 E4、E6 都失敗（每頁按鈕 56×32；滑鼠移上有框線、圖示是藍色），修正後通過。
  - 專案與使用者列高的檢查原本跳過「6 顆按鈕刻意折兩列」的列，現在每一列都算。
  - 測試數 3,232 → 3,235。

## 獨立審查

審查沒有找到會讓功能壞掉的問題。15 張表與 CRUD 樣板的操作欄寬度、`ScrollX` 逐一核對全部正確；刪掉的 scoped CSS 沒有誤刪（`<a>` 原本吃得到的樣式，搬到 theme.css 後完整等價）。指出的問題都已處理：

- 守門測試只認大寫 `Class`，漏抓小寫 `class=`（見上方「測試」）。
- 危險按鈕滑鼠移上的底色比整列 hover 還淺：改成半透明紅，E6 也量刪除鈕。
- 鍵盤焦點外框對比不到 3:1：改用 `--app-accent`。
- E6 的滑鼠移上檢查只看底色不是透明：修正前 AntDesign hover 是白底，也會被判定有底色。改成也不可以是白色或列底。
- 其他補強：E6 沒有表格的頁面也查按鈕；操作欄放不下時寫出是哪張表；角色管理沒有資料列時記成失敗，不會讓整支腳本中斷。
- 7 顆按鈕的使用者從來沒實測過：已實測，見上方。
- 文件與註解：
  - 公式改寫成「無條件進位」，並補上 `TableSize.Small` 的表 padding 是 8；
  - 被蓋過的 AntDesign 規則名稱改正（寫成 `.ant-btn-default:hover` 是錯的）；
  - 修正前尺寸統一為 56×32（有兩處寫成 46）；
  - 「強制登出」的條件改正；
  - 速查表第 144 點一句更新後不成立的話改寫；
  - 規範拿掉「鍵盤焦點也上移」；
  - 寫明對話窗裡的按鈕也一起變。
- 已知、未處理：公告、備份的「刪除」沒有加 `Danger`（紅色），跟其他頁不一致。這是之前就有的，這次沒有動。
