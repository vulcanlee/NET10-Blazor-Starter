# 寄信服務基礎設施：MailKit、背景佇列、健康監控項與測試寄信（0.9.59）

- 文件版本：1.0
- 文件狀態：已實作
- 現行系統版本：0.9.59
- 首次實作版本：0.9.59
- 最後核對日期：2026/09/24

## 為什麼

《腳手架開發指引》§10 缺口 #4 與路線圖第 5 期：全 repo 沒有任何寄信能力，
連帶沒有忘記密碼。這是兩階段中的第一階段，先把寄信基礎打好；
忘記密碼（0.9.60）是第一個用到它的功能。設計見
[設計文件](../superpowers/specs/2026-09-24-email-password-reset-design.md)。

## 做了什麼

- **套件**：新增 `MailKit` 4.18.0（只加在 `MyProject.Web`，遞移帶入 `MimeKit`、`BouncyCastle.Cryptography`，皆無已知弱點）。
- **設定**：新增 `EmailSettings` 區段，出貨 `Provider=None`、`Password=""`。
  - 三種寄送方式：`None`（丟棄，只記日誌）、`Pickup`（寫 `.eml` 到資料夾，開發用）、`Smtp`（MailKit）。
  - 所有環境以 `ValidateOnStart` 檢查；`Smtp` 時 `Host`、`FromAddress` 必填。
  - `StartupSafetyValidator` 新增第 6 道 Production 檢查：`Pickup` 拒絕啟動；`Smtp` 另需完整 http(s) 的 `PublicBaseUrl`。
- **程式介面**（Business，不引用 MailKit）：`IEmailSender`（同步寄出，失敗拋例外）、`IEmailQueue`（入列即返回）、
  `EmailTemplates`（HTML＋純文字、變數 HTML 編碼）。實作在 `MyProject.Web/Email/`。
- **背景寄信**：`ChannelEmailQueue`（有界 100、`Wait` 模式）＋ `EmailDispatchWorker`（全專案第二個 `BackgroundService`）。
  失敗不重試，記 Error 進系統例外紀錄（來源＝背景作業）。
- **系統健康監控**：新增「寄信服務」檢查項（權重 10，總分 125 → 135）與「寄信測試」區塊；
  測試寄信寫稽核 `Email.Test`（不含收件者）。稽核紀錄頁的 `Email` 類別以青色標示。

## 關鍵決定

| 決定 | 理由 |
|---|---|
| provider 在解析 `IEmailSender` 時決定，不在註冊時 switch | 註冊時讀設定會讓 `WebApplicationFactory` 子類的組態覆寫失效，測試無法切換 provider |
| 匿名流程要用佇列，測試寄信用同步 | 同步寄信時回應時間會洩漏帳號是否存在；測試寄信則是要當場看到成敗 |
| 佇列 `FullMode = Wait` ＋ `TryWrite` | Drop 系列模式下 `TryWrite` 永遠回 true，信丟了呼叫端也不知道 |
| Production 拒絕 `Pickup` | `.eml` 是明文、含完整內文，第二階段起還含密碼重設連結 |
| 信中連結以 `PublicBaseUrl` 為準 | 不採用請求的 Host header，防止重設連結被偽造的 Host 導走 |
| 不略過 TLS 憑證驗證 | 略過等於允許中間人攔截 SMTP 密碼與信件 |
| 測試寄信放在系統健康監控頁 | 該頁本來就是管理員專屬，不必新增選單與權限鍵 |
| 健康項 `None`／`Pickup` 黃燈 | 比照 LLM 的選配功能處理；`Smtp` 才實測（上限 5 秒、不寄信）|

## 影響

- 既有部署不需任何動作：出貨 `Provider=None`，什麼都不會寄。
- 系統健康監控的總分會因為新增的黃燈項目略降（未設定寄信時，這一項只拿一半的 10 分）。
- 要啟用寄信：設 `EmailSettings:Provider=Smtp` 並填 `Host`、`FromAddress`、`PublicBaseUrl`，
  帳密走環境變數；上線清單見 [正式部署與安全檢查清單](../operations/正式部署與安全檢查清單.md)。
