## 1. 規範一：每次更新必須 bump 版本

唯一版本來源是：

```
src/MyProject/MyProject.Web/appsettings.json
└─ SystemSettings.SystemInformation.SystemVersion
```

### 1.1 版號格式

顯示格式維持三碼加日期：

```
Major.Minor.Patch (YYYY/MM/DD)
```

例：`0.4.1 (2026/06/22)`

### 1.2 遞增規則

**每次提交異動一律將最後一碼（`Patch`）+1**，不依異動性質區分：

- 不論是 bug 修正、文件更新、新增功能、新 API、新 Entity 或架構調整，都只把 `Patch` +1。
- **不進位**：`0.4.9 → 0.4.10`（最後一碼是獨立遞增的整數，不會進位到 `Minor`）。
- `Major`、`Minor` 不會自動變動；僅在明確決定「里程碑版本」時才由人工調整（一般開發流程不會用到）。
- 範例：`0.4.0 → 0.4.1 → 0.4.2 → …`

### 1.3 日期同步

括號內日期必須更新為 commit 當天日期，格式 `YYYY/MM/DD`，與 `Asia/Taipei` 時區的當天一致。

### 1.4 檢查方式

```powershell
Select-String -Path "src/MyProject/MyProject.Web/appsettings.json" -Pattern "SystemVersion"
```

## 3. 規範三：UTF-8 編碼

### 3.1 適用範圍

- 所有 `.md`、`.razor`、`.cs`、`.json`、`.css` 文件。

### 3.2 編碼規定

- **`docs/` 下所有 `.md` 一律使用「UTF-8 含 BOM」**：CI 的 [`scripts/Test-DocsEncoding.ps1`](../../scripts/Test-DocsEncoding.ps1) 會遞迴檢查，缺少 BOM 或含取代字元（`U+FFFD`）即失敗。
- 其餘原始碼（`.razor`、`.cs`、`.json`、`.css`）採 UTF-8 即可。
- 編輯後請確認繁體中文未出現 `?`、亂碼方塊或其他不可讀字元。

### 3.3 PowerShell 自我驗證

```powershell
Get-ChildItem -Path docs,readme.md -Recurse -Include *.md | ForEach-Object {
    $bytes = [IO.File]::ReadAllBytes($_.FullName)
    $hasBom = $bytes.Length -ge 3 -and $bytes[0] -eq 0xEF -and $bytes[1] -eq 0xBB -and $bytes[2] -eq 0xBF
    "{0,-50}  bytes={1,-8} bom={2}" -f $_.Name, $bytes.Length, $hasBom
}
```

> ⚠️ 對於 PowerShell 自身建立的檔案（例如 `Out-File`、`Set-Content`），請一律使用 **`-Encoding utf8BOM`**。
>
> **不要寫 `-Encoding utf8`**：在 Windows PowerShell 5.1 它含 BOM，但在 **pwsh 7（CI 實際使用的版本）
> 它是「UTF-8 無 BOM」**，會直接被 `scripts/Test-DocsEncoding.ps1` 判定失敗。
> 寫 `utf8BOM` 在兩個版本下行為一致。

## 4. Commit 前自我檢查清單

請於 commit 前逐項確認（建議貼到 PR 描述中）：

- [ ] `appsettings.json` 的 `SystemVersion` 已遞增（含日期）。
- [ ] 本次異動所影響的 docs 文件已同步更新（對照第 2 節）。
- [ ] 所有新增 / 修改檔案皆採 UTF-8（無亂碼）。
- [ ] 新 / 改 API：已寫 `Debug` 進站、`Information` 成功、`Warning` 失敗、`Error` 例外四類日誌。
- [ ] 新 / 改 Entity：已執行 `Add-Migration` 並通過 `Update-Database`。
- [ ] 新 / 改頁面或權限鍵：`Menu.json` / `MenuPermissionMap` / `MagicObjectHelper` / 頁面 `CheckAccessPage`
      **四處必須同步**，並跑 `dotnet test --filter MenuPermissionConsistencyTests` 確認。
- [ ] 本機四道關卡全過（與 CI 一致）：
      `dotnet build src/MyProject/MyProject.slnx -c Release`（0 warning）、
      `dotnet format src/MyProject/MyProject.slnx --verify-no-changes`、
      `dotnet test src/MyProject/MyProject.slnx`、
      `pwsh ./scripts/Test-DocsEncoding.ps1`。
- [ ] 文件相對連結可正確開啟（`docs/` 內互引、與 `readme.md` 之間皆通）。

## 5. 異動範例

> 假設本次新增了「Issue（議題追蹤）」實體：

1. 新增 `MyProject.AccessDatas/Models/Issue.cs`。
2. 新增 Migration → 更新 [資料模型與資料庫.md](../architecture/資料模型與資料庫.md)、[EFCore.md](../guides/EFCore.md)。
3. 新增 `IssueController`、DTO → 更新 [Web API 設計慣例.md](../architecture/Web%20API%20設計慣例.md)。
4. 新增 `Menu.json` 節點與權限 → 同步 `MenuPermissionMap`／`MagicObjectHelper`／頁面 `CheckAccessPage`（四處），並更新 [開發慣例與限制速查.md](../architecture/開發慣例與限制速查.md) §5 與 [prd/README.md](../prd/README.md) 能力矩陣。
5. 若有附件 → 更新 [檔案上傳機制.md](../features/檔案上傳機制.md)。
6. 主 [readme.md](../../readme.md) 第 4、6 節（功能列表 / 結構樹）若改變需同步。
7. `appsettings.json`：`SystemVersion` 最後一碼 +1（例如 `0.4.0` → `0.4.1`），日期更新為 commit 當天。
