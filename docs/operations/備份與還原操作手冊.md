# 備份與還原操作手冊

- 文件版本：1.7
- 文件狀態：已實作
- 現行系統版本：0.9.175
- 首次實作版本：0.9.99
- 最後核對日期：2026/11/08

給部署與維運人員：系統備份放在哪裡、怎麼保管、怎麼還原、怎麼演練。功能規格見 [系統備份與還原 PRD](../prd/系統備份與還原-prd.md)。

## 1. 備份是什麼

- 排程作業「系統備份」每天 02:00 在 `SystemSettings:ExternalFileSystem:BackupPath` 產生一個 `backup-yyyyMMdd-HHmmss.zip`，保留最新 7 份（`BackupSettings:KeepCount`，可在「系統參數」頁調整）。
- 管理員可在「系統管理 › 系統設定與維運 › 系統備份」（`/backups`）立即備份、下載、刪除。
- zip 內容：

| zip 內 | 來源 | 說明 |
|---|---|---|
| `db/BackendDB.db` | `DatabasePath` | 資料庫快照（`VACUUM INTO`，單一檔、沒有 `-wal`） |
| `files/ProjectFile/` | `ProjectFilePath` | 專案附件 |
| `files/Exception/` | `ExceptionPath` | 例外堆疊檔 |
| `files/TokenUsage/` | `TokenUsagePath` | Token 原始 JSON |
| `files/AuditContent/` | `AuditContentPath` | 稽核的詳細內容檔：修改前後差異與查詢條件（0.9.131 起） |
| `files/Keys/` | `DataProtectionKeyPath` | Data Protection 金鑰環 |
| `files/AiCallLog/` | `AiCallLogPath` | 只有 `BackupSettings:IncludeAiCallLogs = true` 時才有 |
| `files/AiAgentConversation/` | `AiAgentConversationPath` | Agent 對話的內容檔（0.9.143 起；0.9.144 起含 Agent 工作流程的執行紀錄；另含系統管理助理對話與定時巡檢報告〔0.9.161 起，`AdminPatrol\{yyyyMM}`〕）；只有 `BackupSettings:IncludeAiAgentConversations = true` 時才有 |
| `manifest.json` | — | 建立時間、系統版本、最後 migration、資料庫 SHA-256、各資料夾檔案數 |

沒有檔案的資料夾不會出現在 zip 裡（zip 不存空資料夾），例如還沒有任何附件時看不到 `files/ProjectFile/`。請以 `manifest.json` 的 `folders[].fileCount`，或「系統備份」頁「內容」欄的檔案數為準。

不在備份裡的項目與理由：

| 項目 | 為什麼不備份 |
|---|---|
| `DatabasePath` 資料夾裡的其他檔（`-wal`、`-shm`、`*.lock`） | 資料庫已用快照取得一致的單一檔，`-wal` 裡的寫入已包含在內。這些都是網站執行時才用的檔，還原時帶回來，殘留的 WAL 反而會把還原的資料庫弄壞。 |
| `AiCallLogPath`（預設） | 內容含完整的提示詞、模型回應、使用者帳號與錯誤堆疊，而備份沒有加密，因此預設關閉（2026/10/04 決定）；需要時在「系統參數」的「備份」分類開啟。⚠️ 沒備份時換主機還原，資料庫裡的 AI 對話紀錄會找不到內容檔；在原主機還原則不受影響（還原腳本只處理 manifest 列出的資料夾）。 |
| `AiAgentConversationPath`（預設，0.9.143 起） | 內容是使用者與 AI 的對話與工具查到的業務資料，本來就依保留天數過期，因此預設關閉；需要時在「系統參數」的「備份」分類開啟「備份 Agent 對話」。⚠️ 沒備份時換主機還原，「我的對話」清單仍在（在資料庫裡），但點開會提示這段對話無法接續（Agent 工作流程的「我的執行紀錄」則提示內容已不存在；系統管理助理的「巡檢報告」清單仍在，但點開會提示找不到這份報告的內容檔）；在原主機還原則不受影響。 |
| `BackupPath` | 備份檔本身，不能把自己也打包進去。 |
| `AuditKeyPath`（0.9.175 起） | 稽核紀錄防竄改的金鑰（`audit-hmac.key`）與檢查點（`audit-chain-checkpoint.json`）。**刻意不備份**：金鑰和資料庫放在同一份備份，拿到備份的人就能改稽核紀錄、再用金鑰重算簽章，防竄改就失效了。請另外離線保存一份金鑰檔（見第 2 節）。 |
| `DownloadPath`／`UploadPath` | 腳手架的程式不會寫入要長期保存的檔案：兩者只在啟動時建立，`DownloadPath` 掛在 `/UploadFiles` 對外提供靜態檔，`UploadPath` 是暫存目錄。專案附件一律放 `ProjectFilePath`。⚠️ 衍生專案若要在這兩處放永久檔案，須依[開發慣例與限制速查](../architecture/開發慣例與限制速查.md) §6.16 第 2 點把資料夾加進備份。 |
| 日誌檔（`NLog:BasePath`） | 只用來追查問題，還原系統不需要它；需要保存時由維運另外處理。 |
| 網站程式、`appsettings*.json` 與環境變數 | 由部署流程重新取得；設定（含機密）請另外保存一份。 |

## 2. 保管

- ⚠️ **備份不加密，而且含金鑰環：拿到備份的人可以偽造任何人的登入 Cookie。**
- 0.9.104 起金鑰環也用來加密兩步驟驗證的密鑰：拿到備份等於拿到每個人的驗證器密鑰。反過來，**還原時金鑰環一定要跟資料庫一起還原** —— 只還原資料庫、留著新的金鑰環，所有人的驗證碼都會不正確，只能由管理員逐一「重設兩步驟驗證」（support 帳號不受強制，可以先登入處理）。
- `BackupPath` 的 NTFS 權限只給**應用程式集區身分**（讀寫）與**系統管理員**；其他帳號不可讀。
- 系統啟動時會擋下：`BackupPath` 與其他資料目錄重疊、或位於網站目錄底下。
- **稽核防竄改金鑰另外保管**（0.9.175 起）：`AuditKeyPath` 底下的 `audit-hmac.key` 不在備份裡，請另外離線保存一份（例如公司的密碼保管庫），**不要和備份放在一起**；目錄權限同樣只給應用程式集區身分與系統管理員。金鑰檔產生後不會自己改變，保存一次即可。
- **異地保存**：同一台主機上的備份會跟著主機一起壞掉。至少每週把最新一份下載或複製到另一台主機／檔案伺服器（權限同樣要收緊），依公司規定保留。
- 備份目錄的磁碟空間：約為（資料庫＋附件＋堆疊檔＋Token 原始檔）壓縮後 × 保留份數；作業開始前會檢查可用空間，不足時失敗並在「排程作業」與「系統健康監控」看得到。
- IIS 回收時間請避開 02:00，避免備份被中斷（被中斷時記為「中斷」，下一次自動清掉暫存）。

## 3. 還原

還原會把資料換回備份當時的樣子；備份之後的新資料不在其中。

1. **決定用哪一份備份**，確認它的系統版本（`/backups` 的「系統版本」欄或 zip 裡的 `manifest.json`）**不比目前部署的程式新**。比較新的話，先部署相同或更新的程式（腳本會中止，加 `-Force` 才略過這項檢查）。
2. **停站**：IIS 停止應用程式集區（或在網站目錄放 `app_offline.htm`）。網站執行中腳本會直接中止。
3. 以系統管理員身分開啟 PowerShell（Windows PowerShell 5.1 或 PowerShell 7 皆可），執行：

   ```powershell
   cd <repo 或部署包>\scripts
   .\Restore-Backup.ps1 -BackupFile D:\Backup\backup-20261004-020000.zip -SitePath C:\inetpub\<網站>
   ```

   - 腳本讀網站目錄的 `appsettings.json` 與 `appsettings.Production.json` 取得路徑。**路徑寫在 web.config 或系統環境變數時讀不到**，請用 `-DatabasePath`、`-ProjectFilePath`、`-ExceptionPath`、`-TokenUsagePath`、`-AiCallLogPath`、`-AiAgentConversationPath`（0.9.143 起）、`-AuditContentPath`（0.9.131 起）、`-DataProtectionKeyPath` 指定。
   - 腳本先列出每個資料夾要放到哪裡，輸入 `YES` 才開始（`-Yes` 可略過確認）。
4. 腳本會：核對 zip 的格式與資料庫雜湊 → 把現有的 `BackendDB.db`、`-wal`、`-shm` 改名為 `*.before-restore-<時間>` → 刪除 `*.lock` → 放入備份的資料庫 → 各資料夾改名保留後換成備份內容 → 金鑰**合併**（只補上沒有的，備份之後才發的登入 Cookie 仍有效）。
   - ⚠️ 殘留的 `-wal` 會被 SQLite 套用到還原的資料庫上把它弄壞，所以一定要改名移走 —— 不要自己手動複製資料庫檔還原。
5. **啟動網站**，登入確認資料回到備份當時；備份版本比程式舊時，網站啟動時會自動 migrate。
6. 確認無誤後，可刪除 `*.before-restore-<時間>` 的檔案與資料夾。
7. **稽核完整性檢查會回報一次「資料庫回退」**（0.9.175 起）：還原等於把稽核紀錄倒回備份當時，下一次排程「稽核紀錄完整性檢查」（每天 03:30）會作業失敗一次並通知全體管理員，這是預期的；再下一次就恢復成功。建議在維運紀錄中註明這次還原，方便日後對照。

**回復到還原前**：停站 → 刪除新放入的資料庫與資料夾 → 把 `*.before-restore-<時間>` 改回原名 → 啟動網站。腳本結束時會印出要改回的清單。

### 限制

- 衍生專案重新產生過 migration，**不能**用腳手架（或其他專案）的備份還原。
- Windows 上金鑰檔以 DPAPI 保護：換主機或換應用程式集區身分時金鑰可能解不開，結果是所有人要重新登入（資料不受影響）。
- **換主機還原時要帶稽核金鑰**（0.9.175 起）：還原腳本不處理 `AuditKeyPath`，請在啟動網站前把離線保存的 `audit-hmac.key` 複製到新主機同樣的 `AuditKeyPath`。沒帶的話系統會自動產生新金鑰、照常運作，但還原前的稽核紀錄只能顯示「金鑰不同」（只確認序號連續、無法驗證內容），而且第一次檢查會回報「金鑰變更」。

## 4. 還原演練（建議每季一次）

1. 在測試主機部署相同版本的程式，`appsettings` 指向測試用的資料目錄。
2. 從正式環境下載最新備份，依第 3 節還原到測試主機。
3. 登入、抽查幾筆資料與附件下載、看「系統健康監控」全綠。
4. 記錄演練日期、使用的備份與耗時。

## 5. 常見問題

| 狀況 | 處理 |
|---|---|
| 「上次執行」顯示可用空間不足 | 刪除舊備份或調低保留份數，或擴充備份目錄所在的磁碟。 |
| 「資料庫快照沒有通過完整性檢查」 | 資料庫可能有問題：保留最近一份成功的備份，立刻聯絡開發人員，不要再刪舊備份。 |
| 腳本說「無法獨佔開啟資料庫」 | 網站還在執行（或有其他程式開著資料庫）：停止應用程式集區後再試。 |
| 腳本說「SHA-256 與 manifest 不符」 | 備份檔損毀（下載或複製不完整），改用另一份。 |
| 還原後所有人都被登出 | 金鑰在新主機解不開（見「限制」）；請大家重新登入即可。 |
| 還原後收到「稽核紀錄完整性檢查」失敗的通知，訊息說比上次檢查時還舊 | 還原把稽核紀錄倒回備份當時，回報一次是預期的（見第 3 節第 7 步），下一次檢查會恢復成功。沒有做過還原卻收到，請當成稽核紀錄可能被動過處理。 |
| 換主機後檢查回報「金鑰和上次檢查時不同」 | 沒把 `audit-hmac.key` 帶到新主機。把離線保存的金鑰檔放回 `AuditKeyPath` 後重新啟動網站；找不到金鑰檔也能照常運作，只是舊紀錄無法驗證內容。 |
