### ⚠️ 已知限制：Web API 不做團隊列級過濾

**這是刻意設計，但交付前必須讓客戶知道。**

- Blazor 服務層（`ProjectService`）對非管理員有套團隊列級權控；
  **Web API 走的是 Repository 路徑（`ProjectRepository`），完全沒有列級過濾**。
- 後果：同一位非管理員在畫面上看不到別團隊的紀錄，但持 JWT 呼叫
  `GET /api/Project/{id}` 或 `POST /api/Project/search` 可取得**全部**紀錄。
- [ ] 若本案會把 API 開放給終端使用者（而非僅供內部系統整合），
      **必須**先補上列級過濾，或改由 Controller 走已有 scope 的 Service。
- [ ] 若維持現狀，請於交付文件中明確載明此限制。

詳見 [開發慣例與限制速查 §4.1](../architecture/開發慣例與限制速查.md)。

## 速率限制與安全標頭（0.4.35 起）
- [ ] 依本案流量特性檢視 `RateLimit:ApiRequestsPerMinute`（預設 120）與 `RateLimit:LoginRequestsPerMinute`（預設 10）。
- [x] 限流**依呼叫端分割**（已驗證身分優先，其次來源 IP），不再是全站共用單一計數器。
- [ ] **走反向代理時必須設定 `ForwardedHeaders:KnownProxies` 或 `KnownNetworks`**：
      未設定時所有請求的來源 IP 都會是代理伺服器（全部擠在同一個限流分割），
      且呼叫端可自行偽造 `X-Forwarded-For`。
- [x] 回應含 `X-Content-Type-Options: nosniff`、`X-Frame-Options: DENY`、`Referrer-Policy`。
- [ ] **CSP 尚未導入**。若本案有需求，請先以 `Content-Security-Policy-Report-Only` 觀察
      （注意 `App.razor` 會從 fonts.googleapis.com 載入字型、AntDesign 會注入 inline style）。
