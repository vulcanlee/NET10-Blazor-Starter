## 1. 日誌方案：NLog

採 `NLog.Web.AspNetCore 6.1.2`，於 [`src/MyProject/MyProject.Web/Program.cs:33-56`](../../src/MyProject/MyProject.Web/Program.cs) 完成設定：

1. 從 `appsettings.json` 讀取 `NLog.BasePath`（預設 `C:\temp\Logs`）。
2. 在 `BasePath/MyProject.Web/` 下建立日誌目錄。
3. 設定 NLog Internal Logger 寫入 `MyProject.Web-nlog-internal.log`。
4. 將 `BasePath` 與 `LogFilenamePrefix` 變數寫入 NLog 設定，供 `nlog.config` 內 `${var:BasePath}` 引用。
5. `builder.Logging.ClearProviders()` 清除預設 Provider，由 `builder.Host.UseNLog()` 接管。

`nlog.config` 位於 `MyProject.Web/` 根目錄，定義具體 Target / Rule。

系統內有兩處會讀取日誌檔，皆僅限管理員使用；但日誌本身仍不應寫入密碼、token 或完整連線字串。

- `/system-health` 人工巡檢頁：依 `NLog.BasePath` 與專案命名空間定位**今日**日誌檔，在頁尾顯示最後 100 筆原始日誌。
- `/logs` 日誌檢視頁：可依時間區段（上限 3 天）、筆數、最低等級與關鍵字篩選，跨日時會合併多個日誌檔，並可將查詢結果以原始 nlog 文字格式匯出下載。詳見 [日誌檢視 PRD](../prd/日誌檢視-prd.md)。

## 執行期調整日誌等級

`/log-level-setting`（統計與分析 › 日誌等級設定，僅管理員）可在**不重新啟動、不異動任何設定檔**的情況下調整最低輸出等級，排查問題時調到 DEBUG／TRACE，查完再還原。詳見 [日誌等級設定 PRD](../prd/日誌等級設定-prd.md)。

幾個需要知道的行為：

- 設定**只在執行期有效**，重新啟動就回到 `nlog.config` 的值。
- **只影響應用程式日誌**。`Microsoft.*`／`System.*` 有專屬的 `final` 規則，調低不會引來框架日誌洪水；但反過來調高也**無法靜音**那些框架警告。
- 套用後即使 `nlog.config` 被 autoReload 重新載入，設定仍會保留 —— 因此**改檔案的 minlevel 不會立即生效**，要回到檔案的值請按「還原為系統預設等級」。
- 每次變更都會寫入稽核軌跡。

> **0.4.29 修掉的既有缺陷**：`autoReload` 重載時 NLog 會整個換掉設定物件，連帶清空 `Program.cs` 注入的 `BasePath`／`LogFilenamePrefix` 變數，導致日誌改寫到磁碟根目錄。現在重載後會自動補回這兩個變數。

> `appsettings.json` 的 `Logging:LogLevel` 區段是**死設定** —— `UseNLog()` 預設會移除 Microsoft 的過濾器，全部由 `nlog.config` 決定。改它不會有任何效果。

## 2. 日誌撰寫規範

日誌是本系統可觀測性的唯一來源。目標是：**只看 Information 就能重建「使用者當時做了什麼」，需要細節時再降到 Debug。**

### 2.1 選等級的三個問題

依序問，第一個答「是」的就是答案：

1. 這個結果是**使用者輸入的正常後果**，行為端正的使用者日常操作就會遇到嗎？
   → **Information**（若屬純查詢／換頁／排序則為 **Debug**）
2. 這是**非預期但已處理**的狀況 —— 可能的誤用、設定錯誤、安全相關的拒絕、資料完整性異常？
   → **Warning**
3. 使用者要求的操作**失敗了**，需要程式或維運介入（例外、外部資源失敗）？
   → **Error**

兩條可直接套用的細則：

- **讀取查無資料 = Information；寫入查無資料 = Warning。** GET 一筆已刪除的資料是常態；UPDATE／DELETE 一筆不存在的資料代表畫面過期或有人在探測。
- **欄位／重複名稱驗證失敗一律 Information；權限與身分驗證失敗一律 Warning。**

> **0.4.30 的修正**：本節先前把「業務驗證未通過」列在 Warning，導致 Warning 數量與 Information 相當（各 139 筆），真正的異常被淹沒。已重新分類 50 處。**Warning 是給「維運人員應該看一眼」的事；使用者打錯字不是。**

### 2.2 等級對照

| 等級 | 使用時機 | 範例 |
|------|----------|------|
| `Trace` | 迴圈內／逐筆的追蹤。**目前專案未使用**；有需要時才寫，不為了填滿等級而寫。 | 逐行解析、逐表統計的每一次迭代。 |
| `Debug` | 流程細節、查詢條件、分頁排序、快取命中、權限判定過程。**排查時才會看。** | `logger.LogDebug("Paged category query executed. PageIndex={PageIndex}, TotalCount={TotalCount}", ...)` |
| `Information` | **使用者做了什麼**（畫面切換、新增／修改／刪除／匯出／登入登出）、商業流程完成、啟動與關閉。 | `logger.LogInformation("User navigated. Path={Path}, Account={Account}, ...")` |
| `Warning` | 授權被拒、身分驗證失敗、寫入時查無資料、設定或資料完整性異常、連線中斷。 | `logger.LogWarning("API request denied by permission check. UserId={UserId}, PermissionKey={PermissionKey}", ...)` |
| `Error` | 例外、外部資源失敗、重要流程中斷。 | `logger.LogError(ex, "Failed to search categories.")` |
| `Critical` | 應用程式無法繼續運作而終止。**全專案只有一處**（`Program.cs` 頂層 catch）。 | `logger.LogCritical(ex, "Application is stopping because of an unhandled exception.")` |

### 2.3 使用者操作追蹤

| 操作 | 等級 | 記在哪裡 |
|------|------|----------|
| 畫面切換 | **Information** | `ApplicationCircuitHandler`（集中一處，涵蓋所有版面，**頁面不需要自己寫**） |
| 改變狀態的按鈕（新增／修改／刪除／匯出／套用／登入登出） | **Information** | 各自的事件處理方法 |
| 純查詢的按鈕（搜尋／重新整理／分頁／排序） | **Debug** | 各自的事件處理方法 |
| circuit 開啟／關閉／斷線 | Information／Warning | `ApplicationCircuitHandler` |

寫入性操作請記兩筆：**意圖**（使用者按下了什麼）與**結果**（成功或失敗）。中間的失敗分支依 §2.1 判斷等級。

### 2.4 不可寫入日誌的資料

日誌是純文字、保留 30 天，且**管理員可從 `/logs` 匯出原始檔案**。以下絕對不可進入日誌：

- 密碼（明文或雜湊）、`Salt`
- JWT／Refresh token、`SigningKey`、OAuth `ClientSecret`、API 金鑰
- TOTP secret，**以及 `GenerateProvisioningUri` 的回傳值**（secret 內嵌在該 URI 裡）
- 圖形驗證碼（正確答案與使用者輸入皆是）
- 連線字串
- **Email、姓名、電話等個資**
- 使用者輸入的搜尋關鍵字內容（可記「有沒有關鍵字」，不記關鍵字是什麼 —— 搜尋「王小明」等於記錄了一個人名）

**可以記錄的身分資訊只有 `Account` 與 `UserId`。**

> **已知且已接受的取捨**：Google SSO 使用者的 `MyUser.Account` 本身就是 Email（`ExternalLoginService` 建立帳號時如此設定）。因此對 SSO 使用者而言記 Account 等於記 Email。這是刻意接受的，因為 Account 是追蹤「是誰做的」最直接的依據，也與稽核表的 `ActorAccount` 一致。

**claim 對應在兩套驗證機制中是相反的，取用時務必確認：**

| Claim | Cookie（Blazor 頁面） | JWT（API） |
|---|---|---|
| `ClaimTypes.Name` | **使用者姓名（個資，絕不記錄）** | Account |
| `ClaimTypes.NameIdentifier` | Account | UserId |
| `ClaimTypes.Sid` | UserId | 未使用 |

在 Blazor 端誤用 `ClaimTypes.Name` 會把使用者姓名寫進日誌。

### 2.5 撰寫格式

- 訊息一律**英文**句子；中文保留給 `ApiResult.Message` 與畫面通知，不要混進日誌。
- 結構化參數用 **PascalCase** 佔位：`Account={Account}`、`UserId={UserId}`。
- **不得使用 `{@Model}` 解構整包物件** —— 那是一次外洩全部欄位最快的方式。逐一列出需要的欄位。
- 例外一律放第一個參數：`logger.LogError(ex, "...")`。
- 不要記錄 QueryString、HTTP header、cookie。

### 2.6 守門測試

`MyProject.Tests/LoggingConventionTests.cs` 會擋下：

| 規則 | 說明 |
|---|---|
| 訊息含中文 | 一律英文 |
| 佔位名稱非 PascalCase | 便於檢索 |
| 佔位名稱含敏感字詞 | `password`／`token`／`secret`／`email`／`captcha` 等 |
| 引數取用敏感屬性 | 樣板寫 `{Value}` 但引數是 `user.Password` 一樣會被擋 |
| 使用 `{@}` 解構 | 禁止整包記錄 |
| 行為類別缺少 `ILogger` | Services／Repositories／Controllers／Diagnostics |

**測試擋不了的**：訊息內容是否有意義、等級選得對不對、有沒有記到該記的東西。這些仍需人工審查 —— 文件是判斷依據，測試只是最低防線。

若某個佔位名稱含敏感字詞但其實無害（例如布林旗標 `NeedChangePassword`），請加入測試中的 `SafePlaceholderNames` 並註明理由，不要放寬規則本身。

## 3. 全域請求日誌

`MyProject.Web/Extensions/ApplicationBuilderExtensions.cs` 的 `UseHttpRequestLogging` 註冊一個自訂 middleware：

- 對每筆 HTTP 請求記錄 `Method`、`Path`、`StatusCode`、`ElapsedMilliseconds`。
- 例外發生時改寫為 `Error`，並重新拋出讓上層 ExceptionHandler 處理。

由此可在不額外加程式的情況下取得每個 endpoint 的響應耗時。

**低價值路徑記在 Debug**（0.4.30 起）：靜態資產（`/css`、`/js`、`/lib`、`/_framework`、`/_content`）、框架端點（`/_blazor`）、健康探針（`/health`）與 `/swagger`、`/favicon`、`/UploadFiles`。

原因很實際：`/health/live` 若每 10 秒被輪詢一次，一天就是 **8,640 筆** Information —— 比一位使用者一整天的操作紀錄還多，會把「使用者做了什麼」整個淹沒。

**但狀態碼 400 以上一律維持 Information 以上**，即使路徑屬於低價值清單。靜態資產的 404 往往正是「連結壞掉」最早的線索。

### 4.1 `Logging`

.NET 預設記錄等級。NLog 啟動後會接管實際輸出，但此區段仍影響 `Microsoft.*` 等內建類別的 Filter。

### 4.2 `NLog.BasePath`

NLog 寫檔的根目錄；專案會在其下建立 `MyProject.Web` 子目錄。若不存在會被 NLog 自動建立。

### 4.3 `Swagger` / `Security` / `Cors`

| 欄位 | 用途 |
|------|------|
| `Swagger.EnabledInProduction` | Production 是否開啟 Swagger UI；Production 必須明確設定。 |
| `Security.ReturnExceptionDetails` | 是否在 API 500 回應填入完整 `Exception`；未設定時 Development 才會回傳。 |
| `Cors.AllowedOrigins` | 允許跨來源呼叫的 origin 清單；空陣列代表不開放。 |

### 4.3.1 `GoogleOAuthSettings`

| 欄位 | 用途 |
|------|------|
| `Enabled` | 是否啟用 Google 第三方登入；`false` 時不註冊 Google 驗證，登入頁也不顯示按鈕。 |
| `ClientId` / `ClientSecret` | Google OAuth 用戶端憑證；正式環境請用 user-secrets / 環境變數，勿進版控。 |
| `DefaultRoleName` | 首次以 Google 登入而自動建立的帳號所套用的預設角色名稱。 |

完整設定步驟與登入流程詳見 [Google OAuth2 第三方登入](../security/Google%20OAuth2%20第三方登入.md)。

### 4.3.2 `CacheSettings`

| 欄位 | 用途 |
|------|------|
| `Provider` | 快取提供者，支援 `Memory`（預設，單機記憶體）與 `Redis`（分散式）。空字串會回退為 `Memory`，未知值在啟動時拋出例外。 |
| `RedisConnection` | `Provider=Redis` 時的連線字串（如 `localhost:6379`）；`Redis` 時不可留空，Production 會被啟動安全檢查阻擋。 |
| `InstanceName` | Redis 鍵前綴，用於隔離同一 Redis 實例上的多個應用。 |
| `DefaultExpirationMinutes` | 未指定過期時間時套用的預設絕對過期（分鐘）。 |

呼叫端統一透過 `ICacheService`（`Get/Set/GetOrCreateAsync<T>/Remove`，內含 JSON 序列化），切換 provider 不需改任何使用端程式。完整說明見 [分散式快取機制](../features/分散式快取機制.md)。

### 4.4 `SystemSettings.ConnectionStrings`

資料庫固定為 SQLite（0.4.24 起已移除 `DatabaseProvider` 設定與 SQL Server 支援），由 `ServiceCollectionExtensions.AddConfiguredDatabase` 直接以 `UseSqlite` 註冊。

| 欄位 | 用途 |
|------|------|
| `SQLiteDefaultConnection` | SQLite 範本字串；實際連線字串由 `MagicObjectHelper.GetSQLiteConnectionString` 結合 `DatabasePath` 動態產生。 |

### 4.5 `SystemSettings.SystemInformation`

| 欄位 | 用途 |
|------|------|
| `SystemName` | 顯示在 UI 上的系統名稱。 |
| `SystemDescription` | 顯示用描述。 |
| **`SystemVersion`** | **唯一版本來源**，每次更新必須遞增；格式 `Major.Minor.Patch (YYYY/MM/DD)`。詳見 [維護規範](維護規範.md)。 |

### 4.6 `SystemSettings.ExternalFileSystem`

| 欄位 | 用途 |
|------|------|
| `DatabasePath` | SQLite 資料庫檔放置目錄。 |
| `DownloadPath` | 對應 `/UploadFiles` 的靜態資源目錄。 |
| `UploadPath` | 通用上傳暫存目錄。 |
| `ProjectFilePath` | 專案附件根目錄（依年/月分層）。 |

啟動時 `Program.cs:132-141` 會逐一呼叫 `EnsureDirectoryExists` 建立缺少的目錄。

### 4.7 `AutoMapper:LicenseKey`

AutoMapper 12+ 商業授權金鑰；留空會走免費條款。註冊位置：`Program.cs:113-122`。

## 5. 環境差異設定

`appsettings.Development.json` 僅覆寫 Logging：

```json
{
  "Logging": {
    "LogLevel": {
      "Default": "Information",
      "Microsoft.AspNetCore": "Warning"
    }
  }
}
```

未來可在 `appsettings.Production.json` 內切換 SystemSettings（例如連線字串、外部目錄）以符合不同部署環境。
