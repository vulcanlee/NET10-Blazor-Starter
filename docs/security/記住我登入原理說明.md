# 記住我登入原理說明

- 文件版本：2.0
- 文件狀態：已實作
- 現行系統版本：0.10.8
- 首次實作版本：0.1.60
- 最後核對日期：2026/11/11

## 文件目的

說明本專案在登入頁勾選「記住我」之後，為什麼下次重新開啟網站時可以不必重新做身分驗證，以及這個機制在本專案中是如何實作的。

0.10.8（WASM 遷移 M9）起網頁改成**純 Token 登入**，不再發登入 Cookie，本文描述的是現行做法；0.10.7 以前的 Cookie 做法放在最後的「沿革」一節。
完整的登入與撤銷規則見 [認證授權與權限機制](認證授權與權限機制.md)。

## 結論

「記住我」的核心不是把密碼記在前端，也不是跳過登入檢查，而是：

1. 使用者登入成功時，伺服器發出一組 **Token**：短效的**存取 Token**（JWT，預設 15 分鐘）與可以換新的**刷新 Token**（伺服器只存它的雜湊）。
2. 勾了「記住我」，瀏覽器把這組 Token 存在 **localStorage**：關掉瀏覽器再開，Token 還在。沒勾就存在 **sessionStorage**：只屬於這個分頁，關掉分頁就沒了。
3. 之後網頁呼叫 API 時帶著存取 Token；存取 Token 快到期時，網頁自動用刷新 Token 換一組新的。
4. 伺服器每次都會檢查 Token 是否有效、帳號是否仍可使用。
5. 因此使用者不需要再次手動輸入帳號、密碼與驗證碼。

也就是說，「記住我」真正記住的是 **登入狀態（Token）**，不是帳號密碼本身；差別只在 Token 放在哪裡、能維持多久。

## 本專案的程式流程

## 1. 使用者在登入頁勾選「記住我」

檔案：`src/MyProject/MyProject.Web.Client/Views/Auths/Login.razor`、`Login.razor.cs`（0.10.8 起登入頁在 WASM）

登入頁的「記住我」勾選框（`#rememberMe`）連同帳號、密碼、驗證碼一起送到 `POST api/v1/Auth/login/web`（`RememberMe` 欄位）。

## 2. 伺服器依「記住我」決定效期

檔案：`src/MyProject/MyProject.Web/Controllers/WebAuthController.cs`、`MyProject.Web/Auth/WebSessionTokens.cs`

帳號密碼通過後（已啟用兩步驟驗證的帳號要先過第二步），`WebSessionTokens.IssueWebAsync` 開一串新的網頁 Token（發出管道 `web`），效期取自 `appsettings.json` 的 `SessionSettings`：

| | 勾了「記住我」 | 沒勾 |
|---|---|---|
| 存在哪裡 | localStorage（整個瀏覽器共用） | sessionStorage（只有這個分頁） |
| 關掉瀏覽器或分頁 | 仍維持登入 | 登出 |
| 刷新 Token 效期 | `RememberMeDays`（預設 30 天） | `IdleTimeoutMinutes`（預設 480 分鐘），每次換新重新起算（閒置逾時） |
| 整次登入的上限 | 從登入那一刻起 `RememberMeDays` 天，一直使用也會到期 | 預設沒有（`IdleTimeoutSliding=true`）；設成 `false` 時從登入起最多 `IdleTimeoutMinutes` 分鐘 |
| 存取 Token | `AccessTokenMinutes`（預設 15 分鐘），到期前自動換新 | 同左 |

刷新 Token 是 32 bytes 的亂數，資料庫（`RefreshSession` 資料表）只存它的 SHA-256；整串上限記在 `AbsoluteExpiresAtUtc`，每次換新都不會超過它。

## 3. Token 裡面裝的是什麼

存取 Token 是伺服器以 `JwtSettings:SigningKey` 簽章的 JWT，內容包括：

- 使用者 Id、帳號
- `security_stamp`：工作階段版本（改密碼、停用、強制登出時會換掉）
- `fid`：屬於哪一串刷新 Token（0.10.8 起，用來即時撤銷）
- `client_kind`：發出管道（網頁是 `web`）

裡面沒有密碼。刷新 Token 則只是一串亂數，本身不含任何資訊，要拿到伺服器查資料庫才知道是誰的。

## 4. 下次重新開啟網站時，為什麼還知道你是誰

檔案：`src/MyProject/MyProject.Web.Client/Auth/ClientSession.cs`、`TokenStore.cs`、`wwwroot/js/client-auth.js`

1. 瀏覽器開啟網站，伺服器只回空的 WASM 外殼。
2. WASM 外框（`ClientMainLayout`）呼叫 `ClientSession.InitializeAsync`，從 localStorage 讀出上次存的 Token。
3. 存取 Token 過期了就用刷新 Token 換一組新的（`POST api/v1/Auth/refresh`）；舊的刷新 Token 隨即作廢（輪替）。
4. 以存取 Token 呼叫 `/api/v1/Auth/me` 取得身分與權限。伺服器端每個請求由 `ApiActorMiddleware` 從資料庫重新載入目前使用者：帳號是否存在、是否停用、工作階段版本是否相符、是否必須先改密碼或設定兩步驟驗證、有沒有主要角色。
5. 全部通過才顯示畫面；任一項不通過就清掉 Token、回登入頁（或導到改密碼／兩步驟驗證設定頁）。

所以「重新進站後仍已登入」不是前端自己說了算，而是：

- 瀏覽器保留 Token
- 伺服器驗證 Token、查資料庫確認帳號狀態
- 系統再從資料庫重建目前使用者的權限

### 沒勾「記住我」時開新分頁

沒勾時 Token 在 sessionStorage，新開的分頁讀不到。新分頁會以 BroadcastChannel 向已開的分頁要：對方以自己的刷新 Token 呼叫 `POST api/v1/Auth/session/fork`，替新分頁**開一串新的** Token 交過去（同一次登入、同樣的效期規則）。所以：

- 已經開著一個分頁時，再開新分頁或從連結開頁面，會自動接續登入。
- 1 秒內沒有分頁回應（所有分頁都關了），就要重新登入。

## 5. 為什麼不需要重新輸入驗證碼

驗證碼只在 **登入當下** 用來防止機器人或暴力嘗試。

一旦登入成功，系統就已經發出有效的 Token。之後再次進站時，系統是根據 Token 來識別你，而不是重新走登入表單流程，所以也不需要重新輸入驗證碼。

換句話說：

- 驗證碼是登入前的防護
- Token 是登入後的身分憑證

兩者用途不同。

兩步驟驗證的「記住這台裝置」是另一回事：它記住的是「這台裝置下次登入時不用再輸入兩步驟驗證碼」（記住裝置 Token，存在 localStorage，預設 30 天），不是登入狀態；帳號密碼照樣要輸入。

## 6. 什麼情況下即使勾選記住我，還是需要重新登入

### 6.1 到期

勾了「記住我」，整次登入最長 `RememberMeDays`（預設 30 天），從登入那一刻算，一直使用也會到期。
沒勾時刷新 Token 閒置 `IdleTimeoutMinutes`（預設 8 小時）沒用就失效；關掉分頁也會登出。

### 6.2 使用者主動登出

`/Auths/Logout` 呼叫 `POST api/v1/Auth/logout`：伺服器撤銷**這次登入的每一串** Token（每個分頁各一串），前端清掉 Token 並通知其他分頁，其他分頁也會回登入頁。已發出的存取 Token 也立即失效（同一台主機立即，多台主機最多 30 秒）。

### 6.3 瀏覽器清除網站資料

手動清除瀏覽器的網站資料（localStorage），或使用隱私模式／無痕模式（關掉視窗就清空），Token 就不見了。

### 6.4 同一個瀏覽器換人登入

同一個瀏覽器只有一個身分：在任一分頁換成另一個人登入，其他分頁也會換成那個人（重新載入）。

### 6.5 帳號狀態改變

改了密碼、被停用、被刪除、被管理員強制登出、角色或管理員身分被改，都會換掉工作階段版本：伺服器拒絕舊 Token，下一次呼叫或換新時就要重新登入（同一台主機立即，多台主機最晚 `SessionSettings:ValidationIntervalMinutes`，預設 5 分鐘）。
自己在這台改密碼、啟用或停用兩步驟驗證，或管理員改了自己的角色、密碼或管理員身分時，伺服器會直接回這台的新 Token，所以這台不會被登出。

另外，帳號沒有主要角色時網頁一律不能用（伺服器回 403），前端會登出。

### 6.6 Token 疑似外洩

已經換新過的舊刷新 Token 在 30 秒後又被拿來用，代表可能被偷：伺服器撤銷這次登入的每一串，所有分頁都要重新登入。

### 6.7 金鑰換掉不會登出（與以前不同）

存取 Token 用 `JwtSettings:SigningKey` 簽章，刷新 Token 只存雜湊在資料庫，**都不靠 Data Protection 金鑰環**，所以金鑰環換掉不會讓已登入的人登出。
但「記住這台裝置」的 Token 以金鑰環加密，金鑰環換掉就要重新輸入兩步驟驗證碼。`JwtSettings:SigningKey` 換掉則所有存取 Token 立即失效，網頁會用刷新 Token 換新的，不必重新登入。

## 7. 本專案裡「記住我」的完整事件順序

### 第一次登入時

1. 使用者輸入帳號、密碼、驗證碼，勾選「記住我」
2. 登入頁送出 `POST api/v1/Auth/login/web`（`RememberMe=true`）
3. 伺服器驗證帳密（與兩步驟驗證），開一串網頁 Token，整串上限 30 天
4. 前端把 Token 存進 localStorage，並通知同一個瀏覽器的其他分頁「誰登入了」
5. 導回原本要去的頁面（`returnUrl`，只接受站內路徑）

### 下次重新開啟網站時

1. 瀏覽器開啟網站，WASM 外框從 localStorage 讀出 Token
2. 存取 Token 過期就以刷新 Token 換新（舊的作廢）
3. 呼叫 `/api/v1/Auth/me`，伺服器查資料庫確認帳號狀態與權限
4. 使用者直接進入系統，不必重新登入

## 8. 常見誤解

### 誤解一：記住我是把密碼存起來

不是。存在瀏覽器裡的是 Token，不是密碼；刷新 Token 在伺服器只存雜湊。

### 誤解二：記住我代表永不登出

不是。整次登入最長 30 天（可設定），而且登出、改密碼、被停用、清除瀏覽器資料都會讓它失效。

### 誤解三：重新開網站不用登入，代表系統沒做驗證

不是。每個 API 請求都會驗證 Token，並查資料庫確認帳號仍可使用，只是驗證依據從「帳密 + 驗證碼」改成「先前登入成功後發出的 Token」。

### 誤解四：沒勾記住我，開新分頁就要重新登入

不會。只要還有一個分頁開著，新分頁會自動向它要一組 Token；全部關掉才要重新登入。

## 9. 沿革（0.10.7 以前的 Cookie 做法）

0.1.60～0.10.7 網頁用 **Cookie 登入**：

- 登入頁（Server 版 `Components/Auths/Login.razor.cs`）以 `HttpContext.SignInAsync(MagicObjectHelper.CookieScheme, …)` 發出登入 Cookie（`.MyProject.Auth`），`AuthenticationProperties.IsPersistent = RememberMe`：勾了是可以跨瀏覽器重開保存的持久 Cookie，沒勾是關掉瀏覽器就消失的工作階段 Cookie。
- 效期由 `CookieSettings` 決定（0.9.39 起：沒勾 8 小時 `ExpireMinutes`、勾了 30 天 `RememberMeDays`、`SlidingExpiration=true`；之前吃框架預設 14 天）。滑動續期只在用掉超過一半效期時的那次 HTTP 請求才續。
- 🔴 Cookie 以 Data Protection 金鑰加密，金鑰換一批就全站登出；0.9.39 之前沒有固定金鑰環，IIS 回收就換一批，這是當時「勾了記住我隔天還是要重新登入」最常見的原因。
- 每次換頁由 `AuthenticationStateHelper.Check` 比對，HTTP 請求另由 `SecurityStampCookieEvents` 每 `CookieSettings:ValidationIntervalMinutes` 分鐘比對工作階段版本。
- 0.10.0～0.10.7 的 WASM 頁面以 `POST api/v1/Auth/bridge` 用 Cookie 換 Token，換出的 Token 不比 Cookie 活得久。

0.10.8 移除登入 Cookie：`CookieSettings` 改名為 `SessionSettings`（舊鍵仍相容，啟動時記警告），沒勾「記住我」的意義從「關掉瀏覽器就登出」變成「關掉分頁就登出，但開新分頁會自動接續」。升級後原本以 Cookie 登入的人要重新登入一次。

---

## 10. 一句話總結

勾選「記住我」之後，系統把登入成功時發出的 Token 存在瀏覽器的 localStorage；下次再開網站時網頁讀出 Token、必要時自動換新，伺服器驗證通過並確認帳號狀態後就能還原你的登入身分，因此不需要重新做帳密與驗證碼驗證。
