每一批都用同一套方法，並和**改動前在乾淨 main（`ba1686d`，0.10.42）取的基準**比對：

1. **基準**：任何修改之前先跑完整品質關卡、抓 Swagger API 介面快照（`swagger.json`）、以 `git worktree` 把 `ba1686d` 獨立取出來啟動隔離主機（`Start-E2EHost.ps1`，全新資料庫）跑 e2e 腳本並留下結果。
2. **編譯器證明**：刪掉的符號只要還有任何程式引用，建置就會失敗；建置 0 警告 0 錯誤（警告視為錯誤）＝沒有程式引用它。
3. **搜尋證明**：編譯器看不到的引用（設定檔、路由字串、JS 互通、CSS class、JSON 欄位、腳本、測試讀原始碼的慣例測試）在刪除前後各全文搜尋一次（排除 `wwwroot/lib` 第三方檔案與 migration）。

5. **測試數量對帳**：改前改後的測試數差異逐一對應到被刪除的程式；保護正式功能的檢查不因刪碼而消失（必要時改寫到仍在用的路徑）。
6. **e2e 前後比對**：同一組腳本、同樣的全新隔離主機，改前改後結果一致。
7. **獨立審查**：每批完成後由一個不知道我結論的審查代理只看 diff 找問題，發現的問題與處理寫在下面。
