## B.6 獨立審查

審查代理只拿到 diff 與使用者的原則（行為不變，只有根目錄檢查是刻意的改變），逐段和原本的程式比對：

| 類別 | 結果與處理 |
|---|---|
| 根目錄檢查以外的行為改變 | ⚠️ **例外紀錄的清除有競態**：例外紀錄和其他表不同，同一個例外再發生時會更新 `LastOccurredAt`。改用「先取檔案路徑、再依時間條件 `ExecuteDelete`」後，兩步之間剛好又發生的那一列不會被刪，它的堆疊檔卻已刪掉（堆疊只在首次發生時寫，就永遠沒了）；原本依主鍵刪不會這樣。**已退回原本的寫法**，並在 `RetentionQueries.DeleteRowsThenFilesAsync` 的說明寫明只適用於寫入後不再更新清理條件欄位的表（AI 對話紀錄、Token 用量、巡檢報告——這三張表的時間欄位寫入後不變，審查也確認 Token 用量改用 `ExecuteDelete` 是安全的）。另一個極小的差異：刪除時剛好 0 筆，會少寫一行日誌、少收一次空資料夾；`DeleteRowsThenFilesAsync` 改成以 null 表示「沒有符合的資料」，行為與原本完全相同。其餘逐項核對無誤：11 個截斷的 null／空字串／超長結果、時間的 `Kind`、稽核包裝（`AuditLogService` 自己接住例外）、共用 JSON 設定沒有被修改、靜態欄位初始化順序、排序與統計的運算式、各 store 照舊不拋出、例外堆疊照舊不用 ILogger |
| 根目錄檢查本身 | 資料庫裡既有的路徑都是 `{yyyyMM}/{Guid 或簽章}.副檔名`，不會被拒絕。⚠️ 邊界情況：根目錄設成磁碟或檔案系統的根（`D:\`、`/`）時，多加一個分隔符號會讓所有路徑都被當成越界、寫入靜默失敗（另外四個 store 原本就有這個問題）。**已修正**並補測試 `RootedFiles_DriveRootAsTheRoot_ShouldStillResolve`。另一點：比對不分大小寫，在 Linux 上大小寫不同的同層資料夾可能被當成在根目錄底下——這是原本四個 store 就有的寫法、本系統部署在 Windows，記錄在此、未改 |
| 讀原始碼的慣例測試 | 沒有風險（`RootedFiles` 已列入日誌慣例的例外清單；沒有新增空的 catch；稽核動作代碼沒變） |
| 留下的孤兒 | 4 個工具類別的 `using Microsoft.Extensions.AI` 已用不到，**已移除**。日誌等級 Controller 的 `logger` 現在沒有讀取，但專案慣例（`BehaviourClasses_ShouldHoldALogger`）要求每個 Controller 都持有 logger，保留 |
| 文件 | 腳手架指引對「哪些 store 經 `RootedFiles`」的描述不精確（專案附件只用它解析路徑）、缺口 7 那一列還寫各自 `Path.Combine`；變更紀錄對例外紀錄與 Agent 對話的描述——**都已修正**。本報告的待填欄位已在 e2e 完成後填入 |

## B.8 評估後刻意不整併

計畫列了這些重複，實際讀過程式後判斷收成共用方法不會比較好，所以維持原樣：

| 重複 | 不整併的理由 |
|---|---|
| PDF 的「缺少內建中文字型」訊息（5 處） | 例外分析、Token 用量、系統巡檢報告的前端自己加「PDF 匯出失敗：」／「PDF 下載失敗：」，伺服器的訊息不帶前綴；日誌檢視、AI 對話紀錄的前端直接顯示伺服器的訊息，伺服器的訊息帶前綴。統一的話某些頁面會重複或少了前綴，必須連前端一起改、改到使用者看得到的文字 |
| 三個日誌維護 Controller 的刪除／清除／清空 | 每個動作約 8 行，稽核內容、成功訊息、事前檢查都不同；收成共用流程只省兩三行、多一層間接 |
| 分批依 Id 刪除的迴圈（寄信紀錄、通知、Token 用量） | 取的欄位、刪不刪檔、日誌都不同；泛型化要動態組 Expression，程式碼不會變少、反而難讀 |
| 服務的刪除單筆／清空全部（AI 對話紀錄、Token 用量、例外紀錄） | 回傳型態（`NotFound` 與 `Build(false)`）、使用者訊息、日誌樣板都不同 |
| AI 對話紀錄與 Token 用量的篩選條件 | 兩張不同的資料表，要共用得替實體加一個介面，只為兩處約 20 行 |
| 頁面路徑正規化（4 處）與 `MaxPathLength` | 空值結果（空字串或 `/`）、是否補開頭斜線、是否去掉控制字元各不相同 |
| 說明頁與側邊選單讀取內嵌 JSON 檔 | 日誌訊息不同，共用要把日誌樣板當參數 |
| DataAnnotations 驗證（3 處） | 後續處理不同：串訊息、補欄位檢查、寫 ModelState |
| `MissingOrConflictAsync`（2 處） | 不同資料表與主鍵型別，共同的只有兩行三元運算 |
| `ApiResult.ServerErrorResult` 與 `FromException` | 回傳型別不同（非泛型與泛型） |
| SHA-256 Token 雜湊 | 密碼重設是大寫、刷新 Token 是小寫，合併會讓資料庫裡已存的雜湊對不上 |

| 一行的保留門檻計算、兩個 AI 分析服務的骨架、保留作業的類別骨架 | 一行式或差異大於共同處；保留作業的稽核 detail 格式是文件規定的 |
